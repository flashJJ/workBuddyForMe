# v5.0.1 发行说明：兜底修正

> 状态：🚧 待发布（5.0.1）
> 主题：**兜底修正——补偿恢复、无人值守语义与运行中心回归修复**
> 类型：补丁版本（无迁移，schema 仍为 57）
> 方案：[v5.0 方案](../plan/v5.0/README.md) · [版本总结](../plan/v5.0/version-summary.md)

## 修复

- **补偿重放保持无人值守语义**：补偿重放沿用原运行的 `trigger`，不再固定为 `manual`；Agent 工具门控与 `interactive=false` 语义恢复，避免自动重试等待人工确认。
- **补偿重启恢复**：新增 `retrying` 收敛。claim 后崩溃（无 last_run_id）立即回 `pending`；重放已成功/取消/失败按结果推进；重放被重启收敛为 `interrupted` 或运行期被中断时，计一次尝试并续排；仍在排队/执行则留给终态事件。
- **中文错误分类**：超时/限流/网络/鉴权/版本/数据/工具/配置补中文关键词；限流优先于鉴权，避免 `token rate limit` 误判为不可重试。
- **运行列表正确性**：`workflowId` 过滤下推 SQL，不再受全局 limit 截断影响；失败节点统一取最后一个，与重放服务一致。
- **列表与清理性能**：运行列表、清理查询不再读取 `graph_snapshot_json`；终态清理拆出独立仓储。
- **保留清理语义**：按 `finished_at`（缺省 `created_at`）计算保留期，避免长跑运行刚结束就被删除。
- **重放边界**：停用流程拒绝单条/批量重放；批量重放先去重再计数与校验上限。
- **定时错过计数**：`missed_count` 封顶 100。
- **运行中心 UI**：补 `schedule/webhook/file` 触发器筛选；批量重放展示逐条未启动原因；HMAC 触发器在未轮换时可切回 Bearer。

## 升级说明

- 无数据库迁移，升级后 schema 仍为 57；
- 启动时自动收敛上次进程遗留的 `retrying` 补偿；
- 已停用流程的运行不能再手动重放，需先启用流程；
- 既有补偿记录无需人工处理。
