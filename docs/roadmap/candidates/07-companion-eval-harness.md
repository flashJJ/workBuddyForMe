# 陪伴质量评测：把「选场是否合理」变成可回归的指标

> 状态：**候选方案，待评审**。关联：[Utility 决策](../../plan/v3.0/pet-engine/14-utility-decision.md)、[进度日志](../../plan/v3.0/progress-log.md)。
> 记录日期：2026-11-15。

## 1. 问题

主动播放与触发键排序已经有打分和理由码，但质量仍靠人工观察：

- 权重调整后，无法快速判断忙碌/深夜/关系变化下的排序是否更合理；
- 生成场景的弱偏好（时段、心情）命中率没有统计；
- 同一天多次开演是否重复、是否打断工作，只有零散日志；
- 没有一个「决策回放」入口，调参只能重新等真实场景。

## 2. 现状证据

| 项 | 现状 |
|---|---|
| 决策记录 | 存 20 条、界面展示 5 条，含总分与理由码 |
| 拒绝候选 | 只进开发日志，不进入决策记录 |
| 生成队列 | 每日次数/间隔/勿扰门控，弱偏好可选 |
| 测试 | Utility 纯函数单测，覆盖权重与去重 |
| 缺失 | 场景矩阵回放、指标汇总、调参前后对比 |

## 3. 可选方案

| 方案 | 做法 | 收益 | 成本 |
|---|---|---|---|
| A 离线回放 | 读取历史决策记录与候选快照，重算分数并对比 | 可复盘、无隐私外泄 | S |
| B 场景矩阵 | 固定一组上下文（时段×工作×关系×心情），跑打分器输出排序 | 调参可回归 | M |
| C 在线 A/B | 两套权重随机分流，比较用户互动 | 最真实 | L（本地单用户样本不足） |

## 4. 推荐

A + B，做成开发期脚本与设置页只读视图：

- 输入：最近决策记录、候选场景元数据、当前权重；
- 输出：每个上下文的 Top-N、分数差、理由码分布、重复率；
- 指标：候选被门控拒绝原因、道具/主题去重命中、今日未播加分、长场次成本、弱偏好命中率；
- 对比：调参前后同一矩阵的排序变化，人工确认是否符合直觉。

不做在线 A/B：单机单用户样本量不足，且会引入分流复杂度。

## 5. 验收口径

1. 同一输入重算分数与线上记录一致（允许浮点尾差）。
2. 场景矩阵覆盖至少 12 组上下文，输出稳定可复现。
3. 权重改动后生成一份差异报告，能指出哪些场景换位。
4. 脚本不读取聊天正文，只使用决策记录与场景元数据。
5. 不新增运行时依赖，不改变现有决策链路。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 历史记录太少，矩阵不具代表性 | 允许用内置场景构造合成上下文 |
| 指标被当成「用户满意度」 | 文档明确是代理指标，不替代真实反馈 |
| 调参过拟合 | 保留一组未参与调参的上下文做留出验证 |

## 7. 待决策

3. 首批指标只做排序与去重，还是同时统计生成成功率？
