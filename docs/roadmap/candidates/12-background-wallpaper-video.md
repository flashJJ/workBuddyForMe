# 背景与壁纸：内置背景、图片壁纸与循环视频

> 状态：**候选**（未排期）
> 来源：2026-11-17 讨论；用户已生成三席角色的循环视频素材，希望作为背景使用。
> 关联：[v4.3 方案](../../plan/v4.3/README.md) 的舞台背景层与 `TheaterBackdrop`。

## 1. 问题

舞台目前只有内置的渐变/场景背景，聊天主界面与主窗口整屏没有可选背景；用户自有的图片与循环视频没有入口，无法作为环境氛围使用。

## 2. 现状证据

- 舞台背景由 `TheaterBackdrop` 按剧集变体渲染，未抽象成可配置背景源。
- 桌宠窗是透明窗（`transparent: true` + 透明背景色），任何不透明背景都会破坏穿透视觉。
- 聊天主界面与主窗口整屏共用同一页面布局，没有背景层。
- 设置里没有背景相关分组，也没有本地媒体的受控读取通道。

## 3. 目标范围（已确认）

| 界面 | 配置口径 |
|---|---|
| 舞台 / 小剧场 | 独立背景配置 |
| 聊天主界面 | 主窗口配置下的「聊天」模式 |
| 主窗口整屏 | 主窗口配置下的「整屏」模式；与聊天模式互斥，在同一配置点切换 |
| 桌宠窗 | 独立配置，与上面三处互不继承（透明窗需要单独处理） |

## 4. 可选方案

| 方案 | 做法 | 收益 | 风险 |
|---|---|---|---|
| A 单层背景源 | 统一 `BackgroundSource = builtin / image / video`，一处渲染组件，舞台与主窗口复用 | 实现小、配置一致 | 主窗口与舞台的层级/遮罩需分别适配 |
| B 能力包扩展 | 新增 `wallpaper-pack` 能力类型，背景走内容包管道 | 可分发、可升级 | 包体与许可成本高，首版过重 |
| C 仅内置 | 只做内置渐变与内置视频 | 最稳 | 用户自有素材无法使用 |

## 5. 推荐

先做 A，内置素材走仓库资源；`wallpaper-pack` 留作后续扩展。

- 背景源：内置（程序化渐变/场景）、图片（PNG/JPEG/WebP）、循环视频（MP4/H.264）。
- 渲染：舞台在底层铺背景，上层 Live2D/VRM 画布不变；聊天主界面与整屏用同一背景层，按模式切换裁切方式（聊天留白、整屏全幅）。
- 配置：`ui.background` 增加 `scope: main | stage | pet`；`main` 内含 `mode: chat | window` 互斥选择；`pet` 独立。
- 本地文件：桌面端经 IPC 选择后复制到 `userData/backgrounds/`，通过受控路由读取；Web 模式走上传接口。
- 性能：窗口不可见或最小化时暂停视频；省电档回落到静帧；尊重「减少动态效果」；建议 720p、H.264、≤8Mbps。
- 体积：安装包预算 300MB，当前 4.3.0 为 264.88MB；内置视频单个控制在 10MB 以内，`check:assets` 增加媒体预算项。
- 许可：内置素材必须自建或 CC0；用户视频只在本机，不随包分发。

## 6. 验收口径

1. 舞台、聊天主界面、主窗口整屏可分别选择内置/图片/视频背景，切换后即时生效并持久化。
2. 聊天与整屏在主窗口配置下互斥切换，不出现两套背景叠加。
3. 桌宠窗背景配置独立，默认保持透明，不被主窗口配置影响。
4. 视频循环无可见卡顿；窗口隐藏/最小化暂停解码；减少动态效果时回落到静帧。
5. 本地图片/视频重启后仍可用；文件缺失时回退内置背景并给出提示。
6. 安装包与内置媒体仍在预算内，零数据库迁移。

## 7. 风险

| 风险 | 对策 |
|---|---|
| 视频解码与多角色渲染抢资源 | 720p/8Mbps 上限；不可见暂停；省电档静帧 |
| 透明桌宠被背景破坏 | 桌宠独立配置，默认透明，不继承主窗口 |
| 本地文件路径失效 | 复制到 userData，记录相对 id，缺失时回退 |
| 内置素材许可不清 | 只收自建或 CC0，许可证随资源入库 |
| 安装包膨胀 | `check:assets` 媒体预算 + 单视频 10MB 上限 |

## 8. 待决策

3. Web 模式是否支持背景上传，还是仅桌面端可用？
4. 是否在后续版本引入 `wallpaper-pack` 能力包分发背景？
5. 视频只支持 MP4/H.264，还是同时支持 WebM？
