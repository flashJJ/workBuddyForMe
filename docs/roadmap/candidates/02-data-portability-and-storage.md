# 候选 02：数据可带走——备份补全、恢复预检与空间清理

> 来源：v1.5 / v1.4 已知边界、v0.3 附件 GC 留白、v2.18 产物导出范围、v2.30 范围说明。
> 状态：候选，建议排期 v2.32。
> 前序：[v2.31 方案](../../plan/v2.31/README.md)。

## 1. 问题

本地优先意味着「数据在你手里」，但现在的数据生命周期只完成了一半：

- **带不走**：备份轨已含对话、知识、记忆、分支事件，但协作运行与交接记录不随备份迁移；恢复后协作历史为空，task_run 的 `agent_run_id` 回落 NULL。
- **不敢恢复**：恢复前没有预检。用户看不到归档版本、各轨条数、哪些数据会被覆盖或跳过，只能先点「恢复」再看结果。
- **产物散落**：`artifact_write` 产物只能单张导出图表（SVG / PNG），没有批量打包下载，也没有跨会话的产物清单。
- **空间看不见**：附件删除消息后不清理（v0.3 起登记 P2），数据目录没有分项占用统计，长期使用只能靠手动翻目录。

## 2. 现状证据

- `packages/shared/src/backup.ts`：`CURRENT_BACKUP_SCHEMA_VERSION = 7`，轨道为 conversations / knowledge / settings / attachments / skills / tasks / emotion / events。
- `packages/core/src/backup/restore-tasks.test.ts:133-139`：协作表存在但「不随备份迁移」，`agentRuns` 与 `handoffs` 断言为 0。
- `apps/web/src/features/chat/overlay/artifact-export.ts`：只做单个产物的 SVG 提取与 PNG 栅格化，没有批量导出。
- `docs/roadmap/v0.3-release-summary.md:102`：附件与消息松耦合，删除消息不强制删文件，GC 登记 P2 后一直未排期。

## 3. 可选方案

| 方案 | 内容 | 成本 | 风险 |
|---|---|---|---|
| A. 备份补全 + 恢复预检 | 备份 schema v8 加法轨（协作运行 / 交接），恢复前 dry-run 报告（版本、轨道计数、覆盖与跳过项） | 中 | 归档变大；旧归档兼容分支增多 |
| B. 产物与附件打包 | 多选产物 / 附件导出为 zip，附 manifest（标题、格式、字节数、来源会话） | 中 | 需引入打包依赖或用流式 tar；大文件内存占用 |
| C. 空间可见与孤儿清理 | 数据目录分项占用（数据库 / 附件 / 产物 / 日志），孤儿附件清理到回收目录 | 中 | 误删风险，必须先扫后删、先移后清 |

## 4. 建议取舍

- P0：A 的恢复预检（只读、无迁移、收益最直接），先让用户敢点恢复。
- P1：A 的备份补全（schema v8，旧归档继续可读）；B 的产物批量打包。
- P2：C 的占用统计与孤儿清理，清理只移入回收目录，不直接删除。
- Non-Goal：云同步、自动定时备份、跨设备增量同步。

## 5. 风险与待决策

1. 协作记录进备份后，归档体积与恢复耗时增加多少，需要一次真实归档测量。
2. 恢复预检是「只报告」还是允许选择轨道后部分恢复（现有 `restore-track-select.ts` 已支持轨道选择，可复用）。
3. 打包格式用 zip 还是 tar.gz；是否复用现有备份归档的 tar.gz 依赖，避免新增原生依赖。
4. 孤儿附件清理的判定口径：仅「无消息引用且无产物引用」，回收目录保留 7 天。
