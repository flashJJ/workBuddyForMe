# WorkBuddy For Me v1.6.0 — Release Notes

## WorkBuddy For Me 1.6.0 — A companion with feelings

Release date: **2026-10-13** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-1.6.0.exe`

Until now the avatar's expression reset the moment a reply finished, and every conversation felt emotionally independent. v1.6 gives your companion a state that **persists across turns**: mood settles over time while intimacy and trust build slowly — and the desktop pet now visibly reacts when you reach out to it.

### 💗 Mood and relationship that persist

- Per-assistant state tracked as a pure, testable engine: **happiness / anger / sadness** (moods that decay exponentially with time apart) plus **intimacy / trust** (slow variables that only grow and are cleared only by reset).
- Events move the numbers conservatively: praise +8 mood, an everyday chat +0.25 intimacy — relationships are measured in weeks, not minutes.
- Everything is stored locally in `assistant_emotion_states`; deleting an assistant cascades, and the backup archive includes the emotion track.

### 🧬 Structured emotion protocol (weak-model safe)

- Replies optionally carry a single trailing JSON block: `{emotion, intensity, soulEvent}` with one of **eight expression tags** and an explicit **praise / chat / belittle** event.
- Parsing is Zod-validated with per-field fallback; malformed JSON, out-of-vocabulary tags, or a 7B model that ignores the format all fall back to **deterministic Chinese keyword guards**, then to a neutral default. A broken emotion signal never affects the actual reply, which is stored and spoken with the JSON block stripped.
- The system prompt injects the current mood/relationship in Chinese; the whole pipeline can be switched off from settings.
- Real-device run with a local **qwen2.5vl:7b**: 3/3 protocol-valid turns (model block or guard/default fallback), zero protocol leakage into the reply body, ~4–5 s per turn.

### 🎬 Fused expressions with afterglow

The displayed expression now fuses the **baseline mood with the current turn**: a strong momentary emotion can briefly override a calm baseline, and the face holds the feeling for a few seconds after the message instead of snapping back to idle.

### 🫳 Head pats, protection mode, and idle life

- The pet window distinguishes **head** from **body**: pat the head for a squash bounce, a blushing expression, and occasionally a local line; body drags still move the window, with no accidental zoom or mis-taps.
- Pat three times within two seconds and the pet enters a short **protection mode** — an indignant look and a lighthearted "charging petting fees" line. Lines are local and capped (cooldown + daily cap), never an LLM call, and never interrupt speech.
- **A-tier micro-dynamics** run only while the pet is visible: breathing, eye tracking that follows your cursor, rare sideways peeks when you leave, and occasional head tilts — pausing while speaking or during performances.

### 👋 Welcome back after time apart

Walk away for a workday and the pet greets your return with a local line and expression — deterministic, **no model request, no IPC, nothing stored**:

- 8 h: a light welcome · 24 h: "kind of missed you" · 72 h: a strong long-time-no-see.
- Triggers on cold start, window focus, visibility regain, cursor return to the pet, and the main window coming to the foreground (cross-window via local storage).
- Each absence is greeted **at most once**; it naturally rearms only after you have chatted again.

### 🎛️ Visible and controllable

A new **Emotion & interaction** settings panel offers:

- **Emotion engine** master switch and a separate **interaction lines** switch (expressions and motions remain when lines are off);
- assistant picker with six-level human-readable status labels (no raw numbers);
- the recent interaction feed — event type, source, expression tag, and time only. **No message text is ever stored in the feed**;
- one-click reset (mood, relationship, and feed) with a confirmation dialog;
- full Simplified Chinese / English coverage.

### 🔬 Verified before tagging

- 20 shared unit tests for the reunion engine and 9 web tests for storage/cross-window hooks, alongside the M0–M4 emotion suites.
- Clean end-to-end run: **46/46 specs green**; full unit suites green (`check` includes types, lint, and the 300-line file-size gate).
- Idle power sampling on the live Electron pet (dev build, pet visible, 24 logical cores): ≈ **4.3 % of the whole machine ≈ one core** (GPU process ~0.6 core, heaviest renderer ~0.41 core), ~750 MB across 5 processes. Dev HMR/polling overhead included; the packaged build is expected to sit lower. Re-sample on the shipping installer.

### Known limits

- Small local models sometimes mislabel the *semantic* event (e.g. a scolding turn as plain chat) while still emitting a schema-valid block; slow-variable tuning keeps the impact of one misjudgement tiny.
- No audio assets ship in this version (pats/greetings are visual + local text only); external Live2D model import remains permanently disabled per the Cubism licensing boundary.

### Post-seal fixes included in this installer

- Backup restore reported a failure toast even though all data was imported successfully (the restore API response was missing the app's standard envelope); the full 7-track export→import loop was verified on a real device after the fix.
- Settings interactions could be unresponsive under slow first-load hydration (a v1.6 panel swapped DOM structure during the hydration window); hydration is now gated and CI is green across 46 end-to-end specs.
- The sidebar version badge was stuck at v1.1.0 (hard-coded); it is now injected at build time and reads v1.6.0.
