# v2.30.0 发行说明

> 主题：**能力补齐——能力可见、审批可读与内容包/产物收口**
> 发布：已打 tag `v2.30.0`（待发布 Release） · 零迁移（`LATEST_SCHEMA_VERSION = 49`，无 v050）
> 完整方案：[v2.30](../plan/v2.30/README.md)

## 新功能

### 能力清单

- **只读工具 `capability_list`**：列出现已安装能力包的 id、名称、种类、状态、版本、权限、effects 与新增工具；支持按 `kind` / `status` 过滤。
- **条数与信息边界**：单次最多 30 条，超出提示用 `capability_search` 缩小范围；不返回正文、密钥或安装路径。
- **设置页可见**：助手工具白名单新增「已安装能力清单」，调试台工具数更新为 26 个内置工具；未装配能力目录时返回可读的不可用说明。

### 审批可读

- **可选 `details` 字段**：`tool_confirmation_required` 事件新增目录快照（`catalogId`、名称、种类、版本、来源、安装策略、签名状态、权限、effects、工具名）；仅 `capability_install` 填充，其他工具不出现该字段。
- **默认精简**：审批框标题下显示「来源 · 版本 · 将新增 N 个工具」；展开后查看签名、权限、effects 与完整工具列表。
- **向后兼容**：旧客户端忽略 `details` 后仍可正常 allow / deny；目录条目缺失时退回原有 `argsSummary`。

### 内容包更新检查

- **只读接口**：新增 `GET /api/content-packs/:id/update-check`，读取内置版本（上游 commit 短哈希）并请求上游仓库最新 commit，10 秒超时。
- **三种结果**：已是最新、上游有更新（附来源链接）、暂时无法检查；网络失败、限流或来源不支持时返回 `status: 'unavailable'` 与可读原因，不抛 500。
- **手动触发**：内容包卡片新增「检查更新」按钮，只在点击时请求；不自动下载、不自动替换已导入内容。

### 单轮产物限流

- **双上限**：单轮最多 6 个产物、累计不超过 8MB；单文件 2MB 上限保持不变。
- **先检查再落盘**：超限直接返回可读错误，不写文件、不生成附件记录。
- **按回合重置**：计数保存在回合工具上下文中，不跨对话累计；保存失败不计入配额。

### 审批审计快照

- **决策可追溯**：`capability_install` 的 allow / deny 审计事件在 `outcome` 中附带 `catalogId@version`、来源与 effects 摘要。
- **只写字符串**：不新增表、不改变审计链哈希字段；审计页可直接看到「批准了哪个版本、来自哪里」。

## 修正

- **助手不知道自己装了什么**：用户问「你装了哪些技能」只能靠模型猜；现在有只读清单可查。
- **审批框只有 catalogId**：安装前看不到来源、版本、签名与新增工具；现在默认展示关键事实并支持展开。
- **内容包过期无感知**：上游内容变化时导入会被哈希校验直接拒绝，用户分不清网络问题还是版本过期；现在可手动核对最新 commit。
- **单轮产物无数量边界**：一次批量生成可能写十几份产物撑满消息区；现在有数量与总大小双上限。

## 升级说明

- 零迁移：启动时不执行新的 schema 迁移，旧库、旧备份、旧消息均可直接读取。
- `tool_confirmation_required.details` 为可选字段，旧前端忽略即可；审计 `outcome` 仍是字符串，旧读取逻辑不受影响。
- 产物单轮数量上限由 3 调整为 6，并新增 8MB 总大小上限；单文件 2MB 限制不变。
- 内容包更新检查只在用户点击时发起一次网络请求；不点击不会产生额外流量。

## 范围说明

本版已交付：能力清单、审批详情、内容包更新检查、单轮产物限流、审批审计快照。

本版未交付：第三方本地 ZIP 进入能力目录、内容包自动更新与差异合并、能力自动安装、产物打包下载、新的存储迁移。
