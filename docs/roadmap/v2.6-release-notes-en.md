# WorkBuddy For Me v2.6.0 — Release Notes

## WorkBuddy For Me 2.6.0 — Conclusions that execute, memories with provenance

Release date: **2026-10-28** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-2.6.0.exe` (190.8 MB)

Installer SHA256: `cc9d7e95205c9e3196eab91a0d3964e5b43ed25f379fac6ac3c0b4b81a0a140f`

v2.6 closes the two loops that used to end too early:

**Discussion → conclusion → action items → reminders / Flows; memory → source conversation → source message → recall reason.**

It also completes the Electron 45 platform migration and ships three P1 improvements: screenshot paste guidance, a cross-chain run report, and a desktop performance baseline script.

### 🧠 Meeting conclusions and action items

- Generate a structured conclusion only after a meeting has finished; generation is user-triggered and guarded against concurrent runs.
- Output must pass Zod validation. Invalid JSON never becomes a fake conclusion; long transcripts are compressed in chunks first.
- Edit summary / decisions / open questions; regenerating replaces generated action items while manual ones survive.
- Action items support owner, due date and `open → done/cancelled → open`.
- Convert an action item into a role-based reminder (requires a due date and a meeting member) or run a **published** Flow with the item content mapped to `actionItem/query/topic/question`.
- Export Markdown with topic, members, transcript, conclusion and action-item checkboxes — no keys or internal prompts.

### 🔍 Memory with provenance

- New memories store their source conversation and assistant message; summary memories keep only the conversation; hand-written and legacy memories show “Source unknown” instead of inventing one.
- Recall returns a score and `reason='semantic'`; `recall_count` and `last_accessed_at` update on every hit.
- Chat memory chips expand to show kind, content, relevance level and a source link; opening it jumps to `/chat?conversation=&message=` and highlights the message.
- Deleted source conversations/messages degrade with a readable notice; the memory itself is kept.

### ⚡ Electron 45 platform

- Electron **45.0.0**; `safeStorage` now uses the async API end to end, and the cipher bridge can await it without blocking.
- Sandboxed preload no longer depends on removed Node globals.
- Existing ciphertext remains decryptable; `pack:dir` and the desktop smoke suite pass.

### 💾 Backup schema v7

- The events track now carries `memories.json`, `meetingConclusions.json` and `meetingActionItems.json`.
- Older archives are read with missing files treated as empty; restores are idempotent and never overwrite local rows.
- Memory sources and recall counts survive restore; vectors are not archived (semantic recall requires re-embedding, matching the knowledge-base policy).

### 🧰 P1 improvements

- **Screenshot paste**: pasting into the composer works for vision models; non-vision models and task mode show an actionable hint.
- **Run report** (`/reports`): success rate, median duration and top failures across tasks, Flows and agent runs, with date/chain filters and Markdown/CSV export. No new run tables.
- **Performance baseline**: `pnpm --filter @wbfm/desktop perf:baseline` measures launch, first window, first interactive content and idle memory on the packaged build.

### ✅ Verification

- `pnpm check`: typecheck, lint (0 errors) and the 300-line gate pass.
- Unit tests: database 226, core 1130, web 581; shared / ai / config / desktop / voice suites pass.
- Desktop smoke: 11/11. Web e2e: 104/109 in the full run; the 5 failures were triaged and the affected dependency chain re-ran 16/16 (details in the v2.6 M5 note).

### ⬆️ Upgrade notes

- Database migration **35 → 36** runs automatically; old data needs no backfill.
- Backup schema **6 → 7**: new builds read old archives; older builds reject newer archives, so upgrade first.
- Supplier keys encrypted before the upgrade remain decryptable after it.
