## 1. 主题与价值主张

v1.4 交付了固定三角色协作，但真机使用（尤其是本地 7B 量化模型）暴露的问题集中在「状态机正确，体验不及格」：

| 断点（v1.4 真机现状） | v1.5 的回答 |
|---|---|
| 助手只能绑 1 个知识库，跨域问题要靠用户自己拆 | **多知识库联合检索**：助手/Agent 节点绑定上限 10 库；一次 embed、各库向量+FTS 双通道召回、跨库 RRF(k=60) 融合、全局多样性去重与统一重排 |
| 引用来源一多就刷屏 | **引用来源折叠**：`>3` 条默认折叠（`COLLAPSE_THRESHOLD=3`），可展开/收起，≤3 条平铺行为不变 |
| 弱模型当 Executor：子任务只收到标题、零工具裸奔直接 fail | **下传完整子任务上下文**：goal 注入 brief/验收标准/绑定库名/工具目录与硬规则；screen 模式同等注入 |
| 弱模型「盲调」：工具正文从不回注，completed 却无交付正文 | **观察回注**：`buildToolObservation` 注入最近动作 output 正文（≤4000 字），历史步 digest 补结果摘要 |
| 弱模型无限换词检索到步数耗尽 | **检索预算硬约束**：`TOOL_RETRIEVAL_CALL_CAP=3`（全任务累计），每轮提示「已用动作 x/max、检索 n/3」，达上限强制 done |
| 授权了知识库却零检索直接收尾 | **确定性门控** `mandatoryRetrievalCorrection`：done/fail 驳回为强制纠正观察，宽限 `MANDATORY_RETRIEVAL_GRACE=2` 次后尊重终态（纠正不计连败，防死循环） |
| 决策连败时 summary 空串，handoff 被 zod 整体拒绝、真实错误被吞 | **终态注记兜底**：`buildExecutorOutcome` 用 terminalNote（含末次真实失败原因，如 403）保证 summary 非空 |
| Planner 给纯知识任务乱派 desktop，screen 模式看无关截图失败 | 提示词明令「读资料/分析/规划/写作禁附 desktop」；Planner 降级单保留 availableToolScopes（知识库留空继承全部绑定库） |
| 系统轨迹（终态说明/预算注记/错误）落库是中文裸串，英文 UI 看到中文、切语言不变 | **语言中立线格式**：系统消息存 `SOH+JSON{k,vars}+STX` 稳定 key，模型边界固定解中文喂模型，渲染边界按当前 UI 语言解码，历史随切换即时变化 |
| 开 TTS 的 2035 字长回复，SSE 连接挂 429 秒 | **语音解耦**：合成移出主管线后台保序并行，文本 done 即 settle；长句 40 字切块 + Markdown 噪声清洗 |
| 生产模式急停早于 SSE 建连，run 永久孤儿在 running | cancel 对「running 无订阅」直接 finalize；客户端 abort SSE 同时显式 POST /cancel；终态轮询对账 |
| 浏览器里展开协作详情，底部多出数千 px 空白滚动区 | sr-only 绝对定位序号无定位祖先致 ICB 包含块逃逸；验收项 li 与主布局外壳补 `relative` |

**关键边界（沿用并收紧）**：多库上限 10 个（防 embed/检索耗时失控）；检索上限与门控只约束授权了 knowledge_search 的任务；系统轨迹 i18n 只覆盖系统模板产出（约 30 key），模型自由产出（summary/reviewNotes/用户目标）原样透传不翻译；引用折叠不改 e2e 断言（≤3 仍平铺）。

## 2. 交付清单（按提交）

### S1 急停竞态热修（`6382238`，6 文件 +48/-13）

生产模式（`next start`）下「停止生成」可能早于 `/events` 建连：客户端只 abort 了未发出的 SSE 请求，断线信号永远到不了服务端，run 孤儿在 running。dev 因编译延迟反而让 SSE 先接通——本地 43/43 不暴露，CI 稳定复现。

| 模块 | 核心交付 |
|---|---|
| core `AgentRunService.cancel` | running 但无活跃订阅时**直接 finalize cancelled**（原语义返回 false、路由 404）；迟到的 GET /events 由状态机 409 拒绝启动 |
| web `use-agent-run-stream.stop` | abort SSE 同时显式 POST /cancel（best-effort：404/409/网络错误不阻塞收尾），两条取消路径互补 |
| web `use-agent-task-turn` | 终态对账改轮询至终态（300ms / 上限 10s），容忍 abort 后 runner 一个动作内的收敛延迟 |

### S2 语音播报性能（`783f83f`，7 文件 +300/-39）

同一条 2035 字真实回复，`chat/stream` 连接耗时 **429s**。三个根因：①`withVoice` 逐句 await 合成串行插在 SSE 主管线（MeloTTS RTF 0.71，全文合成 185s），delta 与 done 都被 CPU 阻塞；②前端 streaming 态绑定连接生命周期，done 后陪绑语音数分钟；③`stripForTts` 未剥表格/URL，114 个噪声字符刷 130+ 行 OOV，104 字无标点长句单句合成 10.5s。

| 模块 | 核心交付 |
|---|---|
| `voice-chat-bridge` | 片段入**保序合成链后台并行**推进，文本事件零背压即时下发；done 文本帧不等合成，SSE 仅尾部为音频帧保活到 final |
| `use-chat-stream` | done/error 即 settle 解除生成态（输入框/重试立即可用），reader 继续排空尾部 voice_audio |
| `stripForTts` | 剔除表格分隔行/水平分隔线/代码围栏/URL，管道符转逗号保留单元格停顿，原文标点不误剥 |
| `chunkForTts`（`MAX_TTS_CHUNK=40`） | 超 40 字句按软标点贪心打包、无标点按字硬切，多块保序合成，仅首块携带字幕片段防桌宠气泡重复 |

实测：最大合成块 104 字/10.5s → 40 字/~4s，超长块清零，3 个纯噪声片段整段丢弃；完成态等待从 429s 降到纯模型生成时长，语音后台继续播完。

### S3 多知识库联合检索 + 引用折叠（`228db09`，47 文件 +500/-186）

| 层 | 核心交付 |
|---|---|
| v021 迁移 | `assistants.knowledge_base_ids` JSON 数组列，旧单值幂等条件回填为数组（v021-assistant-multi-kb，61 测） |

### S4 协作失败链热修 + 系统轨迹双语（`74a28a5`，81 文件 +2070/-456）

**失败链（真机三轮逐层定位，10 处）**：除第 1 节表中 8 项外，另含——`callWithFallback` 打印每次失败原因（原空 catch 是排障黑洞）、signal 已 abort 立即上抛不重试；任务模式失败「重新生成」改走协作重发 `taskTurn.start(content,{regenerate:true})`（原走普通 regenerate 必报「没有可重新生成的用户消息」）；任务占位消息补本地 `crypto.randomUUID()`（原 pendingMessage.id 空串致多轮泳道卡串挂同一个 `''` 键）。

**系统轨迹 i18n（方案 A：存稳定 key）**：

| 模块 | 核心交付 |
|---|---|
| 协议 `shared/i18n/system-message.ts` | 线格式 `\u0001 + JSON{k,vars} + \u0002`（SOH/STX 定界）；`encodeSystemMessage`/`parseSystemMessage`/`renderEmbeddedMessages` 支持夹带、vars 嵌套递归、坏标记原样透传；ESLint no-control-regex 下 `EMBEDDED_RE` 必须用 `new RegExp` 构造（106 测） |
| 词条域 | `messages/agent-trace.ts`（zh 真源）+ `agent-trace-en.ts`（en 全量），约 30 key，前缀 `agentTrace.*`：终态说明/预算注记/降级标注/step reason/error/SSE 连接错误 |
| 两条解码边界 | ①core 模型边界（buildPlannerMessages/buildAgentPlannerMessages/buildReviewMessages/formatStepDigest）固定 `core/i18n/system-text.ts` 的 `toModelText` 渲染中文喂模型；②web 渲染边界 `useSystemText()`（React 随语言切换）+ `system-text-runtime.ts`（SSE 回调等非 React 场景，读 `<html lang>`/localStorage） |
| 覆盖 | 泳道卡/消息错误/任务时间线/任务中心/SSE 兜底；模型产出原样透传 |
| 顺带修复 | 主题切换 aria-label 漏译、Run ID 全角冒号 |

长度坑：subtask title zod max=100，带 goal 的降级标记超限要退化为无 vars 的 degradedBadge；unfinished max=500、嵌套 cause 限 100 字符；纯系统标记禁止 `.slice()`（会切断 STX）。

### S5 布局逃逸修复（`3b1226c`，6 文件 +51/-41）

协作详情验收项每条末尾的读屏序号 `<span className="sr-only">{index}</span>` 是 `position:absolute`，而从 span 到 body 的 6 层祖先全为 `position:static`，包含块退化为**初始包含块（ICB）**：其静态位置随内部列表深入到数千 px 处，沿途 `overflow:hidden/auto` 均无法收纳，直接撑大 `documentElement.scrollHeight`（实测展开 17 项的协作行后 html scrollHeight 901→9245px，多出 8344px 纯空白可滚动区；内层越往下滚空白越长）。Electron 外壳文档不滚故不可见，浏览器稳定复现。

- 验收项 `<li>` 加 `relative` 把包含块收回条目内（a11y 行为不变）；主布局外壳补 `relative`，让既有 `h-screen overflow-hidden` 对未来任何逃逸的 abspos 后代同样生效
- 同时收口本轮排查出的脆弱链：协作泳道/证据/未完成项/步骤时间线全链补 `min-w-0`、`break-words`、证据片段 `line-clamp-2`；任务行根 li/展开容器/行按钮补 `min-w-0`；JSON 详情块 `max-w-full overflow-auto whitespace-pre-wrap break-all`

浏览器实测（新标签硬刷新）：1456/1280/800 三档宽度 + 折叠/展开/内层滚底/切换行四状态，html 最大可滚动距离恒为 0，无横向滚动条。

## 4. 踩坑沉淀（供 v1.6 参考）

1. **dev 绿 CI 红要查时序而非逻辑**：急停竞态中 dev 编译延迟恰好让 SSE 先接通，问题被编译时间「修好」。取消语义必须覆盖「订阅从未建立」这一态：服务端无订阅直接 finalize + 客户端显式 cancel 双保险，不能只靠 abort 一条路。
2. **SSE 主管线上绝不 await CPU 密集任务**：TTS 合成与 SSE 生命周期解耦后，「文本完成态」和「音频播完态」是两个独立承诺——done 帧只代表文本，音频帧尾部保活到 final；前端 settle 只认文本帧。
3. **本地语音管线先过文本净化器**：Markdown 表格/URL 进合成器就是 OOV 噪声放大器；无标点长句必须有字数硬切（40 字）兜底，不能指望标点切句。
4. **提示词软约束对弱模型无效，必须配确定性门控**：「请先检索」写得再强，7B 也会零检索直接 done；门控放在决策循环里（done/fail 前置校验），但要有宽限次数（2）且纠正不计连败，否则必死循环。
5. **给模型的失败原因要一路带到终态**：空 catch 会吃掉真实错误（如 403），空 summary 会被 zod 整包拒绝导致 handoff 失败吞掉原始 cause——终态注记永远非空、fallback 链每次失败都要 console.warn。
6. **持久化用户可见文案时，存 key 而非译文**：系统轨迹与模型产出必须分域——系统模板（可枚举、可翻译）走线格式 key；模型自由文本（不可枚举）原样存。混在一个字段里必然出现半中半英的历史记录。
7. **绝对定位元素先问「包含块是谁」**：`sr-only`/tooltip/浮层类 abspos 元素在深层 overflow 容器里，若祖先无定位上下文会一路逃逸到 ICB，且 overflow 裁剪对它无效。滚动容器外壳加 `relative` 是一行成本的根治；排查时直接搜 `position:absolute` 元素的 offsetParent 是否为 body。
8. **Next dev 改 workspace 包源码后必须重启 web 进程**；i18n 新 hook/模块链在旧标签 HMR 下会把线格式标记当裸 JSON 渲染，验证要开新标签。
9. **PowerShell 5 不支持 `&&` 与 bash heredoc**：多命令用 `;` 分隔，多行 commit message 用多个 `git commit -m`；物理行数核对统一用 Node 脚本口径（`Get-Content | Measure-Object -Line` 少计空行）。
10. **排障真机协作直接读 SQLite**：`~/.workbuddy-for-me/db/wbfm.sqlite` 的 agent_runs/task_runs/task_steps/agent_handoffs 时间线与 payload，比看 UI 快。
