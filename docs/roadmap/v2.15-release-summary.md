## 2. 技术要点

- **删除与占用**：`representativeRows()` 每版本取一行代表（优先当前状态行），`totalBytes` 只对代表行求和，避免跨状态行共享目录重复计数。删除时先判 active / 最后一份，再按 `name + version` 删除全部状态行；对每个目录做引用计数，归零才 `rmSync`。删除成功写 `skill_version_deleted` 审计。
- **归档与锚点**：`buildAuditArchive()` 先校验区间上限，再按 `created_at` 闭区间升序读取事件，生成 JSONL 与锚点。锚点同时记录区间尾（`lastSeq` / `lastHash` / `count` / `chain`）与全账本尾（`ledger.lastSeq` / `lastHash`）。`verifyAuditAnchor()` 先比全账本尾，再比区间尾与计数，最后看生成时链状态；只读，不修改账本。
- **凭证轮换**：Web 主密钥升级为 keyring 文件，保留 active + fallback。轮换顺序固定为「先解密全部 → 原子写新 keyring → 逐行重封装 → `failed===0` 时同步旧 `master.key`」。解密失败归 `skipped`，加密 / 写回失败归 `failed` 并保留旧密文；任一步崩溃旧密文仍可由 fallback 解密。Desktop 复用 safeStorage 桥，只重封装密文。
- **版本对比**：`diffFlowGraphs()` 为纯函数。节点按 id 比较，类型变化优先于配置变化；config 只比较顶层键，使用 `canonicalJson` 判等，返回按字母升序的键名；边按 `source→target→handle` 比较，忽略 edge id；布局字段不参与 diff。对比 API 只读，不改变版本状态。

## 3. 数据与迁移

- **零迁移**：`LATEST_SCHEMA_VERSION = 42`，不新增表 / 列 / 索引。
- 复用 `skill_versions`、`providers.api_key_cipher`、`workflow_versions.graph_json`、`audit_events`；仓储仅补查询 / 删除方法。
- Web 主密钥是文件格式升级（`keys/master-keyring.json`），旧 `master.key` 保留作降级兼容；`failed===0` 时同步旧文件。
- 旧库直接可开；旧版本忽略新审计 kind 与 keyring 文件，不删除历史数据。

## 6. 已知边界

- 技能版本删除不可逆；active 与唯一剩余版本受保护；审计留痕但不提供恢复。
- 审计归档限额 366 天 / 5 万事件 / 20 MB；锚点只存文件、不落库；校验只读。
- 凭证轮换仅覆盖 Provider API Key；MCP `env/headers` 留 P1；Web keyring 最多 3 把。
- Desktop safeStorage 只重封装，不更换系统密钥。
- 工作流 diff 只到 config 顶层键，不做字段级文本 diff。
- 审计尾部整段截断仅在锚点校验中检出；账本不自动清理。
