# v0.5 迭代方案：记得住 — 记忆与上下文工程

> 状态：✅ 已评审通过，开工（2026-09-26）
> 评审决议：① 范围 = P0 全做 + P1 两项均进本期；② Token 预算按**模型级可配置**（模型配置新增 `contextTokens` 字段，Ollama 经 `/api/tags` 自动探测，API 模型设置页手动填写）；③ 长期记忆**默认开启**（全局开关 + 每助手可单独关闭）。

## 1. 版本主题与目标

**一句话价值主张**：WorkBuddy For Me 真正成为「For Me」——跨会话记住你是谁、聊过什么，长对话不再悄悄丢上下文。

**成功指标**：

- 新开会话说「我叫什么/上次聊到哪」，助手能凭记忆作答（召回命中率 ≥ 8/10 抽样）
- 100+ 轮长对话不再出现「前面说过的事忘了」，历史按 token 预算自动压缩而非条数截断
- 记忆可在 UI 中查看/编辑/删除，删除即物理清除（本地优先、隐私合规）
- 全部门禁不降级：check / 四层测试 / 两端 E2E 全绿

## 2. 现状与痛点

| # | 痛点 | 现状证据 |
|---|------|---------|
| 1 | **无跨会话记忆**：每次新会话都是陌生人，个人偏好（称呼、领域、格式习惯）每次重讲 | 代码中无任何记忆存储；助手只有静态 systemPrompt |
| 2 | **长对话静默丢上下文**：`HISTORY_MESSAGE_LIMIT = 20` 按条数截断，20 条之前的消息直接消失；不区分 token 体积（一张 OCR 全文切片和一句「好」算同一条） | `packages/core/src/chat/prompt.ts` |
| 3 | **本地小模型上下文更紧**：qwen2.5:7b 仅 32K，OCR/RAG 内容挤占后，真实可用历史比 20 条更少，截断更快发生 | v0.4 实测：OCR prompt 即占 4K token |
| 4 | **无质量反馈闭环**：回答好坏无法沉淀为数据，检索/记忆策略无法回归验证 | 代码无消息级 👍/👎 |

综合来看：本项目目前只有「短期记忆 + 简单截断」，缺失长期语义记忆、情景记忆、递归摘要压缩与 token 预算分配，距离「复杂任务 Agent」所需的能力还有两块明显短板。

## 3. 功能清单

### P0-1 Token 预算与自适应历史组装

- **用户故事**：作为用户，我和助手聊 200 轮，它依然记得本次对话开头的约定，而不是第 21 轮就失忆。
- **验收标准**：
  - `buildChatMessages` 按 token 预算组装：先扣 system + 工具定义 + RAG 资料块，剩余预算从新到旧装历史，装不下为止
  - 预算来源：优先用上次响应的真实 usage；无则按字符估算（中文 ≈1.5 字符/token，可配置）
  - 超预算时的行为可观测：LangSmith span 记录 `context_budget`（system/history/context 各占多少）
- **技术要点**：`packages/core/src/chat/prompt.ts` 重构；模型配置新增 `contextTokens` 字段（Ollama 经 `/api/tags` 自动探测，API 模型在设置页手动填写），`packages/shared/src/constants.ts` 仅保留兜底默认值
- **工作量**：M（3-4 人日）

### P0-2 对话自动压缩：递归摘要替代硬截断

- **用户故事**：作为用户，很早之前的对话内容被压缩成摘要保留要点，而不是凭空消失。
- **验收标准**：
  - 历史超预算阈值（如 70%）时，把较旧的轮次递归摘要为一条「对话摘要」system 侧消息，最近 N 轮逐字保留
  - 摘要增量更新（新轮次并入旧摘要），存在 `conversations.summary` 字段，随会话持久化
  - 压缩过程对用户透明：会话头部显示「已压缩 X-Y 轮」徽标，可点开看摘要内容
- **技术要点**：摘要调用当前对话模型（temperature 0）；摘要生成失败降级为截断并打日志；单测覆盖「摘要失败不阻塞回答」
- **工作量**：L（4-5 人日）

### P0-3 长期记忆：提取 → 去重 → 向量存储 → 检索注入

- **用户故事**：作为用户，我告诉过助手「我在准备 PMP 考试」，之后任何新会话它都知道，不用重讲。
- **验收标准**：
  - 回合结束后异步提取候选记忆（事实/偏好/事件），JSON 结构化输出；提取失败静默不影响对话
  - 写入前用当前记忆库做相似度查重：高相似 → 更新合并；否则新建；防止重复堆积
  - 提问时按用户消息向量检索 top-K 记忆（相关性阈值过滤），注入 system prompt 独立区块，LangSmith `memory_recall` span
  - 记忆与知识库检索相互独立：没绑知识库的助手也有记忆
- **技术要点**：
  - DB 迁移 v005：`memories` 表（id/kind[fact|preference|event]/content/importance/source_conversation_id/status/created_at/last_accessed_at）+ `memories_vec`（sqlite-vec，复用现有向量管线与 L2 归一化）
  - 新包模块 `packages/core/src/memory/`：`extractor.ts`、`store.ts`（database 包加 DAO）、`retriever.ts`、`injection` 接入 chat-orchestrator
  - 嵌入复用 `defaultEmbeddingModelId`；记忆模型可配置（默认当前对话模型）
- **工作量**：L（5-6 人日）

### P0-4 记忆管理 UI（隐私闭环）

- **用户故事**：作为用户，我能看到助手记了我什么、改错的地方、删掉不想被记住的——记忆完全由我掌控。
- **验收标准**：
  - 设置新增「记忆库」页：列表（按时间/重要性排序）、搜索、编辑、删除（物理删除）、全部清空（二次确认）
  - 全局开关 + 每助手开关（`assistants.memoryEnabled`，默认开）
  - 对话中命中记忆时，回答上方显示「参考了 X 条记忆」轻提示（与 citations 同级交互）
- **技术要点**：REST 路由 `/api/memories*`；复用 v0.4 设置页交互模式；空态引导文案
- **工作量**：M（3-4 人日）

### P1-1 情景记忆与遗忘策略

- 按时间线查询：「上次我们讨论 X 是什么时候」→ 记忆检索支持时间过滤；会话摘要本身成为情景记忆来源
- 遗忘：importance 评分（提取时让模型打分）+ TTL/LRU 软衰减，低分低频记忆自动归档（不物理删，可恢复）
- **工作量**：M（3 人日）

### P1-2 评估与反馈闭环

- 消息级 👍/👎 落库，设置页可导出 JSON（本地数据，配合 v0.4 备份轨）
- 最小评估集（golden set）：10-20 个「记忆召回/RAG 问答」样例 + LLM-as-judge 评分脚本（node 脚本，非 UI），版本回归时跑一次，结果人工解读
- **工作量**：M（3 人日）

### P2 留白（本期不做，只登记）

- 程序性记忆（技能化操作流程）→ 归入 v0.6 技能系统
- 开源记忆框架集成（自研优先，架构预留可替换）、知识图谱/GraphRAG → 归入 v0.7+ 知识层演进

## 4. 架构影响

- **packages/database**：v005 迁移（memories + memories_vec + conversations.summary 列 + assistants.memory_enabled 列）；memories DAO
- **packages/core**：新增 `src/memory/` 模块；`chat/prompt.ts` 预算化重写；`chat-orchestrator.ts` 接记忆检索与压缩钩子
- **packages/shared**：记忆 schema（zod）、模型 schema 新增 `contextTokens` 可选字段、新常量（兜底预算/阈值/Top-K）
- **apps/web**：设置页模型列表加「上下文长度」列（自动探测标注）、记忆管理页、压缩徽标、记忆命中提示、👍/👎
- **apps/desktop**：无主进程改动（纯 renderer 层），E2E 补记忆页用例
- **兼容性**：v005 迁移向前兼容 v004 库；旧会话 summary 为 NULL 视为未压缩

## 6. 风险与取舍

| 风险 | 应对 |
|---|---|
| 本地小模型提取记忆质量差/格式漂移 | 提取 prompt 强约束 JSON + zod 校验 + 失败静默降级；评估集回归 |
| 记忆检索注入挤占上下文预算 | 记忆区块计入 P0-1 预算体系，Top-K 与阈值保守起步（K=3） |
| 摘要调用增加延迟与 token 成本 | 异步后台压缩，完成后下轮生效；摘要模型可与对话模型解耦配置 |
| 隐私顾虑（记忆像「监控」） | 记忆页一级入口 + 随时清空 + 提取内容可见化，宁少勿多（阈值宁高勿低） |
| sqlite-vec 同库多虚表性能 | 单用户量级（千条记忆）远小于文档切片，暂不担心；必要时分库 |

## 7. Non-Goals（本版本明确不做）

- ❌ 多设备记忆同步（本地优先，云端不在宪法内）
- ❌ 跨助手共享记忆空间（先做全局+助手开关，共享策略下版再议）
- ❌ 知识图谱 / GraphRAG（归 v0.7+ 知识层演进）
- ❌ 技能/MCP 扩展（归 v0.6，避免一个版本两个大主题）
- ❌ 记忆的自动微调/强化学习路线（超出本地单机范围）
