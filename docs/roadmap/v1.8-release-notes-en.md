# WorkBuddy For Me v1.8.0 — Release Notes

## WorkBuddy For Me 1.8.0 — Personalize: named themes, character cards, a tuning center

Release date: **2026-10-14** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-1.8.0.exe`

v1.7 gave your companion's feelings timing. v1.8 turns **personality, appearance and generation feel** from developer constants into things you can configure, switch and back up: four named themes, a Markdown character-card library with swap-instant dialogue, and one tuning center that gathers model bindings, sampling parameters, context width and a global prompt — all pure local data, with zero changes to model or audio assets. Existing assistants migrate with behavior unchanged.

### 🎨 Four named themes

- **Stellar** (the familiar brand blue) now has explicit **light / dark / follow-system** modes; three fixed-mood themes join it: **Nocturne Gold** (dark), **Moonwhite** (light) and **Sakura** (light).
- Themes are a web-side registry mapped to HSL tokens; switching only changes `data-theme` on top of the existing hydration-synced persistence (settings as truth + localStorage cache + anti-FOUC inline script) — the v1.2 theming mechanism was not rewritten.
- Every color pairing was audited against WCAG AA before shipping; a contrast script verifies all pairings, and axe runs across the core pages per theme.

### 🃏 Character cards as Markdown

- Cards are plain Markdown: a scalar-only YAML frontmatter (`name` / `description` / `defaultEmotion`) plus four convention sections — **identity, traits, speaking style, boundaries**. The parser is a zero-dependency pure function with line-number diagnostics (e.g. "line 1: file must start with frontmatter").
- **Six built-in read-only cards** ship in the box: Capable Colleague, Cheerful Buddy, Calm Advisor, Warm Companion, Research Scout and Study Coach. Any of them can be duplicated into an editable custom card.
- Custom cards support create, edit, **import/export as `.md`** (16 KB cap, max eight list items per section), and safe delete — assistants referencing a deleted card fall back to the default card instead of breaking.
- **Swap is instant**: re-binding an assistant's card takes effect on the very next turn. A mock-model eval protocol proves end-to-end that the assembled system prompt really changed (`persona=card|marker=hit`), with no restart or cache clearing.
- Existing assistants with a custom system prompt are auto-wrapped into a card once, guarded by a migration-done flag; assistants without one simply use the default card.

### 🎛️ One tuning center

- Per-assistant **temperature / top-p / max output tokens** are gathered from the assistant form into one panel, split into a **Common** section and an **Advanced** fold, with a two-click-confirm **restore default feel** action. Personality weights stay in the assistant form and show as a read-only summary.
- **Context message count (2–50, default 20)**: count clipping runs *before* the model-window token-budget clip — double safety. The server clamps on read, so hand-edited or stale values in the settings store can never leak into the chat pipeline.
- **Global appended prompt (0–2000 chars, with toggle)**: injected as its own `【Global append】` section at a snapshot-locked position — **after the character card, before the emotion block** — for every assistant. Blank or disabled means no injection; toggling takes effect on the next turn.
- **Scenario model matrix**: the five consumers — **chat, memory extraction, planner, executor, reviewer** — are visible and bindable on one page; blank means an explicit "follow default". Memory stays read-only in this version (no separate memory model exists). When the bound model's context window is ≤8K a small-model hint suggests conservative sampling.

### 💽 Backup: the character track (archive schema v4)

- The archive's events track now carries a `characterCards.json` payload (all built-in/custom card rows); the assistant-to-card reference travels with assistant rows and relinks on restore.
- Restore is idempotent (`INSERT OR IGNORE`), skips fixed-id built-in conflicts in favor of the machine's own built-ins, and nulls dangling card references instead of failing. v3 archives without the file restore cleanly.
- New settings keys (`themeId`, context count, global prompt, and the reserved `voiceFavorites` contract) travel automatically in the full-KV settings track.

### 🌍 Accessibility and localization

- Every new select, slider, radio group and toggle in v1.8 panels carries an accessible name (the v1.7 select-name lesson enforced by both unit tests and axe).
- One post-seal accessibility fix from test runs is included: the stellar light/dark/system selected-mode button previously measured **4.49:1** contrast; the selected state now uses solid primary color (5.17:1, WCAG AA).
- The new tuning and character-card namespaces ship with full **Chinese and English** dictionaries; the structural parity test enforces 100% English coverage.

### Known limits and deferred scope

- **Voice favorites are deferred**: the planned cloud-TTS voice library depends on a cloud TTS channel that does not exist in the product (cloud TTS has been interface-reserved since v1.0; all current TTS is local sherpa-onnx Kokoro/Melo). The `voiceFavorites` settings contract is frozen and reserved; no placeholder UI was shipped. Per-archive **bubble theme / nickname** fields likewise await a frozen contract.
- Cards are prompt data, not sandboxed templates: the UI explicitly warns to import only trusted cards. Import never executes code or reads external files.
- No audio assets ship in this version; external Live2D model import remains permanently disabled per the Cubism licensing boundary.
