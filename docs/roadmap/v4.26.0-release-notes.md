# v4.26.0 发行说明：会排班

> 状态：✅ 已发布（2026-11-24，tag `v4.26.0`）
> 主题：**会排班——多定时与 IANA 时区、Webhook Secret 轮换**
> 类型：小版本（迁移 v056，多定时与 Secret 轮换）
> 安装包：`WorkBuddyForMe-Setup-4.26.0.exe`（258.48 MB，SHA256 `1f7b3190…77e106`）
> Release：https://github.com/flashJJ/workBuddyForMe/releases/tag/v4.26.0

## 新增

- **一流程多定时**：每个流程最多 5 条定时，每条独立 cron、IANA 时区、入参与启停；列表内可逐条立即运行、编辑与删除。
- **IANA 时区**：服务端按每条定时声明的时区计算 `next_run_at`；默认 `Asia/Shanghai`，界面支持常用下拉与自定义 IANA 输入。
- **Webhook Secret 轮换**：`POST /api/flows/:id/triggers/:triggerId/rotate` 原地换钥，触发器 id 与 URL 不变，旧密钥即时失效，新 Secret 仅返回一次。

## 变更

- 定时管理 API 从 `/api/flows/:id/schedule` 迁移到集合式 `/api/flows/:id/schedules` 与 `/:scheduleId`；
- 编辑器「定时」对话框改为列表 + 新建/编辑，顶部显示条数上限；
- 「触发」对话框为 Webhook 行增加轮换入口（二次确认）；
- 迁移 v056 重建 `workflow_schedules`：去掉 `workflow_id UNIQUE`，新增 `name`、`timezone`，旧行原样保留；
- `LATEST_SCHEMA_VERSION = 56`。

## 时区语义

- 每条定时以自身时区解释 5 字段 cron；
- cron 或时区永久无效时记录 `error` 并自动停用该条，避免每 30 秒重复失败；
- 春季 DST 跳跃中不存在的墙钟时刻跳过，不补跑；
- 秋季重复的墙钟时刻只执行一次；
- 同流程多条定时同时到点仍按单飞：第一条创建运行，其余记录 `skipped_busy` 并推进到下次。

## 升级说明

- 升级时自动执行迁移 v056，已有单条定时保留 id、cron、入参与历史状态；
- 旧定时时区回填 `Asia/Shanghai`，与 v4.24/v4.25 的系统本地时区行为一致；
- 旧的前端只在开发期使用；已发布的桌面端升级后无需手动改配置。
