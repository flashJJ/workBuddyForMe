# v2.31.0 发行说明

> 主题：**记忆成图——关系边、一跳召回与空闲整理**
> 发布：待合入 main · 一次迁移（`LATEST_SCHEMA_VERSION = 50`，新增 v050）
> 完整方案：[v2.31](../plan/v2.31/README.md)

## 新功能

### 关系边表

- **纯加法迁移 v050**：新增 `memory_edges`，字段为 `from_id`、`to_id`、`relation`、`weight`、`created_at`，`UNIQUE(from_id, to_id, relation)`，`from_id` / `to_id` 各建索引。
- **派生数据**：不建外键、不回填历史记忆；边可重建、可删除，归档记忆的边由查询侧过滤、由整理任务清理。
- **只记录可解释关系**：本版写入同一助手消息抽出的 `same_source`（权重 0.8）；`co_turn`（0.65）只保留枚举与常量，等跨消息同回合写入时启用。

### 回合建边

- **落库后建边**：同一来源消息抽出的多条记忆两两成边，按 id 数值升序规范化配对，避免 A→B / B→A 重复。
- **只连活跃普通记忆**：`status = active` 且非置顶、非 `constraint` 的记忆参与建边，避免把硬约束拉进邻居扩展。
- **失败隔离**：建边异常只告警，不影响记忆落库与回合完成；重复写入按 `MAX(weight)` 取大，不产生重复行。

### 一跳邻居召回

- **种子后扩一跳**：在既有融合排序结果上取最高分 2 条种子，沿边取邻居，邻居分数 = 种子分 × 边权，低于 `MEMORY_RECALL_MIN_SCORE` 直接丢弃。
- **预算不变**：邻居最多 2 条，召回总数仍不超过 3，置顶记忆优先占位，邻居只参与普通候选排序。
- **理由与来源**：召回理由新增 `neighbor`，载荷带 `neighborOf`；提示词里邻居条目追加「（关联自：种子内容）」，让模型知道这条为什么出现。

### 空闲整理

- **三步纯规则**：同义主体归一（去空白、全角转半角、大小写归一后统一到最常见写法）、重复内容归档（正文归一后完全一致时保留 importance 高/最近确认的一条）、悬空边清理。
- **只归档不删除**：被整理的记忆仍可在管理页恢复；恢复后不自动补边，等待下一次整理或新回合。
- **可审计**：每次整理写一条 `actor = 'system'` 的 `consolidate` 审计，记录扫描数、归档数、合并主体数与清理边数。

### 调度与手动触发

- **启动后异步一次**：服务启动后异步执行一次整理，此后每 24 小时一次；距上次不足 24 小时直接跳过。
- **单飞锁**：同一时刻只允许一个整理任务，失败只告警，不阻塞对话。
- **手动入口**：新增 `POST /api/memories/consolidate`，设置页记忆统计卡提供「整理记忆」按钮。

### 观测与评测

- **统计卡新增三项**：关系边总数、关联召回次数、最近整理结果（时间 / 归档 / 合并主体 / 清理边）；空态显示「尚未整理」。
- **评测补邻居用例**：golden 集按 `group` 分组写入并共享来源消息，新增 4 条邻居召回用例；报告新增 `neighborCases`、`neighborHits`、`neighborHitAt3` 与 `edgeTotal`。

## 修正

- **记忆之间是孤立行**：只能按 `subject_key` 消解同主体新旧冲突，无法表达「同一消息里的两件事」；现在有来源关系边。
- **召回只看当前查询**：命中一条记忆后拿不到它的上下文同伴；现在可沿边取一跳邻居，并在提示词标注关联来源。
- **写入后无整理**：同义主体与重复内容只能等下次抽取碰运气；现在有启动后与每日空闲整理。

## 升级说明

- 一次迁移：启动时执行 v050 建表与索引，旧库、旧备份、旧消息可直接读取；不回填历史边。
- 不产生边的记忆不受影响：首次整理只做同义主体归一与重复归档，悬空边只清理已存在的边。
- 召回总数、置顶上限与融合权重均未调整；邻居只作为补充候选，不改变原有排序口径。
- 建边失败不影响对话；整理失败只告警，可通过设置页按钮重试。

## 范围说明

本版已交付：v050 关系边表与仓储、`same_source` 建边、一跳邻居召回与关联说明、空闲整理三步、启动/每日调度与手动 API、统计卡三项观测、评测邻居用例。
