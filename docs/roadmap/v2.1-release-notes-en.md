# WorkBuddy For Me v2.1.0 — Release Notes

## WorkBuddy For Me 2.1.0 — Alive: idle-motion pools and a scriptable pet-interaction pipeline

Release date: **2026-10-17** · Platform: **Windows 64-bit** · Installer: built by the tag-triggered Windows pipeline, attached to the draft GitHub Release

v2.0 brought a 3D avatar in. v2.1 makes it move. A VRM model has no animation of its own — the spec pins it to a T-pose — so v2.1 adds an **idle-motion (VRMA) importer**, builds an **idle-motion pool** out of the built-in motion plus everything you have imported, **rotates through that pool on a timer**, and lets a **click fire a one-shot motion**. In parallel, pet interaction is no longer a pile of ad-hoc hit boxes: it is a normalized event → **Resolver gate** → **ActionExecutor** → **TriggerBus** pipeline, driven by a config table. The release also pays down its own debt: the four files this branch pushed past the repo-wide 300-line hard gate were split back to zero violations. Same three red lines: local-first (motion files stay in `data/motions/` on your machine), licensing boundaries (every imported VRM or VRMA passes GLB magic + extension double-validation and an explicit disclaimer checkbox; no assets are bundled or downloaded for you), and weak-model safety.

### 🎬 Idle motions: import, rotate, react

- **Import your own VRMA.** A new `motion_assets` table (migration v032) plus a `motion-service` that validates the `VRMC_vrm_animation` extension, stores the binary under `data/motions/`, and registers metadata. Four routes cover the surface: list, multipart upload, item detail/delete, and a file stream that accepts either the database id or the file reference so three.js can load it directly.
- **A pool, not a single clip.** The pool is the built-in `daiji.vrma` (always present, so you can never end up with nothing to show) plus every imported motion, with your selected one placed first as the initial idle. Loading is capped at 8 clips concurrently, and any single failure is skipped with a warning rather than aborting the whole pool.
- **Timed rotation.** Every 3–60 seconds (default 8) the app cross-fades to a different randomly chosen clip from the pool. Two settings — `motionRotationEnabled` and `motionRotationSeconds` — live in the existing voice-settings patch, editable from the motion list panel.
- **Click to perform.** Tapping the head or body now dispatches a `controller.tap` action, which plays a randomly chosen one-shot motion (`LoopOnce` + `clampWhenFinished`) and fades back to idle when the mixer reports it finished. Rotating pauses while a one-shot is playing so gestures are never cut off.

### 🧩 One mixer, and why it must be one

- Every clip plays through a **single AnimationMixer**. Two mixers would fight over the same normalized humanoid bones and the blend weights could not be resolved — the visible symptom being an idle clip snapping the model back into a T-pose. This is a hard constraint, not a style choice.
- A movement library means framing must change too: the camera fit is derived from the **union of the animated bounding boxes of every clip in the pool**, sampled per clip with a frame budget proportional to clip duration (900 frames total). Otherwise a wide-arm motion gets its limbs cropped by a scale computed from a calmer one.
- Two real traps fixed here: three.js `Box3.setFromObject` reuses a Mesh/SkinnedMesh bounding box unless it is nulled first (frame-by-frame sampling silently returned first-frame boxes — 0.587 instead of 1.089 sampled width), and the fit function has to be idempotent because it re-runs on every container resize.

### 🖐️ Pet interaction as a gated pipeline

- Events are normalized, then passed to a **pure resolver** that gates before it builds anything: quiet hours (23:00–06:00, only `system.voice-end` passes), relationship level (a Stranger cannot long-press the head or lift the pet; `raised`/`pinch` need Partner or above), and per-region cooldowns (head 500ms, body 800ms, raised 1500ms).
- A config table keyed by `touch::<region>::<gesture>` produces an `ActionChain` with priority, cooldown and an action list; the executor supports squash, expression flashes, taps, expression setting, subtitles, and forwards every event to the TriggerBus for the event director and awareness layers to subscribe to.
- The three-stage interaction state machine (`A_Start → B_Loop → C_End`, borrowed from VPet's animation model) now lives in its own module and only reports phase and overlay angles — the bone and expression layers do the actual writing.

### 🧹 Debt paid: deduplicated and split back under the line gate

- Dead code removed: the T-pose relax offsets, raw-bone mirrors, empty stub methods, and the second (conflicting) tap mixer.
- Duplication extracted: one GLB container parser shared by both sniffers, one skinned-bounds helper shared by both sampling paths, and one generic import wizard plus one generic list shell behind the four VRM/motion settings components.
- Hotspot splitting with zero behavior change: `vrm-controller.ts` (740 → under 300) gave up `MotionMixer`, `VrmFaceLayer`, `VrmPoseLayer` and `VrmInteractionState`; `vrm-canvas.tsx` gave up its loader and camera-fit modules; `pet-stage.tsx` gave up its hit boxes. Repo-wide >300-line violations: **4 → 0**.

### Known limits and deferred scope

- The pool is capped at 8 motions for concurrent loading and framing sampling; extra imports can still be selected as the idle motion but do not rotate.
- VRMA carries no license fields, so the importer never invents metadata; motion renaming/notes are not editable in the UI (the `source`/`note` columns exist in the table for later).
- Gestures are still tap and long-press; `double`/`swipe`/`release` exist in the event contract but the resolver does not cover them, and double-click remains a window behavior (focus main window) rather than a character action.
- The stored `interactionKind` is written but never read — reserved for per-kind action routing.
- `event.fire` and `chat.request` action types are not implemented (the executor warns and skips them); event-director integration lands in v2.2.
- v2.2 focuses on pet interaction feel, borrowing VPet's animation-graph state machine: turning region→chain into a configurable graph, adding drag physics (inertia, throw, edge snap) and state-driven idle selection.
- The installer and its SHA256 checksums come from the tag-triggered Windows release pipeline (see the artifact table above); the release was created as a draft and needs a manual review before it goes public.
