# v0.9 迭代方案：Flow Serving —— 让流程图走出本机对话，成为可调用的服务

> 状态：✅ v0.9.0 已完成（分支 feature/v0.9-flow-serving；基线 v0.8.0，main commit 1930d30；发布总结见 [v0.9-release-summary.md](./v0.9-release-summary.md)）
> 详细设计：见 [docs/plan/v0.9/](../plan/v0.9/README.md)（现状差距 / 功能设计 / 技术架构 / 实施风险 五篇）

## 1. 版本主题与目标

**一句话价值主张**：v0.8 让流程在浏览器里「画得出、调得试、对话里用得上」，但流程的生命被锁死在一次 SSE 连接和一个有人值守的对话里。v0.9 把执行与连接解耦——流程变成**有地址、有密钥、能排队、断了能续、重启能恢复**的服务：本机 HTTP API 可 curl、MCP Server 可被任意 MCP 客户端发现、queued 运行由进程内 runner 拾取执行。

**从「连接即运行」到「落库即运行」**，这是 v0.8 发布时就明确登记的技术债：

> v0.8 接受与 v0.7 tasks 相同的连接内生命周期；但 run/node_executions 先行落库，v0.9 再做「落库 queued + 独立 runner」解耦，保证现在不挡未来。——v0.8 roadmap §6

**版本范围声明**：v0.9 只做 **P1 服务化**（执行解耦 + 本地 HTTP API + MCP Server 暴露 + 无人值守安全策略）。定时/事件驱动自动化登记 **v0.10**（Electron 常驻端 scheduler，依赖本版本的 queued runner 与 api 触发器）；云端多用户、公网网关、Webhook 出站**不在本版本**。

**成功指标**：

- 已发布流程可一键「开启本地 API」，用 curl 携带密钥同步/异步调通，异步运行可轮询或经 SSE 跟踪
- WorkBuddy 作为 MCP 客户端连接自身暴露的 MCP Server（自举），能看到并调用全部已发布流程；stdio 与 streamable HTTP 两种承载至少各验证一次
- 执行中杀掉服务进程并重启：queued 运行被重新拾取、running 运行被标记中断并可「从失败节点重跑」或整体重跑，不产生僵尸运行
- 无人值守触发（API/MCP）下 danger/write 工具节点默认拒绝；流程可在发布时显式声明危险授权策略，策略随版本不可变
- 普通对话、画布试运行（v0.8 的人工 SSE 链路）行为零回归；`pnpm check` 与新增单测全绿
- 版本号 0.8.0 → 0.9.0，发布 tag v0.9.0

## 2. v0.8 留下的精确边界（本版本要偿还的债）

| # | v0.8 现状（代码证据） | v0.9 要变成 |
|---|---|---|
| 1 | 运行与 SSE 连接同生共死：`startEvents` 内部建 active 内存表，断线即 abort（`run-service.ts` active Map） | queued 落库即由 runner 拾取；SSE 订阅只是观察者，可断开重连、可多订阅者（只读） |
| 2 | queued 行在进程重启后永久卡死（active 表是内存 Map，无恢复器） | 启动恢复扫描：queued/running 残留行收敛为 interrupted，可重跑 |
| 3 | 对话触发（trigger=chat）human 节点自动拒绝、danger 工具节点直接拒绝，无策略位 | 发布时可配置无人值守策略（默认拒绝/预设授权清单），随版本固化 |
| 4 | 能力只能入不能出：MCP 模块只有 client（`mcp/client.ts`、`registry.ts`），jsonrpc 编解码已自实现但仅用于出站 | 复用 `mcp/jsonrpc.ts` 新增最小 MCP **server**：initialize/notifications/initialized、tools/list、tools/call |
| 5 | Electron 托管只 fork Web server（`server-manager.ts` 随机端口+bearer token 模式） | 同模式新增 flow 本地端点开关；stdio MCP 支持被第三方进程 spawn（打包内置 server 入口） |
| 6 | trigger 枚举仅 manual/chat（`FLOW_TRIGGERS`） | 新增 api、mcp（v0.10 再加 schedule/event）；运行视图与过滤随之扩展 |

## 3. 功能清单

### P1-1 执行器与连接解耦（runner）

- **用户故事**：我通过 API 提交一个跑得久的流程，不必保持连接；拿到 runId 后过一会儿回来看结果；服务中途更新重启，运行不丢。
- **验收标准**：
  - 新增进程内 `FlowRunQueue`：POST 创建 queued 运行后立即落库返回；队列（同进程串行拾取，v1 不做跨进程分布式锁）驱动执行，SSE/轮询只是观察通道
  - 同一 run 允许「单执行者 + 多只读观察者」：事件经进程内 pub/sub 扇出给多个 SSE 连接；观察者断开不影响执行
  - 启动恢复：扫描 queued/interrupted 状态——queued 重新入队，running（进程死亡时在跑）标记 `interrupted` 并附原因，提供「整体重跑」与「从失败节点重跑（v1 限无人工挂起点的线性段）」
  - 引擎执行核心（compiler/refs/engine/handlers）不改；run-service 拆出「队列调度」与「执行上下文构建」两层
- **工作量**：L（5 人日）

### P1-2 本地 HTTP API 发布

- **用户故事**：我把「网页摘要器」流程开启本地 API，用 curl 或其他程序（笔记软件、快捷指令）传入 URL 拿回摘要。
- **验收标准**：
  - 每个流程独立开关 + 独立密钥（`workflow_endpoints` 表，迁移 v013）：开启后得到 `POST http://127.0.0.1:<port>/api/public/flows/:key/invoke`
  - 同步模式（默认，短流程）：阻塞至终态返回 `{runId, status, output}`，超时上限可配（默认 60s），超时自动转异步返回 runId
  - 异步模式（`?mode=async`）：立即返回 runId；`GET .../runs/:runId` 轮询状态/输出，或 `GET .../runs/:runId/events` 只读订阅（带断点事件序号）
  - 鉴权：`Authorization: Bearer <key>`；密钥经 cipher 加密落库，只在创建/重置时明文展示一次；复用 v0.8 容器的 token-guard 中间件链，公开路由免会话但强制 bearer
  - 安全：仅绑 127.0.0.1；每密钥速率限制（默认 30 次/分，令牌桶内存实现）；输入仍走 start 入参 zod 校验
- **工作量**：M（4 人日）

### P1-3 MCP Server 暴露（自举验证）

- **用户故事**：我让 WorkBuddy 自己（或 Claude Desktop / 任意 MCP 客户端）通过 MCP 协议发现并调用我发布的流程。
- **验收标准**：
  - 复用 `mcp/jsonrpc.ts` 新增 server 端：`initialize`（声明 capabilities.tools）、`notifications/initialized`、`tools/list`（列已开启 MCP 暴露的流程，name 用 `flow_<短id>` 安全标识，description/inputSchema 复用流程契约）、`tools/call`（映射为 trigger=mcp 的 queued 运行，返回 MCP content 文本/结构化结果与 isError）
  - 两种承载：**stdio**（可执行入口，供桌面 app spawn 或外部程序 spawn）与 **streamable HTTP**（`/api/public/mcp`，单端口 bearer 鉴权，SSE 响应流在 v1 可不做，仅 JSON 响应）
  - 自举 E2E：在 WorkBuddy 的 MCP 设置里添加本机 server（http 承载 + bearer），tools/list 出现流程，对话中实际调用成功一次
  - 协议错误归一：未知方法/非法参数/流程不存在/拒绝执行（danger 策略）映射标准 JSON-RPC 错误码
- **工作量**：M（4 人日）

### P1-4 无人值守安全策略

- **用户故事**：我的流程里有 fetch_webpage（danger），我清楚风险，想让 API 调用时自动放行；但我不想让所有危险工具都裸奔。
- **验收标准**：
  - 流程发布设置新增「无人值守策略」：默认 `deny_all`（write/danger 节点直接失败，事件里给出明确策略原因）；可选 `allowlist`（仅对声明的具体 `toolName` 预授权，且不允许选 danger 类桌面控制工具）
  - 策略写入版本不可变快照（v1 存在 workflows 元信息 + 版本快照冗余存一份；改策略必须重新发布）
  - 运行时执行 tool 节点时：trigger∈{manual, chat} 走 v0.8 老链路（HITL/对话拒绝）；trigger∈{api,mcp} 走策略判定，不经 HITL，node_executions 记录 `decision: policy_allow | policy_deny`
  - UI：发布弹窗展示危险节点清单与策略选择，开启 API/MCP 时二次确认提示「该流程含 N 个写入/高危操作」
- **工作量**：M（3 人日）

### P1-5 运行可观测与恢复 UI

- **用户故事**：所有触发来源的运行在一个页面可查；API 跑挂的流程我能一键重跑；中断的运行状态清晰而不是永久转圈。
- **验收标准**：
  - `/flows` 增加「运行记录」视图（或编辑器内运行历史 tab）：按 trigger 来源/状态/时间筛选，API 运行显示来源徽章
  - interrupted 运行行内操作：整体重跑、从失败节点重跑；重跑产生新 run 并以 `parent_run_id`/`resumed_from_node` 关联（迁移 v013 增列）
  - 公开调用的错误响应体结构稳定（code/message/runId），供调用方程序化处理
- **工作量**：S（2 人日）

### P1-6 收尾

- 版本号 0.9.0（root/web/desktop/侧栏/e2e 断言）、README/roadmap、全量门禁、tag v0.9.0
- 工作量：S（1 人日）

**v0.9 总工作量参考：约 19 人日**（M0–M4，单人全职口径，含联调缓冲）。

## 4. 架构影响

| 层 | 影响 | 侵入性 |
|---|---|---|
| packages/shared | trigger 枚举扩 api/mcp；endpoint/strategy/run 状态（interrupted/resuming）契约；MCP server 侧类型；API 密钥 schema | **纯新增 + 枚举加法** |
| packages/database | 迁移 **v013**：`workflow_endpoints` 表 + workflow_runs 增列（parent_run_id/resumed_from_node/interrupt_reason/endpoint_id）；新仓储 | **纯加法**，v012 库平滑升级 |
| packages/core | `flow/queue/`（拾取器、pub/sub、恢复扫描）；run-service 重构调度层；`mcp/server/`（jsonrpc server 处理器，复用编解码）；无人值守策略门控；速率限制器 | 新增为主；run-service 有**一次受控重构**（接口拆分，保 v0.8 行为与测试） |
| apps/web | `/api/public/**` 公开路由组（bearer 鉴权中间件）；端点管理 UI；发布策略弹窗；运行记录筛选/重跑；MCP http 承载路由 | 新增为主 |
| apps/desktop | 打包新增 MCP stdio server 入口（bin）；菜单/设置增加「本地服务」开关与地址密钥展示（沿用 server-manager 随机端口模式） | 新增入口，不改既有 fork 链路 |
| 现有功能 | v0.8 试运行与对话调用保持原链路（manual/chat 触发器行为不变）；普通对话/知识库/桌面任务回归 | 必须零回归 |

## 6. 风险与取舍

| 风险 | 应对 |
|---|---|
| run-service 重构破坏 v0.8 已验证的人工挂起时序（先注册 Promise 再发事件） | 调度层与执行层拆分时保持「引擎事件生成器」零改动；队列只决定**何时执行哪个 run**，单 run 内部协议不动；用 v0.8 的 55 个 flow 测试做安全网 |
| 本地 API 被恶意网页/本机其他程序滥用（DNS rebinding、CSRF） | 仅绑 127.0.0.1；校验 Host 头防 DNS rebinding；公开路由不接受 cookie 会话，只认 bearer（天然免疫 CSRF）；默认关闭，需用户显式开启并展示密钥；速率限制 |
| 无人值守放开 danger 造成损害 | 默认 deny_all；allowlist 逐工具授权且永久排除桌面控制类（mouse/keyboard/window/app_launch）；策略随版本不可变；node_executions 留策略判定记录 |
| 多 SSE 观察者 + 队列并发引入竞态 | v1 同进程单执行者（拾取到即在内存标记认领 + 事务 UPDATE 防重复拾取）；pub/sub 只扇出不可变事件快照；跨进程锁明确推迟（桌面单实例 server） |
| 从失败节点重跑的语义复杂（上游作用域缺失） | v1 限定：重跑从目标节点开始但**重放其全部拓扑上游**（相当于从最近的安全点重放一段），而非用旧输出跳过上游；UI 文案讲清楚；真正的断点续跑（复用落库 outputs）登记 v0.10 评估 |
| MCP 协议覆盖面膨胀（resources/prompts/roots 全实现） | 只实现 tools 能力 + initialize/initialized，协议面与 v0.6 client 自实现同口径；其余方法返回 method-not-found |
| stdio 入口打包后原生模块 ABI | 复用 v0.7 已验证的「打包内置 Node + asarUnpack native 归集」方案，MCP stdio 入口与 web server 共用同一运行时 |

## 7. Non-Goals（本版本明确不做）

- ❌ 定时（cron）/ 事件触发（对话结束、文件变化等）自动化（**v0.10**，Electron 常驻端 scheduler）
- ❌ 公网暴露、隧道穿透、云端托管、多用户/鉴权体系、调用方配额计费
- ❌ Webhook 出站回调（异步结果只支持轮询/只读 SSE；v0.10 随自动化一起做）
- ❌ 跨进程/多实例分布式队列与锁（v1 单进程 runner；桌面/本地 server 本就单实例）
- ❌ 真正意义的断点续跑（复用历史节点输出跳过上游）；本版本重跑=重放拓扑上游段
- ❌ 同层节点并发、subflow 嵌套、循环（维持 v0.8 边界）
- ❌ MCP resources/prompts/completions 等 tools 之外的能力
- ❌ 公网 OAuth / 细粒度多密钥权限角色（v1 一流程一密钥，够用即可）
