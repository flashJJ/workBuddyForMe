# v0.6 迭代方案：会接活 — 技能扩展与 MCP

> 状态：📝 规划中（待评审后开工，前置：v0.5 发布）

## 1. 版本主题与目标

**一句话价值主张**：从「出厂自带几件工具」到「用户自己接工具」——MCP 生态 + 本地技能包，助手能干什么是用户定义的。

**成功指标**：

- 能添加至少一个真实 MCP 服务器（官方 filesystem / 本地自建均可），其工具在对话中被模型正确调用
- 技能包（manifest 声明式）从文件夹放入即被识别，UI 启停即时生效
- 写操作/联网操作默认弹窗人工确认（Human-in-the-Loop），无静默危险操作
- 全部门禁不降级

## 2. 现状与痛点

| # | 痛点 | 现状证据 |
|---|------|---------|
| 1 | **工具硬编码**：`enabledTools` 是固定枚举（TOOL_NAMES），加一个新工具要改 core 代码发版；用户无法扩展 | `packages/shared/src/schemas/assistant.ts` |
| 2 | **与 MCP 生态隔绝**：业界工具生态（filesystem、fetch、各种本地服务）无法接入；本地优先产品恰恰最适合 stdio MCP | 代码无 MCP 客户端 |
| 3 | **无权限分级**：工具执行无「读/写/联网」区分，无确认机制；工具数量多了以后不可控 | tool-runtime 直接执行 |
| 4 | **技能不可沉淀**：v0.5 的程序性记忆（「怎么写周报」的流程）没有承载物；同一套 prompt 组合无法打包复用 | — |

技能体系三要素——声明式定义（Schema）、注册发现（动态加载/热插拔）、安全执行（沙箱/权限/超时熔断/人工确认）。本项目已有最底层的工具调用链（v0.2），缺的是上面两层；MCP 是业界共识的技能生态标准接口。

## 3. 功能清单

### P0-1 MCP 客户端与服务器管理

- **用户故事**：作为用户，我在设置里填一个 MCP 服务器（stdio 命令或 HTTP 地址），它的工具就出现在助手的可选工具里。
- **验收标准**：
  - 支持 stdio（本地子进程）与 Streamable HTTP 两种 transport；连接状态可视（已连接/失败原因）
  - 服务器工具自动发现并注册进现有工具运行时，与内置工具同一套 tool_calls 链路（模型无感知差异）
  - 命名空间隔离：`mcp:<server>:<tool>`，避免与内置工具冲突
  - 服务器配置落库（DB 迁移 v006：`mcp_servers` 表），启用/停用即时生效，进程随应用退出清理
- **技术要点**：新包模块 `packages/core/src/mcp/`（client/registry/transport）；MCP SDK 选型（官方 `@modelcontextprotocol/sdk`）或按协议最小自实现（评审时定）；stdio 子进程生命周期由 desktop 主进程托管（Electron 退出清理）
- **工作量**：L（5-6 人日）

### P0-2 权限分级与人工确认（HITL）

- **用户故事**：作为用户，涉及写文件/联网/删除的操作，助手必须先问我，我可以选择「本次允许」或「一直允许」。
- **验收标准**：
  - 工具分三级权限：`read`（默认放行）/ `write`（本地状态变更）/ `network|danger`（联网与不可逆操作），内置工具与 MCP 工具统一标注
  - `write/danger` 级执行前弹确认对话框：展示工具名、参数摘要、目标（路径/URL），支持「本次允许 / 本会话一直允许 / 拒绝」
  - 拒绝时向模型回传结构化「用户拒绝」结果，助手能得体继续而非报错
  - 允许记录持久化（按 工具×权限维度），设置页可随时撤销
- **技术要点**：tool-runtime 执行前置钩子；确认 UI 走 SSE 事件 + renderer 弹窗（复用 v0.2 工具调用事件通道）；stdio 子进程环境变量白名单注入
- **工作量**：L（4-5 人日）

### P0-3 本地技能包（声明式 Skill）

- **用户故事**：作为用户，我把一个技能文件夹放进技能目录（或 UI 导入），重启后助手就多了一种「干活的套路」，且可一键启停。
- **验收标准**：
  - 技能 = 文件夹 + `skill.json` manifest：`name/description/version/permissions/promptTemplates/allowedTools/示例`；加载失败给出具体原因（不静默）
  - 两类技能形态（本期）：① 提示词技能（注入 system prompt 的流程性知识，承载 v0.5 程序性记忆）；② 工具组合技能（预绑定一组工具 + 推荐参数）
  - 技能页 UI：列表、启停、权限摘要、删除（删的是引用，源文件夹保留）
  - 内置 2 个示例技能随包分发（如「周报生成」「会议纪要整理」），作为模板示范
- **技术要点**：`packages/core/src/skills/`（loader/validator/registry）；manifest zod schema 进 shared；技能目录默认 `<dataDir>/skills/`，随 v0.4 备份轨一起备份（备分手册同步更新）
- **工作量**：L（5 人日）

### P0-4 技能与工具的可观测性

- **用户故事**：作为用户，我能看到这次回答用了哪些工具/技能、各自耗时与结果摘要。
- **验收标准**：消息下方工具调用卡片显示来源（内置/MCP 服务器名/技能名）、耗时、权限级别；LangSmith span 带属性
- **技术要点**：扩展现有 tool 事件与 citations 同通道
- **工作量**：S-M（2 人日）

### P1-1 内置实用技能与本地服务集成

- `fetch` 网页抓取技能（配合 v0.3 剪藏经验，readability 抽正文）、本地文件夹检索技能（配合 MCP filesystem）
- 工具超时熔断与连续失败降级：连续 N 次失败自动停用并提示
- **工作量**：M（3 人日）

### P1-2 技能调试台

- 设置页对单个工具/技能做「试一试」：填参数 → 看结构化结果，不经模型（排障利器）
- **工作量**：M（2-3 人日）

### P2 留白（登记不做）

- 代码执行沙箱（Docker/WASM）——本地单机成本高，先靠权限分级兜底，v0.7+ 评估 WASM 方案
- 技能市场/远程仓库分发、技能定义自动提取、多智能体编排（归 v0.7+）

## 4. 架构影响

- **packages/shared**：`TOOL_NAMES` 固定枚举 → 开放式工具描述（zod schema 化，向后兼容旧数据）；技能/MCP/权限相关 schema 与常量
- **packages/core**：新增 `src/mcp/`、`src/skills/`；`tools/tool-runtime.ts` 改造为统一注册表（内置 + MCP + 技能）+ 权限钩子；`chat-orchestrator.ts` 工具列表装配逻辑调整
- **packages/database**：v006 迁移（`mcp_servers`、`tool_permissions`、`skills_state`）
- **apps/web**：设置页两个新 Tab（MCP 服务器 / 技能）、确认弹窗组件、工具卡片升级
- **apps/desktop**：主进程托管 stdio 子进程生命周期、退出清理、单实例锁下的进程复用
- **兼容性**：旧助手 `enabledTools` 枚举数据自动映射到新体系；v0.5 的记忆/摘要功能不受影响

## 5. 里程碑拆分

| 里程碑 | 内容 | 验收方式 |
|---|---|---|
| M1 | MCP stdio 客户端 + 服务器管理最小闭环（连官方 filesystem） | 集成测试 + 手测文件搜索工具被模型调用 |
| M2 | Streamable HTTP transport + 权限分级 + HITL 确认 | E2E（确认弹窗/拒绝路径）+ 单测 |
| M3 | 技能包体系 + 2 个内置示例技能 + 技能页 | E2E + manifest 校验单测 |
| M4 | 可观测性 + P1 两项 + 全量门禁 + 发布（tag v0.6.0） | 全部门禁 + 发布流程 |

## 6. 风险与取舍

| 风险 | 应对 |
|---|---|
| MCP SDK 引入打包复杂度（v0.4 已有 canvas/tesseract 前车之鉴） | 优先协议最小自实现评审；若用 SDK，Next external + tracing 归集清单照 v0.4 模式登记 |
| stdio 子进程失控/僵尸进程 | 主进程统一托管 + 应用退出 SIGTERM 清理 + 超时熔断 |
| 工具过多导致模型选择混乱（工具描述质量决定选择准确率） | 每助手启用上限（沿用 max 10 约束）；描述规范化校验；评估集回归 |
| HITL 弹窗打扰 | 颗粒度到「工具×权限」的记忆白名单；read 级默认放行 |
| 技能 manifest 质量参差（社区文件夹） | 严格 zod 校验 + 加载失败可见 + 权限摘要前置展示 |

## 7. Non-Goals（本版本明确不做）

- ❌ 代码执行类技能的强沙箱（WASM/Docker）——先权限分级 + 确认制，v0.7+ 立项评估
- ❌ 技能市场/在线分发（本地优先，先做好本地文件夹形态）
- ❌ 多智能体协作/编排（v0.7+ 单独立项）
- ❌ 云端技能同步
- ❌ 移动端/远程访问入口
