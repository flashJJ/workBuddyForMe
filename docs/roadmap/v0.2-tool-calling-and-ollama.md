# v0.2 迭代方案：会动手、能离线

- **版本号**：v0.2.0
- **主题**：会动手、能离线（Tool Calling + 本地模型）
- **状态**：方案已定，待开工
- **预估工作量**：约 12 人天（一个人全职）

---

## 1. 版本主题与目标

v0.1 的助手是个「博学的嘴」——问什么答什么，但它**不会行动**：不知道今天几号、看不了网页、
绑了知识库也只会每轮机械检索；而且只能调云端模型，没有 API Key 或网络不佳就完全不可用。

v0.2 要让它长出两只手：

1. **会动手**：模型可以自主决定调用工具（查时间、读网页、按需检索知识库），过程对用户透明可见。
2. **能离线**：接入 Ollama 本地模型，断网也能对话，隐私敏感内容不出本机。

**成功指标**：

- 绑定知识库的助手面对「先寒暄再提问」的多轮对话，能**自主决定**何时检索（v0.1 是每轮强制检索，浪费且答非所问）。
- 断网状态下，Ollama 本地模型可完成一轮完整流式对话。
- 100% 的工具调用在 UI 上有过程可见（工具名、耗时、成功/失败），没有「黑盒沉默几秒」。

---

## 2. 现状与痛点

| 现状（v0.1） | 痛点 |
|---|---|
| ChatProvider 只有 chatStream/embed/listModels/testConnection | 没有工具调用通道，模型只能纯文本输出 |
| RAG 由助手「绑定知识库」后每轮强制检索 | 无需检索时也检索（费 token、引入噪声），模型没有主动权 |
| Provider 注册中心只有 openai-compatible，ollama 是占位 | spec 明确 Non-Goal，本地模型不可用 |
| 模型知识截止、无法看实时网页 | 「今天新闻/这个链接讲了啥」类问题无解 |
| 消息只能发和停 | 回答不好只能重开，缺重新生成/编辑重发/复制 |
| SSE 事件 meta/citations/delta/done/error | 无工具过程事件，扩展点已预留但未使用 |

## 3. 功能清单

### P0 —— 必做（构成版本主题闭环）

#### P0-1 工具调用内核（Tool Runtime）

- **用户故事**：作为用户，我提问后，模型发现需要外部信息时能自动调用工具，并把调用过程展示给我。
- **验收标准**：
  1. Provider 接口扩展 `toolDefinitions` 声明与 `tool_calls` 解析；不支持工具的模型优雅降级为纯对话。
  2. 编排器实现「模型输出 → tool_calls → 执行 → 结果回灌 → 模型再输出」循环，最多 5 轮，超限带着已有结果收尾。
  3. 工具参数用 Zod 校验；校验/执行失败时给模型一次自我纠正机会，仍失败则向用户可见地报错并降级回答。
  4. 每个工具单独超时（默认 15s），单轮对话工具总耗时上限 60s。
  5. 全部工具调用以 `tool` 事件经 SSE 下发并落库，刷新后历史中仍可展开过程。
- **技术要点**：
  - 新增 `packages/core/src/tools/`：`Tool` 接口（name/description/parametersSchema/execute）、注册表、执行器。
  - ChatProvider 增加 `supportsTools` 能力声明；OpenAI 兼容适配器透传标准 `tools` 字段并解析 `choices[].message.tool_calls`。
  - 工具结果进入对话上下文时按 token 预算截断，超长正文分页摘要。
  - 工具执行注入 AbortSignal，沿用用户「停止」按钮的中断语义。
- **工作量**：3 天

#### P0-2 三个只读内置工具

| 工具 | 能力 | 安全约束 |
|---|---|---|
| `current_time` | 当前日期时间（含时区） | 零依赖纯函数 |
| `knowledge_search` | 在指定知识库内语义检索（复用 v0.1 RAG 内核），由模型自主决定何时查、查什么 | 只能检索用户自己拥有的知识库 |
| `fetch_webpage` | 抓取公开网页正文（URL → 去模板正文） | 见下方 SSRF 防护 |

- **`fetch_webpage` SSRF 防护**（验收硬标准）：
  - 仅允许 http/https；DNS 解析后拒绝回环段（127.0.0.0/8、::1）、私网段（10/172.16/192.168）、链路本地（169.254）、元数据地址（169.254.169.254）。
  - 连接超时 8s、正文上限 200KB、重定向最多 3 跳且每跳重新校验。
  - 响应必须是 text/html 或 text/plain，拒绝二进制下载。
- **用户故事**：我贴一个链接问「这篇文章讲了什么」，模型能自己读网页回答；我问「知识库里面有没有提过报销流程」，模型自主检索而不是每轮硬塞资料。
- **工作量**：1.5 天

#### P0-3 助手工具白名单与过程渲染

- **用户故事**：我可以在助手编辑页勾选它能用哪些工具；对话时能看到「正在读取网页…（2.3s）」的过程卡片。
- **验收标准**：
  1. 助手新增「可用工具」多选（默认仅 `current_time`；未勾选的工具不进入 tools 声明）。
  2. v0.1 的「绑定知识库」语义调整为：绑定 = 授权 `knowledge_search` 可访问该库，**是否检索由模型决定**；保留一个「始终优先参考知识库」开关兼容旧行为。
  3. 前端消息流中渲染工具过程块：图标 + 工具名 + 参数摘要（如 URL/查询词）+ 耗时 + 成功/失败，可折叠查看结果。
  4. 内置「通用助手」默认不开工具，行为与 v0.1 完全一致（回归保证）。
- **工作量**：2 天

#### P0-4 Ollama 本地模型适配器

- **用户故事**：本机装好 Ollama 后，在设置里选「Ollama（本地）」就能拉取模型列表、选择并对话，不需要 API Key，断网可用。
- **验收标准**：
  1. 注册中心新增 `ollama` 协议：`listModels`/`testConnection` 走原生 `GET /api/tags`；chat/embed 走 Ollama 的 `/v1` OpenAI 兼容端点。
  2. 新建供应商时选 Ollama：baseUrl 默认 `http://127.0.0.1:11434`，隐藏 API Key 输入，连通性测试给出「未检测到本地 Ollama 服务」的友好引导（含下载链接）。
  3. Embedding 能力可选（如本地 bge/nomic 模型），配好后知识库摄入可完全离线。
  4. 不支持 tools 的本地模型：助手编辑页工具选择禁用并标注「该模型不支持工具调用」。
- **工作量**：2 天

### P1 —— 争取做（高频体验项，搭车交付）

#### P1-1 消息操作三件套

重新生成（基于上一条用户消息重跑）、编辑用户消息后重发（分支式新回合，不抹除历史）、一键复制代码/全文。
**验收**：重新生成沿用同一会话；编辑重发保留原回合可见（视觉折叠）。**工作量**：1.5 天

#### P1-2 联网搜索工具（search_web）

- 不绑定单一商业 API：支持配置一个 OpenAI 兼容风格的搜索端点（Tavily/博查等），未配置则工具不可见，不阻塞版本。
- **验收**：设置页可选填搜索服务 baseUrl + key；搜索结果以「标题+摘要+链接」回灌模型并在回答中产出引用。
- **工作量**：1.5 天（若超期顺延 v0.3，不阻塞发版）

### P2 —— 留白（登记不承诺）

- 工具调用的 token 用量分工具统计面板
- Ollama 模型下载/管理界面（本期只选择已有模型，不做拉取管理）
- 工具执行结果的缓存（同一 URL 短期复用）

## 4. 架构影响

### 改动包与方向（依赖方向保持无环）

```text
packages/ai      ChatProvider 能力扩展（supportsTools / tools 透传）+ ollama 适配器
packages/core    新增 tools/ 模块；chat-orchestrator 增加工具循环
packages/shared  新增 tool 事件类型、tool schema；assistant settings schema 增 enabledTools
packages/database migration v2：assistants 增 enabled_tools；messages 增 tool_trace（JSON）
apps/web         助手编辑页工具勾选、工具过程卡片、消息操作按钮、Ollama 供应商 UI
apps/desktop     无主进程改动（工具运行在 Next 子进程，沿用现有进程模型）
```

### 数据迁移（遵循 v0.1「读兼容、写收敛」约定，PRAGMA user_version 1 → 2）

```sql
ALTER TABLE assistants ADD COLUMN enabled_tools TEXT NOT NULL DEFAULT '["current_time"]';
ALTER TABLE messages  ADD COLUMN tool_trace TEXT NOT NULL DEFAULT '[]';
```

- v0.1 老助手迁移：绑定知识库的助手自动追加 `knowledge_search`，保证行为不回退。
- tool_trace 仅用于过程展示与上下文重建，不做关系表（单用户本地库，避免过度设计）。

### SSE 协议扩展（追加，不破坏 v0.1 事件）

```
event: tool
data: {"phase":"start","callId":"t_1","tool":"fetch_webpage","argsSummary":"https://..."}

event: tool
data: {"phase":"end","callId":"t_1","status":"ok","durationMs":2310,"resultSummary":"正文约 4.2k 字"}
```

事件序列变为：`meta → citations? → (delta | tool)* → done | error`，api.md 同步增补。

## 6. 风险与取舍

| 风险 | 应对 |
|---|---|
| 各家模型 Function Calling 稳定性差异大（参数乱拼、幻觉工具名） | Zod 校验 + 一次自我纠正 + 降级纯回答；只把白名单内工具下发，杜绝幻觉调用 |
| 工具循环失控（模型反复调工具烧 token） | 硬上限 5 轮、单工具 15s、总时长 60s；超限带已有结果强制收尾 |
| `fetch_webpage` 被利用做 SSRF（打本机服务/云元数据） | DNS 后 IP 段黑名单 + 协议白名单 + 重定向逐跳校验，全部有单测 |
| Ollama 工具能力参差 | supportsTools 能力声明 + UI 禁用提示；本地对话核心不依赖工具 |
| 老用户助手行为变化（强制检索 → 自主检索） | 迁移期保留「始终优先参考知识库」开关，默认开启一个版本，v0.3 再评估默认值 |

**取舍声明**：工具系统刻意只做**只读、无副作用**工具。写文件、执行命令、发消息等写入类工具
能力越大风险越大，需要配套授权模型，本版本不碰。

## 7. Non-Goals（本版本明确不做）

- ❌ 写入类/有副作用工具（文件系统、Shell、邮件、日历）
- ❌ MCP 协议接入与自定义插件市场（规划在插件化大版本统一设计，避免做两遍）
- ❌ 多模态（图片输入）、Office 文档、网页剪藏入库 → v0.3
- ❌ 桌面自动更新、安装器签名 → v0.4 / v1.0
- ❌ Anthropic / Gemini 原生协议（继续通过 OpenAI 兼容网关接入）
- ❌ 工具市场 / 用户自定义工具脚本（安全模型未成型前不开放）
