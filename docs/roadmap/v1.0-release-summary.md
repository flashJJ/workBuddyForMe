## 1. 主题与价值主张

v0.9 的 WorkBuddy 已经能闭环对话、动手执行、服务化接活，但它仍然「只能打字、没有形、不在桌面」：回复必须盯着屏幕读，助手是侧栏里一串配置，应用最小化即消失。

v1.0 的回答：

> 在不引入任何云服务、不增加强制费用的前提下，让工作台变成能听、会说、有形、即将伴身的桌面伙伴：语音全程跑在本机 sherpa-onnx 上，回复按句流式朗读、可随时打断；Live2D 角色口型随声音张合、表情随回复切换；说完即自动发送的半双工免手对话，让手可以留在键盘和工作上。

| 能力断点（v0.9） | v1.0 的回答 |
|---|---|
| 只能打字，无法边干活边听 | 本地 Kokoro 多说话人 TTS 按句流式朗读，103 音色按角色绑定，首句不等全文 |
| 全仓零音频输入 | SenseVoice 本地 ASR（热态 256ms / 4.6s 音频，约 18x 实时，ITN 数字日期归一） |
| 说话必须按住按钮 | 浏览器端能量 VAD：停顿自动发、播放态回声门控、开口即打断（零新增模型） |
| 助手没有「在场」形象 | 懒加载 Live2D：5 套官方样本角色、RMS 口型、8 标签表情、待机/点击动作；另有透明置顶桌宠伴身 |
| 助手只被动应答 | 空闲达阈值主动搭话 1-2 句：skip-history 轻量轮（不落库/无工具/RAG），临时气泡 + 同一条语音通道，用户操作立即中止 |
| 云语音隐私与费用顾虑 | 模型在本机推理，音频不出本机、不入库；模型首用下载、不进安装包 |

**关键边界**：半双工（不做免耳机 AEC/唤醒词/流式 ASR）；仅内置官方 Live2D 样本、不支持外部导入（授权红线）；语音跑在 Next 服务进程不碰 Electron ABI；桌宠 Windows 先行。

## 3. 架构演进

### 3.1 语音与形象的全景

```text
麦克风（主窗 renderer）                 扬声器
  │ 16k 单声道 PCM                        ▲ AudioBuffer 串行队列
  ▼                                       │（Analyser RMS→口型）
POST /api/voice/asr（multipart WAV）     voice_audio（base64 WAV 帧）
  │ SenseVoice 本地（int8）                ▲
  ▼                                       │
识别文本 → 既有 chat/stream 编排（记忆/技能/工具/Flow 全部复用）
              │ orchestrator delta
              ▼
        withVoice 旁路：切句 → stripForTts → Kokoro（fp32 本地，角色绑定 sid）
              │
              ▼  voice_state: thinking→speaking→idle
   Live2D（主窗右栏 / 桌宠小窗）：表情标签同源、RMS 口型、待机/点击
```

### 3.2 五个最关键的架构决策

**① 语音跑在 Next 服务进程，不碰 Electron ABI。** `/api/voice/*` 与既有路由同进程（生产态由内置官方签名 Node 托管），sherpa-onnx 的 `.node`/DLL 走 external + standalone 追踪 + prepare-server 兜底归集，无需 electron-rebuild；web 端零原生依赖。

**② 沿用 HTTP+SSE，不照搬 VTuber 的 WebSocket。** 对话仍走既有 orchestrator（记忆、技能、工具调用、Flow 全部白得），只新增 `voice_audio/voice_state` 两个事件；`voice=false`（默认）时不创建任何语音对象，纯文字路径零回归由代码结构保证而非靠测试补。

**③ 模型不进安装包、首用下载、默认国内镜像。** ASR 228MB + TTS 191MB 进 userData；hf-mirror 满速、大小校验、`.part` 原子改名；Live2D 作为静态资源随 public 分发但保持独立懒加载 chunk——重库与模型都不在首屏关键路径。

**④ 半双工 + 浏览器端能量 VAD，把复杂度挡在版本外。** 不做 AEC/唤醒词/流式 ASR；用播放态回声门控（阈值倍率+前后冷却）+ 开口 barge-in（epoch 作废 + abort 全链路）覆盖 80% 免手场景；VAD 纯前端状态机零新增模型，参数全部可单测。

**⑤ 表情标签成为跨层契约而不是渲染细节。** 8 标签在 @wbfm/shared 定义，提示词注入、消息上屏、复制、分享 HTML/Markdown、TTS 朗读文本共用同一套「解析→剥离」逻辑，多模型只在注册表做语义映射，杜绝标签泄漏到用户可见文本。

## 5. 踩坑记录（均已固化为代码或测试）

1. **Next dev 的 SWC 不做类型检查**：`useState` 命名为 `enabled`、JSX 误写 `checked={checked}`，dev 热更新照常通过，运行时 ReferenceError 被错误边界兜成「页面出了点问题」，并导致整个设置页与全部设置相关 e2e 失败。修复 + 教训：改受控组件必须跑 typecheck 或 e2e，不能只看热更新。
2. **客户端包络双重解包**：`apiGet<{data:T}>` 返回值再取 `.data`，语音设置/模型状态在前端恒为 undefined，朗读与麦克风门控实际从未生效；全仓统一直接消费解包后的 T。
3. **pixi.js 版本必须锁 6.5.10**：pixi-live2d-display 0.4.0 的 peer 是 pixi6，配 pixi7 产生双份 DisplayObject 实例，pointermove 刷 `isInteractive is not a function`。
4. **AudioWorkletNode 不被调度**：只连输入不连 destination 时 process() 不 tick；必须经 0 增益 GainNode 落地。StrictMode 重挂还会导致 wbfm:start 握手重复，握手只发存活链 + cancelled 检查前移。
5. **Mark 样本 LipSync group 为空数组**：不能照抄 model3.json，口型参数以 cdi3.json 实际声明为准（注册表注释写明）；注册表单测直接读模型文件，防止改名/拼写漂移。
6. **Playwright 受控 checkbox 二次点击翻回**：React Query 外部存储驱动时 `.check()` 可能在渲染提交前校验；AvatarSection/ToggleRow 用本地态（onChange 同步 setState + effect 回同步服务端值）根治。
7. **e2e 连续两次 PUT 串台**：勾选开关与切下拉各发一个 PUT，`waitForResponse` 夹在中间会捕获前一个响应；先消费开关 PUT，再用 `r.request().postDataJSON()?.avatarModelId===x` 谓词精确匹配。
8. **e2e 环境自身**：page.route 拦不住 AudioWorklet addModule 内部加载（404），用 addInitScript 桩 AudioWorkletNode + 实例级 defineProperty 包装 AudioContext（原型赋值被静默吞），serial 多测加幂等守卫。
9. **onnxruntime int8 内核因 CPU 退化**（见 M1）：真机验收必须记录合成速率，不能只看「能出声」。
10. **PowerShell 中文 curl 参数乱码**（跨版本老坑延续）：需要中文 body 时走 UTF-8 文件传递，不走命令行参数。
11. **Kokoro 引擎四件套缺一不可**：voices.bin + espeak-ng-data dataDir + 中英 lexicon + ruleFsts 必须同时配置，且 `maxNumSentences` 强制 1（传 2 每次合成都刷原生警告）。另外 @wbfm/voice 在 Next 以 **external 消费 dist**，只改 manifest 源码不 build 不生效，必须重建 voice 包并重启 next dev。
12. **voice_models 的 DB 状态与磁盘状态分离**：换模型后文件已在磁盘且大小匹配，DB 行仍可能是 missing；调一次下载接口（文件全部本地跳过）复验即可 markReady，别误判为下载器坏了。
13. **主动轮的三类测试陷阱**：① TS 会把「嵌套回调里赋值的 let」外层读取窄化成 null/never（spread 报 TS2698/7022），用 holder 对象属性绕开；② fake timer 下 waitFor 内部轮询也被挂起导致超时，改用 advanceTimersByTimeAsync + 手动 Promise.resolve 冲洗 SSE 微任务；③ ReadableStream abort 用例要让 fetch 先 resolve Response、再在 abort 事件里 stream.error，fetch promise 永不 resolve 的写法会 5s 超时。
14. **降级走查抓出的文案错位**：主动轮零文本返回时原复用 `ROUND_LIMIT_FALLBACK`（「工具调用已达轮数上限…」），但主动轮不挂任何工具，用户会看到莫名其妙的气泡；已改为主动轮专属中性短问候 `PROACTIVE_EMPTY_FALLBACK` 并加断言锁定。
