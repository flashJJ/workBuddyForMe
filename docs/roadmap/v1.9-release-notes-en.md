# WorkBuddy For Me v1.9.0 — Release Notes

## WorkBuddy For Me 1.9.0 — On Stage: watchable multi-agent collaboration and multi-assistant meetings

Release date: **2026-10-15** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-1.9.0.exe`

v1.8 made personality, appearance and model feel configurable. v1.9 makes multi-agent work **visible**: the v1.4 collaboration swim lanes move onto a Live2D stage you can open in a separate window, and a new **multi-assistant meeting** lets 2–4 assistants discuss one topic in turn under your control. One architectural rule holds for the entire release: **the stage is only a renderer**. It adds no execution permissions, never owns a run's lifecycle, and closing the stage window never aborts a collaboration or a meeting.

### 🎭 The stage: a read-only renderer

- Three Live2D slots (left/center/right; a fourth `farRight` seat for meetings) with focus, speech subtitles, nameplates, custom backgrounds and **persisted scenes** — managed on a full-screen `/stage` route and in a dedicated Electron window that is mutually exclusive with the desktop pet.
- A frame-rate watchdog measures frame times over a rolling window and automatically drops to a **power-saving mode** where only the current speaker is live Live2D and the other seats show cached static portraits.
- The stage speaks only one language — `StageDirection` (cast / focus / motion / speech). Two pure-function adapters feed it: collaboration-run frames and meeting frames. Speech attribution is taken **only from the server-recorded speaker id**, never from identity claims in the model's text.

### 👀 Watch a real collaboration run

- From any v1.4 agent run you can now choose **"Watch on stage"**. The stage is a second, read-only client: an in-process event bus fans run frames out, a bounded-wait registry attaches a stage opened before the run starts without dropping the first frame, and a finished run can be reopened for terminal replay (reviewer's approval line included).
- The stage has **no execution controls** — no approve/rework/abort buttons. Reconnect uses 409 backoff; losing the connection or closing the window leaves the run running in the main session.

### 🗣️ Multi-assistant meetings (2–4 members)

- **Manual** (`@name` in your message; several names speak serially in written order; a message with no mention is saved but triggers no model call), **Everyone once** (all members speak once in seat order, then the meeting returns to manual), and **Auto chain** (a member may suggest the next speaker with a trailing JSON block; the server hard-rejects non-members, self-nomination, the same member twice in a row, and anything past the **8-round cap**).
- **Anti-impersonation protocol**: each request is rebuilt from stored transcript and is always exactly `[system, user]`; the system section labels every transcript line (`[用户·X]` / `[助手·X]`), tells the model it may only speak as itself, and injects **only the current speaker's own character card** — other members' cards are never included, so personas cannot be mimicked.
- One meeting = one in-flight request = one `AbortController`: submitting while someone is speaking returns 409, and Interrupt/Finish aborts immediately. Meetings and transcripts persist (`v028` migration), and backup schema **v5** carries scenes, meetings and messages (dangling members are pruned on restore while their transcript lines are kept with name snapshots).
- Members are real assistants sharing one meeting-wide model, with **no tools, no MCP and no desktop control**; assistants never chat on their own initiative — every turn starts from your topic or an `@mention`.

### Known limits and deferred scope

- **Meeting conclusion summaries / action items (P1)** are deferred: a post-meeting LLM summary and any task creation did not ship; v1.9 stores the discussion and transcript only.
- **Timestamped replay / audience mode (P1)**: terminal replay re-renders the full transcript without a timeline; read-only audience links require an auth/share design that does not exist yet.
- Free-form N members, a card marketplace, spontaneous group chat, computer-use on stage, 3D VRM stages and mobile/web sharing remain P2 and unscheduled.
- External Live2D model import stays permanently disabled per the Cubism licensing boundary; no voice packs are bundled.
