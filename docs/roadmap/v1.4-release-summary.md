## 1. 主题与价值主张

v1.3 让知识库「答得准」，但复杂任务仍全部压在单轮对话上：多步任务的拆解、取证、自检混在一条消息里，模型既当规划者又当执行者，返工无轨迹，花费不可见。v1.4 按主题 A（会分工）引入**固定三角色、结构化交接、确定性状态机**的最小协作拓扑：

| 断点（v1.3 现状） | v1.4 的回答 |
|---|---|
| 复杂任务单轮直出，无拆解/无自检 | **Planner→Executor→Reviewer 固定拓扑**：规划产出结构化子任务单（SubtaskSpec zod 校验），审查逐条验收（approve/revise/reject），返工沿固定边回 Planner，禁止角色直连 |
| 多轮返工不可见、成本失控 | **三重预算硬治理**：轮次 1–5（默认 3）/步数 1–50（默认 20）/总 token 1 万–20 万（默认 8 万），任一触顶即交付「最佳结果+未竟注记」并收敛 `budget_exceeded` |
| 交接是自由文本，无法回放审计 | **Handoff 结构化落库**：`agent_handoffs` 表（roundNo/seq/from→to/payload JSON），终态 GET 回放泳道；SSE 五族帧实时推送 |
| 桌面 Agent 知识断点（v0.7 遗留 D2） | task-loop 注入 knowledgeBaseId/retrieve/observeMode；executor 两观察模式：screen（截图+视觉门控）/tool（合成观察+知识/MCP/Flow 白名单） |
| 桌面工具授权链路在协作中无归属 | 新增 `agent_tool_confirm` SSE 帧（携 taskScope=task run id），弹窗标注「协作任务 · Executor 发起」；决策仍走全局 confirmations，按 callId 解决 |
| 无人值守 API/MCP 调桌面工具风险 | Flow agent 节点在 api/mcp 触发且声明 desktop 域时**直接拒绝且不发起协作**（policy-gate permanent ban）；manual 画布试运行放行并内联 HITL |
| 多角色协作没有用户入口与可视化 | Composer「任务模式」会话级开关（默认关/不跨会话/不持久化）+ 消息内联角色泳道卡（预算条/终态样式）；tasks 页「协作任务」区段；Flow 试运行 agent 节点只读子泳道 |

**关键边界**：固定三角色（不做 N 角色/群聊）、首期串行单执行（不做并行多 Executor）、不做自由系统提示选角色、不做自动模型采购、协作运行记录不进备份（同级 workflow_runs 语义）、agent 对话无图片附件（通道只收 goal 文本）。

## 4. 踩坑沉淀（供 v1.5 参考）

1. **AsyncGenerator 终态必须显式 return 视图**：runner 四条终态路径都要 `return repo.getById()`，withCleanup 的 `return yield* gen` 才能透传给 events 消费方；SSE 的 done 帧不含终态枚举，客户端必须再 GET 权威对账。
2. **长 await 期间下发中间帧要靠邮箱原语**：runner 在 await executor.run 时无法 yield HITL 帧；GateMailbox.takeOrDone 与「执行定型 Promise」竞速比裸 Promise.race 稳——执行器同步先 post 帧时，队列判定先于 waiters 注册，裸 race 会漏帧。
3. **mock 决策器工具去重别用 `\S+`**：步骤摘要「[action] knowledge_search（理由）」中中文括号是非空白，捕获会吞掉工具名导致重复调用到步数耗尽；工具名用 `[a-z0-9_:]` 字符集。
4. **shared 联合类型加成员会逼出前端穷尽性缺口**：FLOW_NODE_TYPES 加 agent 后 node-meta/graph/utils/canvas 四处 switch/Record 必须同步；SSE 加帧后 web WebStreamSseEvent 与 AgentNodeInnerEvent 两处白名单都要补。
5. **tsc 对可选判别字段不收窄**：`run_failed.nodeId?` + `'nodeId' in e` 后仍可能是 undefined，须显式 typeof 收窄；Playwright APIResponse 是缓冲型（无 body.cancel），SSE 驱动靠「发请求不 await + 轮询详情」。
6. **e2e seed 必须同时配 chat+embed 模型**：只配 mock-chat 时文档编译永远排队；Playwright 冷编译首屏慢，首启向导跳过等待需放宽到 15s；下拉选项按 value（assistantId）选，不依赖 emoji 前缀。
7. **eval 路由冷编译会吞急停窗口**：slow 用例前要先 POST 一次不存在的 cancel 预热路由编译，slow 时长给 3s 余量。
8. **workflow_runs 无 updated_at**（v1.3 教训续）：agent-flow-node 测试夹具只插 workflows。
