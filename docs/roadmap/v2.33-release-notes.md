# v2.33.0 发行说明（含 v2.32 合并内容）

> 主题：**备份可托付——加密归档、附件引用计数与恢复核对**
> 发布：已合入 main · tag `v2.33.0` · 与 v2.32「数据可带走」合并发布
> 数据库：一次纯加法迁移 v051，`LATEST_SCHEMA_VERSION = 51`
> 备份格式：schema v8（容器层新增可选加密，内层结构不变）
> 完整方案：[v2.32](../plan/v2.32/README.md) · [v2.33](../plan/v2.33/README.md)

## 一、核心功能更新

### 1. 备份归档支持密码加密（v2.33）

- 导出时可选择启用密码保护，输出 `.tar.gz.enc` 容器；预检与恢复接受同一密码。
- 容器格式为 `WBFM-ENC1`：magic + 4 字节头长度 + 明文 JSON 头（版本、KDF、salt、N/r/p、iv）+ AES-256-GCM 密文（tag 附尾）。
- 口令派生使用 scrypt（N=2^15、r=8、p=1、keylen=32），每次导出生成新 salt 与 iv；内层仍是 v8 tar.gz，manifest 与轨道文件结构不变。
- 加密发生在整包缓冲上，沿用 500MB 归档上限；不引入流式加密依赖。

### 2. 恢复预检前置为独立只读步骤（v2.32）

- 新增 `POST /api/backup/precheck`：只解析 manifest 与轨道文件，不写库、不落盘解压目录。
- 前端恢复流程拆成「选择归档 → 预检确认 → 执行恢复」两步；版本不兼容时直接禁用确认。
- 恢复接口仍返回 `{ precheck, result }`，旧前端与旧客户端兼容。
- v2.33 起预检同时返回密码错误与缺失附件提示，密码错误可原地重试。

### 3. 附件引用计数内建（v2.33，迁移 v051）

- 新增 `attachment_refs(attachment_id, owner_type, owner_id, created_at)`，主键为三元组，`attachment_id` 外键级联，`owner_type` 限定 `message` / `artifact`。
- 消息写入时解析 `content_parts` 中的图片附件并登记 `owner_type='message'`；产物保存时登记 `owner_type='artifact'`。
- `AFTER DELETE ON messages` 触发器清理消息引用；附件删除由外键级联兜底。
- 启动后单飞回填历史消息与产物引用，写设置项 `attachmentRefs.backfilledAt`；`INSERT OR IGNORE` 幂等，失败只告警。

### 4. 孤儿附件分类与回收清单（v2.32 / v2.33）

- v2.32 新增存储占用分项统计与孤儿附件回收：扫描候选 → dry-run 展示 → 确认后移动到 `attachments/.trash/<date>/`，保留 7 天。
- v2.33 将候选分为两类：
  - `files`：目录中存在、附件表无对应记录；
  - `unreferenced`：附件行存在、引用数为 0、创建超过 7 天，并排除仍被任务截图引用的文件。
- 回收目录新增 `manifest.json`，记录文件清单与附件行快照；恢复时先重建附件行、再移回文件。
- manifest 缺失时退回「仅移文件」语义并在结果中标注；到期清理只删除 7 天前的日期目录。

### 5. 备份补全协作运行与角色交接（v2.32，schema v8）

- tasks 轨新增 `agentRuns.json`、`agentHandoffs.json` 与对应 manifest 计数。
- 恢复顺序固定为「协作运行 → 交接 → 回填 `task_runs.agent_run_id`」；v7 及更早归档缺文件按空数组处理。
- 重复恢复按主键幂等，不产生重复交接记录。

### 6. 产物跨会话批量打包（v2.32）

- 新增 `POST /api/artifacts/export`：接收产物/附件 id 列表，返回 tar.gz。
- 归档内附 `manifest.json`（条目 id、标题、格式、字节数、来源会话、创建时间）；单次最多 100 条、累计 200MB，超限不生成半份归档。
- 复用现有 tar.gz 打包实现，不引入 zip 或原生压缩依赖。

### 7. 导出与恢复核对报告（v2.33）

- 导出结果新增逐轨条目数、负载字节、耗时与总字节；前端展示本次摘要与「最近一次导出」。
- 恢复结果新增 `verification`：manifest 声明 vs 实际写入/跳过、缺失附件清单、恢复后未引用附件计数。
- 预检与恢复共用同一核对结构；差异只告警，不阻断恢复。

## 二、重要特性优化

- **恢复表单体验**：加密归档缺少或输错密码时不重置已选文件，就地展示密码输入并支持重试。
- **清理安全边界**：回收只移动不物理删除；未引用附件要求创建超过 7 天，避免误伤在途上传。
- **任务截图保护**：`task_steps.screenshot_path` 引用的文件不进入未引用候选，避免旧截图被回收。
- **空数据渲染**：备份面板、预检与核对在零计数、空轨道、缺失负载时给出明确空态，不再出现空白区块。
- **备份面板信息密度**：轨道说明补充协作运行记录；导出完成后展示加密状态、总大小与逐轨报告。
- **存储占用统计**：一次目录遍历按数据库、文档、附件、溢出、能力包、日志与其他分桶，结果短时缓存，避免设置页反复全盘扫描。

## 三、问题修复列表

1. **恢复「先执行后看结果」**：预检从恢复请求内抽出为独立只读接口，用户在写库前即可看到版本、计数与警告。
2. **v7 备份协作历史丢失**：schema v8 补全协作运行与交接，恢复后 `task_runs.agent_run_id` 不再回落 `NULL`。
3. **产物只能单张导出**：补跨会话多选与清单式批量打包，超限前置拒绝。
4. **存储占用不可见**：补分项统计与合计，设置页可直接判断空间去向。
5. **删除消息后附件残留**：补孤儿扫描与回收入口；v2.33 再补未引用附件分类与可恢复清单。
6. **明文归档外放风险**：补容器层密码加密，归档离开本机后不再可直接读取。
7. **附件引用无法回答「还被谁用着」**：补 `attachment_refs` 与启动回填，清理判定从文件级升级到引用级。
8. **恢复不可核对**：补导出报告与恢复核对，缺失附件与跳过项可见。
9. **密码错误提示不明确**：新增 `BACKUP_PASSWORD_REQUIRED` / `BACKUP_PASSWORD_INVALID`（均 422），前端就地提示并允许重试。
10. **运维审计 E2E 的 schema 断言滞后**：断言同步到 v051 的 51，修复 main CI 的 E2E 失败。

## 四、兼容性变更说明

- **数据库**：v2.32 无迁移（schema 50）；v2.33 增加一次纯加法迁移 v051（`attachment_refs` 表、索引与消息删除触发器），`LATEST_SCHEMA_VERSION` 由 50 升至 51。旧库启动时自动迁移，不删改既有数据。
- **备份 schema**：v2.32 由 7 升至 8（tasks 轨加法文件与计数）；v2.33 保持 8，仅在容器层增加可选加密。v1–v7 未加密归档仍可恢复，缺失字段按 0/空数组处理。
- **加密归档**：`.tar.gz.enc` 只能由支持 `WBFM-ENC1` 的版本读取；未加密导出与旧版结构一致。旧版本应用无法读取加密归档，但可继续读取未加密归档。
- **错误码**：新增 `BACKUP_PASSWORD_REQUIRED`、`BACKUP_PASSWORD_INVALID`，HTTP 状态均为 422；不区分密码错误与归档损坏，避免信息泄露。
- **接口**：`/api/backup/precheck` 为新增只读接口；`/api/backup/export`、`/api/backup/restore` 增加可选 `password` 字段；`/api/artifacts/export`、`/api/storage/*` 为新增接口。既有调用不传新参数时行为不变。
- **回收目录**：新增 `manifest.json`；旧版本生成的回收目录没有清单，恢复时按「仅移文件」处理。
- **设置项**：新增 `attachmentRefs.backfilledAt` 与 `backup.lastExport`；不改变既有设置键语义。

## 五、升级注意事项

1. **升级前先做一次未加密全量备份**：覆盖全部轨道，确认归档可被当前版本预检通过。
2. **迁移不可逆但可重复**：v051 只建表/索引/触发器，不修改既有行；重复启动不会重复执行。
3. **首次启动会跑引用回填**：历史消息与产物较多时需要一点时间；回填失败只告警，下次启动会重试，不阻塞对话。
4. **密码责任在用户**：加密归档没有找回入口；密码丢失等同于归档不可恢复。建议把密码与归档分开保管。
5. **恢复后仍需人工收尾**：知识库向量需重新索引；被脱敏的凭证需在设置中重新填写；VRM 模型文件不随备份携带，需重新导入。
6. **回收目录保留 7 天**：确认无误后再执行到期清理；清理只删除 7 天前的日期目录。
7. **加密归档体积与耗时**：scrypt 派生在低端设备上可能耗时明显；单次预检/恢复为串行请求，请避免同时发起多个大归档操作。
8. **合并发布**：v2.32 未单独打 tag，其能力随 `v2.33.0` 一并交付；回退时请整体回退到 v2.31.0 或更早版本。
