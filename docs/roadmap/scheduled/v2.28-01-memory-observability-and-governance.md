# 候选 02：记忆可观测与治理收口

> 来源：[v2.26 方案](../../plan/v2.26/README.md) §9、[v2.26 发行说明](../v2.26-release-notes.md)「范围说明」、[v2.15 已知边界](../v2.15-release-summary.md)。
> 状态：已排期（v2.28，方案见 [v2.28 方案](../../plan/v2.28/README.md)）；本版取 A+B+C，D 降级为 P2 本地报告。

## 1. 问题

v2.26 已经产出 `memory_events` 审计与 `GET /api/memories/stats` 计数，但能力只到接口层：

- 统计只在接口里，设置页看不到「多少记忆被取代、多少轮零召回、用户纠正了几次」；
- `memory_events` 没有保留期与轮转，长期运行会线性膨胀；
- 实时约束（过敏/忌口/禁止）是窄规则命中即写入，没有「这条识别错了」的确认与撤销入口；
- golden 评测是离线用例，没有线上回归看板，改动召回权重后只能靠单测兜底。

## 2. 现状证据

- `memory_events` 只写不清理（`packages/database/src/repositories/chat/memory/memory-lifecycle-repo.ts`）。
- 前端无记忆统计页；发行说明「升级说明」明确写「线上计数目前只提供接口，未接入设置页可视化」。
- 约束记忆可在管理页删除，但删除是通用操作，不是「识别纠错」语义。

## 3. 可选方案

| 方案 | 内容 | 成本 | 风险 |
|---|---|---|---|
| A. 统计前端 | 设置页记忆分组加一张统计卡：总量、superseded 比例、零召回率、纠正次数、最近审计 | 低中 | 只读，风险低 |
| B. 审计轮转 | 按 90/180 天或条数上限归档 `memory_events`，保留聚合计数 | 低 | 归档后历史不可逐条回溯 |
| C. 约束确认与撤销 | 实时约束命中后给一条可撤销提示；撤销写 `actor='user'` 审计并降权 | 中 | 打扰率需要控制 |
| D. 线上评测看板 | 定期跑 golden 集，记录 hit@3 等指标趋势 | 中高 | 依赖固定样例与离线模型 |

## 4. 风险

- 统计口径要与 v2.26 已实现的定义完全一致，否则「接口数」与「页面数」对不上。
- 审计轮转会削弱「可追溯」卖点，需要保留聚合与最近 N 条。
- 约束撤销入口若做成弹窗，会与现有「打扰率」原则冲突。

## 5. 待决策

1. 统计前端与审计轮转是否并成一个「记忆治理」小版本。
2. `memory_events` 保留期默认值（90 天 / 180 天）与是否可配置。
3. 约束撤销放在消息内联、管理页还是设置页。
4. golden 看板是本地报告（无服务）还是仅 CI 产物。
