# v4.25-01 事件触发：Webhook 与文件监听

> 状态：已排期（v4.25，规划中）
> 正式方案：[v4.25 选题](../../plan/v4.25/README.md) · [规格](../../plan/v4.25/spec.md) · [契约](../../plan/v4.25/contracts.md) · [任务](../../plan/v4.25/tasks.md)
> 来源：v4.24 版本总结「后续方向」第一条

## 1. 问题

流程已有四种开始方式：手动、对话、HTTP/MCP 端点同步调用、cron 定时。缺少**外部事件驱动**：

- 本机目录出现新文件时无法自动处理；
- 其他工具/脚本完成后无法通过回调触发后续流程；
- 只能靠定时轮询，存在延迟与空跑。

## 2. 现状与可复用资产

- v0.9 公开端点：Bearer 密钥、回环 Host 守卫、限流、统一错误包络；
- v4.23：持久化执行、checkpoint、恢复矩阵；
- v4.24：`workflow_schedules`、原子认领、单飞、状态回写、编辑器对话框骨架；
- v4.24 hotfix：`schedule` 已纳入无人值守门控（写/危险工具默认拒绝）。

## 3. 可选方案

| 方案 | 说明 | 取舍 |
|---|---|---|
| A. 扩展端点配置 | 在既有 `workflow_endpoints` 上增加"允许异步触发"开关 | 改动小，但一个流程只有一个端点，无法多触发器、无法文件监听 |
| B. 独立触发器表（采纳） | 新增 `workflow_triggers`，按类型存配置；Webhook 独立 Secret；文件监听独立服务 | 多触发器、可观测、可扩展；新增一张表和一层服务 |
| C. 复用事件域 EventDirector | 把 Flow 触发接入陪伴事件系统 | 语义耦合（事件剧本面向陪伴），会污染事件冷却/剧场模型 |

## 4. 采纳方案要点

- `webhook`：`/api/public/flows/triggers/:id`，Bearer Secret（只存哈希）、回环 Host、30 次/分钟、256KB body、可选幂等键；
- `file`：目录递归监听、扩展名白名单、800ms 防抖、启动重建、禁用/删除即释放；
- 两类触发均复用 `hasActiveRun` 单飞与 `last_*` 状态；
- 运行 `trigger='webhook' | 'file'`，与 `schedule` 一样按无人值守处理。

## 5. 风险与边界

- 不做公网暴露、HMAC、可视化映射、事件重试队列、分布式互斥；
- 递归监听存在平台差异，非 Windows/macOS 降级为根目录监听并记录状态；
- 事件触发不做重试，失败只记录状态，由用户或后续版本处理。

## 6. 为什么现在做

v4.24 刚刚把"触发配置 + 单飞 + 状态观测"这套骨架跑通，v4.25 在其上增加第二种事件源，复用度最高、边际成本最低；再往后才是多定时、时区与分布式调度等增强项。
