# v2.18-01 可交付产物与内容包（来源方案）

> 状态：已排期（v2.18）
> 正式方案：[v2.18 方案](../../plan/v2.18/README.md)
> 能力借鉴分析：[00-能力借鉴分析](../../plan/v2.18/00-能力借鉴分析.md)

## 1. 问题

v2.17 已解决「接得上、搜得到、装得进」，但 Agent 的产出仍停留在对话文本：

- 模型能写 HTML/Markdown，却没有落盘成文件的工具，用户拿不到可打开的图表/报告；
- 内置技能缺少图表设计规范，图表质量完全依赖模型自由发挥；
- 知识库模板只有空壳，缺少「内容 + 决策流程」的可选示例；
- 工具结果缺少统一的来源/覆盖率/未知项，结论可信度不可见。

## 2. 现状证据

- 技能 manifest 只支持 `promptTemplates` + `allowedTools`，不能携带多文件 references/assets（`packages/shared/src/schemas/knowledge/skill.ts`）。
- 聊天工具集没有文件产物写入工具；`ToolResult` 只有 output/summary/citations/images（`packages/core/src/tools/types.ts`）。
- 知识库种子只写名称/描述/分块参数，不带内容（`packages/core/src/knowledge/seed-starter-knowledge-bases.ts`）。
- 外部参考：Diagram Design（MIT）有 45 类图表选择树与 HTML→SVG/PNG 导出；HowToLiveBetter（CC BY 4.0）有 767 条结构化建议与「查了再答」技能；REA（MIT）强调证据来源/覆盖率/未知项；Moli（Apache-2.0）主张 structure-first 抓取。

## 3. 可选方案

| 方案 | 内容 | 取舍 |
|---|---|---|
| A（推荐） | 产物文件工具 + 精简图表技能 + 可选内容包 + 证据字段 | 范围可控；直接补「可交付」断点 |
| B | 只做图表技能，不落盘 | 成本最低，但用户仍拿不到文件，价值不完整 |
| C | 全量移植 45 类图表 + 内容包 + Rust 浏览器 + ArtCraft | 范围过大，跨技术栈，版本失控 |
| D | 只做内容包 | 依赖知识库导入，缺少通用的产物流水线 |

推荐 A：P0 做产物工具与 8–10 类图表技能；P1 做内容包、证据字段与 SVG/PNG；REA/Moli 只借思路，ArtCraft 不移植。

## 4. 风险

- HTML 产物 XSS / 外联：必须 CSP + sandbox + 禁脚本。
- CC BY 4.0 内容与 GPL-3.0 主仓的分发口径需 M0 复核。
- 医疗/法律/财务内容高风险：只检索引用，不做个性化判断。
- 中文字体与 PNG 导出依赖桌面端；Web 端先只做 HTML/SVG。
- 产物文件增长与清理策略。
- v2.17 尚未发布，v2.18 发布需等待或明确跳过 2.17 M6。

## 5. 待决策

3. 内容包：运行时下载 vs 随包内置；许可与署名方式。
4. 证据字段是否进入模型上下文，还是只做 UI/导出。
5. 是否复用能力目录承载内容包。
