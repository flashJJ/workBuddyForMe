# 候选 01：备份可托付——加密归档、附件引用计数与恢复核对

> 来源：v2.32 范围说明与 §9 下一版本候选、v0.3 附件 GC 留白、v2.15 本地主密钥实践。
> 状态：已排期 v2.33，正式方案见 [v2.33 方案](../../plan/v2.33/README.md)。
> 前序：[v2.32 方案](../../plan/v2.32/README.md)。

## 1. 问题

v2.32 让数据「能带走」，但还不能「放心托付」：

- **明文外放**：`.wbfm-backup` 内含对话、知识、记忆与附件，是明文 tar.gz；放到网盘或移动硬盘时无任何保护。
- **引用说不清**：附件与消息松耦合，删除消息只删 JSON 引用，附件行与文件仍在；「孤儿」只能判断「文件是否在附件表」，无法回答「还被谁用着」。
- **恢复不可核对**：恢复只返回导入/跳过计数，无法确认 manifest 条目是否落库、附件是否齐全、哪些条目被跳过。

## 2. 现状证据

- `packages/core/src/backup/export.ts`：直接 `packTarGz` 输出明文归档，`manifest.json` 可读。
- `packages/database/src/migrations/v003-multimodal.ts`：`attachments` 只有文件元数据，没有引用字段。
- `packages/core/src/services/assistant/attachment-service.ts`：产物复用附件表；消息图片通过 `content_parts` JSON 引用。
- `packages/core/src/backup/portability/storage-usage.ts`：孤儿判定只看「文件不在附件表」。
- `packages/core/src/secrets/cipher.ts`：已有本地主密钥 AES-256-GCM 实践，但主密钥绑定本机，不适合作为跨设备归档密码。

## 3. 可选方案

| 方案 | 内容 | 成本 | 风险 |
|---|---|---|---|
| A. 密码加密归档 | 容器层 magic + scrypt 派生 + AES-256-GCM；预检/恢复输入密码 | 中 | 密码丢失不可恢复；低端设备派生耗时 |
| B. 本地密钥加密 | 复用 keyring 主密钥加密归档 | 低 | 归档离开本机后无法解密，违背「可带走」 |
| C. 引用计数内建 | v051 新增 `attachment_refs`，写入登记、删除触发器清理、启动回填 | 中 | 迁移与回填耗时；遗漏删除路径 |
| D. 回收清单 | `.trash/<date>/manifest.json` 记录附件行快照，恢复可重建记录 | 低 | 清单与文件不一致 |
| E. 增量备份 | 基线 + 增量链式恢复 | 高 | 多轨水位与链状态，易半成品 |

## 4. 建议取舍

- P0：A 密码加密归档（跨设备可用、不依赖本机密钥），全链适配导出/预检/恢复。
- P1：C 引用计数内建；D 回收清单（让清理真正可恢复）。
- P2：导出概览与恢复核对报告。
- Non-Goal：E 增量备份（对多轨 `updated_at` 水位与基线链要求高，放入 v2.34 单独评估）；云同步仍永久关闭。

## 5. 风险与待决策

1. 派生参数固定为 scrypt N=2^15 / r=8 / p=1，需在真实归档上测量一次耗时，超过 1 秒则降为 N=2^14 并记录取舍。
2. 密码错误与「归档损坏」统一返回同一错误码，避免 oracle；前端只提示「密码错误或归档已损坏」。
3. 引用回填放在启动异步任务，失败不阻塞；是否需要设置页显示「回填进行中/失败」待 P1 评审。
4. 无引用附件回收要求 `created_at` 早于 7 天，避免误伤上传后尚未写入消息的在途附件。
5. 回收清单恢复时若附件 id 已被占用，按「跳过并告警」处理，不覆盖本机记录。
