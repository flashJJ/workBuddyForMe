# v2.21-01 来源方案：自由分支会话与回传

> 从 [v2.20-01 Lancer 借鉴分析](v2.20-01-lancer-borrowing-analysis.md) §5.3 拆出；正式方案见 [v2.21](../../plan/v2.21/README.md)。
> 状态：已排期（v2.20 之后的下一个版本，未启动 M0）
> 已决策：做自由分支会话；新表 `conversation_branches`；借回传/上限协议，不搬 Pi 会话树/worktree。

## 1. 问题

v2.20 让单会话的过程可见、阶段可分，但一个助手仍不能把任务拆成多条**真实会话**并行推进：

- 现有 v1.4 协作是固定 Planner/Executor/Reviewer 三角色，不是用户可自由派生的分支；
- v2.8 工作计划是单会话内的目标/待办，不产生独立上下文与独立交付；
- 子代理运行有独立 run，但不是可继续对话、归档、回传的会话；
- 长任务只能串行，父会话无法在等待子任务时继续处理其他分支。

## 2. 已定范围

| 编号 | 范围 | 说明 |
|---|---|---|
| P0 | 父子会话 | 从当前会话/消息派生自由分支会话；父会话保留主线，子会话独立上下文与消息 |
| P0 | 分支回传 | 子会话完成/失败生成结构化 evidence；父会话先核对再汇总，不自动重试/不自动派生 |
| P0 | 准入与上限 | 并发、深度、子节点数、任务树 Token 四项上限；祖先链环检测；先预留再 await |
| P0 | 图车道 | RunGraph 增加分支车道；父/子节点与回传节点可聚焦、折叠 |
| P1 | 分支管理 | 查看/重命名/归档/恢复；运行中禁止删除；删除先停止 |
| P1 | 预算与失败隔离 | 按会话树统计 Token；分支失败不污染父转录；重试只重试当前分支 |

## 3. 数据与协议

- 新表 `conversation_branches`：`id / parent_conversation_id / child_conversation_id / root_conversation_id / goal / status / return_evidence_json / created_at / updated_at`。
- 父子与根分别建索引；删除/归档级联在 M0 定；不改 `conversations` 核心表。
- 回传证据沿用 `worker_report` 语义：父/子会话 id、状态、摘要、产物引用、时间；父会话收到后必须核对再汇总。
- 准入在 core 纯函数 + 仓储事务中完成，UI 只展示拒绝原因。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| 与 v1.4/v2.8 重叠 | 定位为「用户自由派生会话」，不复用三角色调度；文档明确边界 |
| 预算失控 | 四项上限 + 会话树 Token + 环检测 + 预留 |
| 分支爆炸/图不可读 | 深度/子节点上限；默认聚焦当前分支；折叠与「全部分支」视图 |
| 删除/归档丢历史 | 参考会话归档策略；运行中禁止删除；删除前先停止 |
| 上下文串味 | 子会话独立上下文；回传只传摘要与产物，不复制完整转录 |

## 5. 待 M0 决策

1. `conversation_branches.status` 枚举与状态机（queued/running/waiting/succeeded/failed/cancelled/interrupted/budget_exceeded）。
2. 四项上限默认值（并发/深度/子节点/Token）与设置项是否暴露。
3. 派生入口（消息右键/命令面板/API）与父会话回传的展示形态。
4. 删除/归档级联与回收区策略。
5. 与子代理运行、v2.8 工作计划的边界和复用点。
