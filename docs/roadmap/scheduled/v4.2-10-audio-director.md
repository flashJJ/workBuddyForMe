# 统一音频导演：应用音乐、剧场 BGM、语音与音效共用一条总线

> 状态：**已排期 v4.2**，落地方案 B（AudioDirector 单例）；正式方案见 [v4.2 方案](../../plan/v4.2/README.md)。
> 关联：[音乐氛围文档](../../plan/archive/v3/v3.0/music-atmospheres.md)、[发布说明](../../plan/archive/v3/v3.0/release-notes.md)。
> 记录日期：2026-11-15。

## 1. 问题

音频能力已经有多套实现，但彼此不知道对方在做什么：

- 主工作区有全局音乐播放器（HTMLAudioElement + localStorage/IndexedDB）；
- 小剧场有自己的背景乐（HTMLAudioElement + 淡入淡出 + duck）与 WebAudio 音效；
- 语音播放有独立队列与音量控制；
- 三者靠「舞台路由卸载全局播放器」避免叠音，而不是统一调度；
- 没有统一的「谁应该被压低、谁应该暂停」规则，也没有设备切换与响度归一。

## 2. 现状证据

| 项 | 现状 |
|---|---|
| 全局音乐 | 11 首 CC0，主题曲轮播 + 氛围曲顺序播放 |
| 剧场 BGM | 4 首 CC0，按情绪切换，说话 duck 到 35% |
| 语音 | 本地 TTS，逐句播放，有播放队列 |
| 音效 | 剧场幕布/换句音用 WebAudio 合成 |
| 缺失 | 统一会话、优先级、duck 规则、设备选择、响度基线 |

## 3. 可选方案

| 方案 | 做法 | 收益 | 风险 |
|---|---|---|---|
| A 最小 | 抽出共享音频工具：音量淡入淡出、duck、循环、解锁 | 去重，行为一致 | 仍是多套播放器 |
| B 推荐 | AudioDirector 单例：音轨注册 + 优先级 + duck 规则 + 单一解锁 | 不会叠音，规则集中 | 改造现有播放器 |
| C WebAudio 全图 | 所有音频走一条 WebAudio 图与压缩器 | 响度/路由最强 | 迁移成本高 |

## 4. 推荐

先 B，不急着把所有音频迁到 WebAudio：

- 音轨类型：`music` / `theater-bgm` / `voice` / `sfx`；
- 优先级：voice > theater-bgm > music > sfx（音效可叠加但限流）；
- 规则：voice 播放时自动压低 music/theater-bgm；进入舞台暂停 music；退出恢复；
- 统一解锁：首次用户手势解锁所有音轨，失败静默；
- 响度：曲库入库统一 -16 LUFS，运行时只做相对音量。

## 5. 验收口径

1. 任意页面同时只存在一条背景乐（music 或 theater-bgm）。
2. 语音播放时背景乐按规则压低，结束后恢复；静音/暂停同步。
3. 首次手势解锁对所有音轨生效；被拦截时不弹错误。
4. 音量/静音/设备切换行为一致，刷新后偏好保留。
5. 不改变现有曲库与许可登记。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 统一单例引入循环依赖 | 音频内核放 shared 或独立包，只依赖浏览器 API |
| duck 规则过度压低 | 规则可配置，保留单测与真机采样 |
| 迁移期间双播放器 | 用开关按路由灰度，先接舞台与主工作区 |
