# 候选 04：文档质量收口

> 来源：[v2.19 已知边界](../v2.19-release-summary.md)、[v2.19-01 来源方案](../scheduled/v2.19-01-deep-document-rag.md)。
> 状态：已排期（v2.29），方案见 [v2.29 方案](../../plan/v2.29/README.md)。

## 1. 问题

v2.19 把文档解析、结构分块、表格引用与关系检索做出来了，但存量数据与低质输入还没收口：

- 升级前的文档不会自动重解析，结构面板/章节引用对旧文档不可用，需要手工逐篇触发；
- OCR 表格置信度上限 0.55，扫描件表格结构可能不准，界面只给警告不给修正入口；
- 关系抽取是规则实现，不做到指代消解与 LLM 生成，跨句关系容易漏；
- 多跳上限固定 2 跳 / 12 条边，复杂问题容易在第二跳断掉。

## 2. 现状证据

- v2.19 发行说明「已知边界」逐条列出旧文档不自动重解析、OCR 置信度上限、关系抽取为规则实现。
- `document_blocks` 按文档整批替换，重解析是显式动作，没有后台队列（`packages/core/src/services/knowledge/document-service.ts`）。

## 3. 可选方案

| 方案 | 内容 | 成本 | 风险 |
|---|---|---|---|
| A. 存量重解析 | 后台低优先级队列，按「旧 schema / 无结构块」筛选文档逐个重解析，可暂停/续跑 | 中 | 长任务占 CPU，需限速与进度可见 |
| B. OCR 表格修正 | 表格块展示置信度与低置信单元格，允许手工修正并回写 | 中高 | 修正后需重建分片与引用坐标 |
| C. 关系抽取升级 | 规则 + 轻量模型补指代与跨句关系，保留可解释来源 | 高 | 模型质量不稳定，评测成本高 |
| D. 多跳放宽 | 跳数与边数上限可配置，按问题类型自适应 | 低中 | 注入噪声与 token 膨胀 |

## 4. 风险

- 重解析会改动 `document_blocks / document_chunks` 与引用坐标，必须保证进行中的对话引用不悬空。
- 手工修正表格与「整批替换」的写入模型冲突，需要版本化或局部更新策略。
- 关系抽取升级需要新的评测集，否则无法判断是否变好。

## 5. 待决策

1. 只做 A（存量重解析）是否足以解决用户感知问题。
2. 重解析的触发时机（启动后台 / 设置页一键 / 单文档手动）。
3. OCR 修正是否需要，还是维持「只标注不修正」。
4. 多跳上限是否下放到单次检索参数，而不是全局设置。
