# 资产体积预算：把模型、贴图与动作纳入可执行门槛

> 状态：**已排期 v4.3**，按方案 A+B 落地；正式方案见 [v4.3 方案](../../plan/v4.3/README.md)。
> 关联：[进度日志](../../plan/v3.0/progress-log.md) 的资产管线遗留项。
> 记录日期：2026-11-15。

## 1. 问题

角色资产已经能分发，但体积与质量仍靠人工判断：

- 三个内置模型压到 22.29MB，但另外 13 个精简模型仍在 25–33MB；
- 贴图未统一压缩，模型之间的贴图分辨率与格式不一致；
- 100 个非标准 morph 的语义顺序只抽查过，没有自动校验；
- 安装包体积没有硬门槛，新增资产可能悄悄把包撑大。

## 2. 现状证据

| 项 | 现状 |
|---|---|
| 内置三席 | 9.28 / 6.00 / 7.01MB，合计 22.29MB |
| 其他模型 | 13 个精简模型 25–33MB，贴图未压缩 |
| 压缩手段 | morph POSITION 稀疏化 + 贴图 WebP 重编码 |
| 校验 | 家族校验 49 骨骼/118 morph/18 binds；meta 规范化 |
| 缺失 | 贴图预算、morph 语义顺序校验、安装包体积门禁 |

## 3. 可选方案

| 方案 | 做法 | 收益 | 风险 |
|---|---|---|---|
| A 预算门禁 | 单模型 ≤25MB、内置合计 ≤25MB、安装包 ≤?MB，脚本阻断 | 防止回涨 | 需要确定口径 |
| B 贴图管线 | 统一 WebP/尺寸上限/图集，按材质分级 | 直接降体积 | 观感损失 |
| C 可选下载 | 非默认模型改为可选内容包 | 安装包最小 | 首次使用多一步 |

## 4. 推荐

先做 A，再按模型逐个做 B；C 只用于非默认角色，不改变内置三席的开箱体验。

- 预算表写进仓库，`check:assets` 读取并输出超限清单；
- 贴图管线固定：颜色贴图 ≤2048、法线/ORM ≤1024、WebP 质量档位；
- morph 语义顺序用快照校验，新增/重排必须显式更新；
- 体积报告随发布说明归档，口径写清楚（解压后/安装包）。

## 5. 验收口径

1. `check:assets` 能在 CI 与本机运行，超限时给出模型与具体项。
2. 三个内置模型压缩后视觉抽查通过，表情/绑定回读一致。
3. 13 个非内置模型至少完成贴图预算，体积有下降记录。
4. 安装包体积与上一版本对比有数字，不出现无解释的增长。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 贴图压缩导致观感下降 | 逐模型截图对比，保留原始文件 |
| morph 重排破坏表情 | 快照 + 三席回归；不自动重排 |
| 可选下载影响离线体验 | 默认角色仍随包；可选包显式标注 |
