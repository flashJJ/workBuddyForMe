# v2.22-01 来源方案：分支会话收口与可靠性加固

> 来源：[v2.21 M4 发布后遗漏审计](../../plan/v2.21/06-M4-实施记录.md) §9；正式方案见 [v2.22](../../plan/v2.22/README.md)。
> 状态：已发布（v2.22.0，2026-11-04）
> 已决策：不单独发布 `v2.21.1`；本轮修复与遗留项统一进入 v2.22.0。

## 1. 问题

v2.21.0 已发布「自由分支会话」，但发布后审计与两轮深度排查留下两类缺口：

1. **已修未发布**：16 项修复（并发复检、模型继承、图状态同步、重命名、启动失败提示、证据产物、详情字段、归档折叠、右键入口、排队取消等）只存在于 main，安装包与自动更新通道仍是旧行为。
2. **未修且无承接**：8 项残余缺口没有版本归属，长期留在文档里没有执行者。

这些缺口共同指向同一件事：**分支会话已经能用，但「可靠、可恢复、可观测」还没有收口**。继续加新功能会让缺陷面扩大。

## 2. 已定范围

| 编号 | 范围 | 说明 |
|---|---|---|
| P0 | 补丁承接 | `v2.21.0` 之后的全部修复随 v2.22.0 进入安装包与更新通道；不再单独发补丁 |
| P0 | 备份完整性 | 分支事件随备份导出与恢复，恢复后图车道/回传节点不依赖重新运行 |
| P0 | 终态回传补齐 | 中断/取消分支也产出可识别回传（无摘要、需核对），父会话不再「静默结束」 |
| P0 | 失败重试 | 失败分支提供独立重试入口，同时保持「终态不可回 running」契约 |
| P1 | 运行中预算熔断 | Token 超限从「准入拒绝」扩展到运行中收敛为 `budget_exceeded` |
| P1 | 实时帧 | 分支事件接入 RunGraph 实时推送，轮询保留为降级路径 |
| P1 | 真实供应商并行验收 | 有密钥时纳入并行/失败隔离 e2e；无密钥时显式跳过并记录原因 |
| P2 | `waiting` 语义收口 | 确有等待场景则写入该状态；没有则从契约为可选项并加测试守卫 |

## 3. 数据与协议

- **零迁移**：`session_events`、`conversation_branches` 已有表结构足以承载事件导出与终态补齐，`LATEST_SCHEMA_VERSION` 保持 45。
- 备份 conversations 轨新增可选 `branch-events.json`（仅 `scope='branch'` 的事件），缺失时按旧档兼容、恢复为空事件。
- 恢复顺序：会话 → 分支 → 分支事件；父/子会话缺失时事件一并跳过，避免悬挂引用。
- 失败重试不改状态机：重试等于「以失败分支为来源新建一条分支」，旧分支保持终态与 evidence 供追溯。
- 运行中预算熔断复用 `branch-limits` 纯函数；熔断后写 `branch_status` + `branch_returned`，预留归零。

## 4. 风险

| 风险 | 缓解 |
|---|---|
| 补丁承接范围被遗漏 | M0 冻结「补丁清单」，逐条对照 v2.21 §9 已修表打勾 |
| 备份事件膨胀 | 只导出 branch scope；按分支 id 过滤；超限时截断并记录 `truncated` |
| 重试语义被误解为「重启同一分支」 | UI 文案明确「重试将新建分支」；旧分支标注失败原因 |
| 实时帧引入并发与乱序 | 复用 v2.20 `runGraphLiveBus` 快照语义；前端保留轮询兜底 |
| 真实供应商 e2e 不稳定 | 密钥缺失显式跳过；CI 只跑 mock 必过用例 |

## 5. 待 M0 决策

1. 备份事件格式：独立 `branch-events.json` 还是并入现有 `branches.json`。
2. 重试入口形态：分支卡按钮 / 命令面板 / 两者都有。
3. `waiting` 去留：保留并补测试守卫，或从契约降级为「保留但无写入路径」。
4. 实时帧范围：只推 branch 事件，还是整图快照增量。
5. 版本号与发布节奏：直接 `v2.22.0`，不做 `v2.21.1` 补丁。
