# v2.16.0 发行说明

> 可导航：目录按能力收拢、入口统一、页面少拼装。

## 重点

- **目录按能力分区**：`shared/schemas` 84 → 1 个直接文件（12 个子域）、`database/repositories` 70 → 1（11 个子域 + `mapper/`）；`core/services` `agents` `chat` `flow` 53/53/46/35 → 1；web `settings` `chat` `events` `avatar` `flow-editor` 55/46/40/36/23 → 1，`lib/hooks` 26 → 0（7 个域入口）。共移动 561 个文件，只改位置与引用，功能、UI 与 API 零变更。
- **统一公开入口**：31/31 个多文件 web feature 均有 `index.ts`；跨 feature 深引用 91 → 0，`@/lib/hooks` 深引用 0。feature 根入口只导出页面级组件，跨域能力按子域入口引用，避免一次性拉入整域代码。
- **设置页少拼装**：设置页 4 个分组改为「首次进入视口才取数」，面板照常挂载，锚点与交互不变。首屏 API GET 由 29 次 / 22 条 distinct 路径降到 9 次 / 7 条（−68.2%），峰值并发 15 → 4，首屏响应体约 44 KB → 5.6 KB。首屏未达标的页面改用聚合端点的方案被明确否决，现有接口零改动。
- **结构规则可执行**：`pnpm check` 新增目录预算、公开入口、跨域引用、循环依赖四类检查；25 个存量超标目录按基线冻结，新超标或增长直接失败。`docs/architecture.md` 给出目录地图、依赖矩阵、入口规则与「新增文件放哪里」的决策树。

## 修复

- **无 `GET /models` 的厂商连接失败**：火山方舟 Agent Plan 等厂商不提供模型列表接口，原实现把 404 当成致命错误，导致设置页「Agent 无法找到」。现在模型列表 404 归一化为可恢复状态，提示手动填写 Model ID；若已配置对话模型，则改用首字探活验证连接，不再依赖模型列表。新增火山方舟（Ark）与 Agent Plan 两个预设。
- **桌面端下载 401**：能力包示例、审计 JSONL 导出与时间线 ZIP 导出从普通 `<a href>` 下载改为携带 `X-WBFM-Token` 的请求，修复桌面模式下 `UNAUTHORIZED`（缺失或无效的访问令牌）。

## 迁移

- **零迁移**：`LATEST_SCHEMA_VERSION` 保持 42，不新增表 / 列 / 索引。
- 旧库直接可开；本版不改数据结构，旧版本也可直接打开 v2.16 的库。
- 不新增运行时依赖，不拆分包，不改 API 契约与错误码。

## 工程门禁

- `pnpm check` 通过（typecheck / lint / 行数 / 结构 / 循环）；单测 2882 例；生产模式 Web e2e 139/139；桌面冒烟 10/11（`computer-input` 记事本链路为环境相关失败，与上一版基线一致）。
- 首屏 First Load JS：`/settings` 479 kB（+4.8%）、`/chat` 461 kB（+1.8%）、`/flows/[id]` 387 kB（+0.3%），均在 ≤5% 门槛内。
- 循环依赖：扫描 2028 个模块 / 7334 条边，8 个存量 SCC 全部登记，无新增。

- `WorkBuddyForMe-Setup-2.16.0.exe.blockmap`、`latest.yml`（自动更新元数据）

Windows 10/11 x64；Web 模式可跨平台。默认不需要云账号，数据、密钥与向量索引留在本机。
