## 一句话

v4.24 让流程按 cron 自己开始：配置落库、重启不丢、错过只补一次、上一个没跑完就跳过——一个流程一条定时，系统本地时区。

## 新功能

### 定时触发

- 流程编辑器工具栏新增「定时」入口（仅已发布流程可用）；
- 支持 5 字段 cron：通配、列表、范围、步长，日/周同时限制时任一匹配；
- 对话框展示下次与上次运行、立即运行、删除配置；
- 定时触发使用生产版本，`run_started.trigger = schedule`。

### 持久化调度

- 新增 `workflow_schedules` 表（迁移 v054，纯加法）与到期索引；
- 进程内调度器每 30 秒扫描到期项，启动时立即补跑一次；
- 原子认领：以旧 `next_run_at` 为条件推进，避免重复触发；
- 单飞保护：同流程有 `queued / running / waiting_human` 运行时跳过并记录 `skipped_busy`。

### 错过补偿

- 应用关闭期间跨过多个执行点，重启后只补跑一次；
- 下次时间从当前时刻重新计算，不做逐次回放。

### 门控与安全

- 定时触发为非交互：写 / 危险工具默认拒绝；
- 人工节点不挂起，按拒绝处理；
- 未发布流程不能保存定时，调度时记录 `error` 而不创建运行。

## 改进

- 流程从「被调用」扩展为「按计划自动开始」；
- 调度结果可观测：下次时间、上次时间、上次状态（created / skipped_busy / error）；
- 配置保存时即校验 cron 并计算下次时间，写错表达式会在保存阶段被拒绝。

## 兼容性

- 数据库迁移 v054 纯加法，不改现有表；
- 备份/恢复沿用整库机制，无需额外映射；
- 未配置定时的流程行为与 v4.23 一致；
- 回退代码后定时不再触发，配置残留不影响旧版本运行。

## 验证

- `pnpm check`：类型、Lint、行数、目录、循环依赖、MSW、框图、资产、surface、E2E 隔离全绿；
- `pnpm verify:local`：eval、perf、unit、integration、web build 全绿；
- 定向测试：cron 解析、调度器补偿/单飞/认领、仓储与迁移、端到端触发。

## 已知限制

- 暂无 webhook 与文件监听触发；
- 一个流程只支持一条定时；
- 统一使用系统本地时区，不提供每定时时区；
- 错过多个周期只补一次；
- 调度为单进程内实现，不做多实例互斥。
