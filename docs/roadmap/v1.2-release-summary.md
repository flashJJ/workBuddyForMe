## 1. 主题与价值主张

v1.1 把内部工程债清零后，代码质量已具备继续长功能的条件；但**分发形态**停留在「作者本机手工出包」：exe/安装器全是 Electron 默认图标、NSIS 只有英文且无许可页、代码签名与 rcedit 被整体关闭、CI 没有 Windows 打包、更新源停在 v0.9.0；**使用形态**上深色模式半套、无障碍无体系、文案全硬编码中文、新用户零引导。v1.2 不新增长功能线，补齐「从下载安装到第一次成功对话」链路上所有「不像正式产品」的断点：

| 断点（v1.1 现状） | v1.2 的回答 |

| NSIS 一键英文包、无许可页、卸载行为不明 | assisted 安装器（oneClick:false，可改目录/程序组/桌面与开始菜单快捷方式）、简中默认可切英文、GPL 许可页、卸载项显示名带版本；卸载默认保留数据，交互卸载二次询问，静默卸载（升级链）永不删 |

| a11y 无体系：弹窗原生 confirm、命令面板无语义、无焦点环 | skip link + main landmark、命令面板 combobox/listbox/aria-activedescendant、全局 :focus-visible、ConfirmProvider 替代 10 处 window.confirm（危险动作默认焦点落取消）、axe-core/playwright 6 场景门禁 serious/critical=0 |

## 3. 关键设计决策

**① 签名只做流程、不买证书。** 双态构建把「品牌资源（rcedit 图标/版本）」与「可信度（signtool）」解耦：无证书路径也能出完整品牌安装包，CI 只留两个 secret 注入位，购证后零改配置。

**② appId 冻结让位于更新链连续性。** `com.wbfm.desktop` 与 productName 不动——Windows userData 与注册表/更新器身份据此推导，改名即被识别为新应用、切断 0.9→1.2 更新；品牌表达全部落在图标/显示名层。

**③ 主题「设置表真源 + localStorage 缓存」而不是反过来。** 修复 v1.1 双写缺陷：缓存只负责首帧防闪，水合后一律以设置 API 为准并回写；system 态在 init script 阶段就用 matchMedia 解析，避免深色用户首屏白闪。

**④ i18n 自研而非引库，结构真源在编译期发力。** Electron 内嵌 SPA 按设置切语言、非 URL 分段，路由型 i18n 库不适配；zh 字典 satisfies 锁结构、MessageKey 联合锁键、en 为 DeepPartial + parity 叶子键对齐测试，缺键在测试态直接抛错，运行期三级回退保底——新增语言或漏译都无法悄悄发生。

**⑤ 首启引导复用正式业务链路，不造平行实现。** Ollama「检测」就是 create provider → testConnection → remote models；语音下载就是正式下载 API。向导是既有能力的编排壳，避免引导页与设置页行为漂移。老用户由 v016 迁移按「有无用户痕迹」回填，升级不弹向导。

**⑥ 卸载默认不删数据，且静默卸载永不删。** 本地优先产品数据删除不可逆：deleteAppDataOnUninstall 恒 false，仅交互卸载弹一次 YES/NO；electron-updater 跨版本以 /S 调旧卸载器，静默分支跳过询问，杜绝升级误删。

**⑦ a11y 门禁只卡 serious/critical。** moderate/对比度问题出报告人工逐项关（亮色 muted-foreground 即按 4.5:1 修掉），避免一次性红灯淹没；原生 confirm 替换为统一对话框同时获得了焦点管理与默认按钮控制。

## 5. 踩坑记录（均已固化为代码、配置或测试）

1. **首启弹窗改变全局初始态，e2e 串行套件集体被遮罩拦截。** web e2e workers:1 共享一个临时数据根：向导一旦自动弹出，后序所有 spec 找不到表单元素（语音/Live2D 准备用例集体超时 120s）。解法：向导 spec 文件名加 `00-` 前缀保序最先执行，入口先 PUT hasOnboarded=false 确定性复现，走完落 true，为全套件「消费」掉首启态。
2. **FAQ 锚点 chip 的可访问名污染导航严格匹配，并引发跨文件连锁失败。** 帮助页英文问题含 "…after adding it? Chat requires…"，Playwright `getByRole('link',{name:'Chat'})` 子串匹配同时命中侧栏与 chip → strict violation；该 i18n spec 在切回中文前中断，服务端语言留在 en-US，后续中文断言 spec 全部失败。修复：导航断言一律 `exact:true`，spec 加 beforeAll PUT language=zh-CN 保证可重入。
3. **仓库不变量扫描会管到 i18n 文案里的数据目录名。** config 包 repo-invariants 测试禁止 config 与 desktop 主进程之外出现 `.workbuddy-for-me` 字面量；FAQ 初稿写了该名导致单测红。数据位置说明改写为「用户目录下的应用私有数据目录」+ WBFM_DATA_ROOT 环境变量，路径命名权只归 @wbfm/config。
4. **NSIS 自定义脚本被编译两次。** installer.nsh 同时参与安装器/卸载器构建（BUILD_UNINSTALLER），变量与钩子必须包在 ifdef 内，否则安装器目标「Var 声明未引用」warning 6001 在 warningsAsErrors 下直接构建失败；卸载器还存在 $INSTDIR 自删除竞态残留空壳，需 customUnInstall 里兜底 RMDir。
5. **sqlite-vec 原生绑定不被 nft 追踪。** vec0.dll 由 `sqlite-vec-windows-x64` 按平台 require，Next standalone 文件追踪默认漏掉，dev 正常、真机装包启动即失败；prepare-server 显式白名单归集。
6. **React Hooks 规则在异步流程里最易破。** Ollama 面板初版把 useRemoteModels 放在 detect 函数内条件调用（rules-of-hooks 违规），重构为顶层无条件调用、provider 未定时空转；另 vitest 下 vi.fn().mock.calls 类型为 any[][]，解构元组需整体断言为 `Array<[string, RequestInit | undefined]>` 才能过 tsc。
7. **toMatchInlineSnapshot 不输出值为 undefined 的属性。** 手写快照包含 keysAlt:undefined 字段而序列化结果没有，改用 `-u` 让 Vitest 生成真实形态，快照锚点以实际输出为准。
8. **PowerShell 不支持 bash heredoc 与 `&&`。** 多行提交信息改用 `git commit -F` 临时文件；命令串联用 `;`/换行（本版本操作环境教训）。
