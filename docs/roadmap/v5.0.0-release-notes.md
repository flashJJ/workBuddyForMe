# v5.0.0 发行说明：会兜底

> 状态：🚧 待发布（5.0.0）
> 主题：**会兜底——失败补偿、运行快照、运行治理、Agent 门控与 Webhook HMAC**
> 类型：大版本（迁移 v057，五次加法迁移）
> 方案：[v5.0 方案](../plan/v5.0/README.md) · [版本总结](../plan/v5.0/version-summary.md)

## 新增

- **失败补偿队列**：无人值守（api/mcp/schedule/webhook/file）且可重试的失败运行自动进入补偿，原运行 + 最多 3 次重试，退避 30s/2m/10m；状态 `pending/retrying/recovered/exhausted/cancelled`，重启后继续。
- **批量重放**：运行中心多选 ≤20 条失败/中断运行，整体重放或从失败节点重放，逐条返回结果，部分失败不阻断。
- **错误分类与建议**：`config/auth/network/timeout/rate_limit/tool/data/version/unknown` 九类，仅 network/timeout/rate_limit 自动补偿；运行中心展示类别与下一步建议。
- **运行图快照**：运行创建时固化 FlowGraph canonical JSON 与 SHA-256；续跑/重放优先用快照，其次按 `run.version` 精确取，缺失时明确阻断。
- **版本差异提示**：运行详情返回 `versionCheck`，展示新增/删除/改类型节点；支持「按原版本续跑 / 按新版本重放」。
- **运行保留与清理**：成功 30 天、失败 90 天、每流程 500 条；排除待处理补偿，支持 dry-run 与审计。
- **运行健康面板**：调度心跳、文件监听、补偿计数、端点、定时 missed、触发器最近触发、保留统计。
- **定时错过计数**：`missed_count` 上限 100、`last_missed_at`，仍只补跑一次。
- **Agent 写工具门控**：无人值守触发下 Agent 内部写/危险工具统一走流程级策略，拒绝写 `flow_agent_tool_denied` 审计。
- **Webhook HMAC**：可选 `bearer/hmac/both`，HMAC-SHA256 + 300s 时间窗；轮换同步更新 hash 与密文，旧钥立即失效。

## 变更

- 迁移 v057：`workflow_runs` 增 `graph_snapshot_json/graph_hash/replay_batch_id`；新表 `flow_run_compensations`；`workflow_schedules` 增 `missed_count/last_missed_at`；`workflow_triggers` 增 `secret_cipher`；
- `LATEST_SCHEMA_VERSION = 57`；
- 新增 API：`POST /api/flow-runs/replay-batch`、`GET /api/flow-runs/health`、`POST /api/flow-runs/cleanup`、`GET/PATCH /api/flow-runs/retention`；
- `POST /api/flows/runs/:id/replay` 增加 `mode=snapshot|latest`；
- 运行详情增加 `versionCheck`；触发器视图增加 `authMode/hasSigningSecret`；
- 运行中心与设置页新增批量选择、健康抽屉、运行保留区块；触发器对话框新增鉴权方式。

## 升级说明

- 升级时自动执行迁移 v057，旧运行新列为 NULL，旧触发器 `authMode` 为空、`hasSigningSecret=false`；
- 旧运行没有快照时按 `run.version` 精确取版本；版本已被删除则显示不可续跑，不静默改用当前生产图；
- 旧触发器继续使用 Bearer；启用 HMAC 前必须先轮换 Secret，否则明确拒绝；
- 保留策略默认开启，升级后首次清理在启动 5 分钟后执行。

## 语义与边界

- 补偿只覆盖无人值守触发，人工运行仍由用户决定是否重放；
- 补偿同流程单飞：有在途运行时顺延 60s，不消耗尝试次数；
- 批量重放不建补偿行，批次 id 仅用于追溯；
- 清理只删终态，排除 `pending/retrying` 补偿引用的运行；
- 健康面板只读，不自动停用触发器；
- 定时错过仍只补跑一次，仅记录错过次数；
- 不做 OS 级沙箱、目录白名单、通知中心、分布式调度。
