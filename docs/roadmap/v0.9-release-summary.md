# WorkBuddy v0.9 版本总结：Flow Serving——把每个工作流变成本机可调用的 API 与 MCP 工具

- **版本号**：v0.9.0
- **发布日期**：2026-10
- **主题**：执行解耦（队列/事件总线/崩溃恢复）+ 本地 HTTP API + MCP Server（HTTP/stdio 双承载）+ 无人值守安全策略 + 运行记录与重放
- **对应方案**：[v0.9-flow-serving.md](./v0.9-flow-serving.md)（五篇：roadmap / 现状差距 / 功能设计 / 技术架构 / 实施路线）
- **分支**：`feature/v0.9-flow-serving`（M0–M4）

---

## 1. 主题与价值主张

v0.8 让流程在画布上可调试、在对话里可复用，但流程的触发者仍然只有两种：**画布前的人**和**对话里的模型**。外部程序（脚本、定时任务、Claude Desktop 这类 MCP 客户端）无法调用它；而这两种现有触发还有一个共同的脆弱假设——执行由一条 SSE 连接驱动，断线即取消，进程崩溃后运行永久卡在 running/queued。

v0.9 的回答：

> 执行与连接彻底解耦：流程入队后由后台单执行者运行，任何观察者（画布/外部程序）都只读不驱动；同时给每个已发布流程一对独立密钥与标准协议（HTTP JSON + MCP），让它成为本机网络上一个有鉴权、有限流、有安全策略的服务。

| 痛点（v0.8 现状） | v0.9 的回答 |
|---|---|
| SSE 连接即执行生命，断线取消运行 | 队列（DB 原子认领）+ EventBus（缓冲/多观察者）+ 启动恢复扫描，观察者只读 |
| 进程崩溃留下僵尸 running/queued | 启动收敛 running/waiting → interrupted(process_restart)，queued 自动续跑 |
| 外部程序无法调用流程 | 环回专用公开路由：invoke（同步/超时转异步）、runs 轮询、只读 SSE |
| 无法接入 Claude Desktop 等标准生态 | MCP Server：initialize/tools/list/tools/call，HTTP 与 stdio 双承载 |
| 无人在场时危险工具可能被自动执行 | 端点策略门控：read 放行；write/danger 默认拒绝、白名单逐项授权；桌面控制永久禁单 |
| 失败/中断运行无法续跑 | 运行记录中心 + 整体重跑 + 祖先闭包节点重放（parentRunId/resumedFromNode 关联） |

**关键边界**：单进程单执行者（无分布式锁）、仅绑定 127.0.0.1、v1 一密钥一端点一流程、无定时/webhook（v0.10）、策略快照随 run 固化但不做版本并排。

## 2. 交付清单

### M0–M1 契约、迁移与执行解耦

| 模块 | 核心交付 |
|---|---|
| shared 契约 | endpoint/policy/限流/公开调用/serving 错误码全套 zod；`FlowRunStatus + interrupted`、`FlowTrigger + api/mcp`、`FLOW_DESKTOP_CONTROL_TOOLS` 永久禁单 |
| database | 顺序迁移 **v013**（纯加法）：`workflow_endpoints` 表（密钥 hash/前缀、双协议开关、超时/限速、策略 JSON、重确认位、lastUsed）+ run 增列 endpointId/parentRunId/resumedFromNode/interruptReason |
| RunQueue | 内存信号数组 + **DB 原子 claim**（`UPDATE ... WHERE status='queued'`）决定执行权，重复信号不双跑；claim 异常不产生 unhandled rejection |
| EventBus | 每 run 环形缓冲 + 多订阅者，迟到订阅先补历史再接实时；两个观察者收到逐字一致的事件序列 |
| RecoveryScanner | 启动时无主 running/waiting_human 一律收敛 interrupted（waiting TTL 24h 留待 v0.10），queued 重新入队 |
| 韧性补强 | 5s queued 补偿扫描（dev 冷编译窗口丢首信号兜底，claim 原子性保证不双跑） |

### M2 本地 HTTP API

| 模块 | 核心交付 |
|---|---|
| 端点服务 | 密钥 `wfk_`+40hex、sha256 存储、创建/重置仅返回一次明文、恒定时间比较；停用/错密钥统一 404 混淆防枚举；协议位/发布态/重确认 409 |
| 公开路由组 `/api/public/**` | hostGuard（环回白名单，DNS rebinding 防护）→ bearerAuth → rateLimit → handler；不读 Cookie、不发 CORS |
| invoke | 同步等待至终态 200（业务失败也是 200 包 status:failed）；超时 202 + `X-WBFM-Async:1`；`mode=async` 立即 202 |
| 轮询/事件 | GET runs/:id 按 endpoint_id 隔离；GET runs/:id/events 只读 SSE（内部/公开共用终态回放器，支持 `?after=`） |
| 限流 | 每端点固定窗口 + LRU 上限 10000，429 带 Retry-After |
| 入参校验 | 按 start 字段声明严格校验（必填/类型/null/默认值回填/剥离未声明字段），422 带字段详情 |
| 管理 UI | 编辑器「对外服务」对话框：开关、密钥脱敏与一次明文、重置（二次点击确认）、超时、限速、curl 示例、MCP 接入指引 |

### M3 MCP Server

| 模块 | 核心交付 |
|---|---|
| 纯处理器 | initialize（协议版本协商）/ initialized 通知 / tools/list（无分页）/ tools/call / ping；-32600/-32601/-32602/-32603/-32700 完整错误码；传输无关、报文级单测 |
| 工具映射 | `flow_` + workflowId 前 8 位稳定短码、碰撞追加位；inputSchema 与 start 字段同源；wire 剥离内部字段 |
| HTTP 承载 | `POST /api/public/mcp`（无状态单消息，通知 204），鉴权链与 invoke 完全一致；应用内自举验证通过 |
| stdio 承载 | 行分帧 adapter（半包拼接、响应串行化保序、坏帧 -32700、stdout 协议纯净）；独立 bin（esbuild bundle，依赖 external 复用归集 node_modules）；`WBFM_MCP_TOKEN` env 鉴权，坏/缺密钥 exit 1 |
| 桌面打包 | prepare-server 归集 mcp-server bin 与内置 node（ABI 与 better-sqlite3 一致）；主进程注入 node/bin 路径供 UI 生成 spawn 命令行 |

### M4 安全策略、重放与发布收尾

| 模块 | 核心交付 |
|---|---|
| 策略门控 | 纯函数 `evaluateUnattendedPolicy`：read 放行 → 桌面禁单（最高优先级）→ allowlist 命中 → 否则拒绝；策略在建 run 时快照固化（端点后改配置不影响在途 run）；拒绝文本含 `[policy_deny:*]` 审计标记落 node_executions |
| 发布重确认 | 发布新版本且端点已存在 → `policy_revalidation_required=1`，再确认前所有公开调用 409；端点保存配置即清位；UI 红色警告条 |
| 策略编辑 UI | deny_all/allowlist 单选；白名单候选项实时扫描发布图的 write/danger 节点，桌面工具永久禁选并红字标注 |
| 重放 | `computeReplayClosure` 祖先闭包（反向可达）；引擎支持 onlyNodeIds 子集执行 + replayTarget 收尾；POST runs/:id/replay（整体/节点）；新 run 记 parentRunId/resumedFromNode |
| 运行记录中心 | `/flows/runs`：trigger/status 筛选、状态徽章、关联备注、失败/中断行「重放节点」（自动定位失败节点）+「重跑」；编辑器支持 `?run=` 深链打开执行面板 |
| 公开取消 | POST runs/:id/control（带密钥、归属校验） |
| 发布收尾 | 版本号 → **0.9.0**（root/web/desktop/侧栏/e2e 断言）；MCP serverInfo 0.9.0；README 增补对外调用章节 |

## 3. 架构演进

### 3.1 执行/观察分离后的全景

```text
画布（EventSource 只读）   外部程序（curl/脚本）   MCP 客户端（Claude Desktop…）
        │                        │ bearer wfk_         │ JSON-RPC（HTTP/stdio）
        └────────────┬───────────┴─────────────────────┘
              Next.js /api（内部 defineRoute ｜ 公开 definePublicRoute）
          hostGuard → bearerAuth（sha256/恒定时间）→ rateLimiter → handler
                     │ createRun(endpointId, trigger=manual/api/mcp)
              SQLite workflow_runs（queued，原子 claim）
                     │ 信号只加速、DB 状态才是权责来源
   ┌─────────────────┴──────────────────┐
   │ 单执行者 FlowRunQueue（同进程）      │
   │ claim → compile → execute → events │
   │   策略快照门控（api/mcp）           │
   └─────────────────┬──────────────────┘
        EventBus（缓冲 + 多观察者，只读）
   启动：running/waiting→interrupted；queued→重入队
```

### 3.2 四个最关键的架构决策

**① 信号只做加速，DB 原子认领才是权责来源。** 内存 enqueue 可能重复/丢失（HMR、冷编译），所以执行权以 `UPDATE workflow_runs SET status='running' WHERE id=? AND status='queued'` 的变更行数为准；外加 5s 补偿扫描兜底。顺序性由单执行者 + 串行 tick 链保证（v1 不做并发，设计文档明确）。

**② 无人值守与 HITL 是同一引擎里的两条门控分支，不是两套执行路径。** trigger=api/mcp 时引擎改调 `evaluateUnattended`（纯策略，永不挂起）；manual 保留权限记忆 + 内联确认；chat 保持 v0.8 现状。read 工具不进门控，桌面禁单优先级高于白名单，SSRF/熔断/超时对放行调用同样生效——安全机制叠加而非互斥。

**③ MCP 处理器与承载严格分层。** `handleMcpMessage` 是纯函数（消息进、响应出），HTTP 路由与 stdio adapter 都只做帧编解码和鉴权。这让协议正确性可用报文级单测覆盖（9 例），stdio bin 又能复用完全相同的核心逻辑，避免双实现漂移。

**④ 重放 = 祖先闭包子图上的一次新 run，而不是断点续跑。** 不缓存历史 outputs、不人工补审 waiters：从目标节点沿入边反向求全部祖先，在当前发布图上重跑这段闭包并在目标节点收尾。跨版本图变化天然按新图计算，引用完整性由引用解析兜底；语义自洽、成本可控。

## 5. 踩坑记录（都已固化为代码或测试）

1. **transpilePackages 下 instanceof 跨 chunk 失配**：全局容器里 core 类的实例在按需编译的公开路由 chunk 中 `instanceof PublicEndpointError === false`，鉴权拒绝被兜底成 500。修复：错误识别加 `name + 结构化字段` 鸭子判定。
2. **stdio JSON-RPC 响应乱序**：坏帧同步写错误响应会插队到前一个 async 请求结果之前。修复：帧处理链串行化（chain.then），响应顺序严格等于请求顺序。
3. **Next 同层动态段 slug 必须同名**：`runs/[id]` 与误建的 `runs/[runId]` 导致 dev server 直接启动失败。统一为 `[id]`，所有 /:id 路由共用 idParamSchema。
4. **独立 DevTools 窗口抢键盘焦点**：Electron dev 默认 `openDevTools({mode:'detach'})` 在 Windows 偶发造成页面输入框有光标但打不出字，重开窗口才恢复。默认不弹（Ctrl+Shift+I 手动开，env 可恢复旧行为）。
5. **PowerShell 5.1 Set-Content 写 UTF-8 BOM**：改版本号时污染 package.json 致 pnpm 无法解析。统一用 `[IO.File]::WriteAllText + UTF8Encoding($false)`。
6. **claim 抛错产生 unhandled rejection**：DB 关闭竞态时 claim 异常沿 setImmediate 链抛出。队列 tick 对 claim 单独 try/catch。
7. **esbuild shebang 被插在第 2 行**：banner 与前置内容冲突导致 CJS 语法错误。bin 始终由内置 node 显式启动，直接去掉 shebang。

## 6. Non-Goals（本版本明确不做）

- ❌ 分布式锁、多实例、多执行者（单进程本地应用前提）
- ❌ 一密钥多流程/全局限权角色（v1 一密钥一端点一流程）
- ❌ 定时 / webhook / GitHub 式事件触发（**v0.10**）
- ❌ waiting_human 超 24h TTL 强收敛、策略版本并排（当前快照随 run 固化）
- ❌ MCP SSE 响应流/资源与提示词原语（v1 仅 tools）
- ❌ 节点同层并发、subflow 嵌套
