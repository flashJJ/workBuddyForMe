# WorkBuddy For Me v2.4.0 — Release Notes

## WorkBuddy For Me 2.4.0 — Ready out of the box: zero-config first run, reachable templates, voice that works, and trustworthy runs

Release date: **2026-10-22** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-2.4.0.exe`

v2.4 answers a narrower question than previous releases: **after installation, what happens in the first five minutes?**

The product was not short on features; it was short on the path that turns them into value. A new install had to bring its own provider, API key and model before the first answer. Templates, voice, capabilities and failure reasons were buried in Settings or raw error strings. This release makes the first step walkable:

**Answer without a key → templates already in the list → voice in one click → visible capabilities → every run explains why it failed and where the time went.**

### 🚀 Zero-config first run

- **Demo mode as a real product path**: the built-in provider runs the same SSE, retrieval, citation and workflow pipeline; only the model output is deterministic. It works offline, never downloads anything, and is the guaranteed fallback for the first answer.
- **Three sources side by side**: demo, local model, cloud API. The wizard probes local Ollama on entering step two; when detected, the local source is **moved to the front and selected by default**. If the probe is late and the user has already picked a tab, the result only reorders the tabs — it never steals the selection.
- **Cloud presets** prefill the provider name, Base URL and suggested model, so the user only supplies a key.
- **Local small-model guidance** covers the “I have nothing installed” case without pushing a download silently.
- **First-run ends with a first answer, not a configuration screen**: a short latency self-check classifies the path as smooth / usable-but-slow / switch-source; a `firstAsk` example question is sent automatically once the model is ready; four timestamps are stored and `ttfv_ms ≤ 60_000` is the acceptance metric.

### 🧩 Templates within reach

- One source of truth for 15 templates (3 knowledge bases, 6 workflows, 3 skills, 3 assistant presets), rendered by a shared `TemplateGallery`.
- Shown once in empty states plus a collapsible entry pinned to the top of each list — visible on day one, never repeated afterwards.
- “Start from this” has per-type semantics: knowledge bases and workflows clone into editable instances, skills are enabled in place, assistants prefill the create form, character cards reuse the existing copy flow.
- Workflow cloning goes through a server route and falls back to the seeded definition when the source has been deleted, so an empty-state entry never points at a missing object.

### 🎙️ Voice that works in one click

- Two entry points (Settings and the chat page) enable ASR + hands-free + read-aloud + the default profile in one click.
- Only two profiles are exposed by default: **Fast** (balanced sensitivity, 600 ms tail silence) and **Forgiving** (low sensitivity, 1200 ms). Sensitivity and tail-silence fine-tuning moved into a collapsed Advanced section.
- When models are missing, size estimates, download, progress and cancel are offered in place; downloads resume by skipping completed files.
- Default TTS moved to MeloTTS (191 MB, single voice, low latency); Kokoro becomes the multi-voice option.
- A real-machine bug is covered by three guard layers: punctuation-only fragments could terminate the native TTS process; a readability check, chunk filtering and engine rejection now catch it.

### 👁️ Capability visibility

- New additive migration `assistants.skill_names`: an empty array keeps the old “follow globally enabled skills” behavior; a non-empty array narrows the assistant to those skills (still gated by the global switch).
- Assistant cards show skills and MCP tools; the form gains a dedicated skills section (distinct from the per-tool allowlist); the chat header summarizes the current model / knowledge bases / skills / tools.

### 📊 Trustworthy runs and streaming feel

- task / agent-run / flow-run now share eight outcomes: `queued / running / waiting / succeeded / failed / cancelled / interrupted / budget_exceeded`, one duration definition (`startedAt → finishedAt`, `updatedAt` for agents, “so far” while running) and a shared failure taxonomy that renders **why it failed + what to do next**, with the raw error folded away.
- Collaboration cards offer a **read-only stage view** only, explicitly stating it does not affect the run.
- Streaming deltas are batched by `requestAnimationFrame` and flushed on done / error / stop / reset. Long Markdown replies are split at top-level headings and memoized per block (code fences are never split; <1.6k characters stays single-block).
- Waiting past 1.5 s shows elapsed seconds; past 5 s adds “stop + switch to a smaller model / shorten context”. First-token latency stays visible on the assistant message, using the same thresholds as the first-run self-check.
- Consistency pass: shared `EmptyState` / `ErrorState` on three run pages; command palette covers tasks/workflows and new knowledge base/workflow/assistant/character card with `?new=` deep links; shortcut overlay documents the stage group; responsive e2e covers three viewports across six list/run pages.

### 🛠️ Post-merge hardening

- **Strict function-name compatibility**: OpenAI-compatible upstreams may enforce `^[a-zA-Z0-9_-]+$` on `tools[].function.name`. Internal qualified names (`flow:<id>`, `mcp:<server>:<tool>`) are now escaped on the wire and restored on tool calls, including historical `tool_calls` and tool result names, with collision-safe suffixing.
- **Settings hydration fixed**: TTFV and demo-mode panels now gate data-driven text on mount, and the hydration marker is set after the subtree’s effects, so a late settings query can no longer trigger React #425/#422 and drop an in-flight click (the wizard replay button).

### Known limits and deferred scope

- **Full duplex is not shipped**: voice remains “speak, then listen” with barge-in interruption; simultaneous speak-and-listen stays a P2 candidate.
- **Deferred to P2**: screenshot Q&A, MCP catalog expansion, skill import/template area, Electron cold-start/memory measurements, explainable memory.
- **Real-machine long-run stability**: first-token metrics and slow-model advice are covered by automation, but minute-scale waiting on genuinely weak local models still needs a real-machine pass; download times depend on the network and are not promised.
- **v2.3 was never tagged**: it is included in main and covered by this release; only v2.4.0 receives a tag.
