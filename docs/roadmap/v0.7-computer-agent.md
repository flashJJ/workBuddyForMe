# v0.7 迭代方案：看得见、动得了手 — 桌面 Agent 能力

> 状态：✅ 开发完成（feature/v0.7-computer-agent 待手测 + 发布；v0.6.0 已发布）

## 1. 版本主题与目标

**一句话价值主张**：从「对话里调用工具」到「看得见屏幕、动得了键鼠」——助手能观察桌面、执行 GUI 操作，每一步都在用户眼皮底下并经授权，对标腾讯 WorkBuddy 的「接管电脑」能力但坚持本地优先与安全兜底。

**成功指标**：

- 完成 2 个真实端到端 demo：①「打开记事本，写一段话并保存到指定路径」；②「打开浏览器访问指定网页，把正文存入知识库」——全程无人工干预操作，仅干预授权
- 所有桌面动作走统一权限门控：danger 级逐步确认（可批量授权一次任务），有全局紧急停止热键
- 每次任务产生可回放的行动日志（截图 + 动作序列 + 模型决策理由）
- 全部门禁不降级（check / 12 包单测 / 集成 / E2E）

## 2. 现状与痛点

| # | 痛点 | 现状证据 |
|---|------|---------|
| 1 | **看不见**：助手对桌面状态零感知，无法回答「屏幕上现在是什么」这类问题，更无法基于视觉定位操作目标 | 视觉能力仅用于对话图片/PDF OCR（v0.3/v0.4） |
| 2 | **动不了**：工具链只能调用结构化 API（内置工具 + MCP），对没有 API 的桌面应用（记事本、资源管理器、第三方软件）完全无抓手 | tool-runtime 仅有 schema 注册工具 |
| 3 | **浏览器自动化缺失**：fetch_webpage 只能读静态正文，登录态页面、需要交互的网页（搜索、表单）做不了 | fetch-webpage-tool.ts |
| 4 | **长任务无编排**：单轮 tool_calls 循环适合短链路，「打开 A → 等加载 → 填 B → 截图确认」这类多步有状态任务缺少任务级骨架 | tool-call-loop 每轮无跨轮任务状态 |

**关键判断**：腾讯 WorkBuddy 类产品的核心是「视觉感知 + 键鼠注入 + 自主规划循环」。本项目已有视觉模型链路（qwen2.5vl）、工具权限体系（v0.6 HITL/熔断）、Electron 主进程（天然的桌面能力宿主）——三块地基都已具备，v0.7 是把它们拼成 agent 循环。

## 3. 功能清单

### P0-1 屏幕感知（看得见）

- **用户故事**：作为用户，我问「帮看看我屏幕上这个报错是什么」，助手截图当前屏幕/指定窗口，用视觉模型解读并回答。
- **验收标准**：
  - 新内置工具 `screen_snapshot`：支持全屏 / 前台窗口 / 指定区域三种范围，返回缩放后图像供视觉模型解读
  - 截图最大边长自适应（默认压到 1568px 内，控制视觉 token 成本），PNG 走 attachments 目录不入库
  - 双通道感知：截图时附上前台窗口的 UIA 控件清单（名称+矩形+类型），模型「看」屏幕时既有图又有结构化数据，为 P0-2 混合定位提供候选源
  - 权限级 `read`（只读观察），但截图内容打日志时标注可能含敏感信息
- **技术要点**：desktop 主进程用 Electron `desktopCapturer` + `screen` API 抓屏；web server（fork 子进程）经主进程 IPC 请求截图（新增 `WBFM_COMPUTER_CHANNEL` 本地控制通道，仅 127.0.0.1 + 随机 token 鉴权）；web-only 模式（无 desktop）下工具注册但返回「需要桌面端运行」
- **工作量**：M（3 人日）

### P0-2 键鼠执行（动得了手）

- **用户故事**：作为用户，我说「打开记事本，把这段话写进去保存到桌面」，助手逐步点击/输入/按键完成任务，每步我都看得到。
- **验收标准**：
  - 新内置工具组（全部 `danger` 级，走 v0.6 HITL 弹窗）：
    - `mouse_click`（x/y/button/double）/ `mouse_move` / `mouse_scroll`
    - `keyboard_type`（文本）/ `keyboard_press`（组合键，如 Ctrl+S）
    - `window_list` / `window_focus`（read 级：列举与激活窗口）
    - `app_launch`（按名启动应用，danger 级）
  - 坐标定位采用混合分层策略（2026-09-30 评审定）：**UIA 控件树优先**（Windows UI Automation 拿目标应用控件名+精确矩形，模型从候选列表选控件，确定性定位，覆盖标准 Win32/WPF/Qt 应用）→ **SoM 标记兜底**（自绘 UI/Electron 窗口拿不到控件时，截图叠加编号标记，模型选编号而非输出像素坐标，把回归问题变分类问题）→ 纯坐标输出仅作最终兜底；坐标系与截图对齐：SoM 命中区域中心点 / UIA 矩形中心点，服务端统一缩放回真实分辨率
  - 每次危险动作默认逐步确认；弹窗提供「本任务内一直允许」批量授权（会话级白名单，复用 remember='assistant' 机制扩展 remember='task'）
- **技术要点**：主进程集成 `@nut-tree-fork/nut-js`（选型已定，2026-09-30 评审：robotjs 停更 5 年 + NAN 老架构无现代 prebuilt 出局；koffi+SendInput 因跨平台诉求未采纳；fork 版 N-API prebuilt 跨 ABI 稳定，需在 electron-builder 配 asarUnpack 并打包实测）执行键鼠；动作执行前 300ms 延迟 + 屏幕上绘制半透明指示圈（点击落点可视反馈）；全部动作写入行动日志
- **工作量**：L（5 人日）

### P0-3 任务级 Agent 循环（干完一件事）

- **用户故事**：作为用户，我给一个桌面任务目标，助手「观察 → 规划 → 执行 → 再观察」循环直到完成或我喊停，而不是一问一答。
- **验收标准**：
  - 新对话模式「任务模式」：用户给出目标后，orchestrator 进入 agent 循环（观察 → LLM 决策下一步动作 → 权限门控 → 执行 → 观察），单任务步数上限 20 步（防失控）
  - 前端任务视图：步骤时间线（缩略图 + 动作 + 结果），运行中可「暂停 / 继续 / 终止」
  - 全局紧急停止热键（如 Ctrl+Alt+Esc，主进程 globalShortcut 注册），触发立即中断循环并冻结键鼠工具
  - 行动日志落库（新表 `task_runs` + `task_steps`），任务结束后可回放
- **技术要点**：agent 循环放 core（`packages/core/src/agent/`），复用 tool-call-loop 的 SSE 事件通道扩展 `task` 事件类型；步数/时间双上限；与 v0.6 熔断器联动（同一工具连续失败 3 次任务自动终止）
- **工作量**：L（5-6 人日）

### P1-1 浏览器自动化（Playwright 桥）

- **用户故事**：作为用户，我说「去某网站搜 XX，把前三条结果存进知识库」，助手驱动真实浏览器完成，能处理登录态（复用我已登录的浏览器 profile）。
- **验收标准**：
  - 以 MCP 服务器形式接入（`playwright-mcp` 官方服务器优先评估，不达标再自研），工具走 mcp 命名空间，权限 danger 级
  - 支持连接用户日常 Chrome（CDP 端口）复用登录态；也支持独立 Playwright 实例
  - 与 P0-3 任务模式联动：网页任务可混合「浏览器 DOM 操作」与「屏幕键鼠」两条路径
- **技术要点**：评估 playwright-mcp 的依赖体积与打包影响（v0.4 canvas 归集经验）；CDP 连接配置进 MCP 服务器表单
- **工作量**：M（3-4 人日）
- **评估结论（2026-09-30）**：v0.7 不真接入 playwright-mcp，详见 [v0.7-playwright-mcp-eval.md](v0.7-playwright-mcp-eval.md)。demo② 改用「键鼠 + screen_snapshot + fetch_webpage」组合路径完成；架构留口保留（allowedTools 已支持 mcp: 前缀），v0.8+ 重新评估

### P1-2 任务模板与录制回放

- 把成功任务沉淀为可复用模板（参数化目标），与 v0.6 技能包体系打通（技能 = 提示词 + 工具白名单 + 任务模板引用）
- 行动日志回放视图：按步骤回看截图与决策理由
- **工作量**：M（3 人日）

### P2 留白（登记不做）

- 跨设备远程控制、移动端接管——本地单机边界不破
- OCR 纯坐标定位完全替代视觉模型（混合策略已在 P0-2 覆盖，纯 OCR 定位精度不足）
- 游戏/3D 应用的操作（DirectX 独占渲染截图黑屏问题，ROI 极低）

## 4. 架构影响

- **apps/desktop**：新增 `src/main/computer/` 模块（screen.ts 截图 / input.ts 键鼠 / overlay.ts 指示圈 / control-channel.ts 本地 IPC 通道 + 鉴权 token）；globalShortcut 注册急停热键；nut-js 进 dependencies 并登记打包归集
- **packages/core**：新增 `src/agent/`（task-loop、step-executor、run-repo 接口）；`src/tools/computer/` 工具组（经控制通道调主进程能力）；tool-call-loop 扩展 task 事件；熔断器接入任务级终止
- **packages/shared**：computer 工具 schema、task_runs/task_steps 契约、SSE `task` 事件类型、remember='task' 授权范围
- **packages/database**：v011 迁移（`task_runs`、`task_steps` 两表；截图引用 attachments 路径不入库）
- **apps/web**：任务模式对话视图（步骤时间线）、任务控制条（暂停/终止）、行动日志回放页、HITL 弹窗扩展「本任务内一直允许」
- **兼容性**：纯 web 模式（无 desktop 主进程）computer 工具自动隐藏；v0.6 及以前数据不受影响
- **备份**：v0.4 备份轨加 `tasks` 轨道（任务记录与日志元数据，截图附件随 attachments 轨）

## 6. 风险与取舍

| 风险 | 应对 |
|---|---|
| 键鼠失控（模型误点、死循环点击） | 三层兜底：每步 HITL 确认（默认）+ 步数/失败双上限 + 全局急停热键；危险动作绘制指示圈让用户看到「要点哪」 |
| nut-js 打包/兼容性（原生依赖前车之鉴：canvas、sqlite ABI） | M2 第一天先做打包 spike：打包后 exe 内跑通点击 demo 再展开；炸链时回退 koffi + Win32 SendInput（FFI 无 ABI 问题，Windows-only 可接受） |
| 视觉模型坐标定位不准（qwen2.5vl 7B 定位小目标掉点，5 步任务纯视觉成功率约 40%） | 已定混合分层策略：UIA 控件树确定性优先（M2，覆盖标准应用）→ SoM 编号标记兜底（M3，把回归变分类，覆盖自绘 UI）→ 纯坐标最终兜底 + HITL 拦截；UI-TARS-7B 等专用 grounding 模型登记 v0.8+ 视实测差距再评估 |
| 截图隐私（屏幕可能含密码/私聊） | 截图仅存本地 attachments；任务日志本地保留；发送给云端供应商的截图在任务启动时明确提示 |
| web-only 模式能力割裂 | 架构上 computer 工具注册即探测主进程通道，缺失时隐藏；文档明确「桌面 Agent 能力仅桌面端可用」 |
| 与腾讯 WorkBuddy 的体验差距（商用产品有更大模型与工程团队） | 定位差异化：本地优先 + 数据不出机 + 每步可审计；不追求全自主，追求「授权下的半自主」 |

## 7. Non-Goals（本版本明确不做）

- ❌ 完全无确认的自主执行（安全红线：danger 动作必须至少任务级授权一次）
- ❌ 远程控制其他设备 / 移动端
- ❌ 游戏与 3D 应用操作
- ❌ 多智能体编排（仍归 v0.8）
- ❌ 云端模型强制依赖（任务模式可用本地视觉模型全离线跑，云端仅作可选加速）
