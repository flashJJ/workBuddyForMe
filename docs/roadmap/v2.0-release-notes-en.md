# WorkBuddy For Me v2.0.0 — Release Notes

## WorkBuddy For Me 2.0.0 — Bonded: an emotional loop, VRM avatars and a portable mod ecosystem

Release date: **2026-10-16** · Platform: **Windows 64-bit** · Installer: `WorkBuddyForMe-Setup-2.0.0.exe`

v1.6 gave your companion moods and v1.7 gave your time together rituals. v2.0 answers the last question — **what does long-term companionship leave behind?** Every interaction now moves a four-level relationship (Stranger → Acquaintance → Partner → Confidant), level changes unlock new ways to interact, shared milestones become commemorative scenes, and your characters, stage scenes and relationship history can travel offline as `.wbfm-pack` bundles and single-file HTML reports. For the first time you can also bring your own **3D VRM avatar**, rendered by a second, isolated three.js backend. Three red lines hold as always: local-first (raw system signals are never stored), weak-model safety (the relationship kernel is deterministic pure functions), and licensing boundaries (external Live2D import stays permanently disabled; VRM enters only through a double-validated, disclaimer-gated importer).

### 📈 Relationship levels: two axes, four tiers, pure functions

- **Intimacy** and **trust** (0–100, persisted since v1.6) feed a pure-function kernel. Higher tiers require **both** axes to cross thresholds; hysteresis bands prevent edge flicker and a regression floor stops one bad day from resetting a bond.
- Level changes emit level events; a director gate decides whether they surface as performances or unlocks — the math layer never touches the UI. With weak models, emotion inputs fall back field-by-field through zod and keyword rules, so results stay deterministic.
- The relationship panel exposes the current tier and the three locked tiers; the whole section hides when the relationship master switch is off, and re-enabling restores persisted state.

### 🏅 Shared milestones and commemorative scenes

- Six milestones trust only stored evidence: first-day conversation, 30/100/365 days together, and 10/50 collaborations. They are derived from messages and collaboration runs — there is no manual marking entry point.
- On completion, a commemorative scene plays through the v1.7 event-performance pipeline (respecting quiet hours, active-conversation and cooldown/rate locks) with the achieved date recorded. A new `relationship` long-term-memory category captures these events; models can never rewrite them directly.

### 👁️ Proactive awareness: edges only, never raw signals

- The desktop bridge reports just three **edge signals** — unlock, lock, idle. Ticks persist only edge-dedup state; screen contents, window titles and process names never leave the machine and never hit disk.
- Each system event has its own authorization group (off by default) and an independently disableable context script. Turning off any master switch (emotion, events, proactivity) hides the authorization groups and script list together.

### 🧊 VRM: a second render backend with a guarded importer

- A three.js + @pixiv/three-vrm stack coexists with the PIXI Live2D stack, mounted dynamically from the avatar picker so it never enters the first-screen bundle. Live2D / VRM / default backends switch through persisted settings.
- The import wizard rejects extension/size errors on the client, then re-validates GLB structure and the VRM extension server-side, parses metadata, and requires an explicit disclaimer checkbox. Four malformed-file negatives are all rejected. Models live in `data/vrm-avatars/` and are never redistributed inside packs.

### 📦 .wbfm-pack: allowlisted container, blocklisted danger

- A pack is a ZIP plus a zod-validated `manifest.json` with an explicit schema version. Contents are frozen to **character cards, stage scenes and background images**; events/themes/personas/gestures keys accept only empty arrays — one non-empty key rejects the whole pack.
- Model/audio binaries and any eval/script payload are blocklisted; VRM travels by reference only; the `builtin.*` namespace cannot be overwritten. Inspection never touches disk, fatal errors show no import button, name collisions import as clearly labeled copies, and invalid entries are individually uncheckable. Install records persist in the new `mod_installs` table (migration v031).

### 📄 Relationship report and backup schema v6

- Aggregating emotion state, event flow, milestones, event usage and assistant names, the relationship report renders a **single self-contained HTML file with zero external links** (inline styles), bilingual zh/en, with five toggleable sections and deletable memory items.
- Backup schema **v6** adds the events and mod-install tracks; export, precheck counts, the restore transaction and manifest counters were updated together. Restore stays idempotent (`INSERT OR IGNORE`) and older archives missing the new tracks degrade gracefully to zero counts.

### Known limits and deferred scope

- The relationship-metrics read-model and an activity dashboard are deferred; report numbers are aggregated on demand without rolling statistics tables.
- A mod marketplace / one-click subscription, and packs carrying themes or persona weights, are not in this release — the manifest freezes cards, scenes and backgrounds only.
- Multi-VRM 3D stage performances (positioning, lip sync) are not included; VRM renders the single conversational avatar while the stage remains Live2D.
- A UI for the soft "start over" relationship reset is not exposed; the data path is supported through backup/restore.
- External Live2D model import stays permanently disabled per the Cubism licensing boundary; no voice packs are bundled; unattended desktop automation remains forbidden.
