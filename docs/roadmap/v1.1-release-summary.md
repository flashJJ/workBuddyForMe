## 1. 主题与价值主张

v1.0 在一个大版本里同时长出了语音、形象、桌宠三条新能力线，速度优先留下四类结构性债务：跨层依赖靠自觉、大工具输出硬吃上下文窗口、热点文件靠白名单续命、SSE 事件契约靠手写联合与逐案断言。v1.1 不交付任何用户可见功能，只回答一个问题：

> 当代码规模继续增长时，哪些不变量应该由工具强制，而不是靠人记住？

| 工程债（v1.0 现状） | v1.1 的回答 |
|---|---|
| 分层方向与 internal 私有域靠约定，违例只能在评审时肉眼抓 | import/no-restricted-paths 方向 zone × internal 全配对，M0 warn 观察一个完整版本零违例后 M5 翻 **error**，进 CI 硬门禁 |
| 100KB 工具结果原样回灌，和记忆/对话正文抢 context window | 工具结果中央压缩层：模型只见预算视图，trace/SSE/UI 保留完整 output；knowledge 保编号、JSON 头取样 + `__omitted`、出口硬保证不超预算 |
| ≥260 行手写热点 28 个，pet-manager 483 行靠白名单续命 | 纯函数/类型/子组件/夹具外迁 + barrel 域子路径化：≥260 文件 **28→1**（降幅 96%），白名单仅余自动生成类 |
| SSE 事件三方手写（core 联合/web 联合/wire 窄化），漏列无编译错误 | 单一真源 `SseEvent<K>` 条件类型从 `SsePayloadMap` 机械派生；穷尽 switch + 运行时镜像 + 三份契约测试，删映射即红 |
| eval 只有 eval-memory 单脚本，断言与接线揉在一起 | scripts/eval/lib 五件（http/sse-client/assertions/report/mock-seed），3 个 golden set 域，每个都做反向验证 |
| 覆盖率只有 core 一条 70% 全局线，核心纯函数无差异化要求 | 分级门禁：core 全局 70% + 压缩模块 95%；web 三关键域（lib/server、features/chat、features/voice）60%；其余包只出报告 |
| 语音运行时长在 web 应用层，core 无法复用、边界不清 | VoiceRuntime 全量下沉 `@wbfm/core/voice` 独立子路径入口；web 仅留 HMR 单例薄壳与 SSE 桥，路由零改动 |

**关键边界**：零产品行为变更（HTTP/SSE 线上协议、`{success,data}` 信封、UI 交互全部不动）；不引入 DI 容器/Nest 装饰器；不做视觉层重构；每个里程碑独立提交批次，任一关标准不过整体 revert。

## 3. 架构演进：五个最关键的决策

**① 强制力分层：编译器/测试/CI 各管一件事。** 依赖方向归 ESLint zone；事件契约归 TS 条件类型派生 + 穷尽 switch；「不能漏列」归运行时镜像集合与变异测试；预算约束归纯函数出口硬保证。任何不变量都不依赖人在评审时记得。

**② 压缩只造视图、不改事实。** 完整 ToolResult 照常进 trace/SSE/UI，压缩器是无状态纯函数，预算装配期下发、不读全局状态；模型被压掉的信息永远能用具体 id 再查回来，工具连环调用不因压缩断链。

**③ 子路径化保住类身份，再谈域边界。** 子路径 exports 的 import/require 刻意统一指向既有 dist 单 bundle——多入口 chunk 会让 ApiError 等类跨 chunk 多副本、instanceof 失效；types/development 条件才指 src。voice 独立入口是验证过的唯一例外（共享块仅 esbuild helper）。

**④ 搬家先保测试、打包双门禁。** 语音下沉全程「测试随迁断言零改 + 路由零改动」，最后用 pack:dir 真机 TTS→ASR 回环收口；nft 跨盘符归集坑在本批次定位并固化为 outputFileTracingIgnores 配置。

**⑤ eval 断言必须证明自己不是恒真。** 每个 golden set 落地后做一次反向验证（回退被测代码→断言失败）：压缩器回退产生 40949 token 与 3 条 FAIL，是 eval-tool-compact 有效性的取证，而非「跑通了」就算数。

## 5. 踩坑记录（均已固化为代码、配置或测试）

1. **import/no-restricted-paths 的两个语义坑**：方向 zone 的 from 必须用非 glob 目录（containsPath 语义天然放行同包）；internal 限制无法靠 except 按发起方放行，只能枚举全配对。eslint 直跑 .ts 探针必须带 `--ext .ts,.tsx`，resolver 要显式 typescript + project 列表。
2. **vi.mock 按模块说明符拦截**：barrel 拆子路径后，测试 mock 必须写完整子路径（ocr-runner 用例要 mock `@wbfm/shared/constants`），否则静默落到真模块。
3. **codemod 机械归属优于人工判断**：用 TS checker 枚举各 barrel 导出名做成员归属，954 成员迁移零主观分类；根 barrel 兼容保留但消费侧归零，防止漏网。
4. **Next nft 的跨盘符嵌套复制**：manifest 字面量路径（espeak-ng-data 的 `!v`）与 homedir() 静态求值被解析到磁盘真实数据根，生成 `.next/server/C:/Users/...` 嵌套条目；单文件 ENOENT 会中断该路由后续归集，表现为共享 chunk 缺失、打包态全路由 firstWindow 超时（dev 正常）。outputFileTracingExcludes 在 Next 14 会 path.join 拼死分隔符且无法表达盘外路径，只有 outputFileTracingIgnores 的 picomatch 可用（Windows 上 `/` 同时匹配两种分隔符）。
5. **tsup 多入口与类身份**：独立子路径若产出独立 chunk，class instanceof 跨副本失效；voice 的双入口经验证共享块仅 esbuild helper 才放行，规则已写入 M3 交付说明。
6. **覆盖率 glob 门槛要做抓人自测**：vitest glob thresholds 匹配静默，配错 glob 等于没门槛；统一用「临时抬到不可能值观察 exit 1 + 实际值上报」验证一次。
7. **knowledge 压缩的可达性推理**：hint 预留（预算扣除固定提示 token）使「触发压缩但正文未被裁」分支数学上不可达，判定为防御代码保留，分支门槛因此设 95% 而非 100%，门槛数值必须对照真实分支结构设定。
8. **dev server 与构建/安装争用 .next**：跑 e2e 前先杀净 next dev/electron；pnpm 安装依赖也可能因硬链接切换与文件监听冲突造 ENOENT 假失败（v1.0 教训，本批次再次验证）。
