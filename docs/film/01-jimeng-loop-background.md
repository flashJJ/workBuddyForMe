# 01 即梦循环背景视频生产手册

> 目标：用即梦做出**可无缝循环、可长期当桌面 / 舞台背景**的视频，而不是抽卡式地生成一段「看起来能动」的片子。  
> 适用：即梦 AI（图生视频 / 首尾帧）；剪映专业版；FFmpeg 可选。  
> 说明：即梦不同版本的入口名称可能变化，本文按能力描述，不绑定具体按钮文案。

## 0. 结论先行

最合理的顺序是 **五步**，不要一上来就文生视频：

1. **定用途**：桌面背景、舞台背景、短视频背景，三者构图不同。
2. **先生成静帧**：同一场景生成 4 张，挑 1 张；静帧便宜且可控。
3. **首尾帧同图生视频**：把选中的静帧同时作为首帧和尾帧，提示词只写「微动」。
4. **只做必要后处理**：首尾帧同图通常直接可循环；有接缝再叠化 0.5–1 秒。
5. **按桌面标准验收**：固定机位、中心低对比、无文字、循环 3 次不跳。

> 一句话：**静帧定画面，首尾帧定循环，剪映只修接缝。**  
> 角色不要交给即梦生成。角色用项目内 VRM 实拍，即梦只做环境。

### 0.1 最快起步（已有会员，10 分钟）

1. 打开 [bg-deepsea.jpg](./assets/bg-deepsea.jpg) 或 [bg-rain-platform.jpg](./assets/bg-rain-platform.jpg)。
2. 即梦 → 图生视频 → 首尾帧 → **首帧和尾帧都上传同一张图**。
3. 复制第 5 节对应场景的「视频提示词」。
4. 参数：1080p、5 秒、固定机位、运动幅度小、关闭水印。
5. 下载原片，连续播放 3 次；有接缝再做 0.5–1 秒叠化（第 6 节）。

> 如果当前会员档位只有 720p：先用 720p 验证循环与运动，再决定是否升级或后期超分。不要在 720p 阶段反复抽 10 秒视频。

## 1. 先选路径

| 你想要的内容 | 推荐做法 | 不推荐的做法 | 原因 |
|---|---|---|---|
| 纯背景循环（桌宠 / 舞台） | 即梦静帧 → 首尾帧同图 → 8 秒循环 | 直接文生视频 | 构图不可控，镜头容易漂 |
| 角色出镜短视频 | 应用内 VRM 录制 + 即梦背景 + 剪映合成 | 即梦直接生成三个角色 | 脸、发型、服装必跑偏 |
| 四人日常合影 | VRM 截图 + Master 2D + 即梦背景合成 | 即梦一次性生成四人 | 角色一致性无法保证 |
| 直播 / 会议虚拟背景 | 1080p 循环 + 低对比 + 中心留白 | 高饱和、快运动 | 影响前景可读性 |
| 竖屏短视频背景 | 9:16 单独生成，主体偏上，底部留字幕区 | 横屏裁竖屏 | 裁切后构图散 |

## 2. 即梦参数基线

| 参数 | 建议值 | 说明 |
|---|---|---|
| 生成模式 | 图生视频 → 首尾帧 | 比文生视频可控，天然适合循环 |
| 画面比例 | 16:9（横屏）/ 9:16（竖屏） | 桌面与舞台用 16:9；短视频单独出 9:16 |
| 分辨率 | 1080p | 720p 在桌面全屏会糊 |
| 时长 | 5 秒起步，成片 8–10 秒 | 5 秒失败成本低；循环背景 8 秒最耐看 |
| 运镜 | 固定机位 / 静止 | 任何推拉摇移都会破坏循环 |
| 运动幅度 | 小 / 低 | 越大越容易融化、变形 |
| 帧率 | 24fps（电影感）/ 30fps（桌面更顺滑） | 默认 24fps；若桌面播放觉得不够顺滑再改 30fps |
| 首帧 / 尾帧 | 同一张静帧 | 首选方案；平台不允许同图时用 99% 相同副本 |
| 种子 | 固定 | 方便复现和微调 |
| 水印 | 关闭（会员） | 背景不能带平台水印 |
| 下载 | 下载原片 | 不要录屏，录屏必掉画质 |

> 若当前版本不提供「首尾帧」或「种子」：优先保证**固定机位 + 同一张静帧 + 小运动**，再用正放倒放 / 叠化补循环；参数以版本实际能力为准，不必强求本文每一项。

### 会员积分怎么花更合理

1. **静帧用图片生成，不用视频生成。** 视频积分贵，先在图生图阶段把构图定死。
2. **一次只做一个场景。** 一个场景 4 张静帧 → 选 1 张 → 1 条 5 秒视频 → 看效果再决定是否 10 秒。
3. **优先 5 秒。** 5 秒能过的循环，不要直接上 10 秒；10 秒失败一次等于两次 5 秒。
4. **固定种子做 A/B。** 同一张静帧只改运动描述，比较哪条更稳。
5. **下载原片，不做二次转码。** 剪映导出一次即可；反复导出会糊。
6. **把成功参数记下来。** prompt、种子、时长、首尾帧文件名，下次直接复用。

### CLI 调用是否免费（2026-11-17 实测）

- 网页端的「0 积分畅用」是网页侧活动 / 额度，CLI 不自动继承；CLI 帮助里也写着 `All generation operations consume credits`。
- CLI 的 `5.0lite` 在 2026-11-17 前两次 16:9 2K 测试中未扣费（余额 687 不变），但同一天 9:16 2K 生成扣了 16 积分（687→671）；随后 B/C 两张合计扣 35 积分（671→636），单张约 17–18。说明它可能是限时/限量免费，或按比例/尺寸计费，**不能当稳定免费模型**。
- 结论：每次生成前后都用 `dreamina user_credit` 对比余额，以实际扣费为准，不要依赖「免费」标签。
- 视频命令未见免费模型；`frames2video` 的模型列表里没有 lite / free 标识。生成前先 `dreamina user_credit` 记录余额，生成后再查一次；`credit_count` 并非每个模型都会返回。
- 免费额度 / 活动可能随时调整，以提交结果和余额变化为准。

```powershell
dreamina text2image --prompt="你的提示词" --ratio=16:9 --resolution_type=2k --model_version=5.0lite --generate_num=1 --poll=120
```

## 3. 标准作业流程（SOP）

| 步骤 | 操作 | 输出 | 检查点 |
|---|---|---|---|
| 1 | 写清用途：桌面 / 舞台 / 短视频 | 一句话场景目标 | 是否真的需要人物？不需要就纯背景 |
| 2 | 按「静帧提示词公式」生成 4 张 | 4 张 16:9 静帧 | 中心是否留白、是否无文字 |
| 3 | 选 1 张，必要时裁切、压暗、去杂物 | 1 张定稿静帧 | 首帧构图是否稳定 |
| 4 | 图生视频，首帧 = 尾帧 = 定稿静帧 | 5 秒视频 | 是否固定机位、是否微动 |
| 5 | 播放 3 次，检查接缝 | 循环预览 | 首尾是否同一构图 |
| 6 | 有接缝 → 叠化 / 正放倒放；无接缝 → 直接导出 | 8 秒循环 MP4 | 接缝是否不可见 |
| 7 | 导出 1080p / 30fps / H.264 | 成片 | 文件大小、色彩、无 watermark |
| 8 | 放入应用测试：叠 UI 文字看可读性 | 验收记录 | 中心区域是否抢字 |

## 4. 提示词公式

### 4.1 静帧公式

```text
[场景] + [时间/天气] + [环境主体] + [光线与色彩] + [镜头] + [构图留白] + [画质]
```

示例：

```text
深海背景，电影感动画场景，海面透下丁达尔光束，悬浮微粒与缓慢上升的气泡，
远处一只鲸鱼剪影，深蓝到青绿渐变，柔和体积光，
固定远景，画面中心留出低对比空白，无人物，无文字，16:9，高清，细腻颗粒
```

### 4.2 视频公式

```text
固定机位，无镜头运动，无转场；
[元素 A] 缓慢 [动作]，[元素 B] 轻微 [动作]；
画面首帧与末帧完全一致，5 秒无缝循环，可无限重复播放；
柔和体积光，低饱和[暖/冷]色调，浅景深，24fps；
[情绪]；中心区域低对比留白；16:9 / 9:16，1080p
```

示例：

```text
固定机位，无镜头运动，无转场；
气泡持续缓慢上升，光斑轻微呼吸，悬浮微粒缓慢漂移，远处鲸影极慢游过；
画面首帧与末帧完全一致，5 秒无缝循环，可无限重复播放；
柔和体积光，低饱和冷色调，浅景深，24fps；安静、治愈、低对比；
中心区域低对比留白；16:9，1080p
```

> 色彩按场景替换：深海、雨夜用「低饱和冷色调」或「青蓝色调 + 少量暖色点缀」；深夜工位用「低饱和暖色调」。`24fps` 是成片帧率，生成后可在剪映统一；如果桌面播放觉得不够顺滑，再改 30fps。
>
> 「首帧与末帧完全一致」是目标，不是模型保证。实际仍要用同一张图做首尾帧，并在播放 3 次后检查接缝。对气泡上升这类有方向性的运动，首尾「分布密度一致」比「同一批气泡回到原位」更自然。

### 4.3 通用负向提示词

```text
人物，角色，人脸，文字，字幕，水印，Logo，UI，边框，
镜头推进，镜头拉远，镜头平移，镜头旋转，手持晃动，转场，剪辑，
快速运动，剧烈闪烁，颜色跳变，画面撕裂，变形，融化，多余肢体，
高对比，过曝，死黑，密集鱼群，复杂前景
```

> 负向词不是越多越好。优先保留：**人物、文字、水印、镜头运动、转场、变形**。

## 6. 无缝循环的三种做法

### 方法 A：首尾帧同图（首选）

**原理**：首帧和尾帧是同一张图，模型在生成过程中必须回到起点，天然形成闭环。

操作：

1. 在即梦图生视频中选择「首尾帧」。
2. 首帧上传定稿静帧。
3. 尾帧上传**同一张图**。
4. 视频提示词只写微动，明确「首尾画面一致，无缝循环」。
5. 生成 5 秒，播放 3 次检查。

如果平台不允许首尾帧完全相同：

- 把同一张图复制一份，裁掉 1% 边缘，或亮度 ±1%，让文件不同但画面几乎一致。
- 仍按首尾帧上传，后期叠化 0.3 秒即可。

**优点**：最稳、最省事、不需要 FFmpeg。  
**缺点**：模型可能在中段「绕路」，需要挑一条运动自然的。

---

### 方法 B：正放 + 倒放（Boomerang）

**适用**：云、雾、烟、热气、尘埃、光斑呼吸、水波焦散等**没有明确方向**的运动。  
**不适用**：雨、雪、瀑布、人流、车流——倒放会明显反物理。

剪映操作：

1. 视频拖入时间线。
2. 复制一段，右键「倒放」。
3. 两段首尾相接。
4. 删除接缝处重复的一帧（可选）。
5. 导出。

FFmpeg（去掉倒放段第一帧，避免重复帧）：

```powershell
ffmpeg -i in.mp4 -filter_complex "[0:v]split=2[forward][back];[back]reverse,trim=start_frame=1,setpts=PTS-STARTPTS[rev];[forward][rev]concat=n=2:v=1:a=0[v]" -map "[v]" -an -c:v libx264 -crf 18 -pix_fmt yuv420p -r 30 loop.mp4
```

> 正放 + 倒放会让时长翻倍：5 秒变 10 秒。适合做 10 秒背景。

---

### 方法 C：首尾叠化（Crossfade）

**适用**：雨、雪、海浪等有方向、不能倒放的运动；或首尾帧同图仍有轻微接缝。  
**原理**：把开头 1 秒叠到结尾 1 秒上，再删掉开头 1 秒，让新片头和新片尾落在同一帧。

剪映操作：

1. 复制开头 0–1 秒，放到时间线末尾。
2. 末尾这 1 秒与原片最后 1 秒做「叠化」转场（1 秒）。
3. 删除原片开头 0–1 秒。
4. 导出。

结果：新片头 = 原片第 1 秒，新片尾 = 原片第 1 秒，首尾同帧。

FFmpeg（以 5 秒素材、1 秒叠化为例）：

```powershell
ffmpeg -i in.mp4 -filter_complex "[0:v]split=2[body][head];[head]trim=start=0:end=1,setpts=PTS-STARTPTS,format=yuva420p,fade=t=in:st=0:d=1:alpha=1[ov];[body]trim=start=1,setpts=PTS-STARTPTS[main];[main][ov]overlay=enable='gte(t,3)'[v]" -map "[v]" -an -c:v libx264 -crf 18 -pix_fmt yuv420p -r 30 loop.mp4
```

参数换算：

| 原片时长 D | 叠化时长 X | 输出时长 | overlay 起始时间 |
|---|---|---|---|
| 5 秒 | 1 秒 | 4 秒 | 3 秒 |
| 6 秒 | 1 秒 | 5 秒 | 4 秒 |
| 8 秒 | 1 秒 | 7 秒 | 6 秒 |
| 8 秒 | 0.5 秒 | 7.5 秒 | 7 秒 |

> overlay 起始时间 = D − 2X。输出会比原片短 X 秒，这是正常的。

## 7. 桌面 / 舞台适配规范

| 项目 | 规范 | 原因 |
|---|---|---|
| 分辨率 | 1920×1080（16:9） | 桌面全屏与舞台通用 |
| 帧率 | 30fps 恒定 | 避免播放器抖动 |
| 编码 | H.264 High / yuv420p | 兼容性最好 |
| 码率 | 8–12 Mbps（发布包）；4–6 Mbps（内置包） | 兼顾清晰与体积 |
| 音频 | 无音轨 | 背景视频静音，声音由应用控制 |
| 时长 | 8–10 秒 | 循环点少，文件不大 |
| 中心安全区 | 中间 60% 宽度、50% 高度低对比 | UI 文字、角色不被背景抢 |
| 亮度 | 整体 15%–45%，避免纯白高光 | 暗色主题不刺眼 |
| 对比 | 中低对比，暗部保留细节 | 避免「死黑」和色带 |
| 颗粒 | 轻微胶片颗粒 | 抑制渐变色带 |
| 循环点 | 首尾同帧或叠化 | 禁止闪白、跳色、跳构图 |

### 应用内叠加建议

- 背景视频上叠一层 `rgba(0,0,0,0.10–0.25)` 的暗色遮罩，保证文字可读。
- 桌宠站在画面中心偏下时，中心区域不要有亮斑。
- 舞台三席并排时，左右两侧可以略亮，中间保持安静。
- 深色 / 浅色主题各准备一版，或至少准备一版可被 CSS 滤镜压暗的中性版。

## 9. 常见问题

| 问题 | 常见原因 | 处理 |
|---|---|---|
| 首尾接不上 | 模型没有回到起点 | 首尾帧同图；降低运动幅度；缩短到 5 秒；叠化 0.5 秒 |
| 画面融化 / 变形 | 运动太大、主体太复杂 | 简化环境；去掉前景杂物；固定机位；5 秒 |
| 镜头自己动了 | 提示词里有「推进 / 环绕 / 航拍」 | 删除运镜词，明确「固定机位，无镜头运动」 |
| 画面闪烁 | 光源不稳、模型逐帧不一致 | 加「稳定光照，无闪烁」；降低运动；后期轻微降闪 |
| 出现文字 / 水印 | 模型自行添加 | 负向词加「文字，水印，Logo，UI」；裁切；重生成 |
| 出现人物 | 场景描述暗示了人 | 负向词加「人物，角色，人脸」；静帧阶段就清掉 |
| 暗部有色带 | 8-bit 渐变 + 高压缩 | 加轻微颗粒；提高码率；避免大面积纯色渐变 |
| 下载后变糊 | 录屏或多次转码 | 下载原片；只导出一次；不要反复压缩 |
| 积分消耗快 | 直接 10 秒、反复抽卡 | 静帧先定稿；5 秒起步；同种子只改一个变量 |
| 即梦生成的角色不像 | 2D 模型无法稳定还原 VRM | 不让即梦生成角色；用应用内 VRM 实拍 |
