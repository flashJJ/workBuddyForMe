# v2.13 M0：可治理的 Agent——契约冻结

> 状态：📐 评审完成（2026-10-31，见 [01-M0-评审记录](01-M0-评审记录.md)），待产品口径确认后冻结
> 范围：权限模式与工作目录、策略即代码、审批绑定、审计账本、定时 Agent 任务；隔离网页会话列 P1。
> 原则：默认行为与 v2.12 一致；deny 永远优先；无审批入口一律拒绝；治理证据不可静默丢失。
> 关联：[v2.13 方案](README.md) · [竞品对比与借鉴](00-竞品对比与借鉴.md)

## 0. 冻结决策摘要

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 五档模式：`confirm_each`（默认）/ `auto_edits` / `smart_approve` / `plan_only` / `full_access` | 覆盖从「每步问」到「本次全放」的连续控制；默认档等价 v2.12 |
| D2 | 模式只作用于本次运行，不写入长期授权 | 避免「一次放宽」变成永久放宽；长期授权仍走既有 remember |
| D3 | 工作目录可选；文件 / 命令类操作越界拒绝 | 桌面键鼠无法用目录约束，只受工具策略与模式控制 |
| D4 | 策略存 settings JSON，`deny` 永远优先 | 不引入新表；规则语言保持最小 |
| D5 | 审批绑定操作指纹；执行前比对，漂移即拒 | 防止「批准的是 A，执行的是 B」 |
| D6 | 审计独立表 + 哈希链；迁移 v041 纯加法 | 账本需要完整性与可查询；不污染业务时间线 |
| D7 | 定时 Agent 复用 `scheduled_tasks`，payload 判别联合 | 不新增调度表；运行历史落 `task_runs` |
| D8 | 无人值守审批挂起 + 超时拒绝；错过触发不补跑 | fail-closed；与既有提醒「错过即跳过」口径一致 |
| D9 | 隔离网页会话列 P1，不阻塞 v2.13 发布 | 需要新浏览器工具与桌面壳配合，先做治理内核 |
| D10 | 审计本版不自动清理 | 清理会断链；先保留完整账本，归档方案后置 |
| D11 | 调度改为服务端常驻循环（10s），渲染进程 tick 仅作兜底 | 否则无人值守任务在没有页面时永远不会触发 |
| D12 | 「无人值守」以应用进程存活为前提；应用退出即不运行 | 本版不做开机自启 / 系统服务 / 云调度，不夸大能力 |
| D13 | 模式（mode）只作用于 `task_runs`；聊天与协作 Agent 按策略 `defaultMode` 执行 | 避免为 `agent_runs` 再加一套模式字段与迁移 |
| D14 | 桌面输入 / 启动 / 关窗类 danger 工具永不被 `smart_approve` 自动放行 | 目标窗口上下文无法在策略层可靠证明；只允许逐次审批或 `full_access` |
| D15 | `full_access` 需要服务端确认字段，不能只靠前端弹窗 | 防止直接调 API 绕过二次确认 |

## 1. 权限模式契约

### 1.1 枚举

```ts
export const AGENT_PERMISSION_MODES = [
  'confirm_each',
  'auto_edits',
  'smart_approve',
  'plan_only',
  'full_access',
] as const;
export type AgentPermissionMode = (typeof AGENT_PERMISSION_MODES)[number];
```

工具仍使用既有三级分类：`read` / `write` / `danger`（见 `packages/shared/src/types/permission.ts`）。模式不改变工具分级，只决定「当前运行如何对待某一级」。

### 1.2 模式 × 工具级别矩阵

| 模式 | read | write | danger | 无人值守 |
|---|---|---|---|---|
| `confirm_each` | 允许 | 询问 | 询问 | 允许，遇到询问挂起审批 |
| `auto_edits` | 允许 | 工作目录内允许；目录外询问 | 询问 | 允许，遇到询问挂起审批 |
| `smart_approve` | 允许 | 工作目录内允许 | 策略 `dangerAllow` 命中则允许，否则询问 | 允许，遇到询问挂起审批 |
| `plan_only` | 允许 | 拒绝 | 拒绝 | 允许（只读任务） |
| `full_access` | 允许 | 允许 | 允许 | 仅当策略显式允许该模式 |

补充规则：

- `full_access` 在任务启动时必须二次确认；确认一次只对本次运行有效。API 创建任务时必须显式携带 `acknowledgeFullAccess: true`，缺失返回 422。
- `full_access` 仍受策略 deny 与系统硬拒绝约束，不是「无视一切」。
- `plan_only` 允许产出计划、读取信息，不执行任何变更；用于「先看看要做什么」。
- `write` 类若需要路径但任务没有工作目录：`auto_edits` / `smart_approve` / `full_access` 一律降级为询问；`plan_only` 拒绝。
- **桌面控制类 danger 工具**（`mouse_*` / `keyboard_*` / `app_launch` / `window_focus` 等）即使出现在 `dangerAllow` 中，也不会被 `smart_approve` 自动放行；只允许逐次审批或 `full_access`。`fetch_webpage` 与 MCP 工具可按策略放行。

### 1.3 决策优先级（固定）

```
1. 系统硬拒绝（永久禁止对外暴露的桌面输入类操作等）
2. 策略 deny（工具 / 路径 / 域名 / 命令）
3. 已有权限 deny（tool_permissions.action = 'deny'）
4. 模式处置（allow / ask / deny）
5. 策略 allow（仅 write；danger 仅在 smart_approve 且命中 dangerAllow）
6. 已有授权 allow（remember：assistant / all / task）
7. 默认：read 允许；write / danger 询问
```

- **deny 永远优先**：任何一层 deny 都直接拒绝，后续不再求值。
- 策略 allow 不能把 `confirm_each` 的 danger 询问变成允许；danger 的放宽只有 `smart_approve + dangerAllow` 或 `full_access` 两条路径。
- 模式不产生新的持久授权记录；运行结束后失效。

### 1.4 与既有权限记录的兼容

| 既有能力 | v2.13 处置 |
|---|---|
| `isAllowed()` 按工具 × scope | 保留；作为第 3、6 层输入 |
| `remember=assistant/all` | 保留；仍可长期允许某工具 |
| `remember=task` 任务授权 | 保留；任务内有效 |
| 工具三级权限 | 保留；矩阵按级别解释 |

### 1.5 作用范围

- **桌面任务运行**（`task_runs`）：创建时选模式，写入 `permission_mode`；整个运行固定不变。
- **聊天工具调用**：不提供逐轮模式选择，统一按 `policy.defaultMode` 求值；策略、审批、审计仍然全量生效。
- **协作 Agent**（v1.4 多智能体）：其子任务同样落 `task_runs`，但不再单独选模式，按 `policy.defaultMode` 执行；预算与步数沿用协作预算。
- 本版不为 `agent_runs` 增加模式字段；若后续需要「协作任务也选模式」，再单独迁移。

## 2. 工作目录契约

### 2.1 定义

`workspacePath` 是本次运行允许读写的根目录，可选。桌面键鼠 / 窗口类操作不受目录约束；文件写入、命令执行、外部代理 cwd 受约束。

### 2.2 校验步骤（创建时与执行时各一次）

1. 去首尾空白；必须为绝对路径；
2. 归一化（Windows 盘符大写、`\` 统一、去掉末尾分隔符）；含 `..` 的归一化结果必须仍是绝对路径；
3. 必须存在且是目录；
4. realpath 解析后再校验一次（防符号链接逃逸）；
5. 拒绝：盘符根、系统目录（Windows / Program Files / ProgramData 等）、用户主目录根、应用数据根、应用安装目录；
6. 拒绝：realpath 落在上述任一目录内；路径比较在 Windows 不区分大小写，POSIX 区分；
7. 不存在 / 不可读 → 422 `WORKSPACE_INVALID`。

### 2.3 运行期

- 执行前再次校验目录存在；消失则拒绝 `WORKSPACE_MISSING`。
- 文件 / 命令类工具的每个路径参数都必须落在目录内；越界拒绝 `WORKSPACE_ESCAPE`。
- 敏感目录（默认：`.ssh`、`.gnupg`、浏览器配置目录、密钥目录）即使位于工作目录内也拒绝，除非策略显式加入 `paths.allowedRoots` 的例外（不提供例外则不提供）。
- 工作目录不是安全边界：它限制「助手主动访问的范围」，不防恶意代码；包内代码执行仍禁止。

### 2.4 适用范围（本版）

- 外部代理 CLI 的 `cwd`：必须等于或位于工作目录内；否则 422。
- MCP 提供的文件类工具：路径参数按 §2.3 校验；无法识别路径参数的工具不做目录推断，只受策略与审批约束。
- 内置键鼠 / 窗口类工具：**不适用工作目录**；它们受模式、策略与审批约束，审批绑定目标窗口 / 进程。
- 本版不新增内置文件读写 / shell 工具；工作目录的价值主要在外部代理与 MCP 文件工具。若要给桌面 Agent 增加文件能力，需要单独立项（同时把路径校验下沉到工具执行层）。

## 3. 策略即代码契约

### 3.1 存储与形状

存 settings JSON 的 `agentPolicy`。形状：

```ts
interface AgentPolicy {
  version: 1;
  defaultMode: AgentPermissionMode;
  unattended: {
    allowedModes: AgentPermissionMode[]; // 默认 ['plan_only','auto_edits','smart_approve','confirm_each']
    maxConcurrentRuns: number;           // 1..3，默认 1
  };
  tools: {
    deny: string[];        // 精确名或后缀 *，如 'mcp:*'
    allow: string[];       // 仅对 write 生效
    dangerAllow: string[]; // 仅 smart_approve 下对 danger 生效
  };
  paths: {
    allowedRoots: string[]; // 额外允许的根（仍受敏感目录限制）
    deniedRoots: string[];  // 显式拒绝
    sensitiveNames: string[]; // 默认 ['.ssh','.gnupg','.aws','.config/gcloud']
  };
  domains: { allow: string[]; deny: string[] }; // fetch_webpage 等出站工具
  exec: { allowCommands: string[]; denyCommands: string[] }; // 外部代理命令
  limits: {
    maxSteps: number;          // 1..50，默认 20
    maxRuntimeMs: number;      // 默认 10 分钟
    maxWritesPerRun: number;   // 默认 100
    maxExternalCallsPerRun: number; // 默认 20
  };
}
```

### 3.2 默认值

- `version: 1`；`defaultMode: 'confirm_each'`；
- 所有 allow / deny 列表为空；敏感目录为默认列表；
- `limits.maxSteps` 取现有 `TASK_MAX_STEPS` 口径，不放大；
- 读取时非法值回落默认；未知字段丢弃；规则总数 > 50 或单条 > 256 字符直接拒绝保存。

### 3.3 求值

- 工具名匹配：精确匹配或后缀 `*`（`mcp:*` 匹配所有 MCP 工具）；不支持正则与中间通配。
- 域名匹配：完整域名或 `*.` 前缀；端口必须显式。
- 命令匹配：可执行文件名或绝对路径；不接受参数级匹配。
- 每次求值返回：

```ts
interface PolicyDecision {
  decision: 'allow' | 'deny' | 'ask';
  reasonCode: string; // POLICY_DENY / PERMISSION_DENY / MODE_ASK / MODE_DENY / GRANT_ALLOW / DEFAULT_ASK ...
  layer: 'hard' | 'policy' | 'permission' | 'mode' | 'grant' | 'default';
  matchedRule?: string;
}
```

- 决策写入审计事件（含 `policy_hash` 与 `matchedRule`），不写完整参数值。

### 3.4 变更

- 保存前 Zod 校验 + 计算 `policyHash = sha256(canonicalJson(policy))`（复用 shared canonical 实现）。
- 保存成功写审计 `policy_updated`，带旧 / 新哈希；不保存完整策略快照到审计（设置里可查当前值）。
- 任务运行创建时把当前策略快照写入 `task_runs.policy_snapshot_json`，用于复现当时的判断口径。
- 设置页支持可视化编辑与 JSON 导入导出；导入失败不落盘。

### 3.5 实现约束（哈希与规范化）

- 审计、审批绑定、策略哈希都需要稳定的 JSON 字节串；当前 `canonicalValue` 是 `capability-signature.ts` 的私有函数，不能直接复用。
- 实施时抽到 shared 的通用 `canonicalJson(value)`（键递归排序、数组保序、拒绝非有限数字与函数），能力包签名改为调用它并保留原有域前缀与 `signature` 剔除逻辑。
- 黄金向量测试覆盖：键序、数组、Unicode、转义、数字、缺省字段；能力包签名测试必须保持通过。
- 哈希统一使用 `sha256`（`node:crypto` 只在 core / database 侧），shared 只提供 canonical 纯函数。

## 4. 审批绑定契约

### 4.1 绑定形状

```ts
interface OperationBinding {
  tool: string;
  argsHash: string;      // sha256(canonicalJson(args))
  cwd?: string;          // realpath
  envHash?: string;      // sha256(canonicalJson(env))，仅存哈希
  fileOperands?: string[]; // 归一化后的绝对路径，升序
  target?: { windowId?: string; processName?: string };
  policyHash: string;
}
```

### 4.2 时机

- 审批请求生成时计算并展示摘要；
- 用户允许后，执行前重新计算；
- 字段任一变化 → `APPROVAL_BINDING_DRIFT`（409），拒绝执行并审计；
- 用户拒绝 / 超时 / 断线 / 无审批 UI → 拒绝，结构化回灌模型。

### 4.3 外部代理

- 运行审批绑定 `command`、`args[]`、`cwd`、`envHash`；
- 子进程 `permission` 帧绑定 `frameId + argsHash`；
- 命令 / 参数 / cwd / 环境任一漂移 → 拒绝该帧或终止运行，并审计；
- 审批超时沿用 5 分钟；无审批入口 fail-closed。

### 4.4 展示

审批中心显示：工具、级别、参数摘要、工作目录、目标窗口 / 进程、策略来源。用户点「允许一次」只对该 binding 生效；「记住」沿用既有长期授权语义，并在审计中记录为 `grant`。

### 4.5 实现接入点（评审补充）

- `gateToolPermission` 当前只接收 `argsSummary`，拿不到原始参数；需新增 `args` 或 `binding` 入参，由调用方（`chat/tool-call-loop.ts`、`agent/task-loop.ts`）传入。
- 审批登记前计算 binding；登记项携带 binding 摘要；审批通过后、工具执行前再计算一次并比对。
- 桌面控制的 `target` 取当前前台窗口（`windowId` + `processName`）；窗口在审批后变化视为漂移。
- 外部代理在 `subagent-run-service` 中从已解析的 command / args / cwd / settings 计算 binding；无需把命令写进 `subagent_runs` 表。
- 所有调用点的测试必须补 binding 参数；未提供 binding 的旧路径按「无绑定」处理，但仍受策略与模式约束。

## 5. 审计账本契约

### 5.1 表结构（迁移 v041）

```sql
CREATE TABLE audit_events (
  id TEXT PRIMARY KEY,
  seq INTEGER NOT NULL UNIQUE,
  created_at TEXT NOT NULL,
  kind TEXT NOT NULL,
  actor TEXT NOT NULL,              -- 'user' | 'agent' | 'system'
  run_id TEXT,
  conversation_id TEXT,
  tool TEXT,
  decision TEXT,                    -- 'allow' | 'deny' | 'ask'
  reason_code TEXT,
  policy_hash TEXT,
  binding_json TEXT,
  outcome TEXT,
  prev_hash TEXT NOT NULL,
  hash TEXT NOT NULL
);
CREATE INDEX idx_audit_created ON audit_events(created_at);
CREATE INDEX idx_audit_run ON audit_events(run_id);
CREATE INDEX idx_audit_kind ON audit_events(kind);
```

`seq` 单调递增：追加时在同一事务内取 `max(seq) + 1`，唯一索引兜底并发写入。

### 5.2 事件种类

| kind | 触发 |
|---|---|
| `policy_updated` | 策略保存成功 |
| `policy_denied` | 策略 / 权限 deny 阻止 |
| `approval_requested` | 审批项登记 |
| `approval_granted` / `approval_denied` / `approval_timeout` | 审批结果 |
| `binding_drift` | 执行前绑定不一致 |
| `run_started` / `run_finished` | 任务运行生命周期 |
| `scheduled_run_started` / `scheduled_run_finished` | 定时 Agent 触发与终态 |
| `unattended_blocked` | 无人值守模式不被允许 |
| `audit_verified` | 完整性校验执行 |

### 5.3 哈希链与追加事务

```
hash = sha256(prev_hash + "\n" + canonicalJson(eventWithoutHashAndPrev))
```

- `prev_hash` 取上一条的 `hash`；首条 `prev_hash = 'GENESIS'`；
- 追加在单事务内完成：读上一条 hash → 计算 → 插入；`better-sqlite3` 同步执行，天然串行；
- 不允许先插入再补 hash；不允许跳过 `seq`；
- 校验按 `seq` 升序重算，返回首个断链 seq；
- 本版不清理、不提供删除 / 修改接口；导出 JSONL 供外部归档。

### 5.4 写入失败策略

- 治理关键事件（策略决策、审批结果、绑定漂移）：追加失败 → **fail-closed**，操作拒绝并返回 `AUDIT_UNAVAILABLE`；
- 运行生命周期事件：追加失败 → 控制台告警，运行继续；
- 任何审计内容不含密钥、完整环境变量、完整参数值（只存哈希与摘要）。

### 5.5 查询与导出

- `GET /api/audit/events?from&to&kind&runId&cursor&limit=100`（上限 200）；
- `POST /api/audit/verify` 返回 `{ ok, checked, firstBrokenSeq? }`；
- `GET /api/audit/export?format=jsonl` 流式导出；
- 审计页展示链状态、过滤、详情；无删除按钮。

## 6. 定时 Agent 任务契约

### 6.1 payload 判别联合

```ts
type ScheduledTaskPayload =
  | { kind: 'follow_up'; conversationId?: string; planId?: string; runId?: string }
  | {
      kind: 'agent_task';
      goal: string;              // ≤2000
      conversationId: string;
      assistantId?: string;      // 缺省取任务定义
      permissionMode: AgentPermissionMode;
      workspacePath?: string;
      maxSteps?: number;
      notify: 'work_signal' | 'desktop' | 'none';
    };
```

`scheduled_tasks.text` 仍作为展示标题（≤200），`goal` 放 payload。

### 6.2 创建校验

- `permissionMode` 必须在 `policy.unattended.allowedModes` 中，否则 422 `UNATTENDED_MODE_NOT_ALLOWED`；
- `full_access` 出现在白名单时，创建仍必须带 `acknowledgeFullAccess: true`；
- `workspacePath` 按 §2 校验；
- 创建时解析会话 / 助手 / 模型；模型不具备视觉能力则 422（桌面任务无法观察屏幕）；
- 同一任务不允许存在两个未结束的 Agent 运行（启动时检查，冲突记 `SKIPPED_ACTIVE_RUN` 并审计）；
- 提醒 → Agent 任务的类型切换不允许就地改 payload，需新建任务（避免历史语义漂移）。

### 6.3 触发与运行

**调度驱动**（评审补充）：

- Web 服务端启动时常驻 `setInterval(10s)`，单进程单例（`globalThis` 防 Next 热重载重复注册）；循环内 `listDue → markFired → deliver`。
- 渲染进程的 10s tick 保留为兜底：两端都调用 `markFired`，以「先标记后投递」保证同一次触发只执行一次。
- 服务端 tick 保留 `GET /api/schedules/due` 现有的关系检查点与里程碑扫描副作用，避免行为回退。
- 应用进程退出后调度停止；本版不做开机自启 / 系统服务 / 云调度。

**运行流程**：

1. tick 命中（先标记后投递，沿用既有口径）；
2. `agent_task` 创建 `task_run`（`origin_scheduled_task_id`），状态 `queued`；
3. 复用 `resolveTaskLaunchArtifacts` + `taskRunner.start` 后台启动，不依赖 SSE 观察者；
4. 遇到询问 → 审批中心登记，运行挂起；超时（5 分钟）→ 拒绝，运行按拒绝继续或失败；
5. 终态 → WorkSignal 事件（始终）+ 桌面通知（有渲染进程时尽力而为）；写审计 `scheduled_run_finished`；
6. 错过触发不补跑；失败不自动重试（本版）。

### 6.4 限额

- 同时运行的定时 Agent 任务 ≤ `policy.unattended.maxConcurrentRuns`；
- 每次运行步数 / 时长 / 写入 / 外部调用受策略限额约束；
- 超限终止并记录 stopReason（沿用任务运行 stopReason 枚举，新增 `policy_limit`）。

### 6.5 边界（必须写进用户可见文案）

- 只有在应用进程存活时才会触发；应用退出后不会「到点自己跑」。
- 应用在运行但窗口全关时，审批可能无人处理；5 分钟超时后按拒绝，运行可能因此失败。
- WorkSignal 是唯一可靠通知；桌面系统通知依赖渲染进程存在，属于尽力而为。
- 本版不做失败重试、补跑、开机自启；也不把定时任务变成系统级服务。

## 7. API 契约

| 方法 | 路径 | 说明 |

错误码（HTTP 状态 + `details.code`）：

| 场景 | 状态 | code |
|---|---|---|

## 8. 数据模型与迁移

### 8.1 v041 纯加法

```sql
ALTER TABLE task_runs ADD COLUMN permission_mode TEXT NOT NULL DEFAULT 'confirm_each';
ALTER TABLE task_runs ADD COLUMN workspace_path TEXT;
ALTER TABLE task_runs ADD COLUMN policy_snapshot_json TEXT;
ALTER TABLE task_runs ADD COLUMN origin_scheduled_task_id TEXT;
-- audit_events 见 §5.1
```

- `LATEST_SCHEMA_VERSION` 40 → 41；新增 `v041-agent-governance.ts` + 迁移测试；
- 既有运行默认 `confirm_each`，不回溯；
- 旧版本打开新库：忽略新增列与 `audit_events`，不删除数据；
- 回退口径：v2.12 可继续使用任务与定时提醒；审计账本保留但旧版本不可见。

### 8.2 视图与枚举

- `TaskRunView` 新增：`permissionMode: AgentPermissionMode`、`workspacePath: string | null`、`originScheduledTaskId: string | null`；`policySnapshot` 不直接出参，出参附带 `policyHash`。
- `TASK_STOP_REASONS` 新增 `policy_limit`（策略步数 / 时长 / 写入 / 外部调用超限）。
- `WorkApproval` 新增可选 `bindingSummary`（工具、参数摘要、目录、目标窗口）与 `policyReason`（决策来源）；不把完整 args / env 传给前端。
- `ScheduledTaskView.payload` 变为判别联合；旧 `follow_up` 行保持兼容。
