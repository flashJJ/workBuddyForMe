## 2. 哈希链与失败策略

1. `hash = sha256(prev_hash + "\n" + canonicalJson(事件去掉 hash / prev_hash))`；首条 `prev_hash = 'GENESIS'`。
2. 追加在同一次同步调用内读取链尾、计算并插入；`seq` 唯一索引兜底并发。`better-sqlite3` 同步执行，单进程天然串行。
3. 校验按 `seq` 升序重算，检查 `prev_hash`、内容哈希与 `seq` 连续性，返回首个断链 `seq`；校验本身追加 `audit_verified`。
4. 治理关键事件（策略拒绝 / 审批请求与结果 / 绑定漂移）追加失败 → 操作拒绝；运行生命周期与策略变更写入失败 → 告警后继续。
5. 不提供删除 / 修改 API / UI；本版不清理（产品口径 Q2）。

## 3. 事件接入点

| kind | 接入 |
|---|---|
| `policy_updated` | 设置保存 `agentPolicy` 成功 |
| `policy_denied` | 门控策略拒绝 / 显式权限 deny；外部代理路径或命令被拒 |
| `approval_requested` | 工具 HITL 登记；外部代理运行审批；子进程权限帧 |
| `approval_granted` / `approval_denied` / `approval_timeout` | 确认结算回调（区分 allow / deny / timeout / abort）；外部代理审批结果 |
| `binding_drift` | 工具执行前重算不一致；外部代理审批后设置变化 |
| `run_started` / `run_finished` | 任务运行启动 / 终态（含 stopReason） |
| `audit_verified` | 每次完整性校验 |

`run_started` 的 `outcome` 记录 `mode:<permissionMode>`，`policyHash` 取自运行策略快照；`run_finished` 记录 `status[:stopReason]`。

## 4. API 与页面

- `GET /api/audit/events?from&to&kind&runId&cursor&limit`：`createdAt` 闭区间、seq 游标、倒序、`nextCursor`。
- `POST /api/audit/verify`：返回 `{ ok, checked, firstBrokenSeq }`。
- `GET /api/audit/export?format=jsonl`：ReadableStream 流式导出，升序、每行一条 canonical JSON。
- 页面：进入即校验一次链状态；支持 kind / runId / 时间过滤；详情展开绑定、策略哈希、事件哈希与前序哈希；导出走浏览器下载；无删除入口。

## 6. 已知边界

- **尾部截断不可检出**：链本身只能发现中间篡改 / 断链；整表删除尾部事件后，剩余链仍自洽。需要外部锚点（导出归档哈希、后续版本签名）才能覆盖，本版不做。
- **策略变更审计为旁路**：保存成功后再追加，写入失败只告警，不阻断保存（M0 §5.4 的 fail-closed 清单未包含 `policy_updated`）。
- **子进程权限帧的「请求」事件是尽力而为**：帧审批结果写入失败不会否决已发生的帧决策；运行审批请求与结果仍 fail-closed。
- **定时 Agent 事件（`scheduled_run_started/finished`、`unattended_blocked`）契约已就位，M4 调度接线时写入**。
- **页面进入即校验会追加 `audit_verified`**：属于契约行为；若未来账本规模增大，可改为手动校验或按需缓存。
- **本版无保留期清理**：按产品口径保留完整链，归档方案后置。
