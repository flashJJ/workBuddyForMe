## 2. API 契约落地

- `GET /api/conversations/:id/run-graph?limit=&scope=`：会话必须存在；`scope` 只允许 chat/task/flow/agent。
- `GET /api/meetings/:id/run-graph?limit=`：会议必须存在；只读 meeting scope。
- 响应均为 `{ success: true, data: RunGraphSnapshot }`；根为 `rootKind/rootId`。

## 3. 会议事件写入

- `MeetingServiceDeps.onEvent` 由容器注入；总线 `publish` 包装后统一回调。
- `meeting_turn` 落库为 `meeting_turn_start`；`meeting_message` / `meeting_status` 原样落库；`meeting_delta` / `error` 不入图。
- 写入是 best-effort：失败不阻断会议主链路。

## 5. 与 M0 契约的偏差

1. **实时刷新改为 2 秒轮询**：M2 首版图面板用 `refetchInterval: 2000` 刷新快照，未接 SSE 追加 reducer；原因是聊天页 SSE 会话状态未暴露原始事件，避免再开第二条 SSE。SSE 追加与光线联动统一留到 M3。
2. **首版只渲染车道 + 节点卡片**：边数据已随快照返回并参与测试，但 M2 面板未绘制连线；连线与 Light UI 在 M3 落地。
3. 会议 scope 已提前加入 timeline 下拉（M1 完成），本 M2 只新增会议图入口。

## 6. 已知限制 / M3 待办

- M3：Light UI 光线层 + 流动边框 + 边连线渲染 + SSE 追加 reducer。
- M3 需把聊天页原始 SSE 帧暴露给图面板，或增加轻量事件订阅接口；不得再开第二条全量 SSE。
- API 目前每次读取多运行事件；后续可在事件量增大时增加缓存/游标。
