## 2. 行为口径

- `StagePlan`：`steps` 1–8；标题 trim 后 1–40；技能去重、最多 12；目标/交付各 ≤4000；`activeStep` 为 null 或合法下标。
- 保存允许 `goal=''`；`prepare` 要求当前阶段目标非空。
- 模型必须存在且具备 `chat`；技能必须已启用、存在且 manifest 有效；否则 422。
- `PUT` 保存计划与 activeStep 模型写入 `conversations.model_id` 在同一事务；无模型阶段清空覆盖。
- `prepare` 返回 `{ taskText, modelId, stepIndex }`，不发送、不修改会话模型。
- 提示词按契约模板组装；技能路径取 `SkillInfo.sourcePath`；无技能/无交付段自动省略。
- 创建会话：助手显式阶段 > 当前角色卡默认阶段；复制时 activeStep 模型同步到会话模型。
- 应用角色卡：仅当助手 `stagePlan=null` 时复制卡默认阶段；不覆盖已有计划。
- 内置 6 张卡各 4 个阶段（`modelId=null`、技能空、`activeStep=null`）；老库只在阶段为空时补齐。
- 备份 schema 保持 7；新增字段可选，旧备份可直接恢复；目标库缺模型时 `model_id` 回落 null。

## 4. 与 M0 契约的偏差

1. **Schema 文件位置调整**：`schemas/work` 直接文件超目录预算，StagePlan Zod 移入 `schemas/work/stage-plan/schema.ts` 子域；公开导入仍走 `@wbfm/shared/schemas`。
2. **类型文件独立**：`StagePlan` 类型放在 `types/stage-plan/index.ts`，避免 `types ↔ schemas` 运行期循环。
3. **保存总是同步会话模型**：契约写「activeStep 变化时」更新；实现每次 PUT 都以当前 activeStep 的模型同步，保证清空/切换一致。
4. **`prepare` 的 modelId 口径**：返回 `step.modelId ?? conversation.modelId`，不修改会话，支持准备非当前阶段。
5. **`slashCommand` 未实现**：当前技能 manifest 无该字段；提示词路径使用 `SkillInfo.sourcePath`，待未来技能契约提供命令字段再补前缀。
6. **自定义卡不继承阶段**：复制内置卡为自建卡时只复制原文，`stagePlan=null`，符合「自定义卡默认 null」。
7. **聊天开流顺序变化**：先确定/创建会话再解析模型，以便读取会话覆盖；新建会话在模型/视觉校验失败前已落库，与 v2.19 会话创建先于视觉校验的时序一致。
8. **备份 schema 不升版**：按契约保持 7，仅新增可选字段；恢复端缺字段按 null。
