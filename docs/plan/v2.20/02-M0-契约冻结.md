## 2. RunGraph 类型契约

### 2.2 节点、边、车道、快照

### 2.3 节点身份与去重

| 节点 | 身份 `id` | 更新规则 |
|---|---|---|
| 根节点 | `root:<conversation\|meeting>:<rootId>` | 投影开始时建；`status=unknown`，只作为边锚点 |
| 会话主线消息 | `chat:<conversationId>:message:<messageId>` | `message_started` 建节点；completed/error/stopped 更新同节点 |
| 会话工具 | `chat:<conversationId>:tool:<callId>` | 同一 `callId` 只更新状态与结果摘要 |
| task 运行 | `run:task:<runId>` | `run_started` 建；终态更新 |
| task 步骤 | `task:<runId>:step:<stepId>` | `step_started` 建；`step_finished` 更新 |
| flow 运行 | `run:flow:<runId>` | `run_started` 建；终态更新 |
| flow 节点 | `flow:<runId>:node:<nodeId>` | started/succeeded/failed/skipped/waiting 更新同一节点 |
| agent 轮次 | `agent:<runId>:round:<round>:<role>` | `agent_phase` 建/更新 |
| agent 交接 | `agent:<runId>:handoff:<handoffId>` | `agent_handoff` 建；不重复 |
| agent 审查 | `agent:<runId>:review:<round>` | `agent_review` 建/更新 |
| 会议轮次 | `meeting:<meetingId>:turn:<index>` | `meeting_turn_start` 建 |
| 会议消息 | `meeting:<meetingId>:message:<messageId>` | `meeting_message` 建；不重复 |
| 产物 | `artifact:<attachmentId>` | 首次出现建；同一 attachmentId 去重 |
| 错误 | `error:<scope>:<scopeId>:<code>:<seq>` | 终态错误建；重试另建 retry 节点 |
| 重试 | `retry:<scope>:<scopeId>:<targetNodeId>:<seq>` | 只由 retry 事件建 |

规则：

1. 同一身份只更新 `status/summary/at`，不重复建节点。
2. 节点顺序按 `at` 升序；同一 `at` 按 `scope`、`seq`、`id` 稳定排序（`seq` 只在同 scope 内可比）。
3. `parentId` 只指向已存在的节点；找不到父节点时挂到对应 run/会话节点。
4. 未知/截断 payload 生成 `kind='wait'` 或通用节点，`status='unknown'`，不抛错。
5. 同一事件重复到达（SSE 重连/重放）按身份幂等更新。

## 3. 五域事件映射

| scope | 事件 | 节点/动作 | 边 |
|---|---|---|---|
| `chat` | `message_started` | `message`，`running` | conversation → message |
| `chat` | `message_completed` / `message_error` / `message_stopped` | 更新同 message 节点 | — |
| `chat` | `tool_trace` | `tool` 节点；若输出返回 `ArtifactRef`（如 `artifact_write`/`diagram_render`），另建 `artifact` 节点 | message → tool；tool → artifact |
| `task` | `run_started` | `run`（task） | conversation → run |
| `task` | `step_started` / `step_finished` | `task_step` | run → step；错误补 `error` 节点 |
| `task` | `run_finished` / `run_paused` / `run_resumed` | 更新 run 节点 | — |
| `flow` | `run_started` / `run_finished` | `run`（flow） | conversation → run |
| `flow` | `node_started` / `node_succeeded` / `node_failed` / `node_skipped` / `node_waiting_human` | `flow_node` | run → node；失败补 `error` |
| `flow` | `node_agent_event` | 按内部 `agent_*` 事件建子节点 | flow_node → agent 节点 |
| `agent` | `agent_phase` | `agent_phase` | run → phase；role lane |
| `agent` | `agent_handoff` | `agent_handoff` | phase → handoff |
| `agent` | `agent_review` | `agent_review` | round → review |
| `agent` | `agent_budget` | 只更新 lane/run 预算摘要，不建节点 | — |
| `agent` | `done` / `error` | 更新 run 节点；错误补 `error` | — |
| `meeting` | `meeting_turn_start` | `meeting_turn` | meeting → turn |
| `meeting` | `meeting_message` | `meeting_message` | turn → message |
| `meeting` | `meeting_status` | 更新 meeting lane 与状态节点 | — |

状态映射：`started/start → running`；`succeeded/completed/done → succeeded`；`failed/error → failed`；`skipped → skipped`；`waiting/paused → waiting`；`cancelled/stopped/aborted → cancelled`；`budget_exceeded → budget_exceeded`；无法识别 → `unknown`。

产物规则：只从 `tool_trace`、`task_step`、`agent_handoff` 等明确返回 `ArtifactRef`（`attachmentId`）的输出创建 `artifact` 节点；缺失核验证据时标 `artifactUnverified=true`；无 `attachmentId` 不建节点。

## 4. API 契约

### 4.1 图入口

| 根 | 路径 | 返回 `rootKind` |
|---|---|---|
| 会话 | `GET /api/conversations/:id/run-graph` | `conversation` |
| 会议 | `GET /api/meetings/:id/run-graph` | `meeting` |

Query：

- `limit?: number`，默认 500，范围 1–1000；超过上限钳制到 1000。
- 会话图 `scope?: 'chat' | 'task' | 'flow' | 'agent'`，缺省全部；不含 `meeting`。
- 会议图只接受 `scope=meeting`，缺省即 `meeting`。

响应遵循统一信封：

```json
{
  "success": true,
  "data": {
    "rootKind": "conversation",
    "rootId": "...",
    "generatedAt": "2026-11-03T...",
    "nodes": [],
    "edges": [],
    "lanes": [],
    "truncated": false
  }
}
```

错误：根不存在 → 404 `NOT_FOUND`；`limit/scope` 非法 → 422 `VALIDATION_ERROR`；投影异常 → 500 `INTERNAL_ERROR`。

### 4.2 实时追加

- 会话图实时追加只在聊天页现有 `POST /api/chat/stream` 的 SSE 流内生效；`/timeline` 图谱首版为 snapshot + 手动刷新。
- 会议图实时追加使用会议页现有 `meeting_turn/meeting_delta/meeting_message/meeting_status` 帧；不新增 SSE 端点。
- 客户端收到事件后，调用 `apps/web/src/features/run-graph/model/append-event.ts` 的纯函数更新图。
- 追加规则与 §2.3 身份一致；`meta/delta` 只更新 message 文本摘要，不按 token 建节点。
- `generatedAt` 作为历史基线：基线之前的事件不补演；基线之后的新身份才发射光线。
- 默认视图：对话/会议主线常显；task/flow/agent 运行默认折叠，聚焦当前运行；超过 `limit` 保留最近节点并标记 `truncated`。

## 5. `meeting` 事件契约

`session_events` 的 scope 增加 `meeting`；`scopeId = meetingId`。无数据库迁移。

| `type` | 时机 | 载荷 |
|---|---|---|
| `meeting_turn_start` | 一轮发言开始前 | `{ meetingId, mode, speakerIds, autoRounds }` |
| `meeting_message` | 消息落库后 | `{ meetingId, message: { id, speakerId, role, content, createdAt } }` |
| `meeting_status` | 状态机变更后 | `{ meetingId, status, mode, autoRounds }` |

约定：

1. 写入 best-effort：失败只 `console.warn`，不阻断会议。
2. 只写图需要的字段；不复制完整转录。
3. `/timeline` 的 `SCOPES` 增加 `meeting`；旧事件/旧备份不受影响。
4. 会议删除时事件保留（与 `session_events` 现有保留策略一致），图按事件回放；不级联删事件。

## 6. Light UI 契约

### 6.1 模块与 API

`apps/web/src/components/ui/light-layer/` 自研四个模块：

| 文件 | 职责 |
|---|---|
| `geometry.ts` | 纯函数：端点、控制点、缓动、路径采样；无 DOM |
| `svg.ts` | 创建/更新 SVG path、光圈；无 React |
| `light-layer.ts` | 图层生命周期、发射、暂停/恢复、销毁、并发上限 |
| `running-border.tsx` | 活跃节点流动边框组件；只读 `active/colorToken/label` |

```ts
export type LightAnchor =
  | Element
  | { x: number; y: number }
  | (() => Element | { x: number; y: number } | null);

export interface LightEmitInput {
  id: string;
  source: LightAnchor;
  target: LightAnchor;
  color: string;
  duration?: number;
  seed?: number;
  sourceKind?: 'model' | 'bubble';
}

export type FlightResult = 'arrived' | 'cancelled' | 'missing-anchor';

export interface LightFlight {
  finished: Promise<FlightResult>;
  cancel(): void;
}

export interface LightLayer {
  emit(input: LightEmitInput): LightFlight;
  pause(): void;
  resume(): void;
  destroy(): void;
}

export function createLightLayer(root?: HTMLElement): LightLayer;
```

### 6.2 行为约定

1. `duration` 默认 1200ms；两端慢、中段快；`seed ∈ [0,1)` 可固定轨迹。
2. 锚点在 `emit` 时解析；目标缺失返回 `missing-anchor`，不射向附近节点。
3. 同一 `id` 运行中重复发射 → 直接返回 `cancelled`，不叠加。
4. 同时最多 12 条；超出丢弃新发射并返回 `cancelled`，不排队。
5. `prefers-reduced-motion: reduce` → 不飞行，立即 `arrived`。
6. `document.hidden` → 自动 `pause()`；恢复可见 `resume()`。
7. `destroy()` 取消全部未完成光线，移除 SVG 与监听器。
8. 颜色只从语义 token 映射（如 `primary/info/success/warning/destructive`），不写死十六进制。
9. 流动边框 `aria-hidden="true"`；业务状态必须有文字/徽标，不只靠动效。
10. React 只在 `useEffect` 创建图层并在 cleanup `destroy()`；不把每帧进度放进 state。

### 6.3 发射时机

- 只在**新节点身份**出现或节点状态跃迁时发射；历史加载不发射。
- 不按 token/字符发射；同一 run 的连续 delta 合并为一次。
- 发射源：消息气泡或模型标识；目标：图节点。目标不可见时等待可 next paint 后重试一次，仍失败返回 `missing-anchor`。

## 7. 阶段计划契约

### 7.1 Schema 与上限

```ts
export const STAGE_PLAN_LIMITS = {
  maxStages: 8,
  maxTitleLength: 40,
  maxSkillsPerStage: 12,
  maxTextLength: 4000,
} as const;

export interface StagePlanStep {
  title: string;
  /** 本仓 models.id；null=清除会话覆盖，回落助手/系统默认 */
  modelId: string | null;
  skillNames: string[];
  goal: string;
  deliverables: string;
}

export interface StagePlan {
  steps: StagePlanStep[];
  /** 0-based；null=未选择 */
  activeStep: number | null;
}
```

Zod 规则：

- `steps` 1–8；`title` trim 后 1–40；`skillNames` 去重、每个 ≤256、最多 12；`goal/deliverables` ≤4000。
- `activeStep` 为 `null` 或 `0 ≤ n < steps.length`；否则 422。
- 保存时允许 `goal=''`；`prepare` 时 `goal` 必填。
- 模型 ID 必须存在且具备 `chat` 能力；校验在 core 服务层，不在 Schema 里查库。

### 7.2 存储与迁移 `v044`

```sql
CREATE TABLE IF NOT EXISTS conversation_stage_plans (
  conversation_id TEXT PRIMARY KEY REFERENCES conversations(id) ON DELETE CASCADE,
  plan_json TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

ALTER TABLE assistants ADD COLUMN stage_plan_json TEXT;
ALTER TABLE character_cards ADD COLUMN stage_plan_json TEXT;
ALTER TABLE conversations ADD COLUMN model_id TEXT REFERENCES models(id) ON DELETE SET NULL;
```

- 只允许这一条迁移；`plan_json` 存完整 `StagePlan`，`activeStep` 不单独建列，避免双真源。
- `assistants.stage_plan_json` / `character_cards.stage_plan_json` 可空；旧行默认 `NULL`。
- `conversations.model_id` 可空；旧行默认 `NULL`，行为与 v2.19 一致。
- `LATEST_SCHEMA_VERSION` 43 → 44；旧迁移测试的 `toBe(43)` 与 `applied` 数组同步。
- 迁移只 `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN`；不重建表、不改旧列。

### 7.3 角色卡与助手默认阶段

来源优先级：**会话自有 > 助手显式 `stagePlan` > 角色卡默认 `stagePlan` > 空**；只在目标为空时复制，已有内容不被下层覆盖。

- `Assistant` 视图与创建/更新入参增加可选 `stagePlan: StagePlan | null`；Schema 复用同一份。
- `CharacterCard` 视图增加可选 `stagePlan: StagePlan | null`；仅内置卡预置，自定义卡默认 `null`。
- 应用角色卡到助手：仅当助手 `stagePlan` 为空时，复制卡默认阶段；不覆盖已有计划。
- 创建会话：若助手 `stagePlan` 非空，深拷贝写入 `conversation_stage_plans`；助手无计划则取卡默认；仍为空则不建行。
- 助手/角色卡后续修改不回溯覆盖已建会话；会话内编辑只改 `conversation_stage_plans`。

内置 6 张角色卡的默认阶段（每张 4 个阶段，`modelId=null`、技能为空）：

| 角色卡 | 阶段 |
|---|---|
| 干练同事 | 明确目标 / 制定方案 / 执行交付 / 复盘验收 |
| 元气搭子 | 拆小目标 / 立即开始 / 阶段反馈 / 完成庆祝 |
| 沉稳顾问 | 澄清问题 / 权衡选项 / 给出建议 / 验证结论 |
| 暖心伙伴 | 了解现状 / 温和拆解 / 陪伴推进 / 回顾感受 |
| 调研先锋 | 搜集资料 / 对比分析 / 交叉核验 / 整理结论 |
| 学习教练 | 诊断水平 / 制定计划 / 讲解练习 / 复盘巩固 |

### 7.4 API

| 方法/路径 | 作用 | 说明 |
|---|---|---|
| `GET /api/conversations/:id/stage-plan` | 读取会话阶段 | 无行返回 `{ plan: null }` |
| `PUT /api/conversations/:id/stage-plan` | 保存完整计划 | body 为 `StagePlan`；校验失败 422；会话不存在 404；`activeStep` 变化时同一事务更新 `conversations.model_id` |
| `POST /api/conversations/:id/stage-plan/prepare` | 准备任务文本 | body `{ stepIndex }`；返回 `{ taskText, modelId, stepIndex }`；`modelId` 为生效的会话模型；不发送 |

`prepare` 规则：

1. `stepIndex` 必须存在；`goal` 非空。
2. 技能必须存在且启用；任一不可用 → 422，并返回不可用技能名。
3. 阶段 `modelId` 非空时必须存在且有 `chat` 能力；否则 422。
4. 不检查草稿（草稿在客户端）；不自动发送；不新建会话。
5. 不修改 `conversations.model_id`；模型只在该会话计划被 `PUT` 切换 activeStep 时更新。

### 7.5 提示词模板

```text
执行阶段：{title}

要解决的问题：
{goal}

使用以下技能；先读取各技能说明并遵循其中适用的要求：
```

- 无技能时省略技能段；`deliverables` 为空时省略交付段。
- 启用技能命令且第一个技能有 `slashCommand` 时，模板前加 `/{slashCommand} `。
- 技能路径来自当前启用技能清单；不使用模型自行猜测路径。

### 7.6 会话级模型

- `Conversation` 增加 `modelId: string | null`；`conversations.model_id` 可空，引用 `models.id`。
- `resolveChatTarget` 优先级改为：`conversation.modelId ?? assistant.modelId ?? defaultChatModelId`。
- 切换阶段（`PUT` 时 `activeStep` 变化）：阶段 `modelId` 非空 → 写入 `conversations.model_id`；为空 → 置 `NULL`（回落助手/系统默认）。同一事务完成，避免半更新。
- `chatRequestSchema` 不变；不接受客户端逐轮传入 `modelId`。
- 模型必须存在且具备 `chat`；否则 422 `VALIDATION_ERROR`。
- 缺省行为（`model_id=NULL`）与 v2.19 完全一致。
- 阶段 UI 显示当前会话生效模型；切到无模型阶段时显示“跟随助手默认”。

### 7.7 UI 状态与闸门

| 状态 | 行为 |
|---|---|
| `idle` | 无阶段计划：不显示阶段条；有计划但未选阶段：显示阶段条，`activeStep=null` |
| `editing` | 阶段编辑对话框；保存前前端校验，服务端再校验 |
| `prepared` | 任务文本已载入输入框，不自动发送；用户可编辑 |
| `running` | 会话流式/运行中：禁止编辑阶段、禁止载入任务 |
| `error` | 保存/准备失败：保留原草稿与阶段，提示原因 |

闸门：

1. 非空草稿 → 阻止「载入任务」，保留原文并提示。
2. 运行中 → 阶段编辑/载入按钮禁用；服务端不依赖该状态。
3. 技能不可用/模型无效 → 服务端 422；UI 定位到具体阶段字段。
4. 切换阶段不创建新会话、不清空上下文；只更新 `activeStep` 与会话 `model_id`。

## 8. 备份与恢复契约

- 备份 schema 保持 `CURRENT_BACKUP_SCHEMA_VERSION = 7`；新增字段为可选。
- conversations 轨：每个会话序列化 `stagePlan: StagePlan | null` 与 `modelId: string | null`；恢复时用同一 Schema 校验，缺失/非法按 `null` 处理，不阻断其他会话。
- events 轨：助手与角色卡序列化 `stagePlan`；恢复时同样可选校验。
- 不新增备份轨；旧备份（无 `stagePlan` / `modelId`）可直接恢复。
- 迁移与恢复测试必须覆盖：旧库升级、旧备份恢复、阶段计划 roundtrip、助手与角色卡默认阶段 roundtrip、会话模型 roundtrip。

## 10. 验收与偏离

1. 本契约冻结后，M1 起实现不得静默偏离；偏离必须在 `docs/plan/v2.20/` 实施记录中登记原因与影响。
2. 任何新增节点类型/事件类型必须同步更新本文 §2/§3 与测试矩阵。
3. 任何新增迁移必须单独评审；本版只允许 `v044`。
4. 任何新增 API 必须走统一 `{success,data}` 信封与 Zod 校验。
5. 本版完成前，`pnpm check` / `pnpm test` / `pnpm build:web` 不得低于 v2.19 基线。
