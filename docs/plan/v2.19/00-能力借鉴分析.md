# v2.19 能力借鉴分析：下一版本候选方向

> 分支：`feature/v2.19-planning`（从 main `a6f2f23` 切出）
> 分析时间：2026-11-02
> 方法：GitHub API 核对仓库活跃度、许可证与 README/核心文档；只做调研与取舍，不改上游代码
> 结论：**已决策做「看得懂文档」——深度文档解析与可信 RAG（P0+P1+P2）；Promptfoo 纳入 CI；会议与长期记忆留后续候选**

## 1. 现状与缺口

v2.18 已完成「可交付」：产物文件、10 类图表、SVG/PNG 导出、可选内容包、工具证据。下一层缺口不再是“产出格式”，而是**信息从哪里来、如何持续积累、如何被用户信任**：

| 缺口 | 现状 | 用户可感知的问题 |
|---|---|---|
| 会议/长音频 | 语音只有 PTT / VAD 单轮识别，一次性 WAV | 开会、访谈、课程无法录制、转写、分段、生成行动项 |
| 长期记忆 | 有记忆与关系记忆，但抽取/冲突/遗忘策略有限 | 跨会话记得不牢、旧事实与新事实冲突、记忆不可解释 |
| 文档深度解析 | PDF/Office 以文本层为主，无版面/表格结构 | 报告、合同、表格类文档检索与引用质量不足 |
| 语音轮转 | 半双工、按轮识别 | 打断、抢话、自然停顿、连续对话体验不够自然 |
| 桌面视觉 | 电脑工具依赖坐标/UIA | 复杂界面、非标准控件、跨应用流程容易失败 |
| 质量评测 | 有 check/单测/e2e，但缺 Agent/RAG 质量回归 | 提示词、工具、检索改动后缺少可量化回归 |

## 3. 四个候选主题

### A.「会记录」——会议与语音记录（推荐）

**用户故事**：用户在开会/访谈/听课时点“开始记录”，应用同时采集麦克风与系统音频，本地实时转写；结束后按说话人/时间分段，生成摘要、行动项，并可选写入知识库。

- **P0**：会议录音（麦克风 + 系统回环）、本地实时转写、时间戳分段、结束后摘要、保存/导出 Markdown。
- **P1**：说话人分离（本地 diarization）、行动项提取并转待办/提醒、会议记录入知识库、会议搜索。
- **P2**：实时字幕窗、双语转写、说话人命名、会议模板。
- **参考**：Meetily（会议流程/模型选型）、Pipecat（轮转与打断）、WhisperX（时间戳/分离）、Anarlog（产品形态）。
- **风险**：Windows 系统音频回环采集；长音频内存/磁盘；说话人分离模型体积与准确率；会议隐私与保留策略；模型许可。
- **复用边界**：不移植 Meetily/Pipecat 运行时；只借鉴输入采集、分段、摘要与 UI 流程，核心仍用现有 TS + sherpa-onnx。

### B.「会记得」——长期记忆与关系

**用户故事**：助手能记住用户的偏好、承诺、关系变化与历史决定；新事实覆盖旧事实，冲突可解释，用户可查看/修改/删除。

- **P0**：记忆操作语义化（ADD/UPDATE/DELETE/NOOP）、同实体冲突消解、记忆来源与时间、用户可编辑。
- **P1**：时序关系图谱（事实有效期/失效）、记忆检索重排、按会话/助手/全局作用域隔离。
- **参考**：Mem0（操作与抽取）、Graphiti（时序图）、Letta（记忆块）。
- **风险**：错误记忆污染回答；隐私与“被遗忘权”；迁移/清理；评测难。
- **复用边界**：借算法与数据结构，不引入 Python 服务；现有 memory service 增量演进。

### C.「看得懂文档」——深度文档解析与 RAG

**用户故事**：上传复杂 PDF/合同/财报/表格，系统能保留版面、表格与章节结构，回答能引用到页/表/单元格。

- **P0**：版面感知解析、表格抽取、结构化分块、引用 grounding。
- **P1**：跨文档对比、图表理解、扫描件 OCR 增强。
- **参考**：RAGFlow（解析/分块）、LightRAG（图检索）、Ragas（检索评测）。
- **风险**：解析器依赖重（Python/Go/模型）；包体与离线安装；表格准确率；性能。
- **复用边界**：优先借解析/分块规范与测试集，不引入完整 RAGFlow 服务。

### D.「看得见」——屏幕与 GUI 感知

**用户故事**：助手能理解当前屏幕/应用界面，执行跨应用操作；用户可回看“刚才做了什么”。

- **P0**：屏幕截图理解、控件 grounding、操作前确认、失败回退。
- **P1**：连续屏幕/音频记忆、工作流还原、隐私保留策略。
- **参考**：UI-TARS（GUI grounding/动作空间）、Screenpipe（连续记录/检索）。
- **风险**：隐私与合规；常驻录屏资源占用；模型体积/GPU；许可证不确定；错误操作风险。
- **复用边界**：只借动作空间与交互协议；不默认常驻录屏。

## 4. 横切能力：评测与工具 UI

- **Promptfoo（P1，低成本）**：为 Agent/RAG/工具增加声明式评测集与 CI 回归；先覆盖 `web_search`、`knowledge_search`、`diagram_render`、`artifact_write` 与分享导出。
- **Ragas（P2）**：借 faithfulness / context precision / recall 指标，补 RAG 质量评测。
- **mcp-use（P2）**：若要做 MCP Apps / 工具结果交互卡片，可参考其 TS 框架。

## 5. 推荐与最终决策

分析阶段曾建议优先做「会记录」，原因是与现有语音栈连续、增量价值高。但用户已决策选择 **「看得懂文档」——深度文档解析与可信 RAG**，理由是：

1. 知识库是当前产品使用频率最高、可验证价值最直接的链路；
2. 现有解析只到“文本层 + 页码/段落”，复杂 PDF、合同、财报、表格类文档的检索和引用质量明显不足；
3. 可复用 v2.18 的产物、证据与引用链路：解析结果、表格引用与评测都能直接展示“出处”；
4. RAGFlow/LightRAG/Ragas 提供了可拆解的解析、分块、图检索与评测规范，不需要引入重型服务。

**最终范围**：P0 + P1 + P2 全做；Promptfoo 纳入 CI；会议/语音与长期记忆转为后续版本候选。

## 6. 已决策

1. 主题：C 深度文档解析与可信 RAG。
2. 范围：P0 + P1 + P2 全做。
3. 技术路线：TS/Node 原生扩展，不引入重型解析服务。
4. 迁移：允许一次 `v043-document-structure`。
5. 评测：Promptfoo 纳入 CI；Ragas 只借指标。
6. 会议/音频：本版不做，转为后续候选。

完整记录见 [01-M0 决策记录](01-M0-决策记录.md)。

## 7. 明确不做

- 不整库移植 Meetily / Pipecat / RAGFlow / Screenpipe；
- 不引入 Python/Go 常驻服务或新的 Rust sidecar；
- 不默认常驻录屏/录音；
- 不做云端会议同步、团队共享与远程市场；
- 不在本版重写 ASR/TTS 引擎。
