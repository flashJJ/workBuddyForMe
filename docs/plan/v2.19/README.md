## 1. 为什么是「看得懂文档」

v2.18 解决了「可交付」：产物、图表、内容包、证据。但知识库的输入端仍是**文本层思维**：

1. PDF 只按 `TextItem` 合并成行，标题、章节、表格、图注结构丢失；
2. 分块只按段落/长度切，表格会被切断，章节上下文无法进入 embedding；
3. 引用只有页码/段落，无法回答「表 3 第 2 行写的什么」；
4. 复杂 PDF/合同/财报/扫描件一旦解析失败，用户只能看到“失败”，不知道错在哪；
5. 检索/回答质量缺少可重复的评测，提示词与解析改动靠人眼回归。

v2.19 不做更多“输出格式”，只把知识输入与引用链路做深：**结构解析、表格问答、跨文档对比、图检索、评测**。

## 2. 目标与成功指标

| 指标 | 现状（v2.18） | v2.19 目标 |
|---|---|---|
| 复杂 PDF 结构 | 文本层 + 页码/段落 | 页 / 章节路径 / 表格 / 图注；失败可降级并给出警告 |
| 表格问答 | 表格被当普通文本 | 表格块原子化；回答引用「表 N · 第 M 行 · 单元格」 |
| 引用粒度 | 页码/段落/字符 | 增加章节路径、表号、行号、单元格；分享导出同步 |
| 跨文档对比 | 只能分别问答 | 两个文档的章节/表格对比报告，可导出产物 |
| 图检索 | 实体/要点静态层 | 实体关系 + 多跳检索；关系可引用来源文档 |
| 解析可观测 | 仅文档状态 | 结构预览、解析警告、按需重建 |
| 质量回归 | check/单测/e2e | Promptfoo RAG 评测集进入 CI |
| 旧库兼容 | 零迁移 | 允许 1 次迁移 `v043`；旧文档默认不降级 |
| 行为回归 | 2980 单测 / 139 e2e | 不降级；新增解析/表格/引用用例 |

## 3. 功能清单

### 3.1 P0（本版必须）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P0-1 | 结构解析与持久化 | 上传复杂 PDF，能看到页、章节、表格与解析警告 | `ParsedDocument` 落 `document_blocks`；8 份 fixture 均能解析或明确降级 |
| P0-2 | 结构感知分块与引用 | 回答能定位到章节/表格/行，而不是只给页码 | 表格不跨块切断；`section_path`/`table_no` 入库；Citation 扩展字段展示 |
| P0-3 | 结构预览与重建 | 解析错了能看见错在哪，并可手动重建 | `GET /structure` + `POST /reparse`；失败保留旧索引 |
| P0-4 | Promptfoo 基线 | 解析/引用改动有可重复的质量回归 | Promptfoo 配置、8 份 fixture、CI 基线可运行 |
| P0-5 | 迁移与兼容 | 升级后旧库直接可开，旧文档检索不降级 | `v043` 迁移、备份恢复、旧文档 top-3 基线 |

### 3.2 P1（本版锁定）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P1-1 | 表格问答 | 问「去年 Q4 营收是多少」「合同付款比例」 | 表格意图加权；回答引用表/行/单元格；空结果说明未覆盖 |
| P1-2 | 跨文档对比 | 对比两份合同/财报/规格书的章节与表格 | 生成对比产物（Markdown/HTML）并可预览/下载 |
| P1-3 | 文档结构面板 | 阅读时按章节跳转、查看表格、点击引用回原文 | 章节树、表格列表、引用定位；纯文本转义 |
| P1-4 | 图表/图片理解 | 文档里的图表/流程图能被引用与解释 | 配置视觉模型时提取图注/图像摘要；未配置时明确提示不支持 |
| P1-5 | 评测扩展 | 表格/跨文档/空结果都有回归用例 | Promptfoo 用例覆盖 P1；不达基线不合并 |

### 3.3 P2（本版锁定）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|

## 6. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| PDF 表格启发式准确率 | 表格错行/错列，引用错误 | 置信度 + warning + 降级文本；fixture 基线；不承诺所有 PDF |
| 迁移 43 兼容 | 旧库/备份恢复失败 | 只 ADD COLUMN/CREATE TABLE；迁移/恢复测试列为 M1 门禁 |
| 长文档解析耗时 | 上传/重建卡顿 | 后台解析；状态机；大文档上限；不做查询时解析 |
| 表格分块破坏语义 | 检索命中差 | 表格原子/按行切分；重复表头；表格意图加权 |
| 图检索噪声 | 关系错误污染回答 | 关系置信度、来源引用、多跳上限、用户可关闭 |
| 视觉模型成本/离线 | 图表理解不可用 | P1 可选能力；未配置明确提示；不阻塞文本链路 |
| Promptfoo 用例成本 | CI 慢/不稳定 | mock provider + 固定 fixture；只跑关键集；基线阈值 |
| 旧文档不重解析 | 新旧体验不一致 | 结构预览提示“未解析”；提供手动重建，不自动全库重跑 |

## 7. Non-Goals

- 不整库移植 RAGFlow / LightRAG / Graphiti / Ragas；
- 不引入 Python/Go/Rust 常驻服务、版面模型或新的 OCR 引擎；
- 不做文档编辑器、协同批注、云端文档同步；
- 不自动重解析全库历史文档；
- 不做会议录音、屏幕感知、长期记忆；
- 不做文档市场/远程内容包。

## 8. 验收口径

1. 8 份 fixture（多栏 PDF、合同、财报表格、扫描页、MD、DOCX、PPTX、无结构文本）均能解析或明确降级。
2. 表格块不跨 chunk 切断；超长表格按行切分且保留表头/表号/行范围。
3. 引用可展示章节路径、表号、行号、单元格，并能在文档结构面板定位。
4. 旧库升级后旧文档检索不降级；备份恢复通过。
5. 表格问答与跨文档对比在 fixture 上可复现，空结果标明未覆盖。
6. `knowledge_relations` 支持实体/关系多跳检索，关系可追溯来源。
7. Promptfoo RAG 评测进入 CI；`pnpm check` / 单测 / Web e2e / 桌面冒烟不降级。
8. 迁移仅 `v043` 一条；`/knowledge` 首屏包体增长 ≤5%。
