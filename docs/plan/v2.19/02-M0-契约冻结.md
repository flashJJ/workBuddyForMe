## 1. 文档结构契约

```ts
type DocumentBlockKind = 'heading' | 'paragraph' | 'list' | 'table' | 'figure';

interface DocumentTable {
  /** 文档内表格序号，从 1，按出现顺序 */
  tableNo: number;
  /** 表头行；无表头时为空数组 */
  header: string[];
  /** 数据行；每格为纯文本 */
  rows: string[][];
  caption?: string;
  pageNo?: number | null;
}

interface DocumentBlock {
  id: string;
  kind: DocumentBlockKind;
  pageNo: number | null;
  /** 章节路径，最多 4 层；无标题文档为空数组 */
  sectionPath: string[];
  /** 块正文；表格块为 Markdown 表格 */
  content: string;
  charStart: number;
  charEnd: number;
  /** kind=table 时存在 */
  table?: DocumentTable;
}

interface ParsedDocument {
  text: string;
  blocks: DocumentBlock[];
  tables: DocumentTable[];
  /** 解析警告：低置信表格、OCR 降级、标题缺失等 */
  warnings: string[];
}
```

| 项 | 约定 |
|---|---|
| 章节 | 由 heading 层级推导 `sectionPath`；最多 4 层，超出截断 |
| 表格序号 | 每文档从 1 递增；重建解析后序号可能变化，引用按重建后为准 |
| 表格行号 | 数据行从 1；表头行不计入 `tableRow` |
| 单元格 | Excel 风格 `tableCell`（如 `C3`），行号含表头偏移需在 UI 解释 |
| 坐标 | `charStart/charEnd` 相对规范化文本（CRLF→LF、trim），与 `chunkText` 同口径 |
| 扫描件 | OCR 后按文本行/列启发式识别表格；失败降级为 `paragraph` + warning |
| 不阻塞 | 结构解析失败不阻断文档入库；保留原文本分块，状态 `partial` 或 warning |

## 2. 数据库迁移 `v043-document-structure`

只允许这一条迁移；旧库升级后旧文档保持原文本检索，结构列默认 NULL/空数组。

### 2.1 `document_chunks` 新列

```sql
ALTER TABLE document_chunks ADD COLUMN section_path TEXT NOT NULL DEFAULT '[]';
ALTER TABLE document_chunks ADD COLUMN block_kind TEXT;
ALTER TABLE document_chunks ADD COLUMN table_no INTEGER;
ALTER TABLE document_chunks ADD COLUMN table_row_start INTEGER;
ALTER TABLE document_chunks ADD COLUMN table_row_end INTEGER;
```

### 2.2 `document_blocks`

```sql
CREATE TABLE document_blocks (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  ordinal INTEGER NOT NULL,
  kind TEXT NOT NULL,
  page_no INTEGER,
  section_path TEXT NOT NULL DEFAULT '[]',
  content TEXT NOT NULL,
  char_start INTEGER NOT NULL DEFAULT 0,
  char_end INTEGER NOT NULL DEFAULT 0,
  table_json TEXT,
  created_at TEXT NOT NULL
);
CREATE INDEX idx_blocks_document ON document_blocks(document_id, ordinal);
```

### 2.3 `knowledge_relations`（P2 图检索）

```sql
CREATE TABLE knowledge_relations (
  id TEXT PRIMARY KEY,
  knowledge_base_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  from_entity_id TEXT NOT NULL REFERENCES knowledge_entities(id) ON DELETE CASCADE,
  to_entity_id TEXT NOT NULL REFERENCES knowledge_entities(id) ON DELETE CASCADE,

CREATE INDEX idx_relations_from ON knowledge_relations(from_entity_id);
CREATE INDEX idx_relations_to ON knowledge_relations(to_entity_id);
```

### 2.4 兼容与回滚

- 迁移只做 `ADD COLUMN` / `CREATE TABLE IF NOT EXISTS`；不重建表、不改旧列。
- 旧备份恢复后按当前 `LATEST_SCHEMA_VERSION` 正常升级。
- 回滚策略：应用回退即可；新列/新表保留但旧代码忽略，不丢旧数据。
- M1 必须补：迁移前后行数一致、旧文档检索不降级、备份恢复测试。

## 3. 分块与引用契约

### 3.1 分块

- 表格块原子化：一个表格不跨 chunk；超长表格按数据行切分，每片重复表头，记录 `tableNo` 与 `table_row_start/end`。
- 章节上下文：chunk 内容前置 `[章节A › 章节B]`（仅当 `sectionPath` 非空），长度 ≤ 80 字符；完整路径存 `section_path`。
- 普通块沿用现有 `chunkText` 的段落/句子策略；结构块优先级高于纯文本。
- 旧文档/解析失败文档沿用旧分块，`section_path='[]'`，`block_kind='paragraph'`。

### 3.2 Citation 扩展

在既有 `Citation` 上增加可选字段，避免改 messages 表：

```ts
interface Citation {
  // ...既有字段
  sectionPath?: string[];
  tableNo?: number;
  tableRow?: number;
  /** Excel 风格单元格，如 C3 */
  tableCell?: string;
}
```

- 表格引用优先展示：`表 N · 第 M 行 · C3`；无表格引用则回落到页码/段落。
- Markdown / HTML 分享导出同步展示新增字段；旧引用缺字段时保持原样。
- 空结果/无依据仍按 v2.18 evidence 口径标注未覆盖。

### 3.3 检索

- 继续使用向量 + FTS + RRF + 重排；新增结构过滤只在 SQL 层收窄候选。
- 表格意图查询（含“表格/对比/金额/总计/第几行”等）对 `block_kind='table'` 加权；权重在 M2 用 fixture 校准。
- 结构过滤参数不进入模型上下文；只由 UI/工具内部使用。

## 4. API 契约

### `GET /api/documents/:id/structure`

返回：

```json
{
  "documentId": "...",
  "parsedAt": "2026-...",
  "pages": [{ "pageNo": 1, "blockIds": ["..."] }],
  "sections": [{ "path": ["合同", "付款条款"], "blockIds": ["..."] }],
  "blocks": DocumentBlock[],
  "tables": DocumentTable[],
  "warnings": ["..."]
}
```

- 仅允许已入库文档；不存在 404；无结构（旧文档）返回 `blocks: []` + `structureAvailable: false`。
- 内容按纯文本返回，前端必须转义，不渲染 HTML。

### `POST /api/documents/:id/reparse`

- 重新解析并重建结构/分块/索引；入队后台执行，复用文档 `processing → indexed/failed/partial` 状态。
- 重建失败保留旧索引；成功后才替换。
- 旧文档可手动触发；“全部重建”不做自动全库重跑。

## 5. 评测契约

- 工具：Promptfoo（devDependency / CI），配置文件 `tests/eval/promptfoo/rag.yaml`。
- Fixtures：至少 8 份文档（多栏 PDF、合同、财报表格、扫描页、Markdown、DOCX、PPTX、无结构纯文本）。
- 指标：
  - 章节定位准确率
  - 表格单元格引用准确率
  - 引用可追溯率（回答中的事实能在 citation 中找到）
  - 无答案/空结果识别率
- 阈值：M1 建立基线，M3 起设回归门槛；不达基线不得发布。
- P2 增加 Ragas 风格指标（faithfulness / context precision / recall）与 Promptfoo 红队用例。
