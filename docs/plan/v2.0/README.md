# v2.0「活在桌面」· 规划草案（评审前，非 M0 冻结稿）

> 分支：`feature/v2.0-companion-loop`（自 `main` `7fb5b50` 起，v1.9.0 已发布）
> 上游概念稿：[../v1.6-v2.0/v2.0-情感闭环与mod生态.md](../v1.6-v2.0/v2.0-情感闭环与mod生态.md)
> 跨版本总控：[../v1.6-v2.0/04-版本路线图.md](../v1.6-v2.0/04-版本路线图.md)
> 性质：**草案**——用于评审拍板范围与 M0  spike 立项；M0 冻结后产出正式分册契约（等级规则/mod manifest/表结构备份/VRM 结论），冻结前不写产品代码。

## 一句话价值主张

**同一个 WorkBuddy，现在真的认识你。** v1.6–v1.9 让助手有情绪、有仪式、能打扮、可上台；v2.0 把这些零件咬合成一条**长期关系闭环**：共同经历被记住、关系等级带来可见但无压力的解锁、关怀由本地上下文恰当触发、个性化成果能打包成 mod 分享——并对 3D（VRM）路线给出明确 go/no-go。

一版一主题：主题是**关系闭环**，不是功能大杂烩；不重写 UI、不换技术栈、不做云。

## 目标（全部可机械验证；继承概念稿 G1–G7，口径锚定现有表与模块）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 关系养成闭环 | 等级纯函数单测（阈值/解锁判定/日增量上限/回落保底）；面板可见「距下一级」；连刷夸奖冲不上等级（日上限 eval）；长期不互动等级慢速回落但永不清零 |
| G2 | 记忆×情绪联动 | 记忆类型扩 `relationship`；每日提取回归 golden 不退化；情绪/剧本台词可引用关系记忆且引用可溯（沿用 v1.3 RRF 通道，不改检索算法）；首日/30/100/365 天与第 N 次协作里程碑到点触发剧本 |
| G3 | 主动感知 2.0 | 新增上下文触发器（时段/连续工作时长/久未对话/协作终态）全部走 v1.7 事件引擎，受同一档位/勿扰/总开关管辖；系统事件（解锁/空闲）独立授权默认关；触发信号源枚举可列全，原始信号不落盘 |
| G4 | 本地关系报告 | 单文件 HTML 本地生成（复用 v0.4 自包含导出栈），节可选/记忆项可删；报告不发网络，单测断言无外链请求 |
| G5 | `.wbfm-pack` mod 封版 | manifest+schemaVersion+zod 校验；导入预览（新增/覆盖清单）；解包层硬拒模型/音频二进制（伪装后缀/嵌套 zip eval）；`builtin.*` 命名空间不可覆盖 |
| G6 | VRM 路线决策 | spike 结论文档（授权口径/接入成本/共存策略），go→另立 v2.1，no-go→原因归档；**不产出 3D 产品代码** |
| G7 | 情绪价值总验收 | 完整态/关情绪与主动（回 v1.5 工具行为）/极简视觉（无舞台无 fx）三态 e2e 全绿；v1.6–v1.9 指标首次完整本地读数 |

## Non-Goals（本版明确不做）

1. **不做打卡任务化**：无奖励货币、无连续签到、无数值条恐吓 UI；等级规则随时可看/可关/可清。
2. **不做 mod 商店/在线分发/账号体系/云同步**：mod 是本地文件的导入导出；云与本地优先宪法冲突，未来若做须独立宪法修订。
3. **不做 CA 签名体系**：本地文件只做来源标记（builtin/imported + 导入时间）。
4. **不接任何应用内内容到感知**：不读屏、不读窗口标题、不读文档内容；上下文源代码内枚举封闭。
5. **不改 RAG 检索架构与编译流水线**：只加记忆类型与消费场景（RRF/阈值/分片全不动）。
6. **不补 v1.9 P1**（会议结论摘要/待办、观众模式、时间戳回放）：主题不属于关系闭环，入 v2.1+ backlog 候选。
7. **不捆绑/不引导导入任何 Live2D 模型与音色二进制**（Cubism 红线全版本不变）；VRM spike 期间 UI 也不出现模型入口。

## 既有基座与本版改动的映射（详见 [01 现状盘点与差距分析](01-现状盘点与差距分析.md)）

- **直接复用**：情绪 state_json（intimacy/trust 0–100 已在库）、emotion_events 不可变流水、v1.7 事件引擎（schedules/triggers/勿扰/频率档位）、v1.8 角色卡与四主题、v0.4 单文件 HTML 导出栈、v1.6+ 备份恢复轨道。
- **扩展不改写**：记忆类型枚举加 `relationship`；事件触发器加上下文类型；备份 schema 加法升 v6。
- **全新但收口**：等级/解锁/里程碑三张（或两类）新表、desktop 活跃计时桥、mod 打包解包器、报告生成页。

## 待评审决策点（M0 必须拍板）

1. **等级粒度**：概念稿 4 档（陌生→认识→搭档→挚友）；是直接固化 4 档还是 5 档（增加暧昧向中间档的命名争议）？阈值是否 intimacy/trust 双门槛（如「挚友」要求双高）？
2. **回落保底的具体语义**：等级只降档不清零——最低保底在「认识」还是「陌生之上半档」？回落速率（建议：只在连续 N 天零互动后启动，周级慢速）。
3. **解锁内容资产边界**：专属剧本走用户可编辑的 event JSON（可进 mod），微动作配置是否允许 mod 携带（仅参数 JSON，不含任何模型动作文件）？
4. **系统事件授权的最小集**：M3 是否只做解锁/锁屏 + Electron 活跃计时，空闲 API（`getSystemIdleTime`）是否同期开放（隐私文案成本）？
5. **VRM spike 深度**：只做文档调研，还是允许一个 env 门控的 three-vrm 加载工装（同 M0 spike 不进安装包先例）？
6. **指标读数来源**：现网单机数据量小，G7 首读是否接受「eval + 真机人工读数」替代（路线图允许），关系活跃指标的本地统计表是否进 M1 还是 M3 统一做。
