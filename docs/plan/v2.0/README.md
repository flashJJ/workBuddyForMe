# v2.0「活在桌面」· 规划草案（评审前，非 M0 冻结稿）

> 分支：`feature/v2.0-companion-loop`（自 `main` `7fb5b50` 起，v1.9.0 已发布）
> 上游概念稿：[../v1.6-v2.0/v2.0-情感闭环与mod生态.md](../v1.6-v2.0/v2.0-情感闭环与mod生态.md)
> 跨版本总控：[../v1.6-v2.0/04-版本路线图.md](../v1.6-v2.0/04-版本路线图.md)
> 性质：**草案**——用于评审拍板范围与 M0  spike 立项；M0 冻结后产出正式分册契约（等级规则/mod manifest/表结构备份/VRM 结论），冻结前不写产品代码。

## 一句话价值主张

**同一个 WorkBuddy，现在真的认识你。** v1.6–v1.9 让助手有情绪、有仪式、能打扮、可上台；v2.0 把这些零件咬合成一条**长期关系闭环**：共同经历被记住、关系等级带来可见但无压力的解锁、关怀由本地上下文恰当触发、个性化成果能打包成 mod 分享——并对 3D（VRM）路线给出明确 go/no-go。

一版一主题：主题是**关系闭环**，不是功能大杂烩；不重写 UI、不换技术栈、不做云。

## 目标（全部可机械验证；继承概念稿 G1–G7，口径锚定现有表与模块）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 关系养成闭环 | 等级纯函数单测（阈值/解锁判定/日增量上限/回落保底）；面板可见「距下一级」；连刷夸奖冲不上等级（日上限 eval）；长期不互动等级慢速回落但永不清零 |
| G2 | 记忆×情绪联动 | 记忆类型扩 `relationship`；每日提取回归 golden 不退化；情绪/剧本台词可引用关系记忆且引用可溯（沿用 v1.3 RRF 通道，不改检索算法）；首日/30/100/365 天与第 N 次协作里程碑到点触发剧本 |
| G3 | 主动感知 2.0 | 新增上下文触发器（时段/连续工作时长/久未对话/协作终态）全部走 v1.7 事件引擎，受同一档位/勿扰/总开关管辖；系统事件（解锁/空闲）独立授权默认关；触发信号源枚举可列全，原始信号不落盘 |
| G4 | 本地关系报告 | 单文件 HTML 本地生成（复用 v0.4 自包含导出栈），节可选/记忆项可删；报告不发网络，单测断言无外链请求 |
| G5 | `.wbfm-pack` mod 封版 | manifest+schemaVersion+zod 校验；导入预览（新增/覆盖清单）；解包层硬拒模型/音频二进制（伪装后缀/嵌套 zip eval）；`builtin.*` 命名空间不可覆盖 |
| G6 | VRM 自定义模型导入 | 用户可自助导入自有/已获授权的 `.vrm`（60MB 上限、魔数+扩展双校验），导入前强制展示文件内嵌许可并勾选确认；VRM 上舞台（与 Live2D 混排）与桌宠可见、口型与四表情联动；缺许可确认/伪造后缀/嵌套压缩包负例 e2e 全拒；核显真机达到 M0 工装帧率阈值。应用不内置/不分发/不托管模型，Live2D 外部模型红线不变 |
| G7 | 情绪价值总验收 | 完整态/关情绪与主动（回 v1.5 工具行为）/极简视觉（无舞台无 fx）三态 e2e 全绿，另含形象后端切换（Live2D/VRM/默认）回归；v1.6–v1.9 指标首次完整本地读数 |

## Non-Goals（本版明确不做）

1. **不做打卡任务化**：无奖励货币、无连续签到、无数值条恐吓 UI；等级规则随时可看/可关/可清。
2. **不做 mod 商店/在线分发/账号体系/云同步**：mod 是本地文件的导入导出；云与本地优先宪法冲突，未来若做须独立宪法修订。
3. **不做 CA 签名体系**：本地文件只做来源标记（builtin/imported + 导入时间）。
4. **不接任何应用内内容到感知**：不读屏、不读窗口标题、不读文档内容；上下文源代码内枚举封闭。
5. **不改 RAG 检索架构与编译流水线**：只加记忆类型与消费场景（RRF/阈值/分片全不动）。
6. **不补 v1.9 P1**（会议结论摘要/待办、观众模式、时间戳回放）：主题不属于关系闭环，入 v2.1+ backlog 候选。
7. **形象红线的不对称（评审已定向，见 [02 VRM 调研报告](02-VRM导入可行性调研报告.md)）**：VRM（开放 glTF/MIT 生态）允许**用户自助导入**，但应用不内置/不分发/不托管模型（无模型市场/下载器/云同步，备份与 .wbfm-pack 只带引用不带二进制）；**Live2D `.moc3` 等外部模型导入继续永久禁止**（Cubism 专有授权边界，与 VRM 是两套逻辑，UI 必须分开命名说明）。
8. **不做任意 glb/gltf 导入与 VRMA 动作库**：仅接受带 VRM 扩展标记的 `.vrm`；VRMA 回放、模型编辑/换装、3D 舞台空间改造均为 v2.0 后 backlog。

## 里程碑（草案，M0 评审可调整）

| 阶段 | 出口 |
|---|---|
| **M0** | ① 关系等级/解锁/回落/防刷规则评审稿（阈值基于 v1.6–v1.9 现网情绪数值分布抽样，见 01 §3）；② mod 包 manifest 规范评审稿（内容白名单/黑名单/命名空间/预览形状）；③ **VRM 导入真机工装 spike（GO 关卡，评审拍板后才允许 M4 开工）**：门控不进安装包，three+three-vrm 加载 8MB/60MB 样本，测首帧/内存/混排帧率 + 校验链负例，产出阈值复核与降级方案（见 [02](02-VRM导入可行性调研报告.md) §3.4），免责声明定稿；④ 备份 v6 与「重新认识」数据口径草案；**产品代码不进包** |
| **M1** | 关系等级纯函数 + 落库（解锁表/等级事件）+ 等级面板（规则透明、距下一级、可关）+ 称呼/2–3 剧本/1–2 微动作解锁；防刷日上限与回落保底单测 |
| **M2** | 记忆 `relationship` 类型 + 每日提取 prompt 增量与 golden 回归；台词软引用记忆（无把握不提、可溯、可删即不引用）；里程碑计数器与纪念剧本（复用 v1.7 引擎） |
| **M3** | 主动感知 2.0：上下文触发器接 v1.7 注册表（时段/工时/久未对话/协作终态）+ desktop powerMonitor 桥（默认关、显式授权）；指标全量本地读数；勿扰回归 |
| **M4** | **形象开放：VRM 导入交付**——导入向导与 meta 许可确认面板、`data/vrm-avatars/` 存储与双校验、three 渲染后端与 PIXI 双 canvas 分层（cast 形象类型 `vrm:<id>`，可与 Live2D 混排）、口型（电平→aa）与四表情映射、舞台与桌宠双形态、负例 e2e；性能不达标时执行 M0 预案降级（像素比/降帧/同屏 VRM≤1） |
| **M5** | 收口封版：关系报告 HTML（节可选/项可删）+ .wbfm-pack 导入导出向导（黑名单拦截 eval，VRM 只带引用）+ 备份 v6/恢复 + 三态与形象后端切换总回归；双语；封版 2.0.0（沿用 v1.9 SOP：sync-version → --no-ff → tag → Release → 真机抽测归档） |

> 排期说明（2026-10-15 评审调整）：VRM 导入从原拟单立 v2.1 **收回 v2.0 内交付**，里程碑由 M0–M4 扩为 M0–M5（仍在路线图「单版 4–6 个里程碑」约束内）。M1–M3 关系闭环主线不变；M4 为独立形象特性线（与关系代码域几乎不冲突）；M5 做汇聚收口与三态总验收。**关卡约束**：M0 工装若性能或许可评审未过，M4 立即砍除（回到「只留报告」形态），M5 仍可按时封版——大版本不被单一特性拖期。

## 既有基座与本版改动的映射（详见 [01 现状盘点与差距分析](01-现状盘点与差距分析.md)）

- **直接复用**：情绪 state_json（intimacy/trust 0–100 已在库）、emotion_events 不可变流水、v1.7 事件引擎（schedules/triggers/勿扰/频率档位）、v1.8 角色卡与四主题、v0.4 单文件 HTML 导出栈、v1.6+ 备份恢复轨道。
- **扩展不改写**：记忆类型枚举加 `relationship`；事件触发器加上下文类型；备份 schema 加法升 v6。
- **全新但收口**：等级/解锁/里程碑三张（或两类）新表、desktop 活跃计时桥、mod 打包解包器、报告生成页；**three.js VRM 第二渲染后端**（与 PIXI 分层，新增 web 依赖 `three`/`@pixiv/three-vrm`，动态 import 不进首屏）、VRM 导入向导与 `data/vrm-avatars/` 存储。

## 评审记录与待拍板决策点

> 决策点 5 已在评审中定向（2026-10-15）：**VRM 要做可导入，调研结论 GO，且收回 v2.0 内交付（M4）**，见 [02 VRM 调研报告](02-VRM导入可行性调研报告.md)；M0 真机工装为 M4 开工关卡。剩余 1–4、6 待 M0 评审拍板。

1. **等级粒度**：概念稿 4 档（陌生→认识→搭档→挚友）；是直接固化 4 档还是 5 档（增加暧昧向中间档的命名争议）？阈值是否 intimacy/trust 双门槛（如「挚友」要求双高）？
2. **回落保底的具体语义**：等级只降档不清零——最低保底在「认识」还是「陌生之上半档」？回落速率（建议：只在连续 N 天零互动后启动，周级慢速）。
3. **解锁内容资产边界**：专属剧本走用户可编辑的 event JSON（可进 mod），微动作配置是否允许 mod 携带（仅参数 JSON，不含任何模型动作文件）？
4. **系统事件授权的最小集**：M3 是否只做解锁/锁屏 + Electron 活跃计时，空闲 API（`getSystemIdleTime`）是否同期开放（隐私文案成本）？
5. **~~VRM 是否做导入~~（已定：做，v2.0 M4 交付）**：M0 门控真机工装（体积/首帧/混排性能 + 校验负例 + 免责声明定稿）作为开工关卡；不达标 M4 砍除、M5 照常封版。
6. **指标读数来源**：现网单机数据量小，G7 首读是否接受「eval + 真机人工读数」替代（路线图允许），关系活跃指标的本地统计表是否进 M1 还是 M3 统一做。
