## 1. 本版解决什么

v4.18 发布时主动顺延了五项，v4.17 还有两项小遗留。它们不紧急，但都会被真实使用碰到：

1. 备用模型只能配一个、只在助手级；
2. 失败与切换有事件，但没有汇总视图；
3. 回放报告只有单次结果，没有历史对比；
4. 知识检索结果不能复制引用；
5. 桌宠没有主窗入口，窄窗未复核。

本版不启动新主线，只把这些欠账清掉。实现期额外追加了语音链路与寒暄快路径，单独记录在 [voice-and-chitchat.md](./voice-and-chitchat.md)。

## 3. 关键设计

### 3.1 链可以长，切换次数不变

配置复杂度与运行时行为分开：备用链最多 3 个，但单轮仍最多切换 2 次，首字后不切换。链只决定「按什么顺序尝试」，不改变「何时必须停」。

配置全部落在 `settings_kv`：新键存链与会话覆盖，旧单值键继续同步首项。零迁移的同时保留旧数据可读。

### 3.2 健康度是代理指标

失败与切换聚合只读本机 `session_events`，只统计 7 天窗口，不记录正文、不新增埋点。模型或供应商删除后归入 `unknown`，不丢弃历史。

面板明确标注口径。它回答的是「最近哪个供应商在出问题」，不是「用户满意度」。

### 3.3 历史是对比，不是门禁

回放报告按时间命名归档，保留 20 份；`--compare=last` 只输出「本次候选 − 上次候选」的差值。历史可能来自不同 golden，因此不参与阈值判定。

历史写入前复用隐私扫描，命中绝对路径或令牌时拒绝落盘，避免把敏感内容带进长期目录。

### 3.4 小动作也要真实边界

复制引用只含标题与深链；按钮与结果行并排而不是嵌套；失败只做内联提示。E2E 真实读取剪贴板，确认内容不含正文。

桌宠入口用桥接能力检测控制显示，首帧按 Web 处理避免 hydration 问题；窄窗复核除了「可见」，还检查中心点是否被遮挡、点击是否真的调用桥接。

### 3.6 对话宽度跟随视口

消息列表、输入区与提示条统一改为 `clamp(48rem, 70vw, 72rem)`：大屏下随视口增长，不再固定 768px 居中；同时保留 1152px 上限，避免行长失控。

### 3.7 实现期追加：语音与快路径

流式 TTS 让音频块与文本事件同步下发；Matcha 用速度换声线多样性；腾讯云与微软 Edge 覆盖「有密钥」与「零配置」两类用户；寒暄快路径在严格条件下跳过工具 schema 与记忆召回，任何可疑信号都回退完整链路。

这部分唯一破坏的约束是新增两个运行时依赖。二者均为纯 JS/WASM，无原生编译，已随 standalone 产物实测。

## 5. 已知限制

- 备用链最多 3 个，超过 3 个的配置被拒绝；
- 健康度只统计本机 7 天事件，无趋势图与导出；
- 回放对比只展示差值，不参与门禁；
- 知识结果只开放打开与复制，续任务/打开审批没有稳定关联数据；
- 微软 Edge 使用公开端点，协议可能变化，失败时回退本地；
- 在线朗读会把文本发送到对应云服务，需要用户知情。
