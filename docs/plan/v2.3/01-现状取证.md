## 1. 下拉选择器（截图①、②）

### 1.1 根因：Radix Select 已安装但未被使用

- [apps/web/package.json](../../../apps/web/package.json) 依赖中包含 `"@radix-ui/react-select": "^2.1.2"`。
- 但 [apps/web/src/components/ui/select.tsx](../../../apps/web/src/components/ui/select.tsx) 的实现是：

```tsx
/** 原生 select 封装：轻量、可键盘操作，满足桌面端表单场景 */
export const Select = React.forwardRef<HTMLSelectElement, SelectProps>(({ className, children, ...props }, ref) => (
  <select ref={ref} className={cn('flex h-9 w-full rounded-md border border-input bg-background px-3 py-1 text-sm', ...)} {...props}>
    {children}
  </select>
));
```

即：**用原生 `<select>` 套样式**。原生下拉面板由操作系统渲染，选项间距、行高、悬停/选中高亮均不受 CSS 控制——这正是「没间距、挤在一起、生硬蓝高亮」的直接原因。

### 1.2 两套并存：另有 13 个文件裸用原生 `<select>`

用 `Grep '<select'` 命中 14 个文件（含 `select.tsx` 自身），其余 13 个裸用原生标签：

| 目录 | 文件 |
|---|---|
| features/settings | asset-import-section.tsx、emotion-panel.tsx、interaction-graph-row.tsx、knowledge-retrieval-panel.tsx、relationship-panel.tsx、tool-debug-panel.tsx |
| features/events | custom-trigger-form-dialog.tsx、event-usage-stats.tsx |
| features/stage | stage-background-editor.tsx、stage-toolbar.tsx |
| features/flow-editor | endpoint-dialog.tsx |
| features/flows | flow-runs-view.tsx |
| features/reminders | reminder-form-dialog.tsx |

同一个应用里同时存在「封装 Select」与「裸 select」，观感必然不一致。

## 3. 窄窗排版（「小窗口时文字挤压变形」）

| 现象 | 证据 |
|---|---|
| 侧栏固定宽吃空间 | [app-sidebar.tsx](../../../apps/web/src/components/layout/app-sidebar.tsx) `<aside className="flex h-full w-56 shrink-0 ...">`，**无折叠**；[(main)/layout.tsx](../../../apps/web/src/app/(main)/layout.tsx) `<main className="flex-1 ...">` |
| 表单固定网格列 | [task-page.tsx:90](../../../apps/web/src/features/tasks/task-page.tsx#L90) `grid gap-3 md:grid-cols-[260px_1fr_auto]` |
| 无断点固定列 | [scenario-model-matrix.tsx:26](../../../apps/web/src/features/tuning/scenario-model-matrix.tsx#L26) `grid grid-cols-[10rem_1fr] ...`（**无 sm/md 前缀**） |
| 固定控件宽 | [assistant-switcher.tsx](../../../apps/web/src/features/chat/assistant-switcher.tsx) `w-44`；[task-page.tsx](../../../apps/web/src/features/tasks/task-page.tsx) `w-20` |
| 全局缺响应式 | `Grep 'md:|sm:|lg:'` 全仓极少（仅 task-page、flows-list 等零星）；`whitespace-nowrap` 仅出现在 button |

**结论**：排版从设计之初就按「固定窗口宽度」假设，未针对可变窗口做断点，因此小窗必然挤压。

## 4. 知识库 / 工作流「开箱即用」

### 4.1 已有（但用户感知不到）

| 能力 | 文件 | 说明 |
|---|---|---|
| 工作流 starter ×3 | [starters.ts](../../../packages/core/src/flow/starters/starters.ts) | 资料研究助手 / 周报流水线 / 网页摘要器，固定 id |
| 播种入口 | [container.ts:212](../../../apps/web/src/lib/server/container.ts#L212) 调 [seed-starter-flows.ts](../../../packages/core/src/flow/starters/seed-starter-flows.ts#L12) `ensureStarterFlows` | 启动幂等播种并发布，播种即成为对话里的 `flow:<id>` 工具 |
| 内置技能 ×3 | [builtin-skills.ts](../../../packages/core/src/skills/builtin-skills.ts) | weekly-report / meeting-notes / file-search |
| 技能播种 | [skill-service.ts:74](../../../packages/core/src/skills/skill-service.ts#L74) `ensureBuiltinSkills` | 首启写入磁盘 `skills/` 目录，缺失才写、不覆盖用户改动 |

问题：**只有 3 个、且 UI 未说明来源**；列表空态仅「创建」按钮，用户不知道已有现成模板。

### 4.2 缺口

- **知识库零播种**：[seed.ts](../../../packages/core/src/services/seed.ts) 中不含任何 KB 创建逻辑（`Grep 'knowledge|Knowledge'` 仅命中一处无关的 `knowledgeBaseIds: []`）。用户首次进入知识库必须「自建库 + 自传文档」。

### 4.3 可对齐范式

- [built-in-cards.ts](../../../packages/shared/src/character-card/built-in-cards.ts)（内置角色卡）已是「固定 id + 幂等播种 + 不覆盖用户改动」的成熟做法，本版新增内置内容沿用。
