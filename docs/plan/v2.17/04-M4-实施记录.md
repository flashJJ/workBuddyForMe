## 2. 关键口径

- **只收内置包**：目录只含随应用发布的 bundled-pack；不访问网络、不做远程市场。
- **安装复用既有链路**：`CapabilityService.install(sample(kind))` 完成 ZIP 校验 / 验签 / 权限 / 依赖 / 落盘 / 启用，失败按既有 fail-closed 回滚，不改白名单。
- **安装必须 HITL**：`capability_install.alwaysConfirm = true` 跳过一切自动放行；审批请求的 `reasonCode` 固定为 `HITL_REQUIRED`，审批中心与审计同步可见。无人值守运行没有确认 UI，按 `NO_APPROVAL_UI` 拒绝。
- **下一轮绑定**：安装成功后只把 `permission === 'read'` 且可解析的工具并入 `assistant.enabledTools`；write / danger / 未知工具进入 skipped 并提示手动勾选。同轮多次安装共享同一份可变白名单快照，避免后一次覆盖前一次。
- **不做同轮热替换**：当前轮工具声明不变，下一轮按持久化后的白名单重新构造。
- **零迁移**：白名单继续写 `assistant.enabledTools` JSON；目录为代码常量；`LATEST_SCHEMA_VERSION = 42` 不变。

## 3. 契约偏差

| # | 事项 | 说明 |
|---|---|---|
| 1 | MCP 预置未进入目录 | 首批只做 bundled-pack；`mcp-preset` 条目安装会明确返回 422「暂不支持自动安装」，待后续版本接入 MCP 预置安装 |
| 2 | 未实现可选 `capability_list` | 目录检索结果已携带 installed / status，可避免重复安装；独立列举工具留待需要时再补 |
| 3 | 未新增 capability 专用审计 kind | 安装 / 拒绝复用现有审批审计链（`approval_requested / granted / denied / timeout` + `HITL_REQUIRED`）；不扩审计枚举，避免审计页与零迁移口径扩散 |
| 4 | 未新增浏览器端审批 e2e | mock 模型不产出 function call，无法稳定触发 `capability_install`；审批路径由权限门单测（含 alwaysConfirm + 持久授权 + full_access）与工具单测覆盖 |
| 5 | 审批框复用通用工具确认 | 现有 `tool_confirmation_required` 只带工具名 / 权限 / 参数摘要，未展示目录来源、签名、effect 与新增工具；这些信息由 `capability_search` 返回给模型并在调用前说明。扩展结构化审批载荷留待后续版本 |
| 6 | 目录检索不写审计 | `capability_search` 为只读且不改变状态；安装 / 拒绝复用审批审计链，不新增审计 kind |
