# v4.3 版本总结：内容与资产收口

> 版本：4.3.0（2026-11-16）
> 主题：声明式内容包、资产体积预算与只读平台元数据
> 分支：`feat/v4.3-content-and-assets`
> 迁移：零数据库迁移，`LATEST_SCHEMA_VERSION = 51`

## 1. 本版解决什么

v4.0 打通了能力包、依赖拓扑与会话级内容快照，但场景包与道具包仍停在规划；模型、贴图、morph 与安装包体积依赖人工检查；音频输出设备、工具描述符与 provider 能力元数据也还散落在后续版本。

v4.3 把这三类剩余事项一次收口：

1. **内容**：`scene-pack` 与 `prop-pack` 复用现有能力包管道，只做声明式内容，不执行任意代码；
2. **资产**：新增 `check:assets`，把模型、贴图、morph 与安装包体积变成可重复的门禁；
3. **元数据**：音频输出设备可切换；工具描述符与 provider 能力只读展示，不改变执行与路由。

## 3. 关键设计

### 3.1 声明式内容，执行仍在内核

场景包只允许现有 `Scene / Beat / Cue`，道具包只允许元数据 + GLB 文件。两者都不携带脚本代码；安装流程复用 manifest、校验和、签名、升级与回滚。场景 id 强制 `pack.` 前缀，道具 id 同样与内置道具隔离。

### 3.2 内容快照是会话边界

`scene-content` 与 `prop-content` 每次请求按已启用能力行聚合，版本由排序后的 `id@version` 生成。安装/停用不热替换正在播放的内容：下一次挂载、下一次 cue 或下一次请求生效。跨包重复 id 在聚合层 fail-closed。

### 3.3 预算变成门禁，而不是建议

- 单模型 ≤25MB、三席合计 ≤25MB、安装包 ≤300MB；
- 贴图硬上限 4096，目标颜色 2048、数据 1024；非 WebP 只警告；
- morph 用有序 targetNames 的 SHA256 快照锁定，三席签名一致；
- 道具包单文件 5MB、合计 20MB、entry 64KB，安装启用时拒绝超限。

### 3.4 设备选择是偏好，不是硬依赖

AudioDirector 单点持有 `outputDevice`；`applySinkId` 首次失败后回退系统默认。音乐、剧场 BGM、剧场音效与语音各自实现可选 `setOutputDevice`，不支持时静默忽略。设备枚举只在设置面板发生，并监听 `devicechange`。

### 3.5 只读元数据不改行为

工具描述符统一为 `name / description / inputSchema / source / permissions / readOnly / alwaysConfirm`，执行入口、权限门与路由未改；provider 能力按协议声明，不落库、不参与模型选择。

## 4. 数据与验证

- 全量测试：9 包 736 文件 4180 项通过；
- `pnpm check`：typecheck、lint、行数、结构、循环依赖、ASCII、资产全部通过；
- 资产：xuetuan 9.28MB / feibi 7.01MB / rankaluli 6.00MB；三席 118 morph / 49 骨骼；
- 安装包：`WorkBuddyForMe-Setup-4.3.0.exe` 264.88MB（277,742,426 字节），较 v4.1.0 增加 0.26MB；SHA256 `7733e111…8a7bd3`；
- 数据库：零迁移；备份 schema 不变。

## 5. 已知限制

- 场景包不接小剧场；道具包只支持 `.glb`；
- 不做内容热替换与在线目录；
- 输出设备能力取决于运行环境，权限不足时标签可能为空；
- provider 能力是协议级声明，不代表单个模型；
- P2 音频全图、响度归一、统一队列与非默认模型下载包未在本版。
