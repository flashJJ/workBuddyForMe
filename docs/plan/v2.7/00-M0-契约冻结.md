# v2.7 M0：WorkSignal、RunEvent 与审批契约冻结

> 状态：已实现（v2.7，2026-10-29；验收记录见 [M5](05-M5-验收.md)）
> 范围：任务 / Flow / 协作三条运行链路的实时工作信号；工具确认与 Flow 人工节点的统一审批收件箱；桌宠工作态、气泡、提示音与深链。
> P1（不阻塞本期）：桌面控制授权并入审批中心、会议信号、余额/账户信息、完整角色减少动态。

## 1. 运行状态口径

复用 `apps/web/src/lib/runs/run-outcome.ts` 的 8 态，不新增平行状态机：

```ts
type WorkOutcome =
  | 'queued' | 'running' | 'waiting'
  | 'succeeded' | 'failed' | 'cancelled' | 'interrupted' | 'budget_exceeded';
```

运行信号额外增加一个「注意力」维度，而不是新增状态：

```ts
type WorkAttention = 'none' | 'approval' | 'input';
```

- `waiting` + `attention=approval`：等待工具/人工授权，桌宠进入 `WAITING`。
- `waiting` + `attention=input`：流程人工节点等待填写/审核。
- `running` + `attention=none`：正常工作；`activity` 细分思考/检索/写入/执行/验证。

## 2. WorkSignal

```ts
type WorkSource = 'task' | 'flow' | 'agent' | 'chat' | 'meeting';
type WorkActivity =
  | 'idle' | 'thinking' | 'searching' | 'reading'
  | 'writing' | 'executing' | 'verifying' | 'meeting' | 'speaking';

interface WorkSignal {
  key: string;              // `${source}:${runId}`
  source: WorkSource;
  runId: string;
  title: string;            // 任务目标 / 工作流名 / 协作目标，最长 120 字
  outcome: WorkOutcome;
  attention: WorkAttention;
  activity: WorkActivity;
  stepLabel: string | null; // “第 3 步 · web_search” / 节点名
  completedSteps: number;
  totalSteps: number | null;
  startedAt: string;        // ISO
  updatedAt: string;        // ISO
  endedAt: string | null;
  errorReason: string | null;
  deepLink: string;         // 站内路由，不含 token
}
```

约束：

- `title` 由服务端截断，禁止把工具参数/密钥写进标题。
- `deepLink` 只允许站内相对路径：`/tasks`、`/flows/{workflowId}?run={runId}`、`/chat?conversation={id}`、`/meetings/{id}`。
- 终态信号保留 60 秒用于桌宠脉冲，之后由 hub 清理；不落库。
- 同一 `runId` 只保留最新信号；`key` 由 source + runId 决定。

## 3. 运行边界

v2.7 只做「可见」，不改运行归属：

| 链路 | 现状 | v2.7 口径 |
|---|---|---|
| Task | SSE 生命周期绑定请求，断线 abort | 页面/桌宠订阅期间可见；关页续跑留 v2.8 |
| Flow | 队列驱动，断线不取消 | 服务端继续产生信号；晚加入可回放最近快照 |
| Agent | owner SSE + observer 总线 | 复用 observer 总线；桌宠作为独立订阅者 |

事件接入点（不改 runner 核心）：

- Task：`createTaskRunnerService` 增加可选 `onEvent(run, event)`，在 `start` 包装器内逐帧回调。
- Flow：`createFlowRunService` 增加可选 `onEvent(run, event)`，在 `runQueued` 的 `bus.publish` 同时回调。
- Agent：`createAgentRunService` 增加可选 `onEvent(run, event)`，用 `tapRunEvents` 的代理总线回调。

## 4. RunEventHub 与 API

服务端进程内单例（挂在 `ServiceContainer.workSignals`）：

```ts
interface WorkSignalHub {
  ingestTask(run: TaskRunView, event: TaskLoopEvent): void;
  ingestFlow(run: WorkflowRunView, event: FlowEventPayload, title: string): void;
  ingestAgent(run: AgentRunView, event: AgentRunEvent): void;
  snapshot(): WorkSignalSnapshot;
  subscribe(): AsyncIterable<WorkSignalSnapshot>;
  clear(): void;
}
```

- 快照每变更递增 `seq`；订阅者只收订阅后的新快照，并在建连时先收当前快照。
- SSE 端点 `GET /api/work-signals/stream`：`event: snapshot` + JSON；托管模式 token 校验。
- 只读端点 `GET /api/work-signals`：返回当前快照（测试/降级轮询）。
- 终态清理定时器 `unref`，不阻塞进程退出。

## 5. 审批信封

```ts
type ApprovalSource = 'tool' | 'flow' | 'desktop';

interface WorkApproval {
  id: string;                 // tool:{callId} / flow:{runId}:human:{nodeId} / flow:{runId}:tool:{nodeId}
  source: ApprovalSource;
  title: string;
  tool: string | null;
  permission: 'read' | 'write' | 'danger' | null;
  argsSummary: string | null;
  runId: string | null;
  conversationId: string | null;
  createdAt: string;
  expiresAt: string | null;
  deepLink: string;
}
```

统一注册表 `ApprovalRegistry`：

- `register(input, onResolve)` 返回 `{ id, remove }`；`onResolve(decision)` 调底层 `confirmations.resolve` / `waiters.resolve`。
- `resolve(id, { action: 'allow' | 'deny', values? })`；不存在返回 false。
- `list()` 按 `createdAt` 升序。
- 底层超时/abort/任务结束时调用 `remove`，避免僵尸审批。
- 审批中心只提供「一次性允许/拒绝」；`remember` 策略仍由原对话框处理。
- 默认 fail-closed：超时、断线、注册表缺失一律拒绝。

API：

- `GET /api/approvals`：`{ approvals: WorkApproval[] }`。
- `POST /api/approvals/{id}/resolve`：`{ action, values? }`；成功 `{ ok: true }`，不存在 404，已结束 409。
- 审批变化并入 `WorkSignalSnapshot.approvals`，桌宠与审批页共用。

接入：

- 工具确认：`gateToolPermission` 在 `confirmations.request` 后注册；`deepLink` 由调用方传入（chat → 对话，task/agent → 任务）。
- Flow：`requestToolConfirmation` 与 `requestHuman` 在 `waiters.request` 后注册。
- 桌面控制授权：P1，暂不注册。

## 6. 桌宠映射

基础七态：

| WorkSignal 条件 | 桌宠基础态 |
|---|---|
| 无活跃信号，SSE 正常 | IDLE |
| 有 approvals | WAITING |
| 最近终态 failed/interrupted/budget_exceeded | ERROR |
| running + activity=thinking | THINKING |
| running + activity≠thinking | WORKING |
| 最近终态 succeeded 且 15 秒内 | SUCCESS（脉冲后回 IDLE） |
| SSE 断线 | DISCONNECTED |

优先级（高 → 低）：等待审批 > 失败 > 进行中（最近更新优先） > 排队 > 成功脉冲 > 空闲。
多运行聚合：气泡显示主运行标题 + `N 个进行中 · M 个待审批`；主运行选择按上述优先级。

气泡规则：

- 位置：角色上方；顶部空间不足时翻到角色下方（窗口内偏移，不改窗口尺寸）。
- 模式：`auto`（有信号才显示）/ `always` / `hidden`。
- 点击：气泡本身不接收指针（保持点击穿透）；双击头部/右键菜单「打开当前工作」跳到主窗 `deepLink`。
- 提示音：完成 / 错误 / 待审批三类独立开关；默认全开；勿扰时段只留徽标。
- 减少动态：关闭气泡脉冲与完成/错误抖动；角色动作沿用现有 `motionRotationEnabled` 与动画图设置。

## 9. 验收

- 纯函数单测：三套事件 → WorkSignal 映射、优先级聚合、终态清理、审批 register/resolve/remove。
- 服务端集成：三条链路跑一次，`/api/work-signals` 快照包含对应信号；审批 API 能 allow/deny 并唤醒运行。
- 桌宠：desktop e2e 验证工作气泡出现、审批徽标、双击深链、SSE 断线显示 DISCONNECTED。
- Web e2e：`/approvals` 页面允许/拒绝后运行继续；不出现僵尸审批。
- `pnpm check`、单测、Web/桌面 e2e、300 行门禁通过。
