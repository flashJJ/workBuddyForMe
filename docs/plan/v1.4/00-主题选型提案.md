## 1. 决策背景

v1.3 把知识库做成了「预编译、可追溯、可治理」的本地知识层；至此产品的纵向能力栈已经齐整：对话（v0.1）→ 工具（v0.2）→ 多模态文档（v0.3）→ 记忆/上下文（v0.5）→ MCP 与技能（v0.6）→ 桌面 Agent（v0.7）→ 确定性 Flow（v0.8/v0.9）→ 语音伙伴（v1.0）→ 发布完成度（v1.2）→ 编译式知识（v1.3）。

v1.4 要回答的下一问题：**能力都在了，哪些「单个助手一轮对话做不成、做不稳」的真实任务，现在值得被产品化？**

### 已存在、不必重造的编排底座（已核对代码）

| 底座 | 位置 | 对 v1.4 的意义 |
|---|---|---|
| 单 Agent 循环 | `core/agent/task-loop.ts`：观察→LLM 规划→权限门控→执行→再观察，步数/连续失败上限、熔断联动、急停、task_steps 全程落库 | 多角色中的「执行者」可直接复用，不重写循环 |
| 确定性编排 | Flow Studio（v0.8 DAG 画布）+ Flow Serving（v0.9 HTTP/MCP、审批节点、运行记录/重放） | 确定性多步流程已有归属；v1.4 若做多 Agent，必须与 Flow 划清边界而不是再造一个 Flow |
| 编译知识层 | v1.3 实体/摘要静态知识 + 混合检索 + 治理 | 多角色共享同一知识层是天然组合（v1.3 提案已预埋此判断） |

## 2. 四个候选主题

### 候选 A：「会分工」——最小多智能体编排（推荐）

在单助手之上引入**规划者（Planner）→ 执行者（Executor，复用 task-loop）→ 审查者（Reviewer）** 的最小固定角色协作：复杂任务先分解、派发给具备不同工具/知识/模型配置的执行者，审查者对产出校验并决定返工或交付。

形态边界（关键取舍）：

- **确定性骨架仍归 Flow**：分支/循环/人审/服务化不重造；多 Agent 只解决「需要边做边看、动态决定下一步」的概率性协作。
- **Agent 成为 Flow 的新节点类型**：`agent` 节点在确定性 DAG 中承担「开放子任务」，Flow 提供边界与审批，Agent 提供弹性——两者组合而非竞争。
- 共享 v1.3 编译知识与 v0.5 记忆；角色间用显式 Handoff（任务说明/产出/引用/失败原因）交接，不搞自由对话群聊。
- 安全语义沿用现有权限分级：桌面控制类工具在多 Agent 链路中默认更保守（无人值守策略已有 v0.9 底子）。

**为什么推荐**：① 路线图远期展望（v0.8+ 团队协作）与 v1.3 选型记录两次点名，是既定方向；② 知识层、工具链、task-loop、运行记录四块底座恰好齐备，首次出现「只欠编排层」的窗口期；③ 效果可用任务成功率/返工率机械度量（复用 v1.1 eval 平台，新增 agent golden）。

**主要风险**：本地小模型的规划/审查质量不稳（默认模型可按角色选，规划/审查建议用强模型，执行可用本地模型）；token 成本上升（需预算看板与硬上限）；角色数必须克制（首期 3 角色固定模板，不做任意角色拼装）。

### 候选 B：「活知识」——外部连接器与知识保鲜

v1.3 的知识是「上传时定型」的静态文档；本候选让知识库会自己更新：文件夹监听自动摄取、网页/RSS 变更监控、定时剪藏、摄取去重与变更摘要（「这份资料相对上次变了什么」）。

- **价值**：资料时效性（官方文档/价格表/规范更新）；零手动维护感。
- **暂不推荐作为 v1.4 主题**：价值真实但偏「增量增强」，不构成新的使用心智；定时网络抓取在本地优先产品里要处理常驻调度/网络失败/去重噪音，工程量不小而演示性弱。建议作为 v1.5 候选，或在 v1.4 内以 1 个「监听文件夹自动入库」的小切片伴随。

### 候选 C：「稳得住」——桌面 Agent 可靠性 2.0（v0.7 深化）

v0.7 的桌面控制（截图/SOM 标记/键鼠）之后未再系统迭代。本候选攻真实长任务成功率：操作录制与回放、窗口/控件定位的多级回退（UIA→图像→坐标）、失败自愈（目标窗口丢失/弹窗遮挡）、长任务看护与断点续跑。

- **价值**：把「能演示」变成「每天敢托管」；直接提升现有 task-loop 的实战可用性。
- **备选理由**：若近期真实使用中桌面自动化失败是第一痛点，应优先于多智能体（单 Agent 不稳时多 Agent 只会放大不稳）。**需要用户给真机使用反馈来排序**。

### 候选 D：「用起来」——Flow/技能生态与模板分享

工作流与技能目前只能自建：内置模板库、一键导入、对话式生成 Flow（「帮我把这个重复操作做成流程」）、分享包导出/导入。

- **价值**：降低 Flow Studio 的使用门槛，放大 v0.8/v0.9 投入的杠杆。
- **暂不推荐**：单人本地优先产品没有社区侧，分享是「导出文件发给朋友」的弱闭环；对话式生成 Flow 与候选 A 的规划能力共享技术，A 落地后本候选自然变轻。建议 v1.5+。

### 不立项的选项

- **纯收尾版本**（tag/小修/帮助锚点）：内容不足以支撑一个主题版本（v1.1 已有工程向先例），作为伴随项与发布运维消化。
- **移动端/远程访问**：与本地优先宪法和 Windows 单端投入节奏冲突，远期再议。

## 3. 推荐的 v1.4 形态（主题 A 粗框，非正式功能清单）

**主题：会分工——规划/执行/审查的最小多智能体协作**

| 粗目标（待四篇方案细化） | 方向 |
|---|---|
| G1 角色编排内核 | 固定三角色 Planner/Executor/Reviewer 的状态机与 Handoff 契约（纯函数可单测）；步数/轮次/token 硬上限；全程事件流可中断/可急停 |
| G2 Agent 进 Flow | Flow 画布新增 `agent` 节点（角色配置+工具域+知识绑定+预算），确定性 DAG 与概率性子任务统一在一张图里 |
| G3 协作可观测 | 复用 task_steps/Flow 运行记录：角色泳道式时间线（谁在何时基于什么交接做了什么、引用了哪些知识） |
| G4 权限与预算安全 | 多 Agent 链路的工具授权收紧（桌面控制默认需逐次/会话确认）、每角色模型可选、token/步数预算看板与熔断 |
| G5 eval agent golden | 新增任务级 golden（任务→期望最终状态/关键工具调用序列），含「去掉审查者质量下降」的反向验证 |
| G6 零回归 | 全门禁不降级；单助手对话路径零变化（多 Agent 为显式入口，不默认接管普通聊天） |

**预设 Non-Goals**：不做自由形态的 N 角色拼装/Agent 群聊（首期固定模板）；不做 Agent 市场/角色分享；不重造 Flow 已有的分支/循环/审批/服务化；不做云端多用户协作；不默认让多 Agent 接管普通问答（显式创建任务或 Flow agent 节点触发）。
