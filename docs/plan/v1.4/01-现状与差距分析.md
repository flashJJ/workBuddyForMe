## 1. 现有编排资产

### 1.1 桌面任务 Agent 循环（v0.7）——Executor 的直系前身

| 文件 | 现状取证 | v1.4 复用方式 |
|---|---|---|
| [task-loop.ts](../../../packages/core/src/agent/task-loop.ts) | `runTaskLoop` 异步生成器：观察→决策→门控→执行→再观察；护栏含 maxSteps、连续失败上限、熔断联动、AbortSignal/控制句柄急停；每步落 task_steps | **直接作为 Executor 内核复用**，仅泛化观察模式与工具上下文 |
| [llm-planner.ts](../../../packages/core/src/agent/llm-planner.ts) | 注入式 `TaskPlanner`（生产 LLM / 测试 mock）；`buildPlannerMessages`/`parseDecision` 纯函数；JSON 协议 `{action:tool/done/fail}`；temperature=0、maxTokens=1024；容忍 markdown 包裹，解析失败抛 PlannerParseError 记为一次失败步 | Planner/Reviewer 照搬此模式：**system 协议 + 纯函数 build/parse + 失败可自纠错**，不引新框架 |
| [control.ts](../../../packages/core/src/agent/control.ts) | `TaskLoopControl`：running/paused/stopped + waitIfPaused；`TaskLoopEvent = SseEvent<'task'> | 协作级急停在此之上包一层 supervisor control（轮次级停止/单步急停共用 AbortSignal） |
| [task-runner-service.ts](../../../packages/core/src/services/task-runner-service.ts) | task-loop 的唯一生产调用方（第 66 行 `runTaskLoop({...})`），负责创建 run、装配 planner 与工具 | 新增 agent-runner-service 与其并列；**不改动桌面任务服务现有行为** |
| [som-marker.ts](../../../packages/core/src/agent/som-marker.ts) | Set-of-Mind 屏幕控件标记（视觉观察辅助） | 屏幕观察模式继续使用；知识型任务不触发截图链路 |

**关键断点（取证发现）**：`runTaskLoop` 内构造的 `ToolContext` 中 `knowledgeBaseId: null`、`retrieve: async () => []`（task-loop.ts:33-38）——**桌面任务 Agent 从 v0.7 起就是断知识的**。M2 必须修复：工具上下文应由调用方注入（助手/节点的知识库绑定与 RAG retriever）。

### 1.2 Flow 确定性编排（v0.8/v0.9）——agent 节点的宿主

| 模块 | 现状取证 |
|---|---|
| 节点 handler 注册表 | [handlers/index.ts](../../../packages/core/src/flow/handlers/index.ts) `createDefaultHandlers()`：start/end/llm/knowledgeSearch/tool/condition 六类，`FlowNodeHandler<C,O>` 声明式 `{type, ...}`；human 节点引擎内联（挂起/等待） |
| 引擎与编译 | engine.ts / engine-live.ts / compiler.ts：图编译→拓扑执行→分支（engine-branch 纯函数）→挂起恢复；run-options、refs（变量引用 `{{$nodes.x.y}}`） |
| 队列与恢复 | queue/run-queue（单并发）、event-bus、recovery-scanner（崩溃扫描续跑）、wait-registry（human 等待） |
| 运行记录 | run-store + run-service：workflow_runs/node_executions 落库，运行中心支持按节点重放/整体重跑（v0.9） |
| 服务化与策略 | flow/chat-invoke（对话中作为工具）、flow-tool、policy-gate（无人值守 read/write/danger 策略）、v0.9 本地 HTTP/MCP 端点 |
| 画布 | flow-editor 22 组件（v1.3 M5.4 已全部英文化）：node-meta/forms-*/config-panel/diagnostics |

**结论**：新增 agent 节点 = 新增一个 handler 文件 + 节点元数据/表单 + 配置 schema + 画布节点外观 + 运行记录映射，**管道完全现成**；agent 节点的挂起/取消/事件可复用 human 节点与事件总线机制。

### 1.3 对话工具循环（v0.2 起）——普通聊天路径保持不动

chat-orchestrator.ts：`prepareTurnContext` 装配工具 → `runProviderTurnWithToolFallback` → `runToolCallLoop`（最多 MAX_TOOL_ROUNDS 轮）→ citations 合并落库（18461de 已修复持久化）。多智能体**不嵌入此循环**：协作走独立 agent-runner，避免普通聊天路径产生任何行为分叉。

### 1.4 权限与工具生态

- [tool-permission-gate.ts](../../../packages/core/src/chat/tool-permission-gate.ts)：`gateToolPermission` 异步生成器，ToolGateParams/ToolGateResult，逐次工具调用门控（read/write/danger）。
- 工具清单：13 个内置（current_time/knowledge_search/fetch_webpage + 7 个桌面控制 + uia_list/window_list/app_launch）、MCP 工具、已发布 Flow 工具（flow:&lt;id&gt;）；tool-trace 全程可观测（v1.3 已双语）。
- v0.9 policy-gate：仅 API/MCP 无人值守调用按发布时策略放行；交互会话的桌面工具维持 HITL。

### 1.5 运行记录与可观测底座

- v011 迁移：`task_runs`（status/step_count/max_steps…）+ `task_steps`（step_index/kind/tool_name/status/reason/error…+截图附件引用），索引齐全。
- Flow：workflow_runs/node_executions（含等待人审状态）。
- 消息级：messages.tool_trace JSON（工具调用轨迹）+ messages.citations（v1.3 引用，含 staticKind/页段坐标）。
- SSE：OrchestratorEvent 联合类型 + flow run-event-stream + task SseEvent——**三种事件源已并存，agent 事件作为新事件族并入，不改既有帧语义**。

### 1.6 知识层与模型解析（v1.3 新底座）

- 编译式 RAG：createRagRetriever（静态实体/摘要置顶 + 混合检索 8 片）、知识库编译三表、治理（冲突/重复）。
- 模型解析：chat/model-resolver.ts `resolveChatTarget`（助手→默认模型/供应商能力门控）；embedding-target 同理。**角色级模型解析在其之上加一层「角色覆盖→助手→系统默认」回落**。

## 3. 不打算改动的部分（边界确认）

- chat-orchestrator 普通问答路径（含 retrieveAlways、工具循环、记忆/技能注入）——零改动。
- Flow 引擎调度语义（队列/恢复/重放/服务化/策略门控）——agent 节点作为普通 handler 接入，不改拓扑执行算法。
- 权限模型本身（read/write/danger + HITL + v0.9 策略）——只在协作链路上明确「不自动提权」的装配规则，不新增权限级别。
- 知识编译/检索链路——作为 Executor 的能力被消费，不在本版改检索算法。

---

## 4. 前置条件核对（为什么是现在）

1. 执行循环已验证：task-loop 含熔断/急停/落库，不需要重写（v0.7 至今）。
2. 确定性/概率性边界已清晰：Flow 两年迭代把确定性侧做透，agent 节点只需补「开放子任务」一类。
3. 知识层刚封版：Executor 接上 v1.3 编译知识后，「会分工的系统同时有可引用的事实」，避免多角色围绕低质上下文空转。
4. eval 平台与三开关反向验证模式在 v1.3 刚跑通（none/fts/compile），agent 域可直接复制矩阵方法论。
5. i18n 与双语门禁完备：新 UI 域随版翻译有成熟管道（P1 已清零）。
