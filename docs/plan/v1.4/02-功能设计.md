# v1.4 功能设计：角色、交接契约、协作内核与 agent 节点

> 命名前缀：shared 类型 `Agent*`；core 域目录 `core/src/agents/`；数据库迁移 v019；i18n 域 `agents`（与既有 `assistants` 助手区分：助手是用户配置实体，Agent 角色是协作拓扑角色）。

---

## 1. 角色模型与协作拓扑

固定三角色、串行单执行、最多 N 轮返工：

```
用户目标
   │
   ▼
Planner（分解/派单）──► Handoff(subtask) ──► Executor（执行子任务）
   ▲                                              │
   │                                      Handoff(deliverable)
   │                                              ▼
   └──────── revise（附审查意见）──────── Reviewer（对照目标验收）
                                  │
                       approve ──► 汇总交付用户
                       reject  ──► Planner 重新派单（计入返工轮次）
                       超轮次  ──► 交付「预算内最佳结果 + 未完成项」
```

| 角色 | 职责 | 禁止事项 | 默认模型 |
|---|---|---|---|
| planner | 把目标拆为**单个**可执行子任务单（含完成标准、可用工具域提示、所需知识库）；返工轮次结合审查意见重新派单 | 不直接调工具、不产出最终答案 | 默认聊天模型（建议强档，启动时弱档一次性提示） |
| executor | 在子任务范围内执行：知识检索/内置工具/MCP/Flow，产出结构化交付物（结论+证据引用+未竟事项） | 不越出子任务工具域；桌面控制仍受 HITL | 可独立配置（允许本地模型降本） |
| reviewer | 对照原始目标与完成标准验收：证据是否支持结论、引用是否真实、子任务是否被完整回答 | 不自己动手补做（只裁决+文字意见） | 同 planner 档 |

角色拓扑是代码内显式状态机（`AgentPhase` 联合类型），**不做可配置角色图**。

## 2. Handoff 契约（shared，纯数据）

```ts
export type AgentRole = 'planner' | 'executor' | 'reviewer';
export type AgentPhase = 'planning' | 'executing' | 'reviewing' | 'done' | 'failed';
export type ReviewVerdict = 'approve' | 'revise' | 'reject';

export interface SubtaskSpec {
  title: string;                    // 子任务一句话
  brief: string;                   // 执行说明（角色交接的主体文本）
  acceptance: string[];            // 完成标准（Reviewer 逐条核对）
  toolScopes?: string[];           // 允许工具域提示（如 ['knowledge','mcp:xxx']；桌面类需显式列出）
  knowledgeBaseId?: string | null; // 指定知识库（缺省继承助手绑定）
}

export interface ExecutorOutcome {
  summary: string;                 // 给 Reviewer/用户的结论
  evidence: Citation[];            // v1.3 引用（含 staticKind/页段坐标）
  toolCalls: string[];             // 实际调用工具名序列（取自 toolTrace，供审计/eval）
  unfinished: string[];            // 未竟事项（预算/权限/信息不足）
}

export interface AgentHandoffPayload {
  subtask?: SubtaskSpec;           // planner→executor
  outcome?: ExecutorOutcome;       // executor→reviewer
  verdict?: ReviewVerdict;         // reviewer→planner/user
  reviewNotes?: string;            // revise/reject 理由（返工输入）
}
```

- 所有交接必须是合法 JSON（Planner/Reviewer 走 LLM JSON 协议 + zod 校验，失败按角色各自的容错计数处理）。
- Handoff **不承载自由多轮对话**；Executor 内部的思考轨迹留在 toolTrace/task_steps，不进交接正文。
- 交接正文长度有硬上限（brief ≤2000 字、summary ≤4000 字），防爆 token 与提示词注入。

## 3. v019 存储迁移（纯加法）

```sql
CREATE TABLE IF NOT EXISTS agent_runs (
  id TEXT PRIMARY KEY,
  conversation_id TEXT,             -- 任务模式入口关联（agent 节点发起时可空）
  flow_run_id TEXT,                 -- Flow agent 节点发起时关联（可空）
  node_execution_id TEXT,           -- 对应的 node_executions 行（可空）
  assistant_id TEXT NOT NULL,
  goal TEXT NOT NULL,
  status TEXT NOT NULL DEFAULT 'running',  -- running/done/failed/cancelled/budget_exceeded
  round_no INTEGER NOT NULL DEFAULT 0,     -- 已完成的规划-执行-审查轮次
  final_outcome TEXT,                      -- 最终交付 JSON（ExecutorOutcome + 审查结论）
  prompt_tokens INTEGER, completion_tokens INTEGER, total_tokens INTEGER,
  error_code TEXT, error_message TEXT,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS agent_handoffs (
  id TEXT PRIMARY KEY,
  run_id TEXT NOT NULL REFERENCES agent_runs(id) ON DELETE CASCADE,
  round_no INTEGER NOT NULL,
  seq INTEGER NOT NULL,              -- 轮内交接序号（0=派单 1=交付 2=裁决）
  from_role TEXT NOT NULL,
  to_role TEXT NOT NULL,
  payload TEXT NOT NULL,             -- AgentHandoffPayload JSON（zod 校验后写入）
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_agent_handoffs_run ON agent_handoffs(run_id, round_no, seq);
```

- Executor 细节步骤不新建表：屏幕任务沿用 task_runs/task_steps（新增可空 `agent_run_id` 关联列），工具轨迹写消息 toolTrace；**轨迹模型保持一套**。
- agent_runs 与对话/Flow 双侧均可空关联（两种入口）；备份导出随既有消息/工作流轨，agent_runs 属可重建运行记录，导出策略与 workflow_runs 同级。

## 4. 协作内核（`core/src/agents/`，新域 ≤260 行/文件）

| 文件 | 职责 | 测试形态 |
|---|---|---|
| `agents/types.ts` | 协作运行时类型（AgentRunnerParams、AgentRunEvent、预算快照） | 类型契约测试 |
| `agents/planner-protocol.ts` | `buildPlannerPrompt`/`parsePlan`/`validateSubtask`（zod）纯函数；非法输出分类（缺字段/越权工具/超长） | 表驱动单测 ≥15 例 |
| `agents/reviewer-protocol.ts` | `buildReviewPrompt`/`parseVerdict`/`checkAcceptance`（验收逐条比对，纯规则初筛+模型裁决） | ≥12 例 |
| `agents/supervisor.ts` | 协作状态机纯函数骨架：`nextPhase(phase, verdict, budget)` + 轮次/预算判定；不接触模型 | 状态全覆盖单测 |
| `agents/agent-runner-service.ts` | 装配 supervisor + 三角色模型客户端 + executor 适配器；异步生成器产出 SSE 事件；事务写 agent_runs/handoffs | mock 角色集成测 |
| `agents/executor-adapter.ts` | 把子任务交给执行通道：知识/工具型走 chat 工具循环裁剪版，桌面型走 task-loop；统一收敛为 ExecutorOutcome | 两通道各一组测 |
| `agents/budget.ts` | 三重预算纯函数：轮次（默认 3）/单角色步数（沿用 maxSteps 默认 20）/总 token（默认 80k，上限 200k）；`consume/shouldStop/exceededReason` | 边界单测 |

**容错语义**：Planner/Reviewer JSON 解析连续 2 次失败 → 该轮降级（Planner 降级为把原始目标直接派单；Reviewer 降级为 approve 并标注「自动通过」）；Executor 工具失败沿用 task-loop 连续失败上限；任何降级都必须在事件与 handoff 中显式可见。

## 5. Executor 泛化（改造点最小化）

1. `runTaskLoop` 的 `ToolContext` 改为**入参注入**：`knowledgeBaseId` 与 `retrieve` 由调用方提供（修复 D2 硬编码空）；桌面任务服务维持原调用（传 null/空，行为不变）。
2. 观察模式二选一（子任务单声明，不中途切换）：
   - `screen`：现状截图+SOM 循环（桌面控制任务）；
   - `tool`：不截图，观察内容=工具结果与检索片段（知识/MCP/Flow 任务），省掉视觉 token。
3. 桌面控制类工具仅当 SubtaskSpec.toolScopes 显式包含时可进入白名单；知识检索经 rag-retriever，回答证据统一转 `Citation[]`。
4. Executor 结束时由适配器汇总 ExecutorOutcome（summary 取模型收尾文本；evidence 取当轮 citations；toolCalls 取 toolTrace；unfinished 由模型 JSON 声明，缺省空数组）。

## 6. 角色模型解析

解析顺序：**节点/子任务显式 modelId → 助手角色覆盖（assistant 配置新增 plannerModelId/executorModelId/reviewerModelId，均可空）→ 系统默认聊天模型**；executor 允许选择 embedding 同源供应商但不强求。能力门控复用 resolveChatTarget（视觉仅屏幕观察模式要求）。设置 UI 提供三角色下拉（留空=跟随默认），弱模型（contextWindow < 8k 或本地 7B 以下标识）旁置一次性提示。

## 7. Flow agent 节点（M3）

- 节点类型 `agent`，配置：`goal`（支持 `{{$nodes...}}` 引用）、`toolScopes[]`、`knowledgeBaseId`、`maxRounds`、`maxTokens`、三个角色 modelId 覆盖（可空）。
- 注册为 `FlowNodeHandler`：handler 内创建 agent_run（flow_run_id/node_execution_id 回填），把协作事件转发为 Flow 运行事件；取消沿用引擎 AbortSignal；挂起语义不需要（agent 节点内部 HITL 走现有工具门控弹窗通道，不挂起图）。
- 输出：`outcome.summary`（文本）、`outcome.evidence`（引用数组）、`status`、`rounds`，供下游节点引用。
- 画布：node-meta 新增图标/默认配色；forms-agent 配置表单（目标/工具域 chips/知识库选择/预算/角色模型）；diagnostics 校验（goal 非空、预算区间、桌面工具域风险提示）。
- 服务化：agent 节点随已发布 Flow 走 v0.9 端点时，桌面控制工具受 policy-gate 约束（无人值守策略默认拒桌面类，沿用既有 banned 语义）。

## 8. API 与 SSE

| 路由 | 方法 | 说明 |
|---|---|---|
| `/api/agent/runs` | POST | 发起协作（body：assistantId/conversationId?/goal/预算覆盖），返回 runId |
| `/api/agent/runs/[id]` | GET | 运行详情 + handoffs（泳道渲染数据） |
| `/api/agent/runs/[id]/events` | GET（SSE） | 协作事件流（复用事件总线与签名机制） |
| `/api/agent/runs/[id]/cancel` | POST | 协作级急停（停当前角色 + Executor 子循环） |
| `/api/agent/runs` | GET | 运行列表（任务中心 agent 区段，复用列表筛选模式） |

新增 SSE 事件族（并入既有联合类型，不动旧帧）：`agent:phase`（角色/轮次切换）、`agent:handoff`（交接落库后广播）、`agent:review`（裁决+验收逐条结果）、`agent:budget`（预算快照变化）、`agent:delta`（角色产出增量文本，可选）、终态复用 `done/error` 语义。

## 9. UI（M4，随版中英双语）

1. **任务模式入口（显式）**：对话 Composer 旁「任务模式」开关（会话级，默认关，状态不跨会话持久化）；开启后发送走 `/api/agent/runs`，普通发送按钮逻辑不变。
2. **角色泳道时间线**：按轮次折叠的三列泳道（规划卡：子任务单+完成标准；执行卡：复用 tool-trace/citations-list；审查卡：验收逐条 ✓/✗ + 裁决徽标 + 「按意见返工」过程可见）。返工在同一卡片组内追加轮次，不新增消息气泡。
3. **预算条**：运行卡顶部实时显示轮次 x/N、累计 token、步数；熔断终态红色说明 exceededReason。
4. **任务中心**：tasks 页新增「协作任务」区段（agent_runs 列表，状态筛选复用）；点入展开 handoffs。
5. **Flow 画布**：节点面板新增「智能体」分组；agent 节点在运行时间线里展开为子泳道（嵌套但只读）。
6. 权限弹窗：桌面类工具在协作中被调用时，弹窗文案标明「由协作任务 · Executor 发起」。

## 10. eval（M5）

- `scripts/eval/agent-golden.json` ≥15 例，四类：①纯知识执行（证据必须含期望文档）；②工具序列（toolCalls 顺序断言）；③审查拦截（执行产出含可识别瑕疵时 reviewer 必须 revise）；④预算/急停（超轮次终态 budget_exceeded、cancel 及时停止）。
- mock 角色确定性回放（planner/executor/reviewer 各自可注入脚本），不依赖真实模型；另备 1 组可选的真机 Ollama/云端冒烟（不计入门禁）。
- 反向验证三开关：`reviewer=off`（审查通过率虚高、瑕疵用例应失败）、`knowledge=off`（知识类任务证据断言失败）、`budget=1轮`（返工类任务终态应带 unfinished）。
- e2e（tests/e2e/agent-collab.spec.ts，mock 供应商）：规划→执行→引用→审查通过；审查返工一次后通过；急停；预算熔断；Flow 中 agent 节点端到端。
