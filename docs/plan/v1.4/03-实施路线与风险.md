# v1.4 实施路线与风险：M0–M5 合同式任务板

> 验收标准全部可机械判定（测试/脚本/断言），人工主观项显式标注。每里程碑结束必须：check 全绿、新增文件 ≤260 行（300 硬门禁）、里程碑独立提交。

## 1. 里程碑总览

| 阶段 | 主题 | 出口判据 |
|---|---|---|
| M0 | 契约与存储基座 | shared 类型 + v019 迁移 + SSE 事件族占位；无 UI 行为变化 |
| M1 | 三角色协作内核 | mock 角色下端到端跑通规划→执行→审查→交付/返工/熔断；内核单测 ≥60 例 |

## 2. 合同任务板

### M1 三角色协作内核

| 任务 | 验收标准 |
|---|---|
| T1.1 planner 协议纯函数 | buildPlannerPrompt/parsePlan/validateSubtask：≥15 表驱动用例（markdown 包裹/前后杂文本/缺字段/工具越权/超长/非 JSON）；temperature=0 固定 |
| T1.2 reviewer 协议纯函数 | buildReviewPrompt/parseVerdict/checkAcceptance：≥12 例；验收逐条输出 approve/revise/reject + notes；checkAcceptance 规则初筛纯函数 |
| T1.3 supervisor 状态机 | nextPhase 全状态×全输入转移表测试（approve→done/revise→planning/reject 轮次+1/预算各触顶分支）；无模型依赖 |
| T1.4 预算治理 budget.ts | 轮次默认 3/总 token 默认 80k 上限 200k/步数沿用；consume/shouldStop/exceededReason 边界单测；任意超限即停且终态 budget_exceeded |
| T1.5 agent-runner-service | 三角色全 mock：①一次通过 ②返工一次通过 ③reject 超轮次交付最佳结果+unfinished ④Planner 解析失败降级派单 ⑤Reviewer 失败降级 approve 并标注；每场景断言 handoffs 落库序列与事件序列 |
| T1.6 急停与取消 | cancel 后当前角色与 executor 子循环均在 1 个动作内停止（AbortSignal 传播测试）；status=cancelled |
| T1.7 agent-runs 仓储与 API 骨架 | POST/GET/列表/cancel 路由 + with-api-handler 统一错误；服务端单测（404/422/状态机非法转移） |

## 3. 测试策略

- **纯函数优先**：协议解析、状态机、预算、验收初筛全部无模型纯函数，行覆盖目标 ≥95%（与 v1.1 压缩模块同级）。
- **mock 角色集成**：runner 测试注入脚本化 planner/executor/reviewer，断言交接序列、事件序列、落库序列三者一致（不解析自然语言）。
- **真实模型不进门禁**：只保留可选手工冒烟脚本（Ollama/云端），CI 永远 mock——与 v1.3 eval 同策略。
- **测试基座复用**：Flow 引擎测试用 mock handler 的模式直接套用；SSE 用 eval/lib/sse-client。

## 4. 风险矩阵与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 弱模型规划/审查不可用，本地 7B 跑不通三角色 | 高 | 角色模型独立可选+弱档一次性提示；协议纯函数让解析失败可降级；golden 全 mock 门禁不依赖模型质量；发布说明写清推荐档位 |
| token 成本显著上升（多角色多轮） | 高 | 三重硬预算默认保守；交接正文长度上限；历史轨迹摘要化（沿用 HISTORY_STEP_CAP 思路）；预算实时可见让用户即时止损 |
| 与 Flow 定位混淆，用户不知何时用哪个 | 中 | UI 文案与帮助中心明确：步骤确定用 Flow、边做边看用 Agent；agent 节点内嵌于 Flow，长期引导用户「Flow 画骨架、Agent 补弹性」 |
| 多一层 Agent 成为权限提权绕过面 | 高 | 工具门控以最终调用为单位；桌面工具默认 HITL 且标明发起者；SubtaskSpec 工具域外调用一律拒绝；服务化沿用 policy-gate；安全断言进 e2e |
| 协作无限返工/卡死 | 中 | 轮次/失败计数/JSON 降级三重收敛；任意角色连续 2 次协议失败即降级或终止；120s 块间空闲超时（复用 v1.3 经验） |
| Executor 泛化破坏 v0.7 桌面任务稳定性 | 中 | ToolContext 注入式改造，桌面服务调用点行为保持并回归现有 task-loop 全部测试；观察模式显式二选一 |
| Handoff 提示词注入（子任务文本诱导越权） | 中 | toolScopes 白名单在执行器侧强制（不靠提示词自律）；交接文本只进用户内容位不进 system；评审意见同样按数据处理 |
| agent 节点让 Flow 运行时间不可控 | 中 | 节点预算必填且有上限；运行时间线可见轮次；取消即停；服务化场景总超时沿用 v0.9 端点配置 |

## 5. Non-Goals 复核（与 README 一致，任务板期间不得偷渡）

自由 N 角色/群聊、并行多 Executor、重造 Flow 既有能力、云端协作、默认接管普通问答、自动模型采购——均不在 M0–M5 任何任务中。伴随项仅：任务模式相关 UI 的双语随版（T4.6），不夹带其他域改造。

## 6. 封版口径（预计）

check 14/14；新增单测 ≥120（协议/状态机/预算 ≥60，仓储/API/引擎/UI ≥60）；e2e 37+5=42 全绿；eval agent 三态矩阵绿；版本 1.4.0 合 main 后打 tag 与 Release 的流程同 v1.3（发布运维独立签字）。
