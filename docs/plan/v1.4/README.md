# Release v1.4 方案 · 会分工：规划/执行/审查的最小多智能体协作 —— 总览

> 版本：v1.4（基线 main `8df9d9c`，v1.3.0 已封版；分支 `feature/v1.4-planning`）
> 日期：2026-10-11
> 主题：**把「一个助手一轮对话做不成、做不稳」的复杂任务，交给规划者→执行者→审查者的固定角色协作完成**
> 上一版方案：[v1.3 知识变厚](../v1.3/README.md)
> 选型结论：本版为 [00 主题提案](./00-主题选型提案.md) 候选 A（四选一拍板，2026-10-11）

---

## 1. 一句话方案

v1.3 让知识库「越用越准」；v1.4 让系统「会分工」。当前所有复杂任务都压在**单角色、单循环**上：普通对话走 chat-orchestrator 的单模型工具循环，桌面任务走 v0.7 的 task-loop（观察→规划→执行一体，且知识检索在其工具上下文中被硬编码为空）。面对「查资料→跨多个工具操作→产出需要校验」的任务，单角色既要分解又要执行还要自检，规划深度、执行专注度、产出校验互相挤占。v1.4 引入**三个固定角色**：Planner（分解与派单）、Executor（专注执行，复用 task-loop 与全部工具/知识）、Reviewer（对照目标验收，决定通过/返工/失败），角色间以**结构化 Handoff** 交接而非自由群聊；协作过程全程可观测、有预算硬上限、权限不放松。确定性多步流程仍归 Flow，v1.4 同时把整套协作内核注册为 Flow 的 **agent 节点**——确定性 DAG 与概率性子任务首次同图协作。

## 2. 目标与非目标

### 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 三角色协作内核 | Planner/Executor/Reviewer 状态机与 Handoff 契约为纯函数/可注入模型，协作循环 100% 单测覆盖（mock 角色）；轮次/步数/token 三重硬上限必达即停 |
| G2 | 执行能力打通 | Executor 可调全部工具域（知识检索修复 v0.7 硬编码空检索、内置工具/MCP/Flow）+ v1.3 编译知识；角色可独立绑定模型（规划/审查跟强模型、执行可本地） |
| G3 | agent 节点进 Flow | Flow 画布新增 `agent` 节点（目标/角色工具域/知识绑定/预算配置）；在确定性工作流中承担开放子任务，运行记录与普通节点同构展示 |
| G4 | 协作可观测 | 角色泳道时间线：每个角色的接收/产出/引用/工具调用按轮次可见；复用 task_steps/ToolTrace 落库与事件体系，无第二套轨迹模型 |
| G5 | 权限与预算安全 | 桌面控制类工具在协作链路默认逐次/会话确认，绝不因多一层 Agent 而自动提权；UI 可见每角色 token/步数消耗与熔断原因 |
| G6 | eval agent golden | 复用 eval 平台新增 agent 域 ≥15 个任务级用例（期望终态/关键交接/工具序列），含「去掉 Reviewer 质量下降」「关闭知识层执行退化」反向验证，三开关矩阵 CLI 化 |
| G7 | 零回归与显式入口 | 普通单助手对话路径行为零变化；协作仅经两个显式入口触发（对话「任务模式」、Flow agent 节点）；全门禁不降级、中英双语随版补齐 |

### 非目标（本版本明确不做）

- **不做自由 N 角色拼装/Agent 群聊**：首期固定 Planner/Executor/Reviewer 三角色与固定交接拓扑；自定义角色市场/角色分享留后续版本
- **不做并行多 Executor**：首期串行单执行（一次只派一个子任务），并行调度/任务依赖图留后续
- **不重造 Flow 能力**：分支/循环/人审节点/服务化（HTTP/MCP）/重放全部沿用，agent 节点只承担「开放概率性子任务」
- **不做云端多用户协作/Agent 之间的网络通信**：多角色是单机进程内协作，全部数据与密钥不出本机
- **不让协作默认接管普通问答**：无任务模式开关的普通聊天行为与 v1.3 完全一致
- **不承诺本地弱模型可独立完成规划/审查**：弱模型下给出明确降级提示（建议角色使用的模型档位），但不做自动模型采购或代理云端调用

## 3. 方案范围（六个里程碑）

| 阶段 | 主题 | 核心出口 |
|---|---|---|
| M0 | 契约与存储基座 | Handoff/角色/预算类型契约（shared）；v019 迁移（agent_runs/agent_handoffs）；协作事件并入 SSE 联合类型 |
| M1 | 三角色协作内核 | Planner/Reviewer 的 JSON 协议纯函数（build/parse/校验）、supervisor 协作状态机（分解→执行→审查→返工/交付）、三重预算与急停；mock 角色全单测 |
| M2 | Executor 能力贯通 | 修复 task-loop 知识检索硬编码空；执行器工具域/观察模式可配；角色级模型解析；真实知识+MCP+Flow 工具闭环 |
| M3 | Flow agent 节点 | agent 节点 handler/配置/画布表单/校验；agent 运行与 Flow node_executions/task_steps 双向关联；运行记录与重放兼容 |
| M4 | 入口、泳道 UI 与权限 | 对话「任务模式」显式入口；角色泳道时间线 + 返工交互；预算消耗面板；桌面工具 HITL 在协作链路收紧；i18n 双语 |
| M5 | eval、e2e 与封版 | agent golden ≥15 + 反向验证三开关；agent e2e（规划/返工/急停/预算熔断/Flow 节点）；全门禁回归；版本号 1.4.0 |

## 4. 关键设计决策

1. **固定三角色 + 结构化交接，不做 Agent 群聊。** 角色拓扑与交接协议是代码里的显式状态机，Planner 只产出结构化子任务单、Reviewer 只产出结构化裁决，角色之间不传自由对话——通信开销、token 成本与「群聊跑偏」都因此可控可测。
2. **确定性归 Flow、概率性归 Agent，二者以节点组合。** Flow 回答「步骤已知」的流程，Agent 回答「要边做边看」的子任务；agent 节点是 Flow 图中的一个 handler，不另起编排引擎。长期形态：Flow 当骨架、Agent 当弹性器官。
3. **Executor 复用并泛化 task-loop，不写第二套执行循环。** v0.7 的观察→决策→门控→执行→落库循环、熔断与急停句柄直接沿用；泛化点是把「每轮截图观察」抽象为可配观察模式（屏幕观察 / 知识与工具结果观察），并修复工具上下文知识检索被硬编码为空的断点。
4. **Handoff 是一等数据，全程落库。** 每次角色交接（目标、上下文摘要、产出、引用证据、消耗、状态）写 agent_handoffs；协作的可解释性、重放、eval 断言都以交接记录为锚，不靠解析对话文本。
5. **预算三重硬上限默认保守。** 协作轮次（规划-执行-审查，默认 3 轮）、单角色步数（沿用 task-loop max_steps）、总 token 预算（默认值与可配置上限）任一触顶即停并产出「预算内最佳结果 + 未完成项」，禁止无限返工。
6. **多一层 Agent 不多一分权限。** 权限门控以最终执行的工具调用为单位，桌面控制在协作链路默认 HITL；v0.9 无人值守策略只对已发布 Flow 的 API/MCP 调用按原策略生效，任务模式交互会话不享受静默放行。
7. **角色模型显式选择，质量档位透明。** 每个角色可绑独立模型（助手级配置 + agent 节点级覆盖）；规划/审查默认跟随默认聊天模型，执行可降本地模型；启动协作前对「角色模型过弱」给出一次性提示而非拦截。
