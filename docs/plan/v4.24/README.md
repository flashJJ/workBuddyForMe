# v4.24 选题：会守时

> 状态：M0 契约冻结中（2026-11-23）
> 主题：**会守时**——Flow 定时触发、持久化调度、错过补偿与单飞保护
> 规格：[spec.md](./spec.md) · 契约：[contracts.md](./contracts.md) · 任务：[tasks.md](./tasks.md)
> 原则：默认关闭；每流程最多一个定时；系统本地时区；错过只补一次

## 1. 一句话

v4.23 让流程摔了能爬起来，v4.24 让它**自己知道什么时候该开始**：按 cron 定时触发，调度落库、重启不丢、错过补一次、上一个还没跑完就跳过。

## 2. 为什么是现在

到 v4.23 为止，流程只有三种开始方式：手动试运行、对话里作为工具调用、HTTP/MCP 端点被调用。它们都要求「有人或外部系统先发起」。

本地私人助手最典型的需求恰恰相反：每天早上整理资讯、每周五生成周报、每小时检查一次目录。没有定时触发，这些只能靠用户记得点一下。

调度看起来只是「定时创建运行」，但真正难的是进程生命周期：

- 应用关着的时候，定时点错过了怎么办；
- 重启后调度要不要继续；
- 上一次运行还没结束，下一次又到了怎么办；
- 调度配置放内存还是放库。

v4.23 的恢复与幂等经验正好可以复用。

## 3. 借鉴与差异

| 借鉴点 | 来源 | 本版落地方式 |
|---|---|---|
| 定时触发节点 | n8n Schedule Trigger | 每个流程一个 cron 配置，系统本地时区 |
| 调度持久化 | n8n 数据库调度队列 | `workflow_schedules` 表 + 原子认领 |
| 重启不丢任务 | Temporal / n8n | 启动首轮扫描立即处理到期项 |
| 单飞保护 | 定时任务通用实践 | 同一流程有在途运行时跳过并记录原因 |

不做：webhook、文件监听、多定时、每定时独立时区、错过多轮补齐、分布式调度。

## 4. 范围

### 做

- 5 字段 cron 解析与下次时间计算（纯函数、可单测）；
- `workflow_schedules` 表与仓储（迁移 v054，纯加法）；
- 流程定时服务：查询 / 保存 / 删除 / 立即运行；
- 进程内调度器：30 秒 tick、原子认领、到期创建运行；
- 单飞保护与错过只补一次；
- 调度状态观测：下次时间、上次时间、上次结果；
- 编辑器定时对话框（最小 UI）。

### 不做

- webhook / 文件监听 / 事件触发；
- 一个流程多个定时；
- 每定时独立时区（统一系统本地时区）；
- 错过多次的逐次补齐；
- 分布式或多实例互斥。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 重启后重复触发 | 原子认领（按旧 next_run_at 做条件更新），同一时刻只有一个 tick 能推进 |
| 错过大量执行 | 只补一次：下次时间从当前时刻重新计算 |
| 上一个运行未结束 | 单飞保护：跳过本次并记录 `skipped_busy` |
| cron 写错导致永不触发 | 保存时解析校验，并回显下次时间 |
| 时区歧义 | 统一使用系统本地时区，不提供每定时时区 |
| 无人值守写操作 | 沿用现有门控：定时触发视为非交互，写/危险工具默认拒绝 |

## 7. 验收

1. cron 解析覆盖 `* / 列表 / 范围 / 步长` 与 dom/dow 组合；
2. 到期调度在 tick 后创建 `trigger=schedule` 的运行；
3. 重启后到期项补跑一次，不重复；
4. 同流程在途运行时跳过并记录原因；
5. 禁用定时后不再触发；
6. 未配置定时的流程行为与 v4.23 一致；
7. `pnpm check` 与 `pnpm verify:local` 全绿。
