# v2.21 方案：会并行——自由分支会话与回传

> 状态：M0–M4 全部完成，v2.21.0 已发布并置 Latest（2026-11-04，tag `v2.21.0`；Release <https://github.com/flashJJ/workBuddyForMe/releases/tag/v2.21.0>）
> 决策：[01-M0 决策记录](01-M0-决策记录.md) · 契约草案：[02-M0 契约冻结](02-M0-契约冻结.md)
> 前置版本：v2.20（过程图 + 阶段化会话）
> 主题一句话：**让一个助手能把任务拆成多条真实会话并行推进，并把结果可靠地汇回父会话。**
> 来源方案：[v2.21-01 自由分支会话与回传](../../roadmap/scheduled/v2.21-01-free-branch-sessions.md)
> 来源分析：[v2.20-01 Lancer 借鉴分析](../../roadmap/scheduled/v2.20-01-lancer-borrowing-analysis.md) §5.3

## 1. 为什么是「会并行」

v2.20 解决单会话的过程可见与阶段推进，但长任务仍只能串行：

1. v1.4 协作是固定 Planner/Executor/Reviewer，不是用户可自由派生的分支；
2. v2.8 工作计划是单会话内的目标/待办，不产生独立上下文与独立交付；
3. 子代理运行有独立 run，但不是可继续对话、归档、回传的会话；
4. 父会话等待子任务时不能继续处理其他分支；
5. 多分支结果缺少统一的回传证据与预算控制。

v2.21 只做「用户自由派生会话 + 回传 + 上限」，不搬 Lancer 的 Pi 会话树与 worktree。

## 2. 目标与成功指标

| 指标 | 现状（v2.20） | v2.21 目标 |
|---|---|---|
| 并行推进 | 单会话串行 | 父会话可派生多条子会话；并行/串行由用户决定 |
| 独立上下文 | 子代理 run 不独立 | 子会话独立消息、模型、阶段计划与产物 |
| 结果汇总 | 手工复制 | 子会话完成/失败生成结构化 evidence；父会话核对后汇总 |
| 预算控制 | 单运行预算 | 会话树 Token + 并发/深度/子节点四项上限 |
| 可回看 | 单会话图 | RunGraph 增加分支车道与父/子/回传节点 |
| 数据兼容 | schema v44 | 一次 `v045`；旧库/旧备份可恢复 |

## 3. 功能清单

### 3.1 P0（本版必须）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P0-1 | 父子会话 | 从当前会话/消息派生自由分支会话 | 子会话有独立上下文、消息、模型与产物；父会话主线保留 |
| P0-2 | 分支回传 | 子会话完成后父会话收到结构化回传 | evidence 含父/子 id、状态、摘要、产物；父会话先核对再汇总 |
| P0-3 | 准入与上限 | 防止分支爆炸与预算失控 | 并发/深度/子节点/Token 四项上限；祖先环检测；先预留再 await |
| P0-4 | 图车道 | 在 RunGraph 看到分支与回传 | 分支车道、父/子节点、回传节点；可聚焦/折叠 |

### 3.2 P1（本版锁定）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P1-1 | 分支管理 | 查看/重命名/归档/恢复分支 | 运行中禁止删除；删除先停止；归档保留历史 |
| P1-2 | 失败隔离 | 一个分支失败不影响其他分支 | 失败只标记当前分支；父转录不被污染；可单独重试 |
| P1-3 | 预算视图 | 查看会话树 Token 使用 | 按会话树聚合；触顶拒绝新派生并说明原因 |

## 6. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 与 v1.4/v2.8 重叠 | 概念混淆、重复实现 | 定位为「用户自由派生会话」；不复用三角色调度；文档明确边界 |
| 预算失控 | Token/并发爆炸 | 四项上限 + 会话树预算 + 环检测 + 预留 |
| 分支爆炸 | 图不可读、上下文串味 | 深度/子节点上限；默认聚焦当前分支；折叠与「全部分支」视图 |
| 删除/归档丢历史 | 用户数据损失 | 运行中禁止删除；删除前先停止；归档保留历史 |
| 回传污染父会话 | 父会话被错误结论带偏 | evidence 标明「需核对」；父会话先核对再汇总；不自动重试/派生 |

## 7. Non-Goals

- 不做 Git worktree/checkpoint/review；
- 不做 Pi 会话树/Chord/扩展视图宿主；
- 不做自动无限递归派生；
- 不做团队共享、云同步、远程分支；
- 不替代 v1.4 固定三角色协作与 v2.8 工作计划。

## 8. M0 决策结果

1. 状态机：`queued / running / waiting / succeeded / failed / cancelled / interrupted / budget_exceeded` 八态。
2. 四项上限：并发 3、深度 2、每父 6、会话树 200k Token；设置页高级区可调。
3. 派生入口：消息右键 + 命令面板 + REST API；父会话回传以 evidence 卡片展示，先核对再汇总。
4. 删除/归档：归档优先；运行中禁止删除；删除先停止，删除关联后子会话保留为普通会话。
5. 能力边界：独立新能力，不复用三角色调度与工作计划，只复用子代理 run 执行器、预算与 evidence 语义。

完整决策见 [01-M0 决策记录](01-M0-决策记录.md)；契约细化项见该文档 §5。
