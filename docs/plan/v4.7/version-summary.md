# v4.7 版本总结：任务模式有上下文、能续跑

> 版本：4.7.0（2026-11）
> 主题：任务上下文注入、步骤压缩、检查点续跑、计划确认与完整回投
> 分支：`feat/v4.7-agent-task`
> 迁移：新增 `task_run_checkpoints`（纯加法）；备份 schema 不变。
> 博客：[blog/v4.7](../../blog/v4.7/) 7 篇。

## 1. 本版解决什么

v4.6 之前，任务模式已经能跑 Planner → Executor → Reviewer 三角色协作，但更像一次性的批处理：

1. Planner 只拿 `goal`，不知道当前会话在聊什么；
2. Executor 只拿子任务标题与 goal，同样缺少会话背景；
3. 步骤历史固定截取最近 12 条，早期证据直接丢失；
4. 应用重启后运行中的任务统一落为 `cancelled(INTERRUPTED)`；
5. 结果回投只有一行摘要，正文、证据与失败原因都留在运行记录里；
6. 计划不能确认，人工介入只有工具授权一个入口。

v4.7 按「先补上下文，再让长任务可压缩，最后补续跑与干预」的顺序收口。

## 2. 里程碑结果

| 阶段 | 结果 |

| P0 上下文注入 | Planner / Executor 注入会话摘要、结构化事实、当前计划、近期 6 条对话与相关长期记忆；预算按窗口收敛 |
| P0 结果回投 | 协作回投正文 + 证据名 + 未竟事项；单 Agent 任务回投最终步骤正文 |

| P1 计划确认 | Planner 产出后、执行前下发 `agent_plan_preview`；复杂任务默认先确认 |
| P2 任务记忆 | 终态异步沉淀为助手作用域事件记忆，成功 0.55 / 失败 0.4 |
| P2 观测 | handoff payload 增加 per-role token usage；前端交接时间线展示 |

## 3. 关键设计

### 3.1 上下文按「密度」排序，而不是按时间

任务上下文块固定顺序：

1. 会话递归摘要；
2. 结构化事实 / 检查点；
3. 当前计划与待办；
4. 近期 6 条对话原文；
5. 与 goal 相关的长期记忆。

预算独立于子任务单与工具目录；超限时从尾部（记忆 → 近期对话）开始截断，保证摘要与事实优先保留。

### 3.2 两套预算都按模型窗口收敛

- 任务上下文：`clamp(窗口 × 15%, 320, 2000)`；
- 步骤历史：`clamp(窗口 × 12%, 320, 1200)`。

4096 窗口下分别是 614 / 491，32768 以上取上限 2000 / 1200；窗口未知时才回退 8192 兜底。

### 3.3 步骤压缩不调用模型

Condenser 用确定性规则：保留首 2 步与最近 8 步，中段合并为「省略 N 步」的摘要行，并保留数字、URL、文件路径与 id 的线索。原文仍在 `task_steps`，可回溯。

这样做的原因是任务步骤本身已经很结构化，再调一次模型摘要既增加成本，也引入失败路径；把模型摘要留给 v4.9 的统一压缩器。

### 3.4 检查点只记录「可恢复位置」

`task_run_checkpoints` 按轮/步 upsert，保存预算余量、待确认门与幂等键线索；终态 seal 为不可续跑。

续跑不是步骤级重放，而是「带着检查点上下文重新规划」：新建 run、记录 `resumed_from_run_id` 与剩余预算，已完成的步骤由模型按上下文跳过。写操作仍走工具授权与幂等保护。

### 3.5 计划确认只做只读预览

首轮 Planner 产出后，如果任务涉及 desktop 工具、验收标准 ≥3 条或说明 ≥400 字，就先下发 `agent_plan_preview`，由用户批准或拒绝。Flow 节点强制跳过，避免无人值守流程被卡住。

第一版不做可编辑计划，先验证交互成本；计划版本与返工一致性留到后续。

## 4. 数据与验证

- 门禁：`pnpm typecheck`、`pnpm check:lines`、`pnpm check:ascii` 通过。
- 定向测试：core 24 项、web 11 项通过。
- 新增表：`task_run_checkpoints`；`agent_handoffs.payload` 增量增加可选 `usage`，无需迁移。
- 任务用户消息写入 `messages` 表，导出、分享、摘要链路自动生效。

## 5. 已知限制

- 不做并行 / DAG：预算共享、幂等键与审查合并三个问题尚未回答。
- 上下文快照与压缩事件回放延后到 v4.9，避免先造一套快照结构再迁移。
- 续跑是「重新规划」而不是步骤级重放；已完成步骤依赖模型按上下文跳过。
- 计划确认只读，不支持编辑验收标准或增删子任务。
- 任务记忆重要度低于普通对话事实，避免任务流水淹没长期记忆。

## 6. 下一步

v4.8 把同一套「预算 + 压缩 + 事件」策略应用到对话侧：意图路由、按意图分配上下文、压缩事件化与预判、记忆一等意图。v4.9 再把两套装配收敛为统一的场景策略与快照。
