## 1. 本里程碑做了什么

| 类型 | 内容 |
|---|---|
| 数据 schema | `diagramInputSchema`：10 类结构化输入，边/关系/泳道引用校验，数据图有限数值 |
| 渲染器 | `renderDiagram` 结构化数据 → 自包含 HTML + inline SVG；不依赖图表库 |
| 模板 | 架构 / 流程 / 时序 / 状态机 / ER / 时间线 / 四象限 / 泳道 / 柱状图 / 折线图 |
| 工具 | `diagram_render`（`write`）：渲染后直接经 `ctx.writeArtifact` 落盘，返回产物卡片 |
| 技能 | 内置 `diagram-design`：类型选择、数据整理、设计规范、anti-pattern、MIT 归因 |
| 门禁 | `pnpm check` 通过；M2 定向单测 20 例 |

## 2. 关键口径

- **模型不手写 SVG**：只提供 `type/title/size/data`；布局、坐标轴、箭头、配色由模板生成。
- **直接落盘**：`diagram_render` 为 `write`，渲染后立即调用产物服务；避免把大段 HTML/SVG 回灌模型上下文。这是对决策记录「read」的偏差（见 §4）。
- **数据校验**：节点/边引用必须存在；泳道步骤必须属于已声明泳道；折线序列长度必须等于标签数；柱/折线数值必须有限。
- **自包含产物**：内联 SVG + 系统字体栈，不依赖外链字体/图片/脚本；可直接被 M1 卡片预览/下载。
- **归因**：技能与模板保留 Diagram Design（MIT，v2.6）来源说明；未复制 45 类 references。

## 4. 契约偏差

| # | 事项 | 说明 |
|---|---|---|
| 1 | `diagram_render` 由 read 改为 write | 渲染后直接落盘，避免 SVG/HTML 回灌模型；权限门仍会 HITL，产物卡片照常展示 |
| 2 | 10 类布局为简化版 | 网格/坐标轴布局，不做 45 类全量语法；复杂图建议拆图 |
| 3 | 内置技能不携带 references | 技能只含 2 段提示词；全量类型参考与模板扩展放 P2 |
| 4 | 架构图未画分组容器 | `group` 仅作为节点副标题展示；分组框留后续 |
| 5 | 数据图只支持单轴/单系列/多系列折线 | 不做堆叠、双轴、气泡等扩展 |

## 5. 已知边界

- 10 类之外的图表明确不支持；建议表格/文字或后续版本。
- 节点/标签会截断，超长说明应放图外正文。
- PNG/SVG 导出在 M3；M2 只产出 HTML（内联 SVG）。
- 产物卡片在 tool-trace 内，不是独立消息气泡。
- 单轮产物数量限制仍未运行时计数。
