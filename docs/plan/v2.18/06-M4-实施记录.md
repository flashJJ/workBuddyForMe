## 2. 内容包契约（M4 补充冻结）

| 项 | 约定 |
|---|---|
| 内容包 id | `how-to-live-better` |
| 上游与版本 | `eternity4719/HowToLiveBetter`，固定 commit `e2605d3e2242bd6216c9255192b8a8957a08c55a`（2026-10-21） |
| 正文来源 | `book/01-*.md` … `book/34-*.md` 共 34 个 raw 文件，按 01–34 顺序拼接计算整包哈希 |
| 整包 SHA-256 | `7095f7cb286a8ef634750251ef47db7c8de98ce4d5b22a36878ceab619ffff46` |
| 总字节 | 2,385,074（约 2.3 MB） |
| 许可 | CC BY 4.0（<https://creativecommons.org/licenses/by/4.0/>） |
| 目标知识库 | 固定 id `c0000000-0000-4000-8000-000000000004`；存在即视为已导入 |
| 入库形态 | 34 个原文 Markdown + 1 个自动生成的「署名与免责声明」文档；分块 600 / 重叠 80 |
| 失败口径 | 下载失败、单文件大小/哈希不一致、整包哈希不一致 → 抛错且不创建知识库 |
| 零迁移 | 不新增表/列；版本与哈希写入知识库描述和署名文档 |

导入流程：

1. 用户点击“导入内容包”，确认框展示来源、许可、文件数与体积；
2. 服务端按 4 并发分批下载 34 个固定 URL，逐文件校验字节数与 SHA-256；
3. 拼接后校验整包 SHA-256；
4. 校验通过后创建固定 id 知识库，登记署名页与 34 篇文档（pending）；
5. 返回知识库引用；服务端后台按顺序摄入（分片、向量、FTS、自动编译），客户端复用文档状态轮询。

## 3. 署名与高风险边界

- 署名页包含：来源链接、作者/贡献者、CC BY 4.0 许可链接、固定版本/日期、整包哈希、导入日期、“未修改原文”的说明。
- 回答要求引用「第 N 节第 M 条」；技能明确“没查到就说没查到”，不凭记忆补数字/法条。
- 急症（胸痛、呼吸困难、大出血、昏迷、中毒、自杀念头）先给 120 / 110 / 12356；进行中的法律程序先找律师/当地部门。
- 不提供个性化医疗诊断、法律意见或投资建议；政策以当地部门为准。

## 5. 契约偏差与已知边界

| # | 事项 | 说明 |
|---|---|---|
| 1 | 使用 34 个固定 commit 的 Markdown，而非 rolling release 单文件 HTML | `epub-latest` 资产会滚动更新且 ingestion 不支持 HTML；固定 commit 的 MD 可逐文件校验且不可变 |
| 2 | 未实现“检查更新”按钮 | 首版先固定版本；已导入状态按固定知识库 id 判定。更新策略（比对整包哈希、提示重新导入）留后续版本 |
| 3 | 元数据不落新表 | 零迁移约束下，版本/哈希写入 KB 描述与署名文档 |
| 4 | 后台摄入无聚合进度 | 34 篇逐个摄入，沿用现有文档状态轮询；单篇失败不影响其他文档 |
| 5 | 内容包名/描述固定中文 | 内容本身为中文；英文 UI 下仍显示原始书名与简介 |
