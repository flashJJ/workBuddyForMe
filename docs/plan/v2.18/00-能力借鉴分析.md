## 2. Diagram Design（最值得直接移植）

> 上游：[cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design) · 源码入口：[skills/diagram-design/SKILL.md](https://github.com/cathrynlavery/diagram-design/blob/main/skills/diagram-design/SKILL.md)

### 2.1 事实

- 入口是 `skills/diagram-design/SKILL.md`，元数据写明 `license: MIT`、`version: 2.6`，支持 45 种图表。
- 选择逻辑是「先语义模式，后视觉类型」：先判断要表达的行为（fan-in、状态机、信任边界、阶段框架等），再映射到最近图表类型；绘制前先确认类型、尺寸与复杂度预算。
- 设计规范强调「删减优先」、每图 1–2 个焦点色、4/10 密度、超过 9 个节点应拆图；并有一组明确的 anti-pattern（暗色+青紫光、等宽字体滥用、同尺寸卡片等）。
- 输出协议：**永远先生成自包含 HTML**，SVG / PNG 从 HTML 导出；HTML 内含 inline SVG、页眉、摘要卡、页脚与字体设置。
- 导出脚本：`scripts/export_svg.py` 零第三方依赖，修复 class/defs/HTML-only 属性；`scripts/export_png.py` 用 Playwright Chromium 打开 HTML、等待字体与网络、按 viewBox 截图。
- 风险点：默认依赖 Google Fonts；中文字体与离线环境需要替换为系统字体栈。

### 2.2 对我们意味着什么

我们的技能 manifest 只支持 `promptTemplates`（最多 10 段、每段 4000 字）与 `allowedTools`，**不能携带多文件 references/assets**；聊天侧也没有「把模型生成的 HTML 存成文件」的工具。因此不能原样把 45 个 reference 塞进能力包。

最小可行路径：

1. 新增**产物文件工具**（`artifact_write` 或 `create_artifact`）：把 HTML/SVG 文本写入数据根 `artifacts/`，登记附件，返回预览/下载地址；限制体积、扩展名与单轮次数。
2. 内置**图表技能**：把选择树、设计规范、anti-pattern、输出协议压缩成 1–2 段提示词，先覆盖 8–10 个高频类型（架构、流程、时序、状态机、ER、时间线、四象限、柱/折线）。
3. HTML 由模型生成、产物工具落盘；PNG/SVG 导出放 P1，桌面端用 Electron 离屏渲染，Web 端可先只提供 HTML/SVG。

### 2.3 落地边界

- HTML 属于**不可信内容**：预览必须独立路由 + CSP + sandbox iframe，禁止同源 Cookie、默认禁脚本与外链字体；静态图表优先。
- 保留 MIT 版权与许可声明，新增 `THIRD_PARTY_NOTICES.md`；技能元数据标注来源与版本。
- 45 类全量模板是 P1/P2，不在 P0 承诺。

## 3. HowToLiveBetter（内容 + 决策技能）

> 上游：[eternity4719/HowToLiveBetter](https://github.com/eternity4719/HowToLiveBetter) · 技能：[skills/life-decision-guide/SKILL.md](https://github.com/eternity4719/HowToLiveBetter/blob/main/skills/life-decision-guide/SKILL.md)

### 3.1 事实

- 767 条建议、34 节，覆盖健康、法律、财务、安全、租房、育儿等；许可为 CC BY 4.0。
- 每个条目固定字段：成本、说人话、收益、证据等级 A/B/C、来源、备注；另有一行 HTML 注释存机器可读的成本标签（钱/时间/毅力/收益/口径/人群）。
- 仓库自带 `skills/life-decision-guide/SKILL.md`：先定位章节与条目，再按成本、收益量级、证据等级排序；**没查到就别答**，每个数字/法条必须能指回正文，不凭记忆补数字。
- 技能还定义了急症、自杀念头、进行中的法律程序三类「先停下」的分流，以及「不替代医生/律师/会计」的边界。
- 内容以 Markdown 为源，自动生成 EPUB/PDF/离线 HTML/Anki；在线检索页是纯静态。

### 3.2 对我们意味着什么

我们的知识库模板目前只播种名称/描述/分块参数，不带样本文档；但 ingestion 已支持 HTML/PDF/Office。可以把这本书做成**可选内容包**：

- 内置「生活决策」知识库模板（空库，固定 id）；
- 用户显式点击「导入示例内容」后，从**固定的 release 地址**下载单文件 HTML/PDF，校验 SHA-256，再走既有 ingestion；
- 同时内置一个精简版决策技能（把「查了再答、引用节/条、证据分级、四类资源分开算、三类急停」压进 1–2 段提示词）；
- 作品页/回答中展示 CC BY 4.0 署名、来源链接与「内容可能过时，以医生/律师/当地部门为准」。

### 3.3 风险

- 医疗、法律、财务属高风险内容：只做「按书检索并引用」，不做个性化诊断/投资建议；急症与法律程序必须先给紧急处置。
- CC BY 4.0 要求署名、注明是否修改、保留许可链接；若与 GPL-3.0 主仓一起分发，需在 M0 做法务口径复核。
- 内容会过时：必须记录导入版本/日期/哈希，提供「检查更新」，不静默覆盖用户笔记。

## 4. REA（只借思路，不做逆向产品）

> 上游：[morluto/rea](https://github.com/morluto/rea) · 工具设计：[docs/tool-design.md](https://github.com/morluto/rea/blob/main/docs/tool-design.md) · 能力组合：[docs/capability-composition.md](https://github.com/morluto/rea/blob/main/docs/capability-composition.md)

### 4.1 事实

- MIT，TypeScript，核心是本地 MCP server + workflow instructions，覆盖原生二进制、JavaScript/Electron、.NET、网站。
- 工具体系按「分析问题形状」设计：`inspect / search / trace / compare / workflow / observe`；强调 primitive 可复用、workflow 负责组合、不要把发现/执行/修改塞进一个工具。
- 能力组合把「静态声明」与「运行时绑定」分开：capability declarations、services、availability probes、资源生命周期与清理都有明确所有权。
- 每个结论要求 **Evidence provenance / coverage / unknowns**；还能把 HAR/网络证据构建成可运行的 agent environment bundle。

### 4.2 对我们意味着什么

不建议把逆向工程作为产品功能：涉及未授权目标、原生工具依赖（Hopper/Ghidra/IDA）、双用途与合规风险，且与当前「个人 AI 平台」主线不匹配。

值得借的是**证据契约**：

- 给 `ToolResult` 增加可选 `evidence` 元数据：来源类型、覆盖范围、限制/未知项、时间戳；
- 在 tool-trace / 报告 / 分享导出中展示「这条结论来自哪里、没覆盖什么」；
- 先用于 `web_search` / `fetch_webpage` / `knowledge_search`，再推广到 flow/agent。

这会直接提升 v2.18 产物的可信度，且不需要引入任何逆向工具。

## 5. Moli（只借抓取形态，不引入 Rust sidecar）

> 上游：[lexmount/moli](https://github.com/lexmount/moli) · 抓取技能：[skills/moli-webfetch/SKILL.md](https://github.com/lexmount/moli/blob/main/skills/moli-webfetch/SKILL.md)

### 5.1 事实

- Apache-2.0（Cargo 双许可 MIT OR Apache-2.0），Rust，完整无头浏览器；支持 CLI、CDP、WebDriver Classic、WebDriver BiDi。
- 核心差异是 **structure-first**：读取 DOM/样式/网络时不触发布局与绘制；只有截图、坐标点击等才按需 layout/paint，并在用完后丢弃绘制状态。
- `moli fetch` 直接输出 Markdown、JSON、semantic tree text、HTML、截图、整页截图、PDF；技能层规定了何时用哪种输出、何时等 networkidle/domstable/selector。
- 自带 `moli-webfetch` / `moli-websearch` / `moli-cdp-server` 三个技能。

### 5.2 对我们意味着什么

我们的 `browser_*` 工具是 Electron 桌面通道，按 `runId` 隔离，已有 URL/SSRF/域名门控；再引入一个 Rust 浏览器 sidecar 会增加跨平台二进制、签名、杀软与生命周期成本，本版不值得。

可借的是**输出形态与等待策略**：

- `fetch_webpage` 增加 `format: text | markdown | json`，JSON 带 final_url/status/title/redirects；
- `browser_read` 增加「语义树」模式，供导航密集页面使用；
- 把「何时需要截图/布局」写成工具选择规则，避免每次抓取都渲染。

这些是 P2 的渐进改进，不改变现有浏览器架构。

## 6. ArtCraft（本版不移植）

> 上游：[storytold/artcraft](https://github.com/storytold/artcraft) · Omni API：[artcraft_omni_api.md](https://github.com/storytold/artcraft/blob/main/_docs/artcraft_omni_api.md)

### 6.1 事实

- Apache-2.0，Rust workspace：`artcraft-native`（egui）、`crates/desktop/artcraft`（Tauri）、前端 Web/Wasm；定位「AI 图像/视频创作 IDE」。
- 能力面很大：2D/3D 合成、角色姿态、镜头、图生视频、背景移除、62 个图像/视频/音乐/3D 模型目录，依赖多家外部服务。
- 有 Omni API：`POST /v1/omni_api/generate/video`，请求含 model/prompt/duration/aspect_ratio/idempotency_token，返回 job token 轮询。

### 6.2 结论

不移植。原因：

1. 我们没有图像/视频生成管线与供应商账号体系，接入 62 个模型是另一个版本级工程；
2. Rust + Tauri + egui + Wasm 技术栈与现有 Next.js/Electron 主链路重叠且包体大；
3. 2D/3D 场景合成与现有 Live2D/VRM 舞台是不同问题，不能直接复用。

仅保留一条远期候选：若未来做「生成式创作」，可参考其 Omni API 的幂等 token + 异步 job 形状；本版不立项。

## 8. 证据与边界

- 本次只阅读上游文档、技能与脚本，未运行上游项目；性能、稳定性与真实生成质量未验证。
- 仓库可能继续变化，实施时应锁定 commit/tag 并记录版本。

- 不把「star 数」当质量证据；本分析只看可复用契约、许可证与与现有架构的贴合度。
