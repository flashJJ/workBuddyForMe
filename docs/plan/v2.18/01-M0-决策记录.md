## 1. 已冻结的决策

| # | 决策 | 选择 | 影响 |
|---|---|---|---|
| D1 | 本版范围 | **P0 + P1 全部锁定** | 图表、产物、内容包、证据元数据、SVG/PNG 都作为 v2.18 承诺；P2 仍不做 |
| D2 | 图表类型 | **结构 + 数据共 10 类**：架构、流程、时序、状态机、ER、时间线、四象限、泳道、柱状图、折线图 | 数据图需要数值校验与坐标轴/标签规则 |
| D3 | 图表生成方式 | **结构化模板渲染 + 技能选择**：模型选类型并给结构化数据，服务端 `diagram_render` 生成 HTML/SVG；`artifact_write` 只落盘通用 HTML/SVG | 质量与数据校验可控；比纯提示词生成多一套模板引擎 |
| D4 | 产物存储 | **复用 attachments 表 + 专用预览路由** | 扩展 MIME/扩展名映射与服务层保存能力；不改表结构 |
| D5 | PNG 导出 | **Web + 桌面 P0，预览页客户端导出** | 仅对图表产物的内联 SVG 做 SVG→Canvas→PNG；不引入服务端 Chromium/resvg 依赖 |
| D6 | 内容包 | **运行时可选下载**：用户确认后从固定版本 URL 下载，校验 SHA-256 再导入；不随包内置全文 | 降低包体与 GPL/CC BY 分发风险；需要固定 URL 与内容更新策略 |
| D7 | 内容包入口 | **知识库模板页** | 与知识库绑定/检索链路一致；不混入能力包安装语义 |
| D8 | 证据元数据 | **只做 UI / 导出展示，不进模型上下文**；先覆盖 `web_search` / `fetch_webpage` / `knowledge_search` | 避免上下文膨胀；tool-trace 与报告展示来源/覆盖/限制 |
| D9 | 迁移 | **目标零迁移**；复用 attachments / knowledge / documents | 若实现中发现必须新增表/列，暂停并重新决策 |

## 2. 由决策派生的实现口径

### 2.1 产物文件

- 新工具 `artifact_write`：`write` + HITL；参数 `title`、`filename`、`format: html|svg|md`、`content`；单文件 2 MB、单轮 3 个。
- 复用 `attachments` 表：扩展 `attachmentStorageName` 的 MIME→扩展名映射（`text/html`、`image/svg+xml`、`text/markdown`），新增服务层 `saveArtifact`（不走图片校验）。
- 预览：`/api/artifacts/[id]` 独立路由，`Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:`；禁脚本、外链与同源 Cookie。
- 对话卡片：消息内展示标题/格式/大小/打开/下载；刷新后从附件记录恢复。

### 2.2 图表

- 新工具 `diagram_render`：`read`（只生成内容，不写盘）；输入 `type`、`title`、`data`、`size?`；输出 HTML（自包含 inline SVG）。
- 10 类模板：架构 / 流程 / 时序 / 状态机 / ER / 时间线 / 四象限 / 泳道 / 柱状图 / 折线图。
- 内置技能 `diagram-design`：只负责类型选择、数据整理与设计规范（精简自 MIT 上游），不负责 45 类全量 references。
- 数据图要求：数值必须为有限数字；缺值/负值/空序列返回可执行错误；坐标轴与标签由模板生成，不让模型手写 SVG。
- 设计规范：每图 1–2 个焦点色、密度 4/10、超过 9 节点提示拆图、禁暗色青紫光/无意义等宽字体/阴影。
- SVG/PNG：`diagram_render` 同时返回序列化 SVG；预览页可下载 SVG；PNG 由预览页把内联 SVG 绘到 Canvas 导出，Web/桌面同一套。通用 HTML 产物只支持预览/下载，不承诺 PNG。

### 2.3 内容包

- 内容包声明固定字段：id、名称、来源 URL、许可证、版本/日期、SHA-256、目标知识库固定 id、免责声明。
- 只允许白名单 URL；下载前展示体积与来源；校验哈希失败不建库、不落半成品。
- 首版内容：HowToLiveBetter 单文件 HTML（或固定 release 资产），CC BY 4.0 署名页 + 回答引用「第 N 节第 M 条」。
- 更新：记录导入版本/哈希；提供「检查更新」，不静默覆盖用户笔记。
- 高风险边界：急症/自杀念头/进行中的法律程序先分流；不替代医生/律师/会计；不提供个性化投资建议。

### 2.4 证据元数据

- `ToolResult.evidence?: { source: string; coverage?: string; limitations?: string[]; capturedAt?: string }`。
- 填充：`web_search`（provider/结果数/未覆盖）、`fetch_webpage`（final URL/状态/正文截断）、`knowledge_search`（库/命中数/空结果）。
- 展示：tool-trace 折叠区 + 报告/分享导出；不进模型消息。
- 失败/空结果也要标明「未覆盖」，不伪装成成功。

## 3. 仍需在 M0 契约中落盘的细节

1. `artifact_write` / `diagram_render` 的完整 JSON Schema 与错误码。
2. 10 类图表的结构化数据 schema（节点/边/序列/数值表）与尺寸预设。
3. 预览路由的 CSP、缓存头、下载文件名与清理策略。
4. 内容包固定 URL/版本/哈希、导入后的知识库/文档元数据映射。
5. 证据字段在各工具的具体填充文案与 UI 文案。
6. 验收用例：图表 10 类各 1 例、产物预览/下载、PNG 导出、内容包哈希失败、证据展示。

## 4. 明确不做

- 不做 REA 逆向工程产品、Moli Rust sidecar、ArtCraft 创作套件。
- 不做全量 45 类图表 references、远程能力市场、任意 URL 内容包、静默下载、任意 HTML 脚本执行。
- 不做服务端 Chromium/resvg PNG 依赖；不做同轮工具热替换。
- 不为内容包新增数据库表；如必须新增，回到决策。
