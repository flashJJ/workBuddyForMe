# v4.15 版本总结：动作契约收口、桌宠发起聊天与视觉巡检

> 版本：4.15.0（2026-11-20 发布，tag `v4.15.0`）
> 主题：删掉不可达动作、让桌宠递一句话、给稳定界面加截图基线
> 迁移：无数据库迁移；备份格式不变
> 博客：[blog/v4.15](../../blog/v4.15/) 7 篇
> 发行说明：[v4.15.0-release-notes.md](../../roadmap/v4.15.0-release-notes.md)

## 1. 本版解决什么

v4.14 的选型留下三件事，v4.15 按 P0/P1/P2 收口：

1. 动作类型里存在两个永远无法被触发的变体，执行器还因此把字幕动作一并跳过；
2. 桌宠只能被动响应，无法主动把一句想说的话递到主窗；
3. 视觉回归没有基线，界面改动只能靠人工看。

三件事的共同点是「边界」：动作契约要能证明可达，跨进程通信要限制载荷，截图只覆盖稳定面。

## 2. 里程碑结果

| 阶段 | 结果 |
|---|---|
| P0 动作契约 | 删除 `event.fire` / `chat.request` 两个变体及执行器/录制器分支；字幕不再依赖表现控制器；新增执行器双路径单测 |
| P1 桌宠聊天 | 右键「聊两句」→ 聚焦主窗 + 按语义键预填草稿；只预填不发送；IPC 白名单只接受三个语义键 |
| P2 视觉巡检 L1 | Playwright 截图覆盖设置页、记忆面板、上下文洞察面板；固定 Linux 环境生成基线；本地默认跳过 |
| 收尾 | 计划索引、路线图状态、发行说明与安装包归档 |

## 3. 关键设计

### 3.1 不可达动作先删不加通道

判断依据不是「类型里有没有」，而是五条路径能否产生它：类型定义、动作目录、配置校验、触发器、执行器。

五条路径都没有入口，说明这不是「还没接完」，而是没有任何调用方。此时补 IPC 只会扩大死代码面，正确做法是删除类型成员，并让录制器的 switch 继续保持穷尽检查。

### 3.2 字幕守卫收窄

执行器原先在拿到表现控制器之前整体返回，导致模型未加载时字幕也被跳过。

修复不是给字幕加特殊分支，而是把空判断下移到真正需要控制器的动作内部。字幕先处理，控制器只对交互与表情类动作判空。

单测锁定两条路径：无控制器仍出字幕；有控制器才驱动表现。这样下次重构执行器时，早退问题会直接被测出来。

### 3.3 桌宠只递语义键

桌宠是瘦终端：没有麦克风、没有聊天请求，表现数据都从主窗中继。

它发起聊天的合理路径只有一条：聚焦主窗、把一句话放进输入框，由用户决定发不发。

自动发送看似更顺手，但会绕过会话锁、勿扰、冷却与每日上限，还会消耗 token、可能误触任务模式。更根本的问题是它替用户表达了。

因此 IPC 只传三个固定语义键，不传自由文本；主窗按当前语言解析文案，只预填草稿并聚焦输入框。

### 3.4 截图只盯稳定面

截图回归最怕不稳定。WebGL 形象、透明置顶窗、带随机动画的舞台都不适合做像素基线。

本版只选三块二维稳定面：设置页基础区、记忆面板、上下文洞察面板。基线只在固定 Linux 环境生成，本地默认跳过，比对时关闭动画与光标，允许 2% 像素差异。

首月视觉步骤为非阻断，避免基线尚未稳定时阻塞功能发布。

## 4. 数据与验证

- 门禁：`pnpm check` 全绿；全仓无两个已删除动作变体的生产引用；
- 单测：执行器覆盖「无控制器仍出字幕」与「有控制器才驱动表现」；桌宠覆盖「预填但不发送」；
- 视觉：`test:e2e:visual` 在 Linux CI 生成/比对基线，本地默认跳过；
- 发布：Release workflow 构建 NSIS 安装包并生成草稿，核对资产后转正；
- 数据：无迁移，旧数据目录可直接覆盖安装。

## 5. 已知限制

- 视觉巡检只覆盖三块稳定面，WebGL、VRM/Live2D、透明桌宠窗与会议舞台不在基线内；
- 首月视觉步骤非阻断，失败只上传差异产物，不阻塞合并；
- 桌宠聊天不自动发送，也不会自动切换助手或创建新会话；
- 语义键固定为三个，新增意图需要同时改共享白名单、主进程菜单与文案；
- 视觉语义断言（L2）与人工流程（L3）未纳入本版。

## 6. 下一步

v4.15 之后优先处理 CI 与验收的可靠性，再进入易用性收口：

1. 验收脚本退出码、超时隔离、E2E 重试与视觉基线准备；
2. 限制可视化、能力状态统一、错误可恢复与首启不断链；
3. 消息检索、命令面板最近使用与设置常用项。
