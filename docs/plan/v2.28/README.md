# v2.28 方案：记忆可管——统计前端、审计轮转与约束撤销

> 主题：把 v2.26 已产出的记忆观测数据接到界面上，并补上「长期运行不膨胀」与「识别错了能撤销」两条治理闭环。
> 分支：`feat/v2.28-memory-governance`
> 目标：一次迁移（v048，纯加法）、零接口破坏、单一主题。

## 1. 背景与目标

v2.26 把长期记忆做成双时态、混合召回与可审计写入，并新增了 `GET /api/memories/stats`。但能力只到接口层：

- 统计在接口里，设置页看不到「多少记忆被取代、多少轮零召回、用户纠正了几次」；
- `memory_events` 只写不清理，长期运行会线性膨胀；
- 实时约束（过敏 / 忌口 / 禁止）命中即写入，没有「这条识别错了」的撤销入口；
- golden 评测仍是离线用例，改动召回权重后只能靠单测兜底。

本版目标：让用户可读（统计卡）、可维护（审计轮转）、可纠错（约束撤销）；评测看板只做本地报告，不做线上服务。

## 2. 盘点结论

| 来源 | 未交付项 | 本版取舍 |
|---|---|---|
| v2.26 方案 §9 | 统计前端、审计轮转、约束确认与撤销、线上评测看板 | 前三项纳入 P0/P1；评测看板降级为 P2 本地报告 |
| v2.26 发行说明「范围说明」 | 线上计数只提供接口，未接入设置页 | 本版 P0 直接接通 |
| 候选 02 | 四项治理与观测能力 | A+B+C 立项，D 只做离线报告 |

结论：不新增记忆写入链路，不改变召回权重；只做「读、清、撤」三类治理动作。

## 3. 主题与边界

一句话：**已有数据先让人看见，长期运行要能收口，识别错了要能撤回。**

- 读：统计卡只消费现有 `getStats()` 口径，前后端不各算一套。
- 清：审计轮转保留「聚合计数 + 最近 N 条」，不追求逐条永久可回溯。
- 撤：约束撤销复用现有 PATCH 归档语义（写入 `actor='user'` 审计），不新增删除路径。

## 4. 功能清单

### 4.1 设置页记忆统计卡（P0）

- 位置：设置 → 记忆分组顶部，`memory-panel` 只增加一行挂载，卡片独立成文件，避免撞 300 行门禁。
- 数据：`GET /api/memories/stats`，展示总量 / 活跃 / 归档、被取代比例、零召回率、召回总轮次、用户纠正次数；补充「最近 5 条审计」时扩展同一响应为可选字段，不新开接口。
- 口径：比例字段直接展示后端返回值，前端不重新做除法；空库显示 0 而非空白。
- 状态：加载骨架、失败可重试、刷新按钮；写入记忆后局部刷新，不整页 reload。
- i18n：中英成对新增 `memory.stats.*`，数字与百分比走同一格式化函数。

### 4.2 审计轮转（P1）

- 迁移 v048：新增 `memory_event_rollups(action, actor, count)` 聚合表，纯加法；`memory_events` 只加 `created_at` 索引。
- 轮转流程：单事务内「按 action + actor 聚合过期事件 → UPSERT 到 rollups → 删除原文」，返回删除条数与聚合增量。
- 保留期：默认 90 天，可配置 30 / 90 / 180 / 永久；配置存现有 settings，不新增表。
- 触发：服务启动后异步执行一次 + 每 24 小时一次，单飞锁防重入；失败只告警，不阻塞启动。
- 计数一致性：`countUserCorrections()` 改为「在线事件 + rollups 聚合」，轮转前后数字不下降；用户清空记忆时同步清空 rollups。
- 可核对：轮转结果写一条结构化日志（删除条数、聚合键数、耗时），设置页显示最近一次轮转时间。

### 4.3 约束确认与撤销（P1）

- 提前写入：实时约束是零模型成本的纯规则，移到 `done` 帧之前执行（毫秒级 DB 写入），常规模型抽取仍在后台。
- 契约：`done` 帧新增可选 `memoryNotices: Array<{ id, content }>`；旧前端忽略，不影响完成语义。
- 界面：助手消息末尾显示一条内联提示「已记住：{content} · 撤销」，不弹窗、不打断流式；每条新约束只提示一次，可手动关闭。
- 撤销：复用 `PATCH /api/memories/:id` 置为 `archived`，现有服务层会写入 `actor='user'` 的 `archive` 审计；撤销后提示变为「已撤销」，下一轮召回不再注入。
- 防打扰：同一会话同一约束不重复提示；一次命中多条时合并为一条提示，最多列 2 条。

### 4.4 评测基线报告（P2，可选）

- 新增本地命令 `pnpm memory:eval`，跑 golden 集并输出 hit@3、零召回率、耗时对比表；只写本地文件，不上传、不进 CI 必过项。
- 与上一版报告做差值对比，作为调整召回权重前的参考，不替代单测。

## 5. Non-Goals

- 不做线上评测看板、不做定时跑评测的服务端任务。
- 不做记忆图关系边与空闲整理（候选 01）。
- 不做审计事件逐条永久保留；轮转后只保留聚合与最近 N 条。
- 不改召回权重、不改双时态结构、不做跨设备同步。
- 不新增独立删除接口，约束撤销统一走归档语义。

## 6. 阶段拆分

| 阶段 | 内容 | 交付物 |
|---|---|---|
| P0-M1 | 统计卡：hook + 卡片 + 最近审计 + i18n | 设置页可见，接口口径一致 |
| P1-M2 | 审计轮转：v048 + 聚合读写 + 定时触发 + 配置 | 迁移、轮转纯函数与单测 |
| P1-M3 | 约束撤销：done 契约 + 内联提示 + 撤销动作 | 前后端契约与组件测试 |
| P2-M4 | 评测基线报告（可选） | 本地命令与报告样例 |
| 收尾 | 发行说明、路线图状态、博客 10 篇 | `docs/roadmap/v2.28-release-notes.md` |

顺序理由：统计卡只读、风险最低，先建立「页面数与接口数一致」的信心；轮转涉及迁移与计数一致性，单独一段；约束撤销动 `done` 契约与消息渲染，放最后以免反复改契约。

## 7. 验收口径

1. 设置页记忆分组显示统计卡：总量 / 活跃 / 归档 / 被取代比例 / 零召回率 / 召回总轮次 / 用户纠正次数，与 `GET /api/memories/stats` 完全一致；空库为 0，失败可重试。
2. 审计轮转默认保留 90 天，支持 30 / 90 / 180 / 永久；轮转在单事务内完成，删除条数与聚合增量可核对；用户纠正计数轮转前后不下降。
3. 实时约束命中后，助手消息末尾出现一条内联提示，可撤销；撤销写入 `actor='user'` 审计，下一轮不再注入；不出现弹窗，不阻塞流式输出。
4. `done` 帧新增字段为可选，旧客户端与旧消息正常渲染；无 `memoryNotices` 时不显示提示。
5. 迁移 v048 为纯加法、可重复执行；`LATEST_SCHEMA_VERSION = 48`；无数据回填。
6. `pnpm check`（typecheck / lint / 300 行 / 目录预算 / 循环 / ASCII）与 `pnpm test` 全绿；i18n 中英键成对。
7. 发行说明、路线图索引、博客 10 篇同版本收尾。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 统计口径与接口不一致 | 前端只格式化、不重算；组件测试锁定字段映射 |
| 轮转削弱可追溯性 | 保留聚合计数 + 最近 20 条原文，设置页显示最近轮转时间 |
| 约束提示打扰 | 每条只提示一次、合并展示、可关闭；不做弹窗 |
| 提前写入拖慢 done | 纯规则 + 单条事务，失败静默；加耗时日志 |
| 迁移影响老库 | 纯加法 + 幂等；迁移前备份由现有发布流程保证 |
