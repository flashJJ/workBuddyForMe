# v1.2 功能设计：品牌/安装器/签名、深色、a11y、i18n、引导

> 设计原则：行为增量以「子组件 + 纯函数/字典外迁」落地，全部新文件遵守 ≤300 行门禁；跨包共享只走既有方向（枚举/错误码/字典类型放 shared）；每个功能出口可机械验证。

## 1. 品牌图标套件（M0）

### 1.1 源图与生成策略

- 源图：用户提供 1500×1500 PNG，满版深紫底，主体=紫色笑脸 + 窗口/对话气泡/勾选三节点，主体包围盒约 x 21%–81%、y 14%–89%。
- 策略：**紧裁不抠图**。按包围盒取正方形裁切区（边长取主体宽高最大者外扩 ~8% padding，约 `(187,210,1312,1335)` 一带，脚本参数化），保留深紫底形成圆角方形 app icon 风格；发光体在紫底上自然融合，规避自动抠图对模糊光晕的破坏。
- 工具：Python + Pillow（本机官方签名 Python 3.10，SAC 环境可用；不引 npm 依赖）。脚本 `apps/desktop/scripts/gen-icons.py`，源图入仓 `apps/desktop/build/source/icon-source.png`，幂等生成、产物入仓（CI 打包不依赖 Pillow）。

### 1.2 产物清单与落点

| 产物 | 规格 | 落点 |
|---|---|---|
| Windows 应用图标 | ico 内嵌 16/24/32/48/64/128/256 八档 PNG | `build/icon.ico`（electron-builder 自动用于 exe 与 rcedit） |
| NSIS 安装/卸载器图标 | ico | `build/installer.ico`、`build/uninstall.ico`（nsis.installerIcon/uninstallerIcon） |
| 安装器侧栏图 | BMP 164×314 | `build/installerSidebar.bmp` |
| Linux/通用 PNG（预留） | 512/256/128 | `build/icons/512x512.png` 等 |
| 窗口运行时图标 | 256 PNG | extraResources 收 `resources/icon.png`；修 `window.ts` 死代码，BrowserWindow icon 指此文件 |
| Web favicon | 32/ICO | `apps/web/public/favicon.ico`、favicon-32.png（当前为 Next 默认） |

验收：装包后任务栏/标题栏/Alt-Tab/桌面快捷方式/开始菜单/安装器页眉/卸载器/文件属性七处图标一致；16px 档肉眼可辨笑脸。

## 2. 安装器与打包配置（M0/M1）

### 2.1 electron-builder.yml 增补

```yaml
artifactName: ${productName}-Setup-${version}.${ext}   # 恢复 0.9.0 连字符惯例
win:
  icon: build/icon.ico
  # signAndEditExecutable 删除（恢复默认 true）；签名由 sign 钩子按凭据有无双态处理
nsis:
  oneClick: false
  perMachine: false
  allowToChangeInstallationDirectory: true
  installerIcon: build/installer.ico
  uninstallerIcon: build/uninstaller.ico
  installerHeaderIcon: build/icon.ico
  installerSidebar: build/installerSidebar.bmp
  createDesktopShortcut: true
  createStartMenuShortcut: true
  menuCategory: WorkBuddyForMe            # 开始菜单独立程序组
  shortcutName: WorkBuddyForMe
  uninstallDisplayName: WorkBuddyForMe ${version}
  license: build/installer-license.txt     # GPL-3.0 文本（从根 LICENSE 转换）
  installerLanguages: [zh_CN, en_US]       # electron-builder 自带双语 NSIS 界面
  language: '2052'                          # 默认简体中文
  deleteAppDataOnUninstall: false           # 默认保留数据
  include: build/installer.nsh              # 卸载时询问删数据
```

`installer.nsh` 只做一件事：uninstall 自定义页弹「同时删除我的所有数据（模型/对话/配置，不可恢复）」勾选，勾选则在卸载收尾删除数据根（通过 `$PROFILE\.workbuddy-for-me` 与 userData/data 两态路径，实际常量从打包注入读）。NSIS 宏用 `!macro customUnInstall` 系列，单测覆盖不了，靠装包真机清单验收。

### 2.2 签名双态（M1 先 spike）

- 删除 `signAndEditExecutable: false`。Spike 顺序：
  1. 直接构建验证 electron-builder 25.x 无证书时默认行为：期望跳过 signtool、保留 rcedit（exe 有图标+版本资源），构建 exit 0；
  2. 若行为不符（把缺证书当错误），加 `win.signtoolOptions` 不可行则改用自定义签名钩子文件：钩子检测 `process.env.CSC_LINK`，无则直接 `callback()` 放行（rcedit 在签名阶段之外独立执行，不受影响），有则拼装 signtool 参数（含 RFC3161 时间戳服务器 `http://timestamp.digicert.com`）后执行。
- CI 侧签名凭据只通过 secrets 注入（`CSC_LINK` base64 pfx + `CSC_KEY_PASSWORD`），本版本不创建 secret 实参、文档写明购买证书后的启用步骤（3 步：放 secret→跑 tag→验证文件属性数字签名页）。
- 产物自检脚本：构建后检查 exe 版本资源（ProductName/FileVersion）存在；签名态额外验证签名链（PowerShell `Get-AuthenticodeSignature`）。

### 2.3 版本号单一事实源（M0）

- 新增 `scripts/sync-version.mjs`：读 root package.json version → 写 apps/web、apps/desktop 两个 package.json + 生成 `packages/shared/src/generated/version.ts`（`export const APP_VERSION = 'x.y.z'`，generated 文件加文件头注释禁手改，已在 .gitignore 评估——选择**入仓**避免 prepare 漏跑，发布脚本幂等覆盖）。
- MCP serverInfo/clientInfo 改读 `APP_VERSION`（删掉 1.1.0 与 0.6.0 两处硬编码，同步改测试断言为读常量）。
- 运行时误报修复：`server-manager.ts` spawn 内置 node 时注入 `APP_VERSION`（取 `app.getVersion()`）；health/system info 两个路由改读 `process.env.APP_VERSION`，回落链 `APP_VERSION → npm_package_version → '0.0.0-dev'`（不再写死 0.1.0）。
- `pnpm dist:win` 串联：desktop 的 prepack 链先跑 build:web（顶层脚本加 `pnpm --filter web build && prepare-server`），杜绝陈旧 standalone。

### 2.4 CI 发布流水线（M1）

新增 `.github/workflows/release.yml`：
- 触发：手动 `workflow_dispatch` + tag `v*`；runner `windows-latest`（prepare-server/node.exe/native 归集链只在 Windows 验证过）；
- 步骤：pnpm install（electron 二进制走缓存，ELECTRON_*_MIRROR 走 npmmirror 镜像 env）→ check → test:unit（windows 份）→ sync-version（tag 名推导版本并校验与 root 一致）→ build:web → prepare-server → electron-builder `--win nsis --publish onTag`（有 secrets 自动签、draft Release + latest.yml/blockmap）；
- 产物同时上传 workflow artifact（不发 tag 时也能手动取包）；
- 质量 CI（ci.yml）保持 ubuntu 主线不动。
- 发布 runbook 落 `docs/development.md` 增补「发布流程」一节：tag → draft Release 检查 → 人工转正式 → 旧版实机更新验证 → 首次安装 SmartScreen 应对说明。

## 3. 深色模式完检（M2）

### 3.1 主题状态单一数据源

- schema 扩 `theme: z.enum(['light','dark','system'])`，settings 迁移 v016（纯加列/扩枚举）；ThemeProvider 新逻辑：
  1. 首屏：内联脚本读 localStorage 缓存立即挂 class（防闪烁，现状保留）；
  2. hydrate 后异步拉设置 API，以服务端 theme 为准校正并回写 localStorage；
  3. 两个入口（侧栏切换/设置页下拉）都改为「乐观更新 localStorage + PUT 设置表」，同一份 hook `useTheme`；
  4. system 态：监听 `matchMedia('(prefers-color-scheme: dark)')` change 解析为实际 class；
  5. 桌宠独立窗同步主题（pet 窗也要读同一真源）。
- 持久化 key 沿用 `wbfm-theme`，值扩三态，老值自动兼容。

### 3.2 配色补全与缺陷修复

- 补 `popover/popover-foreground` token（:root/.dark 两套），toast `bg-popover` 即刻生效。
- 新增 highlight.js 主题 CSS：明暗两套 CSS 变量映射（不用整包主题，手写一份约 40 行的 token 化代码配色随 .dark 切换），接 markdown.tsx 的 rehype-highlight 输出。
- 130+ 行未配对状态色治理：**不逐行加 dark:**，按语义替换为 token/组件变体——状态徽章统一走 Badge variant（success/warning/danger/info 四语义，variants 内一次性配明暗两套）；其余 red/emerald/amber 工具类逐域替换为 `text-destructive`/语义变量。流程画布节点的状态色映射到一组 `--status-*` CSS 变量。
- 逐域走查清单（每域出深/浅截图）：chat、settings（12 面板）、flow-editor、flow-execution、voice、knowledge、memory、tasks、assistants、command-palette、pet。
- muted-foreground 暗色色值对比度过低问题一并调（目标 ≥4.5:14pt 以上正文）。

## 5. i18n 框架与核心路径双语（M4）

### 5.1 框架（自研，零运行时新依赖）

```text
packages/shared/src/i18n/
├── types.ts            # MessageSchema（从 zh 字典类型推导，en 必须类型对齐/允许 DeepPartial）
├── zh-CN.ts            # 中文完整字典（嵌套 namespace：common/nav/chat/settings/onboarding/...）
└── en-US.ts            # 英文字典（核心路径完整，次要键可缺）
apps/web/src/lib/i18n/
├── i18n-context.tsx    # Provider：语言来自设置（hydrate 逻辑同主题），t(key,vars) 插值+复数
├── t.ts                # 纯函数 translate(dict,key,vars)，框架内核（单测密集）
└── use-i18n.ts         # hook
```

- `t('common.confirmDelete')`；插值 `t('settings.downloadProgress', { percent: 65 })`；复数用 ICU-lite 规则 `{count, plural, one {# item} other {# items}}`（实现 ~30 行，只支持 one/other，中英够用）。
- **缺键回退**：en 缺键 → zh-CN → key 本身（保底不显示空白）；dev/test 环境缺键 console.warn 并在单测里可开「缺键即失败」模式，产出待翻译机械清单。
- 语言切换：设置页语言下拉（zh-CN/en-US），即时生效不刷新；`<html lang>` 同步；v016 迁移把 `language` 从 literal 放 enum；老用户默认 zh-CN。

### 5.2 覆盖范围（核心路径）

P0 全双语：common（按钮/确认/错误通用词）、nav、command-palette、onboarding、help、about、settings 全部面板的标题/按钮/表单/提示、chat 框架（composer/消息操作/空态/引导卡，不含模型生成内容）、assistant/knowledge/memory/tasks/flows 列表框架（导航/按钮/空态/分页/删除确认）、toast 通用、快捷键浮层。

P1 英文（缺键回退可接受）：flow-editor 画布细节、voice 高级面板、MCP/调试台技术文案、错误详情中的开发者信息。

### 5.3 错误消息本地化（服务端不再拼用户可见中文）

- 服务端继续返回 `{success:false, error:{code,message?}}` 信封（v0.1 既有契约）：**code 是主语**，服务端 `message` 降级为仅日志/开发者提示；前端建 `errors.<code>` 字典，按 code + t() 呈现；需要参数的错误（如限流 Retry-After 秒数）走 vars。
- 本版本只迁移用户可见路径（API 错误 toast/表单校验/对话框）；服务端日志保持中文不动。
- 日期/数字本地化：4 处写死 `'zh-CN'` 与手拼日期全部改 `Intl.DateTimeFormat(locale)`、百分比/数字走 `Intl.NumberFormat`。

## 6. 首次启动向导与帮助中心（M5）

### 6.1 首启向导（4 步）

- 状态：AppSettings 加 `hasOnboarded`（v016 迁移，默认 0）；启动时若未完成，主窗进向导全屏遮罩（不挡桌宠），可跳过（跳过=按未配置态正常进应用）。
- 步骤：
  1. **欢迎**：一句话价值 + 本地优先/数据不出本机说明；
  2. **配供应商（核心一步）**：二选一卡片——云端（选厂商→填 Base URL/Key，复用 provider 表单，提供「测试连接」）；本地（检测 Ollama，未装给安装指引与 pull 命令，装好后刷新检测）；完成后拉模型列表；
  3. **语音（可选）**：说明语音模型首用下载（约 230MB+），给「立即下载/稍后自己在设置下载」两选，不阻断；
  4. **完成**：提示「发第一句话」与 Ctrl+K/语音按钮位置，写 hasOnboarded=1 进 chat。
- 结构：`features/onboarding/`（dialog 容器 + 4 个步骤组件 + 纯函数步骤状态机），每文件 ≤150 行；设置页提供「重新打开引导」。
- 向导文案直接走 i18n 字典（M4 先行），中英同步交付。

### 6.2 快捷键浮层与帮助入口

- 新增全局快捷键 `Ctrl+/`（与命令面板 Ctrl+K 并列，Electron global-shortcuts + web 键位双注册）弹快捷键表浮层：分组列出全局/对话/语音/Flow 操作；表格数据为共享常量（i18n 键 + 快捷键常量单一真源）。
- About 面板加：快捷键按钮（打开浮层）、「使用向导」（重放 onboarding）、「帮助与常见问题」锚点。
- 帮助中心：应用内设置子页 `help-center`（内置静态 FAQ markdown：安装/供应商/Ollama/模型下载/语音/数据与备份/卸载，内容约 8-10 条），渲染复用现有 markdown 组件；错误边界/关键错误 toast 增加「查看帮助」动作跳对应锚点。

## 7. 数据与迁移

- v016 一个纯加法迁移：settings 行扩 `theme` 枚举（+system）、`language` 枚举（zh-CN/en-US，默认 zh-CN）、加 `has_onboarded`（INTEGER 默认 0）。
- 无用户数据结构破坏；老用户升级：主题保持 light（行为不变）、语言 zh-CN、hasOnboarded=1（升级用户不弹向导——只新装机首弹）。
- 图标/安装器文件全部在 buildResources，不碰数据根；卸载删数据是唯一涉及数据删除的新逻辑，默认不勾、二次确认文案写明不可恢复。
