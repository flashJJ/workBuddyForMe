# v1.2 实施路线与风险：M0–M5 任务板

> 每条任务带可机械验证的完成标准。顺序：M0 先行（品牌/版本号是后续打包验证的地基）；M1 签名 spike 若证伪需要早发现故紧随；M2/M3/M4 在前端可并行但建议按 M2→M3→M4 串行（同文件区域有交集，且 i18n 依赖最终文案）；M5 收尾。每里程碑一个提交批次，批次间隔保持 typecheck/lint/单测全绿。
>
> 分支：`feature/v1.2-release-polish`（基线 tag `v1.1.0`）。

## 测试策略

- **纯函数先行**：t() 内核、版本同步、图标尺寸参数、向导步骤状态机、卸载判定逻辑全部密集单测。
- **契约不放松**：错误码→文案映射、快捷键表、ns 字典键完整性用快照/枚举测试锁定；en 字典缺键在测试期 fail 模式下机械产出清单。
- **e2e 新增两类取证**：a11y-core（axe serious/critical）、onboarding（新数据根）；深色/双语走查以 Playwright 截图人工签字，不引入视觉回归框架（控制版本规模）。
- **打包只认真机**：NSIS 自定义脚本、签名双态、卸载删数据、跨版本更新四类无法单测，全部进 T5.6 装包清单，每项附期望现象。
- **门禁自身要被证伪**：axe 门禁、缺键 fail 模式都配「故意造违规必失败」探针（沿用 v1.1 规则自证经验）。

## 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| electron-builder 25 无证书时 rcedit 与签名无法分离 | 中 | M1 设计前提动摇 | T1.1 最先 spike；退路是自定义 sign 钩子精确控制；再不行 pin 小版本 electron-builder |
| v0.9→1.2 跨级差分更新失败 | 中 | 老用户更新断链 | T1.6 真机先验；electron-updater 自带全量兜底；发 Release 时保留完整 nsis；必要时发整包而非 blockmap |
| i18n 抽离面超预算（万级汉字） | 高 | 版本膨胀 | P0/P1 边界在任务表写死，P1 回退中文不算缺陷；按域独立提交，超期域顺延 v1.3 |
| 服务端错误消息改造牵连信封 | 低 | 全 API 回归 | 不改信封、不改 code，只加前端映射层；旧 message 字段保留给日志 |
| 深色替换为 token 后视觉回归面大 | 中 | 浅色模式被误伤 | token 值与现状亮色逐值比对，只动映射不动组件布局；11 域截图签字 |
| 自定义 NSIS 删数据误删用户目录 | 低但严重 | 用户数据丢失 | 默认不勾+二次确认；路径常量先在安装产物日志中核对；T0.4 两态真机各走一遍 |
| CI windows 构建慢/electron 下载失败 | 中 | 发布不可用 | npmmirror 镜像 env + 依赖缓存；release.yml 可手动触发取 artifact，不强依赖 tag |
| SAC/杀软对未签名包拦截 | 已知存在 | 新用户首装受阻 | 文档化 SmartScreen 仍要运行指引；签名流程就位后购证即可零代码切换；pack e2e 保留复制官方 exe 的既有降级 |
| 图标小尺寸不可辨 | 中 | 品牌效果差 | 紧裁参数脚本化，T0.1 出三档候选人工选；最差退路用「勾选节点」单元素简化版 |
| onboarding 对老用户骚扰 | 低 | 升级体验 | 迁移默认 hasOnboarded=1，仅全新数据根首弹 |

## 里程碑成功标准（封版对账用）

1. 一台干净 Windows（非开发机）全新安装：中文安装器→新图标→向导→配 Ollama→第一句对话成功，全程不需要看文档。
2. 同一台机器切英文：核心路径无中文裸露；切深色：11 个域无浅底浅字。
3. 键盘 only 完成一次对话与一次配置修改；axe 五场景 0 serious/critical。
4. 「卸载」两种走法（保留/删除数据）都符合预期；0.9.0 老包能应用内更新到 1.2.0 且数据无损。
5. CI 在 tag 上一键产出 draft Release，签名凭据位空时一切正常、填了即签名。
