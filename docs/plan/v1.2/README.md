## 1. 一句话方案

v1.1 把内部工程债清零后，产品的代码质量已经达到可继续长功能的状态；但**分发形态**仍是「作者本机手工出包」水平：exe/安装器全是 Electron 默认图标、NSIS 只有英文且无许可页、代码签名与 rcedit 被整体关闭、CI 没有 Windows 打包、更新源停在 v0.9.0；**使用形态**上深色模式半套、无障碍无体系、文案全硬编码中文、新用户没有任何引导。v1.2 不新增长功能线，把「从下载安装到第一次成功对话」这条链路上所有「不像正式产品」的断点补齐。

### 非目标（本版本明确不做）

- **不购买代码签名证书（OV/EV 均不买）**：只交付签名接入位与无证书降级；SmartScreen 信誉积累与证书采购另行决策
- **不改 appId**：`com.wbfm.desktop` 已随 v0.9.0 发布，改动会被更新器识别为不同应用、切断 0.9→1.2 更新链；appId 是内部标识不对用户可见
- **不做 macOS/Linux 适配**（含桌宠、打包、语音原生绑定）
- **不做全量次要面板英文翻译**：flow-editor、voice 高级面板等次要域 en 缺失回退中文；服务端日志保持中文，仅用户可见错误消息走 code 映射
- **不做视觉体系重设计/品牌大改**：配色、布局、组件形态不动，深色只补配对
- **不做云端帮助中心/账号体系/反馈服务**：帮助内容内置在应用内
- **不新增功能线**（新工具、新模型能力、多 Agent 等一律顺延）

## 4. 关键设计决策

1. **签名只做流程、不买证书**。构建系统检测到签名凭据（`CSC_LINK`/`CSC_KEY_PASSWORD`）时执行 signtool + 时间戳；无凭据时跳过签名，但**必须保留 rcedit**（exe 图标与版本资源）。M0 第一件事就是 spike 验证 electron-builder 25 在恢复 `signAndEditExecutable` 后「无证书不报错且 rcedit 生效」——若该版本无法分离两行为，用自定义 sign 钩子返回 resolve 精确控制。
2. **appId 冻结**。品牌改名冲动让位于更新链连续性：Windows 上 userData 按 productName（保持 WorkBuddyForMe 不变），注册表应用身份与更新器按 appId，二者本版本都不动。
3. **i18n 自研轻量方案，不引第三方库**。桌面应用是 Electron 内嵌 SPA、语言按用户设置切换而非 URL 分段，next-intl 等路由型方案不适配；自研 = React Context + 嵌套 TS 字典 + `t(key, vars)`，约一个文件的核心，与 v1.1「零新增运行时依赖」的取向一致。服务端不再拼中文错误文案，统一返回领域错误码，由前端按当前语言映射（错误码体系早已存在，本次接通最后一公里）。
4. **双语只覆盖核心路径，缺失回退中文**。113 个生产文件约 1.1 万汉字全量英译是周级工程且稀释主题；核心路径（向导/设置/对话框架/导航/命令/快捷键/错误）全双语，次要面板 en 缺键时显示中文并在 dev 控制台报告缺键，为 v1.3 继续翻译留机械清单。
5. **主题状态以设置表为真源、localStorage 仅作首屏缓存**。修复现存「侧边栏开关只写 localStorage、设置页下拉只写 DB」的双写缺陷：ThemeProvider 启动读 localStorage 防闪烁、hydrate 后以设置 API 为准并回写，任一入口切换双写；新增 system 三态（扩 settings schema）。
6. **图标用「紧裁主体 + 圆角方形底」而非抠图**。源图是 1500×1500 满版深紫底，主体（笑脸+三节点）约占画面 60%×75%；直接缩到 16px 会糊成紫块。脚本按主体包围盒紧裁（约 21%–81% / 14%–89%）后再缩，主体占比提到 85% 以上；保留深紫圆角底与整体画风一致，规避发光边缘自动抠图的质量风险。生成参数写进脚本，实施时逐档目检。
7. **a11y 门禁只卡 serious/critical**。引入 @axe-core/playwright（devDep）对核心页面出扫描报告，CI 卡 serious/critical = 0；moderate/对比类问题出报告逐项人工关，避免一次性红灯淹没。
8. **卸载默认保留用户数据**。本地优先产品的数据删除是不可逆操作：卸载器默认不动数据根，仅经自定义 NSIS 脚本在卸载时弹一次「同时删除我的数据」可选项。
