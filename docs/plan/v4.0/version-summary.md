# WorkBuddyForMe v4.0.0 版本总结

> 版本：4.0.0（2026-11-15）
> 主题：平台化一期——依赖拓扑、内容包与发布校验
> 范围：M0 → M1 → M2 → M3 → M4 → M5 → M6
> 真源：[release-notes.md](./release-notes.md)、[progress-log.md](./progress-log.md)

## 1. 这一版解决了什么

v3.1 把三个硬编码分叉改成了注册表，但注册口还不是内容包：能力之间没有依赖顺序，动效内容不能安装，安装后运行时也读不到。v4.0 把这条链路接完整：

| 环节 | 改造前 | 改造后 |
|---|---|---|
| 能力依赖 | 只看单包，缺依赖靠报错 | `coreVersion` + 环检测 + 稳定拓扑序，安装/启用/升级统一预检 |
| 动效契约 | 绑定在 web `animation/` 目录 | 内部包 `@wbfm/motion`，纯数据、多入口、可被 core 校验 |
| 动效内容 | 只能改代码内置表 | `motion-pack` 能力包安装，启用后进入内容快照 |
| 内容刷新 | 重启或改代码 | 会话级快照：安装/停用后下一次挂载生效 |
| 发布校验 | 只有安装包三件套 | `SHA256SUMS.txt` + `build-info.json`，可复算、可回溯 commit |

## 4. 技术与产品收益

- **能力包可以表达依赖**：缺依赖、版本过低与环在安装前就被拒绝，不再等到启用时才炸。
- **动效内容可安装**：内容包复用现有 ZIP、校验和、签名、升级与回滚链路，不新造安装器。
- **运行时与内容解耦**：`MotionContent` 从 web 抽到内部包，VRM 适配仍留 web，core 也能做 payload 校验。
- **刷新边界清晰**：当前会话不换内容，下一次打开舞台/桌宠读取新快照，避免骨骼与轨道错位。
- **发布可验证**：安装包、blockmap 与 `latest.yml` 都可复算哈希，构建信息能回溯到 commit。

## 5. 已知限制

- `motion-pack` 只包含姿态/动作/行为数据，不支持 VRMA 与纹理文件；VRMA 动作由 `pet-action` 单独安装。
- 内容刷新以会话为单位，不做热替换。
- 发布只做校验和，不含代码签名、自有更新源与双通道。
- 场景包、道具包、工具描述符与 provider 能力元数据尚未纳入。
- 未构建 v4.0 安装包，也未做发布真机截图。
