# v2.11 M0：能力包 effect 扩面与外部代理契约冻结

> 状态：冻结稿（待评审）
> 范围：`workflow` / `pet-action` / `event-script` / `report-widget` 四类 effect；六类示例包；外部代理第一个实现（本地 CLI）。
> 决策基线：沿用 v2.10 的清单/校验/生命周期与「不做远程市场、不执行任意代码、不共享宿主密钥」。
> 本文是实现唯一口径；偏离需回写本文并同步 [README](README.md)。

## 1. 决策摘要

| # | 决策 | 理由 |
|---|---|---|
| D1 | 六类 kind 全部接通 effect，`CAPABILITY_SUPPORTED_KINDS` 扩为全量 | 兑现「统一装卸」；不再出现「清单支持、安装拒绝」 |
| D2 | 工作流启用即「建行 + 存版本 + 发布」；停用置 `disabled` 不删行 | 保留历史运行与端点引用；卸载时按「有运行/被端点引用」决定保留禁用行还是删行 |
| D3 | 桌宠动作包只导入动作资产（VRMA + 段/档位），不做自定义动画图 step | 动画图 step 与事件剧本职责重叠，避免第二套编排语言 |
| D4 | 事件剧本包只支持 **短语触发**（本地包含匹配），不支持意图/上下文触发 | 不改既有内置意图注册表；短语触发复用自定义触发器闸门 |
| D5 | 事件剧本需要两处 schema 扩展：标题与台词支持字面量（`title` / `text`） | 能力包无法随包提供 i18n 词条；内置剧本继续用 `titleKey` / `lineKey` |
| D6 | 报告卡片只做声明式指标（成功率/运行数/中位耗时/失败 Top），复用运行证据汇总 | 不给报告页开查询/脚本入口 |
| D7 | 外部代理第一个实现为 **本地 CLI 适配器 + JSON Lines 协议**，默认关、逐次审批 | 实现面小、可用 mock 可执行文件做 CI；ACP 列 P1 |
| D8 | 外部代理配置放 settings JSON，不新建 provider 表 | 单实现单配置；多 provider 管理留 P1 |
| D9 | 外部代理 P0 只支持管理页手动运行，不暴露为模型工具 | 避免提示词注入触发任意命令；模型工具化留 P1 评估 |
| D10 | `mcp` 示例只提供模板包（不自动可连），其余五类提供可一键生效示例 | 远程/本地 MCP 端点无法由示例包伪造；不制造「装完即坏」 |

## 2. 六类 effect 契约

### 2.1 通用约束

- 清单 `entry` 按 kind 固定：

| kind | entry 固定值 |
|---|---|
| `skill` | `payload/skill.json` |
| `mcp` | `payload/server.json`（沿用 v2.10） |
| `workflow` | `payload/workflow.json` |
| `pet-action` | `payload/action.json` |
| `event-script` | `payload/script.json` |
| `report-widget` | `payload/widget.json` |

- 单包体积 ≤20MB（沿用安装路由上限）；单个 payload 文件上限：
  - `workflow.json` ≤256KB；`script.json` ≤64KB；`widget.json` ≤16KB；`action.json` ≤32KB；`.vrma` ≤10MB。
- 所有 JSON 必须通过对应 Zod schema；`.default()` 仅在 schema 内使用，校验失败即 422，不落文件。
- enable 失败：回滚到 `disabled`，写 `lastError`，不留副作用；disable 失败保留 `enabled` 与原 `effectRef`。
- `effectRef` 六类均为可读句柄：技能名 / MCP server id / workflow id / motion id / script id / widget id。

### 2.2 `workflow`

```json
{
  "name": "周报生成",
  "description": "读取本周事件并生成周报草稿",
  "icon": "sparkles",
  "color": "indigo",
  "graph": { "nodes": [], "edges": [] }
}
```

- `name` 1–60、`description` ≤200、`icon`/`color` ≤32；`graph` 复用现有 FlowGraph schema。
- 安装前额外校验：`compileFlow(graph).ok === true`（图非法拒绝，避免污染工具目录）。
- 启用：`createWorkflow`（记录 `origin_capability_id`）→ `addVersion(graph)` → `publishVersion`。
- 停用：`setStatus(id, 'disabled')`；已发布端点保留但调用返回该工作流不可用。
- 卸载：
  - 无运行记录且未被任何端点引用 → `deleteWorkflow`；
  - 否则保留行并置 `disabled`，保留 `origin_capability_id`，列表标注「来源能力包已卸载」。
- 迁移补充列：`workflows.origin_capability_id TEXT NULL`。

### 2.3 `pet-action`

```json
{
  "name": "打招呼",
  "file": "payload/hello.vrma",
  "entryKey": "greet",
  "segment": "single",
  "mood": "good",
  "minRelationshipLevel": 0
}
```

- `file` 必须在 `payload/` 下且纳入 checksums；扩展名必须 `.vrma`。
- `segment` ∈ `single` / `a_start` / `b_loop` / `c_end`；`mood` ∈ `good` / `normal` / `low`；`minRelationshipLevel` ∈ 0–3。
- 启用：读文件 → 走既有 `sniffVrma` 双校验（GLB 魔数 + `VRMC_vrm_animation`）→ `motionService.importMotion`，`source = capability:<packId>`。
- 停用：删除该 `motion_assets` 行与文件；用户自建动作不受影响。
- 卸载：同停用，再清包目录。

### 2.4 `event-script`

```json
{
  "definition": {
    "id": "usr.goodnight",
    "title": "晚安小仪式",
    "priority": 1,
    "interruptPolicy": "ignore",
    "cooldownMs": 3600000,
    "maxPerDay": 2,
    "speechLock": "queue",
    "steps": [
      { "kind": "expression", "tag": "happy" },
      { "kind": "speech", "text": "今天也辛苦了，早点休息。" },
      { "kind": "fx", "id": "sparkle" }
    ]
  },
  "trigger": { "kind": "phrase", "phrases": ["晚安", "睡觉了"] }
}
```

- `definition` 复用 `eventDefinitionSchema`，并做两处 v2.11 扩展（见 2.4.1）。
- `id` 必须形如 `usr.<slug>`（`slug` 仅小写字母/数字，3–40 位）；全局唯一，重复安装 409。
- `trigger.phrases` 1–5 条，每条 2–24 字符，仅本地包含匹配，不区分大小写；不写正则、不联网。
- 启用：写 `installed_event_scripts` 行（`enabled=1`）→ 重载导演剧本注册表。
- 停用：`enabled=0` 并摘除注册表；卸载删行。
- 导演既有闸门（总开关、勿扰、对话锁、冷却×频率档、每日上限、队列上限）对安装剧本同样生效，包不提供任何绕过字段。

#### 2.4.1 事件 schema 扩展（shared，向后兼容）

- `eventDefinitionSchema`：`titleKey` 改为可选，新增 `title`（1–40 字面量）；superRefine 要求二者恰有其一。
- `speechStepSchema`：`lineKey` 改为可选，新增 `text`（1–32 字面量）；superRefine 要求二者恰有其一。
- 内置剧本不变（继续 `titleKey` / `lineKey`）；安装剧本强制使用 `title` / `text`。
- 读标题统一走 `resolveEventTitle(def, t)`：`title ?? t(titleKey)`；缺两者视为非法定义。

### 2.5 `report-widget`

```json
{
  "title": "近 30 天任务成功率",
  "chain": "task",
  "metric": "success_rate",
  "windowDays": 30
}
```

- `title` 1–40；`chain` ∈ `task` / `flow` / `agent`；`windowDays` ∈ 7 / 30 / 90。
- `metric` 白名单与数据映射：

| metric | 数据 | 来源 |
|---|---|---|
| `success_rate` | `summary.successRate`（百分比，保留两位） | 运行证据汇总 |
| `run_count` | `summary.total` | 同上 |
| `median_duration` | `summary.medianDurationMs` | 同上 |
| `failure_top` | `summary.failures[0]`（无失败显示「无」） | 同上 |

- 启用：校验 → 写 `report_widgets` 行（`enabled=1`）；报告页新增「能力包卡片」区，按启用顺序渲染。
- 停用/卸载：删行；卡片数字只读，不缓存跨请求快照（沿用报告页现有时间窗选择）。

## 3. 外部代理（本地 CLI）契约

### 3.1 配置（settings JSON）

| 字段 | 默认 | 约束 |
|---|---|---|
| `subagentCliEnabled` | `false` | 显式开启后才注册可用 |
| `subagentCliCommand` | `''` | 非空时必须是绝对路径或 PATH 可解析命令 |
| `subagentCliArgs` | `[]` | ≤10 项，每项 ≤200 字符；以数组传递，不经 shell |
| `subagentCliTimeoutMs` | `600000` | 60s–30min，服务端钳制 |
| `subagentCliMaxOutputBytes` | `2097152` | 64KB–8MB，服务端钳制 |

- 设置页与能力包页均可读写；关闭开关立即注销 provider 并取消在途运行（收敛为 `cancelled`）。
- 不配置即不存在 provider；`/api/subagents/providers` 返回空列表，核心功能零影响。

### 3.2 协议（JSON Lines，stdin/stdout）

宿主 → 子进程（每行一个 JSON）：

```json
{"type":"run","protocol":1,"goal":"...","conversationId":"...","budget":{"maxRounds":6,"maxTotalTokens":200000}}
{"type":"permission_result","id":"p1","allow":true}
```

子进程 → 宿主：

```json
{"type":"delta","text":"..."}
{"type":"permission","id":"p1","title":"写入文件","detail":"README.md"}
{"type":"done","summary":"..."}
{"type":"error","code":"FAILED","message":"..."}
```

- 首行必须是 `delta` / `permission` / `done` / `error` 之一；未知 `type` 视为协议错误并终止。
- 单行 ≤64KB；非 JSON 行忽略但计入诊断（最多 10 条）；stdout 总量受 `maxOutputBytes` 限制。
- stderr 单独捕获，最多保留 64KB，仅用于失败原因，不进入对话。
- 终止条件（任一）：`done` / `error` / 超时 / 输出超限 / 用户取消 / 审批拒绝 / 子进程退出。
- 取消与超时：Windows 使用 `taskkill /pid <pid> /T /F`，其他平台 `process.kill(-pid, 'SIGKILL')`；确认子进程树回收后才写终态。

### 3.3 审批与运行

- 每次运行先登记审批：`ApprovalSource='subagent'`，标题「运行外部代理」、`argsSummary` 展示命令与目标、`deepLink='/capabilities?run=<runId>'`、`expiresAt=+5min`。
- 拒绝或超时：不启动进程，运行收敛为 `cancelled`，`errorCode=approval_denied / approval_timeout`。
- 允许后才 spawn；`cwd` 必须由用户显式填写且存在、为目录；拒绝系统目录（Windows 系统盘根、`Windows`、`System32`；Unix `/`、`/etc`、`/usr`）与应用数据目录。
- 环境变量白名单：`PATH`、`SystemRoot`、`TEMP`/`TMP`、`HOME`/`USERPROFILE`、`LANG`/`LC_ALL`；不注入任何供应商密钥或应用 token。
- 运行记录写 `subagent_runs`；同时发 WorkSignal（`source='subagent'`）与 `session_events`（`scope='agent'`，`type=subagent_started/subagent_finished`，只记状态与摘要，不写逐帧 delta）。
- 若传 `conversationId`，终态走 `run_completions(run_id, kind='subagent')` 幂等回投一条助手消息；失败也回投可读原因。

### 3.4 安全边界（fail-closed）

| 风险 | 控制 |
|---|---|
| 任意命令执行 | 默认无 provider；显式开关 + 逐次审批；命令以 argv 数组启动，`shell:false` |
| 密钥外泄 | 输入契约无凭据；环境变量白名单；不读取供应商密钥 |
| 挂死/刷屏 | 超时 + 输出上限 + 行上限；超限即终止并写 `failed` |
| 越权目录 | cwd 白名单校验；拒绝系统目录与应用数据目录 |
| 证据缺失 | `subagent_runs` + WorkSignal + 事件日志三处留痕 |
| 模型触发 | P0 不暴露工具；只能人工在管理页发起 |

## 4. 存储与迁移 v040（纯加法）

| 变更 | 内容 |
|---|---|
| `workflows.origin_capability_id` | `TEXT NULL`，记录来源能力包 id（用于卸载后标注与清理判定） |
| `installed_event_scripts` | `id TEXT PK` / `pack_id TEXT` / `name TEXT` / `definition_json TEXT` / `enabled INTEGER` / `created_at TEXT`；唯一 `id`，索引 `(enabled)` |
| `report_widgets` | `id TEXT PK` / `pack_id TEXT` / `title TEXT` / `config_json TEXT` / `enabled INTEGER` / `created_at TEXT` |
| `subagent_runs` | `id TEXT PK` / `provider_id TEXT` / `goal TEXT` / `cwd TEXT` / `conversation_id TEXT NULL` / `status TEXT` / `summary TEXT` / `error_code TEXT NULL` / `error_message TEXT NULL` / `output_bytes INTEGER` / `created_at TEXT` / `started_at TEXT NULL` / `ended_at TEXT NULL`；索引 `(created_at)`、`(status)` |

- 不新增 provider 表；不改 `capability_packs` 结构。
- 备份：三张新表按「可选轨」纳入导出（缺文件按 0 降级），备份 schema 版本不变；M1 时确认。

## 5. API 与 UI

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/capabilities/sample?kind=<kind>` | 六类示例/模板包下载 |
| GET | `/api/subagents/providers` | 提供方列表与可用性 |
| POST | `/api/subagents/runs` | 发起运行（先审批） |
| GET | `/api/subagents/runs?limit=` | 运行记录 |
| POST | `/api/subagents/runs/:id/cancel` | 取消（杀进程树） |

- `/capabilities`：kind 筛选、effect 详情、六类示例下载；新增「外部代理」区（开关/命令/参数/超时/可用性测试/运行表单/运行记录/取消）。
- `/reports`：新增「能力包卡片」区。
- `/settings`：事件剧本列表标注「来自能力包」并支持试运行；外部代理配置与能力包页共用同一设置源。
- `/approvals`：支持 `source='subagent'` 的来源标签与深链。

## 7. 验收用例

1. 六类示例包下载成功；五类一键安装后立即可用（工作流可试运行、动作进动作池、剧本可试演、卡片出数字），停用后效果消失，卸载无残留；`mcp` 模板安装返回 422 并提示需替换端点。
2. 坏包逐类拒绝：`workflow` 图非法 / `pet-action` 非 VRMA 或扩展缺失 / `event-script` 非 `usr.*` 或台词缺 `text` / `report-widget` 未知 metric 或 windowDays / 缺 checksums / 路径穿越。
3. 工作流卸载：无运行无端点删行；有运行或端点保留 disabled 行并在列表标注来源已卸载。
4. 事件剧本受导演三道锁约束；重复 id 409；停用后短语不再触发。
5. 外部代理：未开启零影响；拒绝审批不 spawn；超时/取消/输出超限收敛正确且进程树回收；cwd 非法拒绝；证据可在运行记录与时间线查到；回投只写一条助手消息。
6. `pnpm check`、四层测试、300 行门禁、Web 全量生产模式 e2e、桌面冒烟不降级；迁移 v040 纯加法，旧库可读。

## 8. 与方案的偏差

1. `mcp` 示例降级为模板包（方案原写「六类各 1 个最小示例」），原因见 D10；成功指标改为「六类可下载，五类一键生效」。
2. 事件剧本只支持短语触发（方案未限定触发方式），意图/上下文触发列 P1。
3. 外部代理配置使用 settings JSON（方案未指定存储），不新增 provider 表。

## 9. Non-Goals

- 不做远程市场、自动更新、签名强制校验。
- 不做任意脚本/任意代码加载；能力包仍只是既有资源类型的登记与装卸。
- 不做 ACP/SDK 与多 provider 管理（P1）。
- 不把外部代理暴露为模型工具（P1 再评估）。
- 不做工作流包的自定义节点类型、桌宠动画图 step、报告页查询编辑器。
- 不共享宿主供应商密钥，不把子进程输出原文写入事件日志。
