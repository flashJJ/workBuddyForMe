## 2. 关键语义

- 台词 `text` 只走纯气泡/TTS，不做 i18n 解析；内置剧本继续使用 `lineKey`，运行时行为零变化。
- 能力包剧本不再伪造内置 id：导演按传入定义直接准入，不进入 `getBuiltInEvent` 白名单，避免覆盖/顶替内置剧本。
- 短语匹配沿用既有 `matchAnyPhrase`（本地包含、不区分大小写、不上网）；同一消息命中多个剧本时按安装顺序逐个交导演排队。
- 卡片数字每次请求现算，不落快照；停用即从报告页消失，历史运行记录不受影响。
- 卡片与剧本的 payload 校验均在启用时执行，坏包停用后仍可卸载。

## 4. 与 M0 的偏差

1. **导演注册表落点**：M0 写「写行 → 重载导演剧本注册表」；实现为「存储行 + 客户端拉取启用剧本 → 短语命中后按定义准入」。导演仍以 `admit(def, ctx)` 统一过锁，未新增全局可变注册表单例，避免跨会话/跨助手状态串扰。
2. **设置页剧本列表与试演**：M0 §5 要求 `/settings` 标注来源并可试运行；本里程碑只完成数据/触发链路，列表与试演并入 M4 管理页收口（与能力包 kind 筛选、effect 详情同批）。
3. **示例表达式标签**：M0 示例 JSON 写 `"tag":"happy"`，而表达式白名单为 `joy/anger/sadness/...`；实现改用 `joy`，M0 文本视为笔误。
4. **`mcp` 示例命名**：M0 写「`com.example.<kind>` 统一外壳」，实现按 v2.10 既有 id `com.example.sample.mcp-template` 保持稳定链接与测试断言。
5. **剧本卸载**：M0 表只写「删行」；实现同时在 `uninstallCapabilityEffect` 增加 event-script 分支（workflow 之外唯一需要额外清理的 kind），卡片删行由 disable 已完成，未重复。
