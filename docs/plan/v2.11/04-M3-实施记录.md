## 2. 关键语义

- 默认零影响：未启用或命令为空时注册表为空，`/api/subagents/providers` 返回空列表，核心功能不感知。
- 运行审批拒绝/超时（5 分钟）不启动进程，运行记录收敛为 `cancelled`，`errorCode=approval_denied / approval_timeout`；用户取消为 `cancelled`。
- 子进程 permission 帧拒绝只回写 `{"type":"permission_result","allow":false}`，不强制终止子进程；运行审批未通过时不会出现 permission 帧。
- 终态映射：`done` → done；`error` → failed（`budget_exceeded` 映射同名状态）；超时/输出超限/协议错误/子进程退出均 failed 且保留机器码。
- 审批被拒也会写 `subagent_finished` 事件（证据完整性），但不产生 `subagent_started`。
- `cwd` 只接受用户显式输入；拒绝 UNC 与系统目录，符号链接 realpath 校验按 M0 留待 P1。
- 命令与参数不经 shell、不注入任何供应商密钥；只传最小环境变量白名单。

## 4. 与 M0 的偏差

1. **提供方接口扩展**：`SubagentProviderInput` 增加 `cwd` 与 `requestPermission`，`SubagentProviderResult` 增加 `errorCode / outputBytes`；旧提供方忽略新字段即可兼容。
2. **UI 落点**：M0 §5 把外部代理区放在 `/capabilities`；M3 先落在 `/settings`「工具与权限」，与设置源同页，`/capabilities` 区与运行下钻并入 M4。审批深链仍按 M0 写 `/capabilities?run=`（M4 接管跳转目标）。
3. **cwd 选择**：M3 用文本输入 + 服务端校验；桌面原生目录选择并入 M4（不改变安全口径）。
4. **`.bat/.cmd` 不支持**：`shell:false` 下 Node 无法直接 spawn 批处理脚本；命令解析直接视为不可用，避免「可用但必失败」。
5. **审批过期**：审批注册表本身不做定时过期，外层服务用 `expiresAt` + 进程内计时器实现超时拒绝；与 v2.7 收件箱语义一致。
6. **终态证据**：审批被拒的运行仍写 `subagent_finished`（M0 只要求终态可查，未区分是否 spawn）。
7. **设置实例**：容器经 `subagent-wiring` 另建一个无状态 settings 服务读取同一 `settings_kv`，避免主容器继续增长（容器 299 行）。
