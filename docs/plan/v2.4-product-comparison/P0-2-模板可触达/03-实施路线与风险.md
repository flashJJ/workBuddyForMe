# P0-2 实施路线与风险

> 只给任务拆解与验收口径，**不含工时**。顺序：先「空态可见」，再「一键起手」，最后「分类与标注」。

## 1. 任务拆解

| # | 任务 | 验收口径 | 主要落点 |
|---|---|---|---|
| **T1** | **统一模板清单**（单一事实源） | 清单条目数 == 三套 `ensure*` 播种结果；类型完整（kind/name/desc/group） | 新增 `apps/web/src/lib/templates/starter-templates.ts` |
| **T2** | **`TemplateGallery` 组件** | 卡片含名称/说明/来源徽标/主按钮；空态与顶部折叠入口两种呈现 | 新增 `apps/web/src/components/common/template-gallery.tsx` |
| **T3** | **知识库 + 工作流接线**（复制为自建） | 点「以此开始」生成可打开、可改名、可删的实例 | `features/knowledge/knowledge-page.tsx`、`features/flows/flows-list-page.tsx` + 各自 mutation |
| **T4** | **技能 + 助手接线**（直接启用 / 预填表单） | 技能可一键启用；助手模板落到表单且可改后保存 | `features/settings/skills-panel.tsx`、`features/assistants/assistants-page.tsx` |
| **T5** | **来源徽标 + 分类推荐 + 列表标注** | 列表可区分内置/自建；分组与「推荐先用」可见 | 五个列表 + i18n（zh/en） |

## 2. e2e 与门禁

- 扩展空态用例：五个列表各断言「模板卡片可见 + 来源徽标正确 + 「以此开始」可产出实例」。
- 断言模板数量**来自接口而非硬编码**（A4），避免播种变更后测试失真。
- 门禁沿用：`pnpm check`（typecheck / lint / 单文件 ≤300 行）+ `pnpm test` + 全量 e2e；新增文案过 en-coverage。

## 3. 风险与红线

| 风险 | 影响 | 对策 |
|---|---|---|
| 空态「多一层」反而更绕 | 首屏更复杂，反而降低效率 | 空态只露一次；列表顶部只留可折叠入口（待拍板 1） |
| 模板过多选择困难 | 用户停在选择上 | 固定 3 类分组 + 每组标「推荐先用」+ 卡片写适用场景 |
| 「以此开始」语义分叉 | 用户以为建的是内置对象，实际是副本 | 卡片与结果都明示「已为你复制一份，可改可删」 |
| 复制语义与内置只读冲突 | 出现可删内置条目 | 复用角色卡范式：内置只读、删除隐藏、修改走复制 |
| 模板清单与播种实现漂移 | 卡片与实际内置不一致 | 清单由 `ensure*` 的常量**映射**得出，不做第二份数据 |
| i18n / 行数门禁 | 提交被拦 | 文案双语；`TemplateGallery` 与新清单各自独立文件且 ≤150/≤300 行 |

## 4. 明确不做

- 不做模板市场 / 云下载 / 模板分享（本地优先）。
- 不做「用内置内容覆盖用户内容」。
- 不为模板新增数据库表（模板仍是播种 + 复制的形态）。
