# P0-2 功能设计

> 目标：五个列表的模板**看得见、点得动、知道是内置**；且不改动既有「只增不改」的播种纪律。

## 1. 验收口径（可自动化）

| # | 验收 | 判定方式 |
|---|---|---|
| A1 | 五个列表**空态**均出现模板卡片区（不再是单按钮/空文案） | e2e 逐列表断言卡片数量与来源徽标 |
| A2 | 每张模板卡「以此开始」可产出一个**可用实例** | e2e 点击后断言实例存在且可打开 |
| A3 | 列表内可区分**内置（不可删）**与自建（可改可删） | e2e 断言徽标 + 操作按钮差异 |
| A4 | 模板数量与 `ensure*` 播种结果一致（不硬编码） | 断言卡片数 == 接口返回的内置条目数 |

## 2. 功能设计

### 2.1 F1 · 统一 `TemplateGallery` 组件

- **props**：`{ title, description, groups: Array<{ label, items: TemplateItem[] }>, onStart }`；
  `TemplateItem = { id, name, description, badge: 'builtin'|'custom', actionLabel }`。
- **卡面**：迷你预览（可选）或图标 + 名称 + 一句说明 + 来源徽标 + 主按钮「以此开始」。
- **落点**：`apps/web/src/components/common/template-gallery.tsx`（新文件，≤150 行，避免撞 300 行门禁）。
- **呈现位置**：接在各列表 `EmptyState` 的 `action` 槽位**下方**（空态露一次），并在列表顶部留一个可折叠的「内置模板」入口（待拍板 1）。

### 2.2 F2 · 五处接线（逐类定义「以此开始」语义）

| 列表 | 模板数据源 | 「以此开始」语义 | 落点 |
|---|---|---|---|
| 知识库 | `ensureStarterKnowledgeBases` 的 3 个内置 KB | **复制为自建库**（内置只读，复制后改名可删） | `features/knowledge/knowledge-page.tsx` + 创建 mutation |
| 工作流 | `ensureStarterFlows` 的 6 个已发布 flow | **复制为可编辑草稿**（保留节点图，另存新 id） | `features/flows/flows-list-page.tsx` + flow create/clone |
| 技能 | `ensureBuiltinSkills` 的 3 个技能 | **直接启用**（技能是全局启停，内置不可删） | `features/settings/skills-panel.tsx` + 技能启停 mutation |
| 助手 | 角色卡 + 内置助手的组合预设（如「周报助手 = 通用助手 + 周报技能」） | **预填新建助手表单**（不直接落库，用户可改后保存） | `features/assistants/assistants-page.tsx` + 表单初始值 |
| 角色卡 | `built-in-cards` 的 6 张 | 已有：**复制为自建卡** | 复用现有实现，不重写 |

> 关键取舍：**不复用「内置对象本身」作为用户资产**——内置对象只读且不覆盖用户改动，
> 用户需要的是「一份可改的副本」。这与既有角色卡范式一致。

### 2.3 F3 · 来源徽标与列表内标注

- 列表行复用角色卡的做法：`badge`（内置 / 自建），内置条目**隐藏删除**、编辑需走「复制」。
- 内置条目的 `title` 提示补一句「内置模板，可复制后修改」。

### 2.4 F4 · 分类与推荐

- **M0 细化（取代原「固定 3 类」）**：不做跨类全局分组——模板按所属列表展示（每列表一类），
  仅「助手预设」内按用途分组；**每列表首条标「推荐先用」**（见 [M0 契约冻结 D6](../M0-契约冻结.md)）。
- 说明文案写明**适用场景**（如「研究资料：把网页/文档整理成带引用的结论」），避免只给名字。

### 2.5 F5 · 单一事实源（与 P0-1 复用）

- 新增 `apps/web/src/lib/templates/starter-templates.ts`：把三套 `ensure*` 的内置条目
  **统一导出为一份清单**（`{ kind, id, name, description, group, recommended }`）。
- 用途：① 本项的五处模板区；② P0-1 的 `firstAsk` 示例问题；
  ③ 未来「模板市场」的前置数据。**只在 web 侧做映射，不改 `packages/*` 的播种实现。**

## 3. 红线

1. **不改播种纪律**：内置模板固定 id、幂等、「只增不改、不覆盖用户改动」。
2. **不覆盖用户改动**：本轮不引入任何「用内置内容覆盖用户内容」的路径。
3. **不做模板市场**：不下载、不联网、不做分享（本地优先）。
4. 新增文案走 i18n zh/en 双档；新组件 ≤150 行、单文件 ≤300 行。
