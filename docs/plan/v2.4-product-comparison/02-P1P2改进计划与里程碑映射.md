## 2. P1 计划（4 项）

### P1-1 运行可信度统一与失败归因

- **现状**：三条链路（任务 / 协作 / 工作流）各自可见性都不弱，但**分散在三处**、口径不一，且缺「汇总成功率/耗时」与「失败原因 + 下一步」的人话归因。
- **增量**：① 统一跨 task / agent-run / flow-run 的**状态枚举 + 失败原因字段 + 耗时口径**；
  ② 失败归因文案（把原始 error 映射为「为什么失败 + 你能做什么」）；③ 把协作的「舞台只读观看」前移为**默认起步**之一，写操作显式授权。
- **验收**：任一失败运行都能在 UI 得到「原因 + 下一步」；三条链路状态/耗时口径一致。
- **范围**：`features/tasks`、`features/agent-collab`、`features/flows`、i18n。

### P1-2 能力可见性

- **现状**：助手卡片已展示模型 / 知识库 / 参数（[assistant-card.tsx:29-33](../../../apps/web/src/features/assistants/assistant-card.tsx#L29-L33)、[L77-90](../../../apps/web/src/features/assistants/assistant-card.tsx#L77-L90)），但**技能与 MCP 不可见**；表单只有**工具级** `enabledTools`（[assistant-form-dialog.tsx:60-88](../../../apps/web/src/features/assistants/assistant-form-dialog.tsx#L60-L88)、[L187-226](../../../apps/web/src/features/assistants/assistant-form-dialog.tsx#L187-L226)）；内置技能文案口径不一致（[builtin-skills.ts:71-89](../../../packages/core/src/skills/builtin-skills.ts#L71-L89) 写「再让助手启用本技能」）。
- **增量**：① 助手卡片补「技能 / MCP 工具」区；② 表单加**助手级技能勾选**（与工具级区分）；③ 修正内置技能文案口径；④ 对话页头部展示当前助手能力摘要。
- **验收**：对话内可见「当前助手挂了什么」；表单可选技能且生效；文案与实现一致。
- **范围**：`features/assistants/assistant-card.tsx`、`assistant-form-dialog.tsx`、`features/chat`、`packages/core/src/skills/builtin-skills.ts`（文案）、i18n。

### P1-3 一致性收口（口径修正后）

- **现状**：原生控件已归零；命令面板/快捷键已有。
- **增量（剩余项）**：① 窄窗三尺寸与长文本/长路径溢出**复核**（v2.3 做过一轮，需最终确认）；
  ② **状态语言统一**（空态 / 加载 / 错误 / 无权限在五个列表与三个运行页一致）；
  ③ **命令面板覆盖度**核对（是否覆盖「新建 KB / 工作流 / 助手 / 角色卡」等高频动作）；
  ④ 快捷键浮层与真实绑定核对（[shared/constants/keyboard-shortcuts.ts](../../../packages/shared/src/constants/keyboard-shortcuts.ts)）。
- **验收**：三尺寸无横向溢出；空态/错误态在五个列表用同一组件与同一语气；命令面板覆盖高频动作清单。
- **范围**：`components/common/state.tsx` 调用点、`app-sidebar`/`page-header`、`features/command-palette`、`features/shortcuts`、i18n。

### P1-4 首字与长回复体感

- **现状**：SSE 消费在 [use-chat-stream.ts:38-165](../../../apps/web/src/lib/hooks/use-chat-stream.ts#L38-L165)（**无渲染节流**）；Markdown 走 react-markdown **全量渲染**（[markdown.tsx:8-28](../../../apps/web/src/features/chat/markdown.tsx#L8-L28)）；取消已有（Composer 停止），**降级提示缺**。
- **增量**：① 增量渲染节流（rAF/分片提交）；② 长回复 Markdown 渲染优化（按块渲染 / 长列表虚拟化）；③ 慢模型「进度 + 取消 + 降级建议」提示；④ 首字延迟本地可见指标（与 [P0-1](P0-1-零配置首启/02-功能设计.md) 的自检复用同一口径）。
- **验收**：长回复（≥5k 字）滚动不掉帧；本地慢模型有明确进度与降级建议。
- **范围**：`lib/hooks/use-chat-stream.ts`、`features/chat/markdown.tsx`、`features/chat/chat-page.tsx`。

## 5. 依赖与冲突提示

- **P0-1 的 `firstAsk` 与 P0-2 的模板清单必须同一批实现**，否则会各写一套示例问题。
- **P0-3 的档位映射与 P1-4 的进度组件共用视觉语言**；「进度 / 取消 / 降级」在三处（模型下载、长回复、任务运行）应统一。
- **P1-1 与 P1-2 都在改「运行 / 能力」的展示口径** → 建议同版本内**一次定稿枚举与文案**，避免二次返工。
- 全部受**单文件 ≤300 行**（新组件 ≤150 行）与 **i18n zh/en 双档**约束。
