## 2. e2e 与门禁

- 在既有 [voice-vad.spec.ts](../../../../tests/e2e/voice-vad.spec.ts)（假 worklet 驱动段序列）基础上**新增入口用例**：
  「未就绪 → 点击下载引导 → 就绪 → 一键进入免手 → 首段自动发送成功」。
- 下载接口用路由拦截 mock，断言**预估文案**与**二次进入不重下已完成文件**。
- 门禁沿用：`pnpm check` + `pnpm test` + 全量 e2e；新增文案过 en-coverage。

## 3. 风险与红线

| 风险 | 影响 | 对策 |
|---|---|---|
| 用户以为「一键开启」等于全双工 | 与豆包对比后失望更大 | 开启处明写半双工边界 + 「可打断播放」的实际能力 |
| 默认武装免手在嘈杂环境误触发 | 隐私与体验风险 | 保留一键切 PTT；灵敏度默认取「均衡」而非「高」 |
| 下载体积大、网速不可知 | 预估文案失真 | 文案写「约 X MB · 视网速而定」，不给假承诺；可取消可重试 |
| 磁盘占用未告知 | 用户事后不满 | 下载引导与偏好面板均显示落盘位置与占用 |
| 高档位映射与既有单测冲突 | 门禁红 | 档位→参数用**新增常量映射**，不改 `vad-config.ts` 已有映射语义 |

## 4. 明确不做

- 不做全双工（边听边说）——列入 P2 候选，不承诺。
- 不做云端语音（与本地优先冲突）——继续用本地 sherpa-onnx。
- 不做静默下载 / 预置模型权重。

## 5. 与其他项的关系

- **与 P0-1 同一范式**：P0-1 是「模型就绪即自检」，本项是「语音就绪即武装」——两者的
  「默认可用 + 成本透明 + 边界声明」交互语言应保持一致，建议同一版实现。
- **与 P1-4（延迟体感）** 共享「进度 / 取消 / 降级」的组件语言（下载进度与长回复进度条可复用同一视觉）。
