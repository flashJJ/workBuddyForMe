## 2. 差距（D1–D5）

### D1 参数前置：不懂就不能用
灵敏度（高/均衡/低）+ 尾静音（600/900/1200/1500ms）+ 半双工提示，全部平铺在设置面板上。
用户第一次开语音要先做三个技术判断——这正是「不如豆包」的直接体感来源。

### D2 模型下载缺「入口级」成本提示
体积/镜像/目录分散在设置页偏好面板，**第一次要用语音时**看不到「要下多少、等多久、能不能中断」；
下载虽有进度与取消，但没有「约 X MB · 视网速而定」这类预估文案，也没有失败后的重试引导。

### D3 没有「语音对话」这个心智
语音在 UI 上是「设置里的一个开关 + 对话页一个小按钮」。用户不会认为「这是一个模式」，
更像「一个需要我自己调好的高级功能」。

### D4 半双工边界未声明
当前「说完再听」，打断是播放中止（barge-in）。**这本身没问题**，但 UI 与文案没有声明这条边界，
用户会拿它和豆包的全双工实时语音比（那边是 Seeduplex「边听边说」），落差被放大。

### D5 两个默认值没有量化口径
「说完了」的判定（尾静音）与「打断响应」两个体感关键值没有对外口径（当前尾静音默认 900ms），
无法回归也无法解释「为什么它有时候等很久」。

## 3. 可直接复用的资产

- **模型清单与下载器**：体积、镜像、进度、取消、文件级跳过——全部已在，无需重写。
- **VAD 检测器**：灵敏度→起始倍率的纯函数映射（`vad-config.ts`），单测已覆盖。
- **免手编排**：段→ASR→发送与 barge-in 已实现，本项只做「入口 + 默认值 + 文案」。
- **既有测试**：`voice-vad.spec.ts` 用假 worklet 确定性驱动段序列，可作为新入口的 e2e 基础。
