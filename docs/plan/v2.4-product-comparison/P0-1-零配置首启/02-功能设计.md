# P0-1 功能设计

> 目标一句话：**全新安装 → 第一条有效回答 ≤ 60s，且至少有一条无需 API Key 的可用路径。**

## 1. 验收口径（可自动化）

| # | 验收 | 判定方式 |
|---|---|---|
| A1 | 全新数据根首启，**不填任何 Key**，60s 内发出第一条消息并收到回复 | e2e（走演示模式，无外网依赖） |
| A2 | 三条来源在向导内均可走通并得到「已就绪」反馈 | e2e 逐路径断言 |
| A3 | 演示模式在 UI 有显著标注（非真实模型），可一键关闭且无残留 | e2e + 设置页断言 |
| A4 | 首字延迟自检给出人话结论与「换来源」出口 | e2e 断言结论文案 |
| A5 | TTFV 里程碑本地可读（安装→模型就绪→首答） | 关于页断言 |

## 2. 三条「立即可用」来源

### 2.1 A · 演示模式（零配置、离线、链路真跑）

- **做法**：把现有 mock 兜底（`WBFM_MOCK_AI`）产品化成向导内**可勾选的「演示模式」**。
  勾选后在本机创建一个内置 `demo` 供应商（对话模型 `demo-chat`、向量模型 `demo-embed`），
  对话 / RAG / 工作流的**真实链路**（SSE 流式、检索、引用、工作流节点执行）全部照跑，仅**模型输出为确定性文本**。
- **标注**：凡使用 demo 模型处显示「演示模式（非真实模型）」徽标；设置页可一键关闭并清理 demo 供应商。
- **红线**：只在**本机**运行；不引入账号、不外发数据；关闭后无残留配置。
- **价值**：让「30 秒内看到产品在干什么」成立，且不背叛本地优先定位。
- **实现取舍**：复用现有 `WBFM_MOCK_AI` 的 mock provider 实现，**不新造假模型**；
  仅新增「用户可见开关 + 供应商落库 + 徽标」三件事。

### 2.2 B · 一键本地小模型（真模型、离线、可永久免 Key）

- **做法**：把「本地」从「给指引」升级为**可执行引导**：
  ① 检测（复用现有 `ob-ollama-detect` 链路）；② 未装 → 给系统级安装路径（Windows 安装包 / `winget` 命令）+ 安装向导说明；
  ③ 已装 → 「一键拉取推荐模型」，并在按钮上**明示体积、预计耗时、磁盘占用**。
- **推荐模型收窄到 1–2 个**，选型门槛：中文可用、纯 CPU 或 4–8GB 显存可跑、体积可控（**具体型号在 M0 用真机实测后冻结，不在本文拍板**）。
- **不做**：不内置权重、不做静默下载（必须显式确认），避免包体与首启带宽失控。

### 2.3 C · 厂商预设云（真模型、最少输入）

- **做法**：云端面板从「手填 `baseURL`」升级为「**厂商预设卡片 + 自定义**」：
  预设 6–8 家常用 OpenAI 兼容厂商，选中后自动填 `baseURL`，给「申请 Key」直达链接，
  并给该厂商的推荐模型名与能力（chat / vision / embedding）；选中后「添加模型」一键完成（复用 `inferModelCapabilities`）。
- **边界**：预设只存 `baseURL` 与模型名建议，**不写价格、不做计费承诺**（页脚标「以厂商官网为准」）。
  不做免费云兜底、不引入账号（见 §5 红线）。

## 3. 向导改造

### 3.1 第 2 步：由「二选一」变为「三选一」

- 内容升级为三张来源卡片：**「先试试（演示模式）」/「本地模型（Ollama）」/「云端 API」**；
  默认聚焦「先试试」；若已检测到本机 Ollama，则把「本地模型」提到首位并显示「已检测到 Ollama」。
- 任一路径 `onReady` 后显示「✓ 已就绪」并允许直接「下一步」。
- **低改动取舍（推荐）**：保留步骤 id `provider`（避免改动状态机单测与既有 e2e testid），
  仅替换该步内部内容；现有 `cloud-provider-panel` / `ollama-panel` 继续复用，新增一个「演示模式」面板。

### 3.2 新增：首字延迟自检与体感结论

- 来源就绪后执行一次**固定极短 prompt** 的首 token 计时（`time-to-first-token` + 总耗时）。
- 结论用人话给出三档：「预计首字 ≈ X s，体感流畅 / 偏慢但可用 / 超时，建议换来源」，并给「换一个来源」按钮。
- 只在**用户已选定的来源**上测，不额外调用其他厂商；prompt 为固定常量，**不含用户数据**。

### 3.3 新增 `firstAsk` 步：把终点推到「第一次成功对话」

- 在 `finish` 之前新增一步，给 2–3 个**预置示例问题**（按已就绪能力动态筛选）：
  - 通用：「帮我写一条把这件事说清楚的周报」
  - 有知识库模板时：「用『产品需求』模板总结一段需求」
  - 有语音时：「用语音和我聊两句」
- 点选示例 → 创建对话、以默认助手发出该问题 → 落到 `/chat` 看到流式回复。**这一步即 TTFV 的终点。**

### 3.4 空态统一

- [chat-setup-guide.tsx](../../../../apps/web/src/features/chat/chat-setup-guide.tsx) 的按钮由「去设置」改为**「打开配置向导」**（复用 `reopenOnboarding()`），
  文案标注「三种搞法，最快 30 秒」。

## 4. 可观测（本地、不出机）

- 新增本地里程碑（沿用现有设置本地存储即可，**不新建云上报**）：
  `first_launch_at` / `first_model_ready_at` / `first_answer_at` / `ttfv_ms`。
- [about-panel.tsx](../../../../apps/web/src/features/settings/about-panel.tsx) 展示一行 TTFV（可清除）；供回归与自评。
- 隐私：仅计数与时间戳，**不含任何对话内容**。

## 5. 文案与红线

1. **演示模式必须醒目**（徽标 + 说明），不得让用户误认为真实模型能力。
2. **不引入云端账号、不做数据外发、不做静默下载**。
3. 所有新增文案走 **i18n zh/en 双档**（en-coverage 测试为门禁）。
4. 步骤组件沿用 v1.2 纪律：**每步 ≤150 行/文件、状态机纯函数可单测**。
