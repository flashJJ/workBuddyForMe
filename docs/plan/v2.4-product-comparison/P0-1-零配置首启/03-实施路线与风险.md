# P0-1 实施路线与风险

> 本文只给任务拆解与验收口径，**不含工时与排期承诺**；落地顺序按「先让不填 Key 也能用」定。

## 1. 任务拆解

| # | 任务 | 验收口径 | 主要落点 |
|---|---|---|---|
| **T1** | **演示模式产品化**：内置 `demo` 供应商 + 用户可见开关 + 全局徽标 + 一键关闭清理 | 不填 Key 可对话并看到徽标；关闭后无残留、正式链路不受影响 | `lib/server/container.ts`、`shared/constants`、`features/settings`、`features/chat` |
| **T2** | **第 2 步改三选一**（保留步骤 id `provider`）+ Ollama 提前探测 | 三条路径均可得到「已就绪」；已装 Ollama 时本地卡片优先 | `features/onboarding/steps/*`（新增演示模式面板）、复用 `cloud-provider-panel` / `ollama-panel` |
| **T3** | **厂商预设 + 模型建议**（含 Key 申请直达、页脚免责） | 选厂商自动填 `baseURL`；一键添加推荐模型 | 新增 `shared/constants/provider-presets.ts`、`cloud-provider-panel.tsx`（域名 `apps/web/src/features/onboarding/steps/`） |
| **T4** | **一键本地小模型引导**：安装路径可执行化 + 推荐模型收窄 + 体积/耗时明示 | 未装 Ollama 时有可执行指引；已装可一键拉取；按钮明示体积与预计耗时 | `apps/web/src/features/onboarding/steps/ollama-panel.tsx`、i18n |
| **T5** | **首字延迟自检与体感结论** | 就绪后给出三档结论文案 + 「换来源」出口 | 新增 `use-first-token-probe`（`apps/web/src/features/onboarding/`） |
| **T6** | **`firstAsk` 步 + 预置示例问题** | 点示例即发问并落到 `/chat` 看到流式回复 | `features/onboarding`、`features/chat` |
| **T7** | **空态统一 + TTFV 里程碑** | chat 空态可调起向导；关于页可见 TTFV 且可清除 | `features/chat/chat-setup-guide.tsx`、`features/settings/about-panel.tsx` |

**最小可验收集**：T1 + T2 —— 做完即可断言「不填 Key 也能用」（A1/A2/A3）。
T3–T7 增量交付，不阻塞最小集验收。

## 2. e2e 与门禁

- 扩展 [tests/e2e/00-onboarding.spec.ts](../../../../tests/e2e/00-onboarding.spec.ts)：
  新增「不填 Key → 演示模式 → 首答成功」端到端；断言 TTFV ≤ 60s（走 mock，无外网依赖）。
- 新增 `ob-source-*` / `ob-firstask-*` testid 断言；**保留现有 `ob-tab-*` / `ob-ollama-detect`**（或同步迁移，不得静默删除）。
- 门禁沿用：`pnpm check`（typecheck / lint / 单文件 ≤300 行）+ `pnpm test` + 全量 e2e；
  新增文案必须过 **en-coverage**（zh/en 双档齐全）。

## 3. 风险与红线

| 风险 | 影响 | 对策 |
|---|---|---|
| 演示模式被误当真实模型 | 信任受损（一旦被识破代价很大） | 全局徽标 + 向导文案明示；可选是否作为默认路径（见待拍板） |
| 本地小模型下载慢/失败 | 首启卡住，反而更差 | 明示体积/耗时/磁盘；可跳过；失败可回退演示模式或云端 |
| 厂商预设长期漂移 | 预设过期误导用户 | 只存 `baseURL` 与模型名；页脚免责；不做价格承诺 |
| 无 Key 也想用真模型 | 与本地优先定位冲突 | 只由「本地 Ollama 真模型」满足；**不引入免费云兜底**（见待拍板） |
| 步骤组件膨胀 | 撞 300 行硬门禁 | 沿用 v1.2：每步 ≤150 行、状态机纯函数可单测、新面板独立文件 |
| 静默下载 / 数据外发 | 触碰隐私红线 | 下载必须显式确认；无遥测、无账号、无外发 |

## 4. 明确不做

- 不内置模型权重、不做静默自动下载。
- 不引入云端账号、免费云兜底、团队协作。
- 不做移动端原生 App（与「数据不出机的桌面工作台」定位冲突）。
- 不把演示模式做成「伪装真实能力」——必须可见、可关、可解释。

## 5. 与其他项的关系

- 本项是 [竞品体验对比 §4.2](../01-竞品体验对比与差距诊断.md) 中的 **P0-1（首启闸门）**，建议在 v2.3 收口后优先立项。
- **P0-2（模板可触达）** 与本项的 `firstAsk` 有耦合：示例问题应优先取自「已播种的内置模板」，
  两项可共享同一份「示例/模板」清单，避免各写一套。
- **P0-3（语音可对话）** 的「一键开启」入口与本项 T5 的「来源就绪即自检」同属「默认可用」范式，交互语言应保持一致。
