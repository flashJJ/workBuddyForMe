## 1. 当前基线

v4.9 只做了轻量三层上下文（场景策略 / 预算 / 快照），v4.20 与 v4.21 分别把性能与记忆收口。编排侧仍有两处结构性欠账：

- 上下文装配分散在对话、协作、任务、Flow 四处，任务上下文（摘要 / 事实 / 计划 / 近期对话 / 记忆）仍是一个顺序拼装的函数，没有统一的「采集 → 来源 → 装包」分层；
- Flow 引擎严格按 Kahn 拓扑序串行执行：`start → A → B → end` 的扇出图在第一个 `end` 命中后就收尾，其余分支被标记 skipped，所谓「并行分支」实际只有一条会跑完；
- 并行缺少预算共享、幂等与失败隔离的既定语义，直接开并发会出现重复副作用、预算超卖与一处失败全图中断。

## 2. 候选方案

### 方案 A「会编排」——Controller Pipeline + Flow 并行调度（推荐）

**痛点**：装配不可复用、Flow 扇出跑不全、并行语义未定义。

**做法**：

1. 新增纯函数三层：`collector`（多来源采集，单来源失败隔离）→ `packer`（优先级排序、去重、预算裁剪、稳定顺序）→ 场景装配；先接任务上下文，行为与现状等价；
2. Flow 图增加可选 `parallelism`（1–4，默认 1）；引擎在就绪集合上并发执行可并行节点，`maxConcurrency=1` 时事件序列逐字不变；
3. 并行语义收口：流程级工具预算共享、节点幂等键 `${runId}:${nodeId}`、单节点失败隔离与后代跳过、首个成功 end 决定运行结果；
4. 观测：`run_started` 增加 `parallelism`，节点事件保留 `durationMs`；不新增事件类型。

**验收**：装配结果与现状等价（单测逐字对比）；并行扇出图两条分支都执行且并发度不超上限；单分支失败不影响无关分支；同一运行内节点不重复执行。

**成本/风险**：中高。引擎改动集中，但并发与事件顺序需要严格回归；以默认关闭 + 并发=1 逐字等价兜底。

### 方案 B「视觉巡检 L2/L3」

**痛点**：L1 只有截图与尺寸检查，语义断言与人工流程未自动。

**成本/风险**：中。依赖外部视觉工具链与 VLM 凭据，与本地优先边界冲突，价值密度低。

### 方案 C「记忆社区聚类」

**痛点**：长期挂账的记忆主题簇摘要。

**成本/风险**：高。不可解释、不可验收，已在路线图永久关闭。

### 方案 D「文档存量重解析」

**痛点**：存量文档、OCR 与关系抽取欠账。

**成本/风险**：中高。需要独立评测集，容易变成长期项目。

## 5. 初步范围

### 5.1 Controller Pipeline

- `collector`：注册式来源（会话摘要、结构化事实、当前计划、近期对话、长期记忆），并行采集，单来源失败只记录状态；
- `packer`：按声明优先级排序，按 key 去重，超预算时从最低优先级尾部裁剪，输出稳定；
- 任务上下文改为 collector + packer，输出与 v4.21 逐字一致；协作 / Flow 的提示词仍走 `fitPromptMessages`，不重写。

### 5.2 Flow 并行调度

- 图契约增加可选 `parallelism`（1–4，默认 1）；
- 引擎维护就绪集合：所有前驱已终止且节点激活时启动，执行中数量不超过并发上限；
- 可并行节点：`llm`、`knowledge_search`、`condition`、只读 `tool`、`end`；`human`、写/危险 `tool`、`agent` 节点串行（保持授权与交互时序）。

### 5.3 并行语义

- 预算：流程级工具预算全分支共享，超限分支返回拒绝结果而不中断其他分支；
- 幂等：节点执行键 `${runId}:${nodeId}`，同一运行内重复调度直接复用结果，不重复产生副作用；
- 隔离：并发 > 1 时单节点失败只标记自身 failed 并跳过其未执行后代，其他分支继续；运行最终 `run_failed` 汇总首个失败。

## 6. 已决策（2026-11-23，M0 输入）

1. **并行开关位置**：图 JSON 可选字段 `parallelism`（1–4，默认 1），读旧图回落 1；不新增设置页与数据库列。
2. **可并行节点**：`llm` / `knowledge_search` / `condition` / 只读 `tool` / `end`；`human`、写/危险 `tool`、`agent` 串行，避免授权与交互时序错乱。
3. **失败语义**：并发 = 1 保持现有快速失败；并发 > 1 才启用失败隔离（失败节点后代 skipped，其他分支继续）。
4. **幂等范围**：进程内按 `${runId}:${nodeId}` 记忆一次执行结果，不落库；运行结束即释放。
5. **结果收敛**：编译器「非 end 节点单入边」不变；多个 end 时按拓扑序取首个完成的成功 end 作为运行输出，其余仅记事件。
6. **迁移**：零迁移；`parallelism` 为图 JSON 增量字段，不改变数据库 schema 与备份格式。
