# 04 · 实施路线与风险（v1.0 Voice Companion）

## 1. 里程碑与任务拆解

### M0 契约与 Spike —— ✅ 已完成（2026-10-06）

- [x] 分支 `feature/v1.0-voice-companion`（基线 tag v0.9.0）
- [x] `@wbfm/voice` 包骨架：引擎接口、WAV 编解码、流式切句、状态机、模型清单（35 单测）
- [x] shared：语音设置/HTTP zod 契约 + 默认值；SSE `voice_audio/voice_state`
- [x] database：v014 `voice_models` 迁移 + runner 注册（2 单测）
- [x] Spike A：sherpa-onnx-node 1.13.8 Node 24 真机 TTS→ASR 闭环 PASS
- [x] Spike B：Electron 透明窗冒烟 PASS；`PetClickThroughController` 滞回（8 单测）

### M1 会说（TTS） —— ✅ 已完成（2026-10-06）

1. ✅ `engine/sherpa/tts-engine.ts`：绑定封装、dict/fst 映射、speaker 越界回落、dispose（6 测）。
2. ✅ `models/downloader.ts`：镜像流式下载、进度、取消、.part 原子改名、大小校验（5 测）。
3. ✅ `/api/voice/tts`、`models/status`、`models/download`、`voice/settings` 路由；v014 `voice_models` 仓储（4 测）。
4. ✅ chat/stream 旁路语音桥 `withVoice`：文本先放行→增量/全文差分→切句合成→voice_audio + voice_state，单句失败降级字幕（4 测）；默认纯文字路径零语音事件。
5. ✅ 客户端 `AudioPlaybackQueue`（串行/取消/final，4 测）+ WebAudio 播放器 + `useVoicePlayback`；对话页朗读开关（持久化）；停止/reset 联动取消。
6. ✅ 打包：prepare-server FALLBACK_PACKAGES 与 next.config external/trace 均加 sherpa 两包。
- **真机验收**：应用下载器经 API 完成 17 文件（191MB）：进度→大小校验→DB ready（92s）；稳态合成约 **1.1s/句（约 1.4x 实时，44.1kHz）**；带语音 SSE 对话全闭环（speaking→4 帧 WAV→idle）；纯文字流 0 个 voice 事件。
- **关键取舍（实测）**：Node onnxruntime 1.28 在本机 Arrow Lake（无 AVX512-VNNI）上 int8 量化内核退化到 0.25x 实时，**fp32 达 1.5x**；TTS 清单改用 `model.onnx`（fp32，163MB）。ASR SenseVoice int8 不受影响。同机 Python int8 正常（1.7-2.6s），差异在 Node onnxruntime 量化内核。

### M2 能听（ASR） —— ✅ 已完成（2026-10-06）

1. ✅ `engine/sherpa/asr-engine.ts`（SenseVoice 配置、ITN、16k 校验、缺模型 hint，7 测）。
2. ✅ `/api/voice/asr`（multipart→WAV 解码→必要时重采样→引擎）；runtime ASR 惰性单例与配置失效（线程/目录）。
3. ✅ `use-voice-recorder` PTT（getUserMedia 单声道→0 增益落地 ScriptProcessor→16k 降采样→WAV，6 测）；最短 300ms 门限与权限/无设备/网络错误映射。
4. ✅ composer 麦克风按钮：按住说话（指针捕获，按下途中不切 disabled）→识别文本自动发送；受 `asrEnabled` 开关与模型就绪门控；权限/空语音 toast 引导。
5. ✅ 设置面板「语音」：ASR/TTS 下载管理（进度/取消/重试/错误）、语速/线程、TTS 试听、镜像与模型目录、麦克风设备自检（4s 电平判定）（3 组件测）。
6. ✅ e2e（mock 引擎 + Chromium fake mic）：面板开关、PTT 采集→RIFF WAV 上传→识别文本进对话→mock SSE 回复、关闭开关麦克风消失（4 测）。
- **真机验收**：应用内下载 SenseVoice 2 文件（**228MB**，hf-mirror，大小校验 + DB ready）；TTS→WAV→ASR 引擎闭环：识别"你好，这是离线语音识别的闭环测试。2026年10月6日。"、lang=zh、**ITN 生效**（二零二六年十月六日→2026年10月6日）；ASR 冷启 3.2s（含加载）/热态 **256ms（约 18x 实时，4.6s 音频）**；真人系统浏览器按住说话中文进对话 PASS。
- **关键修复**：① M1 遗留客户端包络双重解包（`apiGet<{data:T}>` 再取 `.data`），语音设置/模型状态在前端恒为 undefined，朗读与麦克风门控实际从未生效——改为直接消费解包后的 T；② PTT 首版在麦克风申请（requesting）阶段给按钮加 disabled，按下途中元素禁用导致活动指针被取消、无法长按——改为指针捕获 + 按下期间保持启用 + lostcapture 守卫；③ toast 自动关闭定时器在测试环境 teardown 后触发的 unhandled rejection，Provider 卸载时统一清理。

## 2. 测试策略（四层不降级）

- **纯函数单测（密集）**：voice 包切句/状态机/wav/下载器/设置契约；expression-parser；penetration 已建。
- **路由/服务**：引擎以接口 mock 注入，测 SSE 帧序、取消语义、错误降级；v0.9 纯文字路径回归（voice 默认 false）。
- **组件/Hook**：播放队列顺序与取消、录音 hook 用 fake MediaStream；设置面板交互。
- **e2e**：Playwright mock `/api/voice/*` 跑主窗语音对话；desktop e2e 跑桌宠窗生命周期。
- **真机取证**：每个 M 里程碑在 Windows 打包/真机记录关键数据（首句延迟、识别准确率主观 10 轮、CPU 占用）。

## 3. 风险与对策

| 风险 | 级别 | 对策 |
|---|---|---|
| sherpa 绑定 ABI/打包问题 | 中 | M0 已证 Node 侧可用；M1 已加 external/trace/FALLBACK 并完成下载+合成真机；降级链 onnxruntime-node → Python sidecar |
| Node int8 量化内核在部分 x86 CPU 退化（M1 已发生并解决） | 高→已处置 | Arrow Lake 实测 int8 0.25x/实时、fp32 1.5x；TTS 默认 fp32；ASR int8 经验证不受影响；真机验收必须记录速率 |
| CPU 上 14B+TTS 延迟 | 中 | 按句流式首句快出、线程可配（实测 8 线程更慢，默认 4）；稳态 1.1s/句；文档给小模型建议 |
| 透明窗边缘抖动/抢焦 | 中 | 滞回 180ms（已测）；复用 overlay 参数；focusable 策略 M4 手调 |
| 麦克风自激 | 中 | 半双工软闭麦 + VAD；不承诺免耳机，Non-Goal 写明 |
| Cubism 许可/体积 | 低-中 | 懒加载独立 chunk；About 许可声明；仅内置许可样本 |
| 范围膨胀 | 中 | 1 个模型、无 VRM/市场/云引擎；主动说话 P1；发布项顺延 v1.1 |

## 4. Non-Goals 复述
