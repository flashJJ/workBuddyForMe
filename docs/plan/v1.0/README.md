## 1. 一句话方案

让 WorkBuddy 从「只能打字的工作台」升级为「**能听、会说、有形、伴身的桌面伙伴**」：本地 sherpa-onnx 语音识别与合成、流式语音对话与可打断、Live2D 形象（口型/表情）、透明置顶鼠标穿透的桌宠窗——全程本地运行、零云服务、零强制费用。

## 2. 为什么做：v0.9 的能力断点

1. **只能打字**：全仓零音频能力（无 TTS/ASR/麦克风/Web Audio），对话必须盯着屏幕读字，无法「边干活边听」。
2. **没有人格化外形**：助手是侧栏里的一串配置，不是「在场」的伙伴；v0.7 已有屏幕感知与键鼠执行（「动得了手」），但缺一个可见可感的形象。
3. **不在桌面陪伴**：应用最小化即「消失」，没有轻量、常驻、半透明的桌宠形态。

v0.1-v0.9 解决了「闭环→会动手→什么都能读→数据随身→记得住→会接活→看得见动得了手→可编排→可服务化」，v1.0 补上最后一块拟人化交互：**语音与形象**。

## 3. 目标与非目标

### 目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 会说：回复可本地朗读 | 对话开关打开后，回复按句流式出声，首句延迟可接受（M1 真机记录） |
| G2 | 能听：语音输入闭环 | 说话→本地 ASR→进现有对话链路，识别文本与文字输入等价 |
| G3 | 有形：Live2D 形象 | 主窗可开关形象，口型随音频 RMS、表情随 `[标签]`、有待机动作 |
| G4 | 伴身：桌宠模式 | 透明置顶窗可拖拽/穿透/回主窗，桌宠同步说话与状态；边缘不抖动 |
| G5 | 本地优先不破 | 断网完成「说→听→答→读」全链路；语音数据不出本机、不入库 |
| G6 | 零回归 | 纯文字对话、Flow、MCP、桌面任务、知识库全部行为不变，全量门禁全绿 |

### 非目标（本版本明确不做）

- 代码签名/安装器打磨/深色完检/a11y 认证/i18n/帮助向导（原路线图 v1.0「正式发布」项）→ **顺延 v1.1**，路线图已同步修订
- 全双工免耳机回声消除（AEC）、唤醒词、连续流式 ASR；v1.0 为**半双工**（TTS 播放时软闭麦）+「停止即打断」
- VRM/3D、自定义模型导入 UI、模型市场；v1.0 仅内置 1 套 Live2D 样本模型
- 云 TTS/ASR 厂商实现（接口预留不实现）、语音克隆、TTS 翻译、语音群聊
- 桌宠的 macOS/Linux 适配（Windows 先行）

## 5. 关键设计决策（M0 已取证）

- **本地语音走 sherpa-onnx 官方 Node 绑定**（`sherpa-onnx-node` 1.13.8 + `sherpa-onnx-win-x64` 平台包）。M0 Spike 已在 Node 24（Next 服务端同款运行时）完成「MeloTTS 合成→重采样→SenseVoice 识别」真机闭环，Smart App Control 下原生 `.node` 加载正常。
- **语音跑在 Next 服务进程，不碰 Electron ABI**：生产态 `/api/voice/*` 由独立托管 Node 运行（v0.9 既有架构），无需 electron-rebuild；打包时把 sherpa 两个包加入 `prepare-server.mjs` 的 FALLBACK_PACKAGES。
- **模型不进安装包**：首用时下载到 userData（ASR int8 ≈228MB、TTS fp32 ≈163MB），默认 hf-mirror，大小校验；支持指定本地目录。M1 实测 Node onnxruntime 1.28 在无 AVX512-VNNI 的 CPU 上 int8 TTS 内核退化（0.25x 实时），TTS 选 fp32（1.5x 实时）；ASR int8 不受影响。
- **不照搬 VTuber 的 WebSocket**：沿用项目 HTTP+SSE 范式，新增 `voice_audio`/`voice_state` 两个 SSE 事件；对话仍走既有 orchestrator（记忆/技能/工具/Flow 全部白得）。
- **穿透滞回**：进入模型区立即可交互、离开延迟 180ms 才穿透（既往 Electron 项目边缘抖动教训固化为 `PetClickThroughController` 单测）。
- **半双工而非全双工**：用「播放中软闭麦 + 停止/急停打断」覆盖 80% 场景，AEC 复杂度不进入 v1.0。
