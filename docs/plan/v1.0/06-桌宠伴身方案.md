## 1. 目标与验收（F6）

**用户故事**：设置中打开「桌宠模式」，桌面弹出半透明置顶小窗角色陪在桌面；角色本体可拖动/点击互动，周围区域鼠标穿透不挡操作；双击角色回主窗；对话时桌宠口型与字幕同步、表情随回复切换；关闭/退出干净无残留。

| 编号 | 验收项 | 度量 |
|---|---|---|
| AC1 | 透明无边框置顶小窗，加载 `/pet`，任务栏不显示 | 窗口属性断言 + 真机目检 |
| AC2 | 穿透态点击落到下层应用；角色本体始终可交互；指针边缘抖动不翻转 | 滞回 180ms（已有 8 单测）+ 真人手测 30s 来回划 |
| AC3 | 角色区可拖拽定位，双击回主窗，右键菜单（回主窗/穿透切换/隐藏桌宠） | 真机逐项 |
| AC4 | 位置/穿透偏好重启保留；多屏拔出后自动回到可见区域 | pet-state 单测 + 真机 |
| AC5 | 对话时桌宠口型随朗读张合、表情随 8 标签切换、字幕按句显示 | 真机一轮带表情语音对话 |
| AC6 | 主窗与桌宠同一时刻只有一个声音出口；主窗隐藏（不退出）后朗读不断 | 真机：开桌宠→关主窗→发消息，有声音型同步 |
| AC7 | 关窗/退出干净：无残留透明窗、无残留进程、无孤儿音频 | desktop e2e + 任务管理器目检 |
| AC8 | 安全基线不破：contextIsolation/sandbox/preload 白名单最小权限；无桥时 `/pet` 不可裸用 | e2e + 纯浏览器访问 `/pet` 回落 |

## 3. 关键设计决策

### 3.1 主窗保持唯一聊天会话与音频管线，桌宠是「瘦终端」（v1 定案）

```text
主窗（唯一 chat/stream 订阅者、唯一 AudioContext）
  │ SSE voice_audio/voice_state 照常播放（窗口 hide 不销毁，音频继续）
  │ ScriptProcessor/audio 回调里读 Analyser RMS（不依赖 rAF！）
  │     节流 30Hz ──IPC pet:level──┐
  │ voice_state 变化 ─IPC pet:voice-state
  │ 切句/剥标签后文本 ─IPC pet:subtitle（限长 120 字）
  │ 表情标签 ─IPC pet:expression
  ▼                                ▼
主进程 pet-manager（转发 + open 状态广播）──► pet 窗 /pet
                                   Live2dCanvas（getLevel=最近电平值）+ 字幕气泡
                                   pet 端无麦克风、无 AudioContext、无聊天请求
```

**为什么这么定**：

- **否决「pet 独立订阅 SSE」**：会产生第二个 `/api/chat/stream` → 双份 TTS 合成、双轮状态、双计费（本地算力），竞态不可接受。
- **否决「隐藏主窗后用 rAF 中继电平」**：Chromium 对不可见窗口的 rAF/定时器会节流甚至冻结。音频图的 `audioprocess` 回调随音频渲染线程走，**只要在播音就持续触发**，作为电平源可靠。
- **音频不搬到 pet**（v1.1 再议「句间宿主切换」）：单 AudioContext、零大体积音频帧 IPC、选举只影响 UI。代价是主窗必须「隐藏而非销毁」——这本来就是桌宠应用的标准行为（§3.3）。
- **兜底**：若真机发现 hide 后个别机型音频挂起，退路是主窗 `setOpacity(0)` + 移出工作区保活（仍 visible），作为实测开关，不改协议。

### 3.2 命中测试：矩形命中盒 + 滞回，不做逐像素 alpha

- pet 窗尺寸裁成紧贴角色（默认 **260×340 DIP**），页面内放一个与模型身体重合的透明命中盒（约窗口宽 70%、高 85%，底对齐常量集中配置，真机微调到不挡角色周边操作）。
- `setIgnoreMouseEvents(true,{forward:true})` 穿透态仍能收 `mousemove`：页面在命中盒上 `pointerenter/leave`（rAF 节流）→ IPC `pet:hover` → 控制器 `update(hovering)`；离开 180ms 后才穿透（控制器已实现并测试）。
- 不做 WebGL `readPixels` 读 alpha（同步阻塞渲染管线）；PIXI 内部 hitTest 精修留 v1.1。

### 3.3 窗口生命周期与「关闭主窗」的新语义

- 新增 `isQuitting` 标志。主窗 `close`：**pet 存活时 `preventDefault()` + `win.hide()`**；真退出路径（应用菜单退出 / pet 右键隐藏且主窗已隐藏 / `before-quit`）置 `isQuitting=true` 放行。
- pet 关闭时：若主窗处于隐藏态 → 显示主窗并聚焦（不直接退出，避免用户找不到应用）；提供「退出应用」仅在主窗菜单。
- `window-all-closed` 维持退出（两窗都没了即走）；`will-quit` 统一 dispose pet 窗/控制器/写状态。
- 单实例 `second-instance`：主窗隐藏时恢复显示并聚焦。
- pet 窗 `showInactive()` 显示，**绝不抢当前应用焦点**；`focusable:true`（双击/右键需要），抢焦程度真机手调（风险表 R2）。

### 3.4 拖拽 / 点击 / 双击 / 右键的事件分工

- 角色命中盒 CSS `-webkit-app-region: drag` 承担拖拽（无边框窗标准做法，穿透态下整个窗口不接收事件，天然只有角色区可拖）。
- 右键菜单走**主进程** `petWin.webContents.on('contextmenu')` → `Menu.popup()`：穿透态右键根本进不来，无需自行命中判断。菜单项：回主窗 / 切换鼠标穿透（`controller.force(!v)`，勾选项同步 `petClickThrough` 偏好）/ 隐藏桌宠。
- 双击回主窗：命中盒 `dblclick` → `pet.focusMain()`（主窗 show+focus）。
- 单击挥手：命中盒 `click` → 复用 Live2D `tap()`（注意 app-region 下 click 派发真机验证；若被拖动手势吞掉，v1 退化为「头部小热区」按钮触发，拖动手势阈值内的 click 仍应派发，需手测，列入验收 AC3）。

### 3.5 pet 开启时主窗形象栏让位

pet 与主窗 rail 同时渲染同一模型 = 两个 WebGL 上下文 + 双倍贴图显存。规则：**pet 窗打开期间，主窗 `/chat` 不挂 `ChatAvatarRail`**（主窗收到 `pet:open-state-changed` 后卸载，口型/表情的中继仍由主窗语音管线产出，与 rail 是否挂载无关——电平从播放 hook 取，不从 canvas 取）。pet 关闭后 rail 按原设置恢复。

## 4. IPC 契约（白名单最小权限）

shared 新增类型（建议 `packages/shared/src/electron.ts`，与 updater 桥同处）：

```ts
export interface WbfmPetBridge {
  /** 主窗：打开/关闭桌宠（幂等）；返回当前是否打开 */
  open(): Promise<boolean>;
  close(): Promise<void>;
  isOpen(): Promise<boolean>;
  /** pet 窗：命中盒悬停结果（高频 send，主进程帧节流） */
  reportHover(hovering: boolean): void;
  /** pet 窗：双击回主窗 */
  focusMain(): void;
  /** pet 窗：订阅主进程中转的语音表现事件 */
  onPerformance(cb: (e: PetPerformanceEvent) => void): () => void;
  /** 主窗：中继语音表现（level 30Hz / state / subtitle / expression） */
  relayPerformance(e: PetPerformanceEvent): void;
  /** 主窗：订阅桌宠开关状态（用于 rail 让位） */
  onOpenChange(cb: (open: boolean) => void): () => void;
}

export type PetPerformanceEvent =
  | { kind: 'level'; value: number }            // 0~1 RMS，约 30Hz
  | { kind: 'state'; state: 'idle' | 'listening' | 'thinking' | 'speaking' }
  | { kind: 'subtitle'; text: string }          // 已剥表情标签、限长
  | { kind: 'expression'; tag: string }         // 8 标签之一
  | { kind: 'conversation' };                    // 切会话/清空字幕
```

- 主进程 channel 命名统一 `pet:*` 前缀；`ipcMain.handle` 用于 open/close/isOpen，`on` 用于高频/上报。
- 主进程只做**单 pet 窗转发**：`relayPerformance` → 唯一 pet webContents.send；pet 不存在时直接丢弃（不缓存）。
- 安全：无任何文件系统/壳能力；`/pet` 页加载时带与主窗相同的 token/baseUrl 注入（复用 window.ts 的 additionalArguments 拼装）。
- 裸浏览器（无桥）访问 `/pet`：页面检测 `window.wbfm?.pet` 缺失 → 渲染极简提示并 `router.replace('/chat')`，不初始化 Live2D。

## 5. 任务拆解（建议顺序，每个文件 ≤300 行）

### P1 主进程窗口与状态（可独立单测，0.5–1 人日）

2. `main/pet/pet-window.ts`：`buildPetWindowOptions(boot, state)` 纯函数（断言 frame:false/transparent/alwaysOnTop/skipTaskbar/resizable:false/show:false + 安全三件套 + token 注入）；`createPetWindow()` 加载 `${serverUrl}/pet`，`showInactive`，接 `contextmenu` 菜单。单测仿 `window.test.ts`。
3. `pet-penetration` 接线落在 manager，窗口文件不塞逻辑。

### P2 pet-manager 与主进程接线（1 人日）

4. `main/pet/pet-manager.ts`：单例 `open()/close()`；持有 win + `PetClickThroughController`（`setPenetrating=v=>win.setIgnoreMouseEvents(v,{forward:v})`）；`reportHover` 帧节流；右键菜单（回主窗/穿透勾选/隐藏）；`relayPerformance` 转发；open 状态广播；关闭时写状态。单测：用注入窗口假体验证 open 幂等、hover 转发、dispose、状态广播（controller 8 测已覆盖滞回本身）。

6. `preload/index.ts` + shared 类型：暴露 `window.wbfm.pet`。

### P3 Web `/pet` 页面（0.5–1 人日）

## 7. 真机验收清单（封版前逐项打勾，Windows 系统浏览器/打包态）

1. 开关注销/开窗：设置勾选 → 桌面右下出现角色；取消勾选 → 窗消失；重开应用后按 `petEnabled` 恢复。
2. 穿透：角色外区域可正常点击下层窗口/打字；鼠标移入角色立即可点，移出约 1/5 秒后穿透；边缘快速抖动不翻转。
3. 互动：拖到任意位置松手定位；双击回主窗；右键三项菜单可用且穿透勾选项持久化。
4. 重启：位置/穿透偏好保留；把窗拖到副屏后拔掉副屏（或改分辨率）→ 窗回到主屏可见区。
