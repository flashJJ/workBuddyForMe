# 03 · 技术架构设计（v1.0 Voice Companion）

## 1. 总体视图

```text
渲染端（主窗 /pet 桌宠窗，同一套 React 特征组件）
  录音(AudioWorklet 16k PCM)  ──POST /api/voice/asr(wav)──┐
  朗读开关/状态徽标/口型 Analyser                            │
  Live2D 画布（懒加载 Cubism/PIXI，独立 chunk）             │
        ▲ SSE（既有 /api/chat/stream 新增事件）             │
        │  voice_audio{fragment,spoken,audio(base64 wav),sampleRate,final}
        │  voice_state{idle|listening|thinking|speaking}    │
Next 服务端（Node，dev=Next dev；prod=托管内置 Node 进程）   │
  /api/voice/asr   → AsrEngine（sherpa-onnx-node）          │
  /api/voice/tts   → TtsEngine（单句，调试/回放）            │
  chat/stream      → orchestrator 文本流                    │
                     └─ voice 会话（可选）：StreamingSentenceSplitter
                        → stripForTts → TtsEngine.synthesize
                        → encodePcm16Wav → voice_audio 帧     │
  /api/voice/models/{status,download} → 文件系统 userData/models/voice
                                          + voice_models(v014)
Electron 主进程
  pet-window（transparent/frameless/alwaysOnTop，/pet 路由）
  PetClickThroughController（滞回，M0 已交付）
  preload: window.wbfm.pet（白名单 IPC：开关窗/穿透/位置/菜单动作）
```

## 2. packages/voice 分层（M0 骨架已建）

```text
packages/voice/src/
  engine/types.ts          ASR/TTS 接口 + VoiceEngineError（不感知 HTTP）
  engine/sherpa/           M1/M2：sherpa-onnx-node 薄封装（构造配置映射、dispose）
  audio/wav-codec.ts       PCM16 WAV 编解码 + 线性重采样兜底（纯函数，6 测）
  text/sentence-splitter.ts 流式切句（首逗号快出）+ TTS 清洗（10 测）
  session/voice-state.ts  状态机纯函数（14 测）
  models/manifest.ts      模型清单/镜像 URL/完整性校验（5 测）
  models/downloader.ts    M1：流式下载+进度+取消+落盘校验（mock fetch 测试）
```

- 原生绑定在 tsup 中 `external`；引擎模块惰性 `import('sherpa-onnx-node')`，未装模型/未启用语音时不加载 DLL。
- 引擎长驻单例（冷启动加载耗时高，M0 实测约 18s），按设置变更做引用计数重建。

## 3. API / SSE 契约（shared）

- SSE 增项（`api/sse.ts`）：
  - `voice_audio`：`{fragment, spoken, audio: string|null, sampleRate, final}`；`audio=null` 用于纯表情/空片段，仅驱动字幕与形象。
  - `voice_state`：`{state}`。
- HTTP：
  - `POST /api/voice/asr`：multipart wav + sampleRate → `{text, lang}`。
  - `POST /api/voice/tts`：`{text, speakerId?, speed?}` → audio/wav（单句，设置试听与重试）。
  - `GET /api/voice/models/status` → `voiceModelStatusSchema`；`POST /api/voice/models/download`（SSE 进度或轮询，M1 定）。
- 路由仅绑定 127.0.0.1（项目既有约束）；音频仅写临时缓存、响应后/退出即删，不入库、不进备份轨。

## 4. 对话接语音的位置

- `chat/stream` 请求体增加可选 `voice?: {tts: boolean}`（沿用 chatRequestSchema 扩展，默认 false → 行为与 v0.9 完全一致）。
- 服务端在收到 orchestrator delta 的同一写入点，旁路喂给「本轮 voice 会话」：切句器产出片段 → strip 后调 TTS → 以 `voice_audio` 发出；`voice_state` 在 thinking/speaking/idle 切换点发出。
- 取消链路复用既有 AbortSignal：abort 同时取消切句器残余与进行中的 TTS。
- 纯文字回归保障：voice=false（默认）时代码路径不创建任何语音对象（G6 零回归的结构性保证）。

## 5. 渲染端

- `features/voice/`：`use-voice-recorder`（AudioWorklet 采 16k PCM；PTT/VAD 两模式）、`use-voice-playback`（单写者队列：顺序 decode base64→AudioBuffer→播放；Analyser RMS 回调；cancel）、composer 语音按钮、状态徽标、设置面板。
- `features/avatar/`：`live2d-canvas` 动态 `import()` 拉取 Cubism Core + PIXI（独立 chunk）；表情纯函数 `expression-parser`（单测）；`avatar-host` 同时服务主窗与 `/pet`。
- `app/pet/page.tsx`：无侧栏、透明背景、极简布局；通过 preload IPC 上报命中测试（鼠标位置是否在模型 alpha 区）与接收窗口控制。

## 6. Electron 桌宠

- `main/pet/pet-window.ts`（M4）：BrowserWindow 参数照搬 overlay；加载 `${server}/pet`；位置持久化复用 window-state 模式。
- `main/pet/pet-penetration.ts`（M0 已交付）：`PetClickThroughController`；Electron 侧 `setPenetrating(v)=>win.setIgnoreMouseEvents(v,{forward:true/false})`；渲染端 mousemove(forward) → IPC → controller.update(hit)。
- preload 白名单（最小权限）：`pet.open/close`、`pet.setClickThrough`、`pet.onStateChange`、`pet.focusMain`、`pet.dragRegion`（用 CSS app-region 时可省略）。不开放任何 Node 能力。
- 语音单例：同 conversationId 仅一个播放宿主。主窗与桌宠都在时，由服务端 voice 会话 + 客户端「焦点宿主选举」（桌宠可见时桌宠，否则主窗）保证不出双声；切换宿主不断流（SSE 多订阅者皆可，播放权单点）。

## 7. 数据（v014，纯加法）

```sql
voice_models(
  kind TEXT CHECK(kind IN ('asr','tts')),
  model_id TEXT,
  status TEXT CHECK(status IN ('missing','downloading','ready','error')),
  bytes_total INTEGER, bytes_done INTEGER, error TEXT, updated_at TEXT,
  PRIMARY KEY(kind, model_id)
)
```
- 迁移/runner 已注册（LATEST=14），含 CHECK/主键/幂等 2 个测试。
- 语音设置无新表：`settings_kv` key=`voice`（JSON）。
