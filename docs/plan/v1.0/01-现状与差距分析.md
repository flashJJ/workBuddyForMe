## 3. Open-LLM-VTuber 借鉴/取舍明细

### 借鉴（已在本机验证可行）

- **模型与引擎选择**：sherpa-onnx SenseVoice int8（中/英/日/粤 ASR）、VITS MeloTTS zh_en int8（TTS）。
- **首句快出策略**：首个句末标点前遇逗号即切句送 TTS；已实现于 `voice/text/sentence-splitter.ts`。
- **播放顺序保证**：片段按序生成/按序播放；停止即取消。VTuber 曾出现「收尾信号与音频帧并发写 WS」断言事故，v1.0 用单写者播放队列规避（服务端则是 SSE 单连接天然有序）。
- **表情协议**：LLM 输出 `[joy]/[sad]…` 标签，TTS 文本清洗剥离、形象侧解析做表情；助手级开关。
- **桌宠交互**：透明、置顶、点击穿透+forward、拖拽、触摸动作、双击回主窗、右键菜单；进入立即/离开延迟的滞回。
- **模型分发**：hf-mirror 镜像 + 本地目录 + 完整性校验的思路。

### 明确不借鉴

- WebSocket 音频协议（项目无 WS 栈，HTTP+SSE 足够且更统一）
- Python 服务形态（项目是 TS 全栈；M0 Spike 已证明 Node 绑定可用，Python 仅作最后降级）
- VAD 全双工/回声消除、pyttsx3 式系统机械音、内心 OS、TTS 翻译、群聊、B 站直播
- 其「引擎工厂+云厂商全家桶」广度：v1.0 只做本地 sherpa 单实现，接口预留

## 4. M0 Spike 取证结论

### Spike A：sherpa-onnx-node 真机闭环（Node 24）

- 版本 1.13.8（onnxruntime 1.28.2），平台包 `sherpa-onnx-win-x64`；SAC 强制模式下加载正常。
- TTS：MeloTTS int8 44.1kHz 合成成功（冷启动约 18s 含加载，长驻进程后续句为秒级）。
- ASR：合成音频经 LinearResampler 降 16k 后 SenseVoice 识别，ITN 正确（「二零二六年十月六日…一百二十三」→「2026年10月6日…数字123」）。
- 待办注意：该 int8 模型在 1.13.8 绑定下 numSpeakers 报 1（sid 合法范围 [0,0]），M1 需对比 sid=0/1 与 fp32 `model.onnx` 的中文音色后定默认值（Python 1.10.46 下 sid=1 中文女声正常）。
- 打包：引擎在 Next 托管 Node 进程加载，与 Electron ABI 无关；`prepare-server.mjs` FALLBACK_PACKAGES 待加包名。

### Spike B：Electron 透明窗

- 真实 Electron 创建 transparent/frameless/alwaysOnTop 窗、加载 data: 页、`setIgnoreMouseEvents(true,{forward}) ↔ false` 往返、置顶定位均通过（spike 脚本留存于 `apps/desktop/spikes/`）。
- `PetClickThroughController` 滞回逻辑 8 个单测通过（进入立即、离开 180ms 延迟、边缘来回不翻转、force/dispose）。
