# 视觉人工巡检 Runbook（Playwright MCP）

> 状态：可用（2026-11-20）
> 定位：L3 探索式巡检，仅人工触发；不进入产品依赖、不进入 CI、不替代 L1 截图基线。
> 关联：[v4.14 视觉巡检分层](./spec.md#5-决策-d3视觉巡检分层) · [v4.15 视觉基线](../v4.15/spec.md) · [v0.7 playwright-mcp 评估](../../roadmap/v0.7-playwright-mcp-eval.md)

## 1. 什么时候用

L1 截图基线只覆盖固定 2D 面（设置页、记忆面板、上下文洞察）。以下场景适合本 runbook：

- 怀疑布局溢出、元素遮挡、弹层盖住关键按钮；
- 新交互路径没有稳定断言，需要像用户一样走一遍；
- WebGL / VRM / Live2D / 舞台等像素不稳定区域，无法做截图基线；
- 线上问题复现，需要记录完整点击路径与截图证据。

不适合：像素级回归（走 L1）、需要长期阻断的检查（补 Playwright spec）、批量重复执行。

## 2. 边界与安全

- **不进仓库、不进产品**：Playwright MCP 在外部 Agent 环境启动，不写入本仓库依赖。
- **不接触真实数据**：默认用 `WBFM_MOCK_AI=1` + 临时数据根；不要用真实 API Key、私人文档或生产账号。
- **截图可能出网**：MCP 会把页面截图与结构交给所配置的模型；默认只用 mock 数据，确有需要时先脱敏。
- **桌面专属窗口不交给 MCP**：透明桌宠窗、原生右键菜单、Electron 窗口层级需要人工操作；MCP 只负责 Chromium 中的 Web 页面。
- **不改产品代码**：发现问题是记录证据，不在巡检过程中顺手改代码。

## 3. 准备

### 3.1 启动应用（隔离数据）

```powershell
# Web 页面（MCP 主要操作对象）
$env:WBFM_MOCK_AI='1'
$env:WBFM_DATA_ROOT="$env:TEMP\wbfm-visual-manual"
pnpm dev:web
```

需要桌宠/舞台时再启动桌面端：

```powershell
$env:WBFM_MOCK_AI='1'
$env:WBFM_DATA_ROOT="$env:TEMP\wbfm-visual-manual"
pnpm dev:desktop
```

### 3.2 在外部 Agent 中挂载 Playwright MCP

在 Agent 的 MCP 配置里增加 stdio 服务器（示例，按所用客户端语法调整）：

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--isolated"]
    }
  }
}
```

- `--isolated` 使用临时浏览器配置，避免污染日常 Chrome；
- 首次运行会下载浏览器，保持网络可用；
- 不要在仓库的 `package.json` 中新增依赖，也不要提交 MCP 配置。

### 3.3 连接检查

让 Agent 打开 `http://127.0.0.1:42337/chat`，确认能读取页面标题与可见文本。打不开时先查：

1. `pnpm dev:web` 是否已监听 127.0.0.1:42337；
2. MCP 浏览器是否能访问本机回环地址；
3. 是否需要先完成首启向导（设置 `hasOnboarded` 或手动走一遍）。

## 4. 巡检清单

每步记录：操作、预期、实际、截图、控制台错误。发现问题时不急着修，先保留证据。

### A. 对话与上下文

- 打开 `/chat`，新建会话；
- 发送一条 mock 消息，确认流式回复、停止按钮、消息气泡无溢出；
- 打开顶栏 `⋯` → 上下文构成，确认抽屉不遮挡发送按钮、无「加载中」残留；
- 打开设置 → 数据 → 记忆面板，确认列表、空状态与滚动正常；
- 切换助手、切换会话、刷新页面，确认状态不串。

### B. 设置页

- 依次访问基础设置、外观与语言、语音、工具、数据；
- 逐个滚动到懒加载分组，确认锚点不跳动、无重复面板；
- 打开一个弹窗（供应商编辑 / 模型管理），确认 Esc 可关闭、焦点回到触发按钮；
- 缩放窗口到 1024×768，确认无横向滚动条、按钮不被裁切。

### C. 桌宠入口（桌面端人工）

- 启动桌面端，右键桌宠 → 聊两句 → 问候一下；
- 确认主窗被唤回并聚焦对话页；
- 确认输入框预填「今天过得怎么样？」，**没有自动发送**、消息列表仍为空；
- 手动删除草稿、再次触发求安慰 / 陪我玩，确认文案切换；
- 确认右键菜单、穿透开关、隐藏桌宠仍可用。

### D. 高风险视觉区域（只做探索，不做基线）

- `/stage?stage=play`：三席轮播、背景与字幕不互相遮挡；
- 对话页 Live2D / VRM 形象：切换模型后无白屏、表情与口型正常；
- 透明桌宠窗：拖动、悬停、菜单、置顶层级正常；
- 会议舞台：多角色切换时旧角色及时退场，无残影。

### E. 健壮性

- 键盘 Tab 走一遍主要操作，焦点可见、顺序合理；
- 打开浏览器控制台，记录任何未处理异常；
- 检查网络面板：无 4xx/5xx、无重复轮询风暴；
- 刷新页面两次，确认会话与设置不丢失。

## 5. 问题记录模板

| 字段 | 内容 |
|---|---|
| 标题 | 一句话描述用户可见问题 |
| 严重度 | Blocker / Major / Minor |
| 环境 | Web / 桌面端、视口尺寸、模型模式 |
| 复现步骤 | 从打开页面到问题出现的最短路径 |
| 预期 | 用户应该看到什么 |
| 实际 | 实际看到什么 |
| 证据 | 截图、控制台错误、网络请求 |
| 归属 | 布局 / 状态 / 交互 / 性能 / 数据 |

严重度建议：

- **Blocker**：主要功能不可用、数据丢失、页面白屏；
- **Major**：关键入口被遮挡、状态错误、明显布局破坏；
- **Minor**：间距、文案、非关键动画。

## 6. 收尾

1. 关闭 `pnpm dev:web` / `pnpm dev:desktop`；
2. 删除 `%TEMP%\wbfm-visual-manual`；
3. 截图只保留在问题单，不提交到仓库；
4. 可复现的问题补一条 Playwright spec，进入日常门禁；
5. 不可复现的一次性问题记录环境与时间，不做代码改动。

## 7. 与 L1 / L2 的关系

| 层级 | 触发 | 判定 | 产物 |
|---|---|---|---|
| L1 截图基线 | CI / 本地开关 | 像素比对 | 基线截图 + diff |
| L2 语义断言（可选） | 手工或夜间 | 模型语义判断 | 断言结果 |
| L3 本 runbook | 人工 | 人/Agent 观察与复现 | 问题单 + 截图证据 |

L3 的价值是发现「L1 拍不到、L2 断言不了」的问题；它不追求可重复，也不应被当成发布阻断条件。
