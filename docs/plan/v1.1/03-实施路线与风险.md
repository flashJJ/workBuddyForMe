# v1.1 实施路线与风险：M0–M5 任务板

> 任务板规则（试点 elpis tasks 模式）：每条任务带**可机械验证的完成标准**；一关单就跑标准，不靠「感觉重构完了」。顺序上 M0 先行（边界规则先立），M1/M4 互不依赖可并行，M2/M3 建议串行（都动热点文件），M5 收尾翻门禁。
>
> 分支：`feature/v1.1-internal-hardening`（基线：v1.0 真人验收通过后的 main）。每个里程碑一个提交批次，中途保持 typecheck/lint/单测随时可过。

## 测试策略

- **纯函数层**（压缩器/断言库）：密集单测先行，覆盖率硬指标；
- **接线层**：依赖既有 chat-orchestrator / tool-call-loop / voice 测试网，改造后零修改通过即证明行为不变；
- **搬家层**（voice runtime）：测试随代码迁移、路由零改动 + 打包态真机抽测；
- **门禁层**：所有新 ESLint 规则/行数档位都配「故意违例被抓住」的自测，防规则空转；
- **评估层**：每个 golden set 必须做一次「反向验证」（回退被测代码→用例失败），防止恒真断言。

## 风险与回滚

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 边界规则翻 error 时历史违例清零不完 | 中 | CI 红 | warn 期贯穿整个版本，T5.4 前出违例清单逐项关；真有合理越界走架构评审而非加 disable |
| barrel 子路径化改动面大、漏 import | 中 | typecheck 红 | codemod 批量改 + 根 barrel 兼容保留；按包独立提交 |
| 语音运行时搬家影响 standalone 打包 | 中 | 桌宠/语音不可用 | 薄壳保接口；T3.4 pack:dir 真机门禁；回滚 = revert 单批次提交 |
| 压缩器压掉后续工具必需的字段 | 中 | 工具连环调用失效 | id/编号白名单 + eval-tool-compact 二次引用断言 + 双视图（trace 完整可查） |
| 拆分 pet-manager 引入时序 bug（拖拽/穿透已有多轮教训） | 中 | 桌宠交互回归 | 只搬代码不改逻辑、23 个测试零修改 + pack:dir e2e + v1.0 真机清单复抽 |
| 覆盖率 60% 门槛设太激进拖垮节奏 | 低 | M5 延误 | warn 先看水位再定值，达不到就降档但要写明豁免 |

**整体回滚策略**：每个 M 独立提交批次且互不揉合；任何一关标准不过，该批次整体 revert，不把「修重构引入的 bug」带进下一批。

## 成功指标（版本结束时对账）

1. `eslint .` 与 CI 中边界规则 0 违例（error 态）；
2. 行数白名单仅余自动生成类（kokoro manifest），≥260 行手写文件较基线降 ≥60%；
3. 100KB 工具输出场景 promptTokens ≤ 基线 40%，二次工具引用成功，UI 完整结果可见；
4. 语音能力在 pack:dir 安装形态下与 v1.0 行为一致，web 侧语音编排代码归位于 core；
5. SSE 事件契约改动无法再「悄悄漏列」（删映射即测试红）；
6. eval 覆盖 ≥3 个域且全部带反向验证；核心覆盖率门槛不降级。
