# v1.1 重构设计：分层强制 · 结果压缩 · 热点拆分 · 契约派生 · 评估平台

> 原则：只搬与框架无关的工程资产；每个改造都先落纯函数/规则，再换接线；所有外部行为保持不变（零用户可见变更）。

---

## 1. 目标分层模型与边界门禁（M0）

### 1.1 允许的依赖方向

```text
apps/web（Next 可部署应用）
  ├─ 可以依赖：packages/{shared,config,database,ai,core,voice} 的公开面
  └─ 禁止：引用任何包的 internal/ 与 src 深路径

apps/desktop（Electron 可部署应用）
  ├─ 可以依赖：packages/{shared,config}（主进程仅 IPC/配置契约）
  └─ 禁止：直接依赖 core/ai/database（桌面壳不碰业务与 DB）

packages/voice ─ shared, config（引擎/编解码/清单，不 import core）
packages/ai    ─ shared（HTTP 底座/供应商适配）
packages/database ─ shared, config
packages/core  ─ shared, config, database, ai, voice（编排层唯一可聚合全部的包）
packages/shared, config ─ 不依赖任何业务包（最底层）
```

现状核实：上述方向当前**实际零违例**（voice 目前没被 core 引是例外，见 §3 归位后建立 core→voice 边），规则的作用是防未来。

### 1.2 `internal/` 私有目录约定

- 包内仅供本包使用的实现文件放入 `src/<域>/internal/`（或文件名加私有语义注释，不强制大搬家）；
- 跨目录/跨包只允许 import 域公开面：`<pkg>` 根 barrel 或 `<pkg>/<domain>` 子路径；
- 规则用 `eslint-plugin-import` 的 `no-restricted-paths` 实现，zones 按上表配置；测试文件 (`**/*.test.ts`) 放开 internal 访问（白体测试需要）；
- 先以 warn 上线（M0），M5 翻 error。

### 1.3 300 行门禁加预警线

`check-file-lines.mjs` 增加 260 行 warning 档（不阻断，仅输出），让热点在撞线前可见；超 300 白名单理由模板收紧：仅「自动生成 / barrel 聚合 / 已登记的技术阻塞（附拆分期）」三类。

## 2. 工具结果中央压缩层（M1，核心改造）

### 2.1 位置与形态

新增纯函数模块（零依赖，只用 shared 的 token 估算）：

```text
packages/core/src/tools/tool-result-compact.ts          # 压缩纯函数
packages/core/src/tools/tool-result-compact.test.ts     # 密集单测（目标行覆盖 ≥95%）
```

对外 API（草稿，实现时可微调，职责不变）：

```ts
interface CompactOptions {
  /** 本条工具消息可占用的 token 预算（由 context-budget 在装配时下发） */
  maxTokens: number;
  /** 工具来源，决定特化压缩策略 */
  source: 'builtin' | 'mcp' | 'flow' | 'computer';
  toolName: string;
}
/** 完整结果 → 入模视图；保证引用句柄（id/编号类字段）不丢 */
export function compactToolResultForModel(result: ToolResult, opts: CompactOptions): string;
/** 判定压缩是否实际发生（供 trace 记录 compacted 标记） */
export function wasCompacted(original: string, compacted: string): boolean;
```

### 2.2 四层策略（移植 elpis 思路，按 wbfm 生态改写）

1. **预算驱动而非固定字数**：预算来自现有 context-budget 统一账（v1.0 的 0.9 安全率机制），token 估算复用 prompt 同款估算器；
2. **工具来源特化**：
   - `knowledge_search`/RAG 类：按片段编号去重，保留「编号 + 文档名 + 120 字摘录」，与现有 RAG 引用编号体系对齐（编号是下一轮引用的句柄）；
   - `flow:*` / MCP 结构化结果：能 JSON.parse 就按结构压——数组识别形状后取样（前 N 条 + `{count, head:[...]}`），id/编号/状态类字段白名单保留；
   - `fetch_webpage`：沿用其自限 8000 字，压缩层只在预算更紧时二次裁；
   - 桌面控制/截图类：文本极短，不压（图片走既有多模态通道，不进文本压缩）；
3. **通用递归兜底**：字符串截断带省略标记；对象数组通用取样；超预算末级降级「保 id 不保内容」并附一句固定提示（工具可凭 id 再查）；
4. **不碰 summary/output 双字段语义**：`summary`（≤120 字，UI 卡片）维持原样，压缩只作用于回灌入模的 `output`。

### 2.3 双视图接线（关键边界）

```text
工具执行 ── 完整 ToolResult ──► tool trace / SSE tool 事件 / 消息记录（用户看到的原样保留）
                 │
                 └─ 入模前：compactToolResultForModel() ──► 下一轮 LLM messages 的 tool content
```

接线点：`tool-call-loop.ts`（当前第 248 行 `content: result.output` 改为压缩后视图）；预算由上层 `chat-orchestrator`/context-budget 计算后经参数下发，压缩器不读全局状态。压缩事件在 trace 条目标 `compacted: true` + 原始长度，便于 eval 与调试。

### 2.4 回归与验收

- 单测：空结果/纯字符串/嵌套 4 层/100KB JSON/数组形状识别/id 保留/中文 token 预算边界/各来源特化，≥15 例；
- 集成：构造 MCP 工具返回 100KB 表数据 → 断言下一轮 prompt tokens 下降且模型二次调用能引用首个 id；
- 不回归：knowledge_search 现有单测、tool-trace UI 显示完整 output 的既有断言全绿。

## 3. 语音运行时归位（M3）

### 3.1 现状与目标

```text
现状：apps/web/src/lib/server/voice/
        voice-runtime.ts(226)  ← 引擎生命周期/sid 解析/缓存（领域策略，错位）
        voice-chat-bridge.ts(101) ← SSE 文本流→语音流（可留 web，属传输接线）
        voice-runtime-singleton.ts(17) ← HMR 单例（留 web，正确）
        voice-settings.ts/model-paths.ts(48) ← 看内容归属

目标：packages/core 新增 voice 运行时域（或 @wbfm/voice 的 runtime 层，二选一，M3 开工取证定）
        - 纯领域：VoiceRuntime 门面（引擎缓存键、sid 解析顺序、settings 失效重建）
        web 侧：
        - 保留 singleton（HMR/globalThis 防护）、withVoice 桥（SSE 传输）、请求路由
        - re-export 同签名薄壳，路由文件零改动
```

裁决依据：`@wbfm/voice` 目前是「引擎与编解码」纯技术包，不依赖 DB；而 VoiceRuntime 依赖 settings 仓储（DB）。因此**预期落点是 `packages/core/src/voice/`**（core 已可依赖 voice + database），@wbfm/voice 保持零业务。开工时用一张依赖关系图复核后再动手。

## 5. SSE 契约机械派生（M4）

```ts
// core/chat/types.ts 改造方向（草稿）
export type OrchestratorEventName =
  | 'meta' | 'delta' | 'citations' | 'memories' | 'tool'
  | 'tool_confirmation_required' | 'done' | 'error';
```
