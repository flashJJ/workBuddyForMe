# v4.16 CI 稳定性与验收退出收口

> 状态：执行中（2026-11-20）
> 关联：[ci.yml](../../../.github/workflows/ci.yml) · [visual.yml](../../../.github/workflows/visual.yml) · [playwright.config.ts](../../../apps/web/playwright.config.ts) · [acceptance/run.mjs](../../../scripts/acceptance/run.mjs)

## 背景

v4.15 发布后 CI 出现三类问题：

1. **自动验收挂起**：日志已打印 `6/6 通过`，但进程不退出，步骤持续 3 小时，堵住后续 E2E 与视觉巡检；
2. **E2E 时序不稳**：设置页锚点滚动、Live2D chunk 轮询、VAD 请求在共享 runner 上超时，且没有重试；
3. **视觉首跑缺基线**：首次运行必然失败（预期），专用工作流还漏构建依赖包。

## 目标

- 验收与评测脚本在完成或异常后干净退出，不留孤儿进程与占用端口；
- 每个长步骤有硬超时，单步骤异常不再无限拖死流水线；
- E2E 在 CI 有有限重试与更合理的时序阈值；
- 视觉基线与专用工作流稳定，可独立于验收单独运行。

## 非目标

- 不重构产品代码，不改业务行为；
- 不引入新的测试框架或 CI 服务；
- 不承诺零 flaky；目标是失败快速、隔离、可诊断。

## 改动清单

### P0 验收进程收口

- POSIX 下子进程使用独立进程组启动，停止时终止整组，避免 `pnpm → next` 孙进程残留；
- 验收主流程结束后显式退出，防止事件循环被残留句柄拖住；
- Windows 保留 `taskkill /T /F` 语义。

### P1 CI 超时与顺序

- `ci.yml` 增加同分支并发取消，避免两次运行并存；
- 每个长步骤设置 `timeout-minutes`：验收 20、工具评测 15、协作回归 15、E2E 25、视觉 10；
- 视觉与 E2E 排在验收之前，验收异常时截图与 E2E 产物仍然可见。

### P2 E2E 稳定性

- Playwright 在 CI 下 `retries: 2`，本地保持 0；
- 设置页锚点滚动、Live2D chunk 轮询、VAD 请求超时放宽到 60 秒；
- 缓存 Playwright Chromium，减少安装抖动。

### P3 视觉基线

- 提交 Linux 三张基线（设置页基础区、记忆面板、上下文洞察）；
- 专用 `visual.yml` 增加并发取消与 Chromium 缓存；
- 视觉任务独立触发，不依赖验收与 E2E。

## 验收标准

- `pnpm check` 全绿；
- 本地运行 `node scripts/acceptance/run.mjs` 完成后进程立即退出，无残留 Next 进程；
- 专用视觉工作流对已提交基线全部通过；
- 新 CI 运行中验收步骤最长 20 分钟，超时后失败但不再阻塞其他检查。

## 风险与回退

- 进程组终止在 Windows 不适用，已保留平台分支；
- 超时可能截断慢机器上的正常长跑，先以日志中的实际耗时调整；
- CI 重试会增加总时长，仅影响失败用例；
- 如出现异常，回退为原有 `child.kill('SIGTERM')` 与更宽松超时。
