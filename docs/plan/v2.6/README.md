## 1. 版本主题与目标

### 1.1 为什么是「会沉淀」

产品已经具备对话、知识库、Flow、桌面 Agent、多智能体会议、长期记忆与陪伴能力。当前最短的两块板不在「能不能做」，而在「做完留下什么」：

- **会议停在讨论**：有议题、成员、轮次与转录，但没有结构化结论、决策、行动项与责任人；会议结束即散场，转录很难二次使用。
- **记忆停在注入**：长期记忆会被召回并注入回答，但用户只看到「参考了 X 条记忆」；不知道是哪几条、为什么被想起、来自哪次对话，也无法从记忆回到来源。

v2.6 把这两条链路补成闭环：**讨论 → 结论 → 行动项 → 提醒 / Flow**，以及**记忆 → 来源会话 → 召回理由 → 编辑 / 遗忘**。这比追逐图片/视频生成或全双工语音更符合「本地优先的个人工作台」定位，也能直接复用现有会议、提醒、Flow、记忆与运行记录资产。

### 1.2 成功指标（可验收）

| 指标 | 现状（v2.5.0） | v2.6 目标 |
|---|---|---|
| 会议结论 | 无结论/行动项数据模型与 API；会议只有 `active / finished / aborted` 状态 | 已结束会议可生成、编辑、持久化、导出结构化结论；行动项可转提醒或 Flow |
| 记忆溯源 | 对话仅显示「参考了 X 条记忆」；记忆面板不展示来源；无召回次数/理由 | 每条召回记忆在对话内可见内容、来源会话与召回理由；面板展示来源与召回次数 |
| Electron 平台 | Electron 44.9.3；v2.5 明确将 45 迁移留给 v2.6 | Electron 45 当前最新稳定 patch；`safeStorage` 异步化与 preload 全局移除完成 |
| 安全基线 | Electron 公告 0（44.9.3） | Electron 公告 0；不新引入运行时 critical/high |
| 数据迁移 | — | 新增 2 张表 + 2 个记忆列；迁移幂等；备份 schema 升版且旧备份可读 |
| 回归 | Web e2e 109/109、桌面 e2e 11/11 | 既有用例全绿；新增会议/记忆/截图/报告用例 |
| 体验不回退 | TTFV、首字延迟、语音、桌宠、Flow 已验收 | 同等机器与模型下不出现可感知回退 |

## 2. 现状与痛点

### 2.1 会议只到「讨论」，没有「结论」

- [meeting.ts](../../../packages/shared/src/schemas/meeting.ts) 当前只有创建、轮次、模式切换三类契约；状态仅 `active / finished / aborted`，没有结论、决策、行动项或责任人字段。
- [features/meetings](../../../apps/web/src/features/meetings) 中检索不到 `conclusion / summary / action / todo` 相关实现；会议结束后的产物只有转录。
- v1.9 的「会议结论摘要 / 待办」原本列为 P1，[v1.9 总结](../../roadmap/v1.9-release-summary.md) 明确「本版只做讨论与转录，不自动建任务」；[v2.0 方案](../v2.0/README.md) 再次明确「不补 v1.9 P1」。
- 用户侧结果：会议开完，决策与行动项仍要靠人回忆/手抄；多智能体会议成了「演示能力」，不是「工作产出」。

### 2.2 记忆被使用，但不可解释

- [sse.ts](../../../packages/shared/src/api/sse.ts) 的 `RecalledMemoryPayload` 只有 `id / kind / content`；没有来源会话、来源消息、相似度或召回理由。
- [chat-page.tsx](../../../apps/web/src/features/chat/chat-page.tsx) 只渲染一个「参考了 X 条记忆」提示，内容靠 `title` 悬浮展示；用户无法逐条查看与跳转。
- [memory-panel.tsx](../../../apps/web/src/features/memory/memory-panel.tsx) 展示类别、重要性、日期与编辑/删除；`sourceConversationId` 虽已存在于数据模型，但 UI 未展示来源，`last_accessed_at` 也未产品化。
- 用户侧结果：记忆像「黑盒」；用户无法判断某条记忆是否准确、是否该保留，也无法回答「你为什么突然提到这件事」。

### 2.3 Electron 45 的两个破坏性变更已到期

- [v2.5 方案](../v2.5/README.md) 明确记录：Electron 45 将同步 `safeStorage` 标记弃用，并移除沙箱 preload 的 `Buffer / events / timers / url` 全局；v2.5 选 44 以避开立即迁移，但要求在 v2.6 前处理。
- [cipher-server.ts](../../../apps/desktop/src/main/cipher-server.ts) 当前在 HTTP handler 内同步调用 `safeStorage.encryptString / decryptString`；45 下需要改为异步 API，且不能阻塞回环桥。
- preload 与 cipher bootstrap 需要区分：**沙箱 preload** 受全局移除影响；**Node 子进程内的 bootstrap** 不受同一限制，不能一刀切改坏。
- 平台风险：不迁移会逐步脱离 Electron 支持窗口；迁移不当会影响密钥解密、启动、安装包与自动更新。

### 2.4 次级缺口（P1 / P2，不抢主题）

- **截图问答入口**：composer 已支持拖拽/文件选择与图片附件（v0.3），但没有剪贴板粘贴截图入口与视觉模型缺失时的明确引导。
- **运行证据汇总**：v2.4 已统一 task / flow / agent-run 的状态与失败归因，但还缺跨链路的成功率、耗时分布与可导出报告。
- **生态桥**：MCP 目录扩面、技能导入/模板区仍是 v2.4 留白。
- **性能基线**：Electron 冷启动、首屏、空闲内存没有可重复基线，Electron 45 迁移需要前后对比。

## 3. 主题取舍

| 候选主题 | 判断 | 原因 |
|---|---|---|
| **会沉淀：会议结论 + 记忆溯源（采用）** | ✅ | 直接补「讨论无结论、记忆无来路」两条闭环；复用现有会议/提醒/Flow/记忆资产；与本地优先、长期关系定位一致 |
| 多模态为主：截图问答 + 图片/视频生成 | ➖ | 单图理解与附件已存在；图片/视频生成不自建，只适合作为 P1/P2 的入口增强 |
| 生态桥为主：MCP 目录 + 技能导入 + 分享 | ➖ | 价值明确但用户感知弱于会议结论；适合 P2，避免版本失焦 |
| 性能 / 平台为主：Electron 45 + 冷启动 + 内存 | ➖ | 平台迁移是必做项，但单独成版缺少用户可见价值；本版作为 P0/P1 一并交付 |

## 4. 功能清单

### P0 必做

#### P0-1 Electron 45 平台续航

- **用户故事**：作为用户，我升级到 2.6 后应用仍能正常启动、解密供应商密钥、安装与自动更新；作为维护者，桌面壳仍处在 Electron 支持窗口内。
- **验收**：
  1. `electron` 升到 45 当前最新稳定 patch；`electron-builder` / `electron-updater` 升级到兼容版本或确认现有版本可用；`pnpm audit` 中 Electron 公告为 0。
  2. `safeStorage` 改用异步 API；cipher bridge 的 encrypt/decrypt 全程可 await；旧密文仍可解密，密钥不出明文、不阻塞回环桥。
  3. 沙箱 preload 全局审计完成：不依赖被移除的 `Buffer / events / timers / url`；`contextIsolation`、`sandbox`、无 `nodeIntegration` 基线不变。
  4. 桌面 smoke 通过：主窗、桌宠、舞台、桌面控制、系统通知、全局快捷键、自动更新检查。
  5. `pnpm dist:win` 出包；干净安装、2.5.0 覆盖升级、卸载保留/删除数据两态通过；`latest.yml` / blockmap 正确。
- **技术要点**：safeStorage 异步迁移、preload 全局审计、N-API 原生模块（nut-js）验证、electron-builder/updater 兼容、Windows 打包与 SAC 降级、内置 node.exe ABI 复核。
- **规模**：L。

#### P0-2 会议结论与行动项

- **用户故事**：作为会议发起者，会议结束后我能一键生成结构化结论；我能修改决策与行动项，并把行动项转成提醒或已发布 Flow，而不是让讨论停在转录里。
- **数据模型（增量）**：
  - `meeting_conclusions`：`meeting_id`（唯一）、`summary`、`decisions_json`、`open_questions_json`、`model_id`、`generated_at`、`edited_at`。
  - `meeting_action_items`：`meeting_id`、`content`、`owner_label`、`owner_member_id`（可空）、`due_at`（可空）、`status`（open / done / cancelled）、`source_turn_id`（可空）、`linked_reminder_id`（可空）、`linked_flow_run_id`（可空）、时间戳。
  - 迁移幂等；备份 schema 升版；旧数据无需回填。
- **接口（增量）**：
  - `POST /api/meetings/:id/conclusion`：对 `finished` 会议生成结论；不自动在每轮触发。
  - `GET /api/meetings/:id/conclusion`；`PATCH` 编辑 summary / decisions / openQuestions。
  - 行动项 CRUD + 状态更新；`POST .../to-reminder`；`POST .../run-flow`；导出 Markdown。
  - 所有接口沿用会议权限；不存在跨会议读取。
- **生成策略**：
  - 复用会议 `modelId` 或系统默认对话模型；一次结构化调用，输出必须通过 Zod 校验。
  - 转录超上下文时先按时间窗分块压缩，再做结论；预算与窗口写入契约，避免无限 token。
  - **失败不伪造**：模型不可用 / JSON 非法 / 超时 → 保留转录，提示重试或手动填写；绝不在无依据时生成「像结论的结论」。
  - 结论调用不启用工具 / MCP / 知识库，延续 v1.9 会议边界。
- **UI**：
  - 会议结束面板：「生成结论」→ 摘要 / 决策 / 未决问题 / 行动项四区；支持行内编辑、保存状态、重新生成（覆盖前确认）。
  - 行动项：负责人、截止时间、状态；「转提醒」「运行 Flow」「复制 / 导出」。
  - 空态、生成中、失败、无模型四条路径；zh/en 双语文案。
- **验收**：
  1. mock 模型 + golden 转录可生成通过 Zod 的结论；非法 JSON / 超时 / 无模型分别进入可恢复错误态。
  2. 结论编辑后刷新仍在；行动项转提醒后提醒可见；运行 Flow 后 run 记录可回到会议。
  3. 导出 Markdown 含议题、成员、结论、行动项；不包含密钥或内部提示词。
  4. 只有 `finished` 会议可生成；`active / aborted` 明确拒绝。
  5. 单测 + 集成测试覆盖生成、编辑、转换、权限与迁移。
- **规模**：L。

#### P0-3 记忆溯源

- **用户故事**：作为用户，当回答提到某条记忆时，我能看到是哪几条、来自哪次对话、为什么被召回；我能从对话跳到来源，也能在记忆面板里编辑或遗忘。
- **数据与契约（增量）**：
  - `memories` 增加 `source_message_id`（可空）与 `recall_count`（默认 0）；保留既有 `source_conversation_id`、`last_accessed_at`。
  - `RecalledMemoryPayload` 增加 `sourceConversationId`、`sourceMessageId`、`score`、`reason`（如 `semantic`）；旧客户端忽略新增字段不受影响。
  - 召回时 `touchAccessed` 同时累加 `recall_count`；删除记忆后不再召回。
- **UI**：
  - 对话：把「参考了 X 条记忆」升级为可展开的记忆 chips；每条展示类别、内容摘要、来源会话、召回理由（如「语义相近 · 高」）；点击跳到来源会话/消息。
  - 记忆面板：展示来源会话链接、召回次数、最近召回时间；保留现有编辑、归档、删除与清空。
  - 无来源的旧记忆显示「来源未知」，不伪造来源。
- **验收**：
  1. 任意一次命中记忆的对话，chips 数量与 SSE 载荷一致；每条都能打开来源或明确标注未知。
  2. `recall_count` 随命中递增；`last_accessed_at` 更新；删除后下一次召回不再出现。
  3. 来源消息跳转可定位到消息；来源会话被删除时给出可读降级。
  4. 迁移幂等；旧记忆可读；备份/恢复后来源字段保留。
- **规模**：M/L。

### P1 争取

#### P1-1 截图问答顺手入口

- **现状**：composer 已支持拖拽与文件选择（v0.3 图片附件），但缺少剪贴板粘贴截图入口与视觉模型缺失时的引导。
- **增量**：粘贴板图片直接进 composer；空态/工具栏提示「可粘贴截图」；当前模型无 vision 能力时明确提示切换视觉模型，不静默失败。
- **验收**：截图粘贴 → 预览 → 发送 → 回答；无视觉模型时给出可操作指引；e2e 覆盖粘贴与无 vision 两条路径。
- **规模**：M。

#### P1-2 运行证据汇总

- **现状**：v2.4 已统一 task / agent-run / flow-run 的状态、耗时与失败归因，但缺跨链路汇总。
- **增量**：按时间窗统计成功率、失败类别 Top N、耗时中位数；支持按链路筛选与 Markdown/CSV 导出；不新增运行表。
- **验收**：同一时间窗内汇总数与明细一致；失败类别与 v2.4 归因口径一致；导出可复核。
- **规模**：M。

#### P1-3 性能基线

- **现状**：Electron 冷启动、首屏、空闲内存没有可重复基线；Electron 45 迁移需要前后对比。
- **增量**：新增桌面性能采样脚本，记录「进程启动 → 窗口可交互」「首屏」「空闲 30 分钟内存斜率」；v2.5 基线 vs v2.6 对比；超过阈值需说明或回退。
- **验收**：脚本可重复执行；报告入库；不出现无法解释的显著回退。
- **规模**：M。

### P2 留白

- **生态桥**：MCP 目录继续扩面；技能导入/模板区；`.wbfm-pack` 分享体验。
- **行动项 → 桌面 Agent 任务**：需要先定义通用任务语义，避免把会议行动项硬塞进桌面任务模型。
- **记忆召回历史**：把每次召回审计化（独立事件表）；v2.6 先做当前回合可解释。
- **按助手隔离记忆**：当前记忆为全局；隔离涉及召回范围与迁移，单独立项。
- **会议结论沉淀到知识库 / 记忆**：先保证结论可编辑可导出，再做自动沉淀。
- **全双工语音、图片/视频生成**：不自建；继续走供应商 / MCP / 本地网关。
- **Next 16 迁移 spike**：按 v2.5 P2 记录另立版本，不与本版混做。

| **M3 会议 UI 与闭环** | 结束面板、编辑、转提醒/Flow、导出、i18n、e2e | M2 | 是 |
| **M4 记忆溯源** | 数据迁移、payload 扩展、对话 chips、面板来源/次数、测试 | M0 | 是 |
| **M5 收口与发布** | P1（截图粘贴 / 运行报告 / 性能对比）、回归、文档、版本号、Release | M1–M4 | 是 |

## 7. 风险与取舍

| 风险 | 影响 | 应对 |
|---|---|---|
| 结论生成 JSON 不稳定 | 会议结论不可用或误导 | Zod 严格校验；失败保留原文 + 手动编辑；不以假数据填充 |
| 转录超上下文 | 结论质量下降/调用失败 | 时间窗分块压缩；预算上限；超限明确提示 |
| 行动项语义被误解 | 用户以为会变成桌面任务 | UI 明确「转提醒 / 运行 Flow」两种落点；桌面任务留 P2 |
| 记忆来源缺失 | 旧数据无法溯源 | 新列可空；旧记忆显示「来源未知」；不伪造 |
| 召回分数被误读 | 用户把相似度当准确率 | UI 只显示高/中/低档与「语义召回」，不展示伪精确百分比 |
| Electron 45 密钥兼容 | 升级后供应商密钥不可用 | 旧密文 round-trip 测试；cipher bridge 异步化；失败可回滚 2.5 |
| preload 全局移除 | 启动/桥接失败 | 沙箱 preload 与 Node 子进程分开审计；补回归测试 |
| builder/updater 不兼容 45 | 无法出包/更新 | 先做兼容矩阵；必要时升最新 patch；保留 2.5 回滚包 |
| 范围膨胀 | P1 拖延封版 | P1 可裁剪；P0 三条为封版门槛 |
| 迁移/备份回归 | 旧数据或旧备份损坏 | 幂等迁移；读兼容；备份 schema 升版；旧备份恢复测试 |

## 8. Non-Goals（本版本明确不做）

- 不做图片/视频生成，不做全双工实时语音；需要时走供应商、MCP 或本地网关。
- 不做移动端原生 App、云账号、多租户或团队协作。
- 不做模型训练/微调。
- 不建通用待办/任务系统；行动项只存在会议域，落点仅提醒与 Flow。
- 不在会议结论调用中启用工具 / MCP / 知识库。
- 不做 Next 16 迁移；不在本版混入开发链大版本升级。
- 不做按助手隔离记忆、召回历史审计表；留 P2。
- 不自动为每场会议生成结论；生成必须由用户显式触发，避免无谓模型成本。

## 9. 验收顺序

1. **M0** 冻结契约，先定结论 JSON、行动项状态与记忆 payload，避免前后端各写一套。
2. **M1** 先完成 Electron 45，拿到性能基线与可回滚安装包，再叠功能。
3. **M2/M3** 会议结论与行动项闭环；每步可独立演示。
4. **M4** 记忆溯源；先做对话内可解释，再做面板来源与计数。
5. **P1** 按 ROI 接入截图粘贴、运行报告、性能对比；可裁剪。
6. **M5** 全量回归、文档、版本号与 Release。
