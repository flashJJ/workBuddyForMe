> 冻结日期：2026-10-27｜分支：`feature/v2.6-conclusion-memory`｜基线：`b9de4bf`（规划分支）

## D1 Electron 45 平台续航

| 项 | 冻结值 |
|---|---|
| Electron | `45.0.0`（当前 latest 稳定版） |
| electron-builder | `26.18.0`（不变；pack:dir 已验证可用） |
| electron-updater | `6.8.11`（不变；更新链真机待验） |
| safeStorage 加密 | `safeStorage.encryptStringAsync(plainText)` |
| safeStorage 解密 | `safeStorage.decryptStringAsync(encrypted)` → `.result` |
| 可用性检查 | `safeStorage.isAsyncEncryptionAvailable()` |
| 同步 API | `encryptString / decryptString / isEncryptionAvailable` 不再使用（45 已弃用） |
| preload 全局 | 不使用 `Buffer / events / timers / url`；保留 `contextBridge + ipcRenderer + process.argv` |
| cipher bootstrap | 继续运行在 Node 子进程，保留 `Buffer / SharedArrayBuffer / Atomics.wait`；不受沙箱 preload 限制 |
| 本地打包 | 网络无法下载 Electron 时使用 `--config.electronDist=<repo>/node_modules/electron/dist`；CI 正常下载 |

**说明**：`decryptStringAsync` 返回 `shouldReEncrypt`；v2.6 的回环桥只返回明文，不做自动重加密，持久化层下次保存时自然重加密。旧密文仍可解密；真机需用现有数据根做一次 round-trip。

## D2 会议结论与行动项

### D2.1 结论 JSON（LLM 输出必须通过 Zod）

```json
{
  "summary": "一句话结论",
  "decisions": ["已达成决策 1"],
  "openQuestions": ["未决问题 1"],
  "actionItems": [
    {
      "content": "行动项内容",
      "ownerLabel": "负责人显示名",
      "ownerMemberId": null,
      "dueAt": null
    }
  ]
}
```

- `summary` 必填，1–2000 字符。
- `decisions` / `openQuestions` / `actionItems` 允许空数组。
- `actionItems[].content` 必填，1–500 字符；`ownerLabel` 可空字符串；`ownerMemberId` 只能引用本会议成员（助手 id）或 `null`（用户/未指定）；`dueAt` 为 ISO 8601 或 `null`。
- 生成失败（无模型 / JSON 非法 / 超时）**不写入伪结论**；保留转录，进入可重试/手动编辑状态。

### D2.2 行动项状态机

`open → done`、`open → cancelled`、`done → open`、`cancelled → open`；不提供 `deleted` 物理删除（保留会议审计），UI 可隐藏 `cancelled`。

### D2.3 生成与转换边界

- 只有 `finished` 会议可生成结论；`active / aborted` 返回 409。
- 生成必须由用户显式触发；每轮对话不自动触发。
- 结论调用复用会议 `modelId` 或系统默认对话模型；不启用工具 / MCP / 知识库。
- 行动项落点只有两种：**转提醒**（要求 `dueAt` 存在）与 **运行已发布 Flow**；不创建通用待办/桌面 Agent 任务。
- 重新生成覆盖当前结论，覆盖前必须二次确认；v2.6 不做结论版本历史。
- 重新生成仅替换 `source=generated` 行动项并重置为 `open`；`source=manual` 行动项保留，避免覆盖用户手工维护内容。

### D2.4 数据表（增量）

- `meeting_conclusions`：`meeting_id` 唯一、`summary`、`decisions_json`、`open_questions_json`、`model_id`、`generated_at`、`edited_at`。
- `meeting_action_items`：`meeting_id`、`content`、`owner_label`、`owner_member_id`、`due_at`、`status`、`source`（generated / manual）、`source_turn_id`、`linked_reminder_id`、`linked_flow_run_id`、`created_at`、`updated_at`。
- 备份 schema 升版与导出/恢复纳入 M5 收口；M2 先保证迁移幂等、旧数据不回填。

## D3 记忆溯源

### D3.1 召回载荷（SSE `memories` 增量字段）

```json
{
  "id": "12",
  "kind": "fact",
  "content": "用户偏好深色主题",
  "sourceConversationId": "c_123",
  "sourceMessageId": "m_456",
  "score": 0.82,
  "reason": "semantic"
}
```

- `reason` 首期只允许 `semantic`；不伪造关键词命中。
- `score` 为语义相似度归一化分；UI 只显示高 / 中 / 低档，不展示伪精确百分比。
- `sourceConversationId / sourceMessageId` 可空；旧记忆缺来源时显示「来源未知」，不伪造。
- 删除记忆后不再召回；`recall_count` 在召回命中时递增，`last_accessed_at` 同步更新。

### D3.2 数据列（增量）

- `memories.source_message_id`（可空，指向来源消息）。
- `memories.recall_count`（整数，默认 0）。
- 保留 `source_conversation_id` 与 `last_accessed_at`。
- 备份/恢复后两列保留；旧备份恢复时按 `NULL / 0` 处理。

### D3.3 UI 边界

- 对话：记忆 chips 可逐条展开；点击来源跳转到来源会话/消息；来源已删除时提示并保留当前内容。
- 记忆面板：展示来源、召回次数、最近召回时间；保留现有编辑、归档、删除、清空。
- 不展示召回历史列表（P2），不按助手隔离记忆（P2）。

## D4 统一 Non-Goals

- 不做图片/视频生成、全双工语音、移动端、云账号、多租户、模型训练。
- 不建通用待办/任务系统；行动项只在会议域。
- 不在会议结论调用中启用工具/MCP/知识库。
- 不做 Next 16 迁移；不混入开发链大版本升级。
- 不自动为每场会议生成结论。

## D5 待评审确认项

1. 行动项 `dueAt` 仅日期时，转提醒是否默认本地 09:00？**当前冻结：必须选择具体时间；仅日期不满足转提醒条件。**
2. 结论重新生成是否保留历史？**当前冻结：不保留，覆盖前确认。**
3. 记忆来源消息被删除时是否保留记忆？**当前冻结：保留记忆，来源显示「已删除」。**
4. 运行 Flow 的行动项是否要求选择已发布版本？**当前冻结：是，只能选择已发布 Flow，并记录 runId。**
