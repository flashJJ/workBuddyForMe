# v2.14 现状取证：五处 P1 欠账的代码位置

> 目的：为 [v2.14 方案](README.md) 提供可核对的现状证据。只记录事实，不做设计。

## 1. 技能：有启用态，没有版本历史

| 事实 | 位置 |
|---|---|
| `SkillManifest.version` 只是清单字段，不参与持久化 | `packages/shared/src/types/skill.ts:23-32` |
| `SkillState` 只有 `enabled` 与 `sourcePath`，无版本 / 历史引用 | `packages/shared/src/types/skill.ts:49-57` |
| `skills_state` 建表只有 `id/name/enabled/source_path/created_at/updated_at` | `packages/database/src/migrations/v010-skills-state.ts:5-20` |
| 技能从数据根 `skills/<name>` 目录扫描，manifest 校验后进入内存 | `packages/core/src/skills/loader.ts:20-56` |

结论：技能升级只能原地覆盖目录；没有快照表、回退入口，也没有「当前版本」概念。

## 2. 工作流：有版本行，但运行读的是当前版本

| 事实 | 位置 |
|---|---|
| `workflow_versions` 保存 `version/graph_json/published_at`，保存图时版本号自增 | `packages/database/src/migrations/v012-flow-studio.ts:26`、`packages/database/src/repositories/workflow-repo.ts:155-176` |
| `publishVersion(workflowId, version?)` 可发布指定版本，并把 `current_version` 指向它 | `packages/database/src/repositories/workflow-repo.ts:192-216` |
| 运行链路只校验 `status === 'published'`，图仍取 `getCurrentVersion` | `packages/core/src/flow/run-service.ts:57-70` |
| MCP 流程上下文同样取 `getCurrentVersion` | `packages/core/src/mcp/server/mcp-flow-context.ts:44` |

结论：发布后再保存草稿，`current_version` 变为新版本且状态回到 `draft`，但运行仍读当前版本——草稿会直接影响下一次生产运行。没有「生产版本」列，也没有版本列表 UI。

## 3. 能力包：只能升，不能降，也不能同版本修复

| 事实 | 位置 |
|---|---|
| 升级要求 kind 一致，且新版本必须高于当前版本；`compared <= 0` 直接 422 | `packages/core/src/capabilities/upgrade.ts:170-176` |
| 版本比较函数 `compareCapabilityVersions` 只用于升级校验 | `packages/core/src/capabilities/upgrade.ts:26-38` |
| 升级端点只接收 `file`，没有降级 / 修复确认字段 | `apps/web/src/app/api/capabilities/[id]/upgrade/route.ts:12-20` |
| v2.12 已实现暂存 → 原子换位 → 失败回滚与健康自检 | `packages/core/src/capabilities/capability-service.ts:257-258` |

结论：降级与同版本修复都不可用；失败回滚已有，但缺「主动回退到旧版」的入口与依赖校验。

## 4. 运行记录：有 runId，没有下钻入口

| 事实 | 位置 |
|---|---|
| 审计仓储支持 `runId` 过滤并返回 `runId` | `packages/database/src/repositories/audit-event-repo.ts:35-125` |
| 审计 API 支持 `kind/created_at/runId` 过滤与 seq 游标 | `apps/web/src/app/api/audit/events/route.ts:1-11` |
| 审计页有 `runId` 输入框，但只是文本过滤 | `apps/web/src/features/audit/audit-page.tsx:62-78` |
| 审批项把 `runId` 当普通文本展示 | `apps/web/src/features/approvals/approvals-page.tsx:109-110` |
| 任务行已有时间线链接 `/timeline?scope=task&id=` | `apps/web/src/features/tasks/task-row.tsx:112-116` |

结论：时间线存在、runId 也存在，两者没有连起来；任务详情也没有治理摘要。

## 5. 诊断与密钥：有备份，没有诊断包与轮换

| 事实 | 位置 |
|---|---|
| 备份按轨道导出 / 恢复，入口在设置页 | `apps/web/src/features/settings/backup-panel.tsx:16-60`、`apps/web/src/app/api/backup/restore/route.ts` |
| 密钥用 Electron `safeStorage` 加解密，走本地回环 cipher 桥 | `apps/desktop/src/main/cipher-server.ts:59-63` |
| 全仓 `diagnostic` 只出现在 UI 文案 / 无关模块，没有诊断包实现 | 全仓检索结论 |
| 审计链校验已有 `verify` 接口与 `AUDIT_CHAIN_BROKEN` | `packages/core/src/governance/audit.ts`、`apps/web/src/app/api/audit/verify/route.ts` |

结论：排障所需的数据大多已存在，但分散在设置、审计、健康自检里；缺一个白名单组装的脱敏诊断包，也缺密钥轮换入口。
