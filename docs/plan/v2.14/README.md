# v2.14 方案：可维护——能升级、能回退、能定位、能对账

> 状态：✅ M0 已冻结（2026-10-31，见 [01-M0-契约冻结](01-M0-契约冻结.md) / [02-M0-评审记录](02-M0-评审记录.md)）；✅ M1 技能版本化（[03-M1-实施记录](03-M1-实施记录.md)）；✅ M2 工作流生产版本（[04-M2-实施记录](04-M2-实施记录.md)）；✅ M3 能力包降级与修复（[05-M3-实施记录](05-M3-实施记录.md)），进入 M4 运行记录下钻
> 上一正式版：v2.13.0（可治理的 Agent：模式、策略、审批绑定、审计、定时任务、隔离网页）
> 主题一句话：**v2.12 让包可信，v2.13 让执行可治理，v2.14 把这两个版本留下的 P1 欠账清零。**

## 1. 版本主题与目标

v2.12 解决了能力包「装进来」的可信问题，v2.13 解决了 Agent「跑起来」的治理问题，但两条链路都留下了同一类欠账：**出事之后的回退与定位**。

- 技能只有启用开关，没有版本历史，改坏了只能手工回滚文件夹；
- 工作流虽然保存了版本行，但运行读取的是 `current_version`，编辑草稿会直接影响生产运行；
- 能力包只允许版本严格递增，降级与同版本修复安装一律 422；
- 审计与审批知道 `runId`，但没有入口跳到任务时间线，证据链最后一步靠手抄；
- 出问题时没有一键诊断包，只能让用户截图、翻日志、逐项问配置。

v2.14 不加新能力面，只把这五件事收口：**版本可回退、生产版本可控、包可降级可修复、证据可下钻、故障可诊断**。

### 1.1 成功指标（可验收）

| 指标 | 现状（v2.13） | 目标（v2.14） |
|---|---|---|
| 技能版本历史 | 只有 `enabled` 与 `source_path`，`manifest.version` 仅供展示 | 安装 / 升级时保存版本快照；可回退到任一历史版本；回退后启用态与磁盘一致 |
| 工作流生产版本 | 有 `workflow_versions`，但运行读 `current_version`；保存草稿即影响生产 | 显式「生产版本」；历史版本可设为生产；运行固定使用生产版本 |
| 能力包降级 / 修复 | 版本必须严格递增；同版本与降级均 422 | 二次确认的降级；同版本修复安装；依赖不满足时拒绝并给出原因 |
| 运行记录下钻 | 审计 / 审批只显示 `runId` 文本；任务时间线独立存在 | 审计事件、审批项一键跳到任务时间线；任务详情展示关联治理事件 |
| 故障诊断 | 无诊断包，只有备份导出 | 一键导出脱敏诊断 ZIP：版本 / 迁移 / 审计链校验 / 能力健康 / 最近错误 |
| 全量门禁 | Web e2e 128/128 | 不降级；新增运维 e2e ≥ 3 例 |

## 2. 现状与缺口（v2.13 取证）

| 面 | 现状 | 缺口 |
|---|---|---|
| 技能 | `skills_state` 只有 `id/name/enabled/source_path`；`SkillManifest.version` 只用于展示；磁盘按 `skills/<name>` 扫描 | 没有版本快照、历史列表与回退；升级失败只能手工恢复目录 |
| 工作流 | `workflow_versions` 保存 `version/graph_json/published_at`；`publishVersion(version)` 已支持发布指定版本 | 运行链路读 `getCurrentVersion`，编辑草稿即改变生产图；没有版本列表与「设为生产」入口 |
| 能力包 | 同 id 原地升级、失败自动回滚、健康自检 11 个 issue 码 | `compareCapabilityVersions <= 0` 一律拒绝：不能降级，也不能同版本修复安装 |
| 运行记录 | 审计支持 `runId` 过滤；任务行有 `/timeline?scope=task&id=` 链接 | 审计 / 审批没有跳转入口；任务详情不展示模式、目录、策略哈希与关联审计 |
| 诊断 | 备份导出 / 恢复（按轨道选择）、能力健康自检 | 没有面向排障的脱敏诊断包；密钥存在 Electron safeStorage，无轮换入口 |
| 迁移 | v041（运行治理字段 + 审计表） | 本版 v042 纯加法：技能版本表、工作流生产版本列 |

## 3. 功能清单

### P0 必做

**P0-1 技能版本化与回退**

- 用户故事：我更新了一个技能，结果它的提示词变差；我想一键回到上一版，而不是去翻文件夹。
- 版本快照：扫描到新版本或内容变化时，把技能目录快照到数据根 `skill-versions/<stateId>/<version>/`；`skill_versions` 表记录 name、version、manifest、checksum、created_at。
- 回退：`skills_state` 增加当前版本引用；回退把目标版本快照原子写回 `skills/<name>`，保持启用态不变。
- 边界：用户在应用外手工改 `skills/<name>` 时，按扫描到的 version + checksum 生成快照；自动保留最近 5 版且永不删除启用版本（P1 提供手动清理入口）。
- 验收：升级后回退，`manifest.version` 与行为恢复；重启后仍生效；无版本的老技能按现有方式工作。

**P0-2 工作流生产版本与回滚**

- 用户故事：我在编辑器里存了一版草稿，但线上流程不该立刻变；我要明确指定哪一版是生产版本。
- 数据：`workflows` 增加 `published_version`（v042 加法）；迁移时按已有 `published_at` 回填。
- 语义：运行 / 端点 / MCP 上下文读取生产版本；无生产版本时回退 `current_version`（兼容未发布草稿）。
- 版本列表：展示版本号、创建时间、是否生产；任意历史版本可「设为生产」，不改变 `current_version`。
- 验收：发布 v1 → 保存 v2 草稿 → 运行仍用 v1；把 v2 设为生产后运行用 v2；回退 v1 后恢复。

**P0-3 能力包降级与同版本修复安装**

- 用户故事：新版本包有 bug，我要回到旧版本；或者包文件损坏，我要用同版本重装修复。
- 降级：版本低于当前时要求 `confirmDowngrade=true` 与目标版本号；服务端校验反向依赖（其他包依赖当前版本时拒绝）。
- 修复：版本相同且 checksum 不同时允许 `repair=true` 重装；完全相同时提示无需修复。
- 失败处理：沿用 v2.12 的暂存目录 → 原子换位 → 失败回滚；降级不删除旧目录，成功后再清理。
- 验收：降级 2.0 → 1.0 成功；依赖不满足返回 422 并给原因；同版本修复后健康自检通过。

**P0-4 运行记录下钻**

- 用户故事：审计里看到一次拒绝，我想直接看当时的任务时间线，而不是复制 runId 再翻页面。
- 审计事件行与审批项：有 `runId` 时提供「查看任务」入口，跳 `/timeline?scope=task&id=<runId>`。
- 审计页：支持 `?runId=` 直达并预填过滤；任务详情增加治理摘要（模式、工作目录、策略哈希、来源定时任务）与最近审计事件。
- 权限：跳转只做导航，不改变审计只读语义；无 `runId` 的事件不显示入口。
- 验收：从审批项 / 审计事件一次点击到达时间线；时间线按 runId 正确过滤；空关联不出现死链。

**P0-5 一键诊断包**

- 用户故事：应用出问题时，我不想逐项截图；给我一个文件，我自己看或者发给开发者，都不泄露密钥和对话内容。
- 内容（白名单组装）：应用与迁移版本、平台 / 架构、能力健康汇总、审计链校验结果（首个断链 seq）、运行统计（按状态计数）、最近 N 条错误摘要、配置摘要（供应商数量、策略哈希、默认模式）。
- 排除：API Key、令牌、密码、对话 / 记忆正文、绝对路径（统一替换为 `<data-root>` / `<app-dir>`）、域名清单明细。
- 形式：本地生成 ZIP 下载，不上传；`manifest.json` 含生成时间与条目清单。
- 验收：30 秒内生成；用带哨兵密钥的测试数据 grep 零命中；审计链断链时诊断包正确标注。

### P1 争取

1. **技能版本清理入口**：列表展示占用，手动删除旧快照，保留策略可配置。
2. **审计归档与外部锚点**：按天导出 JSONL + 链尾哈希文件，缓解「尾部截断不可检出」。
3. **密钥轮换**：重新加密存储中的密钥，清理旧密文，失败不影响既有调用。
4. **工作流版本对比**：图节点 / 边差异摘要，不做到逐字段 diff。

### P2 留白

- IM 渠道与远程访问、多用户与团队部署。
- 多 Agent 并行与可移植 Recipes。
- 远程技能 / 流程市场。
- OS 级沙箱、云 Worker、跨设备续跑。

## 6. 风险与取舍

- **生产版本语义变更**：运行时从 `current_version` 切到 `published_version`，必须保留「无生产版本则回退当前版本」的兼容路径，否则历史草稿工作流会突然不可运行。
- **技能快照占磁盘**：技能目录可能含资源文件；快照设置单目录上限并保留最近 5 版，超限拒绝快照而不是悄悄丢版本。
- **降级的数据兼容**：能力包设置 / effect 数据可能向前不兼容；降级只能保证代码与清单回退，不承诺数据回滚，必须在确认框里写清楚。
- **诊断包泄密**：采用白名单组装而非黑名单脱敏；测试用哨兵密钥与示例对话正文验证零命中，路径统一占位。
- **行数门禁**：技能版本服务、诊断收集器、版本面板都要按 ≤300 行拆分，不靠压缩换行。
- **范围控制**：不借「版本化」扩成远程市场，不借「诊断」引入云上传。

## 7. Non-Goals（本版明确不做）

- 不做 IM 渠道、远程访问、多用户与团队协作。
- 不做新 Agent 能力、子 Agent 并行、可移植 Recipes。
- 不做远程市场、自动更新技能 / 流程、依赖自动安装。
- 不做 OS 级沙箱、云 Worker、跨设备续跑。
- 不做审计自动删除（归档与外部锚点只到 P1）。
- 不修 v2.13 已登记的边界：重定向二次 DNS 私网解析、定时任务跨进程生命周期、Web 模式浏览器能力。

## 8. 验收口径

1. 技能：安装 / 升级产生版本快照；回退到任一版本后行为与 manifest 一致；重启后保持；无版本技能不受影响。
2. 工作流：保存草稿不改变生产运行；任意历史版本可设为生产；端点与 MCP 调用使用生产版本。
3. 能力包：降级需二次确认；反向依赖不满足时拒绝；同版本修复安装可用；失败自动回滚。
4. 下钻：审计事件与审批项可一次点击进入任务时间线；`/audit?runId=` 直达过滤；任务详情展示治理摘要。
5. 诊断包：内容符合白名单；密钥、对话正文、绝对路径零出现；审计链断链可标注。
6. 迁移：v041 → v042 旧库升级保留数据；回退旧版本可打开同一数据库。
7. 门禁：`pnpm check`、八包单测、生产模式 Web 全量 e2e（不低于 128 例）与桌面冒烟不降级。
8. 发布：版本 2.14.0、NSIS 安装包 + blockmap + latest.yml、Release 转正并置 Latest。
