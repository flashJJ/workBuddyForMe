## 3. 关键口径

1. **白名单组装**：每个文件独立从数据库 / 服务读取固定字段，不做「先收集再过滤」。
2. **manifest**：包含 formatVersion、应用版本、实际 schemaVersion、平台 / 架构、生成时间与其余 7 个文件的路径 / 大小 / sha256。
3. **错误日志**：从 `session_events` 取最近 1000 条，再筛 `error / failed / blocked / denied / timeout` 类型，只输出时间、scope、净化后的类型与 `error.code`。
4. **审计截断**：`total > 100000` 时从第 `total - 100000 + 1` 条的 `prev_hash` 续链；`audit-verify.json` 带 `truncated`。
5. **超时**：每个文件装配前检查预算；超时抛 `DIAGNOSTICS_TIMEOUT`（503）。
6. **工作目录**：设置中没有全局工作目录字段，`workspaceConfigured` 表示「最近 7 天存在带 workspacePath 的运行」。

## 4. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | `truncated` 字段 | 只写入 `audit-verify.json`，不改动共享 `AuditVerifyResult` 的既有返回结构 |
| 2 | 错误级事件来源 | 使用追加式 `session_events`（无独立错误日志文件）；只输出类型与安全错误码 |
| 3 | 下载方式 | 浏览器 fetch + blob 下载，保留结构化错误码提示；不使用整页跳转 |
| 4 | ZIP 上限 | 白名单内容天然远低于 10 MB；端点仍做防御性大小检查 |
