## 3. 关键口径

1. **两个版本号**：`current_version` = 最近保存（编辑器打开的内容）；`published_version` = 生产运行版本；`status` 只表示是否存在未发布改动。
2. **兼容路径**：`published_version` 为空时运行回退 `current_version`；从未发布的工作流仍按原有 `status` 校验拒绝 chat / 对外调用。
3. **发布即生产**：显式 `publish` 同时写两个版本号，符合 v2.13 的发布语义；「设为生产」只写生产版本号。
4. **运行一致性**：运行、flow 工具、MCP 上下文、对外端点、能力健康与会议行动项统一用生产版本判定，避免出现「UI 草稿态但生产仍可用」的不一致。
5. **错误口径**：设为生产时版本不存在 → 404 `FLOW_VERSION_NOT_FOUND`；非法 body → 422。
6. **UI 文案**：无生产版本显示「尚未设置生产版本，运行将使用当前版本 vN」；有生产版本且草稿领先时显示「生产版本 vP；当前草稿 vC」。

## 4. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | `publish` UI | 工具栏「发布」仍发布当前保存版本；历史版本切换统一走版本抽屉「设为生产」，避免两个入口语义重叠 |
| 2 | 状态徽章 | 保存草稿后 `status=draft`，但生产版本仍生效；编辑器横幅明确两者关系 |
| 3 | 健康 / 会议判定 | 契约只点名运行与 MCP；实施时同步调整能力健康与会议行动项，否则草稿编辑会误报能力失效或拒绝运行 |
