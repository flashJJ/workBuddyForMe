## 1. 本里程碑做了什么

| 能力 | 行为 |
|---|---|
| 自动快照 | 技能扫描确认 manifest 后按 `(version, checksum)` 去重；同版本内容变化覆盖快照内容 |
| 保留策略 | 每个技能自动保留最近 5 版，永不删除 `active_version`；更早的行与目录一并清理 |
| 回退 | 快照目录先复制到临时目录，原技能目录改名为 `.rollback-backup-*`，临时目录换位后删除备份；任一步失败恢复原目录并返回 `SKILL_ROLLBACK_FAILED` |
| 启用态 | 回退只换文件，不改 `skills_state.enabled`；`active_version` 只由扫描确认与回退成功更新 |
| 历史连续性 | 能力包升级会重建 `skills_state` 行；列表按技能名聚合，同版本同 checksum 复用既有快照目录，历史不丢也不重复占盘 |
| 体积上限 | 单技能目录超过 50 MB 不建快照，写 `SKILL_VERSION_SNAPSHOT_TOO_LARGE` 警告，技能照常加载，版本列表返回 `versioningAvailable=false` |
| 可视化 | 技能面板每个技能可展开「版本历史」，展示版本号、创建时间、当前徽章与回退按钮（二次确认） |

## 3. 关键实现口径

1. **目录结构**：快照根默认与 `skills/` 同级（`<data-root>/skill-versions/<stateId>/<version>/`），测试可注入；版本号非法字符净化后追加短哈希，防止路径穿越与碰撞。
2. **checksum**：`sha256(canonicalJson({ files:[{ path, size, sha256 }] }))`，`path` 为相对技能目录、`/` 分隔、升序；同 checksum 只更新 `active_version`。
3. **跨状态行历史**：`skill_versions` 保留 `skill_state_id` 与 `name`；读取按 `name` 聚合、每个版本优先当前状态行。能力包升级重建状态行后，同版本同 checksum 直接复用旧快照目录。
4. **回退原子性**：复制快照 → 备份原目录 → 换位 → 删除备份；失败时把备份改回原位置，再抛 `SKILL_ROLLBACK_FAILED`。
5. **失败隔离**：快照是旁路能力，复制异常只记日志，不阻断 reconcile / 技能加载；超限返回明确 issue 码并保持 `versioningAvailable=false`。
6. **健康可见性**：回退后立即重扫；若 manifest 损坏，现有 `SkillInfo.error` 会在技能面板标红，由用户修复。
