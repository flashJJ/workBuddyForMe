# 05 交互、模组与 AI：把「能点」变成「有反应」

> 结论：现有 `resolveInteraction` + `ActionExecutor` 已经是正确方向，缺的是
> **数据驱动的命中区、反应组合、冷却/勿扰门控**，以及可扩展的资源包格式。

## 1. 现状

- 命中区硬编码在 `pet-hit-regions.tsx`：头/身体两个矩形，手势靠 pointer 事件；
- 互动由 `resolveInteraction(event, ctx, graph)` 解析为动作链，`ActionExecutor` 执行；
- 已有关系等级、勿扰时段、互动短句开关、工作信号气泡；
- 缺少尾巴/脸颊等细分区，缺少「同一动作不同反应」的权重与冷却配置。

## 2. 数据驱动命中区

把命中区从组件常量迁到角色包：

```json
{
  "hitRegions": [
    { "id": "head",  "polygon": [[0.32,0.08],[0.68,0.08],[0.70,0.30],[0.30,0.30]] },
    { "id": "face",  "polygon": [[0.38,0.14],[0.62,0.14],[0.62,0.26],[0.38,0.26]] },
    { "id": "body",  "polygon": [[0.30,0.34],[0.70,0.34],[0.74,0.78],[0.26,0.78]] },
    { "id": "tail",  "polygon": [[0.68,0.52],[0.88,0.60],[0.84,0.72],[0.66,0.66]] }
  ]
}
```

- 与 `HitProxyBuilder` 使用同一份数据，避免「渲染一套、交互一套」；
- 坐标归一化，适配任意窗口尺寸与 DPI；
- 角色包可覆盖，内置角色给默认值。

## 3. 手势与门控

| 手势 | 头 | 脸 | 身体 | 尾巴 |
|---|---|---|---|---|
| 单击 | 摸头/开心 | 戳脸/害羞 | 拍一拍/回应 | 尾巴弹一下 |
| 双击 | 回主窗 | 回主窗 | 角色动作 | 甩尾 |
| 长按 | 撸头 | — | 抱起/挣扎 | 抓住尾巴 |
| 拖拽 | — | — | 移动窗口 | 拖尾 |

门控（复用现有能力）：

1. **冷却**：按 `region::gesture` 记时间戳，默认 1.5–4 s；
2. **勿扰**：23:00–06:00 只保留最小反馈（表情/动作，不出声）；
3. **关系等级**：0–3 级解锁不同台词/动作；
4. **忙碌**：说话/拖拽/睡眠时拒绝低优先级触摸；
5. **重复惩罚**：连续戳同一区域，反应强度递减，避免鬼畜。

## 4. 反应组合

一次交互不是「播一个动作」，而是组合：

```text
动作（body motion）
  + 表情（expression）
  + 台词（i18n key）
  + 音效（SFX，可空）
  + 粒子（可选）
  + 关系值变化（可选）
```

执行顺序：表情先于动作 1 帧，台词与动作同起，音效延后 80–120 ms，粒子跟随命中点。

打断规则：新反应进入时，旧反应 `fadeOut(0.12s)`；台词直接替换，不排队。

## 5. 环境感知行为

在「能点」之外，增加不需要用户操作的反馈：

| 行为 | 触发 | 实现 |
|---|---|---|
| 视线跟随 | 指针移动 | 主进程 30 Hz 光标 → 头/眼叠加层 |
| 贴边探头 | 拖到屏幕边缘 | 检测 `workArea` 边缘，切 `peek` 动作 |
| 坐窗口 | 拖到窗口顶边 1 s | Win32 枚举 + 顶边吸附（见 02） |
| 坐任务栏 | 拖到任务栏边缘 | `workArea` 边缘吸附 |
| 睡眠 | 10 min 无交互 | AnimationDirector Sleep 状态 |
| 工作状态 | 现有工作信号 SSE | 气泡 + 表情（已实现） |
| 久别迎接 | 长时间未打开 | 现有 reunion 逻辑 |

## 6. 模组 / 角色包

目标：让二创只提供资源，不执行代码。

```text
pet-pack/
  manifest.json
  model/xuetuan.vrm
  animations/idle.vrma
  animations/sit.vrma
  sounds/tap.ogg
  hit-regions.json
  LICENSE
```

```json
{
  "id": "xuetuan",
  "name": "雪团",
  "version": "1.0.0",
  "model": "model/xuetuan.vrm",
  "animations": { "idle": ["idle"], "sit": ["sit"] },
  "sounds": { "tap": "sounds/tap.ogg" },
  "hitRegions": "hit-regions.json",
  "license": "CC-BY-4.0",
  "minAppVersion": "3.0.0"
}
```

规则：

- 只允许 JSON + 模型/音频/动作资源，**禁止脚本**；
- 路径必须相对、禁止 `..`、限制总大小（≤ 100 MB）；
- 加载失败回落到内置角色，不阻塞桌宠启动；
- 角色包与现有舞台/主窗共用同一模型注册表，避免三套加载逻辑。

## 7. 语音与 AI

### 7.1 已有能力优先

- 对话走现有服务端流式接口；
- 朗读走 `/api/voice/tts` + `wavToVoiceFrame` + 播放队列；
- 口型走播放电平；
- 桌宠只负责表现，不复制业务逻辑。

### 7.2 本地 LLM 的取舍

Mate-Engine 内置 Qwen 2.5 1.5B（LLMUnity），优点是离线、隐私；代价是：

- 常驻内存 1–2 GB；
- 首 token 延迟与 CPU 占用；
- 模型分发体积。

本项目已有本地优先的服务端对话与记忆，**不建议默认内置**；可作为「离线模式」可选包（v3.2 评估）。

### 7.3 主动说话

复用现有 proactive 开关与静默时段；桌宠侧只暴露：

- `canSpeak()`：勿扰/静音/睡眠时返回 false；
- `speak(text, { emotion, duration })`：字幕 + TTS + 口型；
- 说话期间暂停待机主动作，保留眨眼/视线。

## 8. 多角色（v3.1）

Mate-Engine 支持最多 9 个角色同屏，技术上是一个进程内多个 Avatar 实例。  
Electron 侧等价方案是多个桌宠窗，但命中、性能、音频出口都会翻倍。建议 v3.1 再评估，v3.0 只做单角色。

## 9. 验收

| 项 | 目标 |
|---|---|
| 命中区 | 头/脸/身体/尾巴均可独立触发，边缘误差 ≤ 2 DIP |
| 冷却 | 连续点击 10 次，同一反应不连播超过 2 次 |
| 勿扰 | 时段内无声音，仅表情/动作 |
| 打断 | 拖拽可打断任何待机/触摸动作 |
| 角色包 | 导入非法包不崩溃，回落内置角色 |
| 语音 | 说话有口型，静音保留字幕 |
| 安全 | 角色包不能执行任意代码/越权读文件 |
