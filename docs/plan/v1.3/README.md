# Release v1.3 方案 · 知识变厚：编译式 RAG 与知识治理 —— 总览

> 版本：v1.3（基线 tag `v1.2.0`，main `9ff38c7`；分支 `feature/v1.3-knowledge` 拟从 main 切出）
> 日期：2026-10-10
> 主题：**让私有知识库从「上传后现查现算」升级为「预编译、可追溯、可治理」的本地知识层**
> 上一版方案：[v1.2 正式发布打磨](../v1.2/README.md)
> 选型结论：本版为 [v1.3 主题提案](../../plan/v1.3/README.md) 候选 A（三选一拍板）

---

## 1. 一句话方案

v1.2 让产品「装得上、用得懂英文、新人有引导」；v1.3 回答留存问题——**用户持续喂进来的资料，能不能越用越准、越用越快，并且每条回答都查得到原文出处？** 当前 RAG 是单跳向量检索：查询 embed 后在 sqlite-vec 做 L2 top-4，取原始 chunk 直接拼进提示词，没有关键词通道、没有重排、没有静态知识层，引用只到「文档 + 片段序号」。v1.3 在不引入云服务、不新增重型运行时依赖的前提下，沿现有 ingestion/retrieval 链路加深：**文档预编译（摘要/实体/关系）+ 向量与 FTS5 混合检索 + 重排 + 语句级引用 + 知识治理（去重/冲突/版本/增量重编译）+ 可度量的 eval golden set**。

## 2. 目标与非目标

### 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 知识编译层 | 文档索引后产出文档摘要与实体/关系编译产物（存本机 SQLite）；问答时「编译知识优先、chunk 检索补细」；编译产物可在设置中查看与重建 |
| G2 | 混合检索 | 向量 + FTS5 双通道召回并融合；纯函数融合打分可单测；纯关键词问题（型号/编号/人名）命中率显著高于单向量基线（eval golden 对照） |
| G3 | 重排与预算自适应 | 召回后统一重排（默认无模型规则重排，可选本地 chat 模型 LLM 重排开关）；注入片段数从固定 4 改为按上下文预算自适应；重排纯函数行覆盖 ≥95% |
| G4 | 语句级引用 | chunk 携带页码/段落坐标（PDF 页码、其余段落序号）；引用角标可定位到页/段；Citation 契约向后兼容（旧字段不删，新坐标可选） |
| G5 | 知识治理 | 同库内容哈希/同源 URL 去重（现状已有底座，补齐交互）、跨文档事实冲突检测标记、文档替换即增量重编译并使旧编译产物退役；治理动作在知识库 UI 可见 |
| G6 | 后台调度与可观测 | 编译为可取消/可重试/可看进度的后台任务（复用现有任务体系，不新建调度框架）；编译失败不阻断普通 chunk 检索；空闲调度有开关与资源上限 |
| G7 | eval 知识 golden set | 复用 v1.1 eval 平台新增 knowledge 域：问题→期望引用文档/期望事实断言；**关闭混合检索/编译层后断言应失败**（反向验证），全链 CLI 化 |
| G8 | 零回归 | check 14 任务不降级；现有 critical-path ⑤ RAG e2e 全绿；备份/恢复（向量不备份、恢复重嵌入）行为不变；P1 七域英文化作为伴随批次完成 |

### 非目标（本版本明确不做）

- **不做云端知识服务/多用户协作知识库/在线同步**：编译与检索全部在本机（延续本地优先宪法）
- **不做多智能体编排**：留 v1.4 在知识层之上评估（agent 共享编译知识是后续组合，不在本版）
- **不引入新的重型运行时依赖**：FTS5 是 SQLite 内置（better-sqlite3 已在用）；实体抽取默认走规则+embedding 聚类的无模型通道，LLM 抽取仅在用户已配置本地/云端 chat 模型时作为可选增强
- **不改备份归档基本格式**：编译产物与向量同属「可由源文档重建的派生索引」，不进导出；导出仍以源文档+分片文本+对话为准
- **不做可视化知识图谱 UI**：实体/关系以结构化产物与文本引用呈现，图谱画布留后续版本
- **不承诺所有文件格式都有页码**：页码坐标首期仅 PDF；Office/剪藏/文本以段落序号为坐标
- **不做跨语言翻译式检索增强（query 改写/多语向量）**：本期保持单语言直接检索

|---|---|---|
| M0 | 坐标与索引基座 | v017 迁移：chunk 页/段坐标列 + FTS5 全文虚表与同步；摄取保留 PDF 页边界；中文分词 spike |

## 4. 关键设计决策

1. **编译层是派生索引，不是新事实源。** 源文档与分片文本仍是唯一事实源；摘要/实体/关系与向量一样可删除、可重建，不进备份导出。这条边界保证编译出错不会污染原始知识，也让「重建索引」永远是安全操作。

2. **默认无模型也能编译，LLM 只做增强。** 本地优先产品不能假设用户装了 Ollama：M2 的基线抽取器用确定性规则（标题/数字/专名启发式）+ embedding 聚类产出实体候选与文档摘要（首段+高频句抽取），零额外调用、结果稳定可单测；配置了 chat 模型时可在设置中开启 LLM 增强（云端或本地用户自担隐私边界，与现有供应商链路一致）。两条通道写同一套编译产物 schema。

3. **混合检索用 RRF 在排名层融合，不混分数。** 向量 L2 距离与 FTS5 bm25 分数量纲不同，直接加权需要反复调参；用 Reciprocal Rank Fusion（`1/(k+rank)`）只依赖两路排名，纯函数、免标定、可单测。最终分仅用于排序与阈值，不展示给用户。

4. **中文全文检索先用 M0 spike 定方案，不预设。** SQLite FTS5 的 unicode61 对无空格中文会把连续汉字当一个 token；候选方案为 trigram 分词器（SQLite ≥3.34，子串匹配天然适合中文）或对写入文本做 uni-gram 加空格。以 better-sqlite3 实际链接的 SQLite 版本与一组中文查询基准做 spike，结论写进 M0，退路明确。

5. **页码坐标从「提取时保留边界」获得，不做事后猜页。** 现有 `readPdfPageTexts()` 已能逐页取文本，只是摄取时被 join 成整文丢掉边界。M0 在提取结果中保留每页字符偏移，分片时据 charStart 反查页码；找不到页边界的格式降级为段落序号，坐标字段允许为 null（契约向后兼容）。

6. **重排默认无模型、可观测。** 固定规则重排（标题命中/关键词覆盖/新鲜度/精确短语）为默认且零成本；LLM 重排是显式开关，开启后在 UI 与任务中可看到额外模型调用，关闭时检索质量不退到 v1.2 以下（G3 要求纯规则重排的 golden 成绩不低于单向量基线）。

7. **增量重编译以「文档」为最小单位，编译产物带世代号。** 文档替换/删除只重算该文档的编译产物；跨文档实体合并是读取时归并，不维护脆弱的全局写时合并。旧世代产物在新世代提交成功后才删除（事务内换代，失败可回退），避免半编译状态被检索读到。

8. **治理只做「提示与隔离」，不做自动删除。** 冲突检测标记出「同一实体不同取值」让用户裁决，去重提示让用户决定是否移除；本地优先产品里自动删用户资料是不可逆操作，系统只建议不执行。
