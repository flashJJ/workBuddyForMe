## 2. 三个候选主题

### 候选 A：「知识变厚」——编译式 RAG 与知识治理（推荐）

**现状基线（已核对代码）**：当前 RAG 链路是单跳向量检索——查询经 embedding 后由 sqlite-vec 做 L2 top-k（`DEFAULT_RETRIEVAL_TOP_K = 4`）取原始 chunk 直接拼上下文（[rag-retriever.ts](../../../packages/core/src/retrieval/rag-retriever.ts)、[retrieval-service.ts](../../../packages/core/src/retrieval/retrieval-service.ts)）。无混合检索、无重排、无静态知识层、引用粒度只到「文档+chunk 序号」。

**核心命题**：知识库从「上传文档→切块→现查现算」升级为「文档→预编译知识层（实体/关系/摘要）→静态知识优先检索」，让常用资料的回答更快、更准、可追溯到页/段。

- 知识编译管线：文档摄取后离线产出摘要、实体/关系索引（本地 LLM/embedding 均可，复用现有 ingestion 队列与 Ollama 通道）
- 混合检索 + 重排：向量 + 关键词（FTS5）召回融合，小模型 cross-encoder/LLM 重排，top-k 从固定 4 改为预算自适应
- 引用升级：chunk 携带页码/段落坐标，回答语句级绑定出处（Source + Page + Paragraph）
- 知识治理：文档去重、冲突检测、版本管理与增量重编译；失效文档的旧编译产物自动退役
- 评估：v1.1 eval 平台新增知识 golden set（问题→期望引用/期望事实），带反向验证

**为什么推荐它**：① 知识是既有核心域，架构上是「在现有链路上加深」而非新开战线，风险可控；② 本地优先产品的护城河正是「我的资料越用越懂我」，与无账号/无云的定位一致；③ v1.1 已备好压缩层与 eval 平台、v1.0 已备好本地模型通道，前置条件全部就位；④ 效果可用 golden set 机械度量，符合「成功指标必须可验证」的版本宪法。

**主要风险**：编译质量依赖本地模型能力（小模型实体抽取不稳定）；增量重编译的失效语义复杂；首次全量编译耗时/耗电需要明确的后台调度与可观测性。

### 候选 B：「团队协作」——最小多智能体编排

规划-执行-审查三角色（3–5 个 agent），任务分解与 Handoff Format，共享上下文 + 记忆隔离边界。

- **价值**：复杂桌面任务（跨应用多步操作）的成功率上限更高；演示效果强。
- **不推荐作为 v1.3 主题的原因**：单机半双工产品上多 agent 通信开销与 token 成本放大明显；现有 Flow 已经覆盖「确定性多步编排」，多智能体的增量价值边界需要先做 spike 而非直接立版本；记忆隔离/权限授予的安全语义在桌面控制域是新增风险面。建议 v1.4 在 A 候选沉淀的知识层之上再评估（agent 共享编译知识是天然组合）。

### 候选 C：「发布后打磨」——小版本收尾（不立主题）

把 P1 英文化、toast 帮助锚点、真机反馈的小问题做一个纯收尾版本。

- **不推荐独立成版**：内容不足以支撑「一个版本一个主题」，且会再次进入无能力增量的版本（v1.1 已做过一次工程向版本）；建议作为 v1.3 主题版本内的伴随批次消化。

## 3. 推荐的 v1.3 形态（主题 A 粗框，非正式功能清单）

**主题：知识变厚——编译式 RAG 与知识治理**

| 粗目标（待四篇方案细化为可机械验收指标） | 方向 |
|---|---|
| G1 知识编译层 | 文档摄取后产出摘要/实体/关系的预编译产物，存本机；问答时静态知识优先，缺失再回落 chunk 检索 |
| G2 混合检索与重排 | 向量 + FTS5 召回融合 + 重排；top-k 预算自适应；纯函数融合/重排打分可单测 |
| G3 语句级引用 | 引用坐标到页/段；回答可定位原文位置（PDF/Office 现有页码元数据先接通） |
| G4 知识治理 | 去重/冲突标记/文档版本/增量重编译与旧产物退役 |
| G5 后台调度与可观测 | 编译任务走现有任务/队列体系，可取消、可看进度、失败可重试，不阻塞对话 |
| G6 eval 知识 golden set | 复用 v1.1 eval 平台，问题→期望事实/引用断言，带「关闭编译层即退化」的反向验证 |
| G7 零回归 + 伴随项 | 全门禁不降级；P1 域英文化作为本版伴随批次完成 |

**预设 Non-Goals**：不做云端知识服务/多人协作知识库；不做多智能体（留 v1.4 评估）；不改备份导出的基本格式（编译产物作为可重建索引，导出仍以源文档+对话为准）；不引入新的运行时重型依赖（FTS5 是 SQLite 内置）。

**迁移预期**：新增知识编译产物表（v017，纯加法）；旧库首次启动不自动全量编译，按知识库显式「编译」或摄取时增量进行。
