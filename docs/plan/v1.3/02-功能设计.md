# v1.3 功能设计：编译式 RAG 与知识治理

> 约定：所有新增纯逻辑（融合/重排/坐标映射/抽取/冲突判定）落在无 I/O 依赖的纯函数模块并密集单测；SQL/仓储放 database 包；编排放 core；API 放 apps/web/app/api；UI 放 features/knowledge。单文件 ≤300 行，超限即按域拆分。

---

## 1. 总体架构

```
                         ┌──────────── 派生索引（可删除/可重建，不进备份）────────────┐
源文档（事实源）          │ document_chunks(+坐标)  chunks_vec(FTS 同步)  编译产物表 ×3 │
  上传/剪藏/替换           │      ↑ 文本/向量通道           ↑ 关键词通道        ↑ 静态知识   │
  ──────────────► 摄取管线 ├─ extract(保留页边界) → chunk → embed → vec             │
                     │     └──────────────────────────► fts_chunks(uni-gram)        │
                     │                                                              │
                     └─► 知识编译器（后台任务，世代号）                              │
                          无模型：规则摘要 + 专名/数字启发式 + embedding 聚类          │
                          LLM 增强（可选，走已配置 chat 模型）                        │
对话检索（新路由）：
  query ─┬─ FTS5 召回（关键词，topN）─┐
         ├─ vec0 召回（语义，topN）──┼─► RRF 融合(纯函数) ─► 规则重排(纯函数) ─► 预算自适应
         └─ 编译实体/摘要命中（精确/别名）┘                              │
                                          └─（可选）LLM 重排 ─► 上下文块 + 语句级 Citation
```

三层抽象：**召回（recall）→ 融合排序（fuse+rerank）→ 装配（assemble）**，彼此纯函数衔接；编译器独立于问答链路，产物经同一检索入口被消费。

## 2. 数据模型（v017，纯加法迁移）

### 2.1 chunk 坐标扩展（ALTER TABLE 加列，旧行回填 NULL）

```sql
ALTER TABLE document_chunks ADD COLUMN page_no INTEGER;      -- PDF 页码（从 1）；非 PDF 为 NULL
ALTER TABLE document_chunks ADD COLUMN paragraph_no INTEGER; -- 文档内段落序号（从 1，按提取段落）
```

坐标由摄取期的「字符偏移→页/段映射」计算（§3），不做运行时猜测。

### 2.2 FTS5 全文虚表（外部内容表，避免文本双份存储）

```sql
CREATE VIRTUAL TABLE IF NOT EXISTS chunks_fts USING fts5(
  content,                                    -- uni-gram 归一化后的可检索文本
  chunk_id UNINDEXED,                         -- = document_chunks.id
  kb_id UNINDEXED,                            -- 冗余知识库 id，免 join 即可按库过滤
  tokenize = 'unicode61'
);
```

- 中文处理不依赖 trigram（实测 2 字词不中）：写入/查询前经纯函数 `tokenizeForFts(text)` 归一化——CJK 统一表意文字逐字插空格，拉丁字母/数字保留整词并小写。
- chunk 增删时在同一事务内同步 FTS 行（bulk insert/delete 与 vec 同步，见 §3.3）。不使用 external-content/trigger 方案：跨事务重建时触发器行为难控，显式同步与现有「删旧→写新」事务一致。
- 重建索引入口：`rebuildFts(db)` 全量重灌（幂等，先 DROP 再 CREATE 再灌）。

### 2.3 编译产物三张表（派生数据，可整体重建）

```sql
-- 文档级摘要
CREATE TABLE IF NOT EXISTS document_summaries (
  document_id TEXT PRIMARY KEY REFERENCES documents(id) ON DELETE CASCADE,
  generation INTEGER NOT NULL DEFAULT 1,      -- 编译世代（与文档内容版本绑定）
  tldr TEXT NOT NULL,                         -- 一句话摘要
  bullets TEXT NOT NULL DEFAULT '[]',         -- JSON string[]：要点句（原文句子，可回指）
  key_terms TEXT NOT NULL DEFAULT '[]',       -- JSON string[]：文档级关键词
  extractor TEXT NOT NULL,                    -- 'rule' | 'llm'
  model_id TEXT,                              -- LLM 增强时记录模型
  created_at TEXT NOT NULL
);

-- 知识库实体表（跨文档归并在读取时按 normalized_name 聚合）
CREATE TABLE IF NOT EXISTS knowledge_entities (
  id TEXT PRIMARY KEY,
  knowledge_base_id TEXT NOT NULL REFERENCES knowledge_bases(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  normalized_name TEXT NOT NULL,              -- 去空白/小写/别名归一键
  kind TEXT NOT NULL DEFAULT 'concept',      -- concept | person | org | product | number | other
  description TEXT NOT NULL DEFAULT '',       -- 来自原文的最具代表性原句
  aliases TEXT NOT NULL DEFAULT '[]',         -- JSON string[]
  mention_count INTEGER NOT NULL DEFAULT 1,
  UNIQUE(knowledge_base_id, normalized_name)
);

-- 实体在具体文档/分片中的出现（关系边与出处统一为 mention）
CREATE TABLE IF NOT EXISTS knowledge_entity_mentions (
  id TEXT PRIMARY KEY,
  entity_id TEXT NOT NULL REFERENCES knowledge_entities(id) ON DELETE CASCADE,
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  chunk_id INTEGER REFERENCES document_chunks(id) ON DELETE CASCADE,
  page_no INTEGER,
  paragraph_no INTEGER,
  context TEXT NOT NULL,                      -- 出现处的原句（回指片段）
  generation INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_mentions_entity ON knowledge_entity_mentions(entity_id);
CREATE INDEX IF NOT EXISTS idx_mentions_doc ON knowledge_entity_mentions(document_id);
```

- **实体间关系**（如「产品 X 兼容 协议 Y」）首期不单独建边表：无模型通道难以稳定产三元组，强行落库噪声大；M2 先把「同一句/同一 chunk 共现的实体对」作为隐式关系（读取时用 mention 共现回答「X 和 Y 的关系」）。显式关系表留 v1.4 随 LLM 通道成熟再加（Non-Goal）。
- **世代语义**：mentions/summaries 带 generation；文档重编译在一个事务内写新世代、删旧世代，读侧永远只见完整世代。`documents` 加列 `compile_generation INTEGER DEFAULT 0` 与 `compiled_at TEXT`（标该文档编译到第几世代；未编译=0，检索回落 chunk-only）。
- 编译失败不影响 documents.indexeded 状态与向量检索；编译状态独立字段 `compile_status TEXT DEFAULT 'skipped'`（skipped|queued|running|ready|failed）与 `compile_error TEXT`。

## 3. 摄取改造：保留页/段坐标

### 3.1 提取结果带结构

`extractDocumentText` 返回值扩展为 `{ text, ocr, structure }`：

```ts
interface TextStructure {
  /** 每个「源段落」的起止字符偏移（相对归一化后的 text）与来源页码（可空） */
  blocks: Array<{ charStart: number; charEnd: number; pageNo: number | null; paragraphNo: number }>;
}
```

- PDF：`readPdfPageTexts()` 已有逐页数组，改为在 join 时记录每页 baseOffset；页内按空行/句号切段，paragraphNo 文档内连续编号。
- Office/网页/纯文本：无页码（pageNo=null），按现有段落拆分给 paragraphNo。
- 纯函数 `mapChunkCoordinates(slices, blocks)`：用每个 slice 的 charStart/charEnd 求覆盖区间——pageNo 取该 slice 首字符所在页（跨页取起始页并允许同段多页时以起始页为准），paragraphNo 取起始段。无法映射为 null，不阻断。

### 3.2 chunking 输出不变

`chunkText()` 已产 charStart/charEnd，不改算法；坐标是切片外层映射，保持 chunking 纯函数零回归。

### 3.3 落库与三索引同步（同事务）

chunk 仓储 bulkInsert 扩 pageNo/paragraphNo；ingestion 在现有「删旧→写 chunks→写 vec」事务中加入：
1. `DELETE FROM chunks_fts WHERE kb_id=? AND chunk_id IN(该文档 chunks)`（或按文档子查）；
2. 批量插入 chunks_fts（content=`tokenizeForFts(chunk.content)`）；
3. 编译产物随文档删除级联（FK CASCADE），compile_status 复位为 queued（等后台编译，§7）。

## 4. 混合检索（M1）

### 4.1 双通道召回

```ts
interface RecallHit { chunkId: number; score: number /* 路内可比 */; channel: 'vec' | 'fts'; }
function recallVec(db, { kbId, vector, candidateN }): RecallHit[]   // distance 归一化为相似度
function recallFts(db, { kbId, query, candidateN }): RecallHit[]   // bm25 排序
```

- 候选数 candidateN（默认 20，可配）远大于最终 top-k；FTS 查询串由 `buildFtsQuery(tokens)` 纯函数生成（uni-gram 后用 OR/短语，转义特殊字符）。
- 向量相似度：`sim = 1 - distance/2`（单位向量 L2 距离∈[0,2]）；**距离阈值** `MIN_VEC_SIM`（默认 0.55，可在检索设置调）以下不入围；FTS bm25 归一化到 [0,1]（按路内 min-max 或 1/(1+b) 固定映射，纯函数里定死并测试）。

### 4.2 RRF 融合（纯函数，免标定）

```ts
function reciprocalRankFusion(
  channels: Array<{ hits: RecallHit[]; weight?: number }>,
  k = 60,
): Array<{ chunkId: number; rrf: number; channels: string[] }>
// score = Σ_c weight_c · 1 / (k + rank_c)
```

- 同 chunk 两路命中：分数相加并记录 channels（后续重排的「双通道命中加权」依据）。
- 纯函数测试：单路退化为该路排名序；两路一致时高排位不变；同分稳定按 chunkId；权重生效。

### 4.3 去重与预算自适应

- 同文档相邻 chunk 命中过多时做**多样性去重**：同一文档至多保留 `MAX_PER_DOC`（默认 3）个，超出按融合分保留（纯函数 `diversify(hits, maxPerDoc)`）。
- 最终条数不再写死 4：装配侧 `fitContextBlock` 已按 token 预算贪心，M1 把召回扩大到候选池，让预算决定实际注入条数（预算内尽量多装，相关性为序）；保留一个上限 `MAX_CHUNKS`（默认 8）防极端长文档撑满。
- 融合→去重→重排全部在 `packages/core/src/retrieval/` 内拆为纯函数文件（每个 ≤300 行），retrieval-service 只做 I/O 编排。

## 5. 重排（M1 末 / M2 前置）

### 5.1 默认规则重排（零成本、无模型）

```ts
function ruleRerank(hits, { query, terms }): ScoredHit[]
// 加权项（权重常量化、单测锁定）：
//  +双通道同时命中；+标题/文档名命中查询词；+查询短语在 chunk 中连续出现；
//  +关键词覆盖率（FTS 命中词数/查询词数）；+实体精确名/别名命中（M2 接入后）；
//  −跨度过短噪声块；新鲜度不参与（私有知识无时效信号，避免偏置）
```

关闭一切增强时，规则重排 + FTS 通道的 golden 成绩必须 ≥ 单向量基线（G3 红线）。

### 5.2 可选 LLM 重排（显式开关，默认关）

- 设置项 `rerankEnabled`（默认 false）；开启后对融合后 top-12 候选，用已配置 **chat** 模型一次性做相关性 0–10 打分（结构化 JSON 输出复用现有 zod 校验与 ProviderError 通道）。
- 失败/超时/未配置模型：静默回落规则重排（检索永不因重排挂掉），并在 RagContext 标注 `rerank: 'fallback'` 供观测。
- token 成本在设置页明示，不静默烧额度。

## 6. 知识编译器（M2，后台任务）

### 6.1 无模型基线抽取器（默认、确定性、可单测）

纯函数模块 `core/knowledge/rule-extractor.ts`，输入文档全文+chunk 结构，输出 `SummarySpec` 与 `EntitySpec[]`：

- **摘要 tldr**：首个含实质内容的段落首句（去标题/目录噪声）；**bullets**：按「含数字/专名/定义动词（是/指/包括/兼容）」打分取 top-3 原句（保留原文，天然可回指）。
- **key_terms**：词频 + 词性无关启发式（大写词组、引号词、数字带单位、型号正则如 `[A-Za-z]+[- ]?\d+`、连续 2–6 个汉字高频组合），停用词表内置。
- **实体候选**：满足专名/型号/数字模式的短语；`normalized_name` 归一（去空白、小写、全半角）；同篇别名（英文缩写/全称）按括号模式 `中文名（English）` 归并。
- **mention**：实体出现的句子 + 其 chunk/page/paragraph 坐标（句子→chunk 用 char 区间相交映射的纯函数 `locateMentions`）。
- 跨文档实体合并：upsert 时按 `(kb_id, normalized_name)` 命中即复用 entity，mention_count 累加；不做模糊聚类写库（避免错误合并难撤销），embedding 聚类只用于**建议**（G5 治理提示，不落自动合并）。

### 6.2 LLM 增强通道（可选）

- 设置项 `compileWithLlm`（默认 false）+ 模型选择（默认取默认 chat 模型）。
- 单次/分段调用产出 JSON（tldr/bullets/entities[{name,kind,aliases,context}]），zod 校验；抽取结果与规则通道写同一 schema（extractor='llm'、记 model_id）。
- 长文档分段编译后实体走 normalized_name 归并；单文档 LLM 调用预算与超时硬上限（复用 v1.1 工具调用超时约定）。
- 任何 LLM 失败**降级到规则通道产物**并标记，而不是整文档编译失败。

### 6.3 世代与编译生命周期

- 文档新摄入：compile_status=queued（不阻塞摄取完成）；后台 worker 取 queued 文档编译。
- 文档替换（同名重传）：现有摄取会重建 chunk/vec/fts（§3），编译任务排队跑新世代；事务内「插新世代产物→删旧世代→UPDATE compiled_at/generation」。
- 文档删除：FK 级联清理产物。
- 手动「重新编译」：知识库/文档级入口，复用同一路径。

### 6.4 编译优先检索路由

RAG 检索结果在融合后、注入前增加「静态知识层」：

1. 从查询抽关键短语（复用 key_terms 同款分词纯函数），在 `knowledge_entities(normalized_name/aliases)` 与 `document_summaries(key_terms/tldr)` 做精确/包含命中（必要时对实体名做一次向量近邻，但仅在已有 embedding 预算内）。
2. 命中实体 → 取其最高价值 mention 原句与归属文档摘要，作为**少量高置信静态事实**置于上下文块前部（带出处编号）；未命中则完全走 chunk 融合结果。
3. 静态层注入条数硬上限（默认 2 条实体 + 1 条摘要），防止「编译摘要挤掉原始证据」；模型始终同时看得到原 chunk，引用以可回指原句为前提。
4. 编译层为空/未开启/未就绪时零行为差异（回落 v1.2 链路 + M1 FTS）。

## 7. 后台调度与可观测（M4）

- 编译任务复用现有任务/队列基础设施（不引新框架）：`compile_status` 状态机 `queued→running→ready|failed`；单并发 + 每库串行（避免本地模型并发限流与 SQLite 写竞争）。
- 任务可**取消**（协作式：chunk 边界检查 AbortSignal，LLM 段直接 abort）；失败可**重试**（指数退避，最多 N 次后 failed 等手动）。
- 资源护栏：仅在有嵌入/LLM 任务需要时调用模型；规则通道零调用；设置「空闲时自动编译」开关（默认开：摄取后延迟编译）与「LLM 增强」开关（默认关）；大库「全部重新编译」需显式确认并显示文档数预估。
- 进度经现有任务事件/SSE 通道暴露（已编译文档数/总数、当前文档、错误）；知识库 UI 显示每文档编译状态徽标。

## 8. 语句级引用（M3）

### 8.1 契约扩展（向后兼容，字段可选）

```ts
interface Citation {
  documentId: string;
  documentName: string;
  ordinal: number;
  snippet?: string;
  sourceUrl?: string | null;
  // v1.3 新增（全部可选，旧消费端忽略）：
  pageNo?: number | null;
  paragraphNo?: number | null;
  charStart?: number;
  charEnd?: number;
  staticKind?: 'chunk' | 'entity' | 'summary'; // 引用来自静态知识层时标注
}
```

SSE/分享导出透传新字段；`share-i18n` 双语模板加「第 N 页/第 N 段」本地化（复用 v1.2 i18n）。

### 8.2 UI 呈现

- 消息内引用角标 hover 显示「《文档》第 N 页 · 第 M 段」；点击弹出引用卡片（复用现有 citation 展示），展示原句/片段与坐标；sourceUrl 仍可跳原文。
- 不做 PDF 内嵌查看器跳转（Non-Goal，工程量与渲染依赖过大）；坐标以文本定位信息呈现。
- 来自实体/摘要层的引用同样回指其 mention 所在 chunk/页（编译器只存原句，不生成无法溯源的新句子——LLM 摘要也必须取原句作 bullets）。

## 9. 知识治理（M3）

| 能力 | 设计 |
|---|---|
| 去重提示 | 上传时已有 hash/URL 命中→沿用现有拦截并明确提示；另用实体 embedding 相似度给「疑似重复文档」列表（**仅建议**，不自动删） |
| 冲突标记 | 纯函数 `detectConflicts(entities, mentions)`：同一 normalized_name 的「数字型/取值型」描述不一致时（如同一产品两个版本号、同一人两个头衔）产出冲突项，知识库页「待裁决」区列出，跳转到两处原句由用户处理 |
| 文档版本/替换 | 保持「同 kb + 同文件名/hash」替换语义，替换=重建索引+重编译（世代换代）；UI 标注 indexed_at/compiled_at |
| 退役 | 旧世代产物在新世代事务提交后删除（§6.3）；读取不会读到半新半旧 |
| 可重建 | 知识库设置提供「重建全部索引（向量+FTS+编译）」；派生数据清空重算，源文档不动；备份恢复后自动排队重编译/重嵌入 |

治理动作不自动删除任何用户资料（决策 8）。

## 10. API 设计（REST 沿用现有风格）

| 方法/路径 | 用途 |
|---|---|
| `GET /api/knowledge-bases/[id]/compile-status` | 编译状态总览（ready/queued/running/failed 计数 + 当前任务） |
| `POST /api/knowledge-bases/[id]/compile` | 触发编译（body: `{ scope: 'new'|'all'|'document', documentId?, withLlm? }`） |
| `POST /api/knowledge-bases/[id]/reindex` | 重建向量+FTS（+可选编译），显式确认 |
| `POST /api/knowledge-bases/[id]/compile/cancel` | 取消编译任务 |
| `GET /api/knowledge-bases/[id]/entities?query=` | 实体浏览/搜索（治理 UI 用） |
| `GET /api/knowledge-bases/[id]/conflicts` | 冲突待裁决列表 |
| （检索无新 API）对话仍走 `/api/chat/stream`，内部 RAG 换混合检索+静态层 |

设置项扩在现有 voice 同级的 knowledge 设置（或写进 app-settings JSON）：`hybridEnabled`(默认 true)、`minVecSim`、`rerankEnabled`(默认 false)、`autoCompile`(默认 true)、`compileWithLlm`(默认 false)、`compileModelId?`。schema 走 zod + 默认值兜底（沿用 v016 模式，无表结构风险）。
