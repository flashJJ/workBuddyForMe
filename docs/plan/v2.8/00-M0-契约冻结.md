# v2.8 M0：持久后台作业、计划与定时跟进契约冻结

> 状态：已实现（v2.8，2026-10-29）
> 范围：Task / 协作（Agent）运行改为服务端持有；重启恢复；完成回投；会话目标 / 计划 / 待办；定时跟进。
> P1（不阻塞本期）：子运行树（父子运行关系、子代理聚合与父级中断）、余额与账户信息。
> 决策：先做单层 job，不改 Flow 队列语义；Todo 是 Plan 的轻量视图，不建平行状态机。

## 1. 运行归属与租约

### 1.1 状态机

```
queued ──start(首次订阅 / 恢复)──▶ running ──pause──▶ paused
  │                                  │  ▲               │
  │                                  │  └────resume─────┘
  │                                  ├── user stop ──▶ stopped(user_stop)
  │                                  ├── 循环自然结束 ──▶ completed(completed)
  │                                  └── 致命错误 / 重启 ──▶ stopped(interrupted)
  └── 启动前重启 ──▶ stopped(interrupted)
```

- Task 新增终止原因 `interrupted`；协作沿用 `cancelled` + `errorCode=INTERRUPTED`。
- 运行真相仍在现有 `task_runs` / `agent_runs`，不新增运行表。
- 后台作业只存在于进程内 `active` 注册表；DB 只记录可观测状态与租约。

### 1.2 租约字段（迁移 v037，纯加法）

| 表 | 字段 | 含义 |
|---|---|---|
| `task_runs` | `lease_owner TEXT` | 当前持有 job 的进程实例 id（启动时生成） |
| `task_runs` | `lease_expires_at TEXT` | 租约到期（心跳 30s，lease 90s） |
| `agent_runs` | `lease_owner TEXT` | 同上 |
| `agent_runs` | `lease_expires_at TEXT` | 同上 |

- 单进程部署下租约只用于「重启后识别幽灵 running」；不做跨进程抢占。
- job 启动写租约，终态/异常清空；服务重启后扫描非终态行，统一收敛（见 1.4）。

### 1.3 订阅语义

- 页面 / 桌宠 / 舞台都是观察者，不再拥有生命周期。
- 同一 `runId` 可被多个观察者同时订阅；重复订阅返回同一事件总线的回放 + 新帧。
- SSE 断开不 abort 运行；只有 `control.stop` / `stop-all` / `cancel` / 预算耗尽 / 致命错误才终止。
- 观察者可用 `?since=<seq>` 从指定序号续传；`seq` 为 job 内单调序号（从 1 开始）。

### 1.4 重启恢复矩阵

| 崩溃时状态 | 重启后动作 | 结果 |
|---|---|---|
| `queued`（从未启动） | 收敛为 `stopped(interrupted)` | 不伪造启动，不自动重跑 |
| `running` / `paused`（有租约） | 收敛为 `stopped(interrupted)` | 明确标记；不出现幽灵 running |
| `running`（Agent） | 收敛为 `cancelled(INTERRUPTED)` | 保留已落库 handoffs |
| 终态 | 不动 | 正常回放 |

- 收敛只写状态与结束时间，不删除步骤 / handoff / 消息，便于 v2.9 复盘。
- 恢复在容器首次装配时执行一次（幂等）。

## 2. 完成回投

- job 进入终态后向所属会话追加一条助手消息（运行卡文本），并触发一次通知（复用 v2.7 WorkSignal 终态脉冲）。
- 幂等键：`run_completions(run_id, kind, status)` 主键；重复终态（重启/竞态）只落库一次。
- 无会话（`conversationId=''`）的运行只写状态，不追加消息。
- 文案不包含工具参数原文、密钥或截图内容；失败原因截断 120 字。

## 3. 目标 / 计划 / 待办

### 3.1 表

| 表 | 关键列 |
|---|---|
| `conversation_goals` | `id, conversation_id, title, success_criteria, status(active/achieved/dropped), created_at, updated_at` |
| `work_plans` | `id, conversation_id, goal_id, kind(plan/todo), title, status(draft/pending_review/approved/running/done/rejected/abandoned), origin(user/model), created_at, updated_at, approved_at` |
| `work_plan_steps` | `id, plan_id, step_index, title, status(pending/running/done/skipped/blocked), note, updated_at` |

- 同一会话同一时间最多一个 `kind=todo` 的活跃清单；`todo_write` 原子替换其步骤。
- Plan 步骤有序；状态推进只允许：`pending → running → done/skipped/blocked`，不可回退（用户改写按新计划重建）。
- Plan 评审：`draft → pending_review → approved/rejected`；`approved → running → done`；`rejected → draft`（可改写后重新提交）。
- 未批准（`draft/pending_review/rejected`）的计划不得下发任何高风险工具；计划只影响提示词与 UI，不直接执行。

### 3.2 模型接缝

- `todo_write` 内置工具：入参 `{ todos: { title, status? }[] }`，按会话替换 Todo 清单，返回 `done/total`。
- 工具默认关闭，由助手白名单显式启用（与现有内置工具一致）；未启用时不影响对话。
- 对话装配注入「当前目标 + 已批准计划 + 待办进度」摘要（上限 1 条计划 / 10 步），未批准计划标注「待评审，勿执行」。

### 3.3 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET/POST | `/api/goals?conversationId=` | 列目标 / 建目标 |
| PATCH/DELETE | `/api/goals/:id` | 编辑 / 结案 / 删除 |
| GET/POST | `/api/work-plans?conversationId=` | 列计划 / 建计划（可带 steps） |
| GET/PATCH/DELETE | `/api/work-plans/:id` | 详情 / 改写标题与步骤 / 删除 |
| POST | `/api/work-plans/:id/review` | `{action: approve\|reject\|submit}` |
| PATCH | `/api/work-plans/:id/steps/:stepId` | 更新单步状态 / 备注 |

## 4. 定时跟进

- 复用 `scheduled_tasks`；迁移 v037 增加 `payload_json TEXT`（可空，旧行为空）。
- `payload = { conversationId?, planId?, runId?, kind: 'follow_up' }`；只有 `follow_up` 会在投递时追加会话消息。
- 到点由现有 tick 先 `fire` 再投递，保证「最多一次」；勿扰时段只留通知不出声；无人值守仍拒绝桌面操作。
- 失败投递只告警，不回滚触发时刻（与 v1.7 一致）。

## 5. UI 交付

- `/plans`：目标、计划、待办三区；计划评审（批准/驳回/改写）、步骤勾选、进度条。
- 对话内：顶部计划提示条（当前目标 + 计划 x/y + 状态），点击进 `/plans`。
- 桌宠：计划/待办作为 `source=chat` 的工作信号，气泡显示 `x/y`；终态自动清理。
- 运行页：Task/Flow 运行卡复用 v2.7 的步骤进度，不新增第二套口径。

## 6. 验收

1. 任务运行中关闭主窗，运行继续；重开页面看到完整时间线；第二个观察者不触发重复启动。
2. 服务重启后非终态运行全部收敛为 interrupted/cancelled，无幽灵 running；旧步骤可回放。
3. 完成回投只写一条助手消息（幂等键生效），WorkSignal 终态脉冲只通知一次。
4. 计划在重启后保留；驳回/改写可再次提交；未批准计划不进入执行提示词。
5. 定时跟进只触发一次，payload 正确带回 `conversationId/planId/runId`。
6. `pnpm check`、四层测试、300 行门禁通过；迁移只做加法，回退 v2.7 可读。

## 7. Non-Goals

- 不做子运行树、跨设备/云端调度、无限并行。
- 不做自动批准、无人值守桌面执行、计划依赖图/甘特图。
- 不改 Flow 队列语义；Flow 运行仍由队列所有方持有。
