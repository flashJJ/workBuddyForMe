## 3. 与 M0 的偏差

1. **对话内计划卡**：以对话顶部计划条（目标/计划 x/y/待评审）代替消息内卡片；评审与改写集中在 `/plans`，避免在消息流里塞入重交互。
2. **计划执行**：计划本身不自动触发运行；批准只解除「待评审」提示并允许步骤推进，高风险工具仍逐次走审批闸门。
3. **Todo 桌宠信号**：全未开始不显示；已有进度才进入工作信号，全部完成时转 succeeded 脉冲。
4. **定时跟进投递**：沿用 v1.7 的客户端 tick（主窗或桌宠页面存活时）先 fire 再投递；服务端不增加独立定时器。
5. **子运行树**：按 M0 决策延后到 v2.10 评估。
