## 3. 公开入口口径

- **页面入口**：`@/features/settings`、`@/features/chat`、`@/features/flow-editor` 只导出 `SettingsPage` / `ChatPage` / `FlowEditor`；app 路由按页面引用。
- **能力入口**：跨域代码引用子域 barrel，例如 `@/features/events/hooks`、`@/features/avatar/ui`、`@/features/flow-editor/canvas`、`@/features/chat/overlay`。
- **无页面入口**：`events` 无独立页面；`avatar` 根入口只导出轻量能力（渲染路由、模型清单、表情、久别信号与控制器类型）。
- **hooks**：`lib/hooks` 无根 barrel，按域引用，避免一次拉入全部查询。

## 4. 关键取舍：barrel 不能 `export *` 全量

首轮把每个子域与根入口都生成 `export *`，生产构建暴露了明显包体回退：

| 页面 | 首轮 | 收紧后 | 基线 |
|---|---:|---:|---:|
| `/settings` | 513 kB | 472 kB | 457 kB |
| `/flows/[id]` | 541 kB | 387 kB | 386 kB |
| `/capabilities` | 510 kB | 278 kB | 278 kB |
| `/tasks` | 465 kB | 310 kB | 308 kB |
| `/pet` | 318 kB | 258 kB | 255 kB |
| `/chat` | 459 kB | 459 kB | 453 kB |

处理方式：
1. 根入口只导出页面级组件，跨域改用子域入口；
2. 子域 barrel 只导出真正跨域需要的模块 / 符号；
3. 把 chat 的 Markdown 从 `message` 拆成独立 `markdown` 入口，避免只需要附件图的任务页拉入 react-markdown；
4. events 的 player / ui / triggers / bus 与实际依赖对齐；flow-editor 的 config 入口只保留 `form-primitives`；
5. avatar 根入口不导出 `ChatAvatarRail`，由 chat 页面直接引用 `avatar/ui`，避免宠物/舞台拉入对话形象栏。

最终各页面相对基线增长 ≤3.5%，满足 ≤5% 门槛。

| # | 问题 | 处理 |

| 1 | 移动后的测试仍 mock 旧 `@/lib/hooks/use-*` 路径 | 6 处 mock 改到域入口；`provider-step` 使用 `importOriginal` 部分 mock，保留真实 `useProviders` |

## 7. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | feature 根入口不是能力全集 | 根入口只承担页面级导出；能力按子域入口引用，符合「按能力引用」 |
| 2 | `events` 根入口保留但当前无外部消费 | 作为 feature 身份入口保留；实际跨域引用走子域 |
| 3 | `lib/hooks` 无根 index | 避免单个 hooks 巨型 barrel；7 个域入口即公开面 |
| 4 | chat Markdown 文件仍在 `message/` 目录 | 为减少移动量，`markdown/index.ts` 转发 `../message/markdown`；后续可物理移动 |
| 5 | 测试 mock 需感知域入口 | 域入口聚合多个 hook，部分 mock 改为 `importOriginal` 部分 mock；断言不变 |
