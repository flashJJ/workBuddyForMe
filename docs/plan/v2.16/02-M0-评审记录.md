## 1. 技术评审

| # | 议题 | 结论 |
|---|---|---|
| R1 | 目录预算与豁免边界 | 采用「基线快照 + 新增超标 error、存量超标 warning」；迁移、生成清单、i18n / 常量豁免；P0 12 个目录必须在 M1-M3 达标 |
| R2 | barrel 与循环 | 入口只做纯 re-export；禁止从自身 barrel 反向导入；M0 基线 9 个 SCC，禁止新增，P0 域内的环在 M5 清零，其余逐条登记 |
| R3 | web 客户端包体 | 不设 `@/features/index.ts` 巨型入口；每个 feature 独立入口；每个里程碑对比 First Load JS，增长 >5% 视为失败 |
| R4 | 移动策略 | 每个目录一批提交；只做 `git mv` + import 改写；测试跟随移动、断言零改动；review 用 rename 检测；行为问题记 backlog |
| R5 | `shared/schemas/index.ts` 523 行白名单 | M1 拆二级 barrel 后复核：若根入口仍 >300 行，保留白名单但要求纯 re-export；若可降至 ≤300 则移除白名单；公开面与深度导入 0 的现状不变 |
| R6 | database 包导出 | 现只有根入口且 0 深导入；文件移动可安全进行，v2.16 不强制新增子路径导出 |
| R7 | 跨 feature 依赖矩阵 | 允许 settings / chat / avatar / pet / stage / interaction / onboarding / flow-execution 的既有合理依赖；`capabilities → settings`、`tuning → assistants` 两处偶然耦合在 M3 整改 |
| R8 | 设置页请求优化 | 基线 29 GET / 22 distinct / 峰值 15 / 44 KB；M4 先 facade + 可见性触发 query，保留 DOM 与锚点；只有仍 ≥4 个独立资源且未达目标时才评估只读聚合端点 |
| R9 | 循环检测误报 | import 图包含 `export type` 与 barrel 转发，存在类型环 / 入口环；M5 工具落地时分类处理，不把类型环当运行时环 |
| R10 | 里程碑顺序 | 先包层（M1/M2）后 web（M3），避免 web import 被重写两次；M4 最后做页面数据，避免与目录移动冲突 |

## 2. 产品口径

| # | 事项 | 结论 |
|---|---|---|
| P1 | 是否允许 UI 变化 | 不允许。M4 只改变「何时发请求」，保留面板 DOM、锚点、文案与交互；若 e2e 因可见性等待失败，只改测试等待方式 |
| P2 | 是否本版新增聚合端点 | 不预先承诺；按 M4 数据与准入表决定，未达标就只交付 facade + 可见性触发 |
| P3 | 是否拆包 / 发布新包 | 不做。保持 monorepo 包边界，只做目录与入口 |
| P4 | P1 大目录是否阻塞发布 | 不阻塞。i18n 词条、shared 常量、desktop 主进程、`lib/server` 等列为候补，按 M1-M3 进度顺延 |
| P5 | 命名整改范围 | 只约束新文件；旧文件不强制批量改名，避免无意义 churn |
| P6 | 行为问题处理 | 重构中发现的 bug / 契约问题只记录，不在本版修复 |

## 3. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 移动导致 Next 生产构建解析失败 | 每批移动后执行 `pnpm build:web`，不只跑 dev / typecheck |
| barrel 引入客户端包体膨胀 | 按域拆入口；不建巨型 barrel；每批对比 First Load JS |
| 循环依赖增加 | 入口纯转发、内部直接引用；M5 检查禁止新增 SCC |
| 设置页 e2e 受可见性影响 | M4 保留 DOM；只给 query 加 `enabled`；e2e 增加滚动 / 锚点等待，不改断言内容 |
| 聚合端点缓存失效复杂 | 只读、最小字段、准入表、失效矩阵；未达标不做 |
| 移动提交 Review 噪音大 | 每批只移动 + 改 import；不使用格式化工具混合提交；用 `git diff --find-renames` |
| 目录预算影响开发节奏 | 基线快照先冻结现状；只对新增超标 error；达标目录从基线移除 |
