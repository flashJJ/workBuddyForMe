## 1. 本里程碑做了什么

| 类型 | 数量 | 说明 |
|---|---:|---|
| 新增公共能力 | 1 | `apps/web/src/lib/ui/panel-visibility.tsx`：可见性 Context + 门控容器 + 查询包装 |

### 1.1 可见性能力（`lib/ui/panel-visibility.tsx`）

| 导出 | 作用 |
|---|---|
| `PanelVisibilityGate` | `IntersectionObserver` + `rootMargin: 200px`，首次进入视口即置可见并 `disconnect`；无 `IntersectionObserver` 时直接可见 |
| `usePanelVisible` | 读取当前门控可见态；无 Provider 时默认 `true` |
| `useVisibleQuery` | 透传 `UseQueryOptions`，把 `enabled` 与可见态合并：`visible && (options.enabled ?? true)` |

设计要点：

- **只改请求时机**：面板照常挂载，DOM、锚点、文案与交互全部保留（符合 D7）；
- **一次置真**：滚出视口不回退为不可见，避免来回滚动造成查询反复启停；
- **默认放行**：不在门控内的页面（对话、工作流、能力中心等）行为零变化；
- **失败安全**：环境无 `IntersectionObserver` 时按可见处理，不因门控丢数据。

### 1.2 门控范围

`settings-page.tsx` 的 4 个分组（appearance / dialog / tools / data）各自包一层 `PanelVisibilityGate`；页面顶部的基础区（演示模式、供应商列表、默认偏好）不入门控，始终按原时机请求。

### 1.3 面板内直接请求

以下三处不走 React Query，原实现挂载即请求，补 `usePanelVisible` 后才发起：

| 文件 | 请求 |
|---|---|
| `settings/dialog/emotion-detail-view.tsx` | `GET /api/assistants/:id/emotion?events=10` |
| `settings/dialog/relationship-level-view.tsx` | `GET /api/assistants/:id/emotion` |
| `voice/settings/voice-preference-panel.tsx`（`StorageSection`） | `GET /api/system/info` |

## 3. 是否需要只读聚合端点

按契约 §4.3 准入判断，**不启用**：

- 首屏 distinct GET 已降到 7，低于目标 ≤11，也低于「facade + 可见区触发后仍 ≥4 个独立资源且未达标」的启用条件；
- 剩余请求分属不同资源与不同消费方（供应商/设置/全局语音/系统信息），聚合成单端点会把页面耦合到服务端编排，收益不抵风险；
- 现有端点零改动，回退成本为 0。

## 7. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | 未新增页面级 facade hook | 设置页顶层数据只有 `useProviders` / `useSettings` 两条，已由页面直接消费；再包一层 facade 不减少请求且增加间接层。聚合端点准入同时被数据否决（见 §3） |
| 2 | 门控粒度是「分组」而非「面板」 | 4 个分组天然是滚动与锚点的单位；面板级门控会让同一分组内的相邻面板产生多次触发，收益有限 |
| 3 | `rootMargin` 取 200px | 提前一屏预取，避免滚动到分组时出现空白；实测首屏未被提前触发 |
| 4 | 门控为一次性 | 滚出视口不回收查询，符合 React Query 缓存语义，也避免滚动抖动导致反复请求 |
| 5 | 对话页等未包门控 | `usePanelVisible` 默认 `true`，非设置页行为与 M3 完全一致 |
