## 4. 关键口径

1. **先移动再聚合**：先按域移动文件并用 codemod 重写相对引用，再生成子域 barrel，最后把根 barrel 改为子域转发；每一步独立可回退。
2. **根入口是唯一公开面**：`@wbfm/shared/schemas` 与 `@wbfm/database` 的包导出不变；未新增 package.json 子路径，避免扩大公开 API。
3. **纯 re-export**：子域 barrel 只包含 `export * from './file'`；不含逻辑、不注册副作用。
4. **测试跟随**：测试文件随实现移动到子域，import 只改路径；用例数量与断言不变（shared 338 / database 247）。
5. **命名**：沿用既有文件名，不做同义后缀改名，避免把移动与重命名混在一批。
6. **例外**：database 的 `capability` 原 12 个文件加上 barrel 会超过 12，按语义拆出 `mcp` 子域（mcp-mapper / mcp-server / tool-permission）；这是本批唯一的额外分区。

## 5. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | 子域 barrel 未加 package.json 子路径 | 根入口已能按能力引用；新增包子路径会扩大公开 API，留到确有外部消费时再评估 |
| 2 | 根 barrel 使用 `export *` | 全量 typecheck 通过，消费者无缺失导出；若未来出现同名冲突，再改显式导出 |
| 3 | `repositories/capability` 拆分 `mcp` | 为了同时满足「含 barrel ≤12」与语义聚合，未扩大 P0 目录数 |
| 4 | 未重命名文件 | M1 只做位置收拢；命名规范从新文件开始执行 |
