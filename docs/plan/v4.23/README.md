# v4.23 选题：会扛事

> 状态：M0 契约冻结中（2026-11-23）
> 主题：**会扛事**——Flow 持久化执行：节点级 checkpoint、启动自动续跑、重试/退避、节点超时与副作用幂等
> 规格：[spec.md](./spec.md) · 契约：[contracts.md](./contracts.md) · 任务：[tasks.md](./tasks.md)
> 调研：[00-能力借鉴分析.md](./00-能力借鉴分析.md)
> 原则：默认行为不变；零数据库迁移；可随时回退

## 1. 一句话

v4.22 让流程「跑得动」，v4.23 让它「摔了能自己爬起来」：已成功节点不重跑，可续跑的运行重启后自动接上，可重试的错误按策略退避重试，风险节点保持人工介入。

## 2. 为什么是现在

v4.22 引入并发后，运行内的失败隔离已经解决，但进程级故障仍只做「收敛 + 等人工重放」：

- 已成功节点的产出在 `node_executions.outputs_json` 里，却没有被当作续跑依据；
- `interrupted` 是终态，用户必须手动重跑整个流程；
- 没有节点级重试与超时，瞬时错误直接终止运行；
- 崩溃时正在执行的写操作没有幂等边界，无法安全自动重放。

对本地桌面应用来说，用户关闭窗口、系统睡眠、更新重启都是常态。长流程不可托付，并发能力就无法真正发挥。

## 3. 借鉴与差异

| 借鉴点 | 来源 | 本版落地方式 |
|---|---|---|
| 每步检查点、从最后状态恢复 | LangGraph Checkpointer | 复用已落库的节点终态重建作用域，不新增存储 |
| 活动重试与幂等键 | Temporal | 节点级 `retry` 策略 + `${runId}:${nodeId}` 执行幂等 |
| 崩溃后不丢任务 | n8n 持久化调度队列 | 启动扫描按安全矩阵决定续跑或保持 interrupted |
| 回退预算约束 | LiteLLM fallback budget | 重试只对可重试错误生效，避免放大失败 |

不做：分布式 Worker、跨进程协程复活、定时触发、工作流跨版本迁移。

## 4. 范围

### 做

- 节点级 checkpoint：从 `node_executions` 重建 `scope / state / liveEdges`；
- 启动自动续跑：安全运行直接续跑，风险运行保持 `interrupted`；
- 节点重试：`maxAttempts`、指数退避、上限；
- 节点超时：仅对非交互节点生效；
- 观测：`run_started.resumed`、`node_started.attempt`、续跑原因；
- 定向单测与运行服务集成测试。

### 不做

- 定时/事件触发（候选主题「会守时」）；
- 沙箱代码执行与浏览器自动化（候选主题「会动手」）；
- 多端同步、分布式执行；
- 修改节点/边/编译诊断规则。

| 阶段 | 内容 |

## 6. 风险

| 风险 | 应对 |
|---|---|
| 自动续跑重复副作用 | 安全矩阵：写/危险工具、human、agent 在途时不自动续跑 |
| checkpoint 与图版本不一致 | 续跑使用运行记录里的版本号与编译产物；版本缺失则保持 interrupted |
| 重试放大故障 | 仅可重试错误 + 指数退避 + 次数上限；默认不重试 |
| 超时留下后台任务 | 仅非交互节点启用；超时后标记失败并等待执行体自行收敛 |
| 事件重复 | 已成功节点静默跳过，不补发 `node_succeeded`；重试只复用 `node_started` + `attempt` |

## 7. 验收

1. 重启后可续跑运行自动完成，无需人工；
2. 已成功节点不重复执行，副作用只发生一次；
3. 风险在途运行保持 `interrupted` 并带原因；
4. 重试按 `maxAttempts` 与退避执行；
5. 超时节点按失败收敛；
6. 未配置策略时事件序列与 v4.22 一致；
7. `pnpm check` 与 `pnpm verify:local` 全绿。
