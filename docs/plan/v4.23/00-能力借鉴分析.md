# v4.23 能力借鉴分析：会扛事

> 状态：已选定（2026-11-23）
> 结论：下个版本主题为「**会扛事**」——Flow 持久化执行、自动续跑、重试/超时与副作用幂等
> 上游调研：LangGraph Checkpointer、Temporal、n8n、LiteLLM、Langfuse、OpenHands、RAGFlow、Pipecat 等

## 1. 为什么是「会扛事」

v4.22 把执行器改成就绪集合并行调度，解决了「运行内」的失败隔离：单分支失败不阻断无关分支。
但进程级故障仍停在原地：

- 重启恢复只把 `running / waiting_human` 收敛为 `interrupted`，并重新入队 `queued`；
- 已成功的节点虽然落库，却没有被当作 checkpoint 用于续跑；
- 没有节点级重试、退避与超时策略；
- 崩溃时正在执行的写操作没有幂等登记，无法安全重放。

对一个本地优先、单机运行、可能被用户随时关闭的应用来说，「长流程可托付」比「再多一个节点类型」更重要。

## 2. 能力对照表

### 工程可靠性

| 方向 | 代表开源项目 | 我们的现状 | 主要差距 | 价值 | 成本 |
|---|---|---|---|---|---|
| 持久化执行 / 断点续跑 | Temporal、LangGraph Checkpointer、Inngest | 运行记录、节点重放、启动恢复（running→interrupted、queued 重入队） | 无节点级 checkpoint 自动续跑；无重试/退避/超时；副作用无幂等登记 | 崩溃/重启不丢进度，长流程可托付 | 中 |
| 触发与调度 | n8n Schedule Trigger（DB 持久化队列）、Khoj 定时自动化 | 手动 / HTTP / MCP 触发；桌宠有提醒 | 无 cron、webhook、文件监听；调度队列未全部落库 | 从「被调用」到「自己开工」 | 中 |
| 统一观测与评测 | Langfuse、OpenTelemetry、promptfoo | 运行事件、审计、记忆评测、离线回放 | 无统一 trace 视图；缺版本级回归门禁 | 排障与调优效率 | 中 |
| 成本账本与配额 | LiteLLM virtual key / budget | 备用链、健康度、场景预算、工具轮次预算 | 无按助手/流程/模型的 token 成本汇总与配额告警 | 本地也怕失控调用 | 小–中 |
| 多端同步 | 本地优先 CRDT 生态 | 单机单用户、备份/恢复 | 无多设备增量同步 | 跨设备连续使用 | 很大 |

### 能力扩展

| 方向 | 代表开源项目 | 我们的现状 | 主要差距 | 价值 | 成本 |
|---|---|---|---|---|---|
| 沙箱代码执行 | OpenHands Docker Runtime、E2B | 无代码解释器；桌面 Agent 直接操作宿主 | 缺隔离执行环境、文件边界、资源限制 | 能算、能转文件、能跑脚本 | 大 |
| 浏览器自动化 | Browser Use、Stagehand | 有抓取工具；桌面 Agent 靠键鼠控制 | 无结构化浏览器操作、登录态管理 | 网页任务成功率与安全性 | 大 |
| 文档解析深度 | RAGFlow DeepDOC、Docling | txt/md/pdf/docx/网页/OCR，混合检索 + RRF + 规则重排 | 缺版面分析、表格结构、跨页表格、图片语义 | 复杂 PDF 质量 | 中–大 |
| 检索增强 | LightRAG / GraphRAG、交叉编码器重排 | 向量 + FTS + RRF + 规则重排；记忆有关系边 | 缺重排模型、查询改写、多跳图检索 | 命中率与引用精度 | 中 |
| 记忆巩固 | Letta sleep-time compute、Mem0 / Zep | 双时态、冲突裁决、治理、空闲整理 | 缺空闲时记忆抽象与预计算 | 记忆越用越准 | 中 |
| 多智能体并行 | LangGraph、AutoGen、CrewAI | 固定三角色串行、会议 ≤ 8 轮 | 角色并行、动态委派、共享黑板 | 复杂任务吞吐 | 大 |
| MCP 工具治理 | MCP Gateway / Registry、Composio | MCP server/client、端点策略、权限门控 | 缺工具注册表、per-tool 策略中心、OAuth 连接器 | 生态接入效率与安全 | 中–大 |
| 全双工语音 | Pipecat、LiveKit Agents | 本地 ASR/TTS、朗读、桌宠语音 | 缺 VAD 打断、流式双工、回声处理 | 陪伴自然度 | 中–大 |

## 3. 候选主题比较

| 候选 | 范围 | 与现有主线关系 | 风险 | 结论 |
|---|---|---|---|---|
| **会扛事** | checkpoint、自动续跑、重试/超时、幂等 | v4.22 并发的自然收口 | 副作用边界需严格定义 | ✅ 选定 |
| 会守时 | cron / webhook / 文件监听、持久化调度 | 编排的另一半 | 调度器与进程生命周期耦合 | 下阶段候选 |
| 会复盘 | trace、成本账本、评测回归 | 横切工程能力 | 单独成版偏内向 | 可并入会扛事 |
| 会动手 | 沙箱代码、浏览器自动化 | 扩展能力边界 | 安全与打包体积 | 单独立项 |

## 4. 选定主题的范围

- **做**：节点级 checkpoint 重建、启动自动续跑、节点重试/退避、节点超时、续跑与重试观测、定向测试；
- **不做**：分布式执行、定时触发、多端同步、工作流跨版本迁移、沙箱代码执行；
- **默认不变**：未配置重试/超时、且没有中断时，行为与 v4.22 完全一致；
- **零迁移**：复用 `node_executions` 与 `workflow_runs`，不新增表、不改备份格式。
