## 6. Next 15 破坏性变更清单（按仓库取证）

### 6.1 React 19

- 官方升级指南：Next 15 的最低 React / React DOM 版本为 19；[apps/web/package.json](../../../apps/web/package.json#L44-L45) 当前为 18.3.1；
- 类型同步到 19.3.0（[apps/web/package.json](../../../apps/web/package.json#L59-L60)）；
- 已扫描但**未命中**的 React 19 常见破坏点：`useRef()` 无参数、全局 `JSX.*`、`ReactDOM.render/hydrate`、函数组件 `defaultProps`（全仓 grep 无匹配）；
- 仍需以 `pnpm typecheck` 为准，重点看第三方库（Radix / TanStack Query / xyflow / testing-library）的 React 19 peer 与运行期行为；只做必要升级，不批量升依赖。

### 6.2 异步请求 API（4 个页面）

Next 15 中 `searchParams` / `params` 为 `Promise`。当前 4 个服务端页面同步读取：

- [assistants/page.tsx](<../../../apps/web/src/app/(main)/assistants/page.tsx#L3-L9>)
- [flows/page.tsx](<../../../apps/web/src/app/(main)/flows/page.tsx#L3-L9>)
- [knowledge/page.tsx](<../../../apps/web/src/app/(main)/knowledge/page.tsx#L3-L9>)
- [settings/page.tsx](<../../../apps/web/src/app/(main)/settings/page.tsx#L3-L9>)

改法：`searchParams: Promise<{ [key: string]: string | string[] | undefined }>` + `await`（或 `use()`）。4 处结构一致，逐页迁移并跑对应页面 e2e。

Route Handler 侧：[with-api-handler.ts](../../../apps/web/src/lib/server/with-api-handler.ts#L26-L32) 已经 `await context.params`，与 Next 15 兼容；建议把 context 类型收窄为 `{ params: Promise<P> }`，去掉同步联合类型，锁死后续误用。

### 6.3 next.config 迁移

| 当前键 | Next 15 状态 | 迁移 |
|---|---|---|
| `experimental.serverComponentsExternalPackages`（[next.config.mjs](../../../apps/web/next.config.mjs#L18-L32)） | 15 中仍存在但已标 `@deprecated`，改名 `serverExternalPackages` | 移到顶层 `serverExternalPackages`，包清单不变 |
| `experimental.outputFileTracingIgnores`（[next.config.mjs](../../../apps/web/next.config.mjs#L33-L62)） | **15.5.28 类型中已无此键**；只剩顶层 `outputFileTracingRoot/Excludes/Includes` | 迁到 `outputFileTracingExcludes`（仅非 Windows 兜底）；Windows 由 build 包装器隔离家目录 + 构建后断言 |
| `experimental.cpus` | 15.5.28 仍存在 | 保留 |

`outputFileTracingIgnores` 是**本版最高打包风险**：原配置用 `**/.workbuddy-for-me/**` 阻止 Next 追踪用户数据根。若迁移后 glob 不生效，standalone 会把 `~/.workbuddy-for-me` 下的模型/附件按绝对路径嵌套成非法条目，导致归集失败或安装包夹带用户数据。

**M1 实测结论**：`outputFileTracingExcludes` 的路由级过滤在 Windows **不生效**——Next 用 `path.join(dir, exclude)` 生成反斜杠 glob，`picomatch` 未开 `windows` 时无法命中；构建日志仍出现 `Failed to copy traced files ... .next\standalone\C:\Users\...`。因此改为：

1. [apps/web/scripts/build.mjs](../../../apps/web/scripts/build.mjs) 在 `next build` 期间把 `HOME`/`USERPROFILE` 指向临时空目录，让 nft 的 `os.homedir()` 静态求值落在空目录；
2. 构建后扫描 `.next/server/**/*.nft.json` 与 `.next/standalone`，出现 `.workbuddy-for-me` 或盘符路径即 **exit 1**；
3. `outputFileTracingExcludes` 仅保留 `/*` 作为非 Windows 兜底，不再作为 Windows 的主防线；
4. 显式设置 `outputFileTracingRoot` 为仓库根：Next 15 探测到 `E:\code\traeWork\package-lock.json` 会把 tracing root 推到仓库外，`prepare-server.mjs` 期望的 `.next/standalone/apps/web/server.js` 层级会改变。

**M1 验收结果**：`pnpm build:web` 无 `Failed to copy traced files` 警告；trace 命中 **0**；standalone 非法目录 **0**；`node .next/standalone/apps/web/server.js` 的 `/api/health` 返回 **200**。`apps/desktop/resources/server` 的归集复检留到 M2 打包时执行。

### 6.4 缓存语义变化

- `fetch` 默认不再缓存；本站的供应商调用、知识库检索、MCP 连接均为实时/本地链路，默认 `no-store` 符合预期；
- GET Route Handler 默认不再缓存；现有业务 API 均带鉴权/动态数据，语义只会更安全；
- 页面段不再从 Client Cache 复用（前进/后退仍复用）；设置页/列表页可能多一次请求，不影响正确性，e2e 回归即可；
- 全仓未使用 `next/font`、`@next/font`、`runtime='experimental-edge'`、`NextRequest.geo/ip`，无对应迁移。

### 6.5 standalone 打包复核

- `output: 'standalone'`、`transpilePackages`、`serverExternalPackages`、`outputFileTracingIncludes` 全部保留；
- [prepare-server.mjs](../../../apps/desktop/scripts/prepare-server.mjs#L12-L47) 的入口路径 `apps/web/server.js`、`.next/static`、`public`、内置 Node 运行时需在 Next 15 产物下复核；
- 原生/worker/wasm 包（better-sqlite3、sqlite-vec、pdfjs-dist、@napi-rs/canvas、tesseract.js、sherpa-onnx）仍走外部 require 与兜底归集（[next.config.mjs](../../../apps/web/next.config.mjs#L64-L89)、[prepare-server.mjs](../../../apps/desktop/scripts/prepare-server.mjs#L64-L97)）；
- 版本号注入 `NEXT_PUBLIC_APP_VERSION` 仍由 [next.config.mjs](../../../apps/web/next.config.mjs#L3-L15) 构建期内联。

## 7. Electron 44 破坏性变更清单

### 7.1 剪贴板 API 异步化（已命中的唯一硬破坏点）

- Electron 44 起 `clipboard.readText()` / `writeText()` / `read()` / `write()` 返回 Promise，同步辅助方法移除；renderer 不再暴露 clipboard；
- 当前中文输入走「写剪贴板 → Ctrl+V」：[input.ts](../../../apps/desktop/src/main/computer/input.ts#L54-L63) 的 `ClipboardSetter` 是同步签名，[input.ts](../../../apps/desktop/src/main/computer/input.ts#L104-L114) 调用后立即 `keyboard.pressKey`；[control-bootstrap.ts](../../../apps/desktop/src/main/computer/control-bootstrap.ts#L48-L51) 注入 `clipboard.writeText`；
- 修法：`ClipboardSetter` 改为 `(text: string) => Promise<void>`，`typeText` 中 `await setClipboard(text)` 后再按 `Ctrl+V`；单测覆盖「写入未完成不按键」；
- **M2 已落地**：`input.ts` 的 `typeText` 在 `keyboard.pressKey(LeftControl, V)` 前 `await setClipboard(text)`；`control-bootstrap.ts` 注入 `async (text) => { await clipboard.writeText(text); }`；`input.test.ts` 用受控 Promise 断言「写入未 resolve 时按键调用为空」；
- 常驻场景：桌面控制输入中文、UIA/坐标点击前的文本输入；真机连续 20 段中文无丢字（M3 真机回归项）。

### 7.2 平台支持变化（对本产品无影响）

- Electron 44 移除 Windows ia32 与 Linux armv7l；本产品仅 Windows x64（[electron-builder.yml](../../../apps/desktop/electron-builder.yml#L42-L49)）；
- macOS 12 不再支持；本产品不构建 macOS。

### 7.3 已扫描的稳定 API 面

主进程使用：`app`、`BrowserWindow`、`session`、`powerMonitor`、`safeStorage`、`globalShortcut`、`ipcMain`、`Menu`、`shell`、`Notification`、`desktopCapturer`、`screen`、`clipboard`；preload 使用 `contextBridge`、`ipcRenderer`、`process.argv`。除 §7.1 外，均为长期稳定 API；仍以 M2 真机 smoke 为准。

### 7.4 原生模块

- `@nut-tree-fork/nut-js 4.2.6` → `@nut-tree-fork/libnut 4.2.6` → `@nut-tree-fork/libnut-win32 2.7.5`，`libnut.node` 为 N-API（node-addon-api 7.1.0），跨 Node/Electron 版本 ABI 稳定；
- 不需 `electron-rebuild`；M2 需验证鼠标移动/点击/滚轮、键盘输入、屏幕截图、窗口枚举、UIA。

### 7.5 Electron 45 前瞻（本版不采用，v2.6 前处理）

- 同步 `safeStorage` 方法在 45 弃用、46 移除；[cipher-server.ts](../../../apps/desktop/src/main/cipher-server.ts#L25) 当前使用 `encryptString`/`decryptString` 同步方法，需迁到异步 API 并验证旧密文可解；

### 7.6 electron-builder 26 配置复核

逐项验证 [electron-builder.yml](../../../apps/desktop/electron-builder.yml)：

- `artifactName`、`directories.output=release`、`files`/`asarUnpack: **/*.node`；
- `extraResources: resources/server` 与 `build/icon.ico`；
- **根级 `node_modules` 排除（M2 实测新增）**：electron-builder 的 `app-builder-lib/out/util/filter.js` 对 file set 根级 `node_modules` 硬编码返回 false，`extraResources` 同样适用。Next standalone 的依赖位于 `server/node_modules`（根级），首版安装包因此缺失 `next`，安装版启动即 `Cannot find module 'next'`。修法：额外挂载 `from: resources/server/node_modules` → `to: server/node_modules`（不能把依赖下移，MCP stdio bin 也从 `server/node_modules` 解析）；
- Windows NSIS：`oneClick:false`、`perMachine:false`、`allowToChangeInstallationDirectory`、`license`、`installerLanguages`、`include: build/installer.nsh`、`deleteAppDataOnUninstall:false`；
- 签名双态：无 `CSC_LINK` 时走 rcedit 写图标/版本；有凭据时自动签名；
- 安装包命名 `WorkBuddyForMe-Setup-2.5.0.exe`，安装/覆盖升级/卸载数据两态。
