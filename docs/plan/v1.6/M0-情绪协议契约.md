## 1. 持久化状态 `EmotionState`（每助手一行）

```ts
{
  schemaVersion: 1,
  mood:     { happiness: -100..100, anger: 0..100, sadness: 0..100 },
  relation: { intimacy: 0..100, trust: 0..100 },
  currentNeed: 'none' | 'attention' | 'comfort' | 'play' | 'rest',
  counters:    Record<string, number>,   // v1.7 剧本 branch 预留，v1.6 只透传不解释
  recentEvents: EmotionEvent[],          // ≤10
  updatedAt: number                      // 毫秒 UTC，衰减惰性计算的基准
}
```

`EmotionEvent = { id, type: 'praise'|'chat'|'belittle', source: 'model'|'rule'|'event'|'manual', timestamp, description? ≤240 }`

设计要点：

1. **情绪/关系分层**：mood 临时、按指数衰减平复；relation 慢变量、只由事件小步增量改变（chat 一轮仅 +0.25 亲密度）。
2. **衰减是读时惰性计算**，不靠常驻定时器：`decayed = value × factor^elapsedMinutes`，不可见窗口/应用退出期间零唤醒；写回发生在下次事件 apply 时。
3. **作用域=用户×助手**：助手切换各读各的状态；v1.4 协作三角色、v1.9 会议链路不挂情绪（沿用「多人链路裁剪 soulEvent」的既定决策）。
4. `currentNeed` v1.6 只允许由事件/手动显式设置，不做自动推导。

## 2. 数值表（M0 评审稿，真机后只准改 constants/emotion.ts）

| 项 | 值 |
|---|---|
| 初值 | happiness 10 / anger 0 / sadness 0 / intimacy 20 / trust 30 |
| praise | happiness +8，intimacy +2，trust +1 |
| chat | intimacy +0.25，trust +0.1 |
| belittle | happiness −6，anger +8，sadness +3，intimacy −1，trust −2 |
| 衰减/分钟 | happiness ×0.98（开心易逝）、anger ×0.97（消气更快）、sadness ×0.995（难过最持久） |
| 强度 | intensity 0..1，默认 0.6；Live2D 表情权重地板 0.55 |
| 情绪等级 | 负：≤−40 明显低落 / 其余轻微低落；正：≥70 很强 / ≥40 明显 / ≥15 轻微 / 否则平静 |
| 关系等级 | ≥80 非常亲密 / ≥55 比较亲近 / ≥30 逐渐熟悉 / 否则还陌生 |

等级文案已落 i18n `emotion.levels.*`（中英双语）；模型注入文案在 core 用中文渲染（v1.5 模型边界约定），与 UI 语言解耦。

## 3. 模型输出协议：单轮情绪信号尾块

主回复正文结束后，模型追加**一个** JSON 代码块（协议候选，M2 前可微调，定版后写进系统提示词）：

````text
<正常回复正文>

```json
{"emotion":"joy","intensity":0.7,"soulEvent":"praise"}
```
````

- `emotion`：现有 8 标签词表（neutral/joy/anger/sadness/surprise/disgust/fear/smirk），**不新增词表**，直接复用 Live2D 表情映射。
- `intensity`：0..1。
- `soulEvent`：praise/chat/belittle——由模型判定「用户这句话对角色意味着什么」，不是模型自己的心情分类。
- 尾块不进气泡、不进 TTS、不进历史展示、不进分享（复用现有标签清洗管线同等级别的剥离处理）。
- v1.6 只做单尾块；Servant 的双 JSON + replies 分条属 P1，协议向前兼容（后续加第二个对象不破坏当前解析）。

## 4. 回落链（弱模型契约，永不阻塞主回复）

```text
尾块 JSON 存在且是对象？
 ├─ 是 → emotionSignalSchema 逐叶 .catch 默认值（词表外/越界/类型错都不整体拒绝）
 └─ 否（没有尾块/JSON 损坏/根不是对象）
       → 规则保底（core，中文短模式白名单：显式夸赞→praise，显式贬损→belittle）
            └─ 未命中 → {emotion:'neutral', soulEvent:'chat'}
```

铁律（v1.5 弱模型教训的直接延伸）：

1. 情绪解析在主回复**成功之后**旁路进行，任何异常都不得改变正文流式行为；
2. 规则保底**宁漏勿伤**：反讽、玩笑、模糊表达一律不判定，默认 chat；
3. 来源必须落 `EmotionEvent.source`（model/rule/event/manual），供本地「情绪协议合法率」统计与 eval 断言；
4. `expressionEnabled=false` 或情绪总开关关闭时：不注入提示词、不解析尾块、不写事件，但已存状态不删除。

## 5. 注入边界（system prompt 段落，core 中文渲染）

在现有 system prompt 组装序列中新增固定一段（具体位置 M2 与记忆/工具段一起做快照锁定）：

```text
[当前情绪状态]
心情：明显　生气：无明显情绪　难过：无明显情绪
亲密度：逐渐熟悉　信任度：比较亲近
当前需求：无
这是角色的真实状态。依据性格与该状态决定本轮语气与表情，不要宣称自己修改了这些数值。
```

会议/协作多人链路不注入本段、不消费 soulEvent（协议裁剪）。

## 6. 表情融合（M3 落地，契约先冻结）

- 展示表情 = `fuseExpression(基线 mood, 本轮 signal.emotion, signal.intensity)`：本轮高强度情绪短时压过基线；低落基线下 joy 降档。
- 余韵：消息结束后表情不瞬切 neutral，按情绪等级保持一段衰减窗口再回 idle（具体时长 M3 真机定）。
- 身体动作 v1.6 不走模型 shortAction（协议预留但不消费），只做触摸/微动作确定性触发。

## 8. eval 用例设计（M2 纳入 golden，三态开关矩阵）

| 用例族 | 断言 |
|---|---|
| 强模型合规 | 尾块合法 → state 按 deltas 变化、source=model、表情融合正确 |
| 弱模型（7B） | 无尾块 → 规则保底或默认 chat；被夸「你真棒」→ praise；全程主回复正常 |
| 脏尾块 | 词表外/半截 JSON/根为数组/intensity 字符串 → 逐叶回落，无异常上抛 |
| 开关双态 | 关闭情绪：不注入、不解析、不写事件，正文与历史零变化 |
| 衰减 | 注入可控时钟：离线 60min 后 happiness×0.98、sadness×0.995；关系不衰减 |
| 多人链路 | 协作/会议 run 不产生情绪事件、prompt 不含情绪段 |
| 持久化 | 重置 → 默认状态；重启读回一致；备份导出含新表、恢复后可读 |
