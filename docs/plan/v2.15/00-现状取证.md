# v2.15 现状取证：四个运维动作的代码位置

> 目的：为 [v2.15 方案](README.md) 提供可核对的现状证据。只记录事实，不做设计。

## 1. 技能快照：只增不减，没有占用与删除入口

| 事实 | 位置 |
|---|---|
| `SkillVersionService` 只暴露 `capture / list / rollback`，没有删除方法 | `packages/core/src/skills/skill-version-service.ts:42-49` |
| `prune` 自动保留最近 `keep` 版 + active，删除超额行与目录 | `packages/core/src/skills/skill-version-service.ts:81-98` |
| `list` 每项返回 `sizeBytes`，但没有全局 `totalBytes` | `packages/core/src/skills/skill-version-service.ts:100-111` |
| 仓储只有 `remove(id)`，没有按 name + version 删除或引用计数 | `packages/database/src/repositories/skill-version-repo.ts:87-120` |
| 版本面板只渲染版本号 / 时间 / 当前徽章 / 回退按钮，没有占用或删除 | `apps/web/src/features/settings/skill-versions.tsx:58-89` |
| 设置页只展开版本面板，不展示磁盘占用 | `apps/web/src/features/settings/skills-panel.tsx:143-152` |

结论：快照自动保留 5 版，用户无法主动清理非启用版本，也看不到它们占了多少磁盘。删除还必须处理「多个状态行共享同一 `dir_path`」的复用逻辑。

## 2. 审计：只有全量导出，没有归档与锚点

| 事实 | 位置 |
|---|---|
| 导出端点只支持 `format=jsonl`，流式输出完整账本 | `apps/web/src/app/api/audit/export/route.ts:6-31` |
| `AuditService` 暴露 `append / safeAppend / verify / iterateJsonl`，没有归档或锚点方法 | `packages/core/src/governance/audit.ts:143-256` |
| 链校验按 seq 升序重算，返回首个断链 seq；支持只校验最近 N 条 | `packages/core/src/governance/audit-verify.ts:17-49` |
| 校验端点直接调用 `services.audit.verify()`，校验本身落账本 | `apps/web/src/app/api/audit/verify/route.ts:1-7` |
| 审计表为追加式哈希链；没有 anchor / archive 相关路由 | 全仓检索：`anchor` 仅出现在无关代码，`apps/web/src/app/api` 无归档路由 |
| 审计页只有刷新 / 校验 / 导出三个动作 | `apps/web/src/features/audit/audit-page.tsx:191-214` |

结论：账本可以导出，但导出物无法证明「导出之后尾部没有被删」；整表尾部截断时剩余链仍自洽，需要外部锚点文件与校验入口。

## 3. 凭证：有密文存储，没有轮换入口

| 事实 | 位置 |
|---|---|
| Provider `api_key_cipher` 在创建 / 更新时通过 `cipher.encrypt` 写入 | `packages/core/src/services/provider-service.ts:59-86` |
| 列表解密失败时降级为「未配置」，不拖垮列表，提示用户重新输入 | `packages/core/src/services/provider-service.ts:30-46` |
| 仓储提供含密文的 `getRow(id)` 与 `update(fields)`，可重写密文 | `packages/database/src/repositories/provider-repo.ts:72-88` |
| Web 主密钥为单一 `keys/master.key`（32 字节），不存在则创建 | `packages/core/src/secrets/master-key.ts:6-23` |
| Electron 通过主进程 safeStorage 回环桥加解密；注释明确「桥只返回明文，持久化由服务层下次保存时重加密」 | `apps/desktop/src/main/cipher-server.ts:56-64` |
| 加密格式自描述 `wbfm.v1.<base64 JSON>`，解密失败返回 null | `packages/core/src/secrets/crypto-box.ts:21-46` |
| 全仓没有 secret rotate / re-encrypt 路由或服务 | `apps/web/src/app/api` 检索无 `rotate` 相关凭证路由 |

结论：Provider Key 已有稳定的密文读写与降级路径，但没有批量重封装入口；Web 主密钥只有单 key 文件，无法在轮换期间同时解旧密文。
