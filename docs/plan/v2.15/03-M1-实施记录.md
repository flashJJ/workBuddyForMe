## 1. 本里程碑做了什么

| 能力 | 行为 |
|---|---|
| 占用统计 | `GET /api/skills/:name/versions` 新增 `totalBytes`，按代表版本求和，共享目录不重复计 |
| 删除 | `DELETE /api/skills/:name/versions/:version` 删除指定非启用版本 |
| 保护 | active 版本 → 409 `SKILL_VERSION_ACTIVE`；代表版本只剩一个 → 409 `SKILL_VERSION_LAST`；版本不存在 / 无行 → 409 `SKILL_VERSION_MISSING` |
| 多行清理 | 按 `name + version` 删除全部状态行，兼容能力包升级重建 `skills_state` 行后的历史行 |
| 目录 | 删除行后按 `dir_path` 引用计数，无引用才删目录；释放字节只计实际删除目录 |
| 审计 | 成功后写 `skill_version_deleted`（actor=user，outcome=`name@version`，不含路径） |
| UI | 版本面板显示「共 N 版 · 占用 X」；非 active 行提供删除按钮与二次确认；active / 最后一份显示保护文案 |

## 3. 关键口径

1. **删除粒度**：UI 以版本号为一个条目，删除时按 `name + version` 删除全部状态行，避免「删了又回来」。
2. **保护顺序**：先确认行存在，再判 active，再判最后一份；不存在版本返回 `SKILL_VERSION_MISSING`。
3. **目录引用**：先删行、再按 `dir_path` 计数，只有 0 引用才 `rmSync`；共享目录只删一次。
4. **审计层级**：审计写在路由层，因为核心服务不依赖 `AuditService`；`safeAppend` 失败不回滚删除。
5. **UI 保护**：active 行与仅剩一版时不渲染删除按钮，显示「当前版本 / 仅剩一个版本，不可删除」。
6. **展示**：字节数在面板内做 B / KB / MB 格式化，不引入跨域工具。

## 4. 契约偏差与说明

| # | 事项 | 说明 |
|---|---|---|
| 1 | 审计写入位置 | M0 只要求成功后写 `skill_version_deleted`；实现放在 web 路由层，避免 core 服务新增 audit 依赖 |
| 2 | `SKILL_VERSION_LAST` | 正常流程里 active 总会命中；该保护用于「active_version 与现有快照不一致」或未来批量清理的防御场景 |
| 3 | 删除失败语义 | 目录删除失败返回 500，已删除的行不回滚；与 M0「删除不可逆、失败不假装成功」一致 |
| 4 | 行数 | `skill-version-service.ts` 262 行，进入 260 行预警区但未触 300 硬门禁；后续 M2–M4 不在此文件继续堆逻辑 |
