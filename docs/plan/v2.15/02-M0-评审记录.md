## 1. 发现与处置

| # | 级别 | 问题 | 取证 | 处置 |
|---|---|---|---|---|
| R1 | 高 | `skill_versions` 唯一约束是 `(skill_state_id, version)`；能力包升级会重建状态行，同一 `name + version` 可能有多行。只删代表行会「删了又回来」 | `packages/core/src/skills/skill-version-service.ts:72-79,140-150`；`packages/database/src/repositories/skill-version-repo.ts:62-85` | 已回写 M0 §0 D1 / §1.2：按 name + version 删除全部状态行；目录仅在无行引用时删除 |
| R2 | 高 | 多个状态行可能共享同一 `dir_path`；按版本求和会重复计占用，直接删目录会误删其他行仍在用的快照 | `skill-version-service.ts:100-111`（list 按代表行）、`findByNameVersionChecksum` 复用目录 | 已回写 M0 §0 D2–D3 / §1.1：`totalBytes` 只按代表行求和；删除前做目录引用计数 |
| R3 | 高 | 审计仓储 `list()` 按 seq 倒序且 limit 上限 200；`listAscending` 只按 seq、无时间区间参数。归档不能直接复用列表接口 | `packages/database/src/repositories/audit-event-repo.ts:110-136` | 已回写 M0 §7：补 `listRangeAscending`、`countRange`、`getBySeq` 查询；不改表 |
| R4 | 高 | 既有 `/api/audit/verify` 默认把校验结果写回 `audit_verified`；锚点校验若复用会反过来污染账本 | `packages/core/src/governance/audit.ts:230-238`；`apps/web/src/app/api/audit/verify/route.ts:1-7` | 已回写 M0 §0 D5 / §2.3：锚点校验走新端点，只读、不写 `audit_verified` |
| R5 | 高 | 锚点只记录区间尾，无法发现「归档之后又删了账本尾部」；必须同时记录生成时的全账本尾 | `audit-event-repo.ts:93-99`（`tail()` 已存在） | 已回写 M0 §0 D5 / §2.2：锚点增加 `ledger.lastSeq / lastHash`；校验先比全账本尾 |
| R6 | 高 | Web 主密钥是单个 32 字节 `keys/master.key`；直接换 key 会让旧密文全部不可解，也无法在轮换中途崩溃后恢复 | `packages/core/src/secrets/master-key.ts:6-23`；`packages/core/src/secrets/cipher.ts:19-29` | 已回写 M0 §0 D8–D9 / §3.3：keyring + fallback；先写 keyring 再重封装；`failed===0` 时同步旧文件 |
| R7 | 中 | `SecretCipher` 没有 mode / 轮换能力；Web 与 Desktop 的轮换语义不同，服务层不能靠猜 | `packages/core/src/secrets/cipher.ts:19-44` | 已回写 M0 §3：cipher 实现暴露 `mode` 与可选 `rotateKey`；Desktop 只重封装 |
| R8 | 高 | 工作流边 id 在保存 / 编辑器重排后可能变化；按 edge id 对比会产生假差异；节点坐标变化也不应算图变化 | `packages/shared/src/schemas/flow.ts`（节点 config 为开放对象）；`flow-versions-dialog.tsx:80-116` | 已回写 M0 §0 D10 / §4.2：边按 `source→target→handle` 归一，忽略坐标与边 id |
| R9 | 中 | 归档、锚点、轮换、diff 都可能撞 300 行门禁；审计页与关于面板已接近上限 | 现有 `audit-page.tsx`、`about-panel.tsx` 体量 | 列为 M2–M4 实施约束：纯函数与 UI 组件独立文件 |
| R10 | 中 | 新增审计 kind 必须同步 `AUDIT_EVENT_KINDS`、审计页 `KIND_KEYS` 与中英文案，漏一处会 typecheck 失败或显示原始 key | `apps/web/src/features/audit/audit-page.tsx:29-43`；`packages/shared/src/schemas/audit.ts` | 列入 M1/M3 清单：shared → 页面映射 → i18n 一次性同步 |
| R11 | 中 | 零迁移容易被误改成 v043；迁移测试大量硬编码 42，任何新迁移都会扩大改动面 | `packages/database/src/migrations/runner.ts:263`；多处迁移测试断言 42 | 已回写 M0 §0 D11 / §7：本版不新增迁移；如需升级必须回到 M0 重新评审 |
| R12 | 中 | 归档事件上限与内存组装方式必须明确，否则大账本会拖垮服务 | 既有 JSONL 导出是流式；诊断包已有 10 MB 上限 | 已回写 M0 §0 D4 / §2.1：区间 ≤366 天、事件 ≤5 万、ZIP ≤20 MB，超限 422 |

## 2. 已回写 M0 的条款

1. §0 D1–D3：技能版本按 name+version 全删、active / 最后一份保护、`totalBytes` 去重。
2. §1：删除算法、目录引用计数、失败语义与审计事件。
3. §0 D4–D6 / §2：归档区间边界、锚点 range + ledger 双尾、只读校验与业务结果码。
4. §0 D7–D9 / §3：Provider-only 范围、Web keyring / Desktop 重封装、写入顺序与降级兼容。
5. §0 D10 / §4：节点与边身份、config 顶层键、坐标忽略、只读对比。
6. §5：HTTP 错误码与 200 业务码分离。
7. §7：零迁移与仓储增量查询。
8. §9：测试矩阵与 4 类运维 e2e。
