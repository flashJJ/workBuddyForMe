# v2.15 M0：可运营——契约冻结

> 状态：✅ 已冻结（2026-10-31，评审记录见 [02-M0-评审记录](02-M0-评审记录.md)）
> 范围：技能版本清理、审计归档与外部锚点、Provider 凭证轮换、工作流版本对比（M5 回归 e2e）。
> 原则：零迁移；默认行为与 v2.14 一致；删除可审计、锚点只校验不落库、轮换失败不影响既有调用、对比只读。
> 关联：[v2.15 方案](README.md) · [现状取证](00-现状取证.md)

## 0. 冻结决策摘要

| # | 决策 | 取舍 |
|---|---|---|
| D1 | 技能版本删除按 `name + version` 删除全部状态行；仅当没有任何行再引用同一目录时才删盘 | 能力包升级会重建 `skills_state` 行，同一版本可能有多行；只删代表行会「删了又回来」 |
| D2 | `active_version` 与「最后一份版本」受保护；删除前先判保护，再动行 / 盘 | 删除不可逆；宁可拒绝，也不让用户删掉唯一可用版本 |
| D3 | 版本列表响应新增 `totalBytes`；按代表行求和，共享目录不重复计 | 面板需要占用总览；不能把跨状态行共享的快照重复计入 |
| D4 | 审计归档按 ISO 时间区间导出 ZIP：`events.jsonl` + `anchor.json`；区间 ≤366 天、事件 ≤5 万、ZIP ≤20 MB | 内存组装的边界明确；超限给出结构化错误，不做静默截断 |
| D5 | 锚点同时包含「区间尾」与「全账本尾」；校验返回业务结果，不落库、不写 `audit_verified` | 只记区间尾无法发现归档之后又删了尾部；校验是读操作，不能污染账本 |
| D6 | 锚点校验的业务失败返回 200 + `code`；只有锚点 JSON 结构非法返回 422 | 与既有 `/audit/verify` 的 `{ ok:false }` 语义一致，UI 不把「账本被截断」当请求失败 |
| D7 | 凭证轮换 P0 只覆盖 Provider `api_key_cipher`；MCP `env/headers` 加密列 P1-3 | 控制范围；MCP 字段是结构化配置，需单独迁移与依赖顺序设计 |
| D8 | Web 主密钥升级为 keyring 文件；Desktop safeStorage 只做重封装 | safeStorage 的系统密钥由 OS 管理，不能宣称更换；Web 才能做真正的 key 轮换 |
| D9 | 轮换写入顺序：先写 keyring（新 active + 旧 fallback）→ 重封装 → 成功时同步旧 `master.key` | 任一步崩溃，旧密文仍可由 fallback 解密；`failed > 0` 时不同步旧文件 |
| D10 | 工作流 diff 以节点 id、边 `source→target→handle` 为身份；忽略坐标与边 id；config 只比较顶层键 | 布局变化不应制造噪音；字段级高亮列 P1 |
| D11 | 零迁移：`LATEST_SCHEMA_VERSION` 保持 42；不新增表 / 列 | 四项均可复用现有数据；锚点只做文件，轮换只改文件与行内密文 |
| D12 | 新增审计事件 `skill_version_deleted`、`secrets_rotated`；归档导出与锚点校验不写审计 | 破坏性操作必须留痕；只读校验不应反过来污染证据 |
| D13 | 设置页入口：技能版本面板、审计页动作区、设置 → 关于（安全区块）、工作流版本抽屉 | 复用现有页面，不新开运维主页 |

## 1. 技能版本清理契约

### 1.1 版本列表（增量）

`GET /api/skills/:name/versions`

```ts
interface SkillVersionsResponse {
  versions: SkillVersionView[];
  versioningAvailable: boolean;
  /** v2.15：所有代表版本的磁盘占用之和；共享目录只计一次 */
  totalBytes: number;
}
```

- `versions` 仍按 `createdAt` 倒序、每版本一行代表（优先当前状态行）；
- `totalBytes` = 代表行 `directorySize` 之和；
- 无快照时 `versions=[]`、`versioningAvailable=false`、`totalBytes=0`。

### 1.2 删除

`DELETE /api/skills/:name/versions/:version`

```ts
interface SkillVersionDeleteResult {
  version: string;
  rowsRemoved: number;
  freedBytes: number;
  dirDeleted: boolean;
}
```

响应：`{ deleted: SkillVersionDeleteResult; versions: SkillVersionsResponse }`。

算法（顺序固定）：

1. 解析 `name` / `version`；
2. 技能状态不存在 → 404（沿用通用 `NOT_FOUND`，消息「技能」）；
3. 收集全部 `skill_versions` 行中 `name + version` 匹配的行（跨状态行）；一行都没有 → 409 `SKILL_VERSION_MISSING`；
4. `active_version === version` → 409 `SKILL_VERSION_ACTIVE`；
5. 代表版本数 ≤ 1 → 409 `SKILL_VERSION_LAST`；
6. 记录每个 `dir_path`，逐行删除；
7. 对每个 `dir_path`，若已无任何行引用，则 `rmSync` 目录，`dirDeleted=true`，否则保留，`freedBytes` 只计实际删除的目录；
8. 成功后 `safeAppend` 审计 `skill_version_deleted`（`actor: user`，`outcome: "<name>@<version>"`，不含绝对路径）；审计失败不回滚删除；
9. 返回最新列表。

保护与边界：

- active 版本永不删除；唯一剩余版本永不删除；
- 删除只影响快照，不影响 `skills/<name>` 正式目录与启用态；
- 删除目录失败 → 500 `SKILL_VERSION_DELETE_FAILED`，已删行不回滚（下次重扫不会重建旧版本）；
- 不做批量删除 / 自动清理；P1 再提供保留策略配置。

### 1.3 UI

- 版本面板标题显示「N 版 · 占用 X」；
- 非 active 行显示删除按钮；active 行显示「当前，不可删除」；
- 删除前二次确认，文案包含版本号与将释放的字节；
- 删除成功后列表与总占用刷新；失败显示结构化错误码。

## 2. 审计归档与锚点契约

### 2.1 归档

`GET /api/audit/archive?from=<ISO>&to=<ISO>`

- `from` / `to` 必填，ISO 8601 含时区；`from <= to`；
- 区间跨度 ≤ 366 天；区间内事件数 ≤ 50,000；ZIP ≤ 20 MB；
- 超限 → 422 `AUDIT_ARCHIVE_TOO_LARGE`（`details: { count, limit, reason }`）；
- 返回 `application/zip`，文件名 `audit-archive-<YYYYMMDD-HHmmss>.zip`；
- 内容仅两个文件：

| 文件 | 内容 |
|---|---|
| `events.jsonl` | 区间内事件，按 seq 升序，一行一条；格式与既有 JSONL 导出一致 |
| `anchor.json` | 锚点对象，见 §2.2 |

- 归档只导出，不删除账本，不写审计事件。

### 2.2 锚点

```ts
interface AuditAnchor {
  formatVersion: 1;
  appVersion: string;
  schemaVersion: number;
  generatedAt: string;
  range: {
    from: string;
    to: string;
    count: number;
    firstSeq: number | null;
    lastSeq: number | null;
    lastHash: string | null;
    chain: { ok: boolean; checked: number; firstBrokenSeq: number | null; truncated: boolean };
  };
  /** 生成时的全账本尾，用于发现归档之后的尾部删除 */
  ledger: { lastSeq: number | null; lastHash: string | null };
}
```

- 空区间：`count=0`、`firstSeq/lastSeq/lastHash=null`；`chain` 仍记录全账本校验结果；
- `chain` 使用只读校验（`record:false`），超过 100,000 条只校验最近 100,000 条并标 `truncated`；
- 不含事件正文之外的新字段；不含绝对路径、密钥、对话内容。

### 2.3 锚点校验

`POST /api/audit/anchor/verify`，请求体为 `anchor.json` 对象。

```ts
type AnchorVerifyCode =
  | 'ANCHOR_OK'
  | 'ANCHOR_TAIL_TRUNCATED'
  | 'ANCHOR_MISMATCH'
  | 'ANCHOR_CHAIN_BROKEN';

interface AuditAnchorVerifyResult {
  ok: boolean;
  code: AnchorVerifyCode;
  anchor: { range: AuditAnchor['range']; ledger: AuditAnchor['ledger'] };
  current: { lastSeq: number | null; lastHash: string | null };
}
```

- JSON 结构 / 版本 / 字段非法 → 422 `VALIDATION_ERROR`；
- 业务结果返回 200：
  1. `anchor.ledger.lastSeq !== null` 且当前账本为空 → `ANCHOR_TAIL_TRUNCATED`；
  2. `anchor.ledger.lastSeq !== null` 且当前最大 seq < `anchor.ledger.lastSeq` → `ANCHOR_TAIL_TRUNCATED`；
  3. `anchor.ledger.lastSeq !== null` 且当前账本在该 seq 处不存在或 hash 不等 → `ANCHOR_MISMATCH`；
  4. `anchor.range.count > 0` 且区间尾事件缺失 / hash 不等 / 重新计数不等 → `ANCHOR_MISMATCH`；
  5. `anchor.ledger.lastSeq === null` 且 `anchor.range.count === 0`：只要锚点结构合法即 `ANCHOR_OK`（空账本锚点不要求当前仍为空）；
  6. `anchor.range.chain.ok === false` → `ANCHOR_CHAIN_BROKEN`；
  7. 其余 → `ANCHOR_OK`；
- 校验不写 `audit_verified`，不写任何审计事件；不做“自动修复”。

### 2.4 UI

- 审计页动作区新增「导出归档」：默认最近 7 天，可修改起止时间；下载 ZIP；
- 新增「验证锚点」：选择 `anchor.json`，展示四种结果与当前 / 锚点尾 seq；
- 归档与校验结果不改变审计页过滤条件；无关联审计事件沿用原空态。

## 3. Provider 凭证轮换契约

### 3.1 范围

- 仅 Provider `api_key_cipher`；无密文的 Provider 计入 `total` 但不计入 `rotated/skipped/failed`；
- MCP `env/headers`、信任库、其他配置不在 P0 范围（P1-3）。

### 3.2 API

`POST /api/secrets/rotate`（无请求体）

```ts
interface SecretRotationResult {
  mode: 'web' | 'desktop';
  total: number;
  rotated: number;
  skipped: number;
  failed: number;
  /** 无法解密或写回失败的 Provider id，供 UI 提示；不含密文 / 明文 */
  skippedProviders: string[];
  failedProviders: string[];
  keyId: string | null;
  /** Web：是否把新 active key 同步到旧 master.key；Desktop 为 null */
  legacyKeySynced: boolean | null;
}
```

- 加密不可用 → 503 `SECRET_ROTATION_UNAVAILABLE`；
- keyring 写入失败 → 500 `SECRET_ROTATION_FAILED`，不更新任何 Provider 行；
- 单条解密返回 null → `skipped`；单条写回失败 → `failed`，保留旧密文；
- 成功写审计 `secrets_rotated`（`actor: user`，`outcome` 仅计数与 mode）；
- 永不返回密文、明文或完整密钥。

### 3.3 Web keyring

`keys/master-keyring.json`（0600，原子写：临时文件 + rename）：

```ts
interface MasterKeyring {
  formatVersion: 1;
  activeKeyId: string;
  keys: Array<{
    id: string;
    key: string; // base64(32 bytes)
    createdAt: string;
    retiredAt: string | null;
  }>;
}
```

- 启动兼容：keyring 不存在但旧 `keys/master.key` 存在 → 读入为 `legacy` key；
- 解密顺序：active → 其余 key 逐个尝试；任一成功即可；
- 加密始终使用 active key；
- keyring 最多 3 把（active + 两个 fallback）；一次「全部成功」的轮换后裁剪到 active + previous；
- 轮换：
  1. 读取全部 Provider 密文并逐条解密；
  2. 生成新 32 字节 key，加入 keyring 并设为 active，原子写；
  3. 对可解密行用新 active 重加密并写回；
  4. `failed === 0` 时，把新 active key 原子写入旧 `keys/master.key`（32 字节 raw），保证回退到 v2.14 可解密；`failed > 0` 时不动旧文件；
  5. `legacyKeySynced` 返回是否完成第 4 步；同步失败不影响 v2.15 通过 keyring 解密；
  6. 审计计数。

### 3.4 Desktop 语义

- safeStorage 的系统密钥由 OS 管理；`POST /api/secrets/rotate` 只对全部可解密 Provider 重新 `encrypt` 并写回；
- 不创建 / 修改 keyring 与 `master.key`；`mode='desktop'`、`keyId=null`、`legacyKeySynced=null`；
- UI 文案「重新加密已存凭证」，不宣称更换系统密钥。

### 3.5 UI

- 设置 → 关于（安全区块）新增「轮换凭证」按钮；
- 二次确认文案说明：只重封装 Provider API Key、不可解密项会跳过、失败不影响既有调用；
- 完成展示 `rotated / skipped / failed` 与需处理的 Provider id；
- 轮换期间按钮禁用。

## 4. 工作流版本对比契约

### 4.1 差异形状

```ts
interface FlowGraphDiff {
  from: number;
  to: number;
  nodes: {
    added: Array<{ id: string; type: string }>;
    removed: Array<{ id: string; type: string }>;
    typeChanged: Array<{ id: string; fromType: string; toType: string }>;
    configChanged: Array<{ id: string; type: string; keys: string[] }>;
  };
  edges: {
    added: Array<{ source: string; target: string; handle: string | null }>;
    removed: Array<{ source: string; target: string; handle: string | null }>;
  };
  summary: {
    nodesAdded: number;
    nodesRemoved: number;
    nodesTypeChanged: number;
    nodesConfigChanged: number;
    edgesAdded: number;
    edgesRemoved: number;
  };
}
```

### 4.2 语义

- 节点身份 = `id`；同名 id 且 type 不同 → `typeChanged`，不再同时报 `configChanged`；
- 节点 config 只比较顶层键；键新增 / 删除 / 值变化都计入 `keys`，按字母升序；
- 边身份 = `source → target → handle`（无 handle 记 `null`）；忽略边 id；
- 节点坐标、尺寸、选中态等布局字段不参与 diff；
- `from === to` 返回全零；版本不存在 → 404 `FLOW_VERSION_NOT_FOUND`（沿用）。

### 4.3 API 与 UI

`GET /api/flows/:id/versions/compare?from=<n>&to=<n>`

- `from` / `to` 为正整数；查询参数非法 → 422 `VALIDATION_ERROR`；
- 返回 `FlowGraphDiff`，不返回完整图。

UI（工作流版本抽屉）：

- 增加两个版本选择器：默认 `from = 生产版本 ?? 当前版本`，`to = 当前版本`；
- 增加「对比」按钮；结果展示节点与边摘要，config 变化列出顶层键名；
- 不改变当前 / 生产版本，不触发保存；
- 两版相同显示「没有差异」。

## 5. API 与错误码汇总

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/skills/:name/versions` | 增量返回 `totalBytes` |
| DELETE | `/api/skills/:name/versions/:version` | 删除非启用快照 |
| GET | `/api/audit/archive` | 区间归档 ZIP |
| POST | `/api/audit/anchor/verify` | 锚点校验（只读） |
| POST | `/api/secrets/rotate` | Provider 凭证轮换 |
| GET | `/api/flows/:id/versions/compare` | 版本差异摘要 |

HTTP 错误：

| 场景 | 状态 | code |
|---|---|---|
| 删除 active 技能版本 | 409 | `SKILL_VERSION_ACTIVE` |
| 删除不存在的技能版本 | 409 | `SKILL_VERSION_MISSING`（沿用） |
| 删除唯一剩余版本 | 409 | `SKILL_VERSION_LAST` |
| 删除快照目录失败 | 500 | `SKILL_VERSION_DELETE_FAILED` |
| 归档区间事件 / 大小超限 | 422 | `AUDIT_ARCHIVE_TOO_LARGE` |
| 加密不可用 | 503 | `SECRET_ROTATION_UNAVAILABLE` |
| keyring 写入失败 | 500 | `SECRET_ROTATION_FAILED` |
| 工作流对比版本不存在 | 404 | `FLOW_VERSION_NOT_FOUND`（沿用） |

业务结果码（HTTP 200）：

| code | 含义 |
|---|---|
| `ANCHOR_OK` | 锚点与当前账本一致 |
| `ANCHOR_TAIL_TRUNCATED` | 当前账本尾短于锚点尾 |
| `ANCHOR_MISMATCH` | 锚点位置事件缺失或哈希不等 |
| `ANCHOR_CHAIN_BROKEN` | 生成锚点时链校验已发现断链 |

## 6. 视图、枚举与审计

- `SkillVersionsResponse` 增加 `totalBytes`；新增 `SkillVersionDeleteResult`；
- 新增 `AuditAnchor`、`AuditAnchorVerifyResult`、`AuditArchiveQuery`；
- 新增 `SecretRotationResult`、`MasterKeyring`（core 内部类型，不暴露明文）；
- 新增 `FlowGraphDiff` 与对比查询 schema；
- `AUDIT_EVENT_KINDS` 新增 `skill_version_deleted`、`secrets_rotated`，同步中英文案与审计页 `KIND_KEYS`；
- 新增错误码与中英文案；锚点业务码放 shared 联合类型，不占 HTTP 错误码表。

## 7. 数据模型与迁移

- **零迁移**：`LATEST_SCHEMA_VERSION` 保持 42，不新增表 / 列 / 索引；
- 复用 `skill_versions`、`providers.api_key_cipher`、`workflow_versions.graph_json`、`audit_events`；
- 仓储仅补查询 / 删除方法：技能版本按 name+version 删除、目录引用计数；审计区间升序、区间计数、按 seq 取事件；
- keyring 是文件格式升级（`keys/`），不是数据库迁移；旧 `master.key` 保留作降级兼容；
- v2.14 打开 v2.15 库：忽略新审计 kind 与文件格式，Provider 密文在 `legacyKeySynced=true` 时可解密。
