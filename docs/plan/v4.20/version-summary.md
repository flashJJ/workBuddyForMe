# v4.20 版本总结：快

> 版本：4.20.0（计划 2026-11-22 发布）
> 主题：首答与长会话体感——先量出来，再让它变快
> 迁移：零数据库迁移；备份格式不变；无新增运行时依赖
> 博客：[blog/v4.20](../../blog/v4.20/) 7 篇
> 发行说明：[v4.20.0-release-notes.md](../../roadmap/v4.20.0-release-notes.md)
> 性能基线：[perf-baseline.md](./perf-baseline.md)

## 1. 本版解决什么

v4.19 把功能欠账清完，但「用起来快不快」仍只能靠体感：

1. 首字、首段与完成三段没有统一指标，优化无法验证；
2. 首字等待没有预算与提示；
3. 长会话一次性渲染全部消息，滚动与流式追加缺少预算；
4. 冷启动与长文本在窄窗下没有回归基线；
5. 语音与评测还有两项小遗留。

本版不启动新主线，把「快」拆成可复算的指标、可回退的渲染策略与可验收的提示。

## 3. 关键设计

### 3.1 先有口径，再谈快慢

四段指标只在本机计算：冷启动、发送→首字、首段、完成。打点名固定为 `wbfm:app-ready / send / first-token / first-paragraph / done`，空 delta、心跳与状态事件不计。报告写 `test-results/perf/`，保留最近 20 份，写入前复用敏感内容扫描。

指标不读正文、不含令牌与绝对路径，是「本机回归」而不是「云端看板」。

### 3.2 阈值相对本机，而不是拍脑袋

客户端维护最近 20 轮成功完成的首字耗时 P50；阈值 = 有基线时 `min(P50×1.5, 10s)`，无基线时 10s。超过阈值只给一条可关闭提示，三个动作都是「打开入口」：停止、换更小模型、缩减上下文——不自动切换、不自动截断。

### 3.3 长会话按需挂载

首屏只挂最近 50 条，向上滚动分批加载；超过 200 条切换窗口化，前后各 10 条 overscan。关闭 `chatVirtualizationEnabled` 后与 v4.19 完全一致。深链目标强制挂载并高亮，流式追加在底部时保持吸底。

滚动更新合并到每帧一次后，500 条会话的 p95 帧间隔从 33.4ms 降到 16.7ms。

### 3.4 并入项只做「接得上」的部分

- 寒暄快路径命中时不创建回合后记忆提取任务，压缩与检查点不受影响；
- Edge TTS 改为 mpg123 增量解码，音频分片边收边经 sink 下发；已下发过分片后失败不再回退，避免重复朗读；
- CI 新增 `replay-compare`，`continue-on-error`，历史缓存只在主分支写入；
- 知识「新建任务」只跳 `/tasks?draft=` 预填标题与深链，不自动提交、不做文档-任务关联；
- 备用链上限 5，单轮切换仍最多 2 次；
- 健康度导出 Markdown/CSV，只使用当前面板报告数据。

## 4. 数据与验证

- `pnpm check`：typecheck、lint、行数、目录、循环依赖、MSW、ASCII、资产、surface、E2E 隔离全部通过；
- 全量单元测试：839 个文件、4689 条用例通过；
- API 集成测试：11 条通过；
- 回放脚本单测：2 个文件通过；
- 定向 E2E（生产模式）：长会话 1/1、冷启动 1/1、首字提示 1/1、知识新建任务 1/1、长文本窄窗 3/3；
- 性能：冷启动 `2605ms`（单次样本）；500 条滚动 p95 `16.7ms`；
- `pnpm verify:local` 全绿（含 Web 生产构建）。

## 5. 已知限制

- 性能数字来自单机单次样本，只做相对回归，不作为绝对值门禁；
- v4.19 无埋点，性能基线没有数值同比，只有 DOM 挂载量与可观测性的相对对比；
- 首字超阈值只提示，不自动降级；
- 健康度导出只包含当前面板数据，不含趋势图；
- 回放对比任务失败不阻断合并，也不改变阈值门禁；
- 流量计费与网络质量仍由供应商决定，本版不做云端上报。

## 6. 下一步

1. 观察首字提示的真实触发率，再决定是否扩大快路径与预算范围；
2. 评估把回放对比从「非阻断提示」升级为更稳定的门禁；
3. 记忆治理、Controller Pipeline、DAG 并行与视觉巡检 L2/L3 仍留待后续版本；
4. 云端性能上报与多机基线继续不做。
