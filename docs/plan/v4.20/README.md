# v4.20 选题与范围（已立项）

> 状态：已立项（2026-11-22）——主题「快」：首答与长会话体感；并入 v4.19 四项小遗留
> 规格：[spec.md](./spec.md) · 契约：[contracts.md](./contracts.md) · 任务：[tasks.md](./tasks.md)
> 上游：v4.19 已发布（`v4.19.0`，2026-11-22）
> 约束：按方案需要放开；若引入数据库迁移，必须可回滚并带备份校验；不新增无法打包的运行时依赖

## 1. 当前基线

v4.19 把所有顺延项清完，并实现期追加了语音链路（流式 TTS / Matcha / 腾讯云 / 微软 Edge）与寒暄快路径。当前能力面已经比较完整，下一版要在「体感」「记忆」「架构」「测试基础设施」之间选主线。

已知仍有体感缺口：

- TTFV 只在开发环境打印（`use-ttfv.ts`），没有首字/首段/完成分段指标，也没有预算与门禁；
- 消息列表仍一次性渲染全部消息（`MessageList` 直接 `map`），长会话缺少虚拟化或分块挂载；
- 语音刚补齐流式与在线兜底，但寒暄轮仍执行回合后记忆提取，Edge 仍是按句缓冲解码；
- 窄窗只复核了遮挡与横向溢出，长文本与长列表滚动帧率没有基线。

## 2. 候选方案

### 方案 A「快」——首答与长会话体感（推荐）

**痛点**：功能正确但慢会被感知为不好用；长会话滚动与首字等待缺少预算与回归门禁。

**做法**：

1. 本地分段指标：冷启动、发送→首字、首字→首段、完成耗时，落事件或本地报告；
2. 首字预算：超阈值给出「停止 / 换更小模型 / 缩减上下文」，不做静默降级；
3. 长会话渲染：消息虚拟化或按需挂载，设定滚动帧率与内存预算；
4. 语音后续：寒暄轮跳过回合后记忆提取、Edge 边收 MP3 边解码（可选 P2）；
5. 长文本与窄窗复核纳入指标，不只看截图。

**验收**：固定数据集上首字/首段耗时与滚动帧率可复算；超预算可解释；零迁移。

**成本/风险**：中高。性能验收受机器差异影响，需要固定基线与相对阈值；优化点分散。

### 方案 B「记得住、管得住」——统一记忆治理

**痛点**：v2.28 已做统计卡、审计轮转与约束撤销，但召回语义、冲突处理与晋升/降权仍分散在规则里，用户无法理解「为什么这条被记住/被忽略」。

**做法**：

1. 统一召回入口 `recall(scene, budget)`：场景、预算、去重、冲突裁决集中到一处；
2. 冲突与过期：同实体多值时保留来源与时间，冲突时按新鲜度/置信度裁决并可解释；
3. 用户治理：固定、降权、合并、删除，全部写 `actor='user'` 审计；
4. 可视化：最近召回、命中理由、被忽略原因（只读解释，不泄露正文）；
5. 评测：把记忆 golden 集接入回放历史，观察治理策略变化。

**验收**：同一输入召回结果可复算；冲突裁决有解释；用户操作可撤销/可追溯。

**成本/风险**：高。语义复杂、验收成本高，可能触及数据库或召回链路；收益偏长期。

### 方案 C「编排升级」——Controller Pipeline + DAG 并行

**痛点**：v4.9 只做了轻量三层（策略 / 预算 / 快照），Collector / Source / Packer / A-B 重放未做；多智能体仍串行，缺少预算共享、幂等与结果合并。

**做法**：

1. 全量 Controller Pipeline：Collector → Source → Packer，统一上下文来源与装配；
2. 多智能体并行/DAG：预算共享、幂等键、失败隔离与审查合并；
3. 回放接入：管线变更必须跑 A/B 回放与保真指标。

**验收**：同一会话在管线开关前后行为可对比；并行执行预算不超卖、重试不重复写。

**成本/风险**：最高。回归面大，收益偏架构而非直接用户感知。

### 方案 D「质量基础设施」——视觉巡检 L2/L3 与门禁

**痛点**：L1 只有截图与尺寸检查；回放对比仍是人工参考，没有进入 PR 非阻断；性能门禁只覆盖桌宠长跑。

**做法**：

1. Midscene 语义断言 L2（需 VLM 凭据）与 Playwright MCP 人工流程 L3；
2. 回放 `--compare=last` 升级为 PR 非阻断提示；
3. 性能基线扩展到聊天首字、长会话滚动与设置页大列表。

**验收**：L2/L3 用例可重复；PR 上能看到对比提示但不阻断；性能回归可定位。

**成本/风险**：中。L2 截图/VLM 可能出网，与本地优先边界冲突；价值密度偏低。

| **v4.20 并入** | 语音后续两项（寒暄轮跳过记忆提取、Edge 边收边解码） | v4.19 语音追加 §12 |

| **v4.20 并入** | 知识结果「继续任务 / 打开审批」（先做设计闸门，无稳定关联时降级为「以引用新建任务」） | v4.19 顺延 |
| **v4.20 并入** | 备用链上限放宽 + 健康度导出 | v4.19 顺延 |
| 后续 | 统一记忆治理（B） | v4.19 候选 |
| 后续 | 全量 Controller Pipeline（F）、并行/DAG（G） | v4.19 候选 |
| 后续 | 视觉巡检 L2/L3（H） | v4.19 候选 |

不把 B/F/G/H 放进本版的原因：

1. B 的召回语义与冲突裁决需要独立版本收敛，和「快」混做会让验收目标失焦；
2. F/G 回归面大，收益偏架构，适合在有明确并行需求后单独立项；
3. H 依赖外部视觉工具链与 VLM 凭据，价值密度低。

## 6. 初步范围与验收

### 6.1 主指标与预算

- 指标：冷启动（首屏可交互）、发送→首字、首字→首段、完成耗时；
- 数据只在本机记录，不含正文、令牌与绝对路径；
- 超过首字阈值时给出非阻断提示：停止 / 换更小模型 / 缩减上下文，不做静默降级；
- 固定数据集与相对基线，避免不同机器绝对值不可比。

### 6.2 长会话渲染

- 消息列表按需挂载或虚拟化，流式追加、回到底部、深链定位与高亮行为保持不变；
- 设滚动帧率与内存预算，500 条消息会话作为验收基线；
- 任何优化都要能用「关闭开关 → 行为与 v4.19 一致」回退。

### 6.3 冷启动与长文本

- 识别启动关键路径，非首屏模块延迟加载；
- 1024 / 1280 / 1440 三档 + 长文本场景复核无横向溢出与遮挡。

### 6.4 并入项（各自独立验收）

- 语音：寒暄轮跳过回合后记忆提取；Edge 在可行时改为边收边解码，否则保留现状并记录原因；
- 回放对比：接入 PR 非阻断提示，不改变现有阈值门禁；
- 知识动作：先过设计闸门；无稳定关联时实现「以引用新建任务」，不硬造审批关联；
- 备用链与健康度：上限放宽需同步 UI 与校验；健康度导出 Markdown/CSV，不含正文。

### 6.5 里程碑草案

| 阶段 | 内容 |

| M0 | 契约冻结：指标口径、预算阈值、虚拟化边界、并入项定义、是否迁移 |
| M1 | 分段指标、本地报告与首字预算提示 |
| M2 | 长会话渲染优化与滚动/内存预算 |

| M5 | 定向 E2E、全量验证与性能基线 |
| M6 | 文档、发行说明、博客与发布 |

## 7. 已决策（2026-11-22，M0 输入）

1. **首字预算**：相对基线 + 绝对兜底。超过本机 P50 的 1.5 倍或 10s 触发提示；动作为「停止 / 换更小模型 / 缩减上下文」，不静默降级。
2. **长会话渲染**：默认按需分块挂载；超过 200 条自动切换虚拟化；保留特性开关，关闭后行为与 v4.19 一致。流式追加、回到底部、深链定位与高亮必须保持。
3. **知识动作**：不做「打开审批」；「继续任务」在无稳定关联时降级为「以引用新建任务」，不新增文档-任务/审批关联字段。
4. **指标与基线存储**：写本机报告文件 `test-results/perf/`，保留最近 20 份；不新增数据库表。报告不含正文、令牌与绝对路径。
5. **并入项范围**：四项全部保留（语音后续两项、回放对比 PR 非阻断、知识动作、备用链上限放宽 + 健康度导出）。
6. **约束**：按方案需要放开；若引入数据库迁移，必须可回滚并带备份校验；不新增无法随 standalone 打包的运行时依赖。

M0 只需把这些决策转成契约、阈值表与任务清单，不再重复讨论范围。
