## 2. 决策说明

### D1 发布节奏

- v2.21.0 之后的 15 行修复已在 main，但安装包仍是旧行为。单独发补丁需要再走一次完整发布与更新通道验证，成本接近小版本。
- 直接 `v2.22.0`：补丁与收口项一起进入，用户只感知一次升级。
- 约束：M4 验收必须逐条回归 15 行修复，不能因「已在 main」跳过。

### D2 备份事件格式

- 不并入 `branches.json`：分支快照与事件是两类数据，合并会让恢复顺序与截断规则纠缠。
- 新文件 `branch-events.json`：结构 `{ schemaVersion, truncated, events: SessionEventView[] }`，只含 `scope='branch'`。
- 旧档缺失该文件 → 恢复为空事件，不报错；事件引用父/子会话缺失 → 整条跳过并计数。
- 恢复顺序：会话 → 分支 → 事件。理由：事件 payload 引用分支 id，分支先落库才能保证图投影完整。

### D3 失败重试语义

- 保持 v2.21 契约「终态不可回 `running`」，不修改状态机。
- 重试实现：读取旧分支的 `parentConversationId` / `goal` / `title`，调用现有 `create` 新建分支；新分支独立子会话。
- 旧分支保留 `failed` + `statusReason` + evidence，供对比追溯。
- UI 文案必须写「重试将新建分支」，避免误解为重启原分支。

### D4 终态回传

- 现状只有 `succeeded/failed` 走 `finalize` 的 evidence。`interrupted`（重启收敛）与 `cancelled`（排队取消）只写 `branch_status`。
- 统一：所有终态写 `branch_status` + `branch_returned`；无运行结果时 `evidence.summary` 为空、`needsReview=true`、`artifacts=[]`、`usage=0`。
- 父会话卡片区分「无运行结果」与「运行失败」，不把中断当失败。

### D5 运行中预算熔断

- 准入阶段保持 422（不创建、不启动）。
- 运行中：在分支运行器的 token 增量回调处检查会话树已用 + 预留；超限则 abort 并落 `budget_exceeded`，`statusReason` 给出上限与已用量。
- 预留归零、写回传；不影响同树其他分支（失败隔离）。

### D6 `waiting` 去留

- 当前没有子分支等待、审批等待或外部依赖等待场景，强行写入会产生无法收敛的状态。
- 决策：保留枚举（兼容已存数据与备份），但**不新增写入路径**；在契约与类型注释标注「保留，无写入路径」；补一条守卫测试，防止未来误写入却没有收敛逻辑。
- 若后续出现等待场景，另立版本实现，不在本版夹带。

### D7 实时帧范围

- 复用 v2.20 `runGraphLiveBus`，只发布 `branch_*` 事件对应的图变更，不推整图快照。
- 前端按 `seq` 去重，收到事件后增量 invalidate；连续 3 次断流或页面隐藏时回落 10s 轮询。
- 不扩大 scope，chat/task/flow 实时化不在本版。

### D8 真实供应商验收

- CI 环境无密钥，强制跑会永久红。
- 策略：检测密钥（供应商配置或环境变量）存在则跑并行/失败隔离用例；不存在则 `test.skip` 并在报告输出「缺少密钥，已跳过」。
- mock 用例（`WBFM_MOCK_AI=1`）保持必过门禁，覆盖回传卡片全链路。

## 5. 契约边界

- 状态机不变：`queued / running / waiting / succeeded / failed / cancelled / interrupted / budget_exceeded`。
- 新增终态写入路径：`interrupted`、`cancelled`、`budget_exceeded` 均写 `branch_returned`。
- 备份 schema 不升版；conversations 轨新增可选文件，保持向后兼容。
- 不新增表、不新增迁移。
