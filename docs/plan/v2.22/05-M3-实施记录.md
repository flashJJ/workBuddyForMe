## 3. 关键实现

- **帧差异**：首次出现的分支发 `branch_created`；`status` / `title` / `archivedAt` 变化发 `branch_status`；首次进入终态追加 `branch_returned`。payload 携带分支全量摘要，供图侧节点 patch 使用。
- **发布时机**：复用面板已有的 5s 轮询结果，`useBranchLiveFrames` 在 `branches` 引用变化时 diff；面板关闭即停止，不新增服务端 SSE 总线。
- **图侧刷新**：`useRunGraph` 只对 `scope === 'branch'` 且 root 匹配的帧响应，1s 节流调用 `refetch`，服务端投影保持权威；原有 10s `refetchInterval` 作为兜底。
- **终态 UI**：终态分支显示「重试」（`onRetry` 走 `POST /api/branches/[id]/retry`）；`evidence.summary` 为空时终态显示 `branch.evidence.noResult`，非终态仍显示 `noSummary`。

## 4. 测试

```
cd apps/web && pnpm exec vitest run src/features/branch src/features/run-graph   # 3 文件 / 13 例
cd packages/core && pnpm exec vitest run src/branch                               # 3 文件 / 18 例
pnpm check:structure && pnpm check:lines
```

新增断言：

1. 首轮快照产生 `branch_created` + `branch_returned`（已是终态）；
2. `running → succeeded` 产生 `branch_status` + `branch_returned`；
3. 仅重命名/归档产生 `branch_status`，不重复回传；
4. 列表无变化不产生帧；
5. 面板：终态卡显示「无运行结果」，点击「重试」命中 `/api/branches/b1/retry`。

## 5. 偏差与说明

- 未实现服务端分支 SSE：M0 决策为「面板轮询 + 帧总线 + 图 refetch」，避免为 branch scope 新增一条流。
- 图侧收到分支帧采用 refetch 而非本地投影：分支投影规则集中在 core，前端不重复实现。
- 结构门禁调整：`resolveBranchTree` / `readTreeUsage` 并入 `branch-limits.ts`，`branch-frames.ts` 改为引用 `@/features/run-graph` 公开入口。
