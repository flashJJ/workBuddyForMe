# v2.22 方案：收口——分支会话可靠性与发布闭环

> 状态：M0–M4 实施完成，验收通过；版本 2.22.0（分支 `feature/v2.22-planning`），发布待确认
> 决策草案：[01-M0 决策记录](01-M0-决策记录.md)
> 前置版本：v2.21（自由分支会话与回传）
> 主题一句话：**把 v2.21 留下的「已修未发布」与「未修无承接」两类缺口一次性收口，让分支会话可靠、可恢复、可观测。**

## 1. 为什么是「收口」

v2.21.0 发布后，两轮审计共修复 15 项缺陷，但都没有进入安装包；另有 8 项残余缺口只写在文档里：

1. 用户装到的版本仍是「并发可越限、子会话不继承模型、图状态不收敛、无法重命名」的旧行为；
2. 分支事件不随备份走，换机恢复后图上车道与回传节点全部消失；
3. 中断/取消分支没有回传，父会话只看到「没了」，不知道是失败还是被取消；
4. 失败分支只能手工重新派生，缺少明确的重试入口；
5. 预算触顶只挡在准入阶段，运行中超预算没有熔断终态；
6. 分支面板与图仍靠 5s/10s 轮询，长任务体验割裂。

这些问题彼此关联，分散成补丁会反复回归。**v2.22 不加新主题，只做收口。**

## 2. 目标与成功指标

| 指标 | 现状（v2.21.0） | v2.22 目标 |
|---|---|---|
| 补丁可达 | 15 项修复仅在 main | 全部进入 v2.22.0 安装包与更新通道 |
| 备份完整性 | 仅 `branches.json`，无分支事件 | 恢复后分支车道/回传节点与导出前一致 |
| 终态回传 | 仅 `succeeded/failed` 有 evidence | `interrupted/cancelled/budget_exceeded` 均产出可识别回传 |
| 失败重试 | 手工重新派生 | 分支卡一键「重试」；旧分支保留追溯 |
| 预算控制 | 仅准入拒绝 | 运行中超限收敛为 `budget_exceeded`，预留归零 |
| 实时性 | 面板 5s / 图 10s 轮询 | 分支事件实时推送，轮询兜底 |
| 数据兼容 | schema 45 | 零迁移，`LATEST_SCHEMA_VERSION = 45`；旧备份可恢复 |

## 3. 功能清单

### 3.1 P0（本版必须）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P0-1 | 补丁承接 | 已修复缺陷必须真正到达用户 | M0 冻结 15 项清单并逐条回归；v2.22.0 安装包行为与 main 一致 |
| P0-2 | 分支事件备份 | 换机/回滚后图仍完整 | 导出含 branch 事件；恢复后分支车道、子会话节点、回传节点与导出前等价；旧档缺文件不报错 |
| P0-3 | 终态回传补齐 | 中断/取消也要有交代 | 四种终态均写 `branch_returned`；无摘要时 evidence 标「需核对」且 UI 明示「无运行结果」 |
| P0-4 | 失败重试 | 失败后能快速再来一次 | 失败分支卡提供「重试」；新建分支继承原目标与父子关系；旧分支保持终态 |

### 3.2 P1（本版锁定）

| # | 功能 | 用户故事 | 验收 |
|---|---|---|---|
| P1-1 | 运行中预算熔断 | 长任务不能无限消耗 | 超预算时状态收敛为 `budget_exceeded`，写回传与预留归零；准入拦截保持 422 |
| P1-2 | 分支实时帧 | 长任务不想等轮询 | `branch_*` 事件推送到图；断流时自动回落轮询 |
| P1-3 | 真实供应商并行验收 | 多分支并行要能验证 | 有密钥跑并行/失败隔离 e2e；无密钥显式 skip 并输出原因 |
| P1-4 | `waiting` 收口 | 状态枚举不能有名无实 | 有等待场景则写入并测；无场景则文档标注「保留无写入」并加守卫测试 |

### 3.3 P2（本版可选）

| # | 功能 | 说明 |
|---|---|---|
| P2-1 | 回传汇总草稿 | 父会话一键把多条 evidence 汇总为草稿消息 |
| P2-2 | 图聚焦当前分支 | 车道过多时默认聚焦，其余折叠 |
| P2-3 | 分支面板批量操作 | 批量归档/恢复/删除 |

## 4. 承接 v2.21 遗留项

| v2.21 §9 残余 | 本版处置 | 归属 |
|---|---|---|
| 1. 分支事件不随备份导出 | 做：新增 branch 事件轨 | P0-2 |
| 2. `waiting` 未由运行器写入 | 决策后收口 | P1-4 |
| 3. 真实供应商并行 e2e 未纳入门禁 | 做：有密钥必跑，无密钥显式 skip | P1-3 |
| 4. 分支实时帧未接 | 做：接入 `runGraphLiveBus` | P1-2 |
| 5. `budget_exceeded` 终态未写入 | 做：运行中熔断 | P1-1 |
| 6. 失败分支无单独重试入口 | 做：重试 = 新建分支 | P0-4 |
| 7. 中断/排队取消无 evidence 与回传节点 | 做：终态回传补齐 | P0-3 |
| 8. `v2.21.1` 未发布 | 做：补丁随 v2.22.0 发布 | P0-1 |

## 7. 风险与取舍

| 风险 | 影响 | 缓解 |
|---|---|---|
| 补丁清单漏项 | 用户仍遇到已修缺陷 | M0 以 v2.21 §9 已修表为唯一真源，逐条打勾 |
| 备份事件过大 | 导出慢、恢复久 | 仅 branch scope；超限截断并标注 |
| 重试被当成「重启原分支」 | 追溯混乱 | 文案与文档统一为「新建分支」，旧分支只读 |
| 实时帧乱序/重复 | 图抖动 | 服务端快照语义、前端按 seq 去重；轮询兜底 |
| 真实供应商不可用 | 门禁不稳定 | 密钥缺失显式 skip，mock 用例必过 |

## 8. Non-Goals

- 不做 Git worktree / checkpoint / review；
- 不做自动递归派生与自动重试；
- 不做多用户共享、云同步、远程分支；
- 不新增迁移，不改 `conversations` 核心表；
- 不做新的分支入口形态（入口已在 v2.21 收口）。

## 9. 验收矩阵

| 维度 | 门禁 |
|---|---|
| 单测 | 分支服务/备份恢复/预算熔断/终态回传全覆盖；`pnpm test` 不降级 |
| 类型与结构 | `pnpm check`（typecheck + lint + lines + structure + cycles + ascii）通过 |
| API | 分支 CRUD/启动/取消/重试/详情契约测试通过 |
| e2e | 分支备份往返、四类终态回传、失败重试、实时帧、并行隔离 |
| 构建 | `pnpm build:web` 与桌面安装包构建通过 |
| 兼容 | 旧备份（无 branch 事件文件）恢复不报错；schema 保持 45 |
