# v2.22 M1 实施记录：备份分支事件轨

> 契约：[02-M0 契约冻结](02-M0-契约冻结.md) §1
> 状态：已完成（2026-11-04）；测试通过，待 M2 实施。

## 1. 目标

把 `scope='branch'` 的会话事件随 conversations 轨导出与恢复，使换机/回滚后 RunGraph 的分支车道、子会话节点与回传节点无需重新运行即可重建。

## 3. 关键实现

- 导出：`listAll({scope:'branch', scopeId, limit:200})` 取最近 200 条后反转；用 `count` 判断是否截断。
- 文件结构：`{ schemaVersion: 1, truncated, events }`；事件保留 `scopeId/type/payload/createdAt`。
- 恢复：只接受 `scope='branch'` 且分支表存在的事件；`seq` 由仓储重新分配，数组顺序即事件顺序。
- 旧档缺 `branch-events.json`：按 0 处理，不告警、不阻断。
- 兼容：备份 schema 仍为 7，`LATEST_SCHEMA_VERSION` 不变。

## 4. 测试

```
pnpm exec vitest run packages/core/src/backup/__tests__/branch-backup.test.ts \
  packages/core/src/backup/export.test.ts packages/core/src/backup/restore.test.ts
```

结果：3 文件 / 21 用例通过。

新增断言：

1. 导出 manifest `branchEventCount=4`、`branchEventsTruncated=false`；
2. 恢复后 `branches=2`、`branchEvents=4`，`br-a` 3 条、`br-b` 1 条；
3. 旧档（无 branches/events 文件）恢复 `branchEvents=0`；
4. 指向缺失分支或非 branch scope 的事件整条跳过并计数。

## 5. 偏差与说明

- 单分支上限按 200 条截断，跨分支总数不设硬上限（受归档 500MB 上限约束）。
- 事件 `id` 在恢复后重新生成；对外标识以 `scopeId + seq` 为准，测试与图投影均不依赖原 id。
- 事件恢复不重建 FTS 之外的其他索引；`append` 已同步写 `session_events_fts`。
