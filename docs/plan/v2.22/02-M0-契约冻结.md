## 1. 备份：分支事件轨

### 1.1 manifest

`tracks.conversations` 增加两个可选字段（v7 内加法，不升版）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `branchEventCount` | `number?` | `branch-events.json` 事件条数；旧档缺省 0 |
| `branchEventsTruncated` | `boolean?` | 是否因单分支 200 条上限被截断 |

`backupPrecheck.tracks` 增加必填 `branchEvents: number`；旧档按 0。

### 1.2 `branch-events.json`

```json
{
  "schemaVersion": 1,
  "truncated": false,
  "events": [
    {
      "id": "e1",
      "scope": "branch",
      "scopeId": "br-1",
      "seq": 1,
      "type": "branch_created",
      "payload": {},
      "schemaVersion": 1,
      "createdAt": "2026-11-04T00:00:00.000Z"
    }
  ]
}
```

- 只导出 `scope='branch'` 的事件；`scopeId` 为分支 id。
- 每个分支最多导出**最近 200 条**，按 `seq` 升序写出；跨分支按 `createdAt` 升序。
- 任一分支被截断时 `truncated=true`，manifest 同步。
- 文件只在 conversations 轨导出时生成；分支数为 0 时仍写空数组（便于恢复端统一处理）。

### 1.3 恢复

- 顺序：会话 → 分支 → 分支事件。
- 事件仅当 `scopeId` 在 `conversation_branches` 中存在时恢复；缺失分支整条跳过并计数。
- 逐条经 `session_event_repo.append` 写入，由库重新分配 `seq`（保持数组内的先后顺序）；`createdAt` 保留原值。
- 旧档缺 `branch-events.json` → `imported.branchEvents=0`、`skipped.branchEvents=0`，不告警、不报错。
- 非法 JSON/非数组 → 按 0 处理，不阻断整档恢复。

## 2. 终态回传

| 终态 | `branch_status` | `branch_returned` | evidence.summary | evidence.usage | needsReview |
|---|---|---|---|---|---|
| `succeeded` | 写 | 写 | 运行结果摘要 | 真实用量 | `true` |
| `failed` | 写 | 写 | 错误摘要 | 真实用量 | `true` |
| `cancelled` | 写 | 写 | 空串 | 0 | `true` |
| `interrupted` | 写 | 写 | 空串 | 0 | `true` |
| `budget_exceeded` | 写 | 写 | 已产生内容截断摘要 | 真实用量 | `true` |

- 无运行结果的终态必须带 `statusReason`（取消原因/恢复中断/预算上限）。
- `evidence.artifacts` 尽力从子会话 `toolTrace` 提取；无产物为空数组。
- 父会话只展示 evidence 卡片，不插入消息；卡片对空摘要显示「无运行结果」。

## 3. 失败重试

- `POST /api/branches/{id}/retry`。
- 前置：分支必须处于终态（`succeeded/failed/cancelled/interrupted/budget_exceeded`）；`queued/running/waiting` 返回 422。
- 行为：以旧分支的 `parentConversationId`、`goal`、`title` 调用现有 `create`，`autoStart=true`；返回新分支与新子会话。
- 旧分支**不改状态、不删证据**；重试不绕过任何上限（并发/深度/子节点/预算照常校验）。
- 响应 `{ branch, conversation, childConversationId, retriedFrom }`。
- UI 按钮文案「重试」，并提示「重试将新建分支」。

## 4. 运行中预算熔断

- 准入阶段不变：预算不足 → 422，不创建/不启动。
- 结算阶段：`finalize` 拿到真实 `usage` 后，重算会话树已用量；若 `usedTokens + reservedTokens > tokenBudget`，将结果从 `succeeded` 改判 `budget_exceeded`，保留内容摘要与真实 usage。
- `statusReason` 形如 `会话树 Token 超限：已用 X / 上限 Y`；预留归零，写 `branch_status` + `branch_returned`。
- 本版不中途 abort 流式请求：编排器仅在 `done` 事件提供 usage。若后续 runner 提供增量 usage，再升级为实时熔断（不在本版范围）。

## 5. `waiting` 语义

- 状态枚举保留，用于兼容历史数据与备份。
- **不新增写入路径**：本版没有任何代码会把分支置为 `waiting`。
- 类型与文档标注「保留，无写入路径」；新增守卫测试断言运行器不产生该状态。
- 重启收敛仍处理 `running/waiting` → `interrupted`。

## 6. 实时帧

- 复用 v2.20 `runGraphLiveBus`；分支事件（`branch_created/branch_started/branch_status/branch_returned`）写入后发布对应根会话的图变更通知。
- 前端按 `seq` 去重；收到通知增量刷新，连续 3 次失败或页面隐藏时回落 10s 轮询。
- 不推送整图快照；chat/task/flow/meeting 实时化不在本版范围。

## 7. 验收口径

| 项 | 门禁 |
|---|---|
| 备份往返 | 分支事件导出→恢复后图车道/回传节点与导出前一致；旧档缺文件不报错 |
| 终态 | 五类终态均产生 evidence 与回传节点 |

| 熔断 | 超预算落 `budget_exceeded`，预留为 0 |
| 守卫 | `waiting` 无写入路径有测试守卫 |
| 兼容 | 零迁移；`pnpm check` 与全量测试通过 |
