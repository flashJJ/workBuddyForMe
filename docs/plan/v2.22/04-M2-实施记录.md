## 1. 目标

补齐分支的「结束交代」：中断/取消不再静默，失败可一键重试，运行超预算能收敛为明确终态；同时保持状态机与上限校验不变。

## 3. 关键实现

- **终态回传**：`cancel`（排队）构造空结果（`summary=''`、`usage=null`、`needsReview=true`）并写 `branch_status` + `branch_returned`；`recoverInterrupted` 同理。
- **预算熔断**：`finalize` 读取真实用量后，`usedTokens + reservedTokens > maxTreeTokens` 时把 `succeeded` 改判 `budget_exceeded`；`statusReason` 给出已用/上限，预留归零，evidence.status 同步。
- **重试**：API 层校验终态后调用现有 `create`（`autoStart=true`），不修改旧分支；上限/深度/预算校验全部复用 create。
- **`waiting` 守卫**：本版无写入路径，测试断言运行完成状态不为 `waiting`。

## 4. 测试

```
pnpm exec vitest run packages/core/src/branch                 # 3 文件 / 18 例
cd apps/web && pnpm exec vitest run src/app/api/branches src/features/branch  # 2 文件 / 5 例
```

新增断言：

1. 重启收敛（含 `waiting` 历史值）产生 2 条 `branch_returned` 且 evidence 为空结果；
2. 排队取消写 `branch_created → branch_status → branch_returned`，evidence `summary=''`；
3. 结算超预算改判 `budget_exceeded`，`reservedTokens=0`，写 1 条 `branch_returned`；
4. retry：queued 返回 422；cancelled 返回 201 且 `retriedFrom` 指向旧分支；旧分支仍 cancelled；`branchMaxChildren=1` 时返回 422。

## 5. 偏差与说明

- 熔断在**结算时**生效，不在流式过程中 abort：编排器只在 `done` 提供 usage。契约已注明，后续 runner 提供增量 usage 再升级。
- 重试逻辑放在 API 路由，不新增 core 服务方法：避免 core 服务重复实现 create 与上限校验。
- 重试的新分支标题沿用旧标题，允许重名；用户在面板可自行重命名。
- `BRANCH_TERMINAL_STATUSES` 为共享常量，API 与前端使用同一口径。
