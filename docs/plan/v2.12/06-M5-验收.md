## 3. 迁移与兼容

- **零迁移**：`packages/database/src/migrations` 无新增文件，末位仍为 `v040-capability-effects`；`LATEST_SCHEMA_VERSION` = 40。
- 旧库直开：取本机 v2.10/v2.11 时期数据库（`%USERPROFILE%\.workbuddy-for-me\db\wbfm.sqlite`，2026-10-23）复制后用当前 `createDatabase` 打开：`schemaVersion = 40`、70 张表、`capability_packs` / `messages` 可读，连续打开两次无异常。
- 回退口径：本版没有新增列与表，旧版本打开同一数据库不会遇到未知 schema；升级只更新 `capability_packs` 行内 `version` / `manifest_json` 等既有字段。
- 签名与策略落在 settings JSON，跟随既有设置导出/备份，不进数据库结构。

## 4. 与 M0 的偏差（汇总）

1. **过期清理时机**：M0 写「服务启动或首次健康检查」，实现放在 `POST /health/cleanup`，保持 `GET /health` 无副作用；用户点一次清理才移除 24h 残留。
2. **清理范围**：只处理目录；根目录散落文件不进入 `orphans`，也不被清理。
3. **升级不预览新版本号**：浏览器端不解压 ZIP，对话框只显示当前版本与回滚提示，成功后列表显示新版本。
4. **策略切换不预统计**：切到 `require` 只提示影响，不实时计算受影响的包数；可先做健康检查。
5. **清理入口只在健康报告后出现**：未点「检查全部」时不扫盘，避免页面加载即 IO。
6. **启用依赖复核**：依赖缺失/停用/版本不符均 422，状态保持 `disabled` 并写 `lastError`；从属包保留但无法启用。
7. **工作流回滚保留历史版本行**：回滚把旧版本重新置为 current/published，不删除升级新增的版本行。
8. **信任公钥整组保存**：走既有 `PUT /api/settings`，多标签页并发覆盖风险沿用设置页现状。
