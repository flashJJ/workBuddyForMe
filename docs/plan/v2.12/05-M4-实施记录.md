## 2. 关键实现

1. **管理页拆分**：行渲染、升级对话框、健康横幅各一文件，页面只保留查询、筛选、安装与编排；后续再加字段不会撞 300 行。
2. **健康状态映射**：`healthQuery` 初始不请求；点击后 `refetch`；结果按 id 映射到行徽章，未检查时不显示徽章。
3. **升级交互**：对话框内做 multipart 上传；成功后 `invalidate` 能力包与健康查询；错误统一提示「升级失败，已回滚或未变更」，不暴露内部堆栈。
4. **设置保存**：前端先做 keyId/名称/PEM 非空与重复 id、20 条上限校验；后端仍是最终裁决（PEM 必须可导入 Ed25519）。
5. **i18n 行数门禁**：签名设置文案独立到 `settings-work.ts` 的 `zhCapabilityTrust` / `enCapabilityTrust`，`settings.ts` 维持 300 行。

## 3. 与 M0 的偏差

1. **升级不预览新版本号**：浏览器端不解压 ZIP，对话框只显示「当前版本」与回滚提示；升级成功后列表显示新版本。M0 的「旧 → 新」预览简化为「当前版本 + 结果」。
2. **策略切换不预统计**：切到 `require` 只显示提示，不实时计算「当前 N 个包将不可用」；用户可先在管理页做健康检查。后续如需精确统计，可复用 health API。
3. **清理入口只在健康报告后出现**：未点击「检查全部」时看不到孤儿目录，避免页面加载即扫盘。
