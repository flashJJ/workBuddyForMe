# v2.34 方案：备份可续——增量归档与链式恢复

> 主题：全量基线可信、日常只导增量、迁移按链恢复并逐段核对。
> 分支：`feat/v2.34-incremental-backup`（待开发）
> 目标：零数据库迁移；备份 schema 由 8 升 9；增量是补量包，全量仍是迁移权威。

## 1. 背景与目标

v2.33 完成了「加密 → 预检 → 恢复 → 核对 → 回收」闭环，但备份的生命周期仍有两个断点：

- **每次都全量**：导出按轨道全量序列化，附件二进制与全部消息重复打包；备份越频繁、数据越多，成本线性增长。
- **基线不全**：全量导出存在静默上限——最多 10,000 个会话、每个会话最多 500 条消息；超出部分既不在归档里，也不在 manifest 中告警，与「可托付」直接冲突。
- **恢复只能单文件单次**：没有「基线 + 日常补量」的链概念，无法表达一段归档依赖哪一段，也无法在迁移前核对整条链是否完整。

v2.34 补三条链路：全量基线改为分页全量并记录真实条数；导出支持「自上次导出以来」的增量；前端多选归档按链预检、服务端校验顺序并逐段恢复，最终聚合核对。

## 2. 盘点结论

| 能力 | 现状 | 本版动作 |
|---|---|---|
| 基线完整性 | `export.ts` 会话 `list(undefined, 10_000)`、消息 `listByConversation(id, 500)`，超限静默丢弃 | 分页读取全部；manifest 记录真实消息数；超过 500MB 显式失败 |
| 增量水位 | manifest v8 无归档 id、类型、父链与时间水位 | manifest v9 增加 `archiveId/kind/chainId/sequence/parentArchiveId/startedAt/watermarks` |
| 增量选择 | 所有轨道都全量序列化 | 新行按 `created_at > since`；settings/skills 小快照；不携带修改与删除 |
| 链式预检 | 预检只接收一个 `file`，响应无链信息 | 预检响应增加 `chain`；前端多选、排序并校验连续性 |
| 链式恢复 | `restore-ops` 中会话已存在即整段跳过 | 增量模式允许向已有会话追加消息；服务端用 meta 链状态校验顺序 |
| 恢复核对 | v2.33 单次 `verification` | 逐段核对 + 链级合计（段数、序号、缺失段） |
| 备份登记 | `backup.lastExport` 存 `settings_kv`，会随设置轨导出 | 迁到 `meta`（`backup.history` / `backup.restoreChain`），不进入备份 |

## 3. 主题与边界

- 单一主题：备份可持续，不新增对话、记忆、能力或文档功能。
- 零数据库迁移：复用 `meta` 表保存导出历史与恢复链状态，`LATEST_SCHEMA_VERSION = 51` 不变。
- 备份 schema 由 8 升 9：v9 新字段均为可选，v8 归档仍按「单段全量」恢复；v8 客户端按版本拒绝 v9 归档。
- **增量语义**：只补 `since` 之后新创建的行，加上 settings/skills 两份小快照；既有行的修改、删除、文档重解析、记忆覆盖**不进入增量**。
- 全量仍是迁移与克隆的唯一权威；增量用于日常补量，UI 必须明示「只含新增，不含删除与修改」。
- 服务端不保存归档文件；链恢复由前端按 manifest 顺序逐段调用现有恢复接口，服务端只做顺序保护。
- 密码：同一链建议同一密码；每段独立 salt/iv；错密码在预检阶段拒绝。

## 4. 功能清单

### 4.1 全量基线完整性（P0）

- 会话与消息改为 keyset 分页（`created_at, id`）读取全部，取消 10,000 / 500 静默上限。
- manifest v9 增加 `tracks.conversations.messageCount`；预检与核对接真实消息数比对（v8 归档缺该字段时回退会话数）。
- 归档仍受 `BACKUP_MAX_ARCHIVE_BYTES`（500MB）保护：超过上限直接失败并给出可读错误，不产出半份文件。
- 导出开始即记录 `startedAt`，作为下一段增量的 `since` 下界；宁可重复（主键幂等吸收），不可遗漏。

### 4.2 增量归档（P1）

- `backupExportRequestSchema` 增加可选 `mode: 'full' | 'incremental'`，默认 `full`。
- manifest v9 字段：
  - `archiveId`、`chainId`、`sequence`（全量固定 0）、`kind`、`parentArchiveId?`、`startedAt`；
  - `watermarks?`：每轨实际最大 `created_at`，仅作审计，不作为下一段下界。
- 增量选择规则：

| 轨道 | 增量内容 | 依据 |
|---|---|---|
| conversations | 新会话 + 已有会话中的新消息 | 会话/消息 `created_at > since` |
| knowledge | 新知识库、新文档与新分片 | `created_at > since` |
| attachments | 新附件行 + 对应二进制 | `created_at > since` |
| tasks | 新运行/步骤/事件/协作运行/交接 | `created_at > since` |
| emotion | 新状态 + 新情绪事件 | `created_at > since` |
| events | 新助手/角色卡/提醒/触发器/场景/会议/里程碑/记忆/流水 | `created_at > since` |
| settings | 全量快照（小表，upsert） | 不适用 |
| skills | 全量快照（skill.json + states，upsert） | 不适用 |

- 无全量基线（`meta backup.history` 为空，或链尾不是同链全量起点）时拒绝增量，返回 `VALIDATION_ERROR`；前端禁用增量并提示先做全量。
- 链长达到 20 段时要求「重新全量」，全量导出开启新链。
- 空增量仍产出归档（保持链连续），报告标明各轨新增 0，UI 提示「没有新增数据」。
- 导出登记写入 `meta`：
  - `backup.history`：最近 20 段（archiveId/chainId/sequence/kind/at/startedAt/tracks/totalBytes/encrypted）；
  - `backup.lastExport`：兼容 v2.33 读取，存在旧值时首次写入后迁移到 meta。

### 4.3 链式预检与恢复（P1）

- 预检响应增加 `chain`：`archiveId/kind/chainId/sequence/parentArchiveId/since`；单文件旧流程不变。
- 前端多选最多 20 个归档，按 `sequence` 排序并校验：
  - 恰好一段 `full` 且 `sequence = 0`；
  - 增量段序号连续、`parentArchiveId` 等于上一段 `archiveId`、`chainId` 一致；
  - 同一链不得出现重复序号。
- 校验失败返回 `BACKUP_CHAIN_INCOMPLETE`（缺基线/缺段）或 `BACKUP_CHAIN_MISMATCH`（跨链/父指针不符），预检阶段就地提示，不进入恢复。
- 恢复仍逐段调用 `/api/backup/restore`（单文件，内存峰值不叠加）：
  - 服务端解析 manifest 后：`full` 总是允许并重置 `meta backup.restoreChain`；`incremental` 要求 `restoreChain` 的 chainId/sequence/archiveId 与 `parentArchiveId` 对得上，否则拒绝。
  - 新增增量恢复分支：会话已存在时不再整段跳过，逐条 `INSERT OR IGNORE` 新消息，会话标题/时间不改；其余轨道沿用现幂等写入。
  - 每段成功后更新 `restoreChain`；中途失败保留已完成段，UI 标出失败段并支持「从该段重试」。
- 恢复核对按段聚合：逐段声明 vs 写入/跳过、缺失附件、未引用附件；新增链级摘要（段数、序号、缺失段），差异只告警不阻断。

### 4.4 前端与迁移引导（P2）

- 导出面板：全量/增量切换；显示上次全量与当前链尾；无基线时禁用增量；文件名带 `-s<seq>`；增量提示「只含新增，不含删除与修改」。
- 恢复面板：多选归档、链时间线、逐段进度、失败段重试、聚合核对卡片；密码一次输入应用到所有段。
- 设置页「备份历史」：最近 20 段（时间/类型/链/大小/加密/轨数），只读。
- 迁移清单（UI 文案 + 文档）：先全量 → 预检 → 按链恢复 → 核对 → 重建知识向量 → 重填凭证；强调迁移必须用全量。

## 5. Non-Goals

- 删除与修改的增量同步（tombstone、软删、变更日志）——需要全表变更追踪与冲突策略，放入 v2.35 评估。
- 自动定时备份、云同步、服务端归档托管与自动清理。
- 恢复演练（隔离临时库）——v2.35 候选。
- 附件合并视图与去重策略调整（v2.33 引用计数继续作为数据基础）。
- 向量、模型文件、日志备份。
- 跨链合并、分叉链、单段去重。

## 6. 阶段拆分

| 阶段 | 内容 | 验证 |
|---|---|---|
| P0-M1 | 基线分页全量 + manifest v9 + meta 备份登记 | 导出条数与库内一致；500MB 显式失败；v8 归档仍可恢复 |
| P1-M2 | 增量选择器 + 水位 + 导出模式 + 前端切换 | 增量只含 since 后新行；无基线拒绝；空增量可登记 |
| P1-M3 | 链预检/恢复 + 已有会话追消息 + 聚合核对 | 完整链恢复计数吻合；缺段/跨链拒绝；重复恢复幂等 |
| P2-M4 | 多文件 UI + 历史卡片 + 迁移引导 + 验收 | 链时间线/失败重试可用；中英 i18n；门禁全绿 |

## 7. 验收口径

1. 基线完整性：1,001 条消息的会话导出 1,001 条；10,001 个会话不被截断；manifest 真实计数与归档一致；超过 500MB 导出失败且不产生文件。
2. 增量：无基线时拒绝；增量只含 `since` 后新行；连续两次增量第二次为空；settings/skills 以快照写入；删除与修改不出现在增量。
3. 链：完整链（0..N）可预检并逐段恢复；缺基线/缺中间段/跨链分别返回对应错误码；重复恢复幂等；v8 归档按单段基线恢复。
4. 会话追加：增量中的新消息能写入已有会话；既有会话标题/时间不被覆盖；新会话正常创建。
5. 核对：逐段声明 vs 写入/跳过可读；链级合计正确；缺失附件与未引用附件可见；差异不阻断。
6. 登记：`meta backup.history` 最多 20 段且不随备份导出；链状态重启后仍生效；设置轨恢复不会带回其他机器的链状态。
7. 工程门禁：`pnpm check` 通过；core / web / database / shared / config / ai / voice / desktop 测试全绿；`LATEST_SCHEMA_VERSION = 51`，备份 schema 为 9。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 用户把增量当克隆 | UI 与文档明示「只补新增，不含删除/修改」；迁移强制全量；核对展示跳过数 |
| 水位竞态漏行 | `since` 取父段 `startedAt` 而非完成时间；重叠由主键幂等吸收 |
| 已有会话追消息破坏全量语义 | 仅增量模式启用追加分支；全量恢复行为不变，测试双覆盖 |
| 链状态丢失/错位 | `restoreChain` 存 `meta`；缺前置段拒绝；重放全量可重置链 |
| 大归档/长链内存 | 单段 500MB、链最多 20 段、逐段恢复；不一次上传多段；超限前置拒绝 |
| 设置轨带回链状态 | 链状态与历史存 `meta`，不进入任何备份轨 |
| v8 客户端读 v9 | schema 升 9，旧端按版本拒绝并提示升级；v9 端兼容 v8 |

## 9. 下一版本衔接

v2.34 完成后，备份具备「全量基线 → 增量补量 → 链式恢复 → 逐段核对」的可持续闭环。

v2.35 候选：删除/修改增量（tombstone / 变更日志）、恢复演练（隔离临时库）、附件合并视图、本地定时备份计划。
