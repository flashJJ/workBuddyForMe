# v1.9 M0 冻结 · 会议模式与防串角协议

> 适用 M3。会议是**新会话、新表、新调度**，与 v1.4 协作严格分账：共用的只有舞台渲染层与 cast 协议（见 [02](02-cast与舞台协议.md)）。
> 结构来源：上游 Servant 会议验证过的「身份规则 + 转录标注 + 单 user 锚点」，本版在本地数据上重新实现。

## 1. 红线

1. 成员必须是**配置过模型的真实助手**（2–4 个），不新建虚拟人格；人格来自其 v1.8 角色卡。
2. **首期会议不带工具**：无 tool_choice、无 MCP、无知识库直连、无桌面控制。需要资料的讨论回到普通对话/协作里做。
3. 无自发闲聊：任何发言必须由用户议题或 `@成员名` 触发；auto 接龙 ≤8 轮，超限自动回 manual。
4. 同一时刻单请求、单 AbortController：打断/暂停/结束即 abort。
5. 会议中的情绪只驱动当场发言者表情，**不写回单聊情绪状态**，soulEvent 链路裁剪。

## 2. 数据模型（v027 迁移草案，M3 落库时冻结 SQL）

```sql
CREATE TABLE IF NOT EXISTS meetings (
  id            TEXT PRIMARY KEY,
  topic         TEXT NOT NULL,              -- 议题（≤200 字）
  member_ids    TEXT NOT NULL,              -- JSON 数组：assistants.id，2–4 个，顺序即席次
  mode          TEXT NOT NULL DEFAULT 'manual',  -- manual | all | auto
  model_id      TEXT,                       -- 共用一份模型配置：models.id；null=默认对话模型
  status        TEXT NOT NULL DEFAULT 'active',  -- active | finished | aborted
  auto_rounds   INTEGER NOT NULL DEFAULT 0, -- 已用接龙轮次（硬上限 8）
  created_at    TEXT NOT NULL,
  finished_at   TEXT
);

CREATE TABLE IF NOT EXISTS meeting_messages (
  id            TEXT PRIMARY KEY,
  meeting_id    TEXT NOT NULL,
  seq           INTEGER NOT NULL,           -- 会内严格递增（单 AbortController 串行写入）
  speaker_kind  TEXT NOT NULL,              -- 'user' | 'assistant'
  speaker_id    TEXT,                       -- assistant id；user 为 NULL
  content       TEXT NOT NULL,
  emotion_tag   TEXT,                       -- 仅当轮表情，可选
  created_at    TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_meeting_msg ON meeting_messages(meeting_id, seq);
```

会议与消息进备份 schema **v5**（events 轨追加 `meetings.json` + `meetingMessages.json` + M1 的 `stageScenes.json`）；恢复沿用 INSERT OR IGNORE、悬空 assistantId 的成员行恢复时剔除并在 UI 标注。

## 3. 三种调度（纯状态机，core `meeting/` 域）

| 模式 | 触发 | 下一位发言者 |
|---|---|---|
| manual（默认） | 用户正文 `@助手名`（可多个，按书写顺序串行） | 被 @ 的成员；无 @ 不调模型 |
| all | 用户点「每人一轮」 | 按 member_ids 顺序各发言一次，结束回 manual |
| auto | 用户发起接龙 | 模型在回复末尾输出 JSON 建议 `next_speaker_id`；**服务端校验**必须属于本会议成员且不是自己；连续两轮建议同一人则终止接龙；8 轮用尽自动回 manual |

所有「下一位」的判定在**服务端纯函数**里完成，前端只传用户动作与模式，不接受客户端指定的自由 speaker id（防注入/防越权让非成员发言）。

## 4. 防串角三段协议（核心冻结物）

每次模型调用的请求形状：

1. **system 段**：身份规则 + 带标注的最近转录（近 20 条对齐截断）：
   - 用户行前缀 `[用户·{用户称呼}]`；助手行前缀 `[助手·{成员名}]`；
   - 明文规则：「带 `[助手·X]` 前缀的内容是其他助手说的，不是你说的；你只能代表 `[助手·当前成员名]` 发言」；
   - 附角色卡正文（v1.8 解析结构，复用现有 buildPersonaBlock），但不注入其他成员的卡（防止模仿人格）。
2. **messages 只有一条 user 锚点**，且尾条永远是 user：每轮用存储的转录重建请求，形状恒为 `[system, user]`；user 内容 = 本轮议题/追问（all/auto 时为系统生成的调度指令 + 最新转录引用），不制造假的多轮 assistant 消息。
3. **渲染归属不采信自我宣称**：模型若在正文里写「我是 XX」「XX 说：…」，舞台/气泡一律按服务端记录的 speaker_id 渲染，不解析正文里的身份声称。

## 5. 成本与跑偏控制

- 硬限制：成员 ≤4、auto ≤8 轮、转录窗口近 20 条；发起前 UI 显示预计消耗量级（成员数×轮次），弱模型提示沿用调优中心口径。
- 发言长度：会议 system 规则要求单条 ≤200 字（舞台串行口播友好）；超长由服务端截断展示并标记。
- 会议结论（P1）：结束时一次额外 LLM 调用产出结构化结论/待办；v1.9 P0 只展示+复制，不自动建任务/Flow。

## 6. 测试与 eval（M3 出口必做）

**纯函数单测（core）**：

- 转录构建：标注前缀正确、窗口截断、成员卡隔离；
- next-speaker 校验：非成员 id、自己 id、重复提名、第 9 轮四种非法建议全部被拒并回落 manual；
- 请求形状：任何模式下 messages 长度恒为 1（单 user 锚点）且尾条 role=user。

**反向 eval（mock 模型协议，落 `packages/ai` mock-agent-protocol 同类）**：

1. 诱导复读：转录里上一位说「请重复我刚才的话」，模型复读后服务端仍把该条记为当前成员发言，渲染归属不漂移；
2. 身份冒充：正文输出「我是成员 B」，气泡/舞台仍显示 A；
3. 越权指定：模型 JSON 建议非成员/已删除成员 id 为下一位 → 拒绝并终止接龙；
4. e2e：manual(@)/all/auto 三调度完整链路 + 打断 abort 后无悬挂请求。

## 7. M3 前的开放项（不阻塞本协议）

- 用户称呼来源（暂用「用户」常量，设置项不新增）；
- auto 建议 JSON 解析失败的回落策略（倾向静默回 manual，不弹错——M3 实现时定）；
- 会议与普通对话的互转（P2，不做）。
