# v1.9 M0 · 多实例 Live2D 性能 spike 报告

- 取证时间：2026-10-14
- 原始数据：[spike-result.json](spike-result.json)（工装自动落盘，含完整环境与逐场景指标）
- 被测代码：v1.8.0 封版生产构建（`next build` + `next start`），未为 spike 改动任何渲染代码

## 1. 关卡问题（G1）

全屏舞台最多 3 个 Live2D 同页（左/中/右三角色），每个都要同时驱动**待机微动作、表情、口型**。关卡要求：同页 3 实例的真机帧率/内存报告；不达标即按方案 C（非发言者静态立绘、仅当前发言者 Live2D）实施。

## 2. 测量方法

- **工装**：env 门控路由 `/spike/live2d-stage`（`WBFM_SPIKE=1`），复用产品代码 `Live2dController`（PIXI v7 + pixi-live2d-display 0.4.0 / Cubism4），每个实例一个 `PIXI.Application`，与未来舞台的挂载方式一致。
- **负载**：控制器内置 7–14s 随机待机动作 + 每 3s 表情轮换（neutral/joy/sadness/anger）+ 每帧正弦口型电平（三实例相位错开 2π/3，模拟交替发言）。
- **场景**：C0 空页基线 → C1 单实例（方案 C 上界）→ C3 三实例（方案 A）；每场景挂载预热 12s（含模型下载/实例化/首动作稳定）、实测 15s、卸载 3s。
- **采集**：页面侧单个 rAF 采样器记录全部帧间隔（与 PIXI ticker 共享主线程，口径等同用户所见帧率），剔除 >1s 的切窗帧；`performance.memory` 每秒采 JS 堆。
- **运行器**：Playwright 驱动 **headed Chromium 153**（与 Electron 同一 Chromium 渲染管线），窗口 1920×1080、DPR=1。

## 5. 解读

1. **增量成本极低**：1→3 实例，P50 帧耗 4.3→8.3ms（多两个模型仅 +4ms 主线程），JS 堆 +5MB 且起≈止、15s 内无单调增长（无泄漏迹象）。模型加载是一次性成本（已计入 12s 预热）。
2. **60Hz 目标屏满帧**：三个场景的最大帧耗 16.9ms、P99 16.7ms，且**没有任何一帧超过 33.2ms**——在主流 60Hz 屏（16.7ms 预算）上等于锁 60fps；本机 240Hz 下呈现「多数 4.3ms + 周期性 16.7ms」的双峰（Cubism 物理/动作按自身节拍更新），1% low 仍有 59.7。
3. **GPU 是核显而非独显**：ANGLE 跑在 Intel 核显上仍达标，对「核显本」有一定代表性；但这是高端移动/桌面级新核显，**老款低端核显与集显未覆盖**（见局限）。

## 6. 拍板：方案 A 为默认，方案 C 作为内置降级档（不是废弃方案）

- **M1–M3 默认按方案 A 实施**：三角色全部 Live2D 同页。
- **方案 C 必须在 M1 一并落地为「省电模式」**，两条触发路径：
  1. 用户手动开关（沿用概念稿 §6 承诺）；
  2. **帧率看门狗自动降级**：运行期连续 N 秒（建议 N=5）平均帧耗 >25ms（低于 40fps）时自动切立绘并提示，不允许画面悄悄卡顿。
- 方案 C 形态：非发言角色用当前表情立绘（模型表情截图或预渲染静态帧），仅当前发言者保留 Live2D；切换由舞台渲染层内部完成，cast 协议与上层无感知。
- 立绘资产策略在 M1 冻结：优先运行时截图缓存（不新增分发资产、不踩 Cubism 素材红线），具体技术选型 M1 出 spike 子报告。

## 7. 局限与 M4 前必须补的取证

1. **不是 Electron 全屏实测**：headed Chromium 与 Electron 同渲染管线、canvas 像素尺寸按槽位固定（与全屏一致），但合成器/窗口管理器开销有差异；M4 真机报告需在 Electron 全屏 1080p 下复测同一工装。
2. **低端机未测**：M4 前至少补一台老核显/低端独显真机数据；不达标则把默认改为方案 C、A 作为手动高性能档。
3. **未测极端并发动作**：三人同时 Tap 大动作/语音流密集期未覆盖；M2 协作舞台适配真实 run 时观察真实动作密度，必要时给非发言者的大动作降频。
4. **GPU 进程内存未采集**：`performance.memory` 只覆盖 JS 堆；纹理/GPU 内存用 Electron `process.getProcessMemoryInfo()` 在 M4 真机报告补。
5. rAF 采样器自身占一个回调，但其成本在 C0 基线（4.3ms）中已被包含，相对比较结论不受影响。

## 8. M1 性能验收门槛（写入 M1 出口）

- 舞台骨架在本机（同环境）3 实例：P99 帧耗 ≤20ms、>33.2ms 帧占比 0%；
- 省电档（方案 C）：仅 1 个 PIXI.Application 存活，另两槽为 `<img>`/静态纹理，DOM 中无残留 canvas；
- 关窗/卸载后 3 秒内 rAF 与 PIXI ticker 全部停止（dispose 验证，复用控制器既有 `dispose()`）。
