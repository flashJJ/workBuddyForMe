# v2.31 方案：记忆成图——关系边、一跳召回与空闲整理

> 主题：让记忆之间有关系，召回能沿关系走一跳，重复与同义记忆能自己收敛。
> 分支：`feat/v2.31-memory-graph`
> 目标：一次纯加法迁移、零接口破坏、单一主题。

## 1. 背景与目标

v2.26 把长期记忆做成「双时态事实 + 混合召回」，v2.28 补上统计、审计轮转与约束撤销，但记忆之间仍是孤立行：

- `memories` 只有 `subject_key / content / kind`，无法表达「同一回合提到的两件事」「同一消息里给出的两个人」；
- 召回只取与当前问题相似的 3 条，无法沿已命中的记忆取一跳上下文，跨记忆综合类问题仍靠单跳碰运气；
- 写入后没有空闲整理：同义 `subject_key`、重复内容、悬空关系只能等下次抽取碰运气合并。

本版目标：**关系可用、召回可走一跳、整理可回滚。** 全部落在 SQLite 与规则层，不引入图数据库，不改变现有召回权重。

## 2. 盘点结论

| 来源 | 未交付项 | 本版取舍 |
|---|---|---|
| v2.26 §9 / 候选 01 A | 关系边表 + 一跳注入 | 纳入 P0/P1，规则优先、低噪声 |
| 候选 01 C | 空闲整理（同义主体、重复内容） | 纳入 P1，只归档不删除 |
| 候选 01 B | 社区聚类与主题簇摘要 | 永久 Non-Goal：参数难解释，收益不可验收 |
| v2.26 / v2.28 | LLM 关系抽取、召回权重调整 | Non-Goal：需独立评测集，先验证规则边 |
| v2.28 | 线上评测看板 | Non-Goal：沿用本地 `pnpm memory:eval` |
| v2.28 / v2.29 | 跨设备同步 | Non-Goal：与本地优先宪法冲突 |

结论：只补「已有记忆数据之间的关系」，不扩大记忆来源，不引入模型调用，不新增前端可视化依赖。

## 3. 主题与边界

一句话：**已有的事实要连得起来，连起来的上下文要能进提示词，重复的事实要能自己退场。**

- 关系：只记录可解释的来源关系（同一回合、同一消息），不猜测语义关系。
- 召回：一跳扩展最多 2 条，总数仍为 `MEMORY_TOP_K = 3`，置顶配额不变。
- 整理：只归档（`status = archived`）与清理派生边，不物理删除记忆行，可人工恢复。
- 观测：设置页只展示计数与最近一次整理结果，不做图谱画布。

## 4. 功能清单

### 4.1 关系边模型（P0）

- 迁移 **v050 纯加法** 新增 `memory_edges`：
  - `id TEXT PRIMARY KEY`、`from_id TEXT NOT NULL`、`to_id TEXT NOT NULL`；
  - `relation TEXT NOT NULL`（本版只写 `same_source`；`co_turn` 仅保留枚举，后续跨消息同回合写入时再启用）；
  - `weight REAL NOT NULL`、`created_at TEXT NOT NULL`；
  - `UNIQUE(from_id, to_id, relation)`，并为 `from_id`、`to_id` 各建索引；
  - 不建外键：记忆归档后边保留，由查询侧 `JOIN memories` 过滤，整理任务负责清理悬空边。
- 边是**派生数据**：可重建、可删除，不进入备份的强一致范围（备份轨沿用现有记忆轨，边在恢复后按现有记忆重建或留空）。
- 新增仓储方法：`link(edges)`、`listNeighbors(seedIds, { assistantId, now })`、`deleteForMemory(id)`、`deleteAll()`、`deleteDangling()`、`count()`。

### 4.2 边抽取（P0）

- 在回合记忆落库后执行，零模型成本：
  - 同一助手消息抽出的多条记忆 → `same_source`，权重 `0.8`；
  - 同一回合跨多条消息的 `co_turn`（权重 `0.65`）只在常量与仓储枚举中预留：当前每回合只调用一次抽取，且约束类不建边，暂不产生该关系；
  - 同一对记忆已有更高权重边时不重复写，权重低者跳过。
- 只为 `status = active` 的记忆建边；约束类（`kind = 'constraint'`）不参与建边，避免把置顶规则拉进邻居扩展。
- 边写入失败只告警，不影响记忆落库与回合完成。

### 4.3 一跳召回（P1）

- `memory.recall` 在现有「向量 + FTS 融合 → 过滤 → 置顶补充」之后追加一步：
  1. 取当前候选里分数最高的 2 条作为种子；
  2. 查询它们的边，取对端记忆（必须 active、通过 scope / TTL 过滤、非 constraint）；
  3. 邻居分数 = `种子分数 × 边权重`，低于 `MEMORY_RECALL_MIN_SCORE` 丢弃；
  4. 邻居去重后最多 2 条，与普通候选一起排序；
  5. 最终仍取 `MEMORY_TOP_K = 3` 条，置顶 / 约束仍优先占位。
- `RecalledMemory.reason` 新增 `neighbor`；提示词中邻居条目附带「关联自：{种子内容摘要}」，让模型知道为什么出现。
- 邻居召回计入 v2.28 已有的召回计数；新增 meta 键记录邻居命中次数，供设置页展示。
- 无嵌入模型时同样生效（纯关键词候选也能扩展），不新增网络请求。

### 4.4 空闲整理（P1）

- 触发：设置页「整理记忆」手动触发 + 启动后异步一次、此后每 24 小时一次；单飞锁，失败只告警。
- 三步纯规则整理：
  1. **同义主体归一**：同 scope 下 `subject_key` 去空白、全角转半角、大小写归一后相同但原值不同，统一到出现次数最多的写法；
  2. **重复内容归档**：归一空白与标点后内容完全一致时，保留 importance 高、最近确认的一条，其余置为 `archived`（本版不引入嵌入距离阈值，避免新增模型调用）；
  3. **悬空边清理**：端点不存在或已归档的边直接删除（派生数据，无需归档）。
- 每次整理写一条 `consolidate` 审计（`actor = 'system'`），记录扫描数、归档数、合并主体数、清理边数；不写模型调用。
- 被归档的记忆仍可在记忆管理页恢复；恢复后不自动补边，等待下一次整理或新回合建边。

### 4.5 可观测（P2）

- 设置页记忆统计卡新增三项：关系边总数、邻居召回次数、上次整理时间与结果摘要。
- `pnpm memory:eval` 的 golden set 增加 4 条「需要邻居才能命中」的用例，报告新增 `neighborHits` 字段；仍只写本地文件，不进 CI 必过项。
- 不新增图谱可视化页面；只在召回理由与统计中体现图的存在。

## 5. Non-Goals

- 不引入图数据库、图遍历 DSL 或社区聚类（候选 01 B 永久关闭）。
- 不做 LLM 关系抽取、指代消解与命名实体识别；边只来自回合与消息归属。
- 不做记忆图谱画布、节点拖拽或主题簇摘要。
- 不改变现有召回权重（`0.55 / 0.20 / 0.15 / 0.10`）与 `MEMORY_TOP_K`。
- 不做跨设备同步、云端图存储、线上评测看板。
- 不做记忆物理删除；整理只归档。
- 不新增记忆来源类型，不改记忆管理页既有交互范式。

## 6. 阶段拆分

| 阶段 | 内容 | 交付物 |
|---|---|---|
| P0-M1 | 迁移 v050 + 边仓储 + 回合建边 | 迁移、仓储与单测 |
| P1-M2 | 一跳召回（种子、邻居打分、`neighbor` 理由、提示词关联说明） | 召回单测、快照断言 |
| P1-M3 | 空闲整理（三步规则、调度、审计、设置页手动入口） | 整理纯函数、调度与组件测试 |
| P2-M4 | 统计卡三项 + `memory:eval` 邻居用例与报告字段 | 界面、报告样例 |
| 收尾 | 发行说明、路线图状态、博客 10 篇 | `docs/roadmap/v2.31-release-notes.md` |

顺序理由：先有边才有一跳，先有一跳才有邻居指标；整理依赖边模型稳定后再做，避免一边建边一边删边；观测最后补，避免为未定型的指标改界面。

## 7. 验收口径

1. 旧库升级执行 v050 后 `memory_edges` 存在，既有记忆不受影响；无记忆时不产生空表写入。
2. 同一消息抽出的两条记忆产生 `same_source` 边，重复抽取不产生重复边；`co_turn` 本版不写入。
3. 召回结果总数仍 ≤ 3；邻居最多 2 条，理由为 `neighbor`，提示词包含「关联自」说明。
4. 置顶与约束仍优先占位，邻居不挤占 `MEMORY_PINNED_LIMIT`。
5. 整理只归档重复/同义记忆，不物理删除；审计含扫描数、归档数、合并主体数与清理边数。
6. 悬空边在整理后清零；已归档记忆不再出现在邻居结果中。
7. 设置页展示边数、邻居召回次数与上次整理结果；`pnpm memory:eval` 输出 `neighborHits`。
8. `pnpm check`（typecheck / lint / 300 行 / 目录预算 / 循环 / ASCII）与 `pnpm test` 全绿；i18n 中英键成对。
9. 发行说明、路线图索引、博客 10 篇同版本收尾。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 边噪声把无关记忆带进提示词 | 只保留来源关系（同消息 / 同回合），权重与分数下限双重过滤，邻居上限 2 |
| 邻居挤占记忆预算 | 总数仍为 3，置顶优先，邻居只参与普通候选排序 |
| 整理误归档 | 只归档不删除，写审计，可恢复；重复判定只做正文归一后完全一致，不做模糊匹配 |
| 启动整理拖慢首轮 | 启动后异步执行，单飞锁，与 24 小时间隔复用 v2.28 轮转调度形状 |
| 旧归档恢复后无边 | 边视为派生数据，恢复后按现有记忆重建或在下一回合自然补齐，不阻塞恢复 |
| 迁移体量 | 纯建表 + 索引，不回填、不改既有列 |
