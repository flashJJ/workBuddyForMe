# v4.8 版本总结：对话上下文有策略

> 版本：4.8.0 / 4.8.1（随 v4.10.0 批量发布）
> 主题：意图路由、按意图装配、压缩事件化、记忆一等意图与本地观测
> 分支：`feat/v4.8-context-intelligence`
> 迁移：无数据库迁移；新增事件类型与设置项。
> 博客：[blog/v4.8](../../blog/v4.8/) 7 篇。

## 1. 本版解决什么

v4.7 解决的是任务侧上下文；对话侧仍是一套固定策略：

1. 所有轮次同一套装配，闲聊也检索、也召回记忆；
2. 追问时最近原文容易被摘要与事实挤掉；
3. 压缩只在回合后 70% 触发，当轮撞墙只能硬截断；
4. 摘要写回没有事件，无法回放「当时为什么这样压缩」；
5. 用户说「记住 / 忘掉」没有显式通道与审计；
6. 本地看不到上下文构成，只能依赖外部 trace。

v4.8 把对话侧从「零散能力」收成一条可解释链路：意图 → 策略 → 装配 → 压缩事件 → 本地面板。

## 2. 里程碑结果

| 阶段 | 结果 |
|---|---|
| M0 契约 | `TurnIntent`、`ContextPlan`、`context_condensed` / `context_snapshot` schema；压缩阈值与预判开关 |
| M1 意图路由 | 规则 + 可插拔小模型分类器；`turn_intent` 事件；低置信度回退默认 |
| M2 混合装配 | 按意图覆盖 TAIL / MIDDLE / MEMORY / EVIDENCE 配额；追问优先保留最近原文 |
| M3 压缩事件化 | 70% 阈值、85% 预判、模型切换、用户显式四种触发；失败写降级事件 |
| M4 记忆治理 | 「记住」写事实、「忘掉」软归档并写审计；冲突保留双方 |
| M5 观测与评测 | `context_snapshot` 事件、上下文面板、`eval-context` 9 用例 |

## 3. 关键设计

### 3.1 意图只加资源，不减资源

意图类型：`chitchat / knowledge / follow_up / tool_task / clarify / memory_write / reminder`。

- 规则优先：关键词、是否带附件、是否引用上轮、消息长度、是否含 URL/路径；
- 小模型只在规则无命中且已配置时调用，超时或失败回退规则；
- 置信度低于 0.6 时走默认策略，不因为误判而关闭检索或工具。

这条约束很重要：上下文策略可以因为意图变得更好，但不能因为意图误判变得更差。

### 3.2 配额是意图的显式表达

| 意图 | TAIL | MIDDLE | MEMORY | EVIDENCE |
|---|---|---|---|---|
| follow_up | 60% | 15% | 10% | 15% |
| knowledge | 35% | 15% | 10% | 40% |
| tool_task | 40% | 15% | 10% | 35% |
| 默认 | 50% | 25% | 10% | 15% |

`ContextPlan` 是纯函数：输入意图、窗口与历史估算，输出配额、裁剪顺序与是否需要预判压缩。对话侧先接入，v4.9 再复用到协作、任务与 Flow。

### 3.3 压缩从「动作」变成「事件」

`context_condensed` 记录触发原因、被折叠消息 id、合并摘要、结构化事实、前后 token 与保真缺失项。

- `conversations.summary/summary_turns` 仍是读取投影；
- 事件是审计真源，原文可按消息 id 读回；
- 摘要失败写 `degraded: true`，不阻断回答。

触发时机从单一的回合后 70% 扩展到：

- `threshold`：回合后阈值；
- `preflight`：装配前估算 >85%，先压缩再请求；
- `model_change`：切换小窗口模型；
- `user_explicit`：面板手动压缩。

### 3.4 记忆写入有一等意图

「记住」写入 `constraint` 或 `fact`，带 subjectKey、来源消息与重要度；重复命中时合并。「忘掉」走软归档，写审计事件，可恢复。

冲突不静默覆盖：同 key 保留双方并标注 superseded，用户可在记忆面板追溯来源。

### 3.5 本地观测不依赖外部 trace

`context_snapshot` 存块 token 统计、保留/丢弃条数，不存正文；对话顶栏的上下文面板读取 `/api/events`，展示最近意图、装配快照与压缩记录，并提供「立即压缩」。

面板只做客户端汇总，不新增索引表；事件仍沿用 180 天保留。

## 4. 数据与验证

- 门禁：`pnpm typecheck`、`pnpm check:lines`、`pnpm check:ascii` 通过。
- 离线评测：`pnpm eval:context` 9 用例通过；`pnpm eval:agent` 不受影响。
- 真机（DeepSeek 大窗口 + 本地 7B 4096）：

| 场景 | 证据 |
|---|---|
| 大窗口长对话 | 5 轮，意图序列 `memory_write → follow_up ×3 → knowledge`；快照 `historyTokens=2605 / kept=9` |
| 手动压缩保真 | `user_explicit`，折叠最早 6 条，`2620→2392`；压缩后代号/端口/负责人仍正确 |
| 模型切换预判 | 大窗口积累 4103 tokens 后切 7B：`model_change`，`4237→1580`；7B 依据摘要仍答对关键数字 |
| 上下文面板 | 意图、快照与压缩记录正常展示 |

### 4.1 v4.8.1 小窗口修复

真机发现 4096 窗口下固定块吃光历史预算（`historyBudget=0`）。修复：

- 输出预留改为窗口比例 `clamp(窗口 × 15%, 512, 2048)`，上次 completion 校准受 40% 窗口上限约束；
- 原文预算低于 512 时先裁技能提示块与技能工具声明，再重装；
- 窗口 < `SMALL_CONTEXT_WINDOW_TOKENS` 时跳过 JSON 摘要抽取与保真重试，直接走纯文本摘要。

实测 4096 / 7B：`system 1721→378`、`tools 1030→0`、`reserve 2048→552`、`historyBudget 0→1843`，单轮 `promptTokens 3330→497`。

## 5. 已知限制

- 意图分类器默认关闭，开启后多一次小模型调用；超时回退规则。
- 预判压缩只在 85% 高水位触发，会增加一次摘要调用，可在调优中心关闭。
- 话题切换只记录信号，不自动压缩。
- 评测脚本做结构化断言；mock 模型不回放历史语义，压缩后的语义保真依赖真机验收。
- 面板读取最多 500 条事件做客户端汇总，不做独立索引表。
- 不统一对话与任务两套装配，留待 v4.9。

## 6. 下一步

v4.9 把 v4.8 的对话侧能力下沉为「场景策略 + 预算 + 快照」三层公共件，接入协作、桌面任务与 Flow；不重写对话侧策略，也不做全量 Controller Pipeline。
