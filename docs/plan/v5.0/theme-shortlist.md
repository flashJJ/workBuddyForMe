## 2. 主题 A：「会兜底」

**一句话**：让本地自动化跑得住、错了能收、危险能拦、事后能查。

**目标用户 / JTBD**：把重复工作交给 WorkBuddyForMe 的个人与小团队；他们不是不会配流程，而是不敢把生产性工作交给一个「失败就重来、出事没记录」的系统。

**范围（5 块，按优先级）**：

1. **运行可靠性**：失败节点批量重放、补偿队列、跨版本运行迁移、错误原因可读化；
2. **触发可靠性**：定时/事件触发器心跳、缺口检测、静默失效告警、可配置补跑；
3. **本地执行安全**：目录白名单、危险动作二次确认、操作前快照/可回滚、prompt injection 防护；
4. **审批与审计产品化**：统一策略、非技术审批人入口、谁在何时批准了什么；
5. **运行治理**：保留/清理策略、失败通知、运行对比与一键诊断。

**必须成立的条件**：

- 失败后 30 秒内能找到「继续/重放/放弃」的入口；
- 危险动作可回滚，且回滚有审计记录；
- 触发器停摆能被系统自己发现，而不是等用户对账。

**壁垒**：Flow、Agent、触发器、审批、审计在同一个本地进程里，可以做到「执行前拦截 + 执行中恢复 + 执行后可回滚」的闭环；云端编排产品很难同时满足本地权限与可回滚。

**风险**：

- 范围容易膨胀成「可靠性大杂烩」，必须用 3 条验收指标约束；
- OS 级安全边界实现复杂，需先做 Windows 白名单与快照；
- 不能宣称「绝对安全」，要明确故障域与用户责任。

**评分**：价值 9、差异化 9、可行性 7、风险可控 5 → **8.0**

## 3. 主题 B：「会记事」

**一句话**：知识引用可核验，记忆看得见、改得动、带得走。

**范围**：

1. 引用可核验：段落级定位、原文对照、低置信度提示；
2. 检索失败可解释：为什么没召回、缺哪个库/模型；
3. 记忆面板：记了什么、来源、置信度、可编辑/删除/导出；
4. 记忆迁移：导出为可读格式，换机/换应用不丢。

**必须成立的条件**：引用错误率可测；用户能在 1 分钟内找到并修正一条错误记忆。

**壁垒**：我们已有混合检索、引用与长期记忆治理；但 RAG 已商品化，差异化不如 A 明显。

**风险**：客户端侧记忆证据薄弱（仅 1 条一手体验）；容易做成「又一个知识库」。

**评分**：价值 7、差异化 7、可行性 8、风险可控 7 → **7.2**

## 4. 主题 C：「会带人」

**一句话**：第一次打开就能跑通一个真实场景，并从旧工具搬过来。

**范围**：

1. 场景模板：下载目录整理、周报简报、笔记问答、会议纪要、网页研究；
2. 迁移导入：Cherry/Obsidian/Notion 的会话、笔记、知识库导入；
3. 引导式配置：模型、嵌入、目录、触发器一次配好；
4. 能力包：模板 + 助手 + 知识库 + 流程打包安装。

**必须成立的条件**：新用户 10 分钟内完成第一个成功任务；模板一次跑通率 ≥ 80%。

**风险**：模板易被复制、需要持续内容运营；更适合作为获取手段，而不是大版本核心。

**评分**：价值 8、差异化 5、可行性 7、风险可控 8 → **6.9**

## 5. 推荐

**推荐 A「会兜底」作为 v5.0 主题**，理由：

1. 痛点证据最强：C1/C2/C9/C11 合计 44 条证据，跨 8 个产品；
2. 与既有资产最匹配：v4.23 持久化执行、v4.24 调度、v4.25 事件触发、审批与审计都可复用；
3. 竞品最难短期复制：云端产品受权限与本地文件边界限制，本地客户端缺少编排与治理；
4. 可形成清晰叙事：不是「功能更多」，而是「敢把活交给它」。

**v5.0 范围已冻结为 3 条可靠性主线 + 2 条安全边界**：

- R1 失败可收：M-1 批量重放与补偿队列、S-4 事件重试；
- R2 跨版本可续：M-2 运行图快照与兼容检查；
- R3 运行可治理：S-2 错过次数、S-5 保留/失败通知、S-6 健康面板；
- S1 执行前拦截：M-3 agent 写工具流程级无人值守门；
- S2 触发入口验真：S-3 Webhook HMAC。

OS 级目录白名单、危险动作快照回滚与 prompt injection 防护移出 v5.0，v5.1 评估。

**明确不做**：模板市场、记忆重构、跨端同步、公网暴露。

## 6. 若选 B 或 C

- 选 B：v5.0 聚焦「可信知识与记忆」，M 层只带引用可核验与记忆面板；A 的可靠性项降为 v4.26/v4.27。
- 选 C：v5.0 聚焦「首启与迁移」，需要先做模板内容与导入器；壁垒最弱，建议只作为 v4.x 的增长版本。
