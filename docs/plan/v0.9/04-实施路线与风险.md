# 04 · 实施路线与风险（v0.9）

## 一、里程碑总览

| 里程碑 | 周期（参考） | 目标 | 出口标准 |
|---|---|---|---|
| **M0 契约与迁移** | 2–3 天 | v013 + endpoint 仓储 + shared 契约 | v012 库升级单测过；密钥加解密/哈希存取可用；web/core 类型全绿 |
| **M1 执行解耦** | 5–6 天 | Queue/EventBus/Recovery + run-service 拆分 | 杀进程重启恢复场景过；v0.8 全部 flow/chat 测试零回归；双 SSE 观察一致 |
| **M2 本地 HTTP API** | 4–5 天 | 公开路由组 + 同步/异步 + UI | curl 双模调通；401/429/422 行为齐全；端点开关/重置可用 |
| **M3 MCP Server** | 4–5 天 | jsonrpc server + 双承载 + 自举 | inspector/自举 tools/list/call 成功；desktop stdio 打包手测过 |
| **M4 策略与收尾** | 3–4 天 | 无人值守策略 + 运行记录/重跑 UI + 0.9.0 | roadmap 成功判据 6 条全过；回归；tag v0.9.0 |

> 单人全职参考值，合计约 18–23 人日（含联调缓冲），与 roadmap 19 人日口径一致。M1 是唯一有回归风险的里程碑，给了最大缓冲。

## 三、验收检查清单（对应 roadmap 成功判据）

1. [ ] curl 同步 200 + output；`mode=async` 202 + runId；轮询终态一致；错误密钥 401；超频 429（Retry-After 存在）；坏入参 422
2. [ ] 运行中 kill 服务进程 → 重启：queued 自动续跑成功；running 记录为 interrupted(reason=process_restart)，可整体重跑与节点重放重跑，均成功；无记录永久 running/queued
3. [ ] 两个 SSE 同时观察同一运行，事件序列逐字一致；观察者全部断开运行仍终态
4. [ ] MCP：initialize/initialized/tools/list/tools/call 全通（http 自举 + stdio 手测各一次）；未知方法/坏参数错误码正确
5. [ ] 含 fetch_webpage 流程 API 调用：默认 policy_deny 失败且节点审计可见；allowlist 重发布后成功；桌面控制类工具无法被加入 allowlist
6. [ ] v0.8 回归：画布 start→llm→end 试运行、人工通过/驳回、对话 flow 工具子步骤、知识库问答、桌面任务页全部正常
7. [ ] 迁移：备份的 v012 真实库升级零数据改动；`pnpm check` 全绿；新文件 ≤300 行

## 四、风险登记与对策

| # | 风险 | 概率 | 影响 | 对策 | 触发信号 |
|---|---|---|---|---|---|
| R1 | run-service 重构破坏挂起时序/取消语义（v0.8 血泪点） | 中 | 高 | executeRun 单 run 内部零改动；只拆调度；55 个 flow 测试先跑后改；M1 单独成里程碑不合其他功能 | manual 测试出现 422/run 卡死 |
| R2 | manual 断线不 abort 后 waiters 永久挂起累积（用户关页面不审批） | 中 | 中 | waiting run 列表可查可取消；v1 加保守兜底：waiting 超 TTL（默认 24h，可配）重启时按 interrupted 处理；TTL 内保持存活 | waiting 数量异常增长 |
| R3 | 本地 HTTP 被本机恶意程序/DNS rebinding 调用 | 中 | 高 | 绑环回 + Host 白名单 + bearer + 默认关闭 + 不接受 cookie；文档明确威胁模型（同机恶意程序已能读文件，密钥仍是门槛） | 安全自测/外部报告 |
| R4 | 队列内存信号与 DB 状态不一致（漏信号 run 永久 queued） | 低 | 中 | claim 以 DB 原子更新为准；启动恢复扫描兜底；信号只作加速不作权责来源 | 出现 queued 超 N 秒无认领 |
| R5 | stdio bin 打包 ABI/native 问题 | 中 | 中 | 复用 v0.7 prepare-server 归集链；M3 早期先做打包冒烟再写功能；http adapter 作为不依赖打包的备用承载 | electron-builder 产物冒烟失败 |
| R6 | MCP 协议细节（版本协商/通知顺序）兼容坑 | 中 | 低 | 参照 v0.6 client 已跑通的协议面；用真实 MCP inspector 早期握手验证；不支持能力优雅降级 | inspector initialize 报错 |
| R7 | allowlist 放权被误用造成实际损害（如 fetch 内网） | 中 | 高 | 桌面控制永久禁单；SSRF/超时/熔断不豁免；发布时强提示并留版本快照；审计可查 | —（设计层缓解） |
| R8 | 重放式重跑语义被用户误解为「从断点继续」 | 中 | 低 | UI 文案明确「将重新执行上游节点」；文档与 tooltip；真断点续跑登记 v0.10 | 用户反馈困惑 |
| R9 | 范围蔓延（忍不住加 cron/webhook/多密钥角色） | 中 | 中 | Non-Goals 写入方案；每里程碑开工对照；新需求一律登记 v0.10 | 评审中出现范围外需求 |

## 五、回滚策略

- v013 纯加法迁移：回滚代码后新表/新列闲置不影响 v0.8 运行（旧代码不读新列）；不需要 down 迁移；
- 队列重构为内部行为：若 M1 出现阻断问题，可在一个发布周期内保留「SSE 驱动」旧路径开关（环境变量），但默认走队列；稳定后删除开关（不长期双轨）；
- HTTP/MCP/策略均为默认关闭能力（endpoint 默认不存在、开关关闭），不开启时 v0.9 与 v0.8 行为等价，风险面不向存量用户外溢。
