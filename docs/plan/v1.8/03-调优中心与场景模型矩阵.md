# v1.8 M0-3 · 调优中心与场景模型矩阵（冻结稿）

## 1. 范围

把分散在助手表单（采样参数）、v1.6 情绪面板（情绪开关）、v1.7 频率设置（主动频率）和 v1.4 协作三角色字段里的「手感配置」聚合成一个可调、可解释、可恢复默认的调优中心；并新增此前没有 UI 的两项：**上下文条数**（G5）与**全局追加提示词**（G4）。音色收藏（G7）只冻结数据契约，实现在 M4。

## 2. 字段盘点（全部来自现有 schema 实证）

`packages/shared/src/schemas/assistant.ts` 助手表已有字段（M3 只是聚合露出，不加列）：

| 字段 | 现有约束 | 现状 UI |
|---|---|---|
| `temperature` | number 0–2，默认 1 | 助手表单已有 |
| `topP` | number 0–1，默认 1 | 助手表单已有 |
| `maxTokens` | int 正数 ≤1,000,000，null=不限 | 助手表单已有 |
| `modelId` | string nullable（跟随默认） | 助手表单已有 |
| `plannerModelId/executorModelId/reviewerModelId` | string nullable，默认 null=跟随 | 仅表单高级区，分散 |
| `memoryEnabled` | boolean 默认 true | 助手表单 |
| `expressionEnabled` | boolean 默认 true（v1.6 情绪尾块开关） | 情绪面板 |
| `personalityFrankness/Tsundere/Shy/Tolerance` | 0–1 默认 0.5（v1.7） | 助手表单滑块 |

记忆提取模型：**当前无独立字段**，记忆任务回落默认对话模型（settings.defaultChatModelId）。本版决策：M3 矩阵中记忆行只读展示「跟随默认对话模型」，**不新增 memoryModelId**（避免出现无 UI 消费者的字段；确有需求待 v1.9 评估）。

## 3. 新增契约

### 3.1 上下文条数（新设置键，G5）

- 现状：`turn-context-assembly.ts` 用 `recentMessagesAfter(conversationId, summaryTurns, HISTORY_MESSAGE_SAFETY_CAP=200)` 取历史，再经 token 预算裁剪（context-budget.ts）。
- 新增 settings 键 `contextMessageCount`：整数 **2–50**，默认 20（新常量 `DEFAULT_CONTEXT_MESSAGES=20`、`CONTEXT_MESSAGES_MIN=2`、`CONTEXT_MESSAGES_MAX=50`，shared/constants/chat.ts）。
- 钳制点：服务端读取历史时 `recentMessagesAfter(..., min(userCount, SAFETY_CAP))` 先按条数裁剪，token 预算裁剪仍在其后（双保险，顺序不变）；**服务端钳制为准**，前端滑杆只约束 UI 提交。
- 全局设置还是每助手？决策：**全局设置键**（与主题同级，属于「上下文预算偏好」），不按助手分化——上下文条数与 token 预算一样是管线参数而非人格。UI 放调优中心「常用区」。

### 3.2 全局追加提示词（G4）

- settings 新键 `globalAppendPrompt`：string 0–2000，默认 `''`；配套布尔 `globalAppendPromptEnabled` 默认 false（空内容时开关无效）。
- 注入位置固定在「角色卡之后、情绪段之前」（见 [02 第 5 节](02-角色卡格式与解析契约.md)），纯拼接独立段落（带固定中文小标题，避免与卡正文粘连）。
- 多窗口一致：沿用 v1.2 语言/主题水合同步机制（settings 真源 + storage 事件），M3 在 providers 层挂 `window.addEventListener('storage')` 刷新缓存，避免桌宠窗与主窗设置漂移。

### 3.3 调优中心信息架构（设置页内新面板，不新开路由）

- 「常用」折叠区（默认展开）：对话模型（= 模型矩阵第一行）、temperature、上下文条数。
- 「高级」折叠区（默认收起）：topP、maxTokens（留空=不限）、情绪输出开关（expressionEnabled，从情绪面板移入并在原位置保留说明入口，避免两处控制）、三角色模型覆盖、人格四权重（v1.7 滑块可保留在助手表单，调优中心以矩阵视角只读汇总）。
- 每项一句人话解释 + 「恢复默认」（仅恢复该助手采样参数，二次确认；全局键恢复全局默认）。
- 弱模型档位提示：矩阵中当选中模型 id 匹配本地/小模型标记（models 表 capabilities 已有 contextWindow 等字段）时展示文案「小模型建议温度 ≤0.7、关闭协作审查以节省轮次」——**只提示不拦截**（对齐 v1.4 弱模型决策）。

## 4. 场景模型矩阵（G6）

一页表格，行=场景，列=当前绑定/可选模型/操作：

| 场景行 | 字段 | null 文案 |
|---|---|---|
| 聊天 | assistants.modelId | 跟随默认对话模型（settings.defaultChatModelId） |
| 记忆提取 | 无字段（回落默认聊天） | 跟随默认对话模型（v1.8 不可改） |
| Planner | assistants.plannerModelId | 跟随助手/系统默认 |
| Executor | assistants.executorModelId | 同上 |
| Reviewer | assistants.reviewerModelId | 同上 |

选项来自 providers/models 接口既有数据（model 行 id 非 model_id，沿用 v1.4 教训）；改动走既有 assistant PATCH。

## 5. 音色收藏（G7，M4 实现，本批冻结形状）

- settings 新键 `voiceFavorites`：数组 `{ id(crypto.randomUUID), label, providerId, modelId, voice }[]`，上限 20，label ≤20、voice ≤80；zod 契约 M3 随 settings schema 一并落（M4 才有 UI）。
- 分组：UI 按 provider+model 分组展示；「写回」=把 voice 写入当前语音设置既有字段（不新增语音配置列）。
- 固定音色厂商（select 可选枚举）不显示自由输入；仅支持私有 voice 的厂商显示自由输入框（沿用上游 v1.1 经验：按厂商能力分流，不放假控件）。M4 开工前先盘当前云 TTS 通道实际支持的参数（语速/响度同理，不支持不放假控件——MeloTTS 语速现有控件已存在，不重复造）。

## 6. 验收（M3/M4 出口）

1. 上下文条数：滑到 2/50 边界各发一轮，服务端历史取数被钳制；超范围提交被服务端 422。
2. 全局追加：开关切换即时生效（下一轮请求 system 段可见/消失），双窗口 storage 事件同步。
3. 调优中心改参数与助手表单同源同存（无第二份真源），刷新后一致。
4. 矩阵五行 null 态文案正确；三角色 PATCH 落库后 v1.4 协作实际读取的模型变更（单测验证服务层）。
5. 音色收藏 CRUD + 写回；不支持私有 voice 的厂商无自由输入框。
6. 新面板 a11y：所有 select/滑块有 label（v1.7 select-name 教训），axe serious/critical=0；中英词条齐全。
