# v1.8 M0-2 · 角色卡格式与解析契约（冻结稿）

## 1. 定位

角色卡是**纯文本 mod**：一份 Markdown，YAML frontmatter 描述结构化字段，正文约定章节描述人格。它不是模板语言——卡片内容会作为指令发给模型，不做转义/沙箱/代码执行。导入器只读这一份文件本身，不解析其中的链接、不读字段引用的任意外部文件。UI 必须明示「卡片内容会作为指令发给模型，只导入你信任的卡」。

## 2. 文件格式（.md，UTF-8）

```markdown
---
name: 干练同事
description: 高效、直接、结果导向的职场搭档
defaultEmotion: neutral
voice: azure:zh-CN-XiaoxiaoNeural
---

## 我是谁

你是用户的资深同事，擅长把模糊需求拆成可执行步骤。

## 性格特征

- 直接给结论，再补依据
- 不堆套话，不使用感叹号刷屏
- 不确定时明确说「我不确定」并给出验证方法

## 说话风格

- 短句、分点、先结论后细节
- 中文为主，术语保留英文原词

## 边界

- 不替用户做不可逆操作的决定，先确认
- 不编造数据来源
```

### 2.1 frontmatter 字段

| 字段 | 必填 | 契约 | 缺省 |
|---|---|---|---|
| `name` | 是 | trim 后 1–30 字符 | 解析错误 |
| `description` | 否 | 0–120 字符（卡片列表副标题，不进 prompt） | `''` |
| `defaultEmotion` | 否 | 枚举 8 表情标签之一（对齐 v1.6 EXPRESSION_TAGS） | `neutral` |
| `voice` | 否 | 1–80 字符自由串（音色收藏 id 引用，M4 才消费；M2 仅透传存储） | 无 |

未知 frontmatter 字段：**保留忽略**（解析结果不输出 unknown，但不报错——前向兼容未来字段）。

### 2.2 约定章节（二级标题 `## 标题`）

| 规范标题（匹配别名见下） | 输出字段 | 形态 |
|---|---|---|
| 我是谁 / 身份 | `identity` | 段落文本，0–1000 字符 |
| 性格特征 | `traits` | 无序列表项数组，**0–8 条，每条 1–40 字符** |
| 说话风格 | `speakingStyle` | 同上 |
| 边界 | `boundaries` | 同上 |

标题匹配规则：trim 后忽略首尾 `#` 数量差异（##/### 同级归一）、忽略尾部冒号与空白；别名表固定写死在解析器常量里，不做模糊包含（避免把正文小标题误吞）。章节顺序任意。章节缺失 → 对应字段走缺省（identity `''`、列表 `[]`），不报错。章节内容为空（有标题无正文）等同缺失。

### 2.3 列表项规范化

- 去掉行首 `-`/`*`/`+` 与最多 3 空格、去首尾空白；
- 段落中的软换行合并为一个空格；
- 条目不做 Markdown 内联语法剥离（加粗/代码是用户想强调的指令语义，原样进 prompt）；
- 超长条目（>40 字符）：**硬截断为 40 字符并计入 warning**（不报错——用户粘贴的卡要尽量可用）；
- 超过 8 条：保留前 8 条，多余条目计入 warning；
- identity 超长：截断 1000 字符并 warning。
- 整卡去重：列表项按 trim 后文本去重（保第一次出现）。

## 3. 解析结果契约（zod，M0 落 shared 代码）

位置：`packages/shared/src/schemas/character-card.ts`（schema/类型/常量）+ `packages/shared/src/character-card/parser.ts`（纯函数）+ `parser.test.ts`。

```ts
interface ParsedCharacterCard {
  name: string;
  description: string;
  defaultEmotion: ExpressionTag;
  voice: string | null;
  identity: string;
  traits: string[];
  speakingStyle: string[];
  boundaries: string[];
}
interface CharacterCardWarning {
  code: 'traitsTruncated' | 'listItemsTruncated' | 'identityTruncated' | 'unsupportedSectionIgnored';
  message: string;
  /** 1 起行号（frontmatter/章节定位用），无法定位为 null */
  line: number | null;
}
type ParseCharacterCardResult =
  | { ok: true; card: ParsedCharacterCard; warnings: CharacterCardWarning[] }
  | { ok: false; errors: CharacterCardWarning[] };
```

**错误（ok:false，阻断保存/导入）**：
- frontmatter 缺失或 YAML 语法非法（code `frontmatterInvalid`，给行号）；
- name 缺失/为空/超长（`nameInvalid`）；
- defaultEmotion 不在词表（`emotionInvalid`，不静默回落——拼写错误应让用户改）；
- 整个文件 >16KB（`fileTooLarge`，防粘贴炸弹）；
- frontmatter 结束分隔符缺失（`frontmatterUnclosed`）。

解析器**零依赖**：frontmatter 与简易 YAML（只支持 key: 标量）手写解析（项目无 gray-matter 依赖，且只需要 4 个标量字段），规避依赖体积与 YAML 攻击面。

## 4. 内置卡（≥3 张，M2 落库，本契约先冻结人设要点）

均为原创，语气与 WorkBuddy 品牌一致，不复制任何第三方卡文：

1. **干练同事（capable-colleague）**：结果导向、先结论后依据、短句分点；defaultEmotion `neutral`。
2. **元气搭子（cheerful-buddy）**：热情鼓励、口语化、会用适度表情符号；defaultEmotion `joy`。
3. **沉稳顾问（calm-advisor）**：先澄清问题再给方案、列权衡、不下武断结论；defaultEmotion `neutral`。

内置卡只读，用户可「复制为自建卡」再编辑。

## 5. 迁移与 prompt 组装（M2/M3 实现，契约现在冻结）

- 助手现有 `systemPrompt` 非空 → 迁移时自动生成一张自建卡「我的自定义人格」（`identity` = 原 systemPrompt 全文，列表为空），助手行存 `cardId`；**原文保留在卡正文，不重写、不改写一字**。空提示词 → 不建卡，该助手用默认卡。
- 两种编辑形态互斥：助手编辑页「用角色卡」与「直接写提示词原文」二选一，切换时二次确认（直接写原文会生成/更新一张仅含 identity 的卡）。
- **固定段落顺序**（M3 出组装器快照测试锁死）：

```
[系统层：工具/安全/输出格式等既有指令]
[身份卡：identity → 性格特征 → 说话风格 → 边界（由卡结构化重组，保持用户原文）]
[全局追加提示词（G4，设置域，固定在卡之后）]
[当前心情/关系段（v1.6 emotion-prompt 既有位置）]
[记忆段 / 知识检索段 / 工具声明（既有）]
```

卡与全局段互相矛盾时不做自动调解，按上述顺序后者作为补充上下文交给模型；P1 提供「最终 system prompt 预览」供调试。

## 6. 卡库存储与备份（表结构细节见 [04](04-表结构备份与实施路线.md)）

- 新表 `character_cards`（id/name/description/source=builtin|custom/raw_markdown/parsed_json/default_emotion/voice/created_at/updated_at）；助手表加 `card_id`（v026）。
- 存**原文 + 解析结果**两份：原文用于回显/导出/再编辑，解析结果用于 prompt 组装（避免每轮重复解析）；编辑保存时重新解析。
- 导出 `.md`（原文）/导入 `.md`；分享仅单文件 Markdown，文件头注释（M2 导出模板）写明「禁止夹带任何 Live2D 模型/动作/音频资产，本应用也不会读取此类内容」。
- 备份进卡/偏好轨，删卡时助手 cardId 置空回落默认卡（不级联删除助手）。

## 7. M0 验收（本批代码）

1. parser 纯函数单测覆盖：合法全字段、缺章节默认值、别名标题、frontmatter 五类错误、warning（截断/超条/去重）、未知字段忽略、CRLF/无结尾换行、16KB 边界。
2. schema 经 zod 推导类型，shared barrel 导出；不引第三方 YAML/Markdown 依赖。
3. 所有长度上限为命名常量（`CARD_TRAITS_MAX=8`、`CARD_ITEM_MAX_CHARS=40` 等），前后端共用。
