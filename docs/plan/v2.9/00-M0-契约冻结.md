# v2.9 M0：事件日志、检索导出与上下文治理契约冻结

> 状态：已实现（v2.9，2026-10-29）
> 范围：追加式 `session_events` 事件日志、CJK 全局检索、会话/运行导出 ZIP、报告下钻时间线、大工具输出溢出。
> P1 延后：一键诊断包；压缩预算可视化面板（现有压缩与预算记账继续生效）。

## 1. 事件日志

### 1.1 表（迁移 v038，纯加法）

| 列 | 含义 |
|---|---|
| `id` | 事件 id |
| `scope` | `chat` / `task` / `flow` / `agent` |
| `scope_id` | 会话 id / runId |
| `seq` | 同一 scope+scopeId 内单调序号（1 起） |
| `type` | 事件类型（见 1.3） |
| `payload_json` | 事件载荷（结构化 JSON） |
| `schema_version` | 事件 schema 版本，只前向（本期固定 1） |
| `created_at` | ISO 时间 |

- 唯一键 `(scope, scope_id, seq)`；索引 `(scope, scope_id, seq)`、`(created_at)`。
- 事件日志是时间线真源；现有 `messages/task_steps/node_executions/agent_handoffs` 继续作为业务查询投影。
- 只追加，不更新/删除；清理按保留天数（默认 180 天）由 API/设置触发，不在写入路径删除。

### 1.2 投影

- `projectTimeline(events)` 把事件折叠为统一时间线条目：`{seq,type,label,detail,at}`，UI 与导出共用。
- Chat 时间线：`message_started` / `message_completed` / `message_error` / `message_stopped` / `tool_trace`。
- Task：`run_started` / `step_started` / `step_finished` / `run_paused` / `run_resumed` / `run_finished`。
- Flow：`run_started` / `node_started` / `node_finished` / `node_failed` / `run_finished` 等（沿用 FlowEventPayload.type）。
- Agent：`agent_handoff` / `done` / `error` / `budget`。

### 1.3 写入点

- 对话：`ConversationService.appendMessage/completeMessage/markMessageError/stopMessage/saveMessageToolTrace` 统一写 `chat` 事件（`deps.events` 未注入时不写，测试可省略）。
- Task / Flow / Agent：容器已有 `onEvent` 回调同时写工作信号与事件日志，不新增第二套事件总线。
- 载荷截断：单条 `payload_json` 内容超过 200 KB 时截断并记录 `truncated:true`；不写密钥。

## 2. 检索

- `session_events_fts`（FTS5 `unicode61`）写入 `normalizeForFtsIndex(type + payload 摘要)`。
- 查询复用 `buildFtsQuery`：中文 2 字词可命中；空 token 返回空。
- 筛选：`scope`、`from`、`to`；默认按 `created_at DESC`，最多 100 条。
- 搜索结果返回：事件 id、scope、scopeId、type、摘要、时间、相关片段（payload 截断 300 字）。

## 3. 导出

- `GET /api/export/session?scope=&scopeId=&redact=1` 返回 ZIP（`application/zip`）。
- 内容：`manifest.json`、`events.jsonl`、`messages.json`（chat）、`steps.json`（task）、`handoffs.json`（agent）、`run.json`（运行行）。
- `manifest.json` 记录条目名、条数、生成时间、schemaVersion、是否脱敏。
- 默认脱敏：移除疑似密钥（`sk-...`、`Bearer ...`、API Key 字段）并省略 `args_json` / 工具参数原文；`redact=0` 才导出原始载荷（仍不含系统凭据/密钥）。
- 导出只读本地 DB 与文件元数据，不含附件二进制。

## 4. 上下文治理

- **大工具输出溢出**：单条工具输出超过 100,000 字符时写入内容寻址文件 `spills/<sha256>.txt`（幂等），模型只看到前 2,000 字符 + `spill://<sha256>` 引用；`GET /api/spills/:hash` 可打开全文。阈值高于常规压缩预算，避免与 v1.1 大输出压缩互相抢占。
- **附件去重**：沿用 v0.3 的 `content_hash` 秒传去重，不重复落盘。
- **压缩**：沿用现有会话摘要/预算记账；本期不新增压缩算法，只在导出中包含压缩摘要快照。

## 5. API 与 UI

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/events?scope=&scopeId=&after=&limit=` | 时间线事件 |
| GET | `/api/search?q=&scope=&from=&to=&limit=` | 全局检索 |
| GET | `/api/export/session?scope=&scopeId=&redact=` | 导出 ZIP |
| GET | `/api/spills/:hash` | 读取溢出全文 |
| 页面 | `/timeline?scope=&id=` | 时间线 + 搜索 + 导出 |
| 入口 | 运行报告行 / 任务详情 / Flow 运行 | 跳转时间线 |

## 6. 验收

1. 进程重启后，chat/task/flow/agent 时间线可从 `session_events` 重建；与业务表条数一致（消息/步骤/节点/handoff）。
2. 中文 2 字词检索命中；检索结果的事件与时间线一致。
3. 导出 ZIP 的 manifest 与实际条目一致；默认脱敏不含 `sk-` 密钥；`redact=0` 仍不含系统凭据。
4. 大工具输出被替换为预览 + `spill://`，全文接口可解析；同一内容重复溢出只落一份文件。
5. 附件同内容只落一份文件（复用既有 hash 秒传）。
6. `pnpm check`、四层测试、300 行门禁通过；迁移只做加法。

## 7. Non-Goals

- 不做多代会话格式迁移、云同步、跨设备检索。
- 不记录密钥、系统凭据或附件二进制到事件日志。
- 不追求永久保存所有 prompt 原文；以可重建、可审计为口径。
