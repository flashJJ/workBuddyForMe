# v1.7「有仪式」· 剧情事件引擎与主动关怀

> 主题：把主动行为从「一条气泡」升级为**有编排的小剧场**，让提醒、节日、哄好都有仪式感。
> 基线：v1.6 情绪内核已发布；分支建议 `feature/v1.7-events`
> 机制来源：Servant EventDirector/EventRunner、TriggerEngine、Scheduler（净室重实现；剧本全部原创）

---

## 1. 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 声明式事件引擎 | EventDefinition（优先级/打断策略/冷却/每日上限）+ Live2D 版 step 集 + 白名单 branch 条件求值，core 纯函数单测 ≥90% |
| G2 | 演出 player | web 侧把 step 映射到表情/动作/视线/走位/轻特效/语音/等待；打断、跳过、排队行为可 e2e |
| G3 | 内置剧本包 | 首批 ≥8 个原创剧本，覆盖日常/时段/关系/任务四个场景族；每个有触发条件、冷却、时长上限 |
| G4 | 触发器体系 | 内置意图（夸/怼/安慰/摸头/归来/晚安…）+ 用户自定义短语触发（约束：冷却/时段/每日上限/亲密度门槛） |
| G5 | 提醒调度 | once/daily/weekly 持久化（SQLite）、重启不丢、到点角色化提醒；对话中自然语言创建（复用触发器解析经验） |
| G6 | 人格参数化 | 人格权重配置（直率/嘴硬/害羞躲藏/容忍度等，数量按 Live2D 能演的动作集收敛），驱动剧本 branch 与情绪演法 |
| G7 | 打扰可控 | 主动频率三档 + 勿扰时段 + 语音占用排队不抢麦 + 一键停用全部主动；本地接受率/打断率统计 |

## 2. 功能清单

### P0

1. **事件引擎（core）**
   - 类型：`EventDefinition{id,title,priority,interruptPolicy:replace|replaceLowerPriority|ignore,cooldownMs,maxPerDay?,steps[]}`；单当前 + FIFO 队列；playsToday 闸门。
   - step（Live2D 集）：`expression / motion / gaze / speech / wait / branch / fx / spatial`。
     - `fx` v1 仅限注册表里的内置轻效果（爱心飘升、汗滴、闪光、出场淡入），DOM/Canvas2D 实现，零三方粒子库。
     - `spatial` 仅桌宠形态：横向滑入/滑出屏幕边、轻微上下跳；通过现有 pet 窗口桥。
   - branch：条件白名单求值（`path op number` 正则，path 仅 emotion/relation/personality/counters/时间变量），禁止任意表达式；非法条件按 false 处理并记日志。
   - 语音占用协议：speech step 在主对话/TTS 进行中入队等待（ignore 或排队，逐剧本声明），任何剧本不可打断用户正在说的话。
2. **内置剧本（原创，首批 8 个）**
   - 日常族：早安（首次当日交互）、晚安（深夜时段 + 晚安意图）、欢迎回家（离开阈值后回归）。
   - 关系族：被夸奖（直球/傲娇两种 branch 演法）、连续摸头害羞、生气哄好（belittle 后检测到安慰意图）。
   - 任务族：协作/Flow 成功的庆祝短演出、失败的打气短演出（仅 UI 会话消费，api/mcp 触发只入队）。
   - 时长全部 ≤20 秒，可跳过（Esc/点击），冷却默认每剧本每日 1–3 次。
3. **触发器**
   - 内置意图映射在 core：消息判定与情绪 soulEvent 共用一套规则/模型信号，不二次发请求。
   - 自定义触发器 UI：短语（多条，包含匹配）+ 绑定剧本（仅用户自建或已启用内置）+ 冷却 + 时段 + 每日上限 + 最低亲密度；输入校验与上限条数（如 30 条）防膨胀。
4. **提醒调度（scheduler）**
   - 新表 `scheduled_tasks`：once/daily/weekly + IANA 时区 + text + 启用开关 + next_run_at；core tick 由 web 会话存活时驱动（Electron 主进程可在应用运行时保活 ticker，但**锁屏/无 UI 不演出**，到点只写待演）。
   - 「叫我/提醒我」解析沿用现有对话触发经验：缺时间追问、否定不创建、24h 内规则；提供管理 UI（列表/增删/启停）。
   - 到点：桌宠/主窗在线 → speech 剧本化提醒；不在线 → 系统通知（Electron notification）兜底，应用内下次可见补演短版。
5. **频率与勿扰**：设置面板三档（少/标准/多）映射各触发间隔系数；勿扰时段（默认 23:00–8:00，仅紧急提醒可破口，本版无紧急级）；总开关「关闭所有主动演出」。
6. **人格权重（首版 4 个）**：直率示好、嘴硬傲娇、害羞易躲、调戏容忍（0..1，助手设置滑块 + 预设两档：坦率/傲娇）。branch 条件与摸头/被夸的台词风格取它；不强求 Servant 六参数全量（physicalLeak 等 3D 语义在 2D 没有对应动作）。

### P1

- 纪念日期：用户可填生日/纪念日（设置），到日触发专属剧本；年份计数（第 N 个）。
- 剧本调试控制台（内部页）：列出剧本、强制播放、看条件求值与队列状态（对齐 Servant debug 页传统，便于真机调参数）。
- 演出后的情绪联动：剧本完成按类型 applyEmotionEvent（庆祝 +happiness、安慰 −sadness）。

### P2 留白

- 剧本编辑器可视化（本版只做 JSON 编辑/导入，且仅高级设置里）。
- 外部事件源（音乐/弹幕/游戏）→ v2.0 评估边界，本版只在引擎留 `external trigger` 类型口但不接适配器。
- 用户上传音效/图片做剧本素材（版权与红线，不做；fx 与文案全部内置/生成）。
- 多剧本并发优先级的复杂策略（固定三级 priority 足够）。

## 3. 架构影响

- shared：event/scheduler schema、条件协议白名单、i18n `event.* / scheduler.*`。
- core：event 域（director/runner 纯逻辑、conditions、cooldown 计数）、scheduler 域（repo/tick/next-run 计算）、触发器规则；全部不依赖 React/DOM。
- web：`EventPlayer`（把 step 投递到 Live2dController/TTS/pet 桥/通知）、剧本与提醒管理 UI、人格权重滑块、频率设置。
- desktop：到点通知兜底、pet spatial 走位 IPC；应用存活但无窗时的 ticker 策略需 M2 真机验证节流。
- 存储：`scheduled_tasks` + `event_usage`（冷却/每日计数/触发流水，JSON 或小表）进备份。
- 安全：自定义短语仅本地匹配，不进任何外发请求；剧本不调用工具、不触网（纯演出），天然在 desktop 无人值守红线之外。

## 5. 风险与取舍

- **最大风险=打扰**：默认频率取「少」；任何主动演出可 Esc/点击跳过且跳过无负面情绪反馈；统计关闭率，过高自动建议降档（只提示不自动改）。
- **剧本中二/尴尬**：文案两轮评审（中文母语真机朗读），台词短（≤32 字/条对齐 Servant 经验）、条数少；允许用户停用单个内置剧本。
- **引擎过度设计**：step 集与条件文法首版从简（不做变量插值、不做循环 step）；条件只支持数值比较，需要更复杂时用两条剧本+计数器表达。
- **时序冲突**：对话、TTS、剧本三者的锁顺序在 M0 画状态机（谁等谁、谁可 abort 谁），用户语音永远最高优先级。
- **弱模型台词质量**：剧本台词优先内置模板（条件选模板），LLM 生成只用于「提醒内容转述」等信息性语句；情绪类台词不依赖当场生成。
