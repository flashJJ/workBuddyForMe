# 04 · v1.6–v2.0 版本路线图

> 本篇是跨版本总控：节奏、依赖、度量、风险。每版的功能/验收/Non-Goals 细节见各分册。

---

## 1. 版本节奏与依赖

```text
v1.6 有情绪（情绪内核 + 桌宠交互）
  │  产出：emotion 状态存储、情绪输出协议、Live2D 交互/微动作配置
  ├──────────────► v1.7 有仪式（事件引擎 + 剧本 + 调度）
  │                 产出：EventDirector(core)、player(web)、8+ 内置剧本、scheduler
  │                   │
  │                   └──────► v1.9 有舞台（协作可视化 + 会议）
  │                              消费：情绪状态、事件 player、agent run 数据
  │
  └─► v1.8 会打扮（皮肤 + 角色卡 + 调优）  ※ 相对独立，可按真机反馈与 v1.7 换序/并行
        产出：多主题 token、角色卡库、调优中心
          └──────────► v2.0 活在桌面（关系养成 × 记忆 × 主动感知 × mod 封版）
                         汇聚：情绪/剧本/角色卡/记忆全部就位后的闭环
```

- **关键路径**：v1.6 → v1.7 → v1.9。v1.6 的情绪 schema 一旦发布即成为跨版本契约，v1.6 评审时必须把 v1.7/v1.9/v2.0 的读取需求一次想全（见 §3 数据契约前瞻），但实现只做 v1.6 范围。
- **可并行支线**：v1.8 与 v1.7 在代码域上几乎不冲突（设置/主题域 vs core 事件域），若真机反馈「外观诉求 > 演出诉求」可提前插 v1.8。
- **每版规模约束**：沿用 v1.3/v1.4 节奏，单版 4–6 个里程碑、一个主题闭环；不允许把舞台（v1.9）提前塞进 v1.7。

## 2. 各版一页速览

| 版本 | 主题 | 核心出口（可被真机演示的一句话） | 主要风险 |
|---|---|---|---|
| v1.6 | 有情绪 | 摸头会脸红抗议、被夸会开心一阵、冷落会想念，表情不再随消息清零 | 弱模型情绪字段不可靠；桌宠常驻功耗 |
| v1.7 | 有仪式 | 深夜弹一段「晚安」小剧场，生日/纪念日有专属演出，提醒由角色开口 | 演出打断对话的时序；主动行为变打扰 |
| v1.8 | 会打扮 | 换主题、换角色卡、调参数，同一个模型立刻换性格与观感 | 主题 token 改造波及面；角色卡与旧提示词兼容 |
| v1.9 | 有舞台 | 三角色协作在全屏舞台上当面讨论，用户还能主持一场多助手会议 | 多 Live2D 实例性能；多角色音频/防串角 |
| v2.0 | 活在桌面 | 它记得共同经历、随关系解锁称呼与剧情，配置能打包分享 | 范围失控（mod 商店诱惑）；授权决策（VRM） |

## 3. 跨版本数据契约前瞻（v1.6 一次想全）

| 表/结构 | 首现 | 后续消费者 | 前瞻要求 |
|---|---|---|---|
| `assistant_emotion_states` | v1.6 | v1.7 剧本条件、v1.9 舞台、v2.0 养成 | mood/relation/need 之外预留 `counters` JSON 与 `schemaVersion`；时间戳用毫秒 UTC |
| `emotion_events`（流水） | v1.6（可选轻量） | v2.0 关系曲线/年度回顾 | 只存 type/强度/来源(chat/event/manual)/时间，不存对话全文（外键引用 message_id） |
| `scheduled_tasks` | v1.7 | v2.0 主动感知 | once/daily/weekly + 时区 IANA + payload JSON + 软删除；进备份 |
| `event_definitions`（内置+用户） | v1.7 | v1.9 舞台剧本、v2.0 mod 包 | 内置剧本用稳定 id 前缀 `builtin.*` 不可删只可停用；用户剧本带版本号 |
| `character_cards` | v1.8 | v1.9 角色档案、v2.0 mod 包 | Markdown 原文 + 解析后 config 双存；来源标记 builtin/imported |
| `stage_scenes` | v1.9 | v2.0 | 背景资源引用而非二进制内联（文件落数据目录，沿用 Servant 教训） |

迁移纪律：每版独立 user_version 迁移、旧数据幂等回填（v1.3 v018 经验）、新表全部纳入备份/恢复测试。

## 4. 情绪价值度量体系（没有度量就会做成自嗨）

全部指标默认**只在本地统计**（设置库/JSON，可选导出），不埋点上报。

| 指标 | 定义 | 首现版本 | 用途 |
|---|---|---|---|
| 互动触达 | 桌宠点击/摸头次数（日，按助手） | v1.6 | 验证交互是否被发现（0 触达=入口失败，不是功能失败） |
| 彩蛋触发 | 保护期/特殊交互触发次数与当日分布 | v1.6 | 调连摸阈值 |
| 情绪协议合法率 | 情绪 JSON 解析成功率/词表合法率/规则保底触发率（按模型档位） | v1.6 | 弱模型回落策略调参；eval 断言 |
| 主动接受率 | proactive/提醒/剧本演出后 10 分钟内用户回应率；主动打断率/手动关闭率 | v1.7 | 定频率档位，**打扰率是负向北极星** |
| 演出完成率 | 剧本完整播完/被跳过/被打断比例 | v1.7 | 剧本时长与节奏调优 |
| 个性化采用 | 主题切换数、角色卡切换/导入数、非默认参数比例 | v1.8 | 判断 mod 方向是否继续投 |
| 舞台使用 | 协作 run 中打开舞台比例、会议场次/平均轮次 | v1.9 | 验证 v1.9 是否真的被看 |
| 关系活跃 | 连续使用天数、关系等级分布、解锁项触达 | v2.0 | 养成体系有效性 |

每版封版必须给出指标口径的本地实现（或明确声明仅用 eval/人工真机评测替代），不允许把度量推给「以后接埋点」。

## 5. 跨版本风险矩阵

| 风险 | 等级 | 缓解 | 责任版本 |
|---|---|---|---|
| Cubism 授权误触（用户被引导导入外部模型） | 高 | 红线写入每版 Non-Goals 与评审单；mod 文档明确禁止资产包；UI 不出现任何「导入模型」入口 | 全版本 |
| 弱模型情绪/剧本字段不遵从 | 高 | zod 回落 + 规则保底 + 词表外默认值；情绪协议 eval（含 7B 档）；永远不阻塞主回复 | v1.6 立规，全版本 |
| 主动行为从「陪伴」变「骚扰」 | 高 | 频率档位（少/标准/多）+ 勿扰时段 + 一键关闭全部主动 + 打扰率负向指标；剧本默认不抢麦（语音占用时排队） | v1.7 |
| 桌宠常驻功耗/动画掉帧 | 中 | 参数驱动走 PIXI ticker 不走 React；不可见窗口暂停调度；空载 CPU 前后对比列入真机验收 | v1.6/v1.7 |
| 多 Live2D 同台性能不达标 | 中 | v1.9 M0 先做 spike（3 实例同页帧率/内存），不通过则降级为「立绘 + 当前发言者 Live2D」方案 | v1.9 |
| 主题改造大面积回归 | 中 | token 先行审计、语义色不动、逐面板迁移；axe 对比度回归（v1.2 基线） | v1.8 |
| Servant 许可/表达相似风险 | 中 | 只读文档做设计、实现者不对照其源码抄结构；剧本/提示词/命名全部原创；封版前过一遍相似性自查 | 全版本 |
| 范围蔓延（弹幕/游戏/3D/mod 商店不断插队） | 中 | 本路线图即冻结清单：新想法入 v2.0+ backlog；每版 Non-Goals 显式拒绝 | 全版本 |
| 情绪数据引发用户不适（「被监视感」） | 中 | 情绪面板完全可见、可重置、可关闭；不写对话原文进事件流；默认不做任何推断式人格标签展示 | v1.6/v2.0 |
| 新旧人格数据迁移（systemPrompt → 角色卡） | 低 | v1.8 保留字段兼容，旧提示词自动包装为「我的自定义卡」，不删除不重写原文 | v1.8 |

## 6. 与既有工程节奏的衔接约定

1. **每版开工**：从本分册扩展为正式四篇（现状/功能设计/架构/实施风险），过评审后才建 feature 分支。
2. **分支与封版**：沿用 feature/vX.Y-* → `--no-ff` 合 main → `pnpm sync-version` → tag → GitHub Release → Windows 真机抽测。
3. **测试不降级**：core 情绪/事件内核走纯函数高覆盖（≥90% 目标，对齐 v1.1 压缩模块标准）；web 交互用 Playwright（pet e2e 已有基座）；新增协议进 eval golden 并带「关情绪/关主动」反向验证开关（对齐 v1.3/v1.4 三开关传统）。
4. **i18n**：剧本名/情绪等级/设置文案全部 zh-CN 真源 + en；剧本正文（模型生成）不翻译；系统模板走线格式 key（v1.5 协议）。
5. **真机验收清单每版追加**：Electron 桌宠形态必测（浏览器测不出窗口穿透/节流/音频挂起），本地 7B 模型必跑一轮。
