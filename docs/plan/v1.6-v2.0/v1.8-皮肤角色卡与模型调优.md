# v1.8「会打扮」· 主题皮肤、角色卡与配置式模型调优

> 主题：把「人格、外观、参数」从开发常量变成**用户可配置、可切换、可分享**的组合（数据 mod，不碰模型资产）。
> 基线：v1.7（或按真机反馈提前到 v1.7 之前，本版与事件域无代码耦合）；分支建议 `feature/v1.8-personalize`
> 机制来源：Servant 命名主题/uiPreferences、CharacterSkill 卡库、Provider 注册表/音色库（设计借鉴，UI 与解析器原创）

---

## 1. 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 命名主题皮肤 | 在明暗之上提供 ≥4 套命名主题（含品牌默认），data-theme 色板切换、水合同步无刷新；对比度全部过 4.5:1，axe 零 serious |
| G2 | 主题色个性化 | 有限档主色可选（6–8 档预设，不开放任意取色器首期），组件语义色不被破坏 |
| G3 | Markdown 角色卡库 | frontmatter + 约定章节解析为人格配置；多卡/切换/导入/导出/重置；旧 systemPrompt 自动包装为一张卡，行为零变化 |
| G4 | 全局追加提示词 | 独立于角色卡的全局附加段，每轮注入位置固定（卡之后），开关即时生效 |
| G5 | 调优中心 | 生成参数（temperature/topP/maxTokens）完整 UI 露出 + 上下文条数可调（2–50 契约钳制）+ 情绪输出开关 + 参数说明/恢复默认 |
| G6 | 场景化模型透明化 | 聊天/记忆/协作三角色模型绑定一处可见可改（字段已有，补聚合 UI 与弱模型档位提示） |
| G7 | 语音参数与音色收藏 | MeloTTS 可达参数（语速等）露出；云 TTS voice 命名收藏（按 provider+model 分级），当前生效反推高亮 |

## 2. 功能清单

### P0

1. **主题令牌化改造（前置工程）**
   - 审计 globals.css：现有 HSL 变量按「明/暗/主题色」重组为 `:root[data-theme='brand-dark']` 等多套色板；语义色（success/warning/info）与代码块色板同步出多套。
   - 切换沿用 v1.2 水合同步（localStorage + `<html data-theme>`）；System/Light/Dark 三态语义保留：命名主题与明暗正交（每个主题声明亮/暗归属，借鉴 Servant 夜金暗/月白亮做法）。
   - 首批 4 套：**星际蓝（品牌默认，现有配色）、夜金（暗色暖金）、月白（亮色素净）、樱粉（亮色柔粉）**——命名与色值原创，不抄其具体取色。
2. **主题选择 UI**：设置-外观，卡片式预览（主色/底色/卡片/按钮样张）；主色档位于主题卡下二级选择。
3. **角色卡（文本 mod）**
   - 格式：Markdown + YAML frontmatter（`name / description / defaultEmotion / voice?`）+ 约定章节（我是谁 / 性格特征 / 说话风格 / 边界），解析为 `{identity, traits[], speakingStyle[], boundaries[], defaultEmotion}`，章节缺失走默认值，解析失败给行号错误。
   - 卡库 UI：内置卡 ≥3 张（原创：如「干练同事」「元气搭子」「沉稳顾问」，语气与现有 WorkBuddy 品牌一致）+ 自建卡；切换 activeCardId 即时生效；导入 .md、导出 .md/.json；每助手选卡。
   - **兼容迁移**：助手现有 systemPrompt 非空时自动生成一张「我的自定义人格」卡（原文保留、不重写、仍可直接编辑原文，二选一编辑形态）；空提示词用默认卡。
4. **全局追加提示词**：设置域一份（非每助手），注入 system 固定位置；沿用 Servant「现场读、跨窗 storage 事件同步」经验避免多窗口陈旧。
5. **调优中心（设置-模型与生成聚合页）**
   - 每助手：temperature（0–2 滑杆带文案解释）、topP、maxTokens（留空=不限）、上下文条数（2–50，前后端同常量，服务端钳制）、情绪开关（v1.6 字段挪入此处聚合）、恢复默认。
   - 场景模型矩阵一页展示：聊天模型 / 记忆提取模型（如无独立配置显示跟随）/ planner/executor/reviewer 覆盖；弱模型给出档位提示文案（不拦截，对齐 v1.4 决策）。
6. **双语 + a11y**：全部新词条；滑块/卡片对比度；键盘可达。

### P1

- 音色收藏库：云 TTS voice id 命名保存、按 provider+model 分组、一键写回；仅对支持私有 voice 的厂商显示自由输入，固定音色厂商用 select（对齐 Servant 形态分流经验）。
- 桌宠气泡样式：跟随主题（气泡底/字色/圆角）、昵称称呼字段（助手怎么叫用户，进情绪/会议 prompt，默认空）。
- TTS 语速/响度：先盘 MeloTTS 与现有云通道实际支持的参数再露，不支持的不放假控件。
- 角色卡分享：单文件导出（纯 Markdown），应用间互发即导入。

### P2 留白

- 主题商店/在线下载（无账号、无网络分发，永不做商店；最多支持本地 .wbfm-theme.json 导入，排 v2.0 mod 包）。
- 任意自定义取色器/自定义字体上传（对比度不可控 + 中文字体体积，暂缓）。
- Live2D 换装贴图/挂件/外部动作包——**红线**，任何形式的模型资产扩展都不做。
- 云端角色卡同步/社区。

## 3. 架构影响

- web：theme 域从「明暗 hook」扩为「主题注册表（id/明暗归属/色板 token 组/预览元数据）」；globals.css 多色板；设置-外观重排。
- shared：character-card schema（Markdown 解析结果 zod + 长度上限：traits ≤8、每条 ≤40 等，防注入超长 prompt）、settings 新增全局追加提示词/主题偏好键；上下文条数契约常量。
- core：角色卡 → system prompt 组装器（卡章节 + 全局追加 + 情绪段 + 记忆段的**固定段落顺序**要出文档并加快照测试，对齐 Servant promptParity 护栏思路）；卡库存储（SQLite 表 `character_cards`，助手行存 cardId）。
- 安全：角色卡是用户自写 prompt，按 prompt 数据处理不做模板转义，但要在 UI 明示「卡片内容会作为指令发给模型，只导入你信任的卡」；导入不执行任何代码、不读字段外文件。
- 备份：卡表/偏好进四轨；迁移保证旧助手无缝。

## 5. 风险与取舍

- **主题改造回归面大**：色板只动 token 不动组件；语义色/代码块双套验收；M1 结束跑全量 e2e 截图对比关键页。
- **角色卡与现有提示词打架**：迁移不删原文、两种编辑形态明确互斥；段落顺序用快照测试锁死，防止注入位置漂移改变所有助手行为。
- **用户写出互相矛盾的卡与全局段**：组装顺序文档化（身份→卡→全局追加→情绪→记忆/工具），不做自动调解；提供「最终 system prompt 预览」（P1 调试用）。
- **参数暴露吓坏普通用户**：调优中心分「常用」（模型/温度/上下文条数）与「高级」折叠；每项带一句人话解释和恢复默认。
- **合规红线再确认**：角色卡是纯文本，绝不能演变为捆绑 Live2D 模型/动作/音效的「人物包」；分享 UI 的文件说明里写明禁止夹带模型资产。
