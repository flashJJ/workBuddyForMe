# v1.9「有舞台」· 多智能体可视化会议舞台

> 主题：把 v1.4 的「工位式泳道」搬上**看得见的舞台**，并新增用户主持的多助手讨论——让协作可感受、可围观。
> 基线：v1.7（事件 player）+ v1.8（角色卡/模型配置，可并行先行）；分支建议 `feature/v1.9-stage`
> 机制来源：Servant Galgame Stage / MeetingPage 调度与防串角协议（2D 化重设计；不复用其舞台代码/素材）

---

## 1. 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 多实例性能 spike 先行 | 3 个 Live2D 同页帧率/内存真机报告；不达标即按降级方案（立绘+发言者 Live2D）实施，方案在 M0 锁死 |
| G2 | 协作可视化 | v1.4 任意 agent run 可「在舞台观看」：三角色按 planner→executor→reviewer 的 handoff/步骤依次发言、做表情动作；舞台是只读渲染器，不改 run 状态机 |
| G3 | 全屏 2D 舞台 | 独立 Electron 窗口：站位布局、当前发言者聚焦、名字牌（名字/表情/动作）、背景层、场景保存、无 UI 截图、H/F11/Esc 快捷键 |
| G4 | 会议模式 | 用户发起多助手讨论：manual(@)/all/auto(接龙≤8 轮) 三调度；防串角双通协议；单 abort 串行；会议本地持久化与历史 |
| G5 | 语音串行 | 共用唯一 AudioContext，按 speech 完成事件串行播放，角色→voice 可选映射；无语音时纯文本舞台完整可用 |
| G6 | 窗口形态 | 桌宠 ↔ 舞台互斥切换（几何保存恢复）；舞台关闭后协作/会议继续在后台跑（队列所有方不在舞台） |
| G7 | 权限不放松 | 会议模式的助手只能用各自被授权的工具读能力（首期会议**不带工具**，对齐 Servant 会议无工具裁剪经验）；协作舞台不新增任何执行权限 |

## 2. 功能清单

### P0

1. **M0 性能 spike（关卡式，不通过就改方案）**
   - 同页 3 实例 PIXI Live2D：待机/表情/口型同时驱动的帧率、内存、GPU；Electron 1080p 全屏真机。
   - 备选方案 B：共享 canvas/离屏渲染；备选方案 C：非发言者用静态立绘（模型当前表情截图或预渲染图），仅当前发言者 Live2D——C 方案工作量与风险最低，作为保底。
2. **舞台渲染器（只读演出 v1.4 run）**
   - cast 协议：角色 id → {显示名, Live2D modelId（助手 vrmId 等价位：从助手形象设置取，缺省 haru）, 表情映射, 可选 voiceId, 角色卡}；planner/executor/reviewer 映射到用户已有三个助手或默认形象。
   - 订阅现有 agent SSE：规划宣读（planner 面向用户讲目标）、执行状态（executor 动作/表情随 task step 变化，工具调用不逐条念，摘要化）、审查结果（reviewer 通过/返工短台词）；等待中角色给 listening/thinking 微动作（复用 v1.6 状态动作）。
   - 时序：发言队列严格串行，动作与语音对齐（语音出口仍是主窗管线，舞台是另一个渲染窗——需评审音频归属，见 §3）。
3. **全屏舞台与 2D 场景**
   - 横向立绘站位（左/中/右，可拖拽调整、滚轮缩放单角色、Ctrl+滚轮缩放画面）；当前发言者居中放大+提亮，其余缩小+降饱和；切换用缓动。
   - 背景：纯色/渐变/内置原创背景图/本地图片（≤20MB、亮度/模糊调节），文件复制进数据目录不引用原路径；2D「灯光」=整体暖色滤镜层与角色亮度，不做三维光照。
   - 名字牌：名字（强）/情绪（色）/动作（色）一行纯文字分层（字号+颜色，无色块）；对话框可隐藏；场景（背景+站位+显隐+滤镜）命名保存。
   - 底栏空闲淡出、H 隐 UI、F11 全屏、Esc 逐级退出、保存无 UI 截图。
4. **会议模式（新功能，独立于协作）**
   - 入口：助手/舞台「发起讨论」；选 2–4 个已有助手作为成员 + 议题；会话本地持久化（会议消息/结论/待办，存 SQLite，不与协作表混用）。
   - 调度：manual（正文 `@助手名`）、all（按序一轮）、auto（模型末尾 JSON `next_speaker_id` 建议，服务端校验成员合法性，≤8 轮，结束自动回 manual）。
   - **防串角协议（直接采用 Servant 验证过的结构）**：system = 身份规则 + 最近转录（每条带 `[用户·称呼]`/`[助手·名字]` 标注，声明历史中其他助手的话不是自己的）；messages 仅一条 user 锚点且尾条永远 user；共用一份模型配置；同一时刻单请求单 AbortController，打断/暂停/结束即 abort。
   - 情绪：会议链路裁剪 soulEvent（沿用其裁剪经验），但每轮允许 emotion 驱动发言者表情；会议中情绪状态不写回单聊状态。
5. **窗口与生命周期**：舞台窗由主进程开关、保存/恢复原桌宠几何；会议/队列所有方在 web 主会话（舞台隐藏不杀队列，对齐 Servant 队列归属经验）；关窗只退演出不退会议。

### P1

- 会议产出：自动结论与待办摘要（会议结束一次 LLM 调用，结构化结论可一键建任务/Flow？首期只展示+复制）。
- 舞台回看：已结束的 agent run/会议可「回放」（按时间戳重播，非重新请求）。
- 观众模式：纯观看无输入框（投屏/挂机场景）。

### P2 留白

- 自由 N 角色/角色市场（固定 2–4 个已有助手，不做新建虚拟人格；角色卡 v1.8 已提供人格，但成员必须是配置过模型的真实助手）。
- 角色间私有私聊/自主群聊（所有发言必须由用户议题或 @ 触发，不做 agents 自发闲聊——成本与打扰不可控）。
- 舞台上的桌面控制/工具实时屏幕画面（computer use 不进舞台，沿用无人值守与隐私红线）。
- 三维 VRM 舞台（v2.0 spike 后再议）。
- 手机/网页分享舞台。

## 3. 关键架构决策（评审重点）

1. **两个场景严格分账**：协作舞台=agent run 的只读渲染器（数据全在现有表，零新执行逻辑）；会议=新会话新表新调度（不开工具、不触桌面）。共用的只是舞台渲染层与 cast 协议。
2. **音频归属**：v1.0 宪法是主窗唯一 AudioContext。舞台窗不建音频管线：语音仍由主会话播放（主窗隐藏不销毁），舞台只收电平/状态中继做口型——与桌宠瘦终端同构。评审若认为舞台开时主窗必然隐藏体验差，P1 再评估 Electron 窗口间音频图迁移（高风险，不阻塞首版）。
3. **队列所有方在主会话**：舞台是显示器不是调度器，避免关窗杀协作（v1.4 run 本来就后台化，舞台仅订阅）。
4. **会议不碰工具链**：无 tool_choice、无 MCP、无知识库直连——需要资料的讨论让用户在普通对话/协作里做。会议价值在「多视角表达」，控制 token 与跑偏。
5. **降级方案预先承诺**：spike 不过就用方案 C，不允许在 M3 还纠结性能。

## 4. 架构影响

- shared：cast/stage/meeting schema、meeting SSE 或本地轮询协议、i18n `stage.* / meeting.*`。
- core：meeting 域（调度状态机纯函数：队列/锚点构建/转录标注/next-speaker 校验）、会议 repo；agent run → 演出事件的适配器（纯映射）。
- web：`/stage` 全屏路由、舞台组件群（站位/名字牌/背景/场景/快捷键）、会议页（成员选择/对话框/模式切换/历史）；live2d-controller 支持多实例或立绘降级。
- desktop：stage 窗口管理（全屏/几何/置顶/互斥）、截图能力、菜单入口。
- 存储：meetings/meeting_messages/stage_scenes；进备份；舞台背景文件纳入备份文件轨策略评审（体积大，默认只备份引用不备份图，恢复时缺失回落默认背景）。

| 阶段 | 出口 |

## 6. 风险与取舍

- **性能（最高）**：M0 关卡制，保底方案 C 提前接受；舞台模式给「省电模式」开关（降帧/立绘化）。
- **token 成本**：auto 接龙 ≤8 轮硬上限 + 每轮转录截断（近 20 条对齐）+ 成员数 ≤4；UI 开始前显示预计消耗量级（弱模型提示）。
- **串角/复读**：防串角标注 + 尾条 user 锚点是已验证结构，eval 必须有「诱导复读队友」反向用例；模型若在正文冒充他人，前端按发言归属渲染不采信自我宣称。
- **协作舞台时序错位**：只读渲染意味着网络/计算等待时角色不能僵住——等待态必须有 listening/thinking 微动作与打字提示（v1.6 资产复用）。
- **与现有任务中心定位重叠**：任务中心/泳道继续服务「审计与操作」，舞台服务「观看与理解」，两者互链不互替，不在舞台上放审批/返工操作按钮（P0）。
