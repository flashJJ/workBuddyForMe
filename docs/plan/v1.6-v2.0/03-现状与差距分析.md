## 2. 七条核心差距

### G1 没有跨轮情绪：表情是「这一条消息」的函数

现状表情由单条回复的标签即时推导，消息结束即回 neutral。没有情绪积累、没有衰减、没有「上一轮被夸这一轮还开心」。Servant 的 mood/relation 双层模型（临时情绪指数衰减 + 慢变量关系）完全缺失。

### G2 桌宠「可看不可玩」

交互全集 = 拖、tap 挥手、双击、右键。无触摸分区反馈（Live2D HitArea 能力只用了 tap）、无连续互动彩蛋、无视线跟随、无「被忽略」反应；idle 只有模型自带动作循环，没有自主的「生命感」小动作调度。用户 3 天后对它的预期就固化为「图标」。

### G3 主动行为没有演出层

proactive 是一条流式文本气泡（不持久化、skip-history），没有多步编排：不能「先做动作→表情变化→再说话→等一下→躲起来」。提醒（叫我/提醒我）在对话层触发但没有角色化的持久调度（once/daily/weekly、重启不丢）。节日/纪念日/久别重逢等**仪式场景为零**。

### G4 协作「可审计但不可感受」

三角色协作有完整泳道时间线，但角色没有形象参与：用户读到的是结构化卡片，不是「三个伙伴在讨论」。情绪价值与可理解性双低——非技术用户甚至分不清 planner/reviewer 谁在说话。

### G5 个性化只有文本框和二选一

人格 = 一个 8000 字 systemPrompt；外观 = 5 模型 + 明暗主题；没有角色卡概念（不能存多个人格切换/导入/分享）、没有命名皮肤与主题色、没有昵称称呼体系、生成参数 schema 有但 UI 没完整露出。「mod 可配置」基本空白。

### G6 情绪没有进入协作与主动链路

v1.4 多人链路刻意裁剪了 soul/memory 段落（Servant 会议也裁），但 Servant 单人链路情绪是完整的；WorkBuddy 连单人链路都还没有情绪字段。LLM 输出协议没有结构化的 emotion/intensity/action 位（8 标签仅靠正文标签解析，弱模型不吐标签就丢），没有确定性保底。

### G7 缺少情绪价值的度量与安全护栏

主动搭话频率/打扰度没有用户可调的精细化档位；情绪/关系数据将来写入后需要：重置入口、备份策略、隐私可见（用户能看到「它以为我们关系怎样」）、弱模型协议遵从率观测。这些在当前都没有设计位。

## 3. 约束清单（设计必须服从）

1. **Live2D 资产红线**：仅内置 5 套官方样本，不做外部模型导入、不做模型编辑器、不捆绑第三方 Live2D 资产（Cubism 发布授权）。mod 边界 = 文本角色卡 + 剧本 JSON + 皮肤色板 + 配置组合。
2. **本地优先**：情绪/关系/剧本/设置全部本机持久化；无账号、无遥测默认开启；v2.0 若加使用统计必须显式 opt-in 且只存本地。
3. **单音频出口**：主窗唯一 AudioContext（v1.0 定案），桌宠瘦终端不动摇；多角色舞台也串行共用。
4. **无人值守禁 desktop**：剧本/情绪触发的桌面动作只在 UI 会话内；api/mcp/Flow 触发只入队待演。
5. **弱模型现实**：v1.5 真机结论——7B 无视提示词软约束。情绪协议必须 zod 校验 + 词表回落 + 规则保底，任何解析失败都不得阻断主回复；剧本触发优先确定性条件，LLM 只负责台词生成。
6. **性能预算**：桌宠窗常驻，新增 rAF 动画/参数驱动不得显著抬升空载功耗（参考 pet 电平中继用 audioprocess 而非 rAF 的教训，不可见窗口的定时器会被节流）；v1.9 多 Live2D 实例先 spike 后立项实现。
7. **工程规范**：core 纯函数内核 + 全单测、web 薄渲染；文件 ≤300 行；i18n 双语随版；系统产出文案走线格式 key；新表进备份四轨与恢复测试。
8. **不复制 Servant**：净室实现，剧本/提示词/配置全部原创（见 [01 第 4 节](./01-Servant借鉴分析.md#4-许可与合规结论写入每版评审检查单)）。
