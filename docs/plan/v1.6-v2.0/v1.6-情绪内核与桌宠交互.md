# v1.6「有情绪」· 情绪内核与桌宠交互

> 主题：让角色的心情**跨轮存在**、让桌宠**摸得到反馈**。
> 基线：v1.5 封版后 main；分支建议 `feature/v1.6-emotion`
> 依赖：无（本路线的地基版本）
> 机制来源：Servant SoulState / 双 JSON 情绪协议 / 触摸与微动作（净室重实现，见 [01 许可结论](./01-Servant借鉴分析.md#4-许可与合规结论写入每版评审检查单)）

---

## 1. 目标（全部可机械验证）

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 情绪/关系状态机 | mood(happiness/anger/sadness)+relation(intimacy/trust)+need 的纯函数内核（应用事件/指数衰减/归一化），单测覆盖 ≥90%；每助手独立、持久化、可重置 |
| G2 | 结构化情绪输出协议 | chat 回复带 emotion(8 标签)/intensity(0..1)/soulEvent，zod 校验 + 词表回落 + 规则保底；协议非法时主回复零影响；表情由「基线情绪+本轮情绪」融合决定 |
| G3 | 情绪注入对话 | system prompt 注入当前状态中文文案；记忆开关/关闭情绪开关双态可关；7B 真机一轮通过且情绪合法率有统计 |
| G4 | 桌宠触摸升级 | 头/身分区反馈：摸头弹性+害羞表情+概率短句；连摸保护期彩蛋；身体/头部交互互不误触（拖拽不触发、tap 不误放大） |
| G5 | 生命感微动作 | A 档自主微动作（视线漂移/偷看/参数级小动作）配置化，按 interval+probability 调度；仅桌宠/形象栏可见时运行 |
| G6 | 久别与被忽略 | 久未交互回应用「想念」类反应；应用回到前台/重新开聊有迎接反应（确定性，不额外发 LLM 或复用 proactive 单飞） |
| G7 | 可见可控 | 设置中「情绪与互动」面板：开关、当前状态查看、重置；全部新文案中英双语；备份覆盖新表 |

## 2. 功能清单

### P0（不做不封版）

1. **情绪内核（core 纯函数 + SQLite）**
   - shared：`emotion` schema（值域、事件类型、版本号、zod）；MessageKey 词条域 `emotion.*`。
   - core：`applyEmotionEvent / decayEmotion / fuseExpression`（基线 mood + 本轮 emotion → 展示表情与权重）；数值初版采用 Servant 量级（praise +8/+2/+1、chat +0.25/+0.1、belittle −6/+8/+8/−1/−2；衰减 0.98/0.97/0.995），全部抽为具名常量便于真机调参。
   - 存储：v022 迁移 `assistant_emotion_states(assistant_id PK, state JSON, updated_at)`；助手删除级联；备份/恢复测试。
   - 衰减时机：读写时按 elapsedMs 惰性计算（不依赖常驻定时器），避免不可见窗口唤醒。
2. **情绪输出协议（chat/stream 扩展）**
   - 模型输出尾块协议（单一 JSON 即可，replies 分条留 P1）：`{emotion,intensity,soulEvent}`；解析复用现有结构化清洗工具。
   - 回落链：非法 JSON/词表外/弱模型 → 规则保底（夸赞/贬损中文显式模式，白名单短词表，宁可漏判不可误伤）→ 全失败给 neutral/chat。
   - `expressionEnabled=false` 或新「情绪状态」开关关闭时：不请求、不注入、不展示，但存储层不删旧数据。
3. **表情融合与 Live2D 落地**
   - `fuseExpression`：高 intensity 本轮情绪可短时压过基线，低落基线会给 joy 「降档」（具体曲线 M0 出文档、单测锁死）。
   - avatar-host/pet 中继：表情不再仅来自当前消息标签；消息结束后表情随情绪余韵保持一段时间再回 idle，不再瞬间清零。
4. **桌宠触摸交互**
   - 摸头：命中盒已有 → 头部 pointerdown 触发弹性（CSS/PIXI 参数 200ms 级）+ Blushing/Wronged + 概率短句（走 proactive 同款轻量轮或本地固定文案，**不每摸都发 LLM**，带日上限与冷却）。
   - 连摸保护期：窗口内 N 次 → Angry/Wronged + 「再摸收费」类短句彩蛋（文案原创），冷却期内 tap 给默认反应；N/窗口/时长写配置。
   - 维持 v1.0 经验：身体 drag 区吞指针，头部 no-drag，不引入「一拖就放大」回归（pet-window e2e 加断言）。
5. **A 档微动作调度**
   - 一份内置 `micro-dynamics.config.json`（原创结构，参数名对齐 Live2D：ParamAngleX/Y、ParamEyeLOpen、ParamBrowLY 等）：规则含 intervalMs 区间、probability、幅度；按模型声明支持的参数，缺失跳过。
   - 控制器挂 PIXI ticker（不可见/语音忙碌/演出播放时让位）；React 仅承载开关。
6. **情绪面板（设置域）**：状态查看（等级文案，不展示裸数字恐吓用户）、重置、两个开关（情绪状态/互动音效与短句）、频率不在本版（v1.7）。

### P1（争取）

- replies 分条气泡（首条即出、后续节奏 reveal）；气泡/动作双时间线的轻量实现（余韵保持）。
- 视线跟随：鼠标在桌宠区域时 ParamAngle 缓动跟随，离开后偶尔 avoid/peek。
- `emotion_events` 轻量流水（仅类型/强度/来源/时间 + message 外键），为 v2.0 铺路。
- 形象栏（主窗 rail）同步触摸与微动作（当前仅 pet 有交互）。

### P2（明确留白）

- 人格权重六参数、剧本 branch 条件 → v1.7。
- 音效资产（本版仅允许一个可选的极轻提示音开关，默认关；不引入 Servant 音频资产）。
- 多助手/协作角色的情绪 → 永不做多情绪实例（单助手维度）。
- 情绪驱动的 TTS 情感参数（等 v1.8 调优中心与厂商能力盘点后做）。

## 3. 架构影响

- `packages/shared`：schemas/emotion、i18n 词条、SSE/IPC 协议字段增量（emotion-state、interaction 事件）。
- `packages/core`：emotion 域新模块（state/decay/fuse/guard 纯函数 + repo）；chat orchestrator 注入与回流接线；上下文构建加情绪段（可开关）。
- `apps/web`：avatar-host/pet-stage 表情源改造、触摸 hook、微动作控制器、设置面板。

- 迁移/备份：v022 + 备份四轨 + 恢复后状态可见。
- 2D 适配映射详见 [02 §3](./02-关键机制深拆.md#3-abc-档微动作--触摸交互v16-体验层)。

## 5. 风险与取舍

- **弱模型不吐情绪字段**：协议设计为「增强而非依赖」，保底规则在 core、可测可关；eval 三态验收。
- **情绪值设计感太重/太儿戏**：首版数值保守、增长缓慢（聊天一轮 +0.25），UI 只给等级文案；所有常量集中，准备真机后热调。
- **摸头彩蛋变骚扰**：短句冷却 + 日上限 + 默认不发声（纯表情动作为主），LLM 短句复用单飞，绝不因触摸打断当前对话/语音。
- **空载功耗**：微动作仅在可见时跑，截尾在暂停恢复时校准；真机录空载 CPU/帧率前后值。
- **不做什么**：不做心情日记分享、不做情绪数值排行榜式 UI、不做外部模型任何入口。
