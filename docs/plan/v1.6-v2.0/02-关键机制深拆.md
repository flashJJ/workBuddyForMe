# 02 · 关键机制深拆与 WorkBuddy 适配映射

> 本篇回答「Servant 的陪伴感到底由哪些机制构成、每个机制搬到 Live2D/Electron 上变成什么」。
> 所有数值/字段名均来自 Servant 源码实读，**数值是起点不是教条**——v1.6 立项时以真机调校为准。

---

## 1. SoulState：情绪与关系的最小数值模型（v1.6 地基）

### 1.1 数据结构（`src/soul/types.ts`）

```text
mood      = { happiness: -100..100, anger: 0..100, sadness: 0..100 }
relation  = { intimacy: 0..100, trust: 0..100 }   // 初值 20 / 30
currentNeed ∈ none | attention | comfort | play | rest
recentEvents: ≤10 条 { type, description, timestamp }
```

- **事件只有三种**：`praise`（开心 +8、亲密 +2、信任 +1）、`chat`（亲密 +0.25、信任 +0.1）、`belittle`（开心 −6、生气 +8、难过 +3、亲密 −1、信任 −2）。
- **指数衰减**（`SoulDecay.ts`，按离线分钟数）：happiness ×0.98^min、anger ×0.97^min、sadness ×0.995^min。情绪是「激起后自然平复」的临时量，关系是慢变量——**情绪与关系分层**是这个模型最值得抄的一点。
- 归一化集中在 `normalizeSoulState`（夹值域、recentEvents 截断、坏数据回落），所有写入路径必经。

### 1.2 怎么进模型、怎么回流（`SoulPrompt.ts` + 对话协议）

- 每轮 system prompt 注入一段「当前真实状态」：开心=明显、亲密度=逐渐建立、当前需求=陪伴……并明令「不得擅自修改或声明修改这些数值」。
- LLM 在每轮回复的元数据 JSON 里回流 `soulEvent: praise|chat|belittle`——**情绪变化由模型对用户话语的判定驱动**，不靠关键词硬编码。
- 人格权重 `PersonalityWeights`：directAffection / verbalDenial / physicalLeak / hideWhenShy / needComfortWhenAngry / teaseTolerance 六个 0..1 参数（直率度/嘴硬度/肢体泄露/害羞就躲/生气求安慰/调戏容忍），让「同一个情绪数值、不同性格演法不同」，也是剧本 branch 的条件输入。

### 1.3 → WorkBuddy 适配（v1.6）

| 决策 | 结论 |
|---|---|
| 存储 | 新增 `assistant_emotion_states`（每助手一行，JSON 列 mood/relation/need/updatedAt）+ `emotion_events`（轻量流水，供 v2.0 关系曲线与回顾）；v022+ 迁移，随备份四轨带走 |
| 作用域 | 情绪是「用户×助手」关系，跟随助手切换；协作三角色不各自有情绪（沿用 Servant 多人链路裁剪 soulEvent 的先例） |
| 回流协议 | chat/stream 元数据扩展 `emotion/intensity/soulEvent`，**zod 校验 + 越界确定性回落**（neutral/chat，不阻断回复）——v1.5 教训：弱模型无视软约束 |
| 弱模型 | 7B 回流不可靠时退化为「规则保底」：含显式夸赞词→praise、显式贬损→belittle、其余 chat；保底在 core 做、可测 |
| i18n | 注入模型的状态文案固定中文（沿用 v1.5 模型边界）；调试页/UI 展示走 MessageKey |
| 差异增强 | need 不做自动推导（Servant 也基本是占位），v1.6 只由剧本事件显式设置；long-term 关系增长曲线 v2.0 再调参 |

## 2. 双 JSON 情绪输出协议（v1.6）

Servant 主 LLM 每轮输出**两个连续 JSON**（旧的 `<emotion>` 标签协议已废弃并被 sanitizer 剥离）：

```json
{"speech":"你又在逗我吗？","emotion":"shy","intensity":0.7,"shortAction":"shy_small","ttsEmotion":"sad"}
{"replies":[{"speech":"别这样看我。","emotion":"shy","intensity":0.6}],"soulEvent":"chat","memories":[]}
```

要点：

1. **脸与身体分离**：`emotion`（词表 PERSONALITY_MOODS，intensity 表情权重下限 0.55 保证看得见）管 VRM 表情 + B/C 档微动作；`shortAction`（词表=情绪组合动作配置）管身体；两者互不越界，词表外值统一回落默认动作。
2. **分条 replies 模拟真人连发**：首条立即出，后续按「约 10 字/秒」延迟逐条吐，`turn-end` 后剩余条目 150ms 快速排空，避免「服务端说完了 UI 还在打字」。
3. `ttsEmotion` 只进 TTS 文本，不进气泡、不进历史；`memories` 至多 3 条记忆候选。
4. 气泡可见性与说话动作是**两条时间线**：动作在音频结束前 1s 收，气泡在音频真结束后再留 5s。

**→ WorkBuddy 适配**：

- emotion 词表直接复用现有 **8 标签**（neutral/joy/anger/sadness/surprise/disgust/fear/smirk），Live2D 表情映射表 `avatar-models.ts` 已有，零新增资产；intensity 映射为表情设置权重 + 动作幅度。
- 不新造解析栈：在现有 chat orchestrator 的结构化解析层加可选 JSON 尾块（v1.5 已有 Markdown/噪声清洗工具），解析失败整段降级为普通流式回复。
- 「分条气泡」v1.6 先做轻量版：模型可选产出 replies，前端按固定节奏 reveal；不强求 Servant 的延迟曲线精调。
- TTS 情绪标签（如豆包 `[开心地说]`）只对明确支持的厂商开启，且只进 spokenText——与 v1.5 stripForTts 管线衔接。
- 口型继续走现有 RMS 电平（Servant 后期改为 MFCC 分析真实音频，WorkBuddy 的 RMS 方案真机已验证，**不换**）。

## 3. ABC 档微动作 + 触摸交互（v1.6 体验层）

### 3.1 Servant 的设计

- **微动作配置**是一个带版本号的 JSON（`micro-dynamics/config.ts` 强校验）：相机位、表情/骨骼/morph 绑定、scheduler.rules（intervalMs 区间 + probability）、actions（tier A/B/C、durationMs、easing、多轨道关键帧 at∈0..1）。A 档=调度器自发的待机小动作，B/C 档=情绪播放时叠加的伴随动作。
- **触摸交互**（`CharacterInteractionController` + 配置 JSON）：头部命中 squash 弹性（210ms sin 曲线按压缩放）；`windowMs` 内连续摸头达 `triggerCount` 进入 `protectDurationMs` 保护期，按概率播语音警告（连续摸头要收 token 笑话）；idle 间隔区间内按权重表随机放动作；角色旁显示 listening/thinking/typing/searching 状态；视线 user/avoid/peek。
- 3D 射线命中测试区分头/身。

### 3.2 → Live2D 适配

| Servant（3D） | WorkBuddy（2D Live2D） |
|---|---|
| 射线命中头/身 | Live2D 模型原生 **HitAreas**（model3.json 已定义 Head/Body，Mark 缺失需回落全画布头部热区，pet-stage 已有头/身双命中盒先例） |
| 骨骼 squash 弹性 | 容器 CSS transform 弹性（scale 210ms 曲线）+ Live2D 参数（ParamAngleX 缩脖、ParamEyeLOpen/ROpen）组合；PIXI ticker 驱动，不进 React render |
| VRMA 情绪组合动作 | motion group 随机播放（已有 idleGroup/tapGroup 机制，扩展 emotion 触发组表，按模型能力声明缺失回落） |
| A 档微动作（呼吸/眨眼/视线漂移） | 呼吸/眨眼样本模型自带 motion；额外加 **参数级**小动作：ParamAngleX/Y 随机微摆、视线偶尔移开（avoid）再偷看（peek）——纯配置 JSON：interval 区间 + probability + 幅度，复用 Servant 的调度结构，轨道值改为 Live2D 参数 |
| 久不理会反应 |  Electron `powerMonitor`/空闲计时（Web 侧用已有 idle 探测）+ 情绪 need=attention，触发一个小动作或一条短句（复用 v1.0 proactive，v1.7 后升级为剧本） |
| 连续摸头保护期彩蛋 | 纯前端计数状态机 + 表情（Wronged/Angry）+ 可选音效（音效默认关、sfx 音量独立，参考 Servant 人声/音效分轨） |

**约束**：所有动作/参数配置是 `public` 下随包 JSON 或内置常量，**不开放模型文件导入**；配置面板（若做）只允许切换内置组合。

## 4. 事件引擎：声明式「演出编排」（v1.7 核心）

### 4.1 引擎结构

- `EventDefinition = { id, title, priority, interruptPolicy: replace|replaceLowerPriority|ignore, cooldownMs, maxPerDay?, steps[] }`
- step 十类：`motion / action / expression / gaze / accessory / spatial / fx / speech / wait / branch`；branch 的 condition 是**白名单表达式**（正则限定 `path op number`，path 只解析 emotions/relationship/personality/counters，杜绝任意求值）。
- `EventDirector`：单当前事件 + FIFO 队列；冷却与每日次数闸门；打断 = abort 当前 + 立即停特效/动作；支持 skipStep/replay/replayLastEvent。
- 触发器两条路：内置 16 种 `UserActionIntent`（praise/comfort/apology/userReturn/tailPoke/goodnight/birthdayToday…）与**自定义触发器**（phrasePatterns + cooldown + constraints{minRelationship,timeRange,maxPerDay}）。
- 剧本是纯 JSON 文件（内置 13 个：晚安仪式、生日、纪念日、欢迎回家、摸头偷看、害羞躲屏幕、傲娇生气、开心到跳、铁盆彩蛋、下班陪伴……），写剧本不碰渲染代码。

### 4.2 → WorkBuddy 适配

- **step 集裁成 Live2D 版**：`expression`（8 标签+权重+时长）、`motion`（内置 motion group 名）、`gaze`（参数方向）、`speech`（走现有 TTS 单出口，语音占用锁——新剧本在说话时只排队不强占）、`wait`、`branch`、`fx`（v1.7 限定为 DOM/CSS/Canvas2D 轻粒子：爱心、汗滴、星星；不引 3D 粒子库）、`spatial`（2D 走位：桌宠横向滑到屏幕边/躲出边界再回来，复用 pet 窗 setPosition 能力）。砍掉 accessory（无尾巴耳朵骨骼）。
- 引擎放 **core 纯函数 + 一个演出 player（web）**：队列/优先级/冷却/条件求值全部 core 单测；player 只把 step 映射到 Live2dController/TTS/窗口桥。复刻 v1.4「内核可注入、UI 可替换」的成功结构。
- **无人值守红线**：剧本只在 UI 会话（主窗或桌宠开启）时演；api/mcp/Flow 触发只写「待演事件」，UI 上线后消费，绝不静默驱动桌面。
- 自定义短语触发器要做**成本护栏**：匹配在本地规则层完成（复用提醒触发器 ConversationTriggers 的否定/描述规则识别经验），每轮对话最多评估一次、不额外发 LLM 请求。
- 内置剧本全部**重新撰写**（版权与语气都要贴合 WorkBuddy 助手人格），首批 8 个左右，见 v1.7 分册。

## 5. 多角色会议与 Galgame 舞台（v1.9）

Servant 的两个独立但互通的设施，机制要点：

1. **角色档案** `{name, avatarId, characterCardId, voiceId, vrmId, isMain}`：人格（卡）、声音、形象三件套自由组合。
2. **会议三调度模式**：manual（正文 `@角色`）、all（全体按序）、auto（模型在末尾 JSON 给 `next_speaker_id` 建议，调度器校验合法后接龙，上限 8 轮）。
3. **防串角双通道**（最容易抄错的设计）：system 里放最近 20 条**带标注转录**（`[用户·称呼]` / `[角色·名字/id]`）+ 身份规则；messages 只放**一条 user 发言锚点**且尾条永远是 user，避免模型把队友的话当自己的、或面对 assistant 结尾失去续写目标。
4. 串行发言：单 AbortController，同一时刻只有一个角色在请求；桌面等 `speech-playback-completed` 再放下一位，迟到语音直接取消。
5. **舞台**：全屏无标题栏；底栏 3.2s 淡出；拖拽站位、滚轮缩放角色、Ctrl+滚轮缩放画面；场景=背景+站位+显隐+灯光，可命名保存；背景支持内置/透明/本地图（20MB/4000 万像素、亮度模糊裁切，文件存数据目录）；灯光共同光照优先于单角色；名字牌=名字/表情/动作一行纯文字（字号+颜色分层，不做色块）；H 隐藏 UI、F11 全屏、Esc 逐层退出、无 UI 截图。

### → WorkBuddy 适配

- v1.9 有两个不同场景，**不要混成一个功能**：①**协作可视化**（v1.4 三角色 run 的只读演出，数据已在 agent_runs/handoffs，舞台是渲染器）；②**会议模式**（用户发起的开放讨论，新建会话存储，结构对齐 Servant meeting 的本地存储 + 防串角协议）。
- 2D 舞台：横向立绘站位（当前发言者放大/居中/提亮，其余缩小半透明）、Live2D 同台多实例必须先做**性能 spike**（PIXI 多模型同页开销；备选：单 canvas 多 stage 或静态立绘+仅当前发言者 Live2D）。
- 「灯光」降维成 2D 滤镜层（暖色 multiply、亮度/对比/模糊），背景支持纯色/渐变/内置图/本地图；场景 JSON 存设置库。
- 音频仍是**唯一 AudioContext**（v1.0 宪法）：多角色共用一个 TTS 通道顺序播放，音色差异先靠「角色→可选 TTS voice 映射」，能力不足时同音色也接受；不为此开多音频管线。
- 窗口形态：Electron 独立全屏舞台窗（几何保存/恢复，参考 Servant set_desktop_stage_mode），桌宠↔舞台互斥切换，复用 pet 窗生命周期管理经验。

## 6. 角色卡、皮肤、模型调优（v1.8）

- **角色卡 = Markdown 数据 mod**：frontmatter（name/description）+ 约定章节（我是谁/行为动态/表达质感/诚实边界），解析成 `PersonalityConfig{identity,traits[],speakingStyle[],boundaries[],defaultEmotion}`；卡库支持多卡、activeId、导入删除、**全局追加提示词**（独立于卡的一份全局附加段，插在卡之后）。→ WorkBuddy：与现有助手 system prompt 字段做**兼容映射**（旧字段=自定义卡的一张），卡库落 SQLite/文件，导出为 `.md`/`.wbfm-card.json` 分享；不含任何模型资产。
- **皮肤**：Servant 单字段三主题（夜金暗/月白亮/樱梦亮），本质是色板+明暗外观。→ WorkBuddy 已有 HSL CSS 变量明暗两套（shadcn 体系），加 `data-theme="xxx"` 多套色板即可，主题色可再放开有限几档个性化；水合同步 localStorage + `<html>` 属性的机制 v1.2 已有，直接沿用。
- **模型调优**：Provider 注册表（id/label/apiKeyUrl/models[]/defaultModel）+ temperature；上下文条数 2–50 由**契约层常量**钳制、服务端不信任前端。→ WorkBuddy 基座更强（provider CRUD、助手绑定、协作角色独立绑定），缺的是：生成参数（temperature/top_p/max_tokens）露出、上下文条数用户可调、情绪输出开关、TTS 播放参数（语速/响度，按 MeloTTS 实际能力）、音色命名收藏（localVoiceLibrary：provider+model 分级、当前生效项反推高亮）。

## 7. 每日记忆仪式与提醒调度（v1.7 / v2.0）

- 提醒：once/daily/weekly 持久化任务文件、FIFO、重启不丢、作为 LLM 工具可增删改查——WorkBuddy 当前 proactive 是「空闲搭话」单点，v1.7 升级为**角色开口的提醒调度**（SQLite 持久化，复用现有任务/通知通道）。
- 每日记忆：按用户 IANA 时区读前一天消息（≤100/批）→ 独立记忆 LLM（默认本地，云端需用户显式选择）提取长期事实，完成日期落盘防重。→ WorkBuddy v0.5 已有记忆提取，v2.0 借的是**仪式感包装**（晨报/当日小结由角色「讲」出来）与 `relationship/event` 记忆类型对 SoulState 的喂料，不重写检索（RRF 不动）。
