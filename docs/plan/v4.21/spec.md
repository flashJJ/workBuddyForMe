# v4.21 规格：记得住、管得住

> 状态：M0 契约已冻结（2026-11-22）
> 选题：[README.md](./README.md) · 契约：[contracts.md](./contracts.md) · 任务：[tasks.md](./tasks.md)
> 上游：v4.20 已发布（`v4.20.0`）
> 原则：零迁移优先；迁移必须可回滚并带备份校验；解释与导出不泄露正文

## 1. 背景

v2.26 把长期记忆做成双时态、混合召回与可审计写入；v2.28 补了统计、审计轮转与约束撤销；v4.20 让寒暄轮不再产生记忆提取。但召回语义、冲突处理与用户治理仍分散：

- 场景与预算没有单一入口，通道权重散在调用点；
- 同实体多值时按写入顺序取胜，用户无法理解为什么是这条；
- 用户只能撤销约束或删除，缺少固定、降权、合并；
- 召回结果不可解释，评测以单测为主。

## 2. 目标

### 2.1 统一召回入口

- 新增唯一入口 `recall(scene, budget)`，场景决定启用通道、权重与预算；
- 通道至少覆盖：关键词、向量、最近使用、关系、图边（已有能力）；
- 返回统一结构：`id / content / channel / score / createdAt / source / reason`；
- 超预算按通道配额裁剪，裁剪顺序稳定、可复算。

### 2.2 冲突与过期

- 同实体多值时保留候选集合，只注入裁决后的值；
- 裁决顺序：用户固定 > 新鲜度 > 置信度 > 稳定排序；
- 输出裁决理由：`pinned / fresher / higher-confidence / stable-order`；
- 落选值仍可查询，但不注入上下文。

### 2.3 用户治理

- 动作：固定、升权/降权、合并、删除（归档语义）；
- 全部写 `actor='user'` 审计，可在统计卡与审计列表追溯；
- 操作幂等：重复固定/降权不产生重复审计；
- 撤销后回到上一状态，不做物理删除。

### 2.4 解释与评测

- 设置页新增只读「最近召回」：场景、命中通道、命中时间、裁决理由、忽略原因；
- 不展示正文摘要、不新增云端上报；
- golden 集扩展：冲突、过期、固定、降权、合并五类；
- 评测结果可写入回放历史做相对对比。

## 3. 非目标

- 不做记忆社区聚类与主题簇摘要（长期挂账）；
- 不做跨设备云同步；
- 不做 LLM 关系抽取与指代消解的自动写入；
- 不更换嵌入模型或重建向量索引；
- 不重做设置页视觉风格；
- 不把记忆解释做成聊天内提示（只放在设置页）。

## 4. 验收标准

1. 固定 golden 集上，`recall` 的命中集合与顺序可复算；
2. 冲突场景输出裁决理由，且与裁决顺序表一致；
3. 固定/降权/合并/删除均写 `actor='user'` 审计，重复操作不重复写入；
4. 撤销后状态与操作前一致；
5. 解释面板只含元数据，不含正文、令牌与绝对路径；
6. 记忆导出（若实现）同样不含正文摘要；
7. 关闭新开关时行为与 v4.20 一致（如引入开关）；
8. `pnpm check` 与 `pnpm verify:local` 全绿，定向 E2E 通过。

## 5. 里程碑

| M2 | 冲突裁决与解释结构 + golden 用例 | 是 |

## 6. 质量约束

- 单文件 ≤300 行、目录直接文件 ≤12、循环依赖与 surface 门禁不退化；
- 召回与裁决优先纯函数，便于单测与回放；
- 解释与导出遵循同一隐私约束：不读正文、不含路径；
- 迁移若发生，必须提供回滚脚本、备份校验与升级说明。
