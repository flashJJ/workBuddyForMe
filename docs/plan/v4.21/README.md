# v4.21 选题与范围（草案，待 M0 评审）

> 状态：计划中（2026-11-22）——主题「记得住、管得住」：统一召回、冲突裁决与用户治理
> 规格：[spec.md](./spec.md) · 任务：[tasks.md](./tasks.md) · 契约：M0 产出
> 上游：v4.20 已发布（`v4.20.0`，2026-11-22）
> 约束：零迁移优先；若必须迁移，必须可回滚并带备份校验；不新增无法随 standalone 打包的依赖

## 1. 当前基线

v4.20 把「快」收口：四段指标、首字预算、长会话窗口化与冷启动拆分都已上线。接下来最明显的欠账不在性能，而在记忆：

- 召回语义分散在 `memory-match`、`memory-embedding`、`memory-retriever`、`relationship-memory`、`graph/memory-edges` 等处，场景与预算没有单一入口；
- v2.28 做了统计卡、审计轮转与约束撤销，但「为什么这条被记住 / 被忽略」仍不可解释；
- 同实体多值时缺少统一裁决，冲突结果依赖写入顺序；
- 用户只能撤销约束与删除，缺固定、降权、合并这些中间治理动作；
- 记忆 golden 集仍以单测为主，没有接入回放历史观察策略变化。

## 2. 候选方案

### 方案 A「记得住、管得住」——统一记忆治理（推荐）

**痛点**：记忆能写、能召回，但不可解释、不可精细治理；用户无法判断该信任哪条。

**做法**：

1. 统一入口 `recall(scene, budget)`：场景预设、预算分配、去重与冲突裁决集中到一处；
2. 冲突与过期：保留来源与时间；同实体多值按新鲜度/置信度裁决，并给出理由；
3. 用户治理：固定、降权、合并、删除，全部写 `actor='user'` 审计；
4. 只读解释：最近召回、命中通道、被忽略原因，不展示正文摘要；
5. 评测：golden 集接入回放历史，策略变化可对比。

**验收**：固定输入召回结果可复算；冲突裁决有解释；用户操作可撤销、可追溯。

**成本/风险**：中高。语义复杂，但已有双时态、混合召回、统计与轮转基础，复用面大。

### 方案 B「编排升级」——Controller Pipeline + DAG 并行

**痛点**：多智能体仍串行，缺少预算共享、幂等键与结果合并。

**做法**：Collector → Source → Packer 统一上下文来源；并行执行预算共享、失败隔离与审查合并。

**成本/风险**：最高。回归面大，收益偏架构，当前没有明确并行需求。

### 方案 C「文档可信」——存量重解析与低质输入收口

**痛点**：v2.29 只解决了新文档质量，存量文档、OCR 与关系抽取仍有欠账。

**做法**：批量重解析、低质输入提示、OCR 质量分级与关系抽取补全。

**成本/风险**：中高。需要独立评测集，容易变成长期项目。

### 方案 D「陪伴内容」——舞台与桌宠内容包更新

**痛点**：内容新鲜度不足，场景包/道具包已有管道但缺少持续供给。

**做法**：新增剧本与动作包、内容刷新与发布校验。

**成本/风险**：中。价值直接，但更偏内容运营，工程增量有限。

## 4. 立项建议

**建议 v4.21 采用方案 A「记得住、管得住」作为主线**，理由：

1. 记忆是跨会话体验的核心，当前「能召回但不可解释」是最高频的信任缺口；
2. 双时态、混合召回、审计轮转、撤销与统计都已存在，本版主要是收口与接线，不是从零造；
3. 可零迁移或一次纯加法迁移完成，验收面清晰；
4. B/C 回归面或评测成本更高，D 更适合作为任意版本的 P2 并入。

**建议并入项**（各自独立验收，不阻塞主线）：

| 归属 | 内容 | 来源 |
|---|---|---|
| 并入 | 记忆导出（Markdown/JSON，不含正文摘要） | v4.20 健康度导出的同类能力 |
| 并入 | 知识「新建任务」回填任务结果到知识库（只提示，不自动写入） | v4.20 M4.4 后续 |
| 后续 | Controller Pipeline / DAG 并行 | v4.20 非目标 |
| 后续 | 视觉巡检 L2/L3、云端性能上报 | v4.20 非目标 |

## 5. 初步范围

### 5.1 统一召回入口

- `recall(scene, budget)` 作为唯一入口，场景决定通道与权重；
- 预算包含条数上限与 token 上限，超限按通道配额裁剪；
- 返回结构带命中通道、时间、来源与裁决理由。

### 5.2 冲突与过期

- 同实体多值保留全部候选，但只注入裁决后的值；
- 裁决优先级：用户固定 > 新鲜度 > 置信度 > 稳定排序；
- 冲突结果可解释：谁被选中、为什么、落选值是否仍可查。

### 5.3 用户治理

- 操作：固定、降权/升权、合并、删除；
- 全部写 `actor='user'` 审计，可在统计卡与审计列表追溯；
- 撤销沿用归档语义，不做物理删除。

### 5.4 解释与评测

- 设置页只读「最近召回」：命中通道、命中时间、被忽略原因；
- 不展示正文摘要，不新增云端上报；
- golden 集扩展冲突、过期、固定三类用例，接入回放历史。

### 5.5 里程碑草案
