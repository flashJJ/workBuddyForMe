# 动效库避坑点

> 每条按「现象 → 根因 → 修复 → 规则」记录。新增问题修复时继续追加。

## 1. 大臂过度外展，动作像伸懒腰

- 现象：鞠躬/叉腰/托腮/打哈欠/拥抱起手时双臂横向张开，肩关节像被反关节拉伸。
- 根因：行为轨道走欧拉姿势，`upperArm.z/x` 直接给了几十度；欧拉角难以表达「大臂微调、小臂主变化」。
- 修复：改用世界方向执行器（`POSE_EXECUTORS`），大臂目标保持在自然下垂附近，小臂用 `aimBone` 完成主要方向变化。
- 规则：大幅度手势不要用大臂欧拉角硬掰；优先世界方向 + 小臂主变化。回归测试断言：大臂相对自然下垂 <40°，小臂变化 > 大臂 1.5 倍。

## 2. 行为起始露 T/A-pose

- 现象：动作切换第一帧双手回到水平绑定姿态。
- 根因：新行为权重从 0 开始，执行器在 `weight=0` 时不写骨骼；Composer 的基准帧是绑定姿态。
- 修复：`BoneCrossFade` 在切换瞬间捕获上一帧手臂姿势，作为 Composer 帧基准；执行器从上一姿势直接向目标过渡。
- 规则：任何「从 0 淡入」的动画都要明确基准姿态；不要假设绑定姿态不会被看到。

## 3. 动作退出/落地回 A-pose

- 现象：手势结束或落地时双手短暂变水平。
- 根因：退出阶段权重降到 0，姿势轨道不再写手臂，且没有 `relaxArms` 接手（行为仍 active）。
- 修复：手势 `exit` 增加 `pose.gesture-hang` 基准轨（不吃权重，始终写垂臂），目标姿势按权重回落；`behavior.land` enter/exit 补手臂回落。
- 规则：退出阶段必须有「基准姿势」；不要只靠目标姿势随权重淡出。

## 4. 双手藏到身体后方

- 现象：叉腰、鞠躬时双手跑到身后，看起来像「后翻」。
- 根因：世界方向目标 `z` 给成负值（后方）；鞠躬时躯干前倾但双臂仍垂直下垂。
- 修复：叉腰前臂目标 z 改到 +0.08；鞠躬双臂略前摆。
- 规则：手部落点用世界坐标采样验证（双手 z 同时 < -0.05 视为异常），不要只看正面截图。

## 5. 被拎起像「练操踏正步」

- 现象：悬空挣扎只有前后摆，左右手/脚同频，像正步。
- 根因：单频正弦 + 同相位/反相位、只有 z 轴变化。
- 修复：多轴（x/z）、多频（1.3–3.5 rad/s）、左右相位差 π、叠加不同频率；手脚频率与幅度不同。
- 规则：悬空/挣扎不要用单一正弦；至少 2–3 个不同频率分量，并同时覆盖左右与前后。

## 6. 被抓住时主体还在摇摆

- 现象：抓点/肩膀跟着 root yaw/roll 晃，像没被抓住。
- 根因：`motion.lift-hover` 给 root 加了 yaw/roll/上下颠。
- 修复：抓住时 root 只保留垂直上提，摆动全部交给四肢。
- 规则：抓取类动作先固定主体，再表现四肢；root 摆动只用于飞行/漂浮等无抓点动作。

## 7. 行为 loop 看起来「停住」

- 现象：hold 阶段四肢不动，只有轻微身体晃。
- 根因：执行器 `t` 固定传 0，`Math.sin(t...)` 不动；或 loop 内没有时间驱动轨道。
- 修复：`ComposeTrack.executor` 增加 `timeMs`，执行器用行为总时长驱动。
- 规则：任何 loop 摆动都要有真实时间源；不要把 `t=0` 写死。

## 8. Golden 测试里执行器「不起作用」

- 现象：执行器行为快照退化为绑定姿态，或与真机不一致。
- 根因：golden 夹具是扁平骨骼（所有节点挂在 scene 下），`aimBone` 没有父子链和偏移。
- 修复：golden 使用简化人形 rest 骨架（spine/neck/head/肩/上臂/前臂/手/腿）。
- 规则：测试世界方向执行器必须提供父子链；不要用扁平节点验证 `aimBone`。

## 9. 场景 beat 比动作短，动作被截断

- 现象：动作还没做完就切回站姿。
- 根因：`moment.*` 最后一条 beat 的 `at` 小于 behavior enter + exit。
- 修复：场景结束时间与动作时长对齐（鞠躬 2300、打哈欠 3100、拥抱 2900）。
- 规则：调整动作时长时同步检查场戏 beat、冷却与轮换节奏。

## 10. 普通动作过快，情绪动作也慢

- 现象：日常手势像偷袭；被拎起等强情绪动作也需要快反馈。
- 根因：所有行为共用 Runner 的 120ms 权重淡入，且动作关键帧偏短。
- 修复：`PhaseDefinition.fadeMs` 按阶段配置；普通手势 500–700ms，被拎起保持 120ms；动作关键帧同步放慢。
- 规则：节奏是动效语义的一部分；按「情绪强度」配置淡入/时长，不要全局统一。

## 11. 手部/腕部残留上一动作的局部旋转

- 现象：切换后手腕看起来折了一下。
- 根因：交叉淡化只应覆盖上臂/前臂，手腕/手指的局部旋转若被一起继承，会残留旧姿势。
- 修复：手势执行器不写手部欧拉；手腕跟随前臂，手指由 `curlHands` 统一；交叉淡化只捕获上臂/前臂。
- 规则：手部是「跟随 + 手型」两层，不要让每个手势单独掰手腕常数。

## 12. 悬空挣扎时手指僵直

- 现象：被拎起后四肢在摆，手指一直保持绑定姿态，看起来很生硬。
- 根因：`pose.lift-struggle` 只写上臂/前臂/腿的世界方向，没有手型轨道；手指只在 enter/exit 的 `curlHands` 里处理。
- 修复：`aimLiftStruggle` 增加 `animateFingers`：四指共享同一伸缩包络（仅微小相位差），拇指用不同频率/相位独立动并带外张；相对 `baseQuat` 写入，避免逐帧累加。
- 规则：手部动效要同时覆盖「手臂朝向 + 手型」；手指分两组：四指协同、拇指独立。

## 13. 帧内自动切换时交叉淡化捕获到 T-pose

- 现象：放下时 `behavior.land` 第一帧双手水平（A-pose），看起来交叉淡化没生效。
- 根因：`lifted exit → land enter` 在 `runner.update()` 帧内完成；此时 Step 1 的 `captureFrame` 已把行为骨骼重置为 mixer 姿势（T-pose），`BoneCrossFade.begin` 再读节点只能读到 T-pose。
- 修复：每帧在 mixer 写骨骼前调用 `rememberFrame()` 缓存上一帧最终手臂姿势，`begin` 优先使用缓存；没有缓存时才回退读节点。
- 规则：交叉淡化起点必须是「上一帧最终渲染结果」；不要在骨骼已被重置后再采样起点。

## 14. 表情只动眼睛，眉/嘴/脸不联动

- 现象：被拎起时只有眼睛有变化，眉、嘴、脸完全没动。
- 根因：家族精简模型把一个网格拆成 11 个 primitive（`Body_Model_up_1..11`），且 morph 名被导出成 `"0".."117"`；执行器按 `Body_Model_up` 精确名查找失败，整个 morph 层降级为不可用。
- 修复：`MorphExecutor` 支持多网格；找不到精确名/名称集合时，按 `Body_Model_up_` 前缀 + morph 数量 + 已校验索引顺序绑定全部 primitive（用 VRM 的 angry 预设索引 24/75/64 与 binding 交叉确认顺序一致）。
- 规则：行为表情不能只认单一网格名；先按名称匹配，再按 target 名称集合匹配，最后才按已验证索引顺序回退。多 primitive 必须全部写入。

## 15. 动作交接「先慢后突然飞快」

- 现象：点击切换动作时前半段很慢，交接瞬间手臂突然大幅跳一下，随后又继续慢慢动。
- 根因：
  - 交叉淡化有 500ms 强制释放上限，慢动作 fade 600–700ms，权重约 0.53 时就被换回 mixer 的 A-pose 基准，一帧跳 38°。
  - `pose.idle-body` 自带 `upperArm.z = ±1.05`，作为动作首尾锚点时会和垂臂基准/目标姿势叠加，导致手臂过转。
  - 一次性动作的 exit 又重新摆出 `pose.bow/yawn/hug`，动作已经回站姿后又弹回目标姿势。
- 修复：交叉淡化只在权重 ≥0.95 后释放；手势 enter/loop 增加 `pose.arms-hang` 基准；一次性动作用 `settledExit`；新增不写手臂的 `pose.idle-torso` 作为动作首尾锚点；行为结束后垂臂权重改为 1。
- 规则：慢动作的淡化起点要一直保留到新姿势权重接近 1；躯干锚点不要顺带写手臂；动作结束的退出阶段不要重新摆出已经收完的姿势。

## 16. 大角度抬臂时手臂「扭一下」或穿过 T-pose

- 现象：伸懒腰、端碗等动作中，手臂有一瞬间横向展开、掌心朝上，像被扭了一下；干饭时双臂绞在胸前。
- 根因：
  - 用欧拉角从垂臂直接插值到上举，会横向穿过 T-pose。
  - 用世界方向 `aimBone` 从垂臂直接指向正上方时方向接近 180°，最短弧会随意选旋转轴，手臂路径不可控。
  - 干饭的端碗姿势用欧拉 x/z 叠加，前臂屈曲轴与上臂不同，容易绞在一起。
- 修复：新增 `pose.stretch-cycle` 与 `pose.eat-cycle` 执行器，把大角度动作拆成「垂臂 → 前平举 → 上举」或「端碗 → 送口」的分段世界方向目标；路径按行为时间驱动，返回沿同一路径。
- 规则：抬臂超过 90° 不要用单段欧拉或直接 aim 到反向目标；至少给一个中间方向（前平举），让路径可预期。

## 17. 伏案起手双手绕到身后

- 现象：`behavior.work-focus` 起手第一帧双手跑到身后，像反关节扭过去。
- 根因：`pose.lean-desk` 用欧拉手臂，且叠加在「上一姿势/垂臂」的帧基准上；同名 `x` 轴实际是沿臂长的 roll，不是前伸，结果依赖进入时的基准姿态。
- 修复：新增 `pose.lean-desk` 执行器，躯干/腿仍用原姿势数据，手臂改为世界方向前伸目标，不再受基准姿态影响。
- 规则：需要「手落到世界某处」的姿势用世界方向执行器；不要用欧拉手臂去猜前后方向，x 轴往往只是 roll。

## 18. 抓起松手后一直挣扎，点击也不切换动作

- 现象：被拎起后松手，角色仍在悬空挣扎；之后点击身体也不怎么切换动作。
- 根因：窗口跟手移动或指针移出命中盒时 `pointerup` 可能收不到，`behavior.lifted` 停在 loop；它 priority 1、`interrupt: 'all'`，后续点击的行为只能排队，永远轮不到播放。
- 修复：`useRaisedGesture` 注册全局 `pointerup` / `pointercancel` 兜底释放；命中盒 `buttons === 0` 的自愈分支也调用 `release()` 与 `endInteraction()`。
- 规则：带 pointer capture 的手势仍要有全局松手兜底；长驻 loop 行为必须保证任何退出路径都能 stop。

## 19. 掌心朝外，看起来像手腕扭到身后

- 现象：伏案起手、待机时双手掌背朝前/掌心朝外，像手腕反折到身后；手臂方向本身是对的。
- 根因：`aimBone` 只对齐骨骼方向，不控制沿前臂轴的 roll；手部 fidget 动作又会覆写手骨，把 roll 带回绑定姿态。
- 修复：新增 `orientPalm`，按前臂轴把掌心旋到目标法线；待机在 fidget 之后统一把掌心转向大腿，伏案执行器把掌心转向桌面。
- 规则：世界方向执行器只解决「手臂指向」，手掌 roll 必须单独校正；手部动作之后要再摆一次掌心。伸懒腰这类抬臂动作也要在前平举阶段把掌心压向下方，否则会翻掌朝上。

## 20. 逐动作补手掌导致越改越乱

- 现象：修好一个动作的掌心，另一个动作又外翻；动作越多，掌心朝向越随机。
- 根因：手骨 roll 没有单一所有者。idle fidget、行为 pose、crossfade 都会继承/覆写手骨，逐动作 `orientPalm` 只是不断新增补丁，补丁之间互相影响。
- 修复：先试过在 `vrm.update` 前统一强制掌心朝内，但伏案/干饭/伸懒腰的掌心语义不同（朝下/朝上/朝前），一刀切反而把正确动作改错。最终引入 `arms/solver.ts` + `arms/intents.ts`：动作只声明意图，方向与 roll 由同一求解器一次算完。
- 规则：一个自由度只能有一个所有者，但「所有者」是求解器，不是一刀切的策略。掌心方向必须按动作意图声明；不要用全局常量覆盖所有动作。

## 21. 掌心局部轴猜反，整只手翻转 180°

- 现象：改完掌心轴后，待机看起来「对」，但伏案掌心朝上、干饭掌心朝下、伸懒腰掌心朝后；肉眼看像每个动作都翻了半圈。
- 根因：手骨局部 `+Y` 是**手背**，`-Y` 才是掌心。之前用 `+Y` 当掌心法线，再配合「朝内」目标，等于把手背转向身体；不同动作的目标法线投影后又被反相，所以上下/前后全错。
- 验证方法：VRM0 经 `rotateVRM0` 后世界 `+X` 是角色左侧；让手臂自然下垂，若「拇指朝前、掌心贴腿」成立，则掌心法线应指向 `-X`，可用拇指方向与掌心贴腿双重校验，别只看单帧截图。
- 修复：`PALM_LOCAL = (0, -1, 0)`；所有掌心意图按真实掌心法线声明（朝内=左手 `-X`、右手 `+X`）。
- 规则：骨骼局部轴必须用「解剖特征 + 世界位置」交叉验证；只凭一个向量或一张截图很容易把内外、上下同时判反。

## 22. 背对时世界方向目标不跟身体转

- 现象：转身/背对后，叉腰、伏案等动作的双手落到身体前面或跨过中线。
- 根因：`PoseExecutor` 只有 `pose.arms-hang` 接收 `frameYaw`；行为轨道里的世界方向目标是固定世界坐标，身体转 π 后左右关系反过来。
- 修复：`VrmAnimationRuntime.setFrameYaw()` 每帧由姿态层写入，Composer 与 `applyPose` 统一把 `frameYaw` 传给执行器；求解器对所有方向与掌心目标做 `applyAxisAngle(Y, frameYaw)`。
- 规则：凡是「世界方向意图」，都必须和角色朝向绑定；不要只给待机路径传转身角。

## 23. 调参越改越乱：同一区域没有写者记录

- 现象：修一个动作影响另一个动作；同一段骨骼被基础 clip、行为、待机垂臂、叠加层反复改写，只能靠肉眼猜是谁最后写的。
- 根因：没有帧级所有权记录。各层靠调用顺序与 `if` 条件避让，条件一改就出现隐式覆盖；数值又散落在动作层，无法追溯。
- 修复（第一步）：新增 `FrameLedger`，每帧登记 `region → owner / priority / weight / intent`；同优先级不同 owner 判为冲突并 dev 告警；`controller.frameDebug` 可查。行为轨道通过 mask 投影成区域 claim，不改变执行结果。
- 后续：把 `winner` 变成真正的写权限，固定 `spine → arms → hands → fingers` 拓扑序；事件只负责 start/stop/interrupt，骨骼值走每帧计划。
- 规则：手指/手臂/脊柱这类共享自由度，先看台账确认唯一写者，再调数值；不要在动作层继续加 `if` 条件打补丁。

## 24. 呼吸/防穿模在手臂求解后改写上臂，掌心被带偏

- 现象：待机或抬臂动作里，掌心朝向偶尔和意图差一点；单独看手臂方向又是对的。
- 根因：`liveliness` 与 `handClearance` 在手臂求解之后绕上臂骨轴微调，手骨作为子节点一起转；掌心的最终 roll 不是 `orientPalm` 算出的那个。
- 修复：手臂求解时登记本帧掌心意图；后置上臂调整结束后调用 `reapplyPalms()`，用当前前臂方向重新滚腕。手部 roll 被定义为手臂子树最后一个写者。
- 规则：任何会改写上臂的后置层，都必须排在腕 roll 之前，或在它之后重新滚腕；不要假设「方向算完，掌心和手一起转过去」还能保持目标朝向。

## 25. 轨道定义顺序决定骨骼写入顺序

- 现象：同一行为换一条轨道的声明顺序，手臂方向或观感就变了；全身体态轨写在手臂轨之后时，手臂像是基于旧脊柱算的。
- 根因：Composer 原来只按 priority + 轨道数组顺序执行，没有阶段概念；多区域轨道与纯躯干轨道混排，顺序依赖声明细节。
- 修复：`stageOfTrack()` 把触及手臂子树的轨道统一归到 `arms` 阶段，纯躯干/腿/头轨道归各自阶段；`compose()` 先按 `STAGE_ORDER` 再按 priority 执行。所有手臂写者仍在同一阶段内保持原 priority 顺序。
- 规则：多区域轨道不要拆到 arms/hands/fingers 不同阶段，否则会打乱手臂写者之间的覆盖关系；阶段只解决「父区域先于子区域」，同一子树内的顺序仍由 priority 决定。

## 26. 台账只记录不拦截，冲突仍会静默覆盖

- 现象：帧台账报告了同优先级冲突，但画面仍被后写者覆盖；知道冲突却无法阻止。
- 根因：`FrameLedger` 在所有写入完成后才记录，`winner` 只是一个展示字段，没有变成写权限。
- 修复：新增 `FramePlan`，在写入前用同一套 `resolveClaims` 决议；`VrmFrameLedger.beginFrame` 生成计划，写者通过 `allows(owner)` 查询是否落败。待机垂臂已接入，同优先级落败时直接不写。
- 规则：冲突检测必须和写权限共用一次决议；不要先写完再检查。低优先级基础层是正常分层，只有同优先级不同 owner 才拒绝后写者。

## 27. 动作采样绕过执行器，与行为姿势两套逻辑

- 现象：行为动作的手臂已经统一求解，但待机余兴/动作的手臂仍是欧拉；同类姿势在两条链路上观感不一致。
- 根因：`applyMotion` 直接 `applyPose`，不经过 `POSE_EXECUTORS`；混合关键帧时更无法用单个姿势执行器处理。
- 修复：新增 `POSE_ARM_INTENTS`（姿势 → 手臂意图）与 `applyMotionArmIntent`；`applyMotion` 先应用姿势/混合，再按 `sample.t` 插值意图并调用统一求解器。未登记意图的姿势（手部 fidget、腿部动作）保持原路径。
- 规则：任何「姿势 + 时间混合」的动作，手臂意图要按 from→to 插值，不要只给关键帧终点加执行器；否则过渡段仍会回退欧拉。

## 28. 内部 MOTIONS 没有运行时入口，看起来像死代码

- 现象：`motion.wave/shy/stretch-up` 在 MOTIONS 里注册并导出，但没有任何场景/待机路径能播放；容易误判为“被改坏的引用”或直接删除。
- 根因：库内容与运行时入口断线。待机轮播走 VRMA 动作池，点击回退走反应/程序化手势，剧本 `motion` cue 依赖 `controller.playMotion`，而 VRM 控制器没有实现它。
- 修复：实现 `VrmController.playMotion(id)`（内部 MOTION 一次性播放）；点击在无 VRMA 手势时回退 `motion.wave/shy`；`pickMotionGesture()` 负责选择。反应开始时清余兴，避免同优先级双写。
- 规则：新增动作库内容时必须同时给出一个可达入口（行为/场景/余兴/兜底），并在 changelog 标注；无引用的内容优先补入口或登记为预览库，不要直接删除。

## 29. 连续点击拥塞与松手后挣扎不停

- 现象：连续点击后角色行为越排越多，最后点不动；抓取松手后悬空挣扎还会继续一段。
- 根因：`BehaviorRunner` 对同级/低优先级请求一律入队且无上限；`setRaised(false)` 走 `stop → 排队 land`，依赖 exit 阶段；场景 behavior cue 也走队列。
- 修复：新增 `playNow()` 强制接管并清空队列，队列上限 4；场景 cue 用 `playBehaviorNow`；`setRaised` 松手直接强制进 `behavior.land`。
- 规则：用户交互和场景新 cue 应该「替换当前意图」，不要排队；只有明确的顺序演出才用队列，并必须设置上限。
- 附带修复：`pose.react-nuzzle` 的大臂欧拉 z 实际是侧展，摸头时手臂会甩到侧面；改为只写头颈 + `HANG` 手臂意图。

## 30. 场景行为 loop 停不下来，待机看起来像「换了个姿势」

- 现象：待机时头歪、手臂停在某个姿势，没有手脚/手指自然微摆；用户以为是待机余兴或待机动作被替换。
- 根因：场景结束后 `behavior.head-pat` 仍在 loop（真机 85 秒）。`VrmCueAdapter.end` 只在「没有其他场景行为」时停止，另一个场景的行为条目会让它跳过；同时行为接管时 `reaction` 不清，`reacting` 残留进一步抑制 relax。
- 修复：场景结束按本场景启动的行为 id 精确停止并清队列；行为 id 不匹配时拒绝停止；行为接管时清空 reaction。
- 规则：loop 行为必须有明确 owner 和结束条件；场景结束按 id 停止，不要用「全局是否还有行为」判断。待机异常先查 `controller.pose.behavior`，不要先怀疑待机 clip/余兴。

## 31. 窗口跟手拖动后 clientY 不再变化

- 现象：拖身体能进入悬空，拖头部不能；窗口在跟手移动，但角色始终不进入拎起姿势。
- 根因：`PetHitHead` 用 `clientY` 计算拖动位移；窗口在 6px 阈值后开始跟手，`clientY` 不再变化，`dy` 永远到不了 24px 的 `RAISED_THRESHOLD_PX`。`PetHitBody` 用 `screenY`，所以只有头部失效。
- 修复：头部按下点与 `dx/dy` 改用 `screenX/screenY`。
- 规则：任何依赖「拖动总位移」的手势都用 `screenX/screenY`；`clientX/clientY` 只适合窗口不跟随的普通拖拽。

## 32. 桌宠大档拎起裁头

- 现象：大小选大后拖起角色，头顶超出透明窗/画布上沿。
- 根因：`PET_SIZE_SCALE.lg = 1.2` 在高度受限的取景结果上再放大，模型本身已轻微超出视口；拎起 `root.y = 0.1` 后头部被裁。只加高窗口也不够——相机会按新高度重新取景，裁切比例不变。
- 修复：窗高 340 → 400；桌宠取景改为「脚底贴底 + 顶部 10% 余量」，放大后的 scale 再被 headroom cap 截断；主窗仍保持竖直居中。
- 规则：存在「角色整体向上移动」的动作时，取景必须为位移预留顶部空间，不能只放大窗口。桌宠脚底贴底比居中更自然，也能把竖直余量集中到头顶。

## 33. 手持道具挂 normalized 骨会缩小 1/100

- 现象：道具挂到 `getNormalizedBoneNode('rightHand')` 后几乎看不见，或位置与手掌差一个量级。
- 根因：normalized bone 带 VRM 的 1/100 归一化缩放；道具作为子节点会继承，模型真实尺度对不上。
- 修复：`VrmPropLayer` 只挂 `getRawBoneNode('rightHand')`；挂载前 `humanoid.update()` 同步 raw，再按 raw 世界矩阵计算本地偏移。
- 规则：骨骼求解用 normalized；场景图/道具挂载用 raw。两者不要混用。

## 34. 持物手型重置手骨会打断掌心 roll

- 现象：持杯时腕部突然扭一下，杯子的相对位置也跟着漂。
- 根因：`applyPose` 的 override 会把姿势里列出的骨骼重置到绑定姿态；早期 `cup-hold` 包含 `rightHand`，在 `reapplyPalms` 之后执行，直接清掉了掌心朝向。
- 修复：`cup-hold` 只写手指；腕部朝向交给 `pose.prop-hold` 的手臂求解器（`PROP_HOLD_RIGHT` 含掌心意图）。
- 规则：持物手型只描述手指屈曲；任何会写手骨腕 roll 的持物姿势必须放在手臂求解器里，不要用 override 姿势覆盖。

## 35. 道具 GLB 异步加载与持物姿态的时序

- 现象：attach 后手臂先抬起、道具稍后出现；或加载未完成时 detach，道具仍被挂上。
- 根因：`GLTFLoader.loadAsync` 是异步的，同步 attach 无法立即 mount；只看加载结果、不校验请求是否已取消就会挂载过期资产。
- 修复：attach 调用时立即登记 `requested` 与 hold（手臂先进入持物姿态）；加载完成后校验 `generation` / `requested` 再 mount；detach 删除 requested，resolve 分支负责 dispose。
- 规则：异步资产不要阻塞姿态；挂载前必须校验请求仍有效。不同道具的握持距离按 manifest 的 `contact` / `lateral` 调整（书 0.10、茶杯 0.048），不要用一个常量套所有资产。

## 36. prop cue 的轨道与场景清理

- 现象：道具挂上后场景结束不消失，或两个场景共用同一道具时被先结束的场景误卸。
- 根因：道具没有进入 Director 的轨道/场景归属；只在 execute 里 attach，没有按场景记录。
- 修复：`cueTrack('prop') = 'world'`（与 body 并行）；`VrmCueAdapter.propScenes` 按场景记录，结束/打断时仅当没有其他场景引用才 detach；未登记 id 直接丢弃。
- 规则：任何「场景创建的资源」都要有场景级 owner 与结束清理；共享资源用引用计数思路，不要直接在 scene end 里无脑销毁。

## 37. 场景道具不能挂 vrm.scene

- 现象：桌子会随角色呼吸轻微浮动，拎起时整张桌子跟着上移。
- 根因：`vrm.scene.position.y` 每帧由呼吸与 root 轨道改写；挂在 `vrm.scene` 下的子节点全部跟随。
- 修复：stage 道具挂渲染 `scene` 根节点，位置/朝向由 manifest 固定；hand 道具才挂 raw hand。
- 规则：跟随骨骼的挂骨骼，跟随世界的挂场景根；两类道具不要共用父节点，否则「道具是角色的一部分还是布景」会失去边界。

## 38. 道具动画不要另起时钟

- 现象：角色降帧/暂停时道具还在动，恢复后与角色不同步；隐藏档回来时道具跳一下。
- 根因：给道具单独 `setInterval`/`rAF`，或使用固定步长而不是主循环 dt。
- 修复：`VrmPropLayer.update(dt)` 由 `VrmController.update` 每帧传入同一个 dt，放在 `vrm.update` 之后、render 之前；采样函数只吃 `elapsedMs`。
- 规则：道具动画、液体、翻页都必须挂在主时钟上；需要暂停/降帧时跟随 `frameMode`，不要自建计时器。

## 39. 剧本动作不要复用触摸反应的 reaction 槽

- 现象：剧本 `motion` cue 播放时被点击打断；或循环动作在场景结束后一直播放。
- 根因：`playMotion` 早期落到 `VrmPoseLayer.playReaction`（待机层 reaction 槽，REACT_MASK 只写上半身、到时释放），点击/待机逻辑会覆盖它；且没有场景归属，循环动作无人停止。
- 修复：新增 `VrmScriptMotionOverlay` 独立槽位，全身 mask + fadeMs 淡入淡出，非循环结束自动释放；`VrmCueAdapter.motionByScene` 记录场景归属，场景结束按 id 停止循环动作（共用不抢停）。
- 规则：触摸反应与剧本动作是两条生命周期，不要共用一个槽；任何循环动作都必须有场景级 owner 与停止路径。

## 40. 行为 cue 的「强制接管 / 按 id 停止」必须在目标层转发

- 现象：剧本切到 `behavior.work-focus` 没生效，画面还是上一个 `behavior.chin-rest`；场景结束后行为一直残留。
- 根因：`VrmCueAdapter` 调用 `playBehaviorNow()` 与 `stopBehavior(id, clearQueue)`，但 `useScriptDirector` 的控制器目标只转发了 `playBehavior()`（同优先级会排队）和无参 `stopBehavior()`（id 被丢弃，无法命中当前行为）。
- 修复：目标层补齐 `playBehaviorNow` 与 `stopBehavior(behavior?, clearQueue?)` 转发，并在 Director 测试中断言 `behaviorNow:*` 与 `stop:<id>:true`。
- 规则：适配器新增可选能力时，目标层必须有同名转发；只测适配器假控制器会漏掉真实接线。

## 41. 模型轮廓之外的桌宠 UI 必须并入 hit proxy

- 现象：鼠标穿透开启时，剧本调试面板（模型右侧/左下的固定面板）点不动；模型本体却可以点。
- 根因：主进程不信任 Windows 穿透转发的 mousemove，改用全局光标 + `PetHitProxy` 轮询决定是否退出穿透；面板在模型轮廓外，永远保持在穿透态，渲染层收不到点击；左下角还被 Next dev 指示器覆盖。
- 修复：`PetHitPolygon` 增加 `ui` 类型；`hit-proxy.ts` 把面板 DOMRect 与模型轮廓拼成同一个 proxy 上报（变化才发 IPC）；面板默认收起并移到右上角。
- 规则：桌宠窗里任何需要点击的固定 UI 都要上报自己的矩形；只写 `pointer-events-auto` 在穿透态下无效。

## 42. 生成剧本必须 fail-closed，且不能复用带状态的原语

- 现象：模型能输出形状合法的场景，但可能把角色留在 sleep/face-away/坐姿，或 attach 道具后不收起；也可能引用未接线 cue。
- 根因：只过 `sceneSchema` 只能保证字段形状，不保证原语注册、状态安全与资源配对。
- 修复：生成专用约束（gen 前缀、触发键白名单、状态 pose/behavior 黑名单、道具成对、禁 VRMA/speak/branch）+ `validateScene`，任何丢弃即整条拒绝；失败回落本地剧本池，失败也消耗一次调用额度。
- 规则：LLM 产物先白名单再入队；生成场景的边界要比手写场景更窄，不要相信模型自觉。

## 43. 剧情状态入账要在副本上改，别改完副本又读原对象

- 现象：`resolves` 收线后，返回的线索仍是 open、悬念还在；单测里看起来「改了个寂寞」。
- 根因：`ingestStory` 先 `threads.map(...)` 生成副本，但 `findThread` 仍在 `state.threads` 里找，拿到的 `existing` 是原对象；改的是原数组，返回的却是副本。
- 修复：`findThread(threads, pending, meta)` 直接在副本数组里查并原地更新，返回的 state 与修改目标一致。
- 规则：不可变更新时，查找与修改必须在同一份副本上完成；测试要断言返回值，而不是只看入账函数的局部变量。

## 44. 低频定时任务不要建常驻定时器

- 现象：Electron/Next 多进程下 `setInterval` 会重复触发，dev 热重载还会叠加；服务重启后窗口记录丢失。
- 修复：`settings_kv` 存 `enabled/date/runsToday/lastRunAt`；客户端 10 分钟心跳调用 tick，服务端用纯函数判断「已过窗口且间隔 ≥4h」；先记窗口再生成，失败也消费窗口。
- 规则：低频任务把「是否到期」做成纯函数并持久化消费记录；不依赖进程内定时器，天然支持重启与多端。
