# 让报告页长出一张卡片：声明式指标如何复用既有汇总

报告页原本只有固定结构：时间窗、链路筛选、成功率、耗时、失败类别，以及 Markdown/CSV 导出。用户想要一张「近 30 天任务成功率」的卡片，只能截图。

能力包提供的报告卡片不能变成查询编辑器。它必须是声明式的：只允许选择指标与窗口，不允许写 SQL、不允许执行代码、不允许定义新的聚合口径。

## 一、卡片契约：四个字段

```json
{
  "title": "近 30 天任务成功率",
  "chain": "task",
  "metric": "success_rate",
  "windowDays": 30
}
```

约束很窄：标题 1–40 字；链路只能是任务、工作流、协作三选一；窗口只能是 7/30/90 天；指标是四个白名单值。

四个指标分别是：成功率、运行数、耗时中位数、失败类别 Top 1。没有「自定义过滤条件」，也没有「按模型/助手分组」。

## 二、数据从哪来：复用运行证据汇总

卡片不在前端算，也不缓存快照。报告接口在返回 JSON 时，服务端按启用卡片逐一计算，然后附在同一个响应里：

```ts
{
  from, to, filter, totals, chains,
  widgets: [{ id, title, metric, windowDays, value, failureCode }]
}
```

每个卡片的窗口是「今天往前 N 天」，与主报告的查询窗口独立。这样做有两个好处：用户切换主报告时间窗时，卡片不会跟着乱跳；卡片口径固定，适合「长期观察」。

计算复用已有的运行证据服务：它把三张运行表（任务、工作流、协作）归一成同一组统计量——总数、成功/失败/取消/运行中、成功率、耗时中位数、失败码分布。卡片只是从这组统计量里取一个字段。

## 三、四个指标如何映射

| 指标 | 取值 | 空数据表现 |
|---|---|---|
| 成功率 | 终态里成功的占比（百分比两位小数） | 显示「无样本」 |
| 运行数 | 窗口内总运行数 | 0 |
| 耗时中位数 | 已完成运行的耗时中位数 | 显示「无样本」 |
| 失败 Top 1 | 失败码分布的第一名与次数 | 显示「无失败」/「无样本」 |

成功率的分母只算终态，运行中的不参与；这是既有汇总口径，卡片不重新发明。

## 四、为什么不在前端算

前端算需要把三张运行表的数据全部拉到浏览器，再按卡片逻辑聚合。这会让报告页的响应体随运行数增长，也会让「指标口径」出现两份实现：一份在前端，一份在导出。

服务端算还有一个安全收益：卡片配置来自能力包，属于外部输入。让服务端只按白名单取值，外部输入最多影响「显示哪一项」，不会变成查询能力。

## 五、坏卡片不能拖垮报告页

卡片行可能被手改数据库、被旧版本写坏，或者 JSON 损坏。处理原则是**跳过，不报错**：

- 配置 JSON 解析失败 → 跳过；
- schema 校验失败（未知指标、非法窗口）→ 跳过；
- 计算时拿不到链路汇总 → 跳过。

报告主结构照常返回。用户最多少看到一张卡片，不会整页 500。

停用或卸载卡片会直接删行，因为卡片没有历史数据可保留；下一次请求自然不再出现。

## 六、渲染：只在 JSON 响应里加字段

Markdown/CSV 导出不包含卡片。导出是「可归档的报告」，卡片是「当前实例的可视化配置」；把用户安装的卡片混进导出，会让同一份报告在不同机器上形状不同。

前端在汇总卡片之后渲染一块独立区域：标题加窗口、指标值、失败码。百分比、时长、无样本各有格式化规则。

```text
[近 30 天任务成功率 · 30d]  96.4%
[近 7 天失败 Top]           timeout × 12
```

## 七、取舍：声明式意味着不灵活

- 不支持自定义过滤（按助手、按模型、按状态）；
- 不支持复合指标（成功率环比、P95 耗时）；
- 不支持卡片下钻到运行列表；
- 不支持前端自定义图表类型。

这些都能做，但每加一项，卡片就从「声明式指标」变成「查询 DSL」，能力包也会从「配置」变成「代码」。当前阶段刻意停在四个指标，是为了让卡片保持可审计：任何人看到配置，都能在几秒内知道它会显示什么。

## 八、验证清单

- 安装卡片后，报告 JSON 出现对应 `widgets` 项，数值与主报告同窗口口径一致；
- 未知指标、非法窗口、损坏 JSON 在安装或读取时被跳过；
- 停用/卸载后卡片消失，历史运行记录不受影响；
- 导出 Markdown/CSV 不包含卡片；
- 空数据时显示「无样本」，不显示 0% 或 NaN。

报告卡片的成功标准不是「能显示数字」，而是「数字与既有报告一致，且永远不会变成一段可执行查询」。
