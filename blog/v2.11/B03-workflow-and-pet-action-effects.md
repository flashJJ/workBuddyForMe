# 把包里的图和动画变成真资源：工作流与桌宠动作的安装接线

能力包统一了安装入口，但有两类资源的副作用特别「重」：工作流会生成版本、发布、可能被外部端点引用；桌宠动作会复制二进制文件、写动作资产、进入动作池。它们不能只写一行数据库记录就算完成。

这篇讲这两条接线：**一张图如何从包变成可运行的工作流，一个动画文件如何从包变成可播放的动作。**

## 一、工作流：包里的图要先编译，再发布

包内的工作流负载只有一份：名称、描述、图标、颜色与图结构。图复用画布已有的节点/边契约，不在能力包里发明第二套 DSL。

启用时做三件事：

1. 用现有编译器校验图（节点类型、边连接、必填配置、循环与孤立节点）；
2. 建一条工作流行，把图存成第一个版本；
3. 发布这个版本，让它出现在列表里并能作为工具被发现。

```ts
createWorkflow({ name, description, icon, color });
addVersion(workflowId, graph);
publishVersion(workflowId);
effectRef = workflowId;
```

顺序不能反：先发布再建行，发布动作找不到目标；先存版本再编译，坏图会被写进历史。

## 二、工作流停用：不删行，只禁用

工作流不是一份纯配置，它有运行记录与对外端点。停用只需要把状态置为 `disabled`，让列表与工具发现不再返回它，但保留历史版本与运行记录。

卸载才需要判断：如果存在运行记录，或者被某个端点引用，同样只保留禁用行；否则删行并让版本级联删除。这个判断必须查两张表，而不是「先删了再说」——外键级联会把运行记录一起带走。

```ts
if (workflows.hasRuns(id) || workflows.hasEndpoint(id)) {
  workflows.setStatus(id, 'disabled');
  return;
}
workflows.delete(id);
```

「包已卸载但工作流还在」看起来像孤儿，其实是刻意保留：用户的历史运行不能因为一次卸载就消失。列表里会带来源标记，告诉用户它来自一个已经不在的能力包。

## 三、桌宠动作：文件与数据库必须成对

动作包的负载是一个 JSON 描述加一个动画文件。启用时不能直接相信扩展名，要走既有导入链路的两道校验：

- 文件必须是合法的 GLB 容器（魔数、版本、块结构）；
- 扩展声明里必须包含 VRM 动画扩展。

两道都过，才复制到动作目录、写动作资产行，并把来源记为能力包 id。`effectRef` 是动作 id。

```text
action.json → { name, file, segment?, mood?, entryKey? }
payload/sample.vrma → sniffVrma → importMotion(source: capability:<packId>)
```

停用要删两样：动作行与文件。只删行会留下垃圾文件；只删文件会让动作池指向一个不存在的资产。动作服务把这两步包成一个可重复调用的撤销操作。

## 四、入口键冲突要前置拒绝

如果动作声明了 `entryKey`，而动作池里已经存在同名条目（用户自建或其它包），安装必须返回 422，而不是悄悄覆盖。覆盖会让用户原有动作消失，而且很难追溯。

不带 `entryKey` 的动作自成一个条目，没有冲突问题。这个设计把「合并到已有条目」与「新增条目」区分开，避免一个字段承担两种语义。

## 五、示例包：二进制素材不在 core 包里

工作流示例可以全部用文本构造，动作示例不行：它需要一个真实的动画文件。core 包不应该为了一个示例携带二进制，因此素材由 web 容器注入一个读取器，按顺序查找：

1. 环境变量指向的示例素材目录；
2. 应用工作目录下的公共素材目录；
3. 独立部署时的公共素材目录。

找不到素材时，示例接口返回 422，并明确说「示例动作素材缺失」，而不是返回一个空 ZIP。这样用户看到的是可解释的失败，不是坏包。

## 六、为什么这两类值得单独写

技能与 MCP 的副作用是「配置级」的：复制文件、注册连接。工作流与动作是「资源级」的：它们有版本、有历史、有二进制、有外部引用。用同一套 enable/disable 接口，但撤销策略必须按资源特性设计。

| 维度 | 工作流 | 桌宠动作 |
|---|---|---|
| 副作用 | 数据库行 + 版本 + 发布状态 | 数据库行 + 磁盘文件 |
| 停用 | 置禁用，保留历史 | 删行 + 删文件 |
| 卸载 | 有运行/端点则保留禁用行 | 删行 + 删文件 |
| 主要风险 | 误删历史运行 | 文件与行不同步、入口键覆盖 |

## 七、验证要点

- 安装后工作流立刻出现在列表且可试运行；
- 有运行记录时卸载只禁用、不删历史；
- 动作文件损坏时安装失败，且动作池不出现半成品；
- 同名入口键返回冲突，不覆盖用户动作；
- 示例素材缺失时返回可读错误，而不是坏包。

这两条接线没有引入新引擎，只是把已有能力接进统一生命周期。真正的难点不是「怎么建一条记录」，而是「停用和卸载时，哪些东西必须留下、哪些必须删干净」。
