# 她主动开口的那一刻：skip-history 轻量轮、空闲武装与「失败必须无声」

v1.0 最后一个功能，也是我们讨论最久的一个：助手能不能在用户长时间没说话时，主动搭一句？

被动应答是安全的——每一次输出都有一次明确的输入在背书。主动说话没有背书。它在用户没有提出任何要求的时候抢占注意力，所以这个功能的设计核心不是「怎么让她说」，而是「怎么保证她永远不烦人」。最后落成的原则只有一句：**主动功能永远不打扰**——任何失败都静默收起，任何时候用户一动手，她立刻让开。

## skip-history：一次不落任何痕迹的轻量轮

最容易做重的是后端。复用普通对话轮最省事，但普通轮会创建会话、写用户消息、挂 RAG、跑记忆、注入技能、允许工具调用、结束后还排一串摘要收尾任务——主动搭一句话要付全部代价，还要在历史里留下一句并不是用户发起的对话。

我们做的是 **skip-history 轻量轮**：

```text
不创建会话、不写消息、无 RAG / 记忆 / 技能 / 工具 / 收尾任务
请求体只有三部分：
  system   人设 + 表情规则
  history  最近 8 条纯文本历史（只读，临时拼装）
  指令     主动触发：说 1-2 句、不超过 60 字
```

提示词里特意**禁止出现「空闲」「主动」这类字眼**——模型不能对用户说「看你闲着没事」，那会立刻暴露这是定时触发，显得机器感十足。指令给的是情境（比如时间、刚才在聊什么），让她像自然想起一样开口。运行时本身完全复用既有对话引擎，流式协议一字不差，只是首帧 meta 里带 `proactive: true` 标记，临时消息 id 统一用 `proactive-` 前缀——前后端各靠这两个标识认出它：不持久化、不进消息计数。真机取证时专门断言过：一轮主动搭话结束，数据库消息数前后不变。

语音也走同一条通道：开了朗读就挂上既有的语音旁路，TTS 按句合成、口型、表情、角色绑定声线全部白得，桌宠和形象栏同步驱动。

## 空闲检测：10s 心跳，与只在武装后挂载的监听

前端 hook 是一个小型武装状态机：

- **10s 周期心跳**检查空闲时长，阈值四档可选：**5 / 10 / 15 / 30 分钟**；
- 用户活动的判定是 `pointerdown` / `keydown` / `wheel`，全部在**捕获阶段**监听，且做 1s 节流；
- 关键省耗细节：这些全局监听**只在计时已武装时才挂载**，未开启功能时页面零额外监听器；
- 达阈值发起请求时保证**单飞**——一个 `inFlight` 标志加一个 `AbortController`，绝不叠轮。

武装条件本身也是门控：没配置对话模型不武装，没有形象出口（形象栏或桌宠都没开）时在设置里明确提示「需要一个能出场的地方」；只开文字气泡不开朗读也能用。设置面板给的控制项只有三样：总开关、四档阈值、一句生效条件说明——不提供更细的打扰参数，克制不仅是代码原则，也体现在不给用户一堆「别来烦我」的高级旋钮上。

## 双向中止：busy 永远是最高优先级

主动轮和正常轮绝不能并发。busy 信号是双向的：

```text
主动轮进行中，用户开始发消息 / 进入语音播放
  → 立即 abort 请求 + 取消未播完的 TTS + 收起气泡
对话流式输出中 / 语音正在播放
  → 空闲计时器不武装，主动轮根本不起
```

中止路径的动作顺序是固定的，先掐源头再收界面：

```text
busy 翻 true / 用户切换上下文
  → controller.abort()      网络请求作废，在途帧丢弃
  → playback.cancel()       未播完的 TTS 立即停，口型归零
  → setBubble(null)         气泡收起，单飞标志释放
```

此外，切助手、切会话一律立即收起并重置计时；页面卸载只做 abort 不重置（计时随页面本来就没了）。一轮主动搭话**完成后冷却一个完整阈值**——她说完一句之后，至少再过一个完整周期才可能说下一句，从节奏上杜绝话痨。

## 临时气泡：浮在列表上，不进列表

主动内容没有资格进消息列表。UI 是一条浮在消息列表底部的临时气泡条：不进入列表数据结构、不入库、不触发未读计数；带表情标签时标签照常驱动 Live2D，但气泡文字走同源剥离逻辑，用户看不到标签。用户一旦操作（敲键盘、点鼠标、滚轮），已完成的气泡也会主动收起——它的存活时间本来就不该比用户的注意力更长。

## 静默降级矩阵：失败的全部姿态都是不出声

这个功能一半的代码量花在「失败时怎么办」。我们逐路径走查了整张降级矩阵：

```text
未武装（没模型 / 没出口）     → 根本不发请求
TTS 模型未就绪                → 请求不带语音，纯文字气泡照常
单句语音合成失败              → 该句仅出字幕，文本流不断，其余句继续
供应商 500 / 网络失败 / 流中断 → 静默收起、释放单飞，冷却一个阈值后再试
请求被 abort                  → 当作无事发生，不算失败、不提示
会话已被删除                  → 历史查空，退化为无历史的问候开场
连接截断、没有结束帧          → 读循环自然收尾，不卡 loading
```

没有任何一种失败会弹错误提示。弹窗对普通功能是反馈，对主动功能就是骚扰——用户根本没发起这件事，凭什么要他处理错误。冷却后自动重试是用户无感的，重试成功他只看到一句适时的问候。

矩阵里还有两个不那么显眼的边界：会话已被删除时，历史查询为空（另有一层 try/catch 双保险），退化成无历史的问候开场而不是报错；连接被截断、结束帧永远不来时，读循环自然结束后按完成收尾，气泡不会卡在 loading。还有一种输出是纯表情标签或空白片段——TTS 净化后文本为空，这种帧只驱动字幕与表情、不出声，不会播一句空气。

## 走查抓出的一处文案错位

矩阵走查真的抓到了一个 bug：模型极端情况下返回零文本，原代码复用了普通对话的「工具调用已达轮数上限」兜底文案。可是主动轮**根本不挂任何工具**——用户会在完全没操作的时候看到一个气泡说「工具调用轮数超限」，莫名其妙。修复是配一句主动轮专属的中性短问候，并加断言锁定，杜绝以后再有人图省事复用别处的兜底文案。

## 顺手修掉的「回答出完还在转圈」

做主动轮时还顺带定位了一个老 bug：正常对话文本已经出完，界面上的加载圈还在转。根因是摘要、记忆提取这类收尾任务排在了 SSE 结束信号之前，它们慢，界面反馈就得等。改成**结束信号先到、收尾任务在其后异步执行**——用户感知的「回答完成」和系统内部的「善后完成」本来就该是两件事。这也正好与轻量轮「不排收尾任务」的取舍呼应：不是所有对话后作业都有资格挡在用户面前。

## 测试与真机取证

主动轮的测试刻意按「编排」和「计时」两层切：core 侧 8 个用例覆盖供应商报错、零文本兜底、无会话无语音分支、会话已删除退化等服务端路径；前端 hook 侧 10 个用例覆盖武装条件、busy 双向中止、切助手/切会话收起、TTS 未就绪降级、网络 reject 静默。时间相关用例几乎全靠假时钟推进，这也引出了下一篇复盘里会讲的三个测试陷阱。

端点真机验证的取证口径很具体：一轮带语音的主动搭话，流里恰好收到 3 个语音音频帧（24kHz 的 Kokoro 合成），状态机从 speaking 正常回到 idle，数据库消息计数前后不变；不带语音的分支只出纯文字 delta。说「功能完成」之前，这些数字必须看得见。

## 收尾

主动搭话上线后，这个应用第一次有了「她在那边」的感觉：你专心干活半小时，余光里角色忽然转过来，说了句不超过 60 个字、和刚才话题有关的话，你一碰键盘她就安静了。克制到近乎苛刻的失败处理，换来了这种感觉的安全感。至此 v1.0 全部功能闭环——下一篇，也是这个系列的收尾，我们把整个版本踩过的坑摊开，做一次总复盘。
