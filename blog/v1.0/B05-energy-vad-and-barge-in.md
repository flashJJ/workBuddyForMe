# 免手聆听与开口打断：一个纯能量 VAD 状态机的全部参数

按住说话能用，但它没有兑现「手可以留在工作上」的承诺——你还是要腾出手去按按钮。真正免手的方案业界通常有三件套：唤醒词、回声消除（AEC）、连续流式 ASR。我们在动手前把这三件套全部划出了 v1.0 的范围。

理由很实际：唤醒词要常驻一个模型，AEC 在免耳机外放场景没有轻量靠谱的本地实现，流式 ASR 则要把识别链路从「整句」重写成「边说边出字」。每一件都是一个独立大版本。

v1.0 的替代方案朴素得多：**浏览器端纯能量 VAD**——不识别内容、不需要网络、不新增任何模型，只用麦克风音量相对底噪的起伏判断「人是不是开始说话了、是不是说完了」。它覆盖不了嘈杂开放环境，但能覆盖这个应用 80% 的目标场景：一个人坐在电脑前，戴着耳机或音量适中，跟桌面前的伙伴轮流说话。

这一篇讲状态机的完整参数、半双工回声门控、开口打断的 epoch 作废链路，以及 AudioWorklet 的两个大坑。

## 状态机：参数全景

检测器是一个纯状态机，输入只有每帧的音量能量，输出「语音起始 / 语音结束」两个事件。全部参数如下：

| 参数 | 值 | 作用 |
|---|---|---|
| 帧时钟 | 32ms | 每 32ms 喂一帧能量，状态机的时间粒度 |
| 底噪 EMA | 0.94 | 环境底噪指数滑动平均，缓慢跟踪背景变化 |
| 底噪 clamp | 2.5x | 单帧最多把底噪估计抬到原值的 2.5 倍，防一句话把底噪带飞 |
| 起始阈值 | 3.2x 底噪 | 能量超过底噪 3.2 倍才算「可能开口」 |
| 结束阈值 | 1.8x 底噪 | 迟滞：跌回 1.8 倍以下才算「可能停了」 |
| 绝对下限 | 0.025 | 再安静的环境，能量不过 0.025 也不触发，防放大自噪 |
| 起始确认 | 连续 240ms | 越过起始阈值要持续 240ms 才确认开口，过滤碰撞声 |
| 最短语音 | 320ms | 短于 320ms 的语音段丢弃，多半是咳嗽喷麦 |
| 尾静音 | 默认 900ms | 说完停顿 900ms 判定一句话结束，自动发送 |

起始和结束用两个不同倍率，是经典的**迟滞**设计：如果开合用同一个阈值，能量在阈值附近抖动时状态机会疯狂反复，一个词切成三句。3.2 开、1.8 合，中间留出宽缝。

底噪估计是这个检测器能不能换环境用的核心。固定阈值在空调房和键盘旁必然有一个不适用；EMA 让它慢慢适应当前环境，0.94 的衰减系数意味着它反应「慢」——这是有意的，底噪应该描述长期环境，而不是跟着当前这句话跑。clamp 2.5 倍则是防「用户说了一长段话，底噪被抬到说话音量，之后再也触发不了」的雪崩。

三档灵敏度只改一个量：起始倍率分别为 **2.6 / 3.2 / 3.8**（低/中/高门槛），其余参数不动。一个旋钮、可预测、可单测，比暴露一堆滑块诚实得多。

## 半双工回声门控：防的是自激

不做 AEC，外放时 TTS 的声音会被麦克风收回来。如果不处理，要么助手自己的声音触发自己（自激循环），要么尾静音刚到就被扬声器余响打断。门控规则有三条：

1. **播放态阈值 ×2.2**：TTS 正在播放时，起始阈值在原有基础上再乘 2.2，用户必须明显压过扬声器音量才被认定为开口；
2. **前置 600ms 门控**：播放开始前后的一小段时间内直接不做起始判定，滤掉启动冲击和第一波外放；
3. **停播后 500ms 冷却**：声音停下后的 500ms 内仍然按播放态对待，等房间里的余响和麦克风管线排空。

播放状态由播放队列的 `getGate()` 实时提供，VAD 不自己猜。这三条加起来，让「不做 AEC」在半双工前提下成立：听和说严格轮流，轮次切换处用门控缝合。

## 开口打断：epoch 作废与 abort 全链路透传

免手对话最爽的瞬间：助手正在一本正经念一长段，你说一句「停，换个思路」，它**立刻闭嘴听你说**。这个动作内部叫 barge-in，链路是这样的：

```text
VAD 确认语音起始
   │ 撞上「播放态」？
   ▼ 是
barge-in：
  ① 播放队列 epoch += 1   —— 当前队列整体作废，声音立即停
  ② abortController.abort() —— 沿既有 AbortSignal 一路透传：
       · 上游大模型生成中止
       · 在途的 TTS 合成中止
       · 切句器残余丢弃
```

关键在 ① 的 **epoch（纪元号）**。取消一个正在播放的队列不能只做「清空数组」——网络上属于旧回答的音频帧还在往回飞，清空之后它们照样到达、照样入队。所以队列持一个单调递增的 epoch，每帧入队时校验归属，旧 epoch 的帧直接扔掉。作废是声明式的：旧轮次的任何迟到数据从结构上都不可能复活。

abort 也不是只停播放。同一条 AbortSignal 是对话编排本来就有的取消通道，abort 一路传到上游：正在吐字的大模型请求中止，正在合成的句子中止，省掉的是实打实的本机算力和云端 token。

## SSE 接收端：epoch + pumpToken 丢弃旧轮

打断发生在客户端，但服务端的 SSE 帧不会因为 abort 瞬间消失——网络缓冲里的旧帧、甚至旧轮次的 final 帧都可能迟到。接收端用 **epoch + pumpToken** 两层标记守门：

```ts
// 说明性伪代码：每一轮对话一个新 epoch，每次驱动播放取一个新 token
let epoch = 0;
async function pump(round: number, token: number, stream: ReadableStream) {
  for await (const ev of stream) {
    if (round !== epoch || token !== currentPumpToken) return; // 旧轮/旧泵：直接丢弃
    if (ev.type === 'voice_audio') queue.enqueue(ev, round);
    if (ev.type === 'voice_final' && round === epoch) queue.finalize();
  }
}
```

- **旧轮迟到的音频帧**：epoch 不匹配，丢弃；
- **旧轮迟到的 final**：丢弃——否则旧回答的收尾信号会把新一轮的播放队列错误 finalize；
- **旧泵不得并发**：每轮 pump 持有自己的 pumpToken，新一轮启动时旧 pump 即使还在读循环里，也会在下一帧自行退出，不存在两个读取者并发操作一个队列。

## 轮次管理：turnId、超时、单飞与单槽排队

免手轮次比按键更容易乱：VAD 可能在助手思考时又检测到语音、用户可能连着说。轮次管理用四条规则收口：

- **turnId 隔离**：每一轮（采集 → ASR → 对话 → 朗读）分配独立 id，所有事件按 turnId 归属，不属于当前轮的一律 stale 丢弃；
- **20s 超时**：一轮从开口到完整收尾最多 20s，超时强制结束，防止异常状态下麦克风永久占用；
- **单飞（single-flight）**：同一时刻只允许一轮在飞，新的起始不能并发开第二轮；
- **单槽排队**：如果用户在收尾间隙又开口，只保留最新一个待处理轮次，排队槽只有一个——本地伙伴不需要消息积压，说最新的比排队更符合直觉。

## AudioWorklet 的两个大坑

免手聆听要持续采集音量电平，ScriptProcessor 在主线程上长期跑不合适，VAD 采集用的是 AudioWorklet（跑在独立音频线程）。两个坑都非常「反直觉」：

**第一，WorkletNode 不连 destination，process 不会被调度。** 和 ASR 录音那边同一个坑的 Worklet 版本：只把麦克风源连到 WorkletNode，音频图没有落地终点，`process()` 一次都不 tick。解法同样是经一个 **0 增益 GainNode 连到 destination**：图活了，声音不外放。

```ts
const node = new AudioWorkletNode(ctx, 'vad-processor');
const silent = ctx.createGain();
silent.gain.value = 0;
source.connect(node);
node.connect(silent);
silent.connect(ctx.destination);
```

**第二，StrictMode 重挂导致握手重复。** React 开发态 StrictMode 会把组件挂载、卸载、再挂载一遍，结果 worklet 的启动握手消息发了两次，采集线程状态错乱，偶发收不到帧。修法是握手只对「当前仍然存活的音频链」发送：卸载时前移 cancelled 检查，重挂后的旧链握手一律视为无效，新链重新建立。这类问题开发态才出现、生产构建没有，但不能因此放过——开发体验也是体验。

## 小结与系列收束

能量 VAD 整个检测器没有模型、没有网络，全部智力都在参数里：32ms 帧、EMA 0.94 与 2.5 倍 clamp、3.2/1.8 迟滞、0.025 绝对下限、240ms 确认、320ms 最短语音、900ms 尾静音，加上播放态 2.2 倍门控和前后冷却。它不完美，嘈杂环境的真人标定仍在发布清单上，但它用极小的复杂度把「手留在键盘上、嘴对着屏幕说话」这件事跑通了。

至此，v1.0 的语音闭环完整：模型首用下载不进安装包，ASR 热态 256ms 出字，回复在文本流旁路上按句合成、首句即响，单句失败只降级字幕，角色有各自的声线和表情，能量 VAD 负责免手轮次，epoch 与 abort 保证开口即断。一个只能打字的侧栏配置，就这样变成了桌面上一个能听、会说、有表情的伙伴。
