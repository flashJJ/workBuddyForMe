# 会话级内容快照：安装内容后如何做到不重启就生效

内容包能安装了，接下来的问题是：安装完成后，正在跑的模型怎么看到新内容？

最容易想到的方案是热替换：监听能力状态变化，把新内容直接推给运行时。听起来很顺，但对骨骼动画来说风险很高：正在播放的轨道可能引用旧内容，替换瞬间会出现骨骼错位或动作跳变。

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。这一轮选择的是**会话级快照**：

- 每次挂载读取一次内容。
- 当前会话继续使用旧快照。
- 下一次打开入口时读取新快照。

## 一、快照由谁聚合

聚合逻辑放在 core 包的服务层，原因有两个：

- 它需要读能力行状态与包目录，属于服务端职责。
- 它不依赖渲染，可以被单测直接调用。

聚合规则很短：

1. 默认内容打底。
2. 读取所有已启用且 kind 为内容包的能力行。
3. 逐个解析 payload，按顺序追加。
4. 同类型重复 id 直接拒绝。
5. 没有内容包时，返回默认快照的同一引用。

最后一条很重要。它不是优化，而是保证“没有内容包”和“以前”完全一致：引用相同，测试可以用 `toBe` 锁住，运行时也不会有任何额外对象。

## 二、版本号为什么要稳定

快照需要版本号，用于告诉运行时“这次内容和上次不一样”。

版本号的生成方式：

```ts
const signature = sources
  .map((source) => `${source.id}@${source.version}`)
  .sort()
  .join(',');
const version = `packs:${sha256(signature).slice(0, 12)}`;
```

两个细节：

- 先按 `id@version` 排序，保证同一组包无论读取顺序如何都得到同一个版本。
- 只取哈希前 12 位，够用且便于日志展示。

版本号不包含内容哈希。包版本变化时 payload 可能没变，但我们仍然认为快照变了。这是刻意的：版本号表达“启用了哪些包”，而不是“内容字节完全一致”。

## 三、跨包冲突要在聚合时拒绝

单个包的 schema 只能检查包内重复；两个包声明同一个姿势 id 时，只有在聚合时才能发现。处理方式是 fail-closed：抛出校验错误，不返回部分内容。

不做“后一个覆盖前一个”，因为用户不知道哪个包生效，停用顺序不同还会导致不同结果。拒绝冲突，让问题在读取快照时立刻暴露，而不是变成难以复现的观感差异。

## 四、不新增表

内容快照完全由“能力行状态 + 磁盘 payload”计算，没有新增表：零迁移、不会出现表与磁盘不一致、停用/卸载无需清理派生数据。

代价是每次读取都要解析 payload。读取发生在挂载时而不是每帧，当前包数量下可以接受；将来包大了，可以加一层键为快照版本的进程内缓存。

## 五、接口只做一件事

服务端接口很简单：

```ts
GET /api/motion-content
```

它返回聚合后的快照，强制动态渲染，不做缓存。原因是安装与停用会改变结果，缓存反而会让“下一次挂载生效”变得不可预期。

接口没有分页、没有查询参数、没有“按包过滤”。内容快照是一个整体，拆开读只会让运行时拿到不一致的组合。

## 六、客户端只读一次

客户端用一个很小的 hook 读取：

```ts
const { content, ready } = useMotionContent();
```

它做三件事：

- 挂载时请求一次。
- 成功则使用返回值，失败则回落默认内容。
- 三秒超时也回落默认内容，避免入口一直停在加载态。

`ready` 单独返回，因为渲染层需要在“内容确定”之后再创建会话。否则会先用默认内容建一次，再用真实内容重建，白白多一次初始化。

## 七、为什么不做实时推送

实时推送需要一条长连接、一套失效策略，还要处理“推送到达时模型正在播放”的冲突。

会话级快照把这些问题推迟到下一次挂载：安装/停用后重新打开桌宠或舞台即可看到结果，当前会话不中断，也不需要新增事件类型与重连逻辑。

这是一个明确的产品取舍：**先保证不崩，再考虑无缝。**

## 八、测试怎么锁

聚合测试覆盖四类场景：

1. 没有内容包：返回默认快照，且是同一引用。
2. 一个包：默认内容 + 包内容按顺序合并。
3. 停用后：聚合结果回到默认。
4. 两个包声明同一 id：抛校验错误。

版本号额外测稳定性：把 source 顺序倒过来，版本号必须一致。

## 九、边界

- 不做内容热替换。
- 不做包级过滤读取。
- 不做快照持久化。
- 不做增量合并，冲突一律拒绝。

这些边界让实现保持很小，也让“下一次挂载生效”成为可验证的行为，而不是模糊的承诺。

## 十、结果

- 安装/停用内容包后不重启应用，下一次挂载生效。
- 默认路径与旧版本完全一致。
- 跨包冲突在读取时被明确拒绝。
- 零数据库迁移，零新增事件通道。
