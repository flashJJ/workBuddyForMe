# coreVersion：把“最低应用版本”做成一条显式约束

能力包升级时最尴尬的情况，是包用了新版本应用才认识的字段，而旧应用仍然把它装进来。

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。能力包与内核同仓开发，但安装是用户本地的 ZIP，无法假设“包和应用永远同版本”。于是 manifest 需要一个版本约束。

这一轮增加的是 `coreVersion`。它的语义被刻意收窄成一句话：**这个包要求的最低应用版本。**

## 一、为什么不是版本范围

版本约束常见写法是范围表达式，比如 `>=3.2 <4.0`。我们评估后没有采用，原因是：

- 当前只有一个应用版本维度，范围的上界没有真实使用场景。
- 范围需要解析器、比较器与错误信息设计，测试面明显变大。
- 用户看到 `>=3.2 <4.0` 这样的字符串，很难直接判断自己能不能装。

最低版本只做一件事：比较两个版本号。语义单一，错误信息也能写得很直白：

```text
该能力包要求应用版本 ≥ 3.5.0，当前为 3.1.0
```

将来如果真有“只兼容某一段版本”的需求，再引入范围表达式，也不会破坏现有字段的含义。

## 二、检查发生在三个入口

`coreVersion` 与依赖检查共用同一个预检函数，在三个地方执行：

1. 安装：ZIP 解包、manifest 校验之后，落盘之前。
2. 启用：能力行状态从 disabled 变 enabled 之前。
3. 升级：新 manifest 替换旧 manifest 之前。

三处共用同一条错误路径，避免出现“安装能过、启用才炸”的不一致。

检查范围包括待安装包本身，以及它依赖的每个包的 manifest。否则一个旧包依赖一个新包时，约束会被绕过。

## 三、比较逻辑要简单到可以手算

版本比较只处理数字段：

```ts
function compareVersion(a: string, b: string): number {
  const left = a.split('.').map(Number);
  const right = b.split('.').map(Number);
  for (let i = 0; i < Math.max(left.length, right.length); i += 1) {
    const diff = (left[i] ?? 0) - (right[i] ?? 0);
    if (diff !== 0) return diff;
  }
  return 0;
}
```

预发布后缀暂时不参与比较。这不是忽略，而是明确声明：当前能力包只发布正式版本，预发布语义留到需要灰度时再补。

比较逻辑越简单，越不容易在“3.10 与 3.9”这种地方出错。测试里专门覆盖了两位数段与缺段补零。

## 四、错误必须 fail-closed

版本不匹配时，预检直接拒绝，不做“先装上再说”。

原因与能力包的其它预检一致：安装动作会落盘、会写数据库行、可能触发 effect。如果先落盘再报错，用户需要自己清理残留，健康检查也会多出一类“半安装”状态。

fail-closed 的代价是用户要升级应用后才能安装新包。这是可接受的：应用升级是显式动作，比“装上一个行为不可预测的包”安全得多。

## 五、和依赖版本的关系

manifest 里有两个版本字段，容易混淆：

- `dependencies[].version`：依赖包的精确版本。
- `coreVersion`：应用的最低版本。

前者描述包与包之间的关系，后者描述包与应用之间的关系。两者都在同一张依赖图预检里执行，但错误信息分开，用户能判断是“该升级依赖包”还是“该升级应用”。

我们刻意没有把应用版本也塞进 `dependencies`，那样会让依赖图同时包含包节点与应用节点，排序与环检测都会变复杂。

## 六、测试覆盖

版本约束的测试分三类：

1. 纯函数：大于、小于、等于、缺段补零、两位数段。
2. 预检：安装、启用、升级三个入口分别拒绝低版本。
3. 依赖链：旧包依赖新包时，约束仍然生效。

另外保留一条正向用例：`coreVersion` 缺省时不做检查。旧包没有这个字段，不能因为新增约束就全部失效。

## 七、这一轮没做什么

- 不做版本范围表达式。
- 不做预发布版本比较。
- 不做“自动提示升级应用”的界面。
- 不把应用版本纳入依赖图节点。

这些都可以在真实需求出现时再加，而且不会破坏现有语义。先把一条约束做准，比一次做一套版本代数更划算。

## 八、结果

- 低于最低应用版本的能力包在安装、启用、升级前被拒绝。
- 错误信息同时给出要求版本与当前版本。
- 依赖链上的每个包都执行同一约束。
- 原有能力包测试零回归，零数据库迁移。
