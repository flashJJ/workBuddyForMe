# 内容包 payload 契约：只允许数据，并且严格到字段

内容包一旦能安装，第一个要回答的问题就是：包里允许放什么？

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。能力包本身是 ZIP，包含 manifest 与 payload。manifest 描述元信息，payload 才是真正的内容。

动效内容包的选择很明确：**payload 只允许数据，不允许执行器代码。**

## 一、固定入口，减少协商

payload 文件名固定为：

```text
payload/motion-pack.json
```

没有“入口可配置”这种设计。原因很实际：

- 安装器不需要读 manifest 才知道文件在哪。
- 校验、健康检查、升级都只认一个路径。
- 错误信息可以直接指出缺哪个文件。

固定入口牺牲了一点灵活性，换来的是链路各处都不用做路径协商。

## 二、空内容必须拒绝

一个只声明了名字、没有任何姿势/动作/行为的内容包，看起来无害，实际上会让聚合结果产生一个“启用了但什么也没加”的版本号。

所以 schema 在对象级别加了一条 refine：

```ts
.refine((value) => value.poses.length + value.motions.length + value.behaviors.length > 0, {
  message: '至少包含一个姿势、动作或行为',
})
```

这条规则的收益不是“更严格”，而是让快照版本有意义：只要版本变了，内容一定变了。

## 三、三类内容，各自有上限

payload 只包含三类内容：

- `poses`：骨骼旋转组合，带 mask 与可选变体。
- `motions`：按时间排布的关键帧，引用姿势 id。
- `behaviors`：分层行为，包含 enter / loop / exit 三个阶段。

每类都有数量与时长上限：姿势 64、动作 64、行为 32、单个动作关键帧 64、单个阶段轨道 16、单个动作时长 60 秒。

这些数字不是随意写的。它们限制了单包聚合后的内存与插值开销，也防止一个恶意或误操作的包把运行时拖死。

## 四、骨骼 mask 是白名单

姿势与轨道都带 mask。mask 使用固定的骨骼分组枚举，而不是任意字符串：

```ts
const boneGroupSchema = z.enum(['root', 'spine', 'head', 'leftArm', 'rightArm', 'leftLeg', 'rightLeg', 'face']);
```

include 与 exclude 都有数量上限。这样运行时不需要处理“未知骨骼名”，校验期就能拒绝。

使用固定枚举还有一个好处：内容包不能引用执行器内部符号。执行器仍然由内核注册，包只能引用已注册的姿势/动作 id。

## 五、轨道是判别联合

行为阶段里的轨道是判别联合，按 `kind` 区分：

- `pose`：按 mask 与权重叠加姿势。
- `motion`：在指定时间点播放动作。
- `root`：整体位移或旋转。
- `expression`：表情标签与保持时长。
- `look`：视线目标与权重。
- `morph`：语义 morph 通道。

每个分支都是严格对象，未知字段直接报错。这样新增轨道类型时，旧应用不会“忽略未知字段继续跑”，而是明确拒绝。

## 六、strict 是刻意的

所有对象都用了 `.strict()`。这意味着多写一个字段就会校验失败。

这看起来不友好，但对内容包是必要的：

- 拼错字段名不会被静默忽略。
- 旧应用不会把新字段当作不存在继续执行。
- 版本升级时，字段变化能被立即发现。

我们宁可让作者在安装时看到一条明确错误，也不要在运行时出现“动作少了一半”的诡异现象。

## 七、重复与冲突在启用时检查

schema 只能保证单个包内部结构合法，无法知道全局状态。启用阶段会再检查同一类型内 id 是否重复、是否与内置内容冲突；失败则不改变能力行状态，坏包整包拒绝。

## 八、示例包长什么样

一个最小内容包只需要一个姿势：

```json
{
  "name": "示例动效",
  "description": "只含一个右臂姿势",
  "poses": [{
    "id": "example.pose.wave",
    "mask": { "include": ["rightArm"] },
    "bones": { "rightUpperArm": { "z": -0.6 }, "rightLowerArm": { "z": 0.4 } }
  }],
  "motions": [],
  "behaviors": []
}
```

它能被安装、启用，并进入内容快照。行为与动作可以后续再加，不需要一次写满。

## 九、边界

- 不支持 VRMA 文件与纹理，只支持姿态/动作/行为数据。
- 不支持脚本表达式或条件逻辑，也不做跨包内容继承。

这些限制让 payload 保持“可校验的数据”，而不是“需要解释器的程序”。


## 十、结果

- 内容包结构在安装与启用两处 fail-closed。
- 空包、重复 id、内置冲突都会被拒绝。
- 轨道与骨骼使用固定枚举，未知内容无法进入运行时。
- 单包大小与条目数量可控，聚合成本可预估。
