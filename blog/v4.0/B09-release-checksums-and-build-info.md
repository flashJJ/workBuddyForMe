# 发布校验和与构建信息：让安装包从“能装”变成“可追溯”

安装包构建出来之后，用户凭什么确认它没被改过？

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。归档脚本早期用 PowerShell 现场算哈希，输出一个 `SHA256SUMS.txt`。能用，但有几个问题：

- 格式靠脚本手写，字段不稳定。
- 只有哈希，没有版本、commit 与构建时间。
- 复核要自己写命令，容易漏文件。

这一轮把发布校验清单做成独立脚本，归档流程只负责调用。

## 一、为什么要独立脚本

归档脚本是 PowerShell，构建在 Windows 上。哈希逻辑如果留在 PowerShell：

- 无法在 CI 的 Linux 环境复用。
- 单元测试困难。
- 格式与字段随脚本修改而漂移。

改成 Node 脚本之后，任何装了 Node 的环境都能运行。它只依赖标准库，不需要安装依赖。

## 二、流式计算，不把安装包读进内存

安装包通常几百 MB。直接 `readFileSync` 会让内存峰值很难看。

脚本按 1 MB 分块读取：

```js
const hash = createHash('sha256');
const fd = fs.openSync(file, 'r');
const buffer = Buffer.allocUnsafe(1024 * 1024);
let bytes;
while ((bytes = fs.readSync(fd, buffer, 0, buffer.length, null)) > 0) {
  hash.update(buffer.subarray(0, bytes));
}
fs.closeSync(fd);
```

这样内存占用与文件大小无关，校验一个包和校验十个包的开销都可预期。

## 三、coreutils 风格，便于互相复核

`SHA256SUMS.txt` 的每一行是：

```text
<小写哈希>  <文件名>
```

两个空格是约定。这样可以直接用 `sha256sum -c` 校验；Windows 上也可以用 `certutil -hashfile` 对单个文件复核。

文件名保持原样，不写绝对路径。归档目录移动位置后，校验清单仍然有效。

## 四、build-info 记录什么

`build-info.json` 包含：

| 字段 | 含义 |
|---|---|
| `version` | 应用版本 |
| `builtAt` | 产物最新修改时间，近似构建完成时间 |
| `generatedAt` | 清单生成时间 |
| `platform` / `arch` | 构建平台与架构 |
| `commit` / `branch` | 构建时的 Git 信息 |
| `files` | 每个产物的文件名、字节数与 SHA256 |

`builtAt` 取产物 mtime 而不是脚本运行时间，是因为归档可能发生在构建之后一段时间。用 mtime 更接近真实构建时间。

commit 与 branch 通过只读 Git 命令获取；取不到时写 `null`，不让脚本失败。构建信息是附加价值，不应该阻断发布。

## 五、--check 才是关键

生成清单只是第一步，能复核才有意义。

`--check` 做四件事：

1. 重新计算目录内每个文件的哈希。
2. 与 `SHA256SUMS.txt` 逐行比对。
3. 检查清单里是否有多余但已不存在的文件。
4. 核对 `build-info.json` 的版本与逐文件哈希。

任何一项不一致都退出 1，并打印期望值与实际值。

我们用临时目录做过验证：先生成，复核通过；再篡改一个 `latest.yml`，复核同时报出校验和与 build-info 两处不一致。

## 六、为什么校验和不包含自己

`SHA256SUMS.txt` 与 `build-info.json` 不进入自己的校验列表。

原因很简单：无法在文件内容里包含自身哈希。它们属于“描述文件”，可信度由发布渠道与后续签名保证，不由自引用保证。

如果未来做代码签名，签名对象应该是安装包与 blockmap，校验清单随 Release 一起分发，而不是反过来。

## 七、归档流程 fail-closed

归档脚本在移动完三个产物后调用清单脚本。调用失败就抛错，不继续清理源目录。

这一点很重要：如果清单生成失败但归档继续，用户会得到一个“看起来完成、实际缺少校验”的目录。下次再归档时，缺失文件很难定位。

fail-closed 让失败停在原地，源目录仍在，可以重试。

## 八、没有做的事

- 不做代码签名。
- 不做自有更新源。
- 不做双通道 feed。
- 不做校验和的在线查询接口。

这些属于发布基础设施，需要证书、域名与灰度策略，和“生成清单”不是同一类工作。先把可复算做扎实，再谈信任链的下一环。

## 九、结果

- 每个归档产物都有一行 SHA256。
- 构建信息包含版本、commit、构建时间、平台与逐文件哈希。
- 一条命令即可复算并核对。
- 篡改、缺文件、版本漂移都能被发现。
