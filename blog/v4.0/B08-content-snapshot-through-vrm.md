# 从 hook 到骨骼：内容快照如何穿透 VRM 渲染链

内容快照到了客户端，还需要一路传到骨骼动画运行时。中间隔着画布、会话、控制器与姿态层。

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。VRM 渲染链大致是：

```text
VrmCanvas → VrmSession → VrmController → VrmPoseLayer → VrmAnimationRuntime
```

这一轮要把 `MotionContent` 从最外层传进最里层，同时不破坏“换模型不重建渲染器”的既有行为。

## 一、先等内容就绪，再建会话

最初的写法是挂载就创建会话，模型加载完再补内容。问题是内容到达后，运行时已经用默认内容初始化过一次，再替换需要重建内部状态。

我们改成：**内容就绪后才创建会话。**

```ts
const { content, ready } = useMotionContent();
React.useEffect(() => {
  if (!ready) return;
  const session = createVrmSession({ ... });
  return () => session.dispose();
}, [ready]);
```

这里的 `ready` 不是“请求成功”，而是“内容已确定”：成功、失败回落、超时回落，三者都会把 `ready` 置为 true。这样即使接口挂了，入口也能在最多三秒后正常显示。

## 二、快照放在 ref 里，不进依赖数组

`MotionContent` 是一个对象。如果直接放进 effect 依赖，每次请求返回新对象都会重建会话。

做法是用 ref 保存当前快照：

```ts
const contentRef = React.useRef(DEFAULT_MOTION_CONTENT);
React.useEffect(() => { contentRef.current = content; }, [content]);
```

创建会话时通过 getter 读取：

```ts
getRuntime: () => ({
  ...,
  motionContent: contentRef.current,
})
```

这样会话只在 `ready` 变化时创建一次；后续内容变化只影响下一次挂载，不会触发重建。这与“会话级快照”的语义一致。

## 三、逐层透传，不做全局单例

传递链路是显式参数，而不是全局单例：

- `VrmSession` 的运行时接口增加 `motionContent`。
- `VrmController` 构造函数增加可选参数。
- `VrmPoseLayer` 构造函数增加可选参数。
- `VrmAnimationRuntime` 使用它构建内部注册表。

为什么不用全局？因为测试需要注入不同内容，未来也可能同时存在多个画布。全局单例会让“这个会话到底用了哪份内容”变得不可追踪。

可选参数保证兼容：不传时运行时使用默认内容，旧调用方不需要改。

## 四、默认值只在一个地方兜底

链路上每一层都接受可选参数，但只有最里层把 undefined 解释为默认内容。外层不复制默认值，也不做空判断。

这样做避免“默认值散落”：

- 画布不判断。
- 会话不判断。
- 控制器与姿态层不判断。
- 运行时统一使用默认快照。

如果每层都写 `content ?? DEFAULT`，默认值就会在多个文件里出现，未来修改默认内容时容易漏掉。

## 五、加载态与错误态

内容请求期间，画布显示加载占位。请求失败或超时，使用默认内容继续，不显示错误横幅。

这是刻意的：内容包是增强，不是启动必需。接口异常不应该让桌宠变成一块空白。

模型加载失败仍然显示错误，因为那是主路径。两类失败的语义不同，UI 也不同。

## 六、测试关注什么

渲染链测试不追求“截图像素一致”，而是锁住三件事：

1. 内容未就绪时不创建会话。
2. 内容就绪后创建一次，不因内容对象变化而重建。
3. 控制器与姿态层收到的是同一份快照。

另外保留默认路径的回归测试：不传内容时，运行时行为与之前一致。全量测试里，动效与 VRM 相关文件全部通过，没有因为新增参数出现类型错误。

## 七、为什么不做运行时替换

有人会问：既然快照已经在控制器里，为什么不监听变化直接换？

原因是替换成本被低估了：

- 正在播放的行为可能引用旧 id。
- 姿态层缓存了上一帧的骨骼。
- 混合器有淡入淡出队列。

直接替换需要一套“内容版本切换”协议：停当前动作、清缓存、重建注册表、恢复状态。这套协议比“下次挂载读取”复杂得多，也更容易出观感问题。

当前选择把复杂度挡在会话边界之外：会话内不变，会话间更新。

## 八、链路的边界

- 内容只影响动效注册表，不改模型与相机。
- 不改变换模型的既有流程。
- 不做跨会话共享缓存。
- 不做内容版本的可视化提示。

这些边界让改动集中在一个参数链路上，回归面可控。

## 九、结果

- 内容就绪后再创建渲染会话，避免二次初始化。
- 快照通过显式参数逐层传递，测试可注入。
- 内容对象变化不会重建渲染器。
- 默认路径零差异，零数据库迁移。
