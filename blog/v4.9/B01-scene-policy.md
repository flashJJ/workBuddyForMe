# 四套预算公式，最后收成一行

我们的桌面 AI 应用在真正调用模型之前，要先给上下文分配预算：这一次能带多少历史、多少背景、多少步骤记录。预算不是孤立数字，它决定了后面所有裁剪的力度。

问题在于，同一件事散落在四个域里：有的各写一套，有的干脆没写。

## 一、分叉长什么样

协作域的上下文块有一套比例和上下限；协作域的步骤历史有另一套；桌面任务的步骤历史又复制了一份；Flow 的 LLM 节点没有预算，上游文本有多长就拼多长。

前三处的数值是分别调出来的，结论却一样：小窗口要保底，大窗口要封顶，中间按比例走。结论相同，实现就该只有一份。

第四处的缺失更直接。没有上限的长流程，会在某个节点上调模型时超窗失败，日志里只剩一个上游 400，很难反推到是提示词太长。

## 二、先把场景定义清楚

我们把“一次装配”拆成七个场景，每个场景只回答一个问题：这段提示词是替谁准备的。

| 场景标识 | 用途 |
|---|---|
| `chat_turn` | 对话轮次，沿用对话侧既有策略 |
| `collab_plan` | 协作里的规划角色提示词 |
| `collab_exec` | 协作里的执行角色决策提示词 |
| `collab_review` | 协作里的审查角色提示词 |
| `task_start` | 桌面任务启动时的会话上下文块 |
| `task_step` | 桌面任务每一步的决策提示词 |
| `flow_node` | Flow 里的 LLM 节点 |

场景只是纯数据，不引入生命周期，也不做成对象。它最大的作用不是分类，而是让“这段提示词属于谁”在日志、事件和测试里都有同一个名字。

## 三、数值一个都不改

收口不是重新调参。我们先把已经跑过的实测值固定下来，两个预设保持原样：

| 预设 | 窗口比例 | 下限 | 上限 |
|---|---|---|---|
| `contextBlock` | 15% | 320 | 2000 |
| `stepHistory` | 12% | 320 | 1200 |

几个典型窗口的结果也逐项对齐：

- 4096 窗口：上下文块 614，步骤历史 491；
- 32768 窗口：2000 与 1200，都已顶到上限；
- 1000 窗口：两者都落到 320 的下限；
- 窗口未知：直接取各自的上限。

先锁数值、再动实现，是这类收口的基本顺序。否则“统一”很容易变成“顺手改了几个数字”，回归时说不清是结构问题还是参数问题。

## 四、一行公式

两个预设的结构完全相同，于是预算解析只剩一个函数：

```ts
resolveClampedBudget(contextWindow, kind)

// 窗口未知或非正数：返回 maxTokens
// 否则：max(minTokens, min(maxTokens, floor(window × ratio)))
```

`kind` 只接受 `contextBlock` 和 `stepHistory` 两个值，其余细节都在预设表里。调用方不再关心“是哪个域”，只关心“是哪类预算”。

这样做的收益不在代码行数，而在可验证性：拿五个窗口档位跑一遍，就能证明新旧实现逐项相等。

## 五、旧函数不删，改成委托

改名和搬家会波及一堆调用方和测试。这一轮我们保留了原来的两个导出函数，只把内部实现换成对新函数的委托：

```ts
resolveTaskContextBudget(window)
  → resolveClampedBudget(window, 'contextBlock')

resolveStepHistoryBudget(window)
  → resolveClampedBudget(window, 'stepHistory')
```

调用方一行不用改，测试也不用重写。等未来某次重构时，再决定是把旧名字彻底删掉，还是干脆让调用方直接使用新函数。

接口兼容不是保守，而是把“结构收口”和“调用点清理”拆成两件事，避免一次提交里同时出现行为变化和签名变化。

## 六、对话侧为什么没有并进来

对话侧也有一套预算，但它的维度不同：它表达的是“某类意图下，各类上下文的配额比例”，不是“某段内容占窗口多少”。

强行合并会抹平意图之间的差异，等于用一个更粗的模型覆盖一个更细的模型。所以我们只把 `chat_turn` 用作快照上的标注，计算逻辑保持不动。

判断两套逻辑该不该合并，标准不是“看起来都在算预算”，而是“它们回答的是不是同一个问题”。

## 七、边界与结果

这一轮只做了三件事：场景枚举、预算预设、单一公式。没有引入控制器对象，没有注册表，也没有插件机制。

结果是：

- 改比例或上下限，只需要动预设表；
- 小窗口适配经验可以跨域复用；
- 预算数值与旧实现完全一致，回归面可控；
- 旧函数仍可调用，外部与测试不受影响。

预算是最容易被复制的一段代码，因为它短、看起来无害。等它复制到第四份时，问题已经不是代码丑陋，而是没人能回答“这个数字到底是谁定的”。
