# 记忆成图：从孤立事实到可解释的关系

长期记忆系统做到后面，真正的瓶颈往往不是「记不住」，而是「记下了但连不起来」。

单条记忆能回答「用户叫什么」「用户在准备什么考试」，却回答不了「搬家那天要特别注意什么」——因为答案分散在两条记忆里，而它们之间没有任何关系。

v2.31 的主题是「记忆成图」，但不是上一套图数据库。它只做三件事：

- 给同一来源抽出的记忆连一条可解释的边；
- 召回命中后，沿边多看一跳；
- 空闲时把同义主体、重复内容和悬空边整理干净。

## 一、为什么先做来源边

记忆之间的关系有很多种：因果、时间、人物、主题相似。

最稳妥的第一步不是让模型去猜，而是记录系统本来就知道的事实：这两条记忆来自同一条助手消息。

这个关系零成本、可解释、不会错。用户问「为什么这条记忆会出现」，答案可以是「因为它和命中的那条来自同一段回复」。

## 二、边是派生数据

关系边不参与强一致，也不进备份的强一致范围。

它可以从记忆重建，可以整表清空，归档记忆的边可以直接删掉。

把它当派生数据，设计一下就松了：不回填历史、不建外键、写失败只告警。

## 三、召回只扩一跳

图能力很容易失控：两跳、三跳、社区发现、中心度排序。

这一版只做一跳，而且只在命中结果之后：取最高分两条做种子，邻居分数按「种子分 × 边权」计算，低于下限就丢，最多补两条，总数仍是三条。

它不会改变原有召回口径，只是让「命中一条」有机会带出「同源的另一条」。

## 四、整理不引入新模型

空闲整理三步都是纯规则：同义主体归一、正文归一后重复归档、悬空边清理。

不做嵌入聚类，不做 LLM 判断。规则能覆盖的部分先做，覆盖不了的留给后续版本。

## 五、观测跟着功能走

既然新增了边、关联召回和整理，就要能在界面上看到：

- 现在有多少条边；
- 有多少次召回用到了邻居；
- 上次整理归档了多少、合并了多少、清了多少边。

没有这三项，功能是否生效只能靠猜。

## 一句话

**先把一条不会错的关系做出来，再谈更复杂的图。**
