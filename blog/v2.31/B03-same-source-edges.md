# 建边：在记忆落库之后，顺手连一条线

边从哪来？

这一版只回答一个问题：**同一段回复里抽出的多条记忆，彼此相关。**

## 一、时机放在落库之后

回合记忆的流程是「抽取 → 去重/冲突消解 → 落库」。

建边放在落库之后，因为它需要拿到最终的记忆 id；放在抽取之后则要处理「被合并掉的那条没有 id」的边界。

顺序是：

1. 抽取候选；
2. 与既有记忆去重、消解冲突；
3. 写入或更新；
4. 用本回合最终留下的记忆建边。

## 二、配对要规范化

同一来源有 N 条记忆，两两配对会产生 N×(N-1)/2 条边。

如果不去重方向，A→B 和 B→A 会各写一行，邻居查询就会重复命中同一条记忆。

做法是按 id 数值升序排序后再配对，只写「小 → 大」一个方向；查询邻居时两端都查。

## 三、只连「应该被想起」的记忆

建边前过滤三类：

- `status` 不是 `active` 的（已归档、已被取代）；
- 置顶记忆（它们本来就优先进入提示词）；
- `constraint` 类记忆（硬约束不该被邻居扩展带进来）。

这样邻居集合天然是「普通、活跃、值得补充上下文」的记忆。

## 四、重复写入取大

同一对记忆可能因为重复抽取再次建边。

唯一约束保证只有一行，冲突时用 `MAX(weight)` 更新：新关系权重更高就覆盖，更低就保留原值。

这让建边操作天然幂等。

## 五、失败不影响主流程

建边是派生动作。

如果它抛错，不能让记忆落库回滚，更不能让回合失败。所以整段包在 try/catch 里，失败只记一条告警日志。

## 小结

建边不复杂，复杂的是边界：

- 时机在落库后；
- 配对规范化；
- 只连活跃普通记忆；
- 重复写入取大；
- 失败隔离。

这五条定完，建边就是一段几十行的纯函数加一次仓储调用。
