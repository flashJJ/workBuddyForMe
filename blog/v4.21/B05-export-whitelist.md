# 记忆导出：白名单比脱敏更可靠

当用户想带走自己的记忆时，最容易犯的错误是「先全量导出，再删敏感字段」。

黑名单式脱敏有两个问题：新增字段默认被导出，评审时很难发现；删除逻辑散在各处，改了一处漏一处。更稳妥的做法是反过来——只允许白名单字段离开。

## 一、导出是用户主动动作

先说边界：记忆导出包含正文。

这不是矛盾，而是定位不同：

- 解释面板是系统自动展示，必须只含元数据；
- 导出是用户点击「导出」后产生的本地文件，用户知道自己在导出什么。

系统不做后台自动导出，不把文件上传到任何地方，也不把导出接进定时任务。边界靠「只有用户主动触发」守住。

## 二、白名单字段

每行只保留十个字段：

```text
kind / content / scope / importance / status / pinned
confidence / subjectKey / createdAt / lastConfirmedAt
```

明确排除：

- 来源会话 id、来源消息 id；
- 审计明细与轮转信息；
- 向量与嵌入模型信息；
- 本机路径与内部版本号。

实现上先用一个映射函数把记忆对象收成导出行，再由 Markdown / JSON 两个构建器消费。以后记忆对象新增字段，默认不会出现在导出里——这是白名单的核心价值。

## 三、两种格式

**Markdown** 适合人读：

```text
## 1. fact · global · active
- 重要性: 0.50 · 置信度 0.80 · 固定 是
- 主体: city
- 创建时间: 2026-11-22T...
```

**JSON** 适合迁移：

```json
{
  "version": 1,
  "exportedAt": "2026-11-23T...",
  "memories": [{ "kind": "fact", "content": "...", "...": "..." }]
}
```

JSON 带 `version` 字段，为未来的格式变化留出判断依据；但这一版没有导入功能，导出只保证可读、可审计。

文件名统一为 `memories-YYYYMMDD.md` / `.json`，日期取本地时间。重复导出同一天会覆盖同名文件，这是浏览器的默认下载行为，不额外处理。

## 四、导出范围与界面一致

导出使用当前列表的数据，也就是用户眼前的筛选结果：

- 搜索词、类别、状态、时间范围都会影响导出；
- 不额外请求全量数据，不绕过筛选。

这样用户看到的和带走的是同一批记忆，不需要猜「导出到底包含了什么」。

## 五、几个细节

**布尔值本地化**：Markdown 里的「固定 是/否」跟随界面语言，JSON 保持布尔值。人读与机读分开。

**空值处理**：`subjectKey` 与 `lastConfirmedAt` 可能为空，Markdown 直接省略该行，JSON 保留 `null`。

**正文原样输出**：Markdown 不转义正文中的 `#`、`-` 等符号。记忆是用户自己的文本，强行转义反而破坏可读性；JSON 由序列化器保证转义。

## 六、测试

- 文件名匹配 `memories-\d{8}\.(md|json)`；
- 导出对象不含来源 id、向量与路径字段；
- Markdown 包含正文、重要性与固定状态；
- JSON 的 `version` 与 `memories` 结构稳定。

白名单不是更复杂的脱敏，而是更少的选择。字段越少，越不容易泄露；默认不导出，才谈得上可信。
