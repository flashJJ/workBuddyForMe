# v1.1 复盘：零新功能的一版，买到了什么

v1.1 没有交付任何用户可见功能：没有新按钮、没有新能力线、数据库迁移 0 个、线上 HTTP/SSE 协议一字未动。相对上个版本，496 个文件、+7741/-4298 行，增量主要来自测试和评估平台。这篇做收口：先对账，再提炼方法论，最后回答那个最现实的问题——单人项目花一个完整版本还工程债，值不值。

## 起点：上个版本留下的五类债

上一个大版本同时长出语音、形象、桌宠三条能力线，速度优先的代价在封版时看得很清楚：

| 债务 | v1.0 的维持方式 |
|---|---|
| 跨层依赖、internal 私有域 | 靠约定和评审肉眼抓，违例没有任何工具声响 |
| 大工具输出 | 约 100KB 的结果原样回灌，和记忆、对话正文抢上下文窗口 |
| 热点文件 | ≥260 行手写文件 28 个，最长的 483 行靠白名单续命 |
| SSE 事件契约 | core/web/wire 三处手写联合，漏列事件编译不报错 |
| 语音运行时 | 长在 web 应用层，core 无法复用，边界倒挂 |

这五类问题的共同点是：**它们都不会让今天的功能坏掉，只会让明天的每次改动更贵**。v1.1 的主题因此不是「修 bug」，而是回答一个问题——当代码规模继续增长，哪些不变量应该由工具强制，而不是靠人记住？

## 收益对账：零功能版本的成功指标

| 承诺（方案里的成功指标） | 封版对账 |
|---|---|
| 分层边界靠工具强制，error 态 0 违例 | warn 观察一个完整版本零违例后翻 error，全仓 0 违例，违例探针实测 exit 1 |
| ≥260 行手写热点文件显著下降 | **28 → 1**（降幅 96%），白名单仅余自动生成类 |
| 100KB 工具输出不再硬吃上下文 | 约 **41k → 1.6k token**（约为原来的 4%），首 id 二次引用 PASS，UI 全文可见 |
| 语音能力打包态与旧版行为一致，编排归位 core | core/voice 独立子路径入口，web 只剩薄壳；打包真机 TTS→ASR 回环逐字正确 |
| SSE 事件无法「悄悄漏列」 | 单一真源派生 + 穷尽 switch + 12 事件锁数 + 13 帧 wire 窄化，删映射即红 |
| 评估 ≥3 域且全部带反向验证 | 记忆/工具压缩/主动轮三域；回退压缩器 3 条断言如期 FAIL（40949 token 原样入模） |
| 核心覆盖率门槛不降级 | core 全局 70% 不动；压缩模块四指标 95% 新硬门槛（实测 100/98.8/100/100） |

另外两笔记账：core 554 测、web 278 测全绿；web 首次接覆盖率，三个关键域以 64/80/67 贴着 60% 门槛过。以及封版后真机抽测抓出的两个打包态热修（上一篇详述）——它们没进上表，但它们是这个版本最重要的产出之一。

账目的另一面也得记：全仓仍挂着 22 条历史 warning（只出报告不阻断，留给后续版本自然消解）；web 的 64% 和 67% 离 60% 门槛只有一步之遥，说明门槛是诚实的、也说明 web 测试水位仍薄；更扎心的是，一套全绿的门禁体系放行了两个真机故障——上表证明的是「计划内的不变量被守住了」，而热修暴露的是「还有不变量压根没被识别出来」。成功指标全部达成，不等于盲区不存在。

## 方法论一：强制力分层，每个不变量只交给一个工具

编译器、测试、CI 各管一件事，**任何不变量都不依赖人在评审时记得**：依赖方向归 ESLint zone；事件契约归 TS 条件类型派生加穷尽 switch；「不能漏列」归运行时镜像集合加变异测试；预算约束归纯函数出口硬保证。工具不擅长的（比如「这个抽象划得合不合理」）才留给人。先问「这条规矩该由谁强制」，再写代码。

落地时连 ESLint 规则自己的语义坑都一并摸清了：方向 zone 的 from 必须用非 glob 目录（同包天然放行），internal 限制无法靠 except 按发起方开口子，只能把「发起域 × 其他包 internal」全配对枚举；规则上线还配了「故意违例必须被抓住」的探针。强制力分层不是把规则写进配置就完事——**强制工具本身的有效性，同样需要验证**。

## 方法论二：新规则先 warn 观察一个完整版本，再翻 error

边界门禁上线当天就是 error，只会和 28 个热点存量代码当场打架，最后逼出一堆 disable 注释。实际路径是 warn 贯穿五个里程碑，让存量代码在正常演进中自然迁移，观察到整整一个版本零违例后，翻 error 才成为一次无冲突的收割。配套的硬规矩是**合理越域走架构评审，不接受 eslint-disable 开口子**——例外一旦开了，zone 图就退化成建议。**门禁的目的是维持秩序，不是制造存量罪犯；但也绝不售卖特赦。**

## 方法论三：重构的安全姿势是行为外迁，不是重写

本版本三次大搬迁（热点拆分、barrel 子路径化、语音下沉）用的是同一套姿势：**代码整簇外迁、测试随迁断言零修改、页面路由零改动；每个里程碑是独立提交批次，任一关标准不过可以整体 revert**。典型如那个 483 行、长期靠白名单续命的热点文件，拆成四个职责单一的协作对象后主文件降到 260 行内、移出白名单，而它名下 23 个测试的断言一个字没改——这就是「搬行为」而非「改行为」的取证。954 个具名成员、401 个文件的 barrel 迁移靠 TS checker 机械归属，不靠人眼分类。可整体回滚的批次让大重构始终有退路——这是单人项目敢动结构的前提。

## 方法论四：压缩只造视图，不改事实，给模型留查回的句柄

中央压缩层只改变「模型看到什么」，完整 ToolResult 照常进 trace/SSE/UI，压缩器是无状态纯函数、预算在装配期下发、不读任何全局状态。knowledge 类结果的编号一个不丢，预算不够时按「短摘录贪心 → 纯编号行 → 文本兜底」三级降级——哪怕压到只剩编号，模型被压掉的内容也永远能用具体 id 二次查回，工具连环调用不因压缩断链。JSON 类结果只做结构头取样、末级保留身份字段；错误结果和计算机类工具结果干脆不压。**省 token 不能以牺牲事实可回溯性为代价**——41k 到 1.6k 的账是这么达成的，27 个针对性测试（含随机感长文恒不超预算）守的也是这条。

## 方法论五：子路径化先保类身份，再谈域边界

子路径 exports 最诱人的收益是清晰的域边界，但独立 chunk 会让同一个类（最典型的是统一错误类型）在两个 chunk 里各存一份副本，`instanceof` 静默失效，错误分支悄无声息地全部走错。所以规则是：import/require 生产条件**统一指向既有单 bundle**，类型/开发条件才指向源码；全仓 19 个子路径域全部按此落地，根 barrel 保留兼容但消费侧归零。voice 独立入口是唯一验证过的例外——双入口产物的共享块只有 esbuild 的 export helper，才放行。边界是收益，类身份是地基，顺序不能反。

## 方法论六：覆盖率门槛要对照真实分支结构，门槛自身也要被测试

压缩器分支覆盖 98.8%，唯一未覆盖的臂是 hint 预留导致的**数学上不可达**分支——保留防御代码，门槛因此诚实地设 95 而不是拍 100。每个门槛数字都要能回答「没覆盖的是什么、为什么允许」。同时，glob 门槛匹配是静默的，配错 glob 等于没门槛；配完必须临时抬到不可能值、亲眼看到 exit 1 自证一次。**规则和裁判自己也需要取证。**

## 方法论七：环境差异矩阵是桌面应用的测试盲区

封版后两个真机事故长在同一块盲区：开发态与打包态是两个世界——启动是否经 `--require` 注入、数据根是空目录还是带密文的真实根、凭据走直连还是跨进程同步桥、窗口存活几秒还是闲置几十秒。三层防护（开发态/e2e/打包冒烟）恰好每一层都绕开了故障条件。从此「测试全绿」要按**环境差异矩阵**审计覆盖面：只覆盖「无注入、空数据根、短生命周期」的测试，不能为打包态背书。这一条的学费是 28GB 内存和 700 个 worker。

防回归测试的设计也被这两个事故教育了：判 fork 炸弹，用子进程文件计数（健康态引导恰好执行 1 次）比用资源 API 数 worker 可靠——worker 生灭太快，采样瞬间根本数不到；测同步桥，mock HTTP server 必须放在独立 Worker 线程，否则调用方的等待会把同线程的 mock server 一起冻死，给出「fetch 超时」的假象。**测试的拓扑必须复刻生产的拓扑，隔离边界错了，测到的就是假行为。**

## 纪律：明确不做什么，和做什么同等重要

零功能版本最大的风险不是做少了，而是做着做着开始「顺手」：顺手换个 UI 体系、顺手引个 DI 容器、顺手把两个校验库合一。本版本的 Non-Goals 清单事先写死、中途没破：不碰任何用户可见行为与线上协议，不引入装饰器框架，不改变响应信封，不做视觉层重构；其余包只出覆盖率报告、不设硬门槛（先看清水位，下一版再议）。

连「顺手修」都被克制——一个构建期 tracing 警告属于预先存在项，最终登记为已知问题而不是当场修掉。范围纪律的含义是：**每个版本只解决自己主题内的问题**，否则加固版本会悄悄膨胀成什么都沾一点、什么都没扎透的版本。

这份克制还体现在依赖账上：整个版本没有新增一个运行时依赖，唯一的新增是开发侧早就躺在依赖树里、这次才被启用的覆盖率工具。结构问题用结构调整和测试解决，而不是用新框架把旧问题盖住——对单人项目，每多一个运行时依赖，都是未来多一份升级与排障成本。

## 回到那个问题：值不值

单人项目做工程债版本，最大的成本是时间没有变成任何能演示的东西。但这一版买的不是「代码变干净了」这种感觉，而是后续每个功能版本的**速度下限**：

- 加一个跨层调用，ESLint 当场拦，不用等评审；
- 加一个 SSE 事件，类型派生和契约测试替你数着三处接线，删一行映射测试立刻红；
- 接一个返回巨大输出的工具，压缩层已在中央等着，不用每次记得省 token；
- 挪任何一块代码，子路径和随迁测试保证行为等价，类身份不会裂成两份；
- 发版前，三个 golden set 各自带着「我不是恒真」的证据；
- 发版时，真机抽测按环境差异矩阵走，而不是赌「开发态没事打包也没事」。

工程债的利息是「每次改动都要绕开旧问题」的隐形成本；本金不清，利息随功能量复利增长。零新功能的一版没有让产品往前走一步，但它让之后的每一步都更便宜、更敢踩油门——对一个还要继续长功能线的单人项目，这就是 ROI。

两个热修还给发版流程本身打了补丁：真机抽测从「随手点点」升级为按环境差异矩阵取差异项（注入方式、数据根、凭据通道、闲置时长），打包冒烟不再允许用空数据根自欺欺人。这相当于给「测试全绿」买了一份覆盖维度的保险。

下一个版本重新开始交付功能：代码签名、安装器打磨、a11y、i18n。带着编译器、测试和门禁一起去，而不是只带着人。
