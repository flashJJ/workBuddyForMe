# 回放报告从「一次结果」变成「可以对比的历史」

离线 A/B 回放解决的是「这次改动有没有让上下文策略变差」。但如果只保留当前一份报告，下一次运行时上一次结果就被覆盖，趋势无从谈起。

v4.19 给回放报告加了两件事：历史归档，以及 `--compare=last`。

## 一、文件名就是时间序

历史目录固定为 `test-results/eval-replay/history/`，文件名由报告时间戳生成：

```text
report-20261122T043943123Z.json
```

把 ISO 时间里的 `-`、`:`、`.` 去掉，文件名天然按时间排序。清理时不需要读文件内容，也不需要维护索引：按文件名排序，删除最旧的即可。

只保留最近 20 份。回放不是每天跑几十次的任务，20 份足够覆盖一轮调参；再多就是占磁盘。

## 二、对比只算「候选 − 历史」

`--compare=last` 读取历史中最新一份（排除本次文件名），逐项输出：

```text
指标          上次 → 本次    差值
budgetUsage   0.025 → 0.025   0
memoryRetention 1 → 1         0
```

差值口径固定为「本次候选 − 上次候选」，保留三位小数。Markdown 报告新增「与上次对比」小节，控制台同步打印。

这里刻意不做结论、不给通过/失败。历史结果可能来自不同 golden 或不同策略，把它当成门禁只会制造噪声。阈值判定仍然只针对当前基线。

## 三、对比不能污染隐私边界

历史文件与主报告遵循同一套隐私检查：绝对路径、Bearer 令牌、常见 API Key 前缀。

关键顺序是「先扫描，再落盘」。扫描命中时拒绝写入历史，并在主流程中跳过归档；不能先把可能含敏感内容的报告写进历史目录，再事后检查。

## 四、参数要能从包管理器传进去

`eval:replay` 外面套了一层自动起服务的包装器。默认它只把 `--base-url` 传给孩子进程，`--compare=last` 会被吞掉。

修复方式不是给回放脚本加环境变量，而是让包装器把未识别的参数原样透传。这样所有 eval 脚本都能接收自己的参数，包装器只负责生命周期。

## 五、确定性仍然优先

同一输入两次运行，除 `at` 时间戳外报告必须完全一致。历史与对比没有破坏这个约束：对比对象是上一次的报告，本次报告本身仍然稳定。

只保留 20 份、按文件名清理、对比不进门禁，三个选择都指向同一个目标：让历史成为参考，而不是新的不确定性来源。
