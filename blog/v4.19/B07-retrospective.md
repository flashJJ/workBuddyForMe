# v4.19 复盘：把「顺延项」一次做完

v4.18 发布时主动顺延了五项，加上 v4.17 的两项小遗留，一共七件事。v4.19 的主题只有一个：补完。

## 一、为什么单独做一版「补完」

顺延项有一个共同特征：都不紧急，但都会被用户真实碰到。

- 备用模型只能配一个、只在助手级；
- 失败与切换有事件，但没有汇总视图；
- 回放报告只有单次结果；
- 知识检索结果不能复制引用；
- 桌宠没有主窗入口，窄窗没复核。

如果每项都插进功能版，就会被新功能不断挤到队尾。单独用一版把它们清掉，代价可控，收益是「不再背着欠账做下一版」。

## 二、四类改动的共同模式

### 1. 只做加法，不碰 schema

备用链、会话覆盖、健康度、回放历史全部落在既有 `settings_kv`、`session_events` 与文件目录。零数据库迁移，覆盖安装即可升级。

### 2. 新数据尽量从旧事件派生

健康度没有新增埋点，只给 `message_error` 补一个可选 `modelId`。面板上的数字都可以从既有事件复算。

### 3. 自动化必须有边界

备用链变长，但单轮切换仍最多两次，首字后仍不切换。历史回放对比只展示差值，不参与阈值判定。能力增强，判定不跟着膨胀。

### 4. 小动作也要验收真实结果

复制引用不只看按钮是否出现，而是真的读剪贴板；桌宠入口不只看元素是否可见，而是看中心点是否被遮挡、点击是否真的调用桥接。

## 三、实现期追加：语音与寒暄

计划之外，本版还完成了流式 TTS、本地 Matcha、腾讯云与微软 Edge 在线朗读，以及寒暄快路径。

这部分带来了一个明确的约束偏离：新增 `ws` 与 `mpg123-decoder` 两个运行时依赖。二者均为纯 JS/WASM，无原生编译，已在 standalone 产物中实测。

它没有破坏「每项可独立验收」：语音、快路径、备用链、健康度、回放历史、复制引用、桌宠入口，各自有单测或 E2E，任一功能关闭不影响其他项。

## 四、验证策略

- 核心逻辑优先纯函数：链解析、健康度聚合、引用拼接、回放对比；
- UI 只测行为，不测样式；
- E2E 用生产模式，避免 dev 首次编译与 HMR 干扰；
- 回放脚本单测覆盖历史清理、对比数值、隐私扫描；
- 三档窄窗用同一份断言模板，截图不入库。

## 五、仍然没做的事

- 备用链超过 3 个；
- 健康度趋势图与导出；
- 回放对比升级为 PR 门禁；
- 知识结果「继续任务」「打开审批」；
- 记忆治理、Controller Pipeline、DAG 并行、视觉巡检 L2/L3。

这些不是遗漏，而是明确不在本版。下一版再决定哪些值得立项。

## 六、一句话总结

「补完」不是低价值版本。把七件小事一次做干净，换来的是后续每个版本都不用再回答「上次那个什么时候做」。
