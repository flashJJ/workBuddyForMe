# 桌宠怎么「说人话」：七态、气泡、提示音与深链

用户不打开主窗的时候，桌宠就是他理解系统的唯一窗口。

这句话听上去像句口号，但它是一条硬约束：桌宠不能显示内部状态，只能显示用户能理解的状态。「注意力维度为审批」这种词对工程师有意义，对用户没有；「等待审批 · 发布流程」才有。

## 一、桌宠有自己的连接

桌宠是一个独立的 Electron 窗口，加载同一套 web 端页面，但它自己建立流式连接，不依赖主窗。

```ts
// 伪代码：建连后先拿首帧，之后按帧更新
fetch('/api/work-signals/stream')
  .then((res) => consume(res, setSnapshot))
  .catch(() => setConnected(false))
  .finally(() => setTimeout(run, 3_000));
```

因此主窗可以最小化、切页、关闭，桌宠的工作态都不受影响。断开时它明确显示「工作信号连接中断」，重连后直接覆盖为最新快照。

## 二、七个状态，一份映射

| 条件 | 基础态 |
|---|---|
| 没有活跃信号，连接正常 | IDLE |
| 有待审批项 | WAITING |
| 最近终态是失败、中断或超预算 | ERROR |
| 运行中且活动是思考 | THINKING |
| 运行中且活动不是思考 | WORKING |
| 最近终态成功且在 15 秒内 | SUCCESS（脉冲后回 IDLE） |
| 流式连接断开 | DISCONNECTED |

七态是刻意的克制。每多一个状态，角色动画、文案、提示音、测试矩阵都要跟着翻倍，而用户能分辨的状态数量并没有那么多。

基础态之外还有一个「脉冲」维度：完成和错误只做一次性提示，不改基础态。这样「一个任务刚成功、另一个还在跑」时，用户能看到成功一闪，但角色不会假装自己空闲。

## 三、气泡：多个运行合成一句话

同时在跑三个任务时，桌宠只能显示一行字。聚合规则是：

- 有待审批，优先显示待审批的那一条，标题前写「等待审批：」；
- 有失败，显示最近一次失败的原因（失败原因优先于标题）；
- 都在跑，取最近更新的那一条，副行写「N 个进行中」；
- 有待审批时，副行额外写「M 项待审批」。

气泡本身只读：一个状态点、一个来源徽标（任务、工作流、协作）、一行标题、一行计数。它不提供按钮，不提供菜单，不提供「立即处理」。

显示模式有三档：有工作才显示、始终显示、隐藏。断线时无论哪一档都会显示——因为「连不上」本身就是要告诉用户的事。

## 四、三类提示音，三种含义

| 提示音 | 触发 | 设计意图 |
|---|---|---|
| 完成 | 出现新的成功终态 | 轻，一声，不打断 |
| 出错 | 出现新的失败终态 | 低，稍长，提醒去看 |
| 待审批 | 出现新的审批项 | 两声，明确「需要你」 |

三个开关彼此独立，默认全开。声音用 Web Audio 现场合成，不依赖任何音频文件——既不用打包资源，也不会因为缺文件而静默失败。

有一条容易被忽略的规则：**首次快照只建立基线，不为历史结果补发提醒。** 否则桌宠每次启动都会为昨天的失败响一遍，用户会立刻关掉所有提示音。

勿扰时段内只保留徽标与气泡，不放声音、不弹系统通知。系统的勿扰是系统的事，产品的勿扰必须自己判断。

## 五、系统通知是回落，不是主路径

声音之外还有一层：桌面壳提供系统通知通道。它只在两种情况下用——新的审批、新的失败。

失败的原因写得很直白：通知会被系统勿扰、权限、精简系统拦掉。所以它必须能静默失败，不能因为弹不出通知就让整个提醒链路报错。声音负责「当下注意到」，通知负责「离开座位也能看到」，两者互不依赖。

## 六、断线就显示断线

这一条单独拿出来说，因为它是一个产品决定，而不是技术细节。

很多桌面小组件的做法是：连接断了就保持最后一帧，看起来一切正常。这会让用户以为任务还在跑，实际上早就没有信号了。

我们的选择相反：断线就进入 DISCONNECTED，气泡写「工作信号连接中断」，不显示任何正在运行的内容。宁可承认不知道，也不假装知道。

## 七、点击穿透：一个要付代价的取舍

桌宠窗口是透明、置顶、可点击穿透的。这意味着气泡不能接收指针事件（`pointer-events-none`），这是硬约束。

所以气泡上没有按钮。要看详情、要处理审批，得通过另一条路径：

- **双击头部**：打开主窗，跳到当前主运行的深链；
- **右键菜单**：同样能打开当前工作。

代价很明确：用户不能「点气泡直接允许」。这个能力被推迟了——它需要重新设计命中区域，把气泡的一部分从穿透区里切出来，而这会破坏「空白处点击穿透」这个更重要的性质。**在一个覆盖全屏的置顶窗口上，任何一块可点击区域都会挡住下面应用的操作。**

这个取舍值得写下来，因为它不是「没做完」，而是「这样换更划算」。

## 八、三种深链

深链只允许站内相对路径，格式按来源区分：

| 来源 | 深链 | 落到哪 |
|---|---|---|
| 任务 | `/tasks?run={runId}` | 任务页并定位该次运行 |
| 工作流 | `/flows/{workflowId}?run={runId}` | 流程详情并定位运行 |
| 协作 | `/chat?conversation={id}`，无会话则 `/tasks` | 对话或任务页 |
| 工具审批 | `/chat?conversation={id}` 或 `/tasks` | 发起审批的地方 |
| 审批中心 | `/approvals` | 统一收件箱 |

深链由服务端生成并随信号下发，客户端不做拼接。原因是客户端不知道自己处在哪个窗口、哪个路由上下文里，而服务端知道这次运行属于谁。标题同理：服务端截断到 120 字，不把长文本原样透出。

跳转的实现也分层：桌宠渲染层把路径交给桌面壳的桥，壳把主窗恢复、聚焦，再把路径发给主窗；主窗的路由收到后跳转。桌宠自己不导航——它没有路由。

## 九、这一层的边界

- **不做动作编排。** 桌宠不因为「完成」就播一段庆祝动画再改状态；动画系统有自己的优先级，工作态只提供输入。
- **不做子运行树。** 多个运行是平铺聚合的，父子关系要等下一步。
- **不做待机节奏控制。** 节奏字段已经定义，但还没接角色控制器，所以设置面板里暂时没有入口。
