# 零迁移改造：注册表与快照怎么做到向后兼容

重构最怕两件事：数据要迁移，行为悄悄变。

这次能力/provider/动效三处改造，数据库迁移是零，`LATEST_SCHEMA_VERSION` 保持不变，备份 schema 也没有动。但“零迁移”不等于“零兼容工作”。

下面按四类契约拆开讲。

## 一、数据结构契约：没有新增表与字段

能力包仍然存原来的表：manifest、状态、effect 句柄、错误信息。

改造只改变了“怎么找到 effect 实现”，没有改变持久化内容。因此：

- 旧版本装的能力包，新版本直接能读。
- 新版本装的能力包，旧版本也能读（前提是 kind 在旧版本支持列表里）。
- 备份与恢复不需要升级格式。

这也是选择 handler 注册表而不是“新增一张能力类型表”的原因：后者会把一次内部重构变成迁移。

## 二、错误语义契约：未知类型的行为必须保持

能力 effect 有三种入口，原来的默认行为不同：

| 入口 | 未知 kind 的行为 |
|---|---|
| enable | 抛校验错误 |
| disable | 静默返回 |
| uninstall | 静默返回 |

改成注册表后，这三条都保留：

```ts
const handler = HANDLERS.get(kind);
if (!handler) throw validationError(kind);   // enable
HANDLERS.get(kind)?.disable(ref, deps);      // disable
HANDLERS.get(kind)?.uninstall?.(ref, deps);  // uninstall
```

为什么不统一成“都报错”？因为调用场景不同：

- enable 是用户主动操作，失败必须提示。
- disable 可能发生在清理旧数据时，报错会让卸载流程卡死。
- uninstall 是补偿动作，没有 handler 说明本来就没有资源需要清理。

错误语义是 API 契约的一部分，重构不能顺手“优化”。

## 三、provider 契约：未知协议仍然是结构化错误

原来未知协议抛 `ProviderError.unsupported`，包含协议名与错误码 `UNSUPPORTED_PROVIDER`。

注册表版本保留同一错误：

```ts
const factory = FACTORIES.get(protocol);
if (!factory) throw ProviderError.unsupported(protocol);
```

上层的重试、提示、设置页校验都不需要改。

新协议注册是纯加法：不注册时行为与旧版完全一致。

## 四、内容契约：默认白名单不能少一项

剧本生成器依赖一份白名单：姿势、动作、行为、表情、手势、视线、台词池、道具。

改造后白名单从默认快照派生。为了确认没有少项，我们保留了原有测试：

- 白名单包含指定姿势。
- 包含指定动作。
- 包含指定行为。
- 包含表情、手势、视线、台词池与两类道具。

只要默认快照直接引用原静态表，这些断言就应当原样通过。

另外补了一条引用断言，防止默认快照变成拷贝：

```ts
expect(DEFAULT_CONTENT.poses).toBe(POSES);
```

## 五、用户可见变化不算迁移

这次有两处用户能直接感知的变化：

1. 舞台普通模式默认角色从 2D 变成 3D。
2. 舞台入口从“托盘单项”变成“子菜单 + 舞台内切换”。

它们不需要数据迁移，但需要写进发布说明：

- 用户会看到不同的角色。
- 用户会看到不同的菜单结构。
- 低配机器首屏加载会更重。

“零迁移”只说明数据兼容，不说明体验无变化。发布说明必须把体验变化单独列出来。

## 六、回滚路径

这次的回滚成本很低：

- 注册表是纯加法，删掉注册函数与表，恢复 switch 即可；provider 同理。
- 动效快照默认引用原静态表，删掉参数就回到原行为。
- 舞台默认值改的是常量，回滚就是改回旧 id。

没有数据形态变化，所以回滚不需要写修复脚本。这是“零迁移”带来的额外收益。

## 七、版本号与发布

版本号升到 3.1.0 并通过单一事实源同步；安装包本轮未生成，需要时再跑构建脚本。

## 八、兼容性检查表

做类似改造时，可以按这五项自查：

1. 持久化结构有没有变？变了就要迁移。
2. 错误码与错误消息有没有变？变了调用方可能误判。
3. 默认值有没有变？变了要写发布说明。
4. 旧数据能不能直接读？不能就要写回填。
5. 回滚是否需要脚本？需要就说明耦合太深。

零迁移不是目标，**可解释的兼容边界**才是。

## 九、结果

- 零数据库迁移，schema 与备份格式不变。
- 六类能力与两个 provider 协议的错误语义不变。
- 默认动效 golden 零差异，剧本白名单字段不变。
- 用户可见变化已写入发布说明。
