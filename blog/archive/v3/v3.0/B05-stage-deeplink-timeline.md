# 一条链接进小剧场：舞台深链、就绪幕布与逐句时间线

我们的桌面 AI 应用是本地优先、单人开发、Electron + Next.js 交付的私人助手。除主工作区外，它还有一个独立舞台窗口，用来播放角色的小剧场。

分享一个「看演出」的链接很容易做坏三件事：参数脏了白屏、模型没加载完就开演、切到后台再回来台词已经跳了三句。

这一篇拆舞台这条链路上的三个决定：参数白名单、就绪幕布、以及一条按台词长度走的轻量时间线。

## 一、深链只认白名单

舞台路由接受三类目标：协作现场、多助手会议、小剧场。小剧场用 `?stage=play&ep=<剧集>` 进入。

参数不是直接读出来就用，而是一个一个洗：

```text
run     = clean(param('run'))       // 1..80 位字母数字下划线短横线
meeting = clean(param('meeting'))   // 同上
theater = param('stage') === 'play' // 精确等于，不是 startsWith
ep      = clean(param('ep'))        // 剧集另有更严的 1..40 位、仅小写与短横线
```

任何一项不合法就变成 null，等同于「没传」。`ep=../etc`、`ep=UPPER` 都会被洗掉，回落到默认剧集。

模式优先级是剧场 > 会议 > 协作 > 本地演示，避免多个参数互相打架时出现两种模式同时挂载。

## 二、为什么首帧不读 URL

舞台是 Next.js 页面，服务端渲染时没有 `window`。如果首帧直接读查询串，客户端第一次渲染的值会和服务端不一致，触发水合报错。

做法是把目标状态初始化成全空，在 effect 里读 `window.location.search` 再写回。首帧恒等于 SSR 输出，之后才切换。

代价是页面会先渲染一帧「没有目标」的默认舞台。对演出场景来说这一帧不可见，因为它正好被加载幕布盖住。

## 三、幕布要等三席都到

小剧场固定三席角色，全部是 VRM 模型，单个 6 到 9MB，冷启动在慢盘上要 20 到 30 秒。

如果不等加载完成就开演，观众会看到：主角说话时只有字幕，配角在第二句才从透明里浮出来。

所以进入剧场先挂一块加载幕布，统计就绪度：

- 只统计 VRM 席位，Live2D 由共享层自己加载，不参与计数；
- 角色加载成功回调 `markReady`，加载失败也回调，失败同样放行；
- 换 cast 时清空旧的就绪表，避免沿用上一集的状态；
- 45 秒兜底，超时把所有席位视为就绪，绝不无限等待。

幕布上显示「已就绪 / 总数」与一条进度条。这个数字不是装饰，它能区分「卡住了」和「还在加载」。

## 四、就绪之前不出声

音频层也订阅同一个 ready。未就绪时既不合成台词、也不起背景音乐，避免幕布还盖着画面就先传出声音。

这个细节不做的话，首句往往在模型加载的十几秒里被念完，幕布拉开时角色刚好闭嘴。

## 五、每句停多久

时间线不是固定间隔轮播，而是按台词长度估算：

```text
step = clamp(2400 + 字符数 * 170, 3600, 12000)  // 毫秒
```

三段取值都有原因：3.6 秒下限保证短句不被抢话，12 秒上限避免长句拖住整场，2400 的基础值留给动作和表情起势。

估算只是下限。真正推进还要看语音状态：正在朗读时不切句，避免长句被下一句截断。

## 六、15 秒的硬上限

只等语音会有风险。自动播放策略拦截、音频解码异常、设备中途切走，都可能让「正在朗读」永远为真。

所以加了一个 15 秒上限：从检测到朗读开始计时，超过 15 秒无论状态如何都推进到下一句。

这一条是整条时间线里唯一的硬兜底。没有它，一场戏会永远停在同一句，而界面看不出任何异常。

## 七、用轮询而不是一次定时

推进逻辑没有用「算出 step 后 setTimeout」这一次性定时，而是 250 毫秒轮询一次，自己比较已过时间。

原因是语音状态是外部输入，随时会变。一次性定时器在语音延长时无法续期，只能推倒重设，反而更容易出竞态。

轮询的成本可以忽略：一场戏六句，每句最多几十次判断。

## 八、切后台暂停，回前台补播

页面不可见时，时间线停止推进，音频同时停掉。这里用的是 `visibilitychange`，不是 `blur`，因为切到别的窗口但页面仍可见时，演出应该继续。

回到前台做三件事：重新计时、恢复背景音乐、补播当前句。

补播的是当前句而不是下一句。否则用户切回来会发现自己错过了一句台词，剧情直接断层。

## 九、上一句、下一句、重播与暂停

四个控制都是纯状态操作：

- 下一句与上一句对总句数取模，最后一句之后回到第一句；
- 重播把索引归零并恢复播放；
- 暂停/继续只切一个布尔值，时间线、语音、背景音乐都跟着它走。

因为都走同一套状态，暂停八秒再继续时，当前句会从头念，而不是从中途接着念。

## 十、幕是半开区间

一集分两幕。幕用半开区间 `[from, to)` 指向台词下标，比如第一幕 `[0, 3)`、第二幕 `[3, 6)`。

取当前幕时先对索引取模，再找第一个满足 `from <= index < to` 的幕。越界或没有幕定义时返回 null。

半开区间的好处是边界不重叠：第 3 句只属于第二幕，不会同时命中两幕，也就不会出现背景闪一下再切回去。

幕可以覆盖三样东西：背景变体（幕布、聚光灯、无）、配乐情绪、类型标签。取值顺序统一是「幕 > 剧集 > 兜底」。

类型标签同时驱动换句提示音的音色：喜剧用轻快，悬疑用紧绷，悲剧用低沉。

## 十一、站位决定朝向

三席按槽位排布，左右两席不该正对镜头，而该看向另外两人的平均位置。

朝向由一个纯函数算：取其他席位的横向位置均值，与自身位置求差；差值小于 6% 视为基本居中，不转；否则按每百分点约 0.012 弧度换算，并夹在正负 19.5 度内。

结果透传到模型的姿态层做平滑插值，拖拽换位后重新计算，所以三席说话时更像在互相对视。

## 十二、一句话

**舞台的稳定性不来自更多判断，而来自把「什么时候可以开演」「什么时候该推进」这两个问题各自收敛到一个明确的信号上。**

就绪度决定开演，语音状态加 15 秒上限决定推进，可见性决定暂停与补播。
