# 让 3D 角色的表情有「力度」：118 个 morph、三档强度与一条独立口型通道

桌面 AI 应用里的 3D 角色一旦开口说话，表情就容易露怯：开心只有一个笑，生气只有一个皱眉，一句平静的问候和一句炸毛的吐槽用同一张脸。观感上不是「演出」，而是「换贴图」。

问题不在美术，而在通道设计。表情、口型、眨眼如果共用同一套 morph 权重，既表达不了轻重，也会互相打架。

下面是一次具体的改造：把导出的 118 个面部 morph 编成目录，用 8 组预设覆盖常用表情，再给表情加一条从舞台指令一直透传到渲染层的强度通道。

## 一、先建目录，再谈驱动

模型里能动的表情比想象中多。一次导出带了 118 个 morph，但 VRM 0.x 的标准表情组只有 5 个，且没有惊讶。只走标准组，等于把大部分素材锁在柜子里。

所以第一步不是写渲染代码，而是给这 118 个 morph 建目录：

```text
118 个 morph = 部位 × 语义组 × 程度 × 眼睑状态
部位：眼 28 / 眉 33 / 嘴 52 / 视线 4 / 其他 1
程度：1 slight/small、2 moderate、3 big/broad/sharp
眼睑：_op 睁眼、_cl 闭眼
```

目录的数据源直接用运行时绑定的 targets，名称与索引同源，不会出现「目录里有、模型里没有」。目录本身不驱动渲染，只回答「有没有现成的轻/中/强档」，渲染交给执行器。这条分工很重要：查表和写入混在一起，后面很难扩展。

## 二、8 个标签 × 3 档 = 24 组预设

对外只暴露 8 个表情标签：中性、开心、难过、生气、害怕、惊讶、厌恶、得意。每个标签给三档「眼/眉/嘴」三层的 morph 组合。

| 标签 | 1 轻 | 2 中 | 3 强 |
|---|---|---|---|
| 开心 | 眯眼 0.5 + 浅笑 | 眯眼 0.8 + 抬眉 + 微笑 | 眯眼满 + 抬眉 0.9 + 闭口大笑 |
| 难过 | 忧虑眼 + 愁眉 | 含泪眼 + 嘴下垂 | 含泪满 + 沮丧眉 + 嘴下垂满 |
| 生气 | 怒眉 + 抿嘴 | 怒眼 + 怒眉 + 怒嘴 | 怒眼满 + 怒嘴加强 |
| 惊讶 | 抬眉 + 小张嘴 | 抬眉满 + 小张嘴满 | 瞪眼 + 大张嘴 |

三条硬规则贯穿整张表：

- 只挑睁眼（`_op`）版本，闭眼交给眨眼通道，否则和 wink 叠加会畸变；
- 不占用口型 morph（a/i/u/e/o）与 wink，这两组由别层驱动；
- 每档只改形状大小与附加层级，不改变语义。

解析时同名 morph 取最大权重，避免同一帧里两个合理来源互相覆盖成中间值。

## 三、强度怎样从舞台指令透传下来

强度不是渲染层拍脑袋，而是舞台契约里的可选字段：取值 1/2/3，缺省 2。链路是纯数据传递，没有额外状态机：

```text
舞台指令 { t: 'expression', slot, tag, intensity? }
  → 舞台控制器：每个槽位一份 {tag, intensity}
  → StageActor → VrmCanvas → VrmSession → VrmFaceLayer
  → resolve(tag, intensity) → morph 权重表
```

落地时有三个细节：

第一，`cast` 指令（换一组角色）会把强度整体重置为 2。否则上一集结尾的「强度 3」会带进下一集，角色一出场就是情绪满格。

第二，表情层按 `${tag}:${intensity}` 做缓存。同一档连续多帧只解析一次，换档才重算，避免每帧构造 Map。

第三，强度只作用于 VRM 的 morph 组合；非 VRM 后端保持既有预设逻辑，不因新增字段改变行为。

## 四、说话时，把嘴部表情剥掉

真正麻烦的是同一批 morph 被两条通道争用：表情层想写 `Mouth_smile_op`，口型层每帧要写 `aa`。两者相加，嘴会张到超过模型设计范围。

做法是让表情层在说话期间「只做上半张脸」：

```text
weights = resolve(tag, intensity)
if (speaking) weights = 去掉所有以 Mouth_ 开头的项
apply(weights)
```

说话开始与结束各切一次缓存，中间不重复计算。这样眼睛和眉毛的情绪还在，嘴型完全交给口型通道，两条通道职责清晰。

## 五、坑：张嘴笑 + 口型，笑得舌头都出来了

最早的开心强度 3 用的是 `Mouth_happy_broad_op`。这个 morph 是「张嘴大笑」，几何里自带舌头——单独做表情时没问题，一旦和口型叠加，嘴张到最大，舌头就露了出来。

取证很直接：把强度 3 的开心和一句正常台词同时播，观察口型权重与表情权重相加后的实际形变。结论是两者不该同时生效。

修复是双保险：

- 强度 3 换成闭口版 `Mouth_happy_broad_cl`，表情本身不再带出舌头；
- 说话期间整套嘴部 morph 剥离，只留眼/眉。

单测把这两条钉死：预设里不得出现 `_op` 版大笑，说话态结果里不得有任何 `Mouth_` 前缀。改预设的人不会悄悄把坑埋回去。

## 六、为什么 Live2D 不跟这套

Live2D 的表情由 Cubism 的动作组决定，表情本身就是一段动作，参数没有「同一语义的强弱档」这种结构。硬套强度只会变成改播放速度，语义不对。

所以强度只作为 VRM 侧的可选属性挂在渲染路由上，Live2D 侧读到也不消费，行为零变化。取舍很明确：宁可两个后端能力不一致，也不为了形式统一破坏已验证的 2D 表现。

## 七、数字与验证

- 118 个 morph 全部归类、索引唯一；部位数量与模型一致。
- 8 个标签 × 3 档共 24 组预设，全部只引用目录内 morph，且不占用口型与眨眼。
- 表情强度相关单测 3 项：缺省回落 2、换角色重置 2、剧场逐句端到端落状态。
- 剧场域 49 项、舞台布局 8 项通过；真机按句切换 2→3→1，观感与状态一致。

一句话：**表情的「力度」不是多画几张脸，而是把语义、程度和通道边界写进数据结构，让渲染层只做查表与写入。**
