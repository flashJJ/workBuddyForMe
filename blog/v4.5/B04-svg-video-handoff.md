# 先 SVG 后视频：启动动画的双层交接与降级

首次安装后的第一印象很重要。我们想做一段 8 秒的品牌短片，但又不能让它拖慢日常启动。最后的方案是双层：日常只播 SVG/CSS，首启在条件满足时切到视频层，条件不满足就留在 SVG。

这套“先 SVG、后视频”的交接，比单独用视频或单独用 SVG 都复杂，但它是首帧速度、品牌表达和失败降级之间的平衡点。

## 一、为什么不是一上来就播视频

视频启动动画最直接的问题是首帧不可控：

- 视频文件要读盘、解复用、解码，首帧可能几百毫秒，也可能几秒；
- 不同机器、不同显卡驱动、不同杀毒软件下差异很大；
- 如果视频还没准备好，窗口先显示一个黑底或封面，观感比静态动画更差；
- 首启视频只在第一次播放，日常启动不应该为它付任何成本。

所以我们把 SVG 作为**永远先出现**的底层，视频只是一个可选的增强层。日常模式根本不加载视频；首启模式才在后台 `preload`，并且只在 1 秒内 `canplay` 时才切换。

## 二、双层结构

HTML 里同时存在两个层：

```html
<svg id="brand" class="brand">...</svg>
<video id="cinema" muted playsinline preload="none" poster="poster.webp"></video>
```

- SVG 层：紫色小团子、三张功能卡、光环和连接线，用 CSS `transform/opacity` 做呼吸、漂浮和描边动画；
- 视频层：默认隐藏，`data-view="video"` 时才显示；
- 封面：`poster` 指向一张 WebP，视频首帧未就绪时不会白屏。

首启模式下，页面收到模式后开始加载视频：

```js
video.preload = 'auto';
video.addEventListener('canplay', onCanPlay, { once: true });
video.addEventListener('ended', onVideoEnded, { once: true });
video.addEventListener('error', onVideoError, { once: true });
video.src = 'cinema.mp4';
video.load();
```

注意 `preload="none"` 写在 HTML 里，只有模式明确是首启时才改成 `auto`。日常启动不会产生视频请求。

## 三、1 秒决策窗

视频加载是异步的，但启动画面不能无限等。我们的规则是：

- 页面启动后 1 秒内收到 `canplay`：切换到视频层，播放完整片；
- 超过 1 秒仍未 `canplay`：认为首帧太慢，不再切换，直接使用 SVG 等待态；
- 视频播放中出错：清除视频层，回到 SVG；
- `prefers-reduced-motion`：不加载视频，直接 SVG；
- 高对比模式：同样走 SVG，避免视频里的低对比画面。

这个 1 秒不是视频时长，而是“首帧决策窗”。它保证无论视频多慢，启动画面都不会停在黑屏上等它。

## 四、退场条件

退场由主进程和页面共同决定。主进程只负责告诉页面“主窗已就绪”，页面根据模式决定什么时候退场：

```js
function scheduleExit() {
  if (!mainReady) return;
  const at = elapsed();

  if (mode === 'compact') {
    if (at < 500) return retryAfter(500 - at);
    return exit();
  }

  if (at >= 9000) {
    enterWaiting();
    return exit();
  }

  if (!videoStarted && !videoEnded && at < 1000) {
    return retryAfter(80);
  }

  if (videoStarted && !videoEnded && !skipped) {
    return retryAfter(9000 - at);
  }

  if (at < 500) return retryAfter(500 - at);
  exit();
}
```

几个关键点：

- 日常模式：主窗就绪 + 最小可见 500ms，立刻退场；
- 首启模式：等视频播完，或用户跳过，或到 9 秒上限；
- 如果视频一直没开始，1 秒后不再等它；
- 如果主窗在视频播完后还没就绪，回到等待态，不黑屏；
- 退场动画 240ms，结束后再通知主进程关闭窗口。

## 五、跳过与等待态

完整片最长 9 秒，必须可跳过。我们支持：

- 点击窗口任意处；
- `Esc`；
- `Enter`；
- 空格。

跳过时：

- 如果主窗已就绪，立即退场；
- 如果主窗还没就绪，回到等待态，隐藏跳过按钮，继续显示阶段文案。

这样“跳过”不会把用户扔到一个没有反馈的空白窗口里。

## 六、视频失败不是错误

视频只是增强层，失败不应该弹错。我们的 `onVideoError` 只做三件事：

1. 标记视频未开始、已结束；
2. 移除 `data-view="video"`，回到 SVG；
3. 如果主窗已就绪，重新调度退场。

用户不会看到“视频加载失败”的提示，因为那对启动没有意义；他们只会看到 SVG 继续工作。

## 七、素材与观感取舍

原片是 854×480、60fps、6.27MB。我们转成 854×480、30fps、无音轨、CRF24、faststart，最终 581KB，封面 26KB。

为什么是 30fps：启动动画不是游戏，30fps 足够；减半帧率能显著降体积和解码压力。

为什么无音轨：启动画面默认静音，避免突然出声；有声版本留到未来的启动音效开关。

为什么 faststart：把 moov 原子放到文件头，浏览器可以边下边解，首帧更快。虽然本地文件不需要网络，但 faststart 对解码器预取仍然友好。

854×480 在 150% DPI 下会轻微软化，这是素材限制。我们没有强行放大到 1280×720，因为那会增加体积和伪影，而启动画面只显示几秒，清晰度不是第一优先级。

## 八、小结

双层交接的核心不是“两个动画”，而是**把视频降级为可选增强**：

- SVG 永远可用，负责首帧和等待态；
- 视频只在首启、首帧够快、用户未关闭动态效果时接管；
- 1 秒决策窗避免无限等待；
- 9 秒上限和跳过保证启动不被品牌片绑架；
- 失败静默回落，不把技术问题丢给用户。

这套结构让我们既能做品牌表达，又不牺牲日常启动的确定性。
