# 8 秒短片压到 581KB：本地视频转码与壁纸复用

首启短片生成出来是 854×480、60fps、H.264 + AAC、8.06 秒、6.27MB。对安装包来说，6MB 不算大，但启动画面只需要几秒的观感，没必要为它付出解码压力和体积。

更重要的是，这段片源还要复用为主窗口的视频壁纸。如果启动和壁纸各存一份，安装包会多一份冗余，后续替换素材也容易漏改。

## 一、先明确目标

转码前我们定了四个约束：

1. 启动画面必须快速出首帧，不能因为解码慢而黑屏；
2. 文件尽量小，不挤压安装包预算；
3. 不需要音频，启动画面默认静音；
4. 同一份文件同时用于启动和壁纸，不维护第二份。

这四个约束决定了参数方向：降帧率、去音轨、适度压缩、faststart。

## 二、参数选择

最终命令的核心参数：

```bash
ffmpeg -i input.mp4 \
  -vf "scale=854:480:flags=lanczos" \
  -r 30 \
  -c:v libx264 -preset slow -crf 24 \
  -pix_fmt yuv420p \
  -an \
  -movflags +faststart \
  output.mp4
```

逐个解释：

- `scale=854:480`：保持原分辨率，不放大。启动窗是 640×360，854×480 已经足够，放大只会增加体积和伪影。
- `-r 30`：60fps 对启动动画没有意义，30fps 足够；帧率减半能明显降低码率和解码压力。
- `-crf 24`：比默认 23 略高一点，肉眼几乎看不出差异，体积更小。启动画面只显示几秒，不需要收藏级画质。
- `-pix_fmt yuv420p`：保证 Windows 和浏览器的兼容性，避免某些解码器不接受 4:4:4。
- `-an`：去掉音轨。启动画面 `muted`，音轨只会增加体积。
- `-movflags +faststart`：把 moov 原子移到文件头，首帧可以更早开始解码。

结果：6.27MB → 581KB，约 90.7% 的降幅；封面转成 WebP 后 26KB。

## 三、为什么保留 854×480

有人会问：既然启动窗只有 640×360，为什么不直接转成 640×360？

两个原因：

1. 这段片源还要作为主窗口视频壁纸，整屏播放时 640×360 会明显发虚；
2. 854×480 在 150% DPI 下也会轻微软化，但比 640×360 好；再往上放大到 1280×720，体积和伪影都会增加。

我们选择了一个折中点：启动窗内足够清晰，壁纸整屏略软但可接受。这是素材限制，不是 CSS 模糊；在文档里明确写出，避免用户以为是渲染 bug。

## 四、首帧和尾帧要单独验

视频转码不能只看文件大小，还要看首帧和尾帧：

```bash
ffmpeg -i output.mp4 -vf "select=eq(n\,0)" -frames:v 1 first.png
ffmpeg -sseof -0.1 -i output.mp4 -frames:v 1 last.png
```

首帧决定启动画面切换时会不会闪黑；尾帧决定视频结束回到 SVG 或主窗时是否突兀。我们实际抽帧检查过：首帧是门缝与光，尾帧是暖色群像与潮汐环，和分镜一致。

封面也从视频首帧生成，转成 WebP：

```bash
ffmpeg -i output.mp4 -frames:v 1 -c:v libwebp -quality 82 poster.webp
```

`poster` 的作用是视频还没 `canplay` 时先显示一张静帧，避免白底或黑底。

## 五、一份素材，两处使用

转码后的 `cinema.mp4` 放在桌面端资源目录，随安装包分发；同时复制一份到 Web 静态目录，作为内置视频壁纸。

两处使用方式不同：

- 启动画面：`<video muted playsinline preload="none" poster="poster.webp">`，首启时改为 `preload="auto"` 并播放一次；
- 视频壁纸：背景层循环播放，`muted`、`loop`、`playsinline`，窗口隐藏时暂停，减少动态时回落到封面。

它们不共享播放逻辑，只共享文件。这样做的好处是启动画面不需要理解壁纸的设置模型，壁纸也不需要知道启动阶段；素材更新时只替换一份文件。

## 六、体积与观感取舍

581KB 的短片在启动画面里看起来很轻，但它仍然是一次完整的视频解码。为了不让解码拖慢首帧，我们加了 1 秒决策窗：1 秒内 `canplay` 才切换，否则直接用 SVG。

这个策略把“视频质量”与“启动确定性”分开了：

- 视频质量：854×480、30fps、CRF24，够用；
- 启动确定性：首帧慢就不切，永远不让用户等视频；
- 体积：581KB，安装包几乎无感；
- 复用：壁纸直接使用同一文件，不重复打包。

## 七、小结

本地视频转码不是“跑一条 ffmpeg 命令”就完了，它需要同时考虑：

- 首帧速度，而不只是平均码率；
- 播放场景，启动窗和整屏壁纸的分辨率需求不同；
- 音频是否存在，静音场景直接去掉；
- 兼容性，`yuv420p` 和 faststart 是低成本高收益；
- 复用方式，同一文件多处使用，避免版本漂移。

对我们这种单人项目来说，素材处理最好一次做对，然后把参数和结论写进文档。否则下次换片，又要重新试一遍。
