# 同一张图，三个入口：图面板与光线层的工程细节

图做出来之后，下一步不是加功能，而是回答「在哪里看」。聊天时需要右侧瞄一眼，回看历史时要一个完整页面，会议时又要独立的图。三个入口如果各写一套，节点卡片、聚焦、折叠、错误态很快就会分叉。

这一版的做法是：一个图面板，三个入口复用；一层自研光线，只负责「新动作指向新节点」。

## 一个面板，三种用法

面板的输入只有四个：根类型、根 id、是否实时、是否紧凑。聊天右侧用抽屉 + 紧凑模式 + 实时；时间线页用整页 + 快照；会议页用抽屉 + 实时。展示逻辑完全共用。

面板内部按车道分行，节点卡片显示 kind、状态徽章、标题与两行摘要。运行中的节点叠加流动边框，但边框对读屏隐藏，状态仍然由文字徽章表达。

## 聚焦与折叠

长会话的节点很容易变成毛线球。面板允许把当前运行的车道聚焦、其他运行收起，具体有两种手段：

- 点击车道名聚焦该车道，再次点击取消；聚焦时其他车道不渲染；
- 每个车道有折叠按钮，收起后只保留车道头与节点数。

边由 DOM 测量后绘制：只画两端都可见的节点，折叠或聚焦变化时通过布局键触发重测。选中节点时高亮与它相连的边，其余边降到低透明度。

## 光线层的四个模块

光线不是引一个动画库，而是四个职责清晰的自研模块：

| 模块 | 职责 |
|---|---|
| 几何 | 端点、控制点、缓动、路径采样；纯函数，无 DOM |
| SVG | 创建/更新 path 与光圈；颜色只从语义 token 映射 |
| 环境 | rAF、reduced motion、随机数的默认实现与测试注入 |
| 图层 | 生命周期、发射、同 id 去重、并发上限、暂停/恢复、销毁 |

几何与 SVG 不依赖 React，图层也不把每帧进度放进 state。React 只在挂载时创建图层，在卸载时销毁。

## 为什么不直接引一个动画库

需求只有两件事：一条从 A 到 B 的短光，以及一个沿边框流动的高亮。现成动画库当然能做，但会带来三个不需要的东西：一套运行时、一套自己的时间轴模型、以及和现有 SSR/测试环境的适配成本。

自研四个模块后，几何可以脱离 DOM 单测，图层可以在测试里注入假的 rAF 与随机数，SVG 的创建与移除有明确的生命周期。整个光线能力没有新增运行时依赖，也没有把动画状态塞进 React。

代价是自己要处理暂停、隐藏页、卸载和并发上限。这些恰好是「动画库默认帮你做、但默认不一定适配你的页面」的部分，写清楚比藏起来更可靠。

## 行为契约

- 默认时长 1200ms，允许 120–4000ms；两端慢、中段快；
- 同时最多 12 条光线；超出直接返回 `cancelled`，不排队；
- 同一 id 正在飞行时再次发射，直接 `cancelled`，不叠加；
- 锚点在发射时解析；目标缺失等一帧重试一次，仍缺失返回 `missing-anchor`；
- `prefers-reduced-motion: reduce` 不创建轨迹，直接 `arrived`；
- 页面隐藏自动暂停，恢复可见继续；
- `destroy()` 取消全部飞行、移除 SVG 与监听器。

颜色只接受 `primary/info/success/warning/destructive` 这类 token，运行时拼成 `hsl(var(--token))`，不写死十六进制。

## 实时帧总线：复用，而不是再开一条流

聊天、协作、会议本来就有自己的 SSE 消费方。图面板不再新开流，而是让这些 hook 在收到帧后，把 `meta/tool/done/error/stop` 与协作、会议事件发布到一个模块级总线；面板订阅总线，用纯函数把帧追加到快照。

两条硬规则：

1. **历史基线**：以快照的 `generatedAt` 为界，基线之前收到的帧不补演；
2. **终态不回退**：`succeeded/failed/cancelled/interrupted/budget_exceeded` 一旦写入，迟到的 `running` 帧不能覆盖它。

实时模式下每 10 秒做一次服务端快照校准；时间线入口保持快照 + 手动刷新。

## 坑：动画残留与重复帧

第一个坑是「历史补演」。面板第一次拿到快照时，如果直接把每个节点都当成新节点发射光线，打开历史会话会看到几十条光同时飞。修复是把首帧快照当作基线，记录已知节点 id，只有之后出现的新身份才发射。

第二个坑是「同一帧到达两次」。SSE 重连会重放，光线如果按「收到帧」发射，就会出现同一节点两道甚至多道光。修复是发射 id 由根 id + 节点 id 组成，图层对运行中的同 id 直接返回 `cancelled`。

第三个坑是「卸载残留」。图层挂到页面根节点上，组件卸载如果不销毁，SVG、`visibilitychange` 监听和未完成飞行都会留在页面上。修复是 React 的 effect cleanup 必须 `destroy()`，并把所有飞行清空。测试断言了销毁后 SVG 不存在、所有飞行返回 `cancelled`。

第四个坑是「每帧进 state」。把动画进度放进 React state 会让整个面板每一帧重渲染。这一版进度只在图层内部用 rAF 更新 DOM 属性，React 只关心「有没有新节点」。

第五个坑是「迟到帧回退终态」。服务端已经成功的节点，客户端又收到一条旧的 running 帧，如果没有终态保护，图上会从绿色跳回蓝色。追加层在写入前检查当前状态是否终态，是则丢弃。

## 可读性不是装饰

节点卡片把「状态」拆成两个通道：颜色徽章给人快速扫视，文字标签给读屏与色觉障碍用户。错误节点额外显示错误码；产物节点提供打开入口。边用低透明度曲线，选中时高亮；车道用语义色点分区，不在数据里存十六进制颜色。

这些细节共同回答一个问题：用户能不能在扫一眼之后，知道哪条运行还在跑、哪里失败了、产物挂在哪。

## 收口

过程图最终的价值不在「多了一个可视化」，而在于把追查成本从翻五个页面降到沿一张图走。面板负责读得懂，光线负责看得见当下，接口与投影负责刷新之后仍然一致。三者缺一，图都会退化成一张静态截图。
