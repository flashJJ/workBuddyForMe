# 只读图接口：把历史过程稳定地交出去

过程图最容易做错的地方，不是画不出来，而是「刷新之后不一样」。历史如果靠前端拼接，每次刷新都可能补演一批节点；如果靠接口返回，就要回答三个问题：查多少、按什么顺序、坏了怎么办。

这一版只暴露两个只读接口，把答案写死在契约里。

## 两个入口

| 根 | 路径 | 返回 |
|---|---|---|
| 会话 | `GET /api/conversations/:id/run-graph` | `rootKind=conversation` |
| 会议 | `GET /api/meetings/:id/run-graph` | `rootKind=meeting` |

会话接口接受 `limit` 与 `scope`，`scope` 只允许 chat/task/flow/agent；会议接口只读 meeting scope，不接受会话域。根不存在返回 404，查询参数非法返回 422，投影异常返回 500，响应统一走 `{ success, data }` 信封。

## 查询边界：默认 500，最大 1000

`limit` 默认 500，合法范围 1–1000。越界由查询校验拦下并返回明确的参数错误；投影函数自身也会把非法值钳制到合法区间，避免内部调用绕过校验。

`scope` 是单域筛选，不传就是全部会话域。它解决的是「我只想看任务步骤」的场景，但不改变投影的身份与排序规则。

## 历史聚合有预算

图不能把一条会话的所有事件都读出来。快照服务按域做聚合，每个域都有上限：

| 来源 | 上限 |
|---|---|
| 最近的任务运行 | 20 个 |
| 最近的工作流运行 | 20 个 |
| 最近的协作运行 | 20 个 |
| 每个运行的事件 | 200 条 |
| 聊天事件 | 1000 条 |
| 会议事件 | 1000 条 |

先按创建时间倒序取最近 20 个运行，再各取 200 条事件。这个策略默认「最近的运行更相关」，代价是超长运行可能只保留前 200 条事件。它不是完美的分页，但在本地单机应用里，比一次性全量读取更可控。

## 快照不依赖前端拼装

接口返回的是完整的节点、边、车道与 `generatedAt`。前端拿到就能渲染，不需要再查消息表或运行表。历史加载也不补演光线：快照是既成事实，只有快照之后到达的新身份才触发动画。

生成过程是一条单向链：

```text
确认根存在
  │
  ▼
按 scope 收集事件（chat / task / flow / agent）
  │  每个运行最多 200 条，最近 20 个运行
  ▼
按 at + scope + seq + id 稳定排序
  │
  ▼
五域 apply 写入同一个 builder
  │
  ▼
limit 截断 + 悬空边过滤 + generatedAt
  │
  ▼
{ rootKind, rootId, nodes, edges, lanes, truncated }
```

这条链上没有任何一步依赖前端状态，也没有一步会写库。相同的事件与相同的 `generatedAt`，得到相同的快照；这让接口测试可以断言完整结构，而不是只断言「返回 200」。

`generatedAt` 同时是实时追加的历史基线。客户端把快照时间点之后收到的帧按同一套身份规则叠上去；基线之前的帧直接丢弃，避免「刷新后重播一遍」。

## 刷新与失败

刷新时最坏的情况有三种：根被删除、事件查询部分失败、参数越界。前两种分别落到 404 与域内降级，第三种在进入服务前被 Schema 拦下并返回 422。客户端只需要处理三种表现：空图、可重试的错误态、带截断提示的图。

这里刻意不做「自动重试直到成功」。本地应用的数据库错误通常是可诊断的，静默重试只会把问题藏起来。

## 截断要说清楚

节点超过 limit 时，快照保留根节点与最近 `limit - 1` 个节点，`truncated=true`；边只保留两端仍存在的。界面上必须显示「事件过多，仅显示最近节点」，而不是让用户以为图只有这些。

这条规则在实时追加时也复用：追加后的节点数同样受 limit 约束，截断标记一旦为 true 就保持。宁可少画，不可假装完整。

## 错误隔离

五个域的事件来自五条写入路径，任何一条都可能出现脏数据。接口层的策略是「域内降级，域间隔离」：

- 载荷缺字段：跳过该节点，不抛错；
- 状态无法识别：落到 `unknown`，保留节点；
- 聚合按域收集，某个域的坏载荷只影响该域节点，不把整张图带崩；
- 会议事件写入是 best-effort：失败只记录警告，不阻断会议，图降级展示。

这里的原则和前面一致：**图是观察工具，不是业务主链路。观察工具坏了，不能反过来弄坏业务。**

## 已知边界

- 没有游标分页，超长会话仍靠 limit 截断；
- 运行摘要只来自事件载荷，运行表的补充字段不参与；
- 会议事件可能有缺口，图按已有事件回放；
- 时间线入口首版是快照加手动刷新，不做自动轮询。

这些边界不算「以后再说」，而是这一版明确的取舍。接口先保证一致与可用，再谈完整。

## 验证

Web 集成 11/11；生产模式 Web e2e 140/140；单测 3122 例覆盖投影、聚合与追加的身份对照。接口用例覆盖了根不存在、参数越界、空事件与会话/会议隔离。
