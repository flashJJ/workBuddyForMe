# 复盘：让 Agent 交付出可打开的文件，这一轮买到了什么

我们的桌面 AI 应用是本地优先、单人开发的私人助手。这一轮没有去扩能力市场，只做了一件事：把模型的产出从「对话里的一段文本」推进到「可打开的文件、可导出的图、可导入的内容包、带出处的结论」。

四件交付物，零数据库迁移，零新增运行时依赖。下面是账目、七条方法论、以及这一轮刻意没做的事。

## 一、收益对账

| 承诺 | 落地结果 |
|---|---|
| 把生成内容变成文件 | 写产物工具落盘三种格式，对话内出现可预览、可下载的卡片，刷新后仍在 |
| 图表质量可控 | 十类结构化模板，数据图拒绝空序列、缺值与 `NaN`；超九节点提示拆图 |
| 图能进文档与幻灯片 | 网页端与桌面端共用同一预览页，均可导出 SVG 与 2 倍 PNG |
| 内容型知识库可选导入 | 34 篇正文加 1 篇署名页，逐文件与整包双哈希，约 2.3 MB |
| 结论有出处 | 三类工具带来源、覆盖、未覆盖与采集时间，界面可见，导出保留 |
| 行为不降级 | 2980 例单测、139 例生产模式端到端、桌面冒烟 10/11 |
| 零迁移 | 表结构版本号停在 42，不新增表、列、索引 |
| 包体预算 | 设置页 483 kB，相对上一版 +0.42%，远低于 5% 的红线 |

账目的另一面也要记：单轮产物数量上限写进了契约但没在运行时计数；证据只覆盖三类工具；内容包没有检查更新；通用 HTML 不承诺 PNG。这些都是登记在案的边界，不是没做完却假装做完。

## 二、方法论一：安全边界写进契约，再写功能

预览这段安全策略是在契约阶段就冻结的，不是上线前补的：`sandbox`、默认全禁、只放行内联样式与 data 图片、禁止同源 Cookie。冻结之后才动手写路由与卡片。

顺序反过来会怎样？先做「能预览」，再用安全策略去收紧，通常收不紧——因为功能已经依赖了脚本执行、外链字体、同源请求中的某一项，最后只能妥协。**安全边界的成本在功能之前最低，在功能之后最高。**

这一轮还叠了两层：服务端响应头管文档自身，前端 iframe 的空 sandbox 属性管容器。两层各自独立成立，一层失效另一层还在。

## 三、方法论二：把自由度收进 schema，而不是交给模型

图表最典型的错误做法是让模型手写 SVG。看着灵活，实际不可复现：布局靠猜、坐标靠估、箭头经常穿字。

这一轮把自由度收进判别联合：模型只能选类型、起标题、填结构化数据；布局、坐标轴、箭头、配色全部由模板负责。校验规则写得比模型能想到的更细——边引用必须存在、泳道步骤必须归属、折线点数必须等于标签数。

收窄自由度不是限制能力，而是**把「质量」从模型的临场发挥里拿出来，变成可测试的确定性**。十类图各一例通过，就是这条方法论的取证。

## 四、方法论三：零迁移是设计约束，不是事后统计

「这一轮零迁移」听起来像运气，其实是每一处存储决策都先问过「能不能复用」。

- 产物不建新表，扩三种 MIME 到扩展名的映射，复用附件表；
- 内容包不建新表，版本与哈希写进知识库描述与署名文档；
- 证据不建新列，随工具追踪的 JSON 一起存；
- 内容包的「已导入」状态不新增字段，用固定知识库 id 是否存在来判定。

四处决策用的是同一把尺子：**已有结构能不能表达这个新概念**。能表达就复用，不能表达才谈迁移。零迁移的真正收益不是省一次脚本，而是老库直接打开就能用，没有升级失败的可能。

## 五、方法论四：不可变引用是内容分发的前提

内容包锁死在一个提交上，逐文件校验字节数与哈希，再对拼接结果做整包校验，全部通过才创建知识库。

这条链的核心是「不可变」：如果指向一个会滚动的发布资产，同一份清单在不同时间下载到不同字节，哈希就退化成装饰。锁死版本之后，「用户拿到的就是清单描述的那一份」才成立。

配套的是原子性：任何一步失败都不建库。失败的导入不留下空壳，用户不需要自己去删。**分发内容的产品，最贵的错误不是下载失败，而是留下一个看起来成功、实际没有内容的库。**

## 六、方法论五：旁路数据要有明确的不入模边界

证据字段只挂三处：工具结果、追踪条目、流式结束事件；只进界面与导出，不进模型消息。

三个理由都已经在实现里落地：证据是给人看的；塞进上下文会让模型把「未覆盖」当事实；压缩层只该处理输出。结构性保证比口头约定可靠——字段不参与输出的序列化，压缩器根本看不到它。

这条方法论可以推广到一切「给人看、不给模型看」的元数据：日志摘要、耗时、成本、置信度。它们的共同点是**增加信息量但不增加推理价值**，一旦入模就是纯 token 浪费，还可能污染判断。

## 七、方法论六：回归必须跨过接缝

全量回归抓到两个缺口，都不是新代码写错：

1. 两条新技能只进了内置播种，没进模板清单，模板数量停在 15，实际应为 17；
2. 工具执行器包装结果时只搬运已知字段，产物字段被吞掉——工具单测绿，生产链路却没有卡片。

两个缺口的共同形态是「每层都对，接缝没人测」。所以修法不只是补代码，而是补一条跨层断言：从执行器入口进，断言出口同时带输出、产物与证据；清单类数据用数量断言把两份清单钉在一起。

另一半是环境：端到端首轮用开发模式跑，设置页重载类用例两次编译超时；改生产模式后 139 例稳定通过。桌面冒烟那一项失败被判定为环境问题，依据是它在上一版同样失败。**验收要跑用户实际使用的形态，失败要先问「上一版是不是也这样」。**

## 八、方法论七：偏差要登记，不要假装契约没变

这一轮有三处实现偏离了最初契约，全部写进了实施记录：

| 偏差 | 原因 |
|---|---|
| 图表工具由只读改为写 | 渲染后直接落盘，避免几十 KB 的 SVG 在上下文里搬两次，也避免模型篡改模板 |
| 导出入口放在卡片而非预览页 | 预览是沙箱 iframe，无法在内部注入工具栏 |
| 单轮三个上限未运行时计数 | 界面与契约已声明，计数留到后续 |

偏差本身不是问题，隐藏偏差才是。契约文档如果继续写着「只读」，下一个维护者会按只读去设计调用方，然后在真实链路上撞墙。**文档的价值不在于正确，而在于和代码一致。**

## 九、纪律：明确不做什么

这一轮的非目标清单在动手前就写死了，中途没破：

- 不引入服务端 Chromium、resvg 或 Playwright 到生产依赖；
- 不做四十五类图表全量参考，只做十类简化布局；
- 不做任意地址内容包、不做静默下载、不做任意 HTML 脚本执行；
- 不做远程能力市场，不新增数据库迁移；
- 不重写对话主结构，产物卡片挂在工具追踪区，不新增消息片段。

每一条「不做」都对应一个具体的诱惑。比如图表只有十类，用户一定会遇到画不了的图；但把四十五类塞进来，这一轮就做不完，而且质量会全面下滑。**范围纪律的本质是承认资源有限，并把有限资源压在能被验收的那部分。**

## 十、代价与边界

四件交付物都有明确的表达力上限：

| 交付物 | 上限 |
|---|---|
| 图表 | 十类简化布局，超九节点建议拆图，分组容器只作副标题 |
| 导出 | 仅图表内联 SVG，通用 HTML 只预览与下载，字体不内嵌 |
| 内容包 | 固定版本，无检查更新，上游变化会被哈希拒绝 |
| 证据 | 三类工具，其余工具暂无字段 |

这些上限没有一项是「以后再说」的模糊承诺，都写成了具体行为：超九节点会提示拆图、Markdown 不显示导出、哈希不符直接报错、没有证据的工具不显示徽章。**可预期的限制比不可预期的失败体验好。**

## 十一、四个可以复用的判断顺序

如果要把这一轮的经验压缩成四条，可以按这个顺序问：

1. **这个东西的信任级别是什么？** 不可信内容先定沙箱与策略，再谈渲染；可信的内部数据才谈便利。
2. **自由度该放在模型还是模板？** 有语法、有质量的产出（图、报告结构）放模板；只有措辞与取舍放模型。
3. **已有结构能不能表达新概念？** 能表达就复用，不能表达才迁移。先问这一句，零迁移就不是运气。
4. **这份数据是给谁看的？** 给人看的走旁路（界面、导出）；给模型推理的才进上下文。混在一起两头都不讨好。

这四问的顺序也有讲究：信任级别决定架构，架构决定复用点，复用点决定数据流向。反过来从「怎么实现最方便」出发，通常会在某一层留下需要后面几轮偿还的债。

## 十二、这一轮到底买到了什么

四件交付物合起来，改变的是产品的「出口」：

- 用户拿到的不再是一段话，而是一个能打开、能带走、能贴进别的软件的文件；
- 图不再是模型即兴画的草图，而是有语法、可校验、可复现的产物；
- 知识库里不再只有自己的笔记，还可以一键导入一本带署名与版本的书；
- 每个来自外部的结论旁边，都有一行「从哪来、看了多少、没看什么」。

验收这一轮的标准，从来不是「演示时能跑通」：

| 维度 | 判据 |
|---|---|
| 可打开 | 产物在应用内、下载后离线都能看 |
| 可带走 | SVG 与 PNG 能进文档与幻灯片 |
| 可追溯 | 内容包有版本与哈希，结论有来源与未覆盖 |
| 不降级 | 单测、端到端、冒烟、包体、零迁移全部守住 |

演示能过说明主路径通了；这四条同时成立，才说明它是交付物而不是一个 demo。

对一个单人项目，这些能力不会立刻变成演示效果，但它们把「回答得好」升级成了「交付得出去」。而交付得出去，才谈得上被真正用起来。

同时，这一轮也留下了下一轮的地基：产物计数、更多图表类型、内容包更新检查、证据覆盖更多工具。它们都不需要改结构，只需要在既有骨架上加肉——这正是这一轮最想要的结果。
