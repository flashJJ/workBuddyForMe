# 把一本书装进知识库之前，先处理署名与高风险问题

我们的桌面 AI 应用（本地优先、单人开发）里，导入一个内容包在技术上只是「下载、校验、建库、摄入」四步。但内容不是中性数据：它有一位作者、一份许可证，讲的又是健康、法律与金钱这类一旦被误用就会造成实际损失的话题。技术跑通之后，真正需要设计的是边界。

这篇讲两件事：署名怎么落到用户看得见的地方，高风险问题怎么在回答之前先被分流。

## 一、入口放在知识库模板页

内容包没有单独做成一类「能力」，入口放在知识库模板页。这个选择有三个理由：

- 与既有的知识库绑定、检索链路一致，导入完立刻能问，不需要先理解「内容包」是什么新概念；
- 不混进能力安装的语义，避免用户以为这是一个插件；
- 模板页本来就是「不知道建什么库」时来的地方，放示例包最自然。

卡片上直接给出决策所需的信息：名称、简介、许可、篇数、体积、版本与来源。点「导入」先弹确认框，再次展示下载来源与体积——用户有权在产生流量之前知道自己要下什么。

## 二、署名页：许可证要求的最小集合

CC BY 4.0 允许再分发与改编，条件是署名、附许可证链接、标明是否修改。落到产品里就是一篇自动生成的文档，固定作为知识库的最后一篇：

| 署名页字段 | 内容 |
|---|---|
| 作品名与作者 | 原始书名，作者与贡献者 |
| 来源 | 固定版本的来源地址 |
| 许可证 | CC BY 4.0 及许可证链接 |
| 版本 | 固定提交与对应日期 |
| 整包哈希 | 用于核对内容未被替换 |
| 导入时间 | 本地生成 |
| 修改声明 | 「原文未做修改」 |
| 免责声明 | 见下一节 |

为什么把哈希也写进署名页：署名不只是「写上名字」，还包括「让人能验证你分发的是不是这一版」。哈希放在用户可见的文档里，而不是只藏在服务端清单里，才算完整。

版本字段同样重要。书在持续修订，用户问「第 12 节怎么说」时，必须能确定自己拿到的是哪一版，否则同一个问题在不同时间得到的答案无法互相比较。

## 三、回答里必须有位置

这类内容的回答不能只给结论，要给坐标。技能层的硬规则是引用「第 N 节第 M 条」，让用户能翻回原文核对。

- 检索命中哪一段，就引哪一段的节号与条号；
- 没命中就说没查到，不凭记忆补法条、补剂量、补数字；
- 多段命中时按相关度排序，不合并成一段「大意」。

这条规则看起来只是引用格式，实际是在防一类很常见的失败：模型读过相关内容后，会用常识把缺失的部分补圆。补出来的内容读起来最顺，也最危险。

## 四、高风险问题先分流，再回答

医疗与法律有一个共同点：错误的回答代价不是「不满意」，而是延误。所以技能在任何检索之前先做一次分流：

| 触发 | 处理 |
|---|---|
| 胸痛、呼吸困难、大出血、昏迷、中毒、自杀念头 | 先给急救电话（120 / 110 / 12356），再谈其他 |
| 正在进行中的法律程序（开庭、被拘留、收到传票） | 先找律师或当地主管部门，再谈书里的通用建议 |
| 明确的用药、诊断、投资决策请求 | 明确说明不提供个性化建议，只做资料整理 |

分流的关键是**顺序**：急救信息必须在最前面，不能被一段「根据书中第 3 节……」压在后面。用户在最慌的时候只会读第一段。

同时明确不做的三件事：不做个性化医疗诊断、不做法律意见、不做投资建议。书里的内容是通识，通识不能替代执业者看过你的具体材料。

## 五、免责声明写在哪

免责声明写两处，理由不同：

1. **署名页**：跟着内容走。用户导出、分享、迁移知识库时，声明一起走。
2. **回答页脚**：跟着对话走。用户不会每次都去翻署名页，但每个回答下面都能看到「以医生、律师或当地主管部门为准」。

只在设置里放一条总声明是不够的——没人会去读。声明必须出现在用户产生疑问的那一秒所在的位置。

## 六、内置技能只做三件事

内容包配套的技能不负责「替用户做决定」，只负责：

- 判断问题是否属于高风险，需要先分流；
- 把问题转成知识库检索，命中后按节、条引用；
- 未命中时明确说未命中，并建议用户查阅原文或咨询专业人士。

技能里不写任何具体医学结论或法律条文——那些必须来自检索到的原文，不能来自提示词。这条边界决定了内容更新时不需要改提示词，也决定了模型的自由发挥空间被压在最小。

## 七、几个刻意的取舍

| 取舍 | 理由 |
|---|---|
| 内容包名称与简介固定中文 | 内容本身是中文，英文界面下也展示原名，避免翻译造成误解 |
| 不做个性化建议 | 责任边界，不是能力不足 |
| 不做「一键生成方案」 | 生成方案听起来友好，实际是把通用内容伪装成定制结论 |
| 急症分流不依赖检索 | 检索可能失败，急救信息不能等 |

## 八、验证

技能播种测试两例，确认内容包技能与图表技能都在内置清单里；内容包服务七例覆盖哈希失败、重复导入与下载失败；界面五例覆盖卡片、确认框与导入反馈。高风险分流与引用格式属于提示词层行为，能自动锁住的只有结构——技能是否播种、服务是否拒绝坏数据、界面是否给出确认。措辞层面的正确性，靠技能文本与人工抽测保证。
