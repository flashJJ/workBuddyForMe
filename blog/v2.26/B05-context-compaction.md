# 上下文分层压缩：摘要写成 JSON，数字才活得下来

一个用户和助手讨论了两个月，中间定下了体检间隔六个月、预算五千、会议在三月一日。

对话变长，早期消息必须被折叠。旧的压缩方式是让模型写一段自然语言摘要，结果那一天系统里的摘要变成了「用户计划定期体检，预算有所调整，会议安排在春季」。

信息量还在吗？在。用得上吗？基本用不上。「六个月」变成「定期」，「五千」变成「有所调整」，「三月一日」变成「春季」——三个关键值在压缩那一刻蒸发，后面的对话再也无法把它们捞回来。

这一篇讲上下文怎么分层压缩：摘要为什么要输出 JSON，事实为什么要单独落表，以及为什么要在压缩之后再做一次数字与日期的保真校验。

## 自然语言摘要的三个问题

自然语言摘要不是没用，它对「聊了什么」的概括能力很强。问题出在它同时承担了两类信息：

- **叙事**：用户最近在忙什么、情绪如何、话题怎么演变的。这类信息适合用散文概括。
- **参数**：具体数字、日期、预算、剂量、地址、编号。这类信息需要逐字保真。

散文格式对第二类天然不友好。模型在压缩时会做「合理概括」，而概括的定义就是把细节抽象掉。你很难在提示词里既要求「写得简练」又要求「一个数字都不能丢」，前者会稳定压倒后者。

第三个问题是不可校验。一段自然语言摘要写完了，你没法机械地判断它有没有漏掉某个数字，只能再让一个模型去读，成本和不确定性都翻倍。

## 摘要输出 JSON：四个字段各管一类

改成结构化输出之后，摘要不再是一段文本，而是一个对象，固定四个字段：

- **摘要正文**：保留叙事性内容，用户是谁、在做什么、有什么约定；
- **事实列表**：稳定可复用的事实，每条带一个稳定键、值、单位和生效时间；
- **决策列表**：已经确定下来的决定；
- **未决问题列表**：还没解决、需要在后续对话里继续推进的问题。

提示词里明确要求：原文出现的数字、日期、金额必须原样保留，要么在摘要正文里，要么在事实列表里。事实的键要求用稳定的英文小写下划线命名，同一主体的属性复用同一个键——这样「居住城市」不会这轮叫 city、下轮叫 location。

结构化之后，压缩结果可以被程序读取。这是后面所有校验和渲染的前提。

## 结构化事实单独落表

事实列表不塞回摘要字符串，而是落到一张独立的事实表里。每条事实带这些信息：

- 会话标识，事实只属于某个对话，不跨会话污染；
- 类型，区分事实、决策、未决问题；
- 稳定键，同一会话内同类型同键唯一；
- 值、单位、生效时间；
- 来源消息标识，能追到是哪几句话得出的；
- 校验和，内容没变就不重复写。

唯一约束是关键。模型每次压缩都可能重复输出同一条事实，如果放任插入，事实表会以对话轮次的速度膨胀。有了唯一约束，写入变成「存在则更新、内容相同则跳过」，表的大小和事实数量成正比，而不是和压缩次数成正比。

单会话事实还有数量上限，按类型分组后按更新时间截断。事实是用来支撑当前对话的，不是长期记忆的替代品；超过一定规模说明抽取过宽，该收敛了。

## 数字与日期保真：压缩后要验收

结构化只是让校验成为可能，真正的保险是压缩完成后立刻做一次核对。

做法不复杂：

1. 从**折叠前的原文**里抽取所有数字与日期片段；
2. 把结构化结果（摘要正文、事实、决策、未决问题）拼成一段可比对文本；
3. 逐个检查原文里的片段是否仍然出现在结果里；
4. 缺失的片段收集起来，触发一次重试。

抽取要处理书写差异，否则会产生大量误报：全角数字转半角，斜杠日期统一成连字符，「2026 年 3 月 1 日」和「2026-03-01」视为同一个值，数字与单位之间的空格去掉。误报的代价是被浪费的重试，漏报的代价是永久丢失信息。所以归一化宁可宽一点：先保证「看起来一样的东西能对上」，再谈严格。

## 重试一次，然后兜底

校验失败时先重试一次。重试请求里会明确列出「上一版摘要缺少这些值」，要求模型重新输出完整 JSON。

重试之后如果缺失项没有减少，就放弃继续重试，改用兜底：从原文里挑出包含缺失值的句子，最多三行、两百字，追加到摘要末尾，标成「原文片段」。

```text
首次摘要 → 校验缺失 → 重试一次
                         ├─ 缺失减少：采用重试结果
                         └─ 缺失未减：保留原文片段兜底
```

注意兜底的方向：宁可多占一点上下文预算，也不让关键数字消失。一条体检间隔写错的代价，远高于多占两百个 token。

重试只做一次也是刻意的。模型如果第一次就没保住数字，第二次通常也保不住，继续重试只是在消耗时间和预算，还拖长了压缩任务的整体耗时。

## 固定注入顺序：谁该压过谁

压缩产物最终要拼进系统提示，顺序不能随便排。这一版固定为：

```text
人设 → 硬约束 → 结构化事实 → 摘要 → 最近原文 → 检索资料
```

顺序背后是优先级。人设定义身份，永远在最前；硬约束是安全边界，排在所有软信息之前；结构化事实是这一轮最可能用到的参数，排在摘要之前；摘要提供背景叙事；最近原文保证当前对话的连贯；检索资料是外部补充，放最后。

事实块内部还有一层顺序：先事实、再决策、后未决问题。事实是「是什么」，决策是「定了什么」，未决问题是「还差什么」，按这个顺序读，模型更容易建立上下文。

顺带说一句，工作记忆的检查点也走这个顺序，排在结构化事实之前。它描述「当前任务进行到哪」，时效性最强，过期就归档，不参与长期记忆。

## 预算：50 / 25 / 10 / 10，余量留给输出

分层之后，每一层都要有预算上限，否则压缩只是把超支从一种形式换成另一种形式。

在安全窗口内，配额是：

| 区块 | 占安全窗口比例 |
|---|---|
| 最近原文 | 50% |
| 摘要 | 25% |
| 结构化事实 | 10% |
| 长期记忆 | 10% |

剩下的部分留给输出。输出预留优先用上一轮真实完成量校准，取固定下限和「上次完成量加一点余量」中的较大值，避免模型这轮话变多时把请求顶出窗口。

这些配额是硬上限，不是强制分配。某个区块没有内容时，其他区块可以使用剩余空间——否则一个没有摘要的新对话会白白浪费 25% 的窗口。

原文 50% 这一条尤其重要。压缩的触发条件是历史占用超过原文预算的某个比例，触发后保留最近一段逐字内容，至少保护最近四条消息。也就是说，压缩不会把最近几轮也卷进摘要，当前对话的连贯性始终有一份原文保底。

## 代价与边界

这套方案的代价是链路变长：一次压缩要经历「调模型出 JSON、解析、校验、可能重试、兜底、落事实表、渲染」多个步骤，任何一步失败都要有降级路径。摘要请求失败时，系统会退化为纯截断，保证对话不中断，但会失去叙事信息。

另一条边界是保真校验只覆盖数字和日期。否定语义、条件关系、指代对象都不在校验范围内——「不要买 A」被压缩成「考虑 A」这种错误，当前机制抓不到。这是明确的已知局限，后续需要更结构化的抽取才能解决。

还有一点：事实抽取依赖模型质量。本地小模型在长对话上可能抽不出稳定键，导致同一事实写成多条。唯一约束能挡住重复，但挡不住键名漂移。

## 数字

- 分层预算：原文 50%、摘要 25%、结构化事实 10%、长期记忆 10%；
- 保真校验失败重试一次，兜底片段最多三行、两百字；
- 单会话结构化事实按类型分组后限量保留；
- 全量测试覆盖 core 包 1539 例、database 包 270 例、web 端 738 例。

回到开头那段摘要。现在它会被拆成「体检间隔：六个月」「预算：五千元」「会议日期：三月一日」三条结构化事实，外加一段简短的叙事摘要。数字不再依赖模型「记得写下来」，而是被抽取、比对、缺失就重试、再缺失就保留原文。

压缩的本质不是「变短」，而是「决定什么不能短」。叙事可以短，参数不行。
