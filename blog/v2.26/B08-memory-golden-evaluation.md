# 记忆评测：用假向量证明召回真的在工作

给记忆系统写测试，第一个冒出来的方案通常是「让模型自己判断」。准备一批问题和期望答案，跑一遍真实召回，把召回结果交给 LLM 打分。写起来快，跑起来也像那么回事，但它有一个致命问题：不可重复。

同一个用例跑十次，模型可能给出十种措辞；换一个模型，基线整体漂移；CI 里没有网络和密钥，这套评估根本跑不起来。更隐蔽的是，LLM 裁判会倾向说「基本正确」——它和被测系统共享同一种含糊。

记忆召回是一个可以被精确判定的任务：给定查询，前 3 条里有没有期望的那条，有没有不该出现的那条。这些都是布尔判断，不需要模型来当裁判。我们需要的是把「语义相近」变成可构造的输入，而不是让另一个模型来评价语义。

## 四类 golden 用例

这个版本固化四类用例，覆盖记忆系统最容易骗过自己的四个方向。

**第一类，冲突。** 先写入「用户住在北京」，再写入「用户住在上海」，两条带同一个主体键。然后问「我现在住在哪个城市」，断言召回里有上海、没有北京，并且 active 状态只剩一条。这一类检验的是版本链：如果写入只是简单覆盖，旧行会消失，但「旧行消失」不等于「召回正确」；如果写入两边都留，召回就会同时给出两个城市。

**第二类，陈旧。** 写入一条低重要性的旧事件「计划下周六搬家」，把它的创建时间改到一年前；再写入一条新的高重要性事实「已经搬到新家」。跑一次衰减，然后查询。断言旧事件状态变成 archived，且不再出现在召回里，新事实仍然在。这一类检验的是「过期信息会不会继续干扰当前问题」。改创建时间是刻意的——衰减看的是年龄，不能靠等一年。

**第三类，负样本。** 用完全无关的查询去召回，断言结果为空。只测正样本的系统会有一个系统性偏差：召回器越宽松，正样本命中率越高，看起来越好。负样本是唯一能反向压住这种膨胀的用例。如果一条无关问题也能召回三条记忆，那说明下限形同虚设。

**第四类，作用域隔离。** 用助手 A 的身份写入一条记忆，分别以 A 和 B 的身份召回同一个问题。断言 A 能召回，B 不能。这一类检验的不是相似度，而是过滤条件有没有在正确的时机生效——很多召回 bug 不是算错了分，是忘了加 where 条件。

四类用例对应四种失败：冲突处理错、时间没起作用、召回太宽松、作用域没隔离。它们都不需要真实模型参与判断。

换成表格更清楚：

| 用例 | 它检验的失败 | 关键断言 |
|---|---|---|
| 冲突 | 新旧版本同时出现，或旧版本被直接删掉 | 只召回新内容，active 只剩一条 |
| 陈旧 | 过期信息继续干扰当前问题 | 旧内容 archived 且不再出现 |
| 负样本 | 召回下限过松，什么都能召回 | 无关查询结果为空 |
| 作用域 | 过滤条件缺失或时机不对 | 助手 A 可见，助手 B 不可见 |

四类用例的断言都落在可观察结果上：内容有没有出现、状态是什么、条数是多少。没有一条依赖「模型觉得对不对」。

## 五项指标

用例之上，用五个数字收口：

```text
hit@3               前 3 条里出现期望内容的比例
误召回率            负样本查询产生了任何结果的比例
冲突解决正确率      冲突用例中「只召回新版本」的比例
陈旧干扰率          陈旧用例中旧内容仍被召回的比例
无嵌入召回率        关闭嵌入后，纯关键词通道的 hit@3
```

hit@3 而不是 hit@1，是因为注入预算是 3 条，用户看到的也是前 3 条；要求第 1 条必须命中，会把「排序略差但信息已到位」误判成失败。误召回率只看「有没有结果」，不看结果多少，因为负样本场景下多一条和十条一样糟糕。

冲突解决正确率和陈旧干扰率本质上是专项的 hit@3，单独列出来是因为它们更容易被平均值掩盖。一个系统可以在总体 hit@3 上很好看，同时把所有冲突都处理错——只要冲突用例占比不高。

无嵌入召回率是一个独立的健康指标。嵌入模型是可选依赖，没有它时系统必须仍然能用。这个指标如果掉下去，说明关键词通道退化了，而用户不会收到任何报错，只会觉得「助手变笨了」。

## 确定性假向量：把语义变成轴

真实嵌入模型不可控，所以我们用一个 16 维的假向量器替代它。

每个用例分配一根轴：内容「用户养了一只橘猫」和查询「我养的猫叫什么名字」都映射到同一根 one-hot 轴，余弦相似度恒为 1。负样本查询映射到最后那根单独的轴，和所有正样本都不相交。假向量器按文本查表返回，同样的文本永远得到同样的向量。

这一步把「语义相近」从模型能力变成了测试数据的一部分。召回链路里的融合、阈值、排序、过滤全都照常执行，唯一被替换的是「这句话的向量是多少」。于是测试既覆盖了真实路径，又不依赖任何模型。

假向量也有它自己的风险：如果每个正样本的向量都和查询完全相等，测试可能过于宽松，任何不破坏查表的实现都能通过。所以断言必须落在**内容**上，而不是分数上——不检查「分数大于 0.9」，而检查「结果里有没有这条内容、有没有那条不该有的内容」。分数可以因为权重调整而变化，内容是否出现才是产品承诺。

真实嵌入模型还有一层隐性成本：它的排序会随模型版本变化。同一份测试数据，升级模型前后可能差出几条，基线要不要跟着改、改多少，全凭人判断。假向量把这一层不确定性彻底移除，测试失败只可能是代码问题，不会是模型换了。

## 关键词通道：无嵌入也要能召回

无嵌入用例把向量解析器整个返回空，然后重跑同一批正样本。此时召回只走全文索引通道，融合权重从 0.55 / 0.20 / 0.15 / 0.10 切成 0.75 / 0.15 / 0.10——语义的份额并入关键词。

中文全文索引按字切分，短查询和记忆内容之间靠字面重叠打分。这套通道的命中率天然低于向量，所以它的门槛也单独设：不低于 0.75，而混合通道要求 0.8。

两个门槛分开，是为了避免一个常见错误：用同一根线卡两种通道，结果要么向量通道被拉低，要么关键词通道永远不达标。它们的上限不同，目标也该不同。

## 三层防线

这批评测不是孤立存在的，它叠在两层已有测试之上。

最底层是纯函数单测：打分、阈值、分档、摘要构造，输入输出确定，毫秒级。中间层就是这四类 golden 用例加五项指标，它们在内存数据库上跑完整写入和召回链路。最外层是全量回归：core 1539 例、database 270 例、web 端 738 例，其中记忆专项 27 例。

三层的分工是「算得对」「链路对」「没弄坏别的」。golden 用例不替代单测，单测也不替代端到端；少了任何一层，失败定位都会变慢。

## 评测集怎么生长

这批用例不是一次性冻结的资产，它跟着故障长。

一个真实的坏例子进了线上，第一件事不是改代码，而是先把它压成一条 golden 用例：输入是什么、期望看到什么、不许看到什么。用例先红，再修代码，修完变绿。这样同一个故障下次回来时，会先撞上测试。

用例还要小且独立。每条用例自带写入、自带查询、跑在内存数据库上，不共享前置状态；否则一个用例改坏了数据，后面几条跟着红，定位成本立刻翻倍。独立性比覆盖率更值得优先保证。

最后，评测数据不要从生产记忆里直接拷。真实数据带隐私，也带「当前实现恰好能过」的偏差。手工构造的小样本更能表达意图，也更容易解释为什么这条该命中、那条不该。

## 评测本身也要能被证伪

最后一个原则：断言必须在行为回退时变红。

如果去掉作用域过滤，隔离用例必须失败；如果让写入变成直接覆盖，冲突用例的 active 计数断言必须失败；如果把衰减任务跳过，陈旧用例必须失败。做不到这一点的用例，只是在描述当前实现，而不是在守承诺。

这也是为什么我们坚持用假向量而不是真模型：一个可重复的裁判，才能让「回退后是否变红」这件事本身可验证。评测的价值不在于它跑绿了，而在于它有能力跑红。
