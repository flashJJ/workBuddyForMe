## 复盘一：先算清楚「确定性」到底买到了什么

v0.8 最核心的决策是 condition 分支不允许使用模型。开工前这是有争论的——「让 LLM 输出结构化决策」在 demo 里非常惊艳，用户甚至不用写规则。最终否决它，是因为认真算了一遍确定性这笔账：

**确定性买到的第一样东西是可复现。** 相同输入相同路径意味着：试运行成功一次的流程，发布后每次都成功；线上出问题能在本地逐节点重放出同样的轨迹。模型决策分支的流程，「调试通过」这个结论本身不成立——你调的是这次采样，下次采样是另一个东西。

**第二样是可调试。** B08 的逐节点时间线之所以有意义，是因为节点状态有明确的预期：规则节点输出 true 就是 true，该亮的分支一定会亮。如果分支由模型决定，调试器展示得再漂亮，用户看到「它这次选了 A」也无法回答「为什么不是 B、下次会不会还是 A」。

**第三样是可审计。** 每个 run 的每个节点输入输出落库。确定性流程的审计记录是一条因果链；模型随机决策的审计记录只是「它当时这么想了」。

付出的代价也真实：表达力下降了。「判断这封邮件是不是投诉」这类语义判断没法用 `contains/==` 写。v0.8 的答案不是忍，而是**分层**：语义判断交给上游 llm 节点产出结构化结论，规则节点对结论做确定性分流。不确定性被关进节点的黑盒里，节点之间的控制流保持纯白。这个模式以后会反复用——它本质上是在回答「AI 系统里什么该确定、什么可以概率」。

可以泛化的方法论：**在一个引入概率组件的系统里，把不确定性限制在最内层、用确定性外壳包起来，系统的可运维性会发生质变。** 这和数据库里「事务边界内确定、边界外随便重试」是同一种智慧。

## 复盘二：MVP 边界不是砍功能，是保护语义

v0.8 开工前列的 Non-Goals 比功能清单还长：无环、无并发、无循环、无子流程、无 HTTP 节点、无跨进程恢复、无自定义代码、无定时触发。开发过程中至少有三次手痒想破例，每次回头看都幸亏没破：

**「普通节点也支持多入边吧，就多一个 join 判断。」** 真做下去要定义 and-join/or-join、跳过的前驱算不算、两个前驱在不同条件分支上怎么计数——引擎的活性判断复杂度翻倍。最后的选择是把汇聚语义只给 end 节点，starter① 用双 end 表达「不同路径不同产出」。限制写进编译器后，真实业务里没有一个流程被这条限制卡住。

**「同层节点顺手并行了吧，for await 改成 Promise.all 而已。」** 事件顺序立刻变得不确定（两个模型节点谁先回谁先落库），时间线快照、测试断言、SSE 去重全部要适配乱序。串行多花的几秒在本地单用户场景毫无痛感，放弃。

**「SSE 断线后让 run 在后台继续跑完吧。」** 这需要独立 worker、运行队列、人工挂起的跨进程等待存储——等于把 v0.9 服务化的一半提前做了。接受「连接即生命周期」，但把 run/node_executions 先行落库，让未来的解耦只动执行层不动数据层。

边界纪律的核心洞察：**MVP 阶段每一个「顺手支持」的特性，买的都是未来语义复杂化的期权，而期权费是立刻支付的。** 单人项目没有余钱预付。判断标准很简单——这个特性拿掉后，当前成功指标是否不成立？不成立才做，成立就登记，并写清楚「现在的什么设计保证未来能加」。

## 复盘三：事件流作为唯一输出通道的复利

M0 设计引擎时做了一个看似平常的决定：AsyncGenerator 事件流是唯一输出。M2/M3 三次从这个决定上收到复利：

1. M2 试运行：事件 → SSE → 前端时间线，引擎零改动；
2. M2 落库：同一个流 tee 一份给 run-store，执行与持久化同序（先落库后下发，崩溃可自愈）；
3. M3 对话子步骤：同一个流换一个投影函数，变成工具卡片上的节点行。

对比之下，「引擎直接返回结果 + 旁路回调通知进度」的设计会在第三种消费者出现时被迫重构。**当一个过程天然是时序性的（逐节点执行），让事件成为第一公民，消费者永远是后加的。** 这条经验和 v0.6 SSE 流式对话、v0.7 任务循环一脉相承——整个项目现在所有长过程（聊天/任务/流程）都是同一种 AsyncGenerator 心智模型，认知成本是摊薄的。

但这个模式也有纪律：事件必须是**事实**而不是**指令**。node_succeeded 表示节点确实成功（落库已完成），不是「请把节点标成成功」。M3 桥接工具子步骤时曾踩过快照时序坑（队列里传引用导致状态覆盖），本质就是一度把「对未来状态的引用」当成了「当下的事实」入队。

## 复盘四：平台化的验收标准是「宿主骨架不动」

M3 最让我满意的不是功能本身，而是它的侵入性数据：flow 工具接入对话，聊天主循环的控制流零改动、消息表零改动、HITL 协议零改动；新代码全是「实现同一接口 + 加一个来源分支 + 加一种 SSE phase」。

这验证了 v0.2–v0.6 工具抽象的长期价值，但也反过来给出一条平台化设计的验收标准，值得固化：

> 新增一种能力提供者（MCP 是第一种，flow 是第二种，未来的 HTTP API 工具是第三种）时，**宿主的消费代码（工具循环/权限/熔断/追踪/前端卡片）应该只在「枚举来源」的地方加分支，不能在控制流上加 if**。

M3 有两处差点破功，都在评审时拦住了：一是想给 flow 工具的子步骤新开一种 SSE 事件名（`flow_progress`），最后克制为复用 `tool` 事件加 `substep` phase——前端工具卡片的既有渲染逻辑得以沿用；二是想在对话里给流程单独做「进行中不可打断」的状态，最后确认复用 read 权限 + 既有取消语义即可。枚举扩展优于新造通道，这条在设计 SSE payload map 时就该想清楚。

## 复盘五：真机端到端是抓架构问题的最后一张网

这个版本有 4 个问题，单测 100% 绿但只有真机跑才暴露：

| 问题 | 为什么单测抓不到 |
|---|---|
| EventSource 终态重连风暴（32 次回放） | 需要真实浏览器的自动重连行为 |
| dev HMR 单例分裂致人工审核 422 | 开发服务器按需编译时序，单测容器是手动 new 的 |
| 空 modelId 不回退默认（`"" ?? 默认`） | 单元测试都显式传了 modelId，「跟随默认」路径只在 UI 真实操作时走到 |
| 画布空白点击不关抽屉 | React Flow 事件在真实 SVG 渲染层上的冒泡行为 |

教训不是「单测没用」——编译器/引擎/引用/门控这些纯逻辑的信心 100% 来自单测（447 个）；而是**集成层的真实环境行为（浏览器重连、HMR、DOM 事件目标）必须靠真机端到端兜底，且每修一个这类问题都要留下对应的防回归认知**。v0.8 的做法是把「浏览器走查真实用户路径」作为每个里程碑出口标准的一部分，而不是发布前才想起来点一遍。

另一个配套经验：M2 浏览器代理直接在环境里改了 model-resolver 的一行（`??`→`||`），事后代码评审确认这行修复是正确且最小的——说明给执行者「发现阻断可直接修」的授权能显著缩短真机调试回路，但修完必须回到门禁流程里重新过全量检查，不能让热修游离在提交历史之外（这次它已正常进入 M2 的 fix 提交）。

## 给 v0.9 留的口子（以及为什么它们现在不还）

| 留口 | 现在埋好的基础 | v0.9 要补的东西 |
|---|---|---|
| HTTP API / MCP Server 对外触发 | trigger 枚举已预留 api/mcp；Tool 式调用链已验证 | 鉴权、外部输入校验、无人值守 danger 策略 |
| 独立 runner + 跨进程恢复 | run 即 queued 落库、节点逐行落库、active 与存储分离 | 队列、worker 进程、跨进程等待注册表、失败节点单点重放 |
| 同层并发 | Kahn 拓扑已含「层」信息 | 层内 Promise.all、乱序事件定序、并发取消语义 |
| 定时/事件自动化（v0.10） | 流程已可作为稳定工具被调用 | Electron 常驻端的调度器与触发器表 |
| 嵌套子流程 | flow 已可解析 flow 工具（第三来源） | 嵌套深度保护、子流程入参映射 UI |

每一条都是「数据模型不挡路、只欠执行层」的状态。这是非目标管理做得好的证据——砍掉的东西没有给将来挖坑。

## 写在最后：从「会聊天」到「能交付一条确定的业务线」

八个版本走过的路线很清晰：

- v0.1–v0.3：会聊天、会读文档、会看图片（信息进出）；
- v0.4：数据能带走（备份/分享/更新）；
- v0.5：有长期记忆；
- v0.6：会接标准工具（MCP、技能、权限、熔断）；
- v0.7：能操作桌面（眼和手）；
- **v0.8：能力可以被编排成确定的、可复现的、可被对话自主调用的业务流程。**

v0.8 之前，这个平台有一堆能力很强的零件；v0.8 之后，用户第一次能把这些零件**焊死**成一条别人（或未来的自己）触发时必然按设计走完的线，同时这条线又以工具的身份回到最自然的交互入口——对话里一句话。

确定性的 DAG 和自主性的 Agent 不是竞争关系，是分层关系：**确定的流程做骨架，模型在节点里做判断，Agent（v0.7 的任务循环）在没有流程可依时做兜底。** 下一站 v0.9，让这条骨架走出本机——服务化之后，它就能被定时、被事件、被外部系统触发。从一张画在浏览器里的图开始，这条路的方向没有变过。
