## 先回答：v0.8 为什么要做流程图

做了七版之后，普通对话已经很能打：多模型流式对话、知识库 RAG、13 个内置工具、MCP 生态、HITL 授权、桌面 Agent。但有一个问题从 v0.2 工具调用上线起就一直在：

**助手调什么工具、按什么顺序调，全靠模型每一轮临场决定。**

同一句「帮我整理本周周报」，周一它可能先翻知识库再动笔，周五心情好直接编；一个需要「先检索 → 判断有没有料 → 有料才写 → 写完找人审」的任务，你没法把这条路径固定下来。错了没法复现（这次走了 A 路径，下次走 B），也没法交接（流程只存在于提示词的暗示里）。

v0.8 的主题一句话：

> 从「每轮靠模型临场决定调什么工具」到「把检索、判断、生成、工具、人工审核画成一张确定的流程图」——流程可调试、可复现，并能作为工具回到普通对话中被助手调用。

产品形态对标 [Langflow](https://github.com/langflow/langflow)（我对照读过它 v1.12.4 的源码），但不移植一行 Python，全部长在本项目已有的 TypeScript / Next.js / SQLite 资产上。

## 四个里程碑

| 里程碑 | 内容 | 出口标准 |
|---|---|---|
| M0 地基 | shared 图契约（zod）+ v012 四表迁移 + 两仓储 + 编译器 + 引擎骨架 | 最小图 start→end 编译并产生 run 事件 |
| M1 引擎与节点 | 引用解析 + 就绪队列/分支剪枝/取消 + 7 类 handler + 落库 + flow 工具第三来源 | 不经 UI 的引擎单测全绿（分支/跳过/失败/取消/挂起） |
| M2 画布与试运行 | @xyflow/react + /flows 两页 + 7 自定义节点/边 + 配置抽屉 + 插入变量 + 校验定位 + SSE 试运行面板 | 浏览器搭出真实流程完整跑通，人工节点内联审核 |
| M3 集成与发布 | flow 工具对话链路 + tool-trace 子步骤 + 3 个 starter 播种 + 版本号 0.8.0 | 对话中助手自主调用已发布流程，节点进度可见 |

M0/M1 是「没有 UI 也必须全对」的内核层，M2 是人机界面，M3 让流程图重新融入对话。

## 架构总图

```text
┌─────────────────────── 浏览器（Next.js） ───────────────────────┐
│  /flows 列表 · @xyflow/react 画布 · 节点配置抽屉 · 试运行面板      │
│  对话页 tool-trace 卡片（tool start / substep / end 三阶段）      │
└────────────────────────────┬───────────────────────────────────┘
                             │ REST 统一包络 / SSE
┌────────────────────────────▼───────────────────────────────────┐
│  Route Handlers：/api/flows/*（11 个路由）                       │
│  runs 只登记 queued；events 订阅才启动；终态从落库记录回放         │
└────────────────────────────┬───────────────────────────────────┘
┌────────────────────────────▼──────────── core/flow ────────────┐
│  compiler（环/拓扑/可达诊断）→ engine（就绪队列+分支剪枝+取消）   │
│  refs（插值 / $ref）→ 7 handlers → run-store（逐节点落库）       │
│  run-service（manual 交互 / chat 非交互）· flow-tool · starters  │
└────────────────────────────┬───────────────────────────────────┘
                             │ 全部复用既有内核
        retrieval（sqlite-vec）· ChatProvider · tool-runtime（门控/熔断/超时）
                             │
              SQLite v012：workflows / workflow_versions
                           workflow_runs / node_executions
```

三个关键架构事实，后面九篇会逐个展开：

**1. 引擎是纯顺序的确定性 DAG 解释器，不是另一个 Agent。** 拓扑序在保存前由编译器算死（Kahn），运行时只有一个就绪队列按序推进；唯一的「判断」节点 condition 跑的是声明式规则（等于/包含/大于/为空……），**不调模型**。模型只出现在 llm 节点内部，且它的上下游连接不由它决定。

**2. 运行生命周期等于 SSE 订阅生命周期。** `POST /runs` 只写一条 queued 记录；前端打开 EventSource 订阅 `/events` 时才真正启动引擎；断线即 abort。这直接照搬 v0.7 桌面任务验证过的范式，不需要独立 worker 进程。详见 B06。

**3. 流程图不是新的对话入口，而是一种新的工具。** 调好的流程一键发布，之后它以 `flow:<id>` 出现在工具目录里——普通对话中助手自己决定何时调用，调用时对话工具卡片里逐节点显示流程内部进度。聊天主循环一行没改。详见 B09。

## 七类节点，每一块都踩在现成内核上

v0.8 没有新造任何 AI 或工具能力，只做「编排与接线」：

| 节点 | 干什么 | 复用的现成资产 |
|---|---|---|
| start | 声明流程入参（名/类型/必填/默认），发布后生成工具参数 schema | zod |
| knowledgeSearch | 选知识库 + 检索词模板 + topK | v0.1 的 sqlite-vec 检索服务 |
| llm | 选模型（可跟随默认）+ system/user 模板 + 采样参数 | v0.1 的 ChatProvider 流式接口（节点内累积完整文本） |
| tool | 选内置/MCP/flow 工具 + JSON 参数 | v0.2/v0.6 的 tool-runtime + 门控/熔断/15s 超时/SSRF |
| condition | 声明式规则，输出 true/false 两分支 | 纯本地函数，无模型 |
| human | 挂起等待通过/驳回，输出 `{approved, values}` | v0.6 HITL 挂起注册表同构 |
| end | 输出映射，决定 Run 最终结果（可多个做路径汇聚） | 无 |

节点间数据流动靠统一引用语法：`{{$nodes.<节点id>.outputs.<字段>}}` 做字符串插值，`{ "$ref": "nodes.xxx.outputs" }` 做整字段绑定（对象/数组原样透传）。引擎在每个节点执行前统一解析配置，引用错了直接报「节点 x 尚未执行 / 字段不存在」而不是让脏数据流进模型。详见 B04。

## 关键决策速览

**条件分支不依赖模型（condition 是规则节点）。** 社区可视化流程工具最常见的坑是让 LLM 输出 JSON 来决定走哪条边——7B 模型的 JSON 格式抖动会直接变成流程随机跳转。v0.8 用声明式规则彻底规避：要语义判断？让上游 llm 节点先把判断写成结构化文本，再用规则节点比对。确定性是本版本的立身之本，不能在岔路口让出去。详见 B05。

**MVP 硬性限定：DAG 无环、顺序执行、普通节点单入边。** 想要循环？想同层并发？想子流程嵌套？全部明确写进 Non-Goals 登记 v0.9+。单入边限制逼出一个干净的汇聚语义：**只有 end 节点可以多入边**，「不同路径产出不同最终结果」用多个 end 表达——starter① 的资料研究助手就是这么画的（没检索到资料走独立 end 给提示，检索到走生成→人工→end）。详见 B03。

**图状态不引入 zustand。** 画布态直接用 React Flow 原生的受控 `nodes/edges` + change 回调，服务端态继续 React Query。全项目状态管理口径不分裂，少一个依赖少一层心智负担。详见 B07。

**发布是不可变快照，不是开关。** 每次保存生成自增版本，发布固定某个版本；发布后再改图，状态自动回到 draft，线上对话仍调旧版本直到重新发布。这和函数部署的「版本不可变 + 别名指向」是同一个道理。详见 B02。

## 最终验证到什么程度

不是只跑单测就发布。M3 收尾时在浏览器里做了真机端到端：

- 画布从零拖出 start→llm→end，真实调用豆包跑通，逐节点看到输入输出；人工节点通过输出 `true`、驳回输出 `false` 两条路径都验证；
- 对话里发一句「调用周报流水线整理这些要点」，模型第一轮 tool_call 就选中了 `flow:b0000002-...`，工具卡片实时滚出 4 个节点子步骤，97.9 秒后产出带四个小节的结构化周报；
- 3 个 starter 首次启动自动播种为已发布态，删掉重开能恢复，改名后再启动不覆盖；
- 普通对话、知识库（37 文档的真实库）、桌面任务、助手、设置逐页回归，零应用错误。

全量门禁（typecheck / eslint / 300 行文件限制）全绿，core 447 个测试、web 160 个测试通过，v011 老库直接启动平滑升级到 v012。
