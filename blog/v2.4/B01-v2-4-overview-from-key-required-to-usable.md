# 装完即用：从「必须先配 Key」到「第一条回答」

用户给过一句很重的反馈：这软件不如头部竞品好用。

我们没有拿功能清单去对打。功能面上，这个本地优先的桌面 AI 应用其实不窄：对话、检索增强、工作流、本地 API 与 MCP 服务、桌面 Agent、技能、角色卡、形象、桌宠、语音、情绪与关系、主动感知，一项不缺。真正的问题发生在另一条轴上——**用户从「装完」到「第一次拿到价值」之间，要跨过多少道坎。**

## 一、差距不在功能表，在价值兑现链条

把「好不好用」拆成三段，每段只问一个问题：

| 段位 | 用户的问法 | 头部竞品 | 我们的桌面 AI 应用 |
|---|---|---|---|
| 能不能开始用 | 装完能用了吗 | 模型与算力由产品兜底 | 要自备供应商、Base URL、API Key、模型 |
| 用起来顺不顺 | 找得到、看得见吗 | 模板与入口前置 | 功能在，入口浅，能力隐形 |
| 留不留得住 | 数据和关系归谁 | 云端账号 | 数据不出机、有形象与长期关系 |

第一段是致命的。竞品把「模型从哪来」消化在产品里，用户打开就能说话；我们把这件事原样交给了用户，而用户大多不是模型专家。于是「功能很多」在第一次打开时完全无法兑现——他看到的只是一个要求他先做技术决策的配置页。

第二段和第三段不是没有做，而是**做了却没被看见**：模板早已播种，空态却不提；语音早已可用，却要先理解灵敏度和尾静音；助手挂了什么技能与工具，对话页里没有任何交代。

所以这一版的主题不是「再加几个功能」，而是**把已有的能力铺到用户脚边**。一句话概括：装完即用。

## 二、断点很具体：第一步就是一道专家题

首次配置的路径是：选供应商 → 填 Base URL → 填 API Key → 选模型 → 回对话。

这条路径上任何一环答不上来，用户就停在「配置页」，而不是停在「产品里」。更隐蔽的是兜底：代码里其实有一个 mock 开关，但它是一个只给开发用的环境变量——用户看不见，也不会用。

还有一个放大效应。没有可用模型时，对话是空的、知识库是空的、工作流也是空的。用户不会把这三个空归因于「我还没配置」，只会归因于「这软件没什么用」。

> 本地优先把「模型从哪来」交给了用户，却没有回答「模型还没来的时候，产品怎么活」。

这一版就是补这个答案。

## 三、五条主线

### 1. 零配置首启：把兜底做成产品能力

向导第二步从「云端 / 本地」二选一，改成三条来源并列：**演示模式、本地模型、云端 API**。本机探测到 Ollama 时，本地来源置顶并默认选中；没探测到时，演示模式置顶。

演示模式不是假数据：SSE 流式、检索、引用、工作流节点执行全部走真实链路，只有模型输出是确定性文本。它在本机创建一个内置演示供应商（对话模型与向量模型各一），凡用到它的地方都挂「演示模式（非真实模型）」徽标，设置页可一键关闭且不留残留。

云端路径由厂商卡片预填 Base URL 与模型建议，用户只需要补一个 Key；本地路径只做「可执行引导」，不内置权重、不静默下载。

向导的终点也不是「配置完成」，而是**第一次成功对话**：选定来源后自动发出一个示例问题，落到对话页看到流式回复。这条链路的耗时被记成四个时间戳，验收线是 `ttfv_ms ≤ 60_000`。

### 2. 模板可触达：空态不是终点

内置模板收敛成一份 15 条的清单：知识库 3、工作流 6、技能 3、助手预设 3。统一用同一个模板画廊渲染，每条带名称、一句适用场景、来源徽标和「推荐先用」。

出现时机被冻结成两条：**列表空态显示一次，列表顶部保留一个可折叠入口**。空态时让首启用户看见现成货，之后不再重复打扰。

「以此开始」按类型给不同语义：知识库与工作流复制成可改的自建实例，技能直接启用，助手预填新建表单。核心取舍是——不复用「内置对象本身」当用户资产，内置只读，用户需要的是一份能改的副本。

### 3. 语音开箱：一次点击，参数后退

设置页语音面板顶部与对话页语音按钮旁各有一个入口。点一下，写入「识别开 + 免手模式 + 朗读开 + 默认档位」，不做任何静默下载。

默认路径只留两档人话选项：**反应快**（均衡灵敏度 + 600ms 尾静音）与**更宽容**（低灵敏度 + 1200ms）。灵敏度三档、尾静音四档退进默认收起的「高级」。

模型没就绪时，入口处就地给出体积预估、下载、进度与取消，下载器按文件级断点跳过已完成文件。默认 TTS 切到 MeloTTS（191MB，单声低延迟），Kokoro（394MB、103 音色）退为「更多音色」。

真机还暴露过一个致命问题：回复里的纯标点片段会让 sherpa-onnx 在转 token 时直接终止 Node 进程。最终用「可朗读判定 + 分块过滤 + 引擎拒绝」三层护栏兜住。

### 4. 能力可见：助手到底挂了什么

新增助手级技能字段：空数组表示跟随全局已启用技能（旧行为不变），非空表示只注入这些，且它们仍需在全局启用。

三处一起补：助手卡片加「技能 / MCP 工具」区，助手表单加「技能（能力包）」区块（与工具级白名单明确区分），对话页头部展示当前助手的模型、知识库、技能与工具摘要。

### 5. 运行可信与体感：失败能解释，慢也能看见

任务、桌面 Agent 运行、工作流运行三套状态归一成 8 个结果：排队、运行中、等待、成功、失败、已取消、已中断、超预算。耗时统一按「开始 → 结束」一个口径算，运行中按「至今」算。

失败由纯函数分类，UI 输出「为什么失败 + 下一步」，原始错误折叠保留。协作舞台只提供只读观看入口，写操作仍需在授权弹窗里显式允许。

体感侧：流式增量按帧合帧提交，完成、出错、停止、重置都同步冲刷；长回复按顶级标题切块并逐块缓存，代码围栏内不切；等待首字超过 1.5 秒显示已等待秒数，超过 5 秒追加「停止 + 换更小模型 / 缩短上下文」建议。

## 四、四条不能碰的红线

1. **无账号、无遥测、数据不出机**：所有时间节点只落本机，只记时间戳与计数，不含对话内容。
2. **不静默下载**：模型与权重都必须显式确认，下载可取消、可断点续传。
3. **不假装全双工**：界面如实写明「说完再答 + 可打断」，不暗示边听边说。
4. **内置模板只增不改**：固定 id、幂等播种，不覆盖用户改动。

## 五、门禁数字

| 项 | 结果 |
|---|---|
| 类型检查 | 14/14 包通过 |
| 静态检查 | 8/8 包，0 error |
| 行数门禁 | 手写文件 ≤300 行，新组件 ≤150 行 |
| 单测 | 8 个包全绿：web 555 例、core 1112 例、shared 314 例、database 215 例、desktop 164 例、ai 62 例、voice 75 例、config 14 例 |
| 浏览器端到端 | 109 例全部通过，含首启、命令面板深链接、三尺寸 × 六页面、协作与语音系列 |

新增测试集中在四件事：三链路运行结果映射与归因、长回复切块的无损性、合帧与首字计时、命令面板覆盖度。

## 六、刻意不做的事

- **不做全双工**：边听边说需要模型侧原生支持，这一版只把半双工的边界讲清楚。
- **不做免费云兜底**：与「数据不出机」冲突，也不引入账号。
- **不做模板市场**：不下载、不联网、不分享。
- **不承诺下载分钟数**：本地模型下载耗时以实际网络为准，只给档位。
- **不把慢模型的等待藏起来**：超过 5 秒就给降级建议，而不是让用户盯着一个转圈。

## 七、这一版真正回答的问题

「装完即用」不是「装完就有一个云模型可用」。在本地优先的约束下，它只能意味着另一件事：**把三条最短路径都铺到用户脚下，并且让每一条都能在 60 秒内产出第一句回答。**

零配置解决「能不能开始」，模板解决「找不找得到」，语音解决「敢不敢开口」，能力可见解决「看不看得见」，运行可信解决「信不信得过」。五件事指向同一个东西：价值兑现的摩擦。
