# 记忆的来源与召回理由：如何不伪造溯源

长期记忆最容易被误解的一点，是把它当成「更长的上下文」。实际上它更像一份**没有署名的笔记**：内容可能对，但你不知道是谁写的、什么时候写的、为什么现在被翻出来。

这篇讲我们如何给每条记忆补上署名：来源会话、来源消息、召回分数与召回理由，以及在这些信息缺失时，如何诚实地显示「不知道」。

## 一、没有来源的记忆等于传闻

此前的召回结果只有一段文本。用户看到「用户偏好深色主题」，会产生三种疑问：

- 这是我在哪次对话里说过的？
- 是助手从哪句话推断出来的？
- 它现在为什么被引用？

没有答案时，用户只有两个选择：无条件相信，或者干脆关掉记忆功能。两者都不是好结果。溯源的目的不是做审计工具，而是让用户能**判断这条记忆该不该信**。

## 二、来源的四种情况

不是所有记忆都能追到具体消息。我们把来源分成四类，并给每类一个诚实的展示：

| 情况 | 来源会话 | 来源消息 | 界面显示 |
|---|---|---|---|
| 本轮新提取的事实 / 偏好 / 事件 | 有 | 有（本轮助手消息） | 来源消息 |
| 会话摘要类记忆 | 有 | 无 | 来源会话 |
| 手工新建 | 无 | 无 | 来源未知 |
| 升级前的旧记忆 | 无 | 无 | 来源未知 |

关键决策是：**摘要记忆不伪造单一来源消息。** 摘要来自多条早期消息，硬指向其中一条会造成「这条总结就是那句话」的误解。同理，旧记忆无法补齐来源，我们不根据内容去猜——猜测出来的溯源比没有溯源更糟。

被删除的来源不会连带删除记忆。界面提示「来源会话已删除」或「来源消息已删除」，记忆内容仍然保留。删除对话是整理行为，不是撤回事实。

## 三、写入：来源在什么时候被记录

自动记忆的写入发生在回合成功之后。编排器把本轮助手消息 id 传进记忆服务，和来源会话 id 一起落库：

```text
回合完成
  → 提取候选记忆
  → 逐条嵌入
  → 去重合并 / 新建
  → 写入 source_conversation_id + source_message_id
```

去重合并有一个容易忽略的规则：**保留首次来源，不把来源改写到最近一次对话。** 否则一条记忆被反复提到之后，来源会漂移到最后一次提及，用户点进去看到的是一段与原始事实无关的对话。

手工新建与旧数据走同一条降级路径：两个字段为空，界面显示「来源未知」。这不是缺陷，而是数据诚实性的一部分。

## 四、召回：分数是怎么算出来的

向量检索返回的是距离，不是相似度。我们做的换算很直接：

```text
score = clamp(1 - d² / 2, 0, 1)
```

其中 `d` 是归一化向量的 L2 距离。归一化之后，`d² = 2 - 2cos`，所以这个式子等价于余弦相似度。分数保留三位小数，仅用于排序与分档。

界面不展示百分比，只显示「相关度高 / 中 / 低」。原因很实际：余弦分数不是概率，高相似度只代表向量接近，不代表事实确定成立；把它当百分比展示是一种伪精确。分档足够用户判断，也避免不同嵌入模型之间分数不可比的问题。

召回载荷同时带上 `reason='semantic'`。首期只允许这一种理由，不伪造「关键词命中」或「用户置顶」。将来增加其他召回通道时，理由字段才有意义。

## 五、召回计数：一次命中，两处刷新

语义召回命中后，同时更新两列：

- `recall_count += 1`；
- `last_accessed_at = now`。

面板据此显示「已召回 N 次 / 尚未召回」与最近召回时间。这让用户能看到哪些记忆真的在被使用，哪些只是占位。

有一个例外：主动搭话使用的关系记忆走仓储直读，不属于语义召回，不计数。这是刻意的，主动搭话是轻量路径，不应该因为一次问候就污染召回统计。口径写清楚，比让数字看起来更大重要。

## 六、对话里的 chips：把来源放在手边

每轮回答下方会出现记忆 chips：

- 折叠态显示「本轮参考了 N 条长期记忆」；
- 展开后逐条展示类别徽标、内容、相关度与来源入口；
- 来源入口按可用性显示「来源消息」「来源会话」或「来源未知」。

不在回答正文里塞引用角标，是因为正文需要保持可读；也不把来源藏进设置页，因为用户判断记忆时就在对话现场。chips 是这两者之间的折中：不打断阅读，但随时可查。

## 七、深链：点进去要能落到那条消息

点击来源进入 `/chat?conversation=<id>&message=<id>`，页面做四件事：

1. 解析会话并切换助手；
2. 加载消息列表；
3. 滚动到目标消息；
4. 高亮该消息。

失败路径同样明确：

| 情况 | 行为 |
|---|---|
| 来源会话已删除 | 提示「来源会话已删除」，不阻断普通对话 |
| 来源消息已删除 | 会话正常打开，提示「来源消息已删除」，不误高亮其他消息 |
| 两者都缺失 | 显示「来源未知」，不提供跳转入口 |

最容易做错的是第二条：消息不存在时，很多实现会退化成「定位到会话顶部」或「高亮最后一条」，用户以为找到了来源，其实看的是无关内容。我们宁可什么都不高亮，也不制造错误对应。

## 八、三条不伪造原则

1. **没有来源就说没有。** 旧记忆、手工记忆一律「来源未知」，不按内容相似度反推。
2. **不把分数当概率。** 只做高 / 中 / 低分档，不展示百分比。
3. **不因来源消失而删记忆。** 来源是证据，不是记忆存在的前提。

这套设计没有让记忆变得更「聪明」，但让它变得可质疑。对私人 AI 应用来说，可质疑比聪明更重要——用户需要的是能核对的事实，而不是听起来合理的断言。
