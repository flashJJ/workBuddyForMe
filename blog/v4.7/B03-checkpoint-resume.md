# 重启之后任务还能接着跑：检查点、续跑与幂等

桌面应用有一个绕不开的现实：用户会关掉窗口，系统会更新，进程会崩溃。任务模式跑得好好的，一次重启就全没了。

这一轮我们把“中断”从终点改成了逗号。

## 一、原来的行为：running 一律变 cancelled

应用启动时会做一次恢复扫描：所有还停留在 running 的协作运行，统一终止为 `cancelled`，原因标记为“被应用重启打断”。

从数据一致性看这是对的——进程已经没了，不能假装它还在跑。但从用户视角看，这条规则等于：只要中途重启，前面所有步骤作废，只能从头再来。

更糟的是，会话里只会多一条“任务因重启被中断，可重新发起”，没有任何可以接着用的信息。

## 二、检查点记录的是“可恢复位置”

我们没有复用已有的步骤表，而是新增了一张检查点表。理由很直接：步骤表是执行流水，检查点要存的是另一类东西——预算用了多少、当前在第几轮、卡在哪个待确认门、幂等键是什么。把这些塞进步骤表会污染它的语义。

表的结构很窄，每次运行至多一行，按运行 id 唯一：

- 当前轮次与阶段（规划 / 执行 / 审查）；
- 当前子任务与最近一次执行结果；
- 已用预算（轮次、步数、token）；
- 是否可续跑，以及一条备注。

与交接记录（handoff）的区别要强调：交接记录是只追加的审计流水，检查点是“当前可恢复位置”，会被反复覆盖。

## 三、什么时候写，什么时候封

检查点在每个阶段结束后 upsert：规划完、执行完、审查完各落一次。写的是最新状态，不追加历史。

进入终态时执行 seal（封存）：把可续跑标记置为不可续跑。以下情况都会封：

- 任务正常完成或失败；
- 预算触顶结束；
- 用户主动终止；
- 计划被用户拒绝。

封存之后，任务中心不会出现“继续运行”。这是刻意的：正常结束的任务再续跑，等于重复执行。

## 四、续跑是新建一次运行，不是步骤级重放

这是整个设计里最容易被误解的一点。

续跑不会从第 7 步的第 3 个工具调用继续，也不会把已完成的步骤重新执行一遍。它的真实动作是：

1. 校验源运行确实是“中断收敛”，且检查点仍可续跑；
2. 新建一次运行，记录 `resumed_from_run_id` 指向源运行；
3. 沿用同一个会话与目标，携带剩余预算；
4. 把检查点内容作为上下文重新规划；
5. 已完成的步骤由模型根据上下文跳过。

```ts
const resumed = createRun({
  goal: source.goal,
  conversationId: source.conversationId,
  resumedFromRunId: source.id,
  budget: remainingBudget(source),
});
consumeCheckpoint(source.id); // 再点一次「继续」直接冲突
```

说白了，这是“带着笔记重新开工”，不是“录像回放”。好处是实现简单、不依赖每一步都可重入；代价是模型可能重复少量工作。

## 五、剩余预算怎么算

新运行不能白拿一份满额预算，否则续跑就成了绕过预算上限的后门。

规则是：

- 轮次：原上限减去已用轮次，至少保留 1 轮；
- 步数：沿用原上限（步数本身是单轮内的约束）；
- token：原上限减去已消耗，且不低于系统最小值。

这样即使连续中断多次，总消耗仍然收敛在原预算附近。

## 六、并发点击与重复续跑

用户可能连点两次“继续运行”，或者两个客户端同时操作。处理方式是在创建新运行之前，先把源检查点标记为不可续跑：

- 第一次请求成功创建新运行；
- 第二次请求发现检查点已消费，返回冲突；
- 重启扫描也只列出仍可续跑的检查点。

检查点的消费是“先占后跑”，而不是“跑完再标记”。顺序反过来，就会出现两次运行同时读同一份状态。

## 七、写操作的幂等与授权

续跑最容易出的问题是副作用重复：上次已经发过一封邮件，这次重新规划又发一遍。

我们保留了两道闸：

- 工具授权不变。写操作和危险操作仍然逐次确认，续跑不会跳过确认；
- 写操作需要幂等标记。执行侧按“同一运行谱系 + 同一动作”识别重复，能跳过就跳过，不能跳过就要求人工确认。

换句话说，续跑复用上下文，但不复用“已经获得过的许可”。这是安全边界，不是体验问题。

## 八、边界

- 续跑是重新规划，不是步骤级重放，已完成步骤依赖模型按上下文跳过；
- 只对“中断收敛”的运行开放，正常结束、用户急停都不提供续跑；
- 不做跨设备续跑，运行状态仍在本机；
- 定时流程与无人值守节点强制走自动执行，不弹人工确认，避免流程被卡死。

## 九、结果

- 重启后任务不再直接作废，任务中心出现“继续运行”；
- 续跑不会重复消耗整份额度；
- 连续点击只会有一次生效；
- 写操作仍受授权与幂等保护；
- 正常结束的任务不会被误续跑。

中断恢复的价值不在于“技术上能恢复”，而在于恢复之后用户敢点。预算、授权、幂等这三件事都交代清楚，续跑才是一个可用的功能，而不是一个危险的按钮。
