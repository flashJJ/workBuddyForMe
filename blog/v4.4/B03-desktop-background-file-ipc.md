# 桌面端背景文件：IPC、类型嗅探与 20/50MB 上限

浏览器里选文件、桌面壳里选文件，看起来都是“弹个对话框”，实际约束完全不同。Web 的 `File` 对象有沙箱、有内存生命周期；Electron 主进程拿到的是一条真实路径，能直接读盘。背景文件功能必须利用后者，同时把前者的安全习惯带过来。

## 一、只开三个通道

渲染层需要三件事：选一个文件、列出已有文件、删掉一个文件。对应三个 IPC：

```text
background:pick    renderer → main   打开对话框，复制并返回元数据
background:list    renderer → main   列出已复制背景
background:remove  renderer → main   按 id 删除
```

通道只在主窗口注册。桌宠窗也能拿到 preload，但我们用 `event.sender` 判断来源窗口，非主窗直接拒绝。理由很直接：背景设置属于主窗口，桌宠窗没有必要拥有写磁盘的能力。

preload 侧只暴露这三个方法，不暴露底层 `ipcRenderer`：

```ts
contextBridge.exposeInMainWorld('app', {
  background: {
    pick: () => ipcRenderer.invoke('background:pick'),
    list: () => ipcRenderer.invoke('background:list'),
    remove: (id) => ipcRenderer.invoke('background:remove', id),
  },
});
```

渲染层拿到的是一组语义化方法，不是“任意通道名 + 任意参数”。

## 二、选择之后立刻复制

对话框返回的是原始路径。我们没有把这个路径传回渲染层，而是当场复制：

1. 读取文件头做类型嗅探；
2. 检查体积上限；
3. 用 uuid 生成新文件名；
4. 复制到 `<应用数据目录>/backgrounds/`；
5. 返回 `{ id, kind, name, bytes }`。

复制而不是引用，换来四个确定性：

- 用户之后移动或删除原文件，背景仍然可用；
- 渲染层永远只拿到 id，不接触磁盘路径；
- 删除背景变成删除自己目录下的一个文件，不会误删用户素材；
- 备份与清理可以只针对一个目录。

代价是占用一份额外空间。对图片 20MB、视频 50MB 的上限来说，这个代价可以接受。

## 三、扩展名白名单与内容嗅探双轨

允许的扩展名是 `png / jpg / jpeg / webp / mp4`。但扩展名只参与两件事：生成文件名、给路由做第二道校验。真正的类型判断来自文件头：

```text
PNG   89 50 4E 47 0D 0A 1A 0A
JPEG  FF D8 FF
WebP  RIFF ?? ?? ?? ?? WEBP
MP4   00 00 00 ?? 66 74 79 70
```

嗅探失败一律拒绝，不猜测、不尝试用扩展名兜底。这样“把压缩包改名成 mp4”不会进入背景目录。

嗅探结果还会写回返回值的 `kind`。渲染层不需要自己判断该用 `<img>` 还是 `<video>`，它信任主进程给出的类型。

## 四、上限不是拍脑袋

图片 20MB、视频 50MB 是两个不同理由的产物：

- 图片上限来自内存：一张 4K 图解码后可能占几十 MB，背景层还要叠加模糊与压暗；20MB 的压缩文件已经能覆盖常见高分辨率壁纸。
- 视频上限来自解码与磁盘：背景视频是循环播放的，太大意味着持续读盘与解码压力；50MB 足够放下几分钟的 1080p 循环素材。

超限时不做截断、不自动压缩，直接返回错误码。设置页把错误翻译成用户能理解的提示，而不是抛一个异常字符串。

## 五、列表与删除也要防路径穿越

`list` 只读取背景目录，返回文件名、类型、体积与修改时间；`remove` 先校验 id 正则，再拼路径，最后确认目标仍位于背景目录内。

删除采用“校验后 unlink”，不递归、不跟随符号链接。删除成功返回 `{ removed: true }`，不存在返回 `removed: false`，不抛异常——删除一个已经消失的文件不应该让设置页报错。

## 六、读取走受控路由

渲染层需要 URL 才能把资源放进 `<img>` 或 `<video>`。我们提供一个只读路由：

```text
GET /api/backgrounds/<id>
```

路由侧重复三道校验：uuid 形态、扩展名白名单、解析后路径仍在目录内。命中后按扩展名返回 Content-Type，并设置长缓存——文件名是 uuid，内容不会变。

文件不存在返回 404。渲染层的处理不是弹错误，而是交给解析器回退：主窗口回到内置视频，桌宠回到透明。用户看到的是“背景没了但应用正常”，而不是一个坏掉的画面。

## 七、IPC 的测试怎么写

主进程逻辑被拆成可注入依赖的纯函数：目录、picker、文件系统都能替换。测试覆盖：

- 正常选择：复制成功、返回 uuid 与正确 kind；
- 超限：图片超过 20MB、视频超过 50MB 均拒绝；
- 非法类型：内容嗅探不通过时拒绝且不落盘；
- 路径穿越：id 含 `..`、绝对路径、非法字符时拒绝；
- 删除：存在时删除，不存在时返回 false；
- 来源窗口：非主窗调用被拒绝。

这些用例不需要真的开对话框，也不需要真的 Electron：把 picker 换成返回固定路径的函数即可。桌面端的复杂度被压在一个可测试的边界内。
