# 背景素材压缩流水线：sharp 与 ffmpeg 的体积账

桌宠背景与主窗口背景的原始素材，是用户用生成工具产出的：28 张场景图、2 段桌宠循环视频、3 张桌宠静态图、3 段主窗口循环视频。原始体积加起来接近一百 MB。直接塞进安装包，安装包会瞬间突破预算，启动时的首屏加载也会变慢。

这一轮把素材压缩做成一条可重复执行的流水线，而不是手工导出。

## 一、图片：先定宽，再定格式

场景图原始是 1440–2560 宽 PNG，单张 0.6–4MB。背景层的实际显示宽度不会超过 1920（主窗口整屏在 2K 屏上也就是这个量级），继续保留更大尺寸没有意义。

规则：

- 统一缩放到宽 1920，保持比例；
- 输出 WebP，质量 80；
- 文件名保持 `gallery-NN.webp`，序号与清单一致。

用 sharp 写成一个脚本，读取原图目录、批量转换、同时生成 TypeScript 清单：

```js
await sharp(input)
  .resize({ width: 1920, withoutEnlargement: true })
  .webp({ quality: 80 })
  .toFile(output);
```

`withoutEnlargement` 保证小图不会被拉大。清单由脚本生成，避免手工维护 28 个文件名。

结果：75.7MB → 5.06MB，约 93% 降幅。单张最大不超过 400KB，背景切换不再有明显加载等待。

## 二、桌宠图片：按窗口比例给尺寸

桌宠窗是 270×480，3x 素材是 810×1440。原始 PNG 是 1440×2560，直接缩放即可。

三张图 4.06MB → 121KB。这个降幅看起来夸张，主要来自 PNG 转 WebP 与尺寸减半的组合；背景图本身是平滑渐变与柔和光照，WebP 对这种内容的压缩效率很高。

## 三、视频：统一参数，而不是逐条调

视频的原始参数各不相同：有 60fps 的，有 5Mbps 的，有带音轨的。逐条调参数不可维护，我们定了一组统一规则：

- 30fps；
- H.264，CRF 22（桌宠）或 23（主窗口）；
- 去掉音轨；
- `+faststart`，把索引放到文件头，边下边播；
- 桌宠 480×854，主窗口 854×480。

ffmpeg 命令的核心部分：

```bash
ffmpeg -i input.mp4 \
  -vf "fps=30,scale=854:-2" \
  -c:v libx264 -crf 23 -preset medium \
  -an -movflags +faststart \
  output.mp4
```

`-an` 是必须的：背景视频永远静音，音轨只会增加体积。`-2` 让高度自动取偶数，H.264 对奇数尺寸不友好。

## 四、体积账

| 素材 | 原始 | 压缩后 |
|---|---|---|
| 场景图集 28 张 | 75.7MB | 5.06MB |
| 主窗口视频 3 段 | 16.21MB | 1.52MB |
| 桌宠视频 2 段 | 5.8MB | 0.58MB |
| 桌宠静态图 3 张 | 4.06MB | 0.12MB |

合计从约 101MB 降到约 7.3MB。安装包最终 272.32MB，仍在 300MB 预算内。

这里有一个容易忽略的点：压缩不是“越小越好”。背景视频压得太狠会在暗部出现色带，渐变背景尤其明显。CRF 22/23 是在体积与观感之间试出来的，再高就会看到明显块效应。

## 五、命名与清单要对齐

素材压缩之后，最容易出的错不是画质，而是“文件在但清单没更新”。我们让脚本同时产出两样东西：

- `public/backgrounds/gallery/gallery-NN.webp`；
- `features/background/gallery.ts`，标注 AUTO-GENERATED。

清单里的 id 是 `wallpaper.gallery.NN`，标签从文件名关键词归并。脚本重跑一次，文件与清单一起更新，不需要手工对照。

生成的清单文件带“请勿手改”注释。需要调标签时改生成规则，而不是改产物。

## 六、为什么不做运行时转码

一个自然的想法是：用户选了什么就转什么，统一到 WebP 与 H.264。我们没做，原因有三：

- 转码是 CPU 密集操作，桌面端运行时转码会卡住主进程或渲染进程；
- 转码需要引入额外二进制，安装包变大；
- 失败路径变多：格式不支持、编码器缺失、磁盘不足。

当前策略是“入口白名单 + 明确提示”：只接受指定格式，超限或格式不符直接拒绝。压缩只发生在构建期，运行时只做校验与复制。

## 七、素材也是代码的一部分

这条流水线最终固化成一个脚本，和门禁一起跑。素材更新时重跑脚本，产物体积随手可见；发布前再核对安装包体积。

把素材当代码管理，最大的收益不是省空间，而是让“这张图从哪来、压了多少、有没有替换”都有迹可循。下一篇回到界面：设置面板如何把三处背景、三种来源和桌面能力差异收进一个页面。
