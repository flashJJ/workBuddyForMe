# 背景设置面板：三作用域、预览与桌面能力降级

背景功能的最后一公里在设置页：用户要能看见“现在三块界面分别是什么背景”，并且能在同一个页面里换掉它们。功能不复杂，但有几个界面层的细节值得记录。

## 一、三个作用域用一个面板，而不是三个页面

主窗口、舞台、桌宠的配置结构完全相同：来源、铺放、压暗、模糊。如果拆成三个设置页，用户要来回跳；如果各写一套表单，代码会重复三份。

最终用“顶部切换 + 一份表单”：

```text
[主窗口] [舞台] [桌宠]
来源：内置 | 图集 | 桌宠专用 | 主窗视频 | 本地文件 | 壁纸包
铺放：cover | contain
压暗：0 – 1
模糊：0 – 20px
[预览] [保存] [恢复默认]
```

切换作用域时，表单读写对应的配置；主窗口额外显示“聊天/整屏”切换。同一个组件、同一套校验，只在主窗口分支显示 `mode`。

## 二、预览与真实渲染共用解析器

预览如果另写一套渲染，迟早会和真实背景不一致。我们的做法是让预览直接复用解析器与背景层：

- 取当前表单值，构造一个临时 `BackgroundConfig`；
- 用同一份文件列表与壁纸列表解析；
- 渲染到一个固定尺寸的预览框里。

预览框里的铺放、压暗、模糊与真实界面完全相同。用户调参数时看到的就是结果，不需要保存后再回主界面确认。

## 三、桌面能力要在渲染期探测，而不是构建期

本地文件选择只有桌面端可用。Web 模式下按钮要不要显示？我们的选择是：显示，但禁用并附带说明“仅桌面端可用”。

能力探测发生在渲染期：

```ts
const bridge = typeof window !== 'undefined' ? window.app?.background : undefined;
```

三个细节：

- `typeof window` 判断保证服务端渲染不报错；
- 可选链保证旧版桌面壳没有这个桥时也不崩；
- 桥不存在时不是隐藏功能，而是显示禁用态，用户能理解“为什么这里点不了”。

不在构建期用环境变量裁剪，是因为同一份 Web 产物会同时跑在浏览器与桌面壳里，构建期无法区分。

## 四、错误要翻译成用户语言

选择文件可能失败：超限、格式不支持、复制失败、磁盘不可写。主进程返回结构化错误码，面板负责翻译：

- 超限：“图片不能超过 20MB，视频不能超过 50MB”；
- 格式：“仅支持 PNG / JPG / WebP / MP4”；
- 复制失败：“写入应用数据目录失败，请检查磁盘空间”。

错误显示在来源选择器下方，不弹全局 toast。原因是用户正在这个区域操作，错误应该出现在视线附近；全局提示会遮住预览。

## 五、保存与恢复默认的语义

保存只写当前作用域，不覆盖另外两个。恢复默认也按作用域重置：

- 主窗口回到内置雨夜视频；
- 舞台回到 `none`，交还剧集背景；
- 桌宠回到 `none`，恢复透明。

这两个动作都不触碰本地文件与壁纸包本身。用户重置背景，不会删除已经复制的图片；想清理空间，去文件列表里逐个删除。

## 六、i18n 与可搜索

面板文案进入独立的 i18n 命名空间：标题、描述、作用域、来源分组、铺放、压暗、模糊、按钮、错误提示，中英文各一套。

设置页有搜索，用户输入“背景”“壁纸”“wallpaper”都应该命中这个面板。因此设置目录里同时登记了中文与英文关键词，而不是只登记面板标题。

## 七、测试覆盖什么

面板测试不追求渲染细节，只覆盖行为：

- 切换作用域后，表单显示对应配置；
- 修改来源与参数后保存，写入 `settings.background` 的对应作用域；
- 主窗口切换聊天/整屏，`mode` 互斥更新；
- 没有桌面桥时，本地文件分组显示禁用提示；
- 恢复默认只重置当前作用域。

测试里用 `fireEvent.click` 而不是直接调状态更新，保证事件链路真实。媒体元素在 jsdom 下不存在播放能力，背景层自身做了防御，所以测试不需要额外 mock。

## 八、设置页是能力的说明书

做到最后会发现，设置页不只是操作入口，也是能力边界的说明书：哪些来源可用、哪些格式支持、文件多大、缺失会怎样，都应该在这里说清楚。

把这些写进界面，比写进发布说明更有效。用户不会读发布说明，但一定会看设置页。
