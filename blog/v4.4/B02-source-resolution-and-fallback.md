# 背景源解析：为什么只存 id，不存路径

给桌面应用加“选择本地图片当背景”时，最容易顺手写下的就是绝对路径：用户在对话框里选了 `D:\壁纸\夜雨.png`，设置里就存这个字符串，渲染时拼成 `file://` 地址。实现只要十几行，但它在真实使用里会连续出问题。

## 一、绝对路径的四个坑

第一，文件会被移动或删除。设置里存着路径，界面却打不开图，用户看到的是空白背景，而不是“这张图不见了”。

第二，路径会泄露到不该出现的地方。设置通过 HTTP 接口读写，绝对路径进入接口响应、日志、导出备份，就变成一条敏感信息。

第三，权限边界会破。渲染层拿到任意路径，意味着它可以读取磁盘上任何位置；安全审查时，这条路径就是一个必须解释的洞。

第四，跨平台格式不一致。反斜杠、盘符、中文目录、符号链接，每一个都能让拼接失败。

所以背景源只存 id。文件在进入系统时复制到应用数据目录，用 uuid 重命名：

```text
<应用数据目录>/backgrounds/8f3c2a1e-....webp
```

设置里留下的是 `{ kind: 'image', id: '8f3c2a1e-...' }`。路径由服务端按同一规则重新拼出来，渲染层永远不接触磁盘路径。

## 二、id 必须可校验

id 来自前端请求，任何“拼路径”的地方都必须假设它可能恶意。读取路由的校验规则是白名单，而不是黑名单：

```text
^[a-z0-9-]{8,64}\.(png|jpg|jpeg|webp|mp4)$
```

- 只允许小写字母、数字与连字符；
- 长度 8–64，挡住空串与超长输入；
- 扩展名必须在图片/视频白名单内；
- 拼路径前再做一次“解析后仍位于 backgrounds 目录内”的检查。

这三层里，最后一道是兜底。前两道让正常请求快速通过，第三道保证即使规则被绕过，也不会读到目录之外的文件。

## 三、扩展名不可信，内容才可信

用户把 `.exe` 改名成 `.png` 是最常见的试探。复制文件时，我们读取文件头做 magic 嗅探：

- PNG：`89 50 4E 47`；
- JPEG：`FF D8 FF`；
- WebP：`RIFF....WEBP`；
- MP4：第 4–8 字节为 `ftyp`。

嗅探结果决定 `kind`，扩展名只用来生成文件名。两者不一致时按嗅探结果为准；无法识别就拒绝。这样即使有人把可执行文件塞进背景目录，渲染层也只会看到“不支持的媒体类型”。

## 四、回退语义按作用域区分

解析器定位不到资源时，不同界面需要不同答案：

- 主窗口：回退到内置雨夜视频，用户至少还有氛围；
- 舞台：回退到内置视频，或干脆交还给剧集背景；
- 桌宠：回退到 `none`，保持透明，避免一张图盖掉角色边缘。

因此解析函数接收一个 `fallback` 开关，而不是全局常量。桌宠的调用点显式传 `false`，把“缺失就透明”写进代码，而不是写进注释。

回退只发生在解析阶段。渲染层不会因为加载失败再触发一次解析，避免“文件损坏 → 回退 → 又加载失败”的循环。

## 五、为什么把本地文件与包内资源分开

本地文件与能力包壁纸在数据上都是 `image/video + id`，但读取通道不同：

- 本地文件走桌面端复制目录，由受控路由按 uuid 读取；
- 包内资源走能力包 payload，由内容服务按启用状态聚合。

解析器并不关心通道，它只拿到两份列表：`files` 与 `wallpapers`。列表由各自的 hook 提供，注入顺序固定为“本地优先”。这让“用户自己的图覆盖包内同名图”成为确定行为，而不是偶然。

## 六、id 也有生命周期

id 一旦写进设置，就不再只是“一个文件名”，而是一条引用。它的生命周期需要和设置一起考虑：

- 删除：删除文件后，设置里的 id 仍然存在，直到下一次解析失败并回退；渲染层不会因为删除动作而崩溃。
- 重选：用户重新选择同一张图，会生成新的 uuid，旧副本需要显式删除，避免目录里堆积无人引用的文件。
- 迁移：从其他设备导入设置时，id 对不上任何本地文件，解析按“未命中”处理，回退内置背景。

这三条都不需要额外的同步协议，因为“id 找不到就回退”本身就是解析器的默认路径。反过来说，如果设置里存的是绝对路径，这三种情况都要单独写迁移与清理逻辑。

## 七、测试怎么覆盖

解析是纯函数，测试可以完全脱离 React：

- 默认值：三个作用域各自的初始配置；
- 内置命中：`wallpaper.rainy-room` 返回视频；
- 本地命中：文件列表包含 id 时返回对应路由；
- 包内命中：壁纸列表包含 id 时返回包内 URL；
- 缺失回退：主窗口回视频，桌宠回 `none`；
- 非法 id：路由层拒绝，解析层当作未命中。

六条用例覆盖了所有分支。新增一种来源时，先加用例再加实现，解析顺序不会被悄悄改掉。

把路径换成 id，看起来是多写了一个复制步骤，实际是把“资源在哪里”从用户输入变成了系统内部约定。下一篇文章讲桌面端这条复制链路本身。
