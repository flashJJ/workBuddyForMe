# 关系检索的边界：把写死的 2 和 12 变成设置

多跳关系检索里有两个数字：最多走 2 跳，最多取 12 条边。

它们写死在函数默认值里。简单问题够用，复杂问题在第二跳断掉，用户只能换一种问法。

## 为什么当初写死

多跳检索会引入噪声。跳得越远，关系越弱，上下文越容易被无关实体撑满。

2 跳 / 12 条边是一个保守的默认值：能覆盖「A 和 B 通过 C 有关系」这类常见问题，又不至于把整张图塞进提示词。

在功能刚上线时，写死默认值是合理的——先保证不炸，再谈可调。

## 可调不等于放开

这一版把两个数字放进设置，但加了范围：

- 跳数 1–3；
- 边数 4–24。

不做自由输入，也不允许无限跳。上限来自上下文预算：每多一条边，就多一段关系描述与来源引用，超过一定数量，回答质量反而下降。

范围限制在服务层做，而不是只靠界面控件。设置可能来自旧配置、手工修改或未来导入，服务层必须能自己收窄。

## 默认行为不变

不配置时仍然是 2 / 12。

这一点很重要：升级不应该改变现有用户的检索结果。设置项只在用户显式修改后生效，非法值回落默认，而不是报错或变成 0。

## 收窄函数

把范围逻辑抽成一个纯函数：

```text
clamp(input):
  hops = input.hops 合法 ? input.hops : 2
  edges = input.edges 合法 ? input.edges : 12
  return { hops: clamp(hops, 1, 3), edges: clamp(edges, 4, 24) }
```

它处理三种输入：缺省、越界、非法（NaN、小数）。

测试直接断言四组结果：默认、上界、下界、非法回落。检索层只负责把设置传进来，不重复写一遍范围判断。

## 设置界面的位置

放在知识检索设置里，与相似度阈值、片段上限并列。

说明文字写清楚代价：值越大召回越广，噪声与 token 也越多。不写「推荐值」，因为推荐值取决于文档规模与问题类型，没有统一答案。

## 边界

只开放跳数与边数，不改变关系抽取算法。

不做按问题类型自适应。当前没有可靠的分类器判断「这个问题需要几跳」，自适应只会制造不可解释的行为。

不做社区聚类与图摘要，那是更重的图能力。

## 收尾

把一个写死的常量变成设置，看起来只是多两个输入框。

真正的价值在于：它承认了「默认值不是唯一正确答案」，并把调整代价明确告诉用户。

系统不必替用户决定走几跳，但必须保证无论选几跳，都在可控范围内。
