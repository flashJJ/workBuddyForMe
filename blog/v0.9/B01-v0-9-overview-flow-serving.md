# v0.9 总览：让画出来的流程，成为本机网络上的一个服务

v0.8 我们把 AI 的临场决策画成了确定的流程图：检索、条件、大模型、工具、人工审核，拖拖拽拽连成 DAG，发布后还能以工具身份回到对话里被助手调用。但做完以后有个明显的边界——**流程的触发者只有两种：画布前的人、对话里的模型**。

你写了一个「网页摘要器」流程，想让定时任务每天早上调一次？想让 curl、让另一个脚本、让 Claude Desktop 去调它？都不行。而且执行还挂在一条 SSE 连接上，页面一关运行就取消，Electron 进程崩了，数据库里的运行永远停在 running。

v0.9 要解决的就是这两件事：

1. **执行和观察者解耦**——运行入队后由后台执行者负责，画布、对话、外部程序都只是只读观察者，断线不取消、崩溃能恢复；
2. **把流程变成标准服务**——每个已发布流程一对独立密钥，HTTP JSON 和 MCP 两种协议，本机环回，带鉴权、限流和无人值守安全策略。

## 四个里程碑

| 里程碑 | 主题 | 出口 |
|---|---|---|
| M0/M1 | 契约、v013 迁移、队列/事件总线/恢复 | 杀进程重启后无僵尸运行 |
| M2 | 本地 HTTP API + 限流 + 端点管理 UI | curl 双模调通，401/404/422/429 齐全 |
| M3 | MCP Server（HTTP + stdio） | 自举 tools/list、tools/call 成功 |
| M4 | 无人值守策略、运行记录、重放、发布收尾 | 策略 deny/allow/桌面禁单闭环，0.9.0 tag |

## 能力一：执行不再依赖任何连接

v0.8 的运行模型是「SSE 驱动」：`POST /runs` 只建行，前端连上 EventSource 时才启动执行，断线就 abort。v0.9 改成：

```text
createRun → INSERT queued → 信号通知队列
                              │
          队列 tick：UPDATE ... SET running WHERE status='queued'（原子认领）
                              │
                          后台执行 → 事件发 EventBus
                              │
画布 SSE / 公开 SSE / waitForTerminal ── 全部只是 EventBus 的订阅者
```

进程启动时做一次恢复扫描：没有执行者的 running/waiting 行收敛为 `interrupted(process_restart)`，queued 行重新入队。于是「杀进程 → 重启」之后，排队的流程自动续跑，跑完的运行可从落库记录完整回放。

## 能力二：一个端点 = 一个密钥 = 一套策略

在已发布流程的编辑器工具栏点「对外服务」，勾选本地 API 或 MCP 暴露，就会生成一个端点和一次性明文密钥（`wfk_` 前缀）：

```text
POST http://127.0.0.1:3000/api/public/flows/<密钥>/invoke
Authorization: Bearer <密钥>
```

安全默认值全部朝保守方向：

- 只监听 127.0.0.1，Host 头白名单防 DNS rebinding，不读 Cookie、不发 CORS；
- 密钥 sha256 落库，比对用恒定时间；停用端点和错密钥都回同一个 404，不让调用方枚举端点是否存在；
- 每密钥独立限流（默认 30 次/分），429 带 Retry-After；
- 同步调用超时自动转异步（202 + `X-WBFM-Async`），轮询和只读 SSE 都按密钥隔离。

## 能力三：同一个流程也是一个 MCP 工具

MCP（Model Context Protocol）让 Claude Desktop 这类客户端用一套标准 JSON-RPC 发现和调用工具。v0.9 给每个开启 MCP 暴露的流程实现了一个完整的最小 MCP Server：

- HTTP 承载：`POST /api/public/mcp`，无状态、bearer 鉴权，应用自身的「设置 → MCP 服务器」就能自举；
- stdio 承载：打包进桌面版的独立 bin，外部客户端 spawn 内置 node 运行，env 传端点密钥。

工具名是稳定短码 `flow_<id 前 8 位>`，inputSchema 直接从 start 节点声明的入参生成。我们在应用内完成了自举验证：注册自己的 HTTP MCP 服务器后，工具目录里出现 `mcp:bootstrap:flow_*`，调试台真实调用返回流程输出。

## 能力四：无人在场时，危险操作谁说了算

API/MCP 调用没有人坐在屏幕前点「允许」。v0.9 的策略是：

- **read 工具**：始终放行；
- **write/danger 工具**：默认 `deny_all` 全部拒绝；用户可在端点设置里切到 `allowlist`，从当前发布图实际存在的危险节点中逐项勾选；
- **桌面控制类**（鼠标、键盘、窗口、UIA 等 10 个）：不管白名单怎么配，API/MCP 永久禁止——GUI 操控必须走有人链路。

策略在建 run 的那一刻快照固化，执行期间改端点配置不影响在途运行。发布含新危险节点的新版本后，端点进入「待重新确认」状态，重新保存策略前所有调用返回 409。拒绝/放行都有可检索的审计标记落在节点执行记录里。

配套还有运行记录中心（按来源/状态筛选）和重放：失败/中断的运行可以整体重跑，也可以从失败节点重放其**祖先闭包**——新 run 只跑目标节点的全部上游段，用 `parentRunId`/`resumedFromNode` 关联。
