# 单来源失败不该拖垮整个上下文

任务上下文有五个来源。最慢、最容易失败的是长期记忆检索：它可能走本地向量库、可能超时、可能被中途取消。

旧实现里，这几段是串在同一个函数里的。一个来源抛错，整个函数就抛；调用方拿到异常，只能按「这次没有上下文」处理。摘要在手、近期对话在手，也一起丢了。

这一版把容错放到了收集器的边界上。

## 一、失败粒度决定可用性

先看一个真实的取舍：上下文不是一个整体，它是有优先级的集合。摘要最重要，记忆最不重要。既然如此，「记忆检索失败」就不应该等价于「没有任何上下文」。

旧结构的问题不在 `try/catch` 写得少，而在于**失败粒度太粗**：函数级别只有一个出口，失败就是整体失败。

新的结构里，每个来源单独执行、单独结算：

```ts
for (const source of sources) {
  try {
    const fragments = await source.collect(request);
    status = fragments.length ? 'ok' : 'empty';
  } catch {
    status = 'failed';
  }
}
```

注意这里不是真的用 `for` 串行——实现上仍然是 `Promise.all` 并发，只是每个任务内部有独立的异常边界。串行还是并发，与容错粒度是两件事。

## 二、四种状态就够了

每个来源结算成四种状态之一：

| 状态 | 含义 | 片段 |
|---|---|---|
| `ok` | 采集成功且有内容 | 返回 |
| `empty` | 采集成功但没内容 | 空 |
| `skipped` | 开关关闭，未调用 | 空 |
| `failed` | 抛错 | 空 |

区分 `empty` 和 `skipped` 很重要：前者说明「查了但没有」，后者说明「根本没查」。排查「为什么这段没进来」时，这两种结论完全不同。

状态里还带 `durationMs`，能看出哪个来源最慢。对一个本地应用来说，这比打日志更直接。

## 三、为什么不让收集器抛错

一个自然的疑问：既然失败了，为什么不往上抛，让调用方决定？

因为调用方没有更好的决定。任务上下文的消费方是规划与执行，它们能做的只有「有就用，没有就算」。把异常往上抛，只会在更高层再写一遍「整体降级」的逻辑。

所以收集器的契约是：**永不因单来源异常而失败**。它返回片段与状态，调用方按结果装包。

真正的整体异常（比如装配入口本身出错）仍然会被外层捕获并降级为 `null`——这是最后一道保险，不是常态。

## 四、异步来源与取消

五个来源里只有记忆检索是异步的，其余是同步查询。并发采集对同步来源几乎没有收益，但它带来两个隐性好处：

1. 同步来源不会因为某个异步来源慢而被推迟（在旧实现里，记忆总是最后执行，但结构上仍受前面的耗时影响）；
2. 取消信号可以统一透传，记忆检索被中断时按 `failed` 结算，其它来源不受影响。

注意：这里的并发不是「性能优化」，而是「结构优化」。五个同步查询并发执行并不会更快，真正收益是失败隔离与状态可见。

## 五、容错不等于吞错

失败被隔离，不代表失败被隐藏。

- 收集结果里 `failed` 是可见的，调用方或调试面板可以展示；
- 装配入口仍然保留最外层降级，避免异常穿透到任务循环；
- 装备器不会因为某个来源失败而改变其它片段的顺序——这是验收项之一：「单来源失败不改变其他来源的片段与顺序」。

这三条一起，才算「隔离」而不是「掩盖」。

## 六、边界与取舍

- 不做来源级重试：本地检索失败通常是配置或索引问题，重试收益低，反而拖慢装配；
- 不做来源级超时：取消信号由上层统一控制，收集器不引入第二套计时器；
- 不合并失败信息进提示词：模型不需要知道「记忆挂了」，那是给人和日志看的。

## 七、一个小例子

假设一次任务启动时，五个来源的状态是这样：

```text
conversation-summary   ok      12ms
conversation-facts     ok       3ms
active-plan            empty    1ms
recent-messages        ok       6ms
long-term-memory       failed  800ms
```

旧实现的结果：整块上下文为 `null`，规划器完全看不到会话刚才在聊什么。

新实现的结果：四段片段照常装包，记忆这段缺席；状态表里清楚写着 `failed` 与 800ms，排查时一眼能看到瓶颈在检索而不在装配。

这时如果再配合取消信号，用户中途取消任务，记忆来源会按 `failed` 结算，其它片段仍然可用——旧实现会直接抛异常。
