# 运行记录下钻：把证据链的最后一步从「手抄」变成一个链接

治理相关的功能做了一整套之后，复盘时会发现一个尴尬的细节：审计账本里有 `runId`，审批中心里有 `runId`，任务时间线也按 `runId` 过滤——三个地方数据都在，但从一个地方走到另一个地方，中间需要人复制、切页面、粘贴、再翻。

这不是功能缺失，是**缺失一个入口**。而证据链只要断在最后一步，前面做得多完整都白搭：用户在事后复盘时，往往就是想知道「那次拒绝发生时，Agent 到底在做什么」。

## 唯一关联键：任务运行的 id

三个页面的关联键必须完全一致，否则跳过去只会得到一个空结果。这里选的是任务运行记录的主键——它同时被审计事件写成 `run_id`，被审批项保存，也被时间线用作过滤参数。

一条规则跟着这条键走：**没有关联键就不提供入口**。审计事件里并非每条都有运行上下文（设置变更、登录、策略保存都可能没有），这些行不渲染链接，而是显示「无关联运行」。宁可少一个按钮，也不给用户一个点进去什么都没有的死链。

## 两个入口，同一个目标

| 位置 | 之前 | 现在 |
|---|---|---|
| 审计事件行 | `runId` 一段等宽文本 | 有 id 时显示「查看任务」链接 |
| 审批项 | `runId` 一段等宽文本 | 文本本身变链接，保留原值与深链按钮 |

审批项的处理值得多说一句：原来的文本被完整保留，只是变成可点击——用户想复制 id 仍然可以复制，想跳转则一次点击。链接化不等于替换内容，尤其是在一个以「留证」为目的的页面上。

两者跳的都是任务时间线，参数是 `scope=task` 加运行 id。把范围显式写进 URL，是为了让时间线自身保持通用：它不只服务任务，未来别的范围也能复用同一个页面。

## 审计页：支持直达，也支持清空

审计页原来只有一个内存里的过滤框。现在增加一路从地址栏进来的输入：

1. 页面挂载时读 `?runId=`，预填到过滤条件并立即生效；
2. 用户在页面内改过滤条件时，用 `history.replaceState` 同步地址栏，不触发整页导航；
3. 清空或重置过滤时，主动移除 `runId` 参数；
4. 按 id 过滤无结果时，显示专用空态「该 runId 无关联审计事件」，而不是报错或空白。

第 2 步用替换而不是推入历史，是因为过滤条件变化不该在浏览器后退栈里堆出一长串记录；但地址栏仍需同步，这样用户复制当前链接发给别人，对方打开看到的是同一份过滤结果。

第 3 步常被忘。如果清空过滤后地址栏还挂着 `runId`，用户刷新页面会突然回到旧结果，会以为清空没生效。

第 4 步是「空态不是错误」的典型：一个 id 没查到事件是完全合法的状态——可能是运行被清理了，可能是审计写入时那条事件没有 id。这种情况返回 404 会让用户以为页面坏了。

## 任务详情的形态：没有独立页面，就用展开区

设计稿里说「任务详情页展示治理摘要」，但现有界面从来没有独立的任务详情页，任务是一个列表，每行可以展开。硬造一个页面等于为一个字段组新增一条路由、一套加载态、一套权限判断。

实际做法是复用展开区：展开后先显示原有信息与时间线入口，再加一块治理摘要，最后是最近十条关联审计。用户的操作路径完全没变——还是点那一行。

## 只读是硬约束

下钻这件事最容易越界的地方，是「既然都跳到任务了，顺便给个重试按钮吧」「既然看到拒绝了，顺便给个忽略按钮吧」。这一版明确不做：

- 新增的只有导航链接，没有新的写接口；
- 审计账本的追加语义不变，不因为页面跳转产生任何事件；
- 任务详情的审计列表是查询，不触发校验、不写回任何标记。

原因很实际：审计和审批的可信度来自「它只记录，不干预」。一旦这些页面能顺手改状态，用户就很难再相信里面的内容。

## 路径显示要脱敏，但不能无意义

任务详情里会显示工作目录。完整路径在排障时有用，在截图分享时是隐私——两级需求冲突，处理办法是折叠中段：

```text
/app/workspace/project → /app/…/project
/app/scratch/output    → /app/…/output
```

规则统一为「保留开头有辨识度的部分与最后一两级目录，中间用省略号」。Windows 路径同理，保留首段与末级。原始路径放在悬停提示里，需要精确值时仍然拿得到。

这不是安全边界——数据本身还在数据库里，只是不主动铺在界面上。对本地应用而言，这已经足够：绝大多数泄露发生在截图，而不是数据库被读。

## 验收走一遍真实路径

验收不看组件，走三个动作：

1. 从一条带运行 id 的审批项点进去，时间线显示的是那一次运行的事件；
2. 把 `/audit?runId=` 的链接直接粘到新标签页，过滤条件已预填，结果正确；
3. 清空过滤，刷新页面，地址栏不带参数，列表回到全量。

再补一条反向用例：给一个不存在的 id，审计页显示空态，任务时间线显示「无事件」，两边都不报错。

## 这一版的测试

新增八条用例：路径折叠三种形态（绝对路径、另一种分隔符风格、相对路径）、治理摘要三件事（字段渲染、最近审计、空态）、审计页两件事（参数预填与跳转链接、清空移除参数）。

数量不多，因为它们测的是「入口对不对」，而不是「数据对不对」——数据正确性早在上一个阶段就被账本自身的校验覆盖了。

## 边界

- 下钻不做跨运行聚合，只看单次运行；
- 审计页的过滤仍以运行 id 为主键，不做模糊搜索；
- 没有运行上下文的事件永远不显示入口，这是设计，不是缺陷。
