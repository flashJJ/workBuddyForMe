# 103 个音色怎么放进设置页：分组、试听与默认回落

多说话人 TTS 给了 103 个音色，但把 103 个选项直接塞进下拉框，体验通常很差：名字不直观、不知道哪个适合当前角色、选完还要去别处试听。

这一轮我们要给“用户导入的 VRM”加声线选择。难点不是存储，而是让选择这件事可用。

## 一、先理解音色表的结构

Kokoro 的 103 个音色都在一个 `voices.bin` 里，合成时用 sid 选择。官方表大致分三组：

- 0–2：英文音色；
- 3–57：中文女声，`zf_001`–`zf_055`；
- 58–102：中文男声，`zm_009`–`zm_053`。

注意男声不是从 `zm_001` 开始：58 对应 `zm_009`，59 对应 `zm_010`。如果按 sid 直接拼 `zm_00X`，前几个会错位。

我们按官方顺序推导了一个只读目录：每个选项包含 sid、音色名、性别、分组。推导逻辑集中在一处，UI 只消费结果。

## 二、默认值怎么表达

导入模型未绑定时，不应该强制用户先选一个音色才能用。默认选项是：

> 跟随默认（Haru · sid 3）

这表达的是“没有用户偏好”，而不是“用户选择了 Haru”。两者的区别在数据上就是 NULL 和 3：

- NULL：解析时继续走默认角色；
- 3：用户明确绑定到 Haru，未来默认角色变化时仍保持 3。

UI 用空字符串表示 NULL，提交时转成 null。这样用户随时可以“清除绑定”，而不需要删除模型。

## 三、分组与试听

下拉框按英文、中文女声、中文男声分组。每个选项只显示音色名，分组标签承担解释；不把性别、sid 重复塞进每个 option，避免列表过长。

试听复用已有的单句合成接口，传入当前选中的 sid。试听按钮在 Kokoro 模型未就绪时禁用，避免用户点了没反应。

这里有一个细节：试听的是“即将保存的声线”，不是“当前已保存的声线”。用户切换下拉框但还没保存时，试听应该跟随选择；保存后再刷新列表。

## 四、MeloTTS 下怎么办

默认引擎是 MeloTTS，单说话人。此时声线绑定不会生效，但用户仍然可以提前配置，等切到 Kokoro 再用。

UI 的处理是：

- 绑定入口始终可见；
- 在当前不是 Kokoro 时显示一行提示：“仅 Kokoro 多角色引擎生效；MeloTTS 为单声线”；
- 试听在 Kokoro 未就绪时禁用。

没有把入口藏起来，是因为“先配置、后切换引擎”是合理路径；也没有假装生效，因为提示必须诚实。

## 五、设置页形象区怎么同步

导入模型的声线保存在列表接口里。设置页形象区已经会拉取 `/api/vrm-avatars`，所以不需要再发一次请求：

```ts
const imported = avatars.find(a => a.fileRef === fileRef);
const voice = resolveAvatarVoice(modelId, {
  speakerSid: imported?.voiceSid ?? null,
});
```

这样用户在已导入模型列表里改了声线，回到形象区看到的就是同一个值；试听也用这个值，不会再出现“列表里是 58，形象区试听是 3”的情况。

## 六、为什么不做“自动推荐音色”

一个很自然的想法是：根据 VRM 的名称或 meta 猜性别，自动推荐音色。

我们没有做，原因是：

- VRM 名称不可靠，很多模型叫 `avatar_01`；
- meta 里没有性别字段；
- 猜错比不猜更尴尬，用户会以为应用“听懂了这个角色”；
- 自动推荐需要额外的模型/规则，收益不确定。

默认“跟随 Haru”是保守但可解释的；用户想换，随时可以在 103 个音色里选。未来如果要做推荐，也应该建立在用户显式选择的历史上，而不是猜名字。

## 七、测试与边界

- 目录长度 103；
- 3、57、58、102 的音色名与官方顺序对齐；
- PATCH 契约接受 0/102/null，拒绝 103 与额外字段；
- 旧记录无 `voiceSid` 时按 null 读取；
- 服务层越界与不存在记录拒绝。

UI 没有做 103 项的逐个视觉测试，但选择器的数据源和保存路径都有单测覆盖；真正的听感仍需要人工试听。

## 八、经验

1. **数量大时先分组，再谈搜索。** 103 项分组后仍可扫读，直接平铺则不可用。
2. **默认值要表达“未设置”。** NULL 和具体 sid 是两种语义，不能混用。
3. **试听要跟随当前选择。** 否则用户会以为保存失败。
4. **引擎不匹配时给提示，不要隐藏入口。** 先配置后切换是真实路径。
5. **不要用不可靠的元数据猜用户偏好。** 宁可默认，也不要自作聪明。

声线选择不是一个“大功能”，但它把 103 个音色从模型参数变成了用户能理解、能试听、能撤销的偏好。
