# 同一份清单，两种字节：签名前的 canonical 序列化怎么做

清单签名最容易踩的坑不是密码学，而是序列化。

作者写了一份 JSON 清单，宿主用 schema 解析它、补上默认值、再计算签名。如果签名工具签的是作者手写的原文，宿主验的是解析后的对象，两边看到的字节不同，验签必然失败——而且看起来「明明没改过」。

所以签名链路的第一步不是生成密钥，而是把「逻辑等价的清单」压成同一串字节。这一步叫 canonical 序列化。

## 一、JSON 没有唯一表示

下面两份 JSON 在语义上完全相同：

```json
{"id":"demo","version":"1.0.0"}
{"version":"1.0.0","id":"demo"}
```

键顺序不同，字节不同。再考虑空格、换行、Unicode 转义、数字写法（`1` 与 `1.0`），同一份数据可以有无数种文本形态。直接对原文签名，等于把「谁的序列化器先跑」变成了协议的一部分。

canonical 序列化要做的，就是人为定义一个唯一表示：

- 对象键递归排序；
- 数组保持原顺序（数组顺序是语义的一部分，不能排）；
- 不输出多余空白；
- 删除 `signature` 字段本身，避免「签名包含签名」；
- 前面加一段固定域前缀。

域前缀看起来多余，实际是防跨协议复用：同一份 JSON 在另一个协议里被签名，不能拿来当本协议的签名用。前缀把签名空间隔离成两块。

## 二、顺序必须是「先解析，后规范化」

签名工具与宿主的顺序必须完全一致：

```
原始清单 → schema 解析（补默认值、丢未知字段）→ 剔除 signature → canonical 字节串 → 签名
```

如果签名端跳过 schema 解析，作者漏写的可选字段在签名端不存在，在宿主端却被补上默认值，两端字节不同。这个 bug 很隐蔽：包安装成功、验签失败，而作者坚持「我一个字都没改」。

反过来，如果签名端解析了、宿主端没解析，问题同样存在。所以规范化的输入被约定为「schema 解析之后的清单」，两端只共用一个函数。

## 三、只允许一份实现

规范化函数放在共享包里，签名工具从共享包的构建产物导入，宿主从源码导入，都是同一份实现。禁止在脚本里复制第二份——复制的那天就是漂移的开始。

验签则放在服务端包里，因为它依赖 Node 的加密模块，而共享包会被打进客户端 bundle。边界要提前划清：**纯函数进共享，加密原语不进客户端。**

签名工具只做四件事：读清单、schema 解析、规范化、签名。加 `--write` 才回写文件；不带参数时只打印 base64 与密钥标识，避免误改。工具启动时检查构建产物是否存在，不存在就提示先构建，而不是自己实现一遍。

## 四、五态判定与策略矩阵

验签结果不是布尔值，而是五种状态：

| 状态 | 含义 |
|---|---|
| 无签名 | 清单没有签名字段 |
| 有效 | 签名可解析，密钥在信任库，密码学校验通过 |
| 无效 | 签名格式正确，但校验失败 |
| 未知密钥 | 签名可解析，密钥不在信任库 |
| 格式坏 | 签名字段本身不合法 |

策略只有三档，作用范围被刻意限制：

| 策略 | 无签名 | 未知密钥 | 无效 / 格式坏 |
|---|---|---|---|
| 关闭 | 放行 | 放行 | 放行 |
| 提醒（默认） | 放行 | 放行 | 拒绝 |
| 强制 | 拒绝 | 拒绝 | 拒绝 |

关键一行：**「无效」在提醒与强制下都拒绝。** 如果提醒档连无效签名也放行，攻击者只要破坏签名就能绕过强制校验；签名系统会变成「越坏越容易进」。策略只能放行「没有」和「不认识」，不能放行「对不上」。

关闭档是显式逃生门：用户明确选择不验签，系统就不假装验过。列表里的签名徽章会显示「未检查」，而不是「有效」。

## 五、测试怎么写

黄金向量比随机测试更重要。至少要覆盖：

- 键顺序不同的等价清单，规范化结果一致；
- 数组顺序不同，结果不同；
- 含 Unicode、转义字符、数字与布尔值时结果稳定；
- 缺省字段被 schema 补齐后，签名与验签一致；
- 改任一业务字段，验签失败；
- 同一清单重打包 ZIP（文件时间、压缩参数变化）不影响验签，因为签名只覆盖清单，不覆盖压缩包字节。

最后一类用例解释了一个常见误解：签名保护的是「安装时会被读取的那份清单」，不是 ZIP 文件的哈希。ZIP 重打包不改清单，验签自然通过；payload 完整性由 checksum 负责，两者分工明确。

## 六、这一层得到什么

canonical 序列化把「签名」从字段变成了可重复的判决：同一份清单，无论谁在什么机器上序列化，字节都一致；不同来源的清单，宿主能给出五态结论，而不是一句「验签失败」。
