# 把「能用」做成「看起来可靠」：一次界面质感的系统化升级

我们的桌面 AI 应用是一个本地优先、单人开发的私人助手，界面基于 Next.js 与 Tailwind，跑在 Electron 桌面壳里。功能齐了之后，最先暴露的问题不是「用不了」，而是「看起来不像一个能长期用的东西」。

同一个按钮在设置页高一点、在聊天页矮一点；卡片阴影一处深一处浅；弹窗出现得很突然；中文长段落挤成一坨。这些单看都是小事，叠在一起就变成了不可信。

这一轮没有新增任何业务功能，也没有数据库迁移，只做一件事：把「能用」的界面，做成「看起来可靠」的界面。

## 质感不是装饰，是约束

「豪华感」「高级感」这类词没法验收，也没法分工。所以动手之前，先把主观描述翻译成五条可以逐项打勾的硬口径。

第一条是层级：任意界面最多三级表面——页面底、卡片、浮层，每一级都有对应的阴影档位。同一层里的两个元素，不能靠加深边框来区分，否则层级会越用越乱。

第二条是节奏：内外边距落在同一套尺度上，消息正文有最大宽度并居中。没有最大宽度，宽屏下正文会贴边拉伸，读一行长文要转头。

第三条是细节：交互元素四态齐备，hover、active、focus-visible、disabled 都要有明确反馈，过渡时长全部取自令牌，不随手写一个时长。

第四条是一致：同一个语义只有一种令牌来源。新增颜色必须先进入主题块，禁止在组件里写死某一个色阶。

第五条是可读：表格、代码、引用、列表都有明确的容器样式，中文长文不出现竖排挤压。

五条之外还有几个附加指标：亮暗与五套主题下的对比度不低于 4.5:1；键盘可以完整操作；系统开启「减弱动态效果」时动画降级；1280、1440、1920 三档窗口不出现横向溢出和控件换行错位。

## 五条口径落到页面上

把这五条摊到具体位置，才不至于停留在口号。

| 位置 | 之前 | 这一轮 |
|---|---|---|
| 按钮 | 各页自定义高度与圆角 | 高度三档，四态与焦点环统一 |
| 弹层 | 阴影与遮罩各自为政 | 三级表面 + 三档阴影 + 毛玻璃遮罩 |
| 消息 | 双方都是整块气泡 | 助手去气泡，用户右对齐胶囊 |
| 富文本 | 裸 pre、表格挤压 | 代码标题栏、表格滚动与首列粘性 |
| 空态 | 只有配置向导 | 品牌区 + 示例 prompt 卡 + 四段式状态 |

表格里没有一项是新能力，全是把已有元素放到统一的规则下。

## 为什么不直接重写页面

看到「不齐」，最直接的冲动是按新设计把页面重画一遍。真做起来，代价远比想象大。

重写会把已经验证过的交互、快捷键、错误分支和边界状态一起推倒。聊天页里光是流式、重试、反馈、分支入口就有不少组合，重画一遍等于把旧 bug 的修复记录全部作废。

这一轮选择在既有结构上换基座：先换颜色、阴影、时长和组件，再逐块调整布局。页面结构基本不动，但每个元素都换成了同一套语言。

这也解释了一个反直觉的现象：改动看起来铺得很广，实际风险却比「重画三个页面」低。

## 为什么先做设计基座

顺序不是拍脑袋定的。早期实现里，颜色、阴影、时长散落在各个组件：这个按钮写 `shadow-sm`，那个弹层直接写死一个过渡时长，某个状态标签用了 Tailwind 的固定色阶。

这样做的直接后果是五套主题没法一起成立。亮色下刚好的阴影，到了深色主题里完全看不见；某个语义色在浅底上够用，换到另一套底色就掉到对比度线下。

所以第一步不是改页面，而是补三类令牌：表面层级、阴影档位、动效时长与缓动。它们先进主题块，组件只引用语义名。改一处，全站受益，这是唯一能一次性覆盖五套主题的位置。

## 先基座，再消息，最后动效

基座之后，第二个做的是消息与富文本。原因很实际：用户每天盯着看的就是消息区，气泡、代码块、表格的观感变化最容易被感知。基座刚落地时就去改消息，能最快验证令牌是不是够用。

消息改完，才轮到聊天页骨架：正文列限宽居中、会话列可收成图标条、形象栏在窄屏默认收起。这一步依赖前面两块的尺寸稳定，提前做会返工。

最后是动效与空态。入场、骨架屏、滚动渐隐、「回到底部」浮标，都建立在结构不再变动的前提上；空态与错误态则收敛成「图标 + 标题 + 说明 + 主按钮」四段式，供全站复用。

顺序背后的判断只有一句：**越低层、越全局的改动越先做；越依赖结构、越容易被返工的改动越后做。**

## 这一轮刻意没做什么

不新增业务功能。托盘入口属于桌面壳的可见性补丁，不改变任何业务数据流。

不引入新的 UI 依赖。仍然沿用 Radix 与 Tailwind，也不引入动画库；弹层入场用纯 CSS 关键帧完成。

不做数据库迁移。旧库直接可用，数据库结构版本保持 45，没有新增表，也没有改写字段。

不为动效牺牲流式渲染性能。消息块的分块 memo 策略保持原样，动画只加在外层容器上。

不改主题的既有语义。新增令牌只做加法，老主题不需要手工迁移。

这些「不做」看起来保守，但它们保证了一次纯界面升级不会顺手变成一次架构改造。

## 验收看的是跨页一致性

单项好看没有意义，跨页一致才有意义。

所以验收不看某一页的截图，而是把设置页与聊天页并排：按钮高度、圆角、焦点环、卡片阴影是否完全一致；同一语义的颜色是否来自同一个令牌；键盘走一遍，焦点是否始终可见。

这也是为什么令牌必须先落地。如果只在页面上调，两个页面很容易各自「顺手」，最后仍然对不齐。

## 验收与遗留

门禁层面，类型检查、Lint、单文件行数、目录预算、循环依赖与 ASCII 框图检查全部通过。

功能层面，聊天、形象与通用组件相关的单测共 126 例通过，中英文案对等测试通过；桌面壳新增的托盘菜单单测 6 例与图标解析回归测试也通过。

没有做的是三档窗口的截图巡检。本机端口被占用，前端起不来，这一项被明确记为遗留，而不是假装验过。界面的视觉回归目前也没有自动化基线，这是下一轮更值得补的基础设施。
