# 在撞墙之前先压缩：四种触发时机与它们的成本

以前的压缩只有一个时机：一轮回答结束后，如果历史占用超过 70%，就把最旧的消息折叠掉。

这带来一个尴尬的窗口期。用户发来一条很长的消息，加上历史正好超过预算，装配侧只能直接丢弃最旧的消息，既没有摘要，也没有记录。等回答结束再压缩，那一轮已经损失了中段信息。

这一轮我们把压缩时机从一种扩展成四种，并给每种时机算清成本。

## 一、回合后阈值：保留 70%

这是原有路径，没有改。

一轮回答完成后，估算未折叠历史的 token 数。超过可用窗口的 70%，就折叠最旧的一部分，保留大约 50% 的逐字后缀，且至少保留 4 条消息。

保留后缀是必须的。最近几轮通常包含当前任务的参数、约束和指代对象，全部换成摘要会让下一轮直接失去上下文。

70% 这个数字也没动。它不是理论最优值，而是在“压缩太频繁”和“撞墙太突然”之间踩出来的经验值。贸然调整会让所有历史数据失去可比性。

## 二、装配前预判：85% 高水位

新增的第一种时机发生在请求之前。

装配前先估算一次历史占用。如果超过可用窗口的 85%，先压缩，再组装本轮上下文。

为什么是 85%，而不是 70%？因为这两个数字服务于不同目的。70% 是“回合结束后顺手整理”，85% 是“这轮马上要撞墙了，必须提前处理”。中间留出 15 个百分点，形成滞回区，避免每一轮都触发预判压缩。

预判压缩的代价很明确：多一次摘要调用。它不是免费的，所以只在真正的高水位触发，并且提供设置开关，可以在调优中心关闭。

还有一个细节：冷开场和闲聊不触发预判。没有历史可压，或者这一轮本来就不需要大上下文，提前调用模型只是浪费。

## 三、模型切换：窗口变小了

第二种时机来自模型切换。

用户可能上午用一个大窗口模型聊了很久，下午切到本地 7B，窗口只有 4096。此时同一段历史，昨天装得下，今天装不下。

预判逻辑会读最近一次装配快照里的窗口值，和当前模型窗口比较：

```ts
if (previousWindow > currentWindow) trigger = 'model_change';
else trigger = 'preflight';
```

如果之前的窗口更大，说明是“换小模型”导致的预算不足，事件标记为 `model_change`；否则仍然算普通的预判压缩。

这个区分不是为了好看。模型切换引发的压缩，用户往往没有心理准备，排查时也需要知道“不是历史突然变长了，而是窗口变了”。

真机验证过一次：大窗口模型积累到 4103 token 后切到 4096 窗口的本地模型，压缩把 4237 token 降到 1580，小模型依据摘要仍然答对了关键数字。

## 四、用户显式触发

第三种时机是用户自己点。

上下文面板上有一个“立即压缩”按钮，调用会话的压缩接口。事件里的 `trigger` 是 `user_explicit`。

它解决的是“我知道现在上下文很乱，但不想等到下一轮自动触发”的需求。手动压缩也走同一条压缩管线，不是另一套逻辑，所以摘要、事实、事件、降级行为完全一致。

真机上手压一次：折叠最早 6 条消息，token 从 2620 降到 2392。压缩后继续追问，端口、负责人等关键信息仍然答对。

## 五、四种时机的成本对照

| 触发 | 发生时机 | 额外模型调用 | 可否关闭 |
|---|---|---|---|
| 阈值 | 回合结束后 | 有 | 否，基础路径 |
| 预判 | 装配前 | 有 | 可关 |
| 模型切换 | 装配前 | 有 | 随预判开关 |
| 用户显式 | 用户点击 | 有 | 不需要 |

四种触发都会产生摘要调用，区别在于“谁决定现在压”。阈值是系统例行维护，预判是风险规避，模型切换是被动适配，用户显式是主动控制。

成本控制的关键不是消灭调用，而是让调用发生在有收益的时刻。预判只在 85% 以上触发，就是为了把“多一次调用”换成“少一次硬截断”。

## 六、失败不阻断回答

压缩是旁路，不是主链路。摘要失败时，系统做三件事：

1. 保留“首条 + 最近 K 条”，中间部分放弃；
2. 写一条 `degraded: true` 的压缩事件；
3. 继续本轮回答。

不重试到成功，也不因为压缩失败而拒绝回答。重试会把一次延迟放大成多次，而用户此刻要的是答案，不是完美的摘要。

事件写入失败同样不阻断摘要写回。观测可以丢，读取路径不能断。

## 七、为什么不做话题切换自动压缩

我们考虑过：检测到用户换话题，就自动压缩旧话题。

最后只记录信号，不自动执行。原因是收益未经验证，风险却很清楚：话题边界判断错了，会把仍然相关的上下文压掉，而且用户毫无察觉。

目前的信号是“意图变化 + 与最近摘要相似度低”。先积累数据，再决定是否开启，而不是先上线再解释。

## 八、结果与边界

压缩不再只发生在回合之后，撞墙前也有一次补救；模型切换这种隐性预算变化，有了明确的触发原因；用户想整理上下文时，有可点的入口。

边界也很清楚：预判会增加一次摘要调用，默认只在 85% 高水位触发，且可关闭；话题切换不自动压缩；压缩后的语义保真仍要靠真机体验验收，结构化评测只能证明事件、范围与预算正确。
