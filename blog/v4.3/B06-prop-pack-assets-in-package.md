# 道具包：把 GLB 放进能力包之后

场景包解决的是“表演怎么组合”，道具包解决的是“新模型怎么进来”。前者只有 JSON，后者第一次把二进制资源放进能力包。

这一步带来的问题比想象中多：资源放哪、怎么读、路径怎么防越界、体积怎么算、许可怎么声明。

## 一、资源不能写进 public

最省事的做法是安装时把 GLB 复制到 web 的静态目录。但桌面应用的静态目录属于构建产物，运行时会随版本更新被覆盖；多用户、多安装路径下也不可控。

我们选择让资源留在能力包目录里，通过一个只读资源接口按需读取。接口接收包 id 与相对路径，校验后返回文件流。

这样安装、停用、卸载都只操作能力包目录，不会污染构建产物。

## 二、两层校验：路径与声明

只做路径校验不够，只做声明校验也不够。

第一层是路径：把请求路径 resolve 到包目录，必须仍在包目录内。`..` 越界在这里被挡住。

第二层是声明：请求的文件必须出现在该包 payload 的道具列表里。即使路径合法，只要不是包声明的资源，也不能读。

两层都过，才返回文件。接口还会检查能力包是否处于启用状态，停用后立即不可读。

## 三、许可与类型是必填项

道具元数据必须声明：

- id：与内置道具隔离的 `pack.` 前缀；
- 类型：手持或场景；
- 文件：`payload/` 下的 `.glb`；
- 许可：只允许明确的白名单值；
- 几何参数：手持的接触点/横向偏移，或场景的位置/朝向。

手持道具不能声明场景位置，场景道具不能声明手持参数。类型与参数互斥在 schema 层校验，避免“声明成手持却按场景摆放”的静默错误。

许可必填不是为了法律合规流程，而是为了让每个进入应用的资源都有明确来源。缺失许可的包在启用时直接拒绝。

## 四、体积预算在启用时执行

道具资源不进入仓库，因此不能靠仓库里的检查脚本。预算放在启用 effect：

- 单个 GLB 不超过 5MB；
- 整包资源合计不超过 20MB；
- entry 不超过 64KB。

校验时逐个 stat 文件，确认存在、是普通文件、大小在预算内。任何一个不满足，整包拒绝启用。

资源接口读取时还会再检查一次单文件大小，防止启用后文件被替换成超大文件。

## 五、示例资源也可以程序化生成

示例道具包需要一个真实可加载的 GLB。我们不想在仓库里塞一个来路不明的二进制，也不希望示例依赖某个内置模型。

最终用代码直接构造了一个最小立方体 GLB：位置缓冲、索引缓冲、一个无光照材质、JSON 块与二进制块按 4 字节对齐。文件大约 1KB，用 three.js 的加载器验证过可以正常解析出一个 mesh。

这让示例包完全自包含，也让测试可以断言 GLB 头部与资源读取，而不需要外部文件。

## 六、坏包的处理原则

道具包的失败路径比成功路径更重要：

- payload 非法 JSON：拒绝；
- 缺少资源：拒绝；
- 路径越界：拒绝；
- 单文件或合计超预算：拒绝；
- 未声明许可：拒绝；
- 两个包声明同一个道具 id：聚合层拒绝。

所有拒绝都发生在启用或读取阶段，不会留下“安装成功但运行时才崩”的半成品。

## 七、结论

把二进制资源放进能力包，本质上是把“内容分发”与“资源分发”合并。合并之后，路径、许可、预算和声明必须一起校验，缺一项都会留下缺口。

这条链路跑通后，后续再加音频、贴图或其他资源类型，都可以复用同一套边界。

## 八、payload 示例

道具包的 payload 只描述元数据与资源位置：

```json
{
  "name": "示例道具包",
  "props": [
    {
      "id": "pack.sample.cube",
      "kind": "stage",
      "file": "payload/assets/sample-cube.glb",
      "license": "CC0-1.0",
      "position": [0.22, 0, -0.1],
      "rotationY": 0.3
    }
  ]
}
```

`file` 不是 URL，而是包内相对路径。资源接口根据包 id 与这个路径定位文件，前端只拿到拼好的只读 URL。

## 九、启用时的校验顺序

启用 effect 按固定顺序执行：

1. 读取 payload，JSON 解析失败即拒绝；
2. schema 校验：数量、前缀、许可、类型与参数互斥；
3. 逐个资源检查：路径是否越界、文件是否存在、是否为普通文件；
4. 单文件与合计体积是否超预算；
5. 全部通过后返回句柄，允许能力行变为 enabled。

顺序很重要：先做便宜的 schema 校验，再做磁盘 IO；先检查路径，再读文件。失败越早，错误信息越具体。

## 十、资源路由的边界

资源接口只接受两个参数：包 id 与文件相对路径。它不会列目录，也不会返回包内其他文件。

请求处理顺序是：

- 包不存在或未启用：拒绝；
- 文件未被 payload 声明：拒绝；
- 路径 resolve 后越出包目录：拒绝；
- 文件不存在或超过单文件预算：拒绝；
- 通过后返回 `model/gltf-binary` 与私有缓存头。

这条路径上没有“回退到静态目录”，也没有“按扩展名猜文件”。所有可读文件都必须先被声明。

## 十一、示例 GLB 的构造

示例立方体没有使用外部资产，而是在代码里直接构造 GLB：

- 8 个顶点位置；
- 36 个索引；
- 一个 `KHR_materials_unlit` 材质；
- JSON 块按 4 字节空格补齐，二进制块按 0 补齐。

最终文件约 1KB，加载器可以解析出一个 mesh。它同时用于示例包与测试，避免测试依赖仓库里的大模型文件。

## 十二、结论

资源随包不是“把文件塞进 ZIP”这么简单。它要求路径、声明、许可、预算与读取接口形成闭环。

闭环建立后，内容包才真正具备分发二进制资源的能力，而不是只能分发 JSON。
