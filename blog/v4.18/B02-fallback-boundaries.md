# 自动切换模型的三个边界：只在首字前、只对可重试错误、最多两次

失败恢复听起来简单：主模型失败就换备用模型。真正落地时会发现，最难的不是切换，而是**什么时候不许切换**。

一个本地优先的桌面 AI 应用，用户对「回答到一半突然重来」极其敏感。切换错了，比不切换更糟。

## 一、先分类，再决定

第一步不是写路由，而是把所有供应商异常收敛成有限几个错误码：

| 错误码 | 触发 | 首字前自动切换 |
|---|---|---|
| `auth_failed` | 401 / 403 | 否 |
| `rate_limited` | 429 | 是 |
| `timeout` | 连接或首字超时 | 是 |
| `stream_interrupted` | 已连接但中途断流 | 仅首字前 |
| `context_overflow` | 上下文超限 | 否 |
| `provider_5xx` | 供应商 5xx | 是 |
| `unknown` | 其他 | 否 |

分类集中在 AI 适配层，UI 只消费错误码，不解析供应商原始报文。

这条约束很重要：不同供应商的错误结构差异很大，如果让 UI 判断「这个 429 能不能换模型」，逻辑很快会散落在十几个组件里。

## 二、边界一：首字后不切换

判断依据只有一个：本轮是否已经产出任何非空文本。

- 首字前失败：用户还没看到内容，切换是透明的，体验等同于「换了个模型重试」；
- 首字后失败：用户已经看到半段回答，再切换会产生重复输出或语义断裂。

首字后断流只给一个动作：「换模型继续」，由用户确认。这不是保守，而是把不可逆的重复输出风险交给用户判断。

实现上，每收到一个非空 delta 就把 `emitted` 置为真；失败分类时把 `before_first_token / after_first_token` 作为参数传入，由分类函数决定这个错误在当前阶段是否可切换。

## 三、边界二：只对可重试错误切换

不可重试的错误切换没有意义：

- 401/403 是密钥问题，换模型通常也没用；
- 上下文超限说明窗口装不下，换备用模型往往同样装不下，正确动作是压缩或换大窗口模型；
- `unknown` 无法判断，贸然切换可能掩盖真正的问题。

可重试错误才进入切换路径。这个判断写成共享常量表，服务端路由与前端提示引用同一份定义，避免两边口径不一致。

## 四、边界三：最多两次

单轮最多自动切换两次。原因有三个：

1. 防止两个模型互相甩锅，形成无限重试；
2. 控制成本，尤其是按次计费的供应商；
3. 两次之后用户需要明确知道「自动恢复失败」，而不是继续等待。

切换顺序固定：当前模型 → 备用模型 → 停止并提示。首版只支持一个助手级备用模型，不做模型链；模型链的配置复杂度远高于收益。

## 五、切换必须看得见

自动化最怕悄无声息。每次切换做两件事：

- 消息流插入一行提示：「当前模型不可用，已从 A 切换到 B」；
- 写入会话事件，固定四个字段：`fromModelId / toModelId / reason / attempt`。

事件不记录正文，只记录模型身份与原因。这样时间线可以解释「这一轮为什么换了模型」，又不会扩大隐私面。

提示放在助手消息内部，而不是全局 toast：它属于这一轮回答的上下文，滚动回看时仍然能看到。

## 六、错误态的三个动作

自动切换失败后，错误态不能只有「重试」。这一版统一提供三个动作：

- 重试：同样的模型再试一次，适合瞬时抖动；
- 换备用模型：用户显式选择降级路径；
- 保留输入：把原文留在输入框，避免重新输入。

三个动作覆盖了「再试一次」「换条路」「先不发了」三种真实意图。

## 七、怎么验证

单测覆盖六类路径：

- 401/403 不切换；
- 429 切换；
- 超时切换；
- 5xx 切换；
- 上下文超限不切换；
- 首字前断流切换，首字后断流不切换。

另外两条不变量测试：最多两次、切换顺序固定。

端到端验证用 mock 供应商注入一条 429：在用户消息里带一个只对主模型生效的故障标记，主模型返回 429，备用模型正常作答，界面必须出现切换提示。

故障标记必须带模型身份，否则备用模型会再次命中同一条错误，形成死循环。这是实现时最容易踩的坑。

## 八、为什么不支持会话级覆盖

第一版只做助手级 `fallbackModelId`。会话级覆盖看起来更灵活，但会带来两个问题：

- 用户在会话里改了备用模型，下一条会话又回到助手默认值，行为难解释；
- 配置层级越多，排查「为什么切到了这个模型」越困难。

先让一条路径稳定、可见、可解释，再考虑更细的粒度。

## 九、小结

自动切换的价值不在「切」，而在「知道什么时候不切」。

三个边界——只在首字前、只对可重试错误、最多两次——加上一条可见提示与一条事件记录，构成了这个功能的全部约束。
